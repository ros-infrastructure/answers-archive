ROS2 robot localization package - problem with high frequency

Hi, I am using the robot localization package for ros2 galactic on the (fix/galactic/load_parameters branch). I have encountered an issue with the running frequency. Initially, the frequencies in both config yaml files for ekf node and navsat transform node are settled at 30 hz. If I keep the frequency the same or go lower, everything is fine.

The problem is when increasing the frequency above 30 hz, the filtered topics stops publishing at all. I noticed, when increasing gradually for example at 50 hz, the topics publish fine for short moments and stop completly afterwards. Then, at 80 hz , they publish for shorter moment and stop, and at 100 hz they cannot publish at all.

My cpu usage is very well below the limit.

I am running data (imu, gps,..) from ros2 bag db3 file having all data recorded at 100 hz and I can see streaming at same frequency.

My question is, does the ros2 robot localization package capable to run at 100 hz ? and if yes, what could be the possible issue.

Looking forward for your help and thank you in advance.

A quick solution for this issue is: Try to insert the following param in your config (ex. ekf.yaml) and set it to true: "predict_to_current_time: true" and you should not face any problem.

I have submitted a pull request for a permanent fix without initially always use this param. I will keep update here with any news. As for now, the previous mentioned solution should work fine.
