I've no idea why, but the second MD5 contains an unprintable character (0x01 or SOH) in the place of the 3 (you can see it when you look at the source of your question text (click the edit button/link)):

  • correct: e45d45a5a1ce597b249e23fb30fc871f (first hash in the error message)
  • wrong: e45d45a5a1ce597b249e23fb_0x01_0fc871f (second hash in the error message: I've added the _0x01_ to make it easier to spot it)

It's essentially a byte with a value of 1.

This is indeed a different MD5 hash, and so if this is really what the assertion also 'sees', it would seem the assertion is 'right' to fail.

As to why the second hash contains that 0x01, I wouldn't know.
