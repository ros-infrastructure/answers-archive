Joints on incoming goal don't match the controller joints when controlling two UR robots via MoveIt

We want to control two Universal robots via MoveIt in Noetic. We are able to communicate with each robot individually via MoveIt when we run a MoveIt instance for each robot in the same namespace as the urrobotdriver but fail to execute a plan when we combine both robots in one factory model that we derived from the exercise used in the excellent course that can be found at https://online-learning.tudelft.nl/courses/hello-real-world-with-ros-robot-operating-systems/. The message that we get is: "Joints on incoming goal don't match the controller joints"

Exact lines:

[ INFO] [1636994953.809972433]: ParallelPlan::solve(): Solution found by one or more threads in 5.001659 seconds
[ INFO] [1636994953.831453705]: SimpleSetup: Path simplification took 0.021397 seconds and changed from 3 to 3 states
[ INFO] [1636994955.457423321]: Execution request received
**[ERROR] [1636994955.506505067]: Joints on incoming goal don't match the controller joints.**
[ WARN] [1636994955.506671253]: Controller UR3e/scaled_pos_joint_traj_controller failed with error INVALID_JOINTS: 
[ WARN] [1636994955.506728636]: Controller handle UR3e/scaled_pos_joint_traj_controller reports status FAILED
[ INFO] [1636994955.506763180]: Completed trajectory execution with status FAILED ...
[ INFO] [1636994955.506828451]: Execution completed: FAILED

We suspect that this is related to the renaming of the joints by the prefix in the xacro file and the use of namespaces in the launch file because we see that the joint names in the topic of the controller (/UR3e/scaledposjointtrajcontroller/followjointtrajectory/goal) are different from the ones in the /UR3e/joint_states (I can attach the images when I have more then 5 points). However we fail to pinpoint where the error is, please have a look.

Thanks!

Update Nov 18: We got it working by adding a specific robotdescription file in the launch file. This enabled us to prefix the joint names of the hardwareinterface with the prefix used in the xacro file. However, in https://github.com/UniversalRobots/Universal_Robots_ROS_Driver/issues/81#issuecomment-578418515 gavanderhoorn states that not prefixing the joints is by design and with the following advise:

So for a multi-robot setup, start two instances of the driver (each in their own namespace), make sure to create two copies of the configuration .yaml (one for each of the driver instances, I would place these in your "workcell package", as they're part of the application configuration, not of urrobotdriver), load them in their respective namespaces and make sure to specify the correct joint names for each.

In my perception we are doing what is stated by adding the ur3econtrollerdwlab.yaml as the controllerconfigfile in the launch file. However, we need the prefix of the joint names, if not we get the following errors:
