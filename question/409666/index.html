Three ROS2 Standard Nodes Publish to the Same Topic, Messing Up the Execution!

Hello,

I am using ROS2 Foxy on Ubuntu 20.04.

This is a problem that would be difficult to explain! I will do my best. Please kindly ask me for any clarification.

I have a differential drive robot with arms. I am trying to use:

1) A "forwardcommandcontroller/ForwardCommandController" to control the arms and the neck.

2) A "diffdrivecontroller/DiffDriveController" and "bt_navigator" (nav2) with SLAM for the motion control.

In the examples that I have found, people use the "/robotstatepublisher" node to publish the robot transformations to "/tf" and "/tf_static". This is all okay, but the other nodes that I need for control of the wheels and navigation also publish to the same topics!

The "/robotstatepublisher" publishes all of the joint transformations (robotfootprint, robotbase, arms, and neck) on /tf and /tfstatic. A LiDAR is on the head that sits on the neck, so the "scanlink" frame transformation depends on all the transformations from the neck to the robotfoot_print.

Then, the "diffdrivecontroller" node, publishes to the same topic /tf, I am not sure what that one publishes.

Then, the "bt_navigator" node subscribes to the same topic /tf, I am not sure what it looks for in that topic.

Then, the "slam_toolbox" node publishes to the same topic /tf. It seems that it only publishes the "odom" and "map" frames..

It seems like, on each separate run, at random each of the above nodes may start publishing first, and dominating the /tf topic. If the robotstatepublisher gets to initialize the /tf topic first, all is well.

When this happens, the /tf tree in RVIZ shows all the coordinate frames from the "robotfootprint" to "scan_link". The navigation works fine.

If any other three of the above mentioned nodes start publishing to the /tf topic first, nothing works. I get the following message:

[syncslamtoolboxnode-11] [INFO] [1668984486.138684884] [slamtoolbox]: Message Filter dropping message: frame 'scan_link' at time 1668984485.947 for reason 'Unknown'

When this happens, the /tf tree in RVIZ only shows two coordinate frames "odom" and "robotfootprint" and the navigation does not work.
