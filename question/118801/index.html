ros::Time::init() if ros has already been initialized

I want to use ros::Time in a library. This library will sometimes be used in a ros node, and sometimes not. If it is not, I need to initialize the time system with ros::Time::init(). So, can I either:

  1. call ros::Time::init() multiple times (eg, in the constructor for my class which is going to use ros::Time), and possibly after the node has already been initialized, without hurting anything (eg, resetting the time used by my program and causing a jump in the clock). Or..

  2. Check if the time system has already been initialized and only call ros::Time::init() if it has not. If so, how do I perform this check?

It looks like you should be able to call ros::isInitialized() (see here) to check if ros::init() has been called (and thus ros::Time has already been initialized in ros::init()).

If checking whether the system has been initialized, there are 2 cases that must be handled:

a) If running as part of a node (ie, ros::init() has been called and a node handle created), then ros::Time::init() should not ever be directly called by my library.

b) If not running as part of a node, call ros::Time::init() in my library only once.

ros::isInitialized() handles case a) but completely fails in case b), since ros::Time::init() does not fully initialize a node and therefore does not change the value returned by ros::isInitialized().

I did some more digging around in the API as well as some empirical checks, and it looks like ros::Time::isValid() is probably the check that I want. It reports true if either the node has been initialized or ros::Time::init() has been called directly, and false otherwise. However, the documentation for it is pretty vague, so I'm not entirely sure that it was meant for this purpose or that it will handle every case the way I want. I'll use it for now though.
