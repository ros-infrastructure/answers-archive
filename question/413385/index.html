Correct process to distribute ROS projects as containers?

Hello,

I'm a DevOps helping a team of Robotics Developers to streamline their development and deployment process.

With their help I've been able to create a custom DevContainer image for our VScode needs as well as our CI needs.

Currently we have an environnement where all developers works with the same config, and all our commits trigger proper tests.

Now, we need to work on the CD part. Which is where my folks start to be less sure about what is needed or not.

Our goal for the distribution is to end with the lightest possible image with the following characteristics:

  • ARM64 and AMD64 variants (handled by workflow running on different runners, no cross compil)
  • Cuda support
  • ROS
  • only binaries from our own code, no source code
  • no debug tools

Our containers factory so far is quite mature and no problem for most of this.

Where I need help is on the ROS part.

Considering we are using Noetic and our code is C++, what should be the steps for us to:

  • build in release mode from our DevContainers
  • extract the build artifacts
  • create a containers from scratch (ideally from nvidia/cuda) to add the minimal ROS dependencies
  • inject the build artifacts
  • configure the appropriate entry points to run ROS with the container

For all those point, we are unsure about what to do.

If someone here can share a working process, or if there is already existing KB / Blog / Conference / Sample Repo on that topic, I'm really interested.

Cheers Yoann

I'm just going to drop some example links specific to each step you listed.

build in release mode from our DevContainers

Perhaps this could be done via docker build args passed to colcon using mixins or cmake args?

  • https://github.com/ros-planning/navigation2/blob/ae887b1eb91bbce5de8f4c8787946acc9af2e384/.devcontainer/update-content-command.sh#L59
  • https://github.com/ros-planning/navigation2/blob/ae887b1eb91bbce5de8f4c8787946acc9af2e384/Dockerfile#L127
  • https://github.com/devcontainers/spec/blob/42ec3d766096aaefe7abf700f1b2825505e9189f/docs/specs/devcontainer-reference.md?plain=1#L117
  • https://github.com/colcon/colcon-mixin-repository/blob/c75e4b34a3959524564afb584e2aa33c7eec323c/build-type.mixin#L12-L13

extract the build artifacts create a containers from scratch (ideally from nvidia/cuda) to add the minimal ROS dependencies inject the build artifacts

Perhaps you could use multi staged dockerfiles, based on the nvida cuda images, and the official ros images as a template?

  • https://github.com/ros-planning/navigation2/blob/ae887b1eb91bbce5de8f4c8787946acc9af2e384/tools/source.Dockerfile#L1
  • https://github.com/ruffsl/docs-1/pull/1
  • https://github.com/ros-infrastructure/rosdep/pull/789#issuecomment-868858650
  • https://github.com/osrf/docker_images/blob/2b593a4cf56f9834937fc5089e5de5390e463204/ros/rolling/ubuntu/jammy/ros-core/Dockerfile#L18
  • https://gitlab.com/nvidia/container-images/cuda/-/blob/master/dist/12.1.0/ubuntu2204/base/Dockerfile

configure the appropriate entry points to run ROS with the container

Check the official docker images and docs for reference:

  • https://github.com/osrf/docker_images/blob/2b593a4cf56f9834937fc5089e5de5390e463204/ros/rolling/ubuntu/jammy/ros-core/ros_entrypoint.sh#L4
  • https://github.com/docker-library/docs/blob/ab34d0162c2b1e1d3d25748d1c4a5a9e240295c2/ros/content.md?plain=1#L25

Hope those help.
