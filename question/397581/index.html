Building custom IDL based Arduino application

Hello!

Following is the about a symbol resolution problem I am facing in creating a new MicroROS service. What might I be missing?

The setup is as below:

  • Using https://github.com/ros2/example_interfaces as a reference, I place the sources under the src directory in a ROS2/foxy workspace. I rename the directory from 'exampleinterfaces' to 'exampleinterfaces2'. And in every file (CMakeLists.txt, package.xml, and mappingrules.yaml) that has 'exampleinterfaces' I replace it with 'exampleinterfaces_2'.

Then execute 'colcon build --packages-select exampleinterfaces2', which completes successfully. I can see directory structure created under 'install/exampleinterfaces2'.

  • The Micro ROS side is a PlatformIO based build. It has 'https://github.com/micro-ROS/micro_ros_arduino/blob/foxy/examples/micro-ros_publisher/micro-ros_publisher.ino' that compiles and works in an ESP32 setup with UART as transport. So I know the basic setup is correct.

I copy the generated 'exampleinterfaces2/include/exampleinterfaces2' directory to the 'include' directory along side the my 'src' directory in the PlatformIO setup. I place the sources for example the AddTwoInts service in a 'main.cpp'. Then rename all occurances of 'exampleinterfaces' in it with 'exampleinterfaces_2'.

The problem when linking:

Running 'pio run' completes ok till the linker phase, which aborts with error about undefined reference to 'rosidltypesupportcgetservicetypesupporthandleexampleinterfaces2srvAddTwoInts'.

Investigating:

To determine where the equivalent symbol is defined in the working 'exampleinterfaces' provided, a search through the object files in "libmicroros.a" (from https://github.com/micro-ROS/microrosarduino), leads to 'libexampleinterfacesrosidltypesupportc-addtwointstype_support.cpp.obj'.

Question next is where does this originate, how is 'libmicroros.a' built? Which leads me to 'https://github.com/micro-ROS/micro_ros_arduino#how-to-build-the-precompiled-library'.

Question:

Are there direct means to build an custom interface, than building it inside 'microrosarduino' build environment as is done for 'exampleinterfaces'? To put it another way, is there a way to build custom interface such that it is not built into 'libmicroros.a' as is done for the 'exampleinterfaces'? If yes, where might I find the instructions for it?

Answers

Following is overall idea of what I have done to resolve the issue I described:

  1. Git clone 'https://github.com/micro-ROS/micro_ros_arduino' in a directory
  2. Then execute docker run the 'microros/micro_ros_static_library_builder' image in the cloned directory:

docker run -d --name uros-builder2 -v $(pwd):/project --dns 192.168.6.1 --hostname uros-builder2 --env MICROROS_LIBRARY_FOLDER=extras --entrypoint /bin/sleep microros/micro_ros_static_library_builder:foxy 9999d

Then the following to execute in that container:

  • Use 'docker exec -it uros-builder2 /bin/bash' to get into the container started above.
  • In that 'cd /project' and execute './extras/library_generation/library_generation.sh'.
  • Copy the 'example_interfaces_2' directory with the IDL definitions to '/uros_ws/firmware/mcu_ws/ros2/',
  • "cd /project" to execute "./extras/library_generation/library_generation.sh".

This builds results in '/project/src/example_interfaces_2' directory to have the header files as needed. The generated 'libmicroros.a' in '/project/src/esp32' has the objects that I am missing.

The bit of mystery remaining is to understand the why and how of the specific object files in the "libmicroros.a" library. But for now I have a work around.
