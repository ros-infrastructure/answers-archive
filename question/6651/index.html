How to resolve "failed to connecto to master" error message?

Hello, I just installed Gazebo by virtue of having installed ROS Hydro on a Ubuntu 12.04 box. When I attempt to run through the Gazebo tutorial, starting a blank world works fine, but when I attempt t run:

gazebo worlds/pioneer2dx.world

it fails with the following error message:

Msg Waiting for master.Warning [ModelDatabase.cc:335] Getting models from[http://gazebosim.org/models/]. This may take a few seconds.
.............................
Error [ConnectionManager.cc:116] Failed to connect to master in 30 seconds.

In searching around the internet, I have found that others have had this error in the past and have resolved it by reinstalling from scratch, running killall gzserver, etc... none of which has worked for me. I did find this post which suggested (to me) that there might be some issue with Gazebo 1.9 getting confused by Gazebo 2.0 models. (Perhaps I read too much into that).

Anyway, my questions are: 1) should I expect this to work with the stock Gazebo (1.9.5) installed on Ubuntu 12.04 by ROS Hydro?; and 2) How can I debug this if it does not? (I should mention that I have tried the obvious thing of pointing my browser at http://gazebosim.org/models/ and verifying that I can, indeed, connect to the http server at that URL).

Thanks for any tips.

--wpd

Hmmm... I finally tried starting gzserver by itself and waiting (quite likely longer than 30 seconds) until:

Msg Waiting for master
Msg Connected to gazebo master @ http://127.0.0.1:11345
Msg Publicized address: 192.168.238.240

spit out. Then I was able to run gzclient in another window, and I was able to run my original gazebo worlds/pioneer2dx.world command by itself.

It would seem that the 30 second timeout must be related to the time that gazabo (or possibly gzclient) waits to be able to connect to gzserver, and that, in my situation, it took longer than 30 seconds to download whatever stuff gzserver needed from gazebosim.org.

I guess this must not be that common of a problem if nobody else has asked about it and has found the same answer I did.

Thanks for listening.

It sounds like it's having trouble downloading the models. You can get a local cache by cloning https://bitbucket.org/osrf/gazebo_models and setting the GAZEBO_MODEL_PATH environment variable to point to that location.


cd somewhere
hg clone https://bitbucket.org/osrf/gazebo_models
export GAZEBO_MODEL_PATH=${GAZEBO_MODEL_PATH}:$PWD/gazebo_models

I just made an issue on the gazebo_tutorials repo to list this workaround in the quick_start tutorial.
