libgazebo_ros_multicamera.so runs differently between host machine vs docker container

Background:

  • I have a Docker image that has source code for my robot, sensors, virtual worlds (gazebo world files)
  • I am specifically using a stereo camera that uses libgazeborosmulticamera.so

Problem:

  • Launching a simulation on the local host is not a problem

  • Launching a simulation inside a docker container fails to load the libgazeborosmulticamera.so

  • This is evidenced by failure to populate stereocamera/left/imagecolor and stereocamera/right/imagecolor

Let's assume my docker image is called simulator:latest, I have an entrypoint.sh that loads setup.bash for ROS and my project. It then parses all arguments to the "exec" method.

  1. I have copied snippets of code that I thought are relevant below
  2. Results are posted from a simulation launch run on local host and also from the docker implementation

Question

I have named my stereo camera as 'multisenseL' & 'multisenseR' for two instances. I am expecting the following topics to be populated:

//multisenseL/left/image_color

//multisenseL/right/image_color

//multisenseR/left/image_color

//multisenseR/right/image_color

  1. It seems to me that the libgazeborosmulticamera.so plugin is not loading correctly in a docker container. Is my conclusion correct?
  2. If so, what is the resolution to ensure that the plugin loads correctly inside the docker container?
  3. I have noticed that things run a bit slower inside docker containers, I am not sure if some latency issue is causing gazebo nodes to crash? (speculation)

Any help in resolving this is greatly appreciated. Thank you.
