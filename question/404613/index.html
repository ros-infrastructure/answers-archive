Navigating with a robot onto a conveyor belt with Nav2

First of all, thank you for reading this question. I have a mobile robot (KUKA KMR) with two laser scanners installed and a ROS interface for ROS2 (Foxy Fitzroy). In an industry-like scenario, I want a robot to move onto a large moving conveyor belt like in the automotive industry. The problem with this is that localisation becomes difficult because once the conveyor belt has been travelled on, another part of the environment is stationary and another part is moving. In my opinion, the robot is in a different frame of reference. However, it should also be able to localise itself on the conveyor belt.

In ROS1 with the old navigation stack, I divided the map into two parts: a stationary part and the part with the conveyor belt that is moving. Then I started two navigation stacks, each with one of the maps mentioned in two different namespaces. In the TF tree, depending on where the robot is, I changed the parent frame of the robot in the TF tree and sent it via movebasesimple_goal related to the current parent frame. This worked quite well in ROS1 or with the old navigation stack. In ROS2 Foxy with Nav2, I am already failing to start two navigation pipelines in namespaces and also to send the destinations, because the basic architecture with the lifecycle nodes and the action interface has changed.

Has anyone had a similar use case or does anyone know a way to perform navigation with Nav2 two maps offset to each other?

Many greetings, Fabian
