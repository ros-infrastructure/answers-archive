Get a non-implementation specific type identifier of a ros2 message

Some history first to understand what I am trying to do:

Originally I was working on a project where we have developed a storage API (similar to rosbag) to store sensor data (in form of ros messages) into a database for later access. The database provides near constant-time random access of data based on indices or message time stamps, which ros bag itself does not give.

Then, ros2 and rosbag2 came out, which uses sqlite3 as its default storage backend, and we decided to switch to sqlite3 as our database and hope that we could replace our own storage API with the rosbag2 API/CLI. However, we noticed, then, that rosbag2 API is a bit limited - it does not allow one to modify stored data, even though sqlite3 definitely allows that.

So, I am now working on extending the ros bag2 storage API (or basically re-create my own storage API) so that it allows random access based on timestamps and modifying stored data.

However, I would still like the resulting dataset format on disk to be the same as the resulting dataset format of ros bag2 when using sqlite3 as it's backend - the advantage is that I can then use the rosbag2 cli to replay my dataset.

My complete question:

when rosbag2 finishes recording a bag, it stores a metadata.yaml file, which contains the message type and name information. I know that the message type and name information, in ROSbag2 case, essentially comes from this function: gettopicnamesandtypes: https://github.com/ros2/rclcpp/blob/2801553d61c5a30a0327d5cbc8d28bcd74e9703d/rclcpp/include/rclcpp/node_interfaces/node_graph_interface.hpp#L156 where both are std::string. Especially the topic type is something like: "sensor_msgs/msg/PointCloud2"

Now, suppose that, in my c++ code, when I try to store some serialized ros2 message into the sqlite3 database - I obviously will know what the name of my message should, BUT, how can I get the type of my ros2 message as a string like "sensor_msgs/msg/PointCloud2"?

In other words, Given and only given an instance of sensormsgs::msg::PointCloud2, how to generate the std::string "sensormsgs/msg/PointCloud2" from it?

I want to then store this type string into the metadata.yaml, so that my store api results in the same on disk data format as rosbag2.

Very importantly, in my use case, the ros2 message does not come from a topic, so I cannot use the 'gettopicnamesandtypes' function.

Thanks!
