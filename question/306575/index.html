Did I understood the tf from map to odom correctly?

I have a third party localization which will give me the location of my robot via web server. So therefore, I need to correct the location of my robot at any time. From my understanding, I need to provide a transform from /map topic to /odom topic as I will be giving a location in map coordinates and need to transform the message to suite the /odom so robot could locate itself. I have wrote this simple code:

int32_t publish_rate_ = 100;
tf::TransformBroadcaster tf_br_;
tf::StampedTransform tf_map_to_odom_;

// set up parent and child frames
tf_map_to_odom_.frame_id_ = std::string("map");
tf_map_to_odom_.child_frame_id_ = std::string("odom");

// set up publish rate
ros::Rate loop_rate(publish_rate_);

// main loop
while (ros::ok())
{
  // time stamp
  tf_map_to_odom_.stamp_ = ros::Time::now();

  // specify actual transformation vectors from odometry
  // NOTE: zeros have to be substituted with actual variable data
  tf_map_to_odom_.setOrigin(tf::Vector3(0.0f, 0.0f, 0.0f));
  tf_map_to_odom_.setRotation(tf::Quaternion(0.0f, 0.0f, 0.0f));

  // broadcast transform
  tf_br_.sendTransform(tf_map_to_odom_);

  ros::spinOnce();
  loop_rate.sleep();
}

So in the code above, I will simply provide the location to odom which will provide real location values instead of putting 0's. After that, I will call sendTransform to transform the message between map and odom.

Am I getting this correctly?

Also, as Odometry of my robot will be based on wheel encoders + localization will it conflict the location somehow? What is a normal practice in this case?

When you say 'you get the location of your robot via web server', do you get a map to base_link f? Typically Odometry provides odom to base_link tf. Localization component should use this to publish a map to odom tf (i.e. a correction). Combining both you get a map to base_link tf i.e. location.

Asked by stevemartin on 2018-10-24 01:31:47 UTC

No. odom to base_link should be published by Odometry component. This is accurate only for very short time intervals. That is why localization component publishes map to odom tf. This is like a correction. So the map to base_link tf is your robot's actual location.
