High CPU usage when use_sim_time=false in navigation stack

Hello,

I have a physical robot with the nav2 stack set up. The parameters of the nav2 stack are copied from the default demo file that comes with ROS2 Foxy, installed from deb: /opt/ros/foxy/share/nav2bringup/params/nav2params.yaml. Modification were made to use e.g. a rectangular footprint and change some topic names.

Considering the sections below:

   amcl_rclcpp_node:
      ros__parameters:
        use_sim_time: False     # If False, CPU load of nav2_acml/acml is ~70%, else ~5%
  ...
  local_costmap_rclcpp_node:
     ros__parameters:
        use_sim_time: False    # If False, CPU load of nav2_controller/controller_server is ~100%, else ~5%

This usage looks abnormally high to me and I don't understand why using the non-simulated time should affect so much the CPU load.

In both cases the navigation stack seems approximately functional (can navigate and avoid some obstacles), however it ends up crashing and struggle to navigate when the CPU is overloaded (probably because of this timeout issue )

However I could not reproduce the issue with the TB3 demo simulation, but I saw the same issue on Raspberry Pi 4, an VM running on a i5 laptop, and on an Intel i5 NUC PC. In all cases, the CPU usage of the controller_server hit 100%, as if it fell in an endless blocking while loop.

Closest issues were this but ros2 doctor did not detected any TF issues

What could be the source of this error ? Do I have incompatible parameters ? (I attached my params file) Are we supposed to set usesimtime to true for some nodes on a physical robot ?
