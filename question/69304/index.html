/odom and /vo priority in robot_pose_ekf

This question has also been migrated to Robotics StackExchange as https://robotics.stackexchange.com/questions/53096/odom-and-vo-priority-in-robot-pose-ekf.

Hi, my setup currently is using ccnyrgbd to provide /vo data and then using this with gmapping. If I publish odometry transforms then the vo corrects the odometry too much, what is the best way to change odom so it has a higher priority and robotpose_ekf takes into account odom more than vo?

Asked by boog on 2013-07-26 05:37:56 UTC

Comments

Answers

This is controlled by the covariance part of the of the nav_msgs/Odometry and sensor_msgs/Imu messages subscribed to by robot_pose_ekf. Larger values in the covariance will cause that source to be "trusted" less.
