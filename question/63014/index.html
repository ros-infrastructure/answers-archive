Potential data loss with stereo_image_proc

This question has also been migrated to Robotics StackExchange as https://robotics.stackexchange.com/questions/51232/potential-data-loss-with-stereo-image-proc.

Hello,

I have been messing around with the point clouds generated by stereoimageproc for the bumblebee2 for a little bit now. I have just applied the toROSMsg command to convert my point clouds to opencv images and realized that there are many gapping holes in my images.

Is this a universal tendency for stereoimageproc? Or is this an indication that I need to do much more parameter tuning via rqt_reconfigure?

Answers

Yes, the artifacts you are seeing are related to how stereo block matching works. Parameter tuning will allow some optimization, but noise and gaps in stereo point clouds should be expected and will not go away completely in any but the most controlled scenarios.

The "Choosing good stereo parameters" tutorial provides some help on what the knobs are with regards to hopefully improving results.
