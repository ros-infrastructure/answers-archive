Interoperable node code ROS2 and ROS1

Hello everyone,

We are about to pass our packages and our code from ROS1 to ROS2 as time dictates. One of the alternatives that we are evaluating is to try to keep the code of the projects interoperable from ROS1 to ROS2, trying to minimize the conversion effort and to maintain a sort of compatibility with the previous ROS project which could still be useful.

We are trying to study design patterns that allow you to define packages that, regardless of the version of ROS used, allow you to compile with both versions, for example by defining the signatures of the functions as templates so that they are independent of the type of message contained, or by uncoupling the logic from the code from the part strictly dependent on the platform. For now, this is just an investigation exercise, but I would like to find out if anyone has ever had a problem or been addressed in the past.

PS. We would like to avoid using solutions such as bridge as we do not consider it an "elegant" solution and in general we would like to avoid system overloads that can be avoided
