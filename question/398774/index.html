Overall, you need to know what kind of program API this robot has, then if there is an option to get or calculate energy consumption - then you should implement this in a ROS publisher or as a ROS service to call. This is a kind of example for working with I2C simpler electronics connected to ROS: https://people.eng.unimelb.edu.au/pbeuchat/asclinic/software/workflow_i2c.html. I think KUKA robots should have some higher-level libraries...
