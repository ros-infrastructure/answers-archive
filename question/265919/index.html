If you modify code in rtabmap_ros package, you don't have to rebuild rtabmap, just redo catkin_make. I think you are meaning: 

$ roslaunch rtabmap_ros demo_stereo_outdoor.launch

Note also that obstacles_detection nodelet is not started with demo_stereo_outdoor.launch. However, you should see your printfs added in CoreWrapper. You can copy/paste the terminal output after launching the launch file in your question for more info, normally onInit() printfs would appear at start.

Asked by Mikhail on 2017-07-11 12:57:43 UTC

RTAB-Map is split into 2 projects, one independent of ROS ("rtabmap") that should be installed like any other Linux library (in /usr/local, with standard cmake, make, make install), and a ROS package project ("rtabmap_ros") which should be built the ROS way (catkin_make).

Asked by matlabbe on 2017-07-11 14:36:22 UTC

When launching ROS nodes, the ~/catkin_ws/devel path is used to find ros binaries/libraries built locally, then look for those installed with apt-get in /opt/ros/kinetic.

Asked by matlabbe on 2017-07-11 14:38:31 UTC

Doing catkin_make does not remake all scripts/binaries/libraries, it first checks if something has changed in the ~/catkin_ws/src folder, then rebuild the binaries if needed.
