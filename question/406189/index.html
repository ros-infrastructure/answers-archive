Communication between ROS and non-ROS computers

I'm attempting to communicate data from a Windows computer that is also using Python to a ROS computer that is running ccsp training. When I incorporate the script into a ROS script, the ROS script dies when attempting to receive data from the connection, notably at socketName.recvfrom, even though I have successfully sent data from Windows to Linux using TCP sockets (bufferSize).

Researching online, I found that this is expected behaviour. ROS uses TCP to communicate and purposely makes it difficult to implement a separate socket for this (if I have understood it correctly).

Is there a way around this? What is the most effective way to implement a ROS script that reads data from a non-ROS computer?

There are tons of ways to make it work. You need to spend more time on it. Never mind, the easiest way to use an external library that can send data from a non-ROS computer to the ROS computer. One such robust and popular library is ZeroMQ. Furthermore, you can check ros_zeromq_tutorial for more info. Please note that the ZeroMQ library has python bindings as well.
