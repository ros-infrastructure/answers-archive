Asked by aa-tom on 2021-07-14 10:01:50 UTC

From what you describe, I don't believe this would be an issue with catkin_tools, nor with catkin_make_isolated.

Tbh, the "migration" tutorial is a bit too conservative.

If packages don't build with catkin_tools, it's not really seriously more complex to diagnose that with catkin_tools than it is with catkin_make_isolated.

Often seen problems mostly include build order issues due to people not having stated their build_depends properly in the manifest.

A lot of these can be detected by catkin_lint.

This is all CMake.

The only thing Catkin does/is, is:

  1. provide a set of CMake macros and files which make it easier to build large sets of CMake-based projects in the correct order and in a "workspace", and
  2. provide a tool (catkin_make or catkin_make_isolated or catkin) which invokes cmake (so CMake itself) in the correct order and in the right place (ie: directories)

CMake runs cppcheck (well, technically it would probably be make in the end, depending on the generator you've selected, but ..).

I'm not claiming necessarily that the environment Catkin configures for you couldn't influence what cppcheck does or doesn't do, but in the end, it's all CMake.
