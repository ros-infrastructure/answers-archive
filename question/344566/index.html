Asked by gvdhoorn on 2020-02-19 05:29:56 UTC

If the ZED wrapper slows down to such frequencies the cause is often related to a problem with the TF tree. If the configuration of your robot requires to disable static TF by URDF (publish_urdf=false) or to disable odom TF (publish_tf=false) you must guarantee that the TF chain map->odom->base_link->zed_camera_center->zed_left_camera exists, otherwise the node will wait for it to be available with a timeout set to 2 seconds. The ZED Node respects the conventions described in the REP105 for TF chain: https://www.ros.org/reps/rep-0105.html

For more info you can read these issues on Github: - https://github.com/stereolabs/zed-ros-wrapper/issues/526 - https://github.com/stereolabs/zed-ros-wrapper/issues/525
