Where is the right place for logic

Hi there,

I have rather a general question. I know that I can do it either way but still ...

For example: I have a node witch reads data thru I2C from ADC convertor. I can publish raw measured data like from 2347 to up 4729 from potentiometer and so on. But at the end I will need convert these raw number to 0-100%.

I know how to create nice numbers from raw data. This question is where to put the logic. To the sensor node and publish the polished data? Publish both raw and polished? Or put the logic to a different node? Something like a solo node just for the conversion. Or keep the raw data as far as possible a convert them just before the use?

I know I can do what is best for my purposes but what is the general approach? What is the best practise?

Personally I try to convert raw data to SI units as early as possible. Rationale(s): separation of concerns, increases reusability (other nodes only see ROS API with standard messages (if possible)), decreases coupling, increases cohesion, etc, etc.

Why "bother" the rest of your ROS application with the fact you're using I2C or an ADC? Let alone a potentiometer. They don't care, and they shouldn't need to.

Edit: but of course, as everything in software, nothing is as binary as it may seem here: there could be valid reasons in specific cases for publishing raw data and doing the conversion later or multiple times. But in general I would say try to be clear on why you do things, and convenience is not a good rationale.

Echo what gvdhoom says. If your HW driver is supposed to measure voltage, then the output should be voltage. There should be a conversion in only one location. If you have multiple customers for the data no point in having them individually doing a conversion. If the HW changes later in the project you only want to change the driver and nothing else.
