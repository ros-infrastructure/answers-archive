Errors in depth measures with openni

Hi, I have a problem on depth using gazeborosopenni plugin with Gazebo 4, ROS Indigo and Ubuntu 14.04. In the URDF of my quadrotor there is a kinect. The model is the same as it's told by the tutorial, but I've set pointcloudMaxCutOff to 15 meters. The orientation of my camera has a pitch angle not equal to 0, but I've tried to change that and the results are the same. My gazebo world is empty, there is only the ground plane, so I would expect to get pointclouds with z = 0 respect to the world frame. I use a tf stamped transform in a node ROS to rotate the pointcloud got by Gazebo as it is done in octomap_server code, so I'm sure to do it correctly. tf update frequency is greater than pointcloud rate. But sometimes I get strange results: my pointcloud contains some points with z > 2 meters!! How is it possible?

Thanks to all, Anna

Yes, of course. Here you are:

  <gazebo reference="${name}_depth_frame">
    <sensor type="depth" name="${name}">
      <update_rate>0.5</update_rate>
      <camera>
        <horizontal_fov>${100 * M_PI/180.0}</horizontal_fov>
        <image>
          <format>R8G8B8</format> <!--A 24-bit RGB pixel format that uses 8 bits per channel.-->
          <width>640</width>
          <height>480</height>
        </image>
        <clip>
          <near>1</near>
      <far>15</far>
        </clip>
      </camera>
    <plugin name="${name}_camera_controller" filename="libgazebo_ros_openni_kinect.so">
        <alwaysOn>true</alwaysOn>
        <updateRate>0.5</updateRate>
        <imageTopicName>${name}/rgb/image_raw</imageTopicName>
        <cameraInfoTopicName>${name}/rgb/camera_info</cameraInfoTopicName>
        <depthImageTopicName>${name}/depth/image_raw</depthImageTopicName>
        <depthImageCameraInfoTopicName>${name}/depth/camera_info</depthImageCameraInfoTopicName>
        <pointCloudTopicName>${name}/depth/points</pointCloudTopicName>
    <pointCloudCutoff>1</pointCloudCutoff>
    <pointCloudCutoffMax>15</pointCloudCutoffMax>
        <frameName>${name}_depth_optical_frame</frameName>
        <distortion_k1>0.0</distortion_k1>
        <distortion_k2>0.0</distortion_k2>
        <distortion_k3>0.0</distortion_k3>
        <distortion_t1>0.0</distortion_t1>
        <distortion_t2>0.0</distortion_t2>
      </plugin>
    </sensor>
<turnGravityOff>true</turnGravityOff>
  </gazebo>

I think that the problem may be related to the speed of the robot. I noticed that depth will be quite right if I set camera update rate to 30 Hz. Particularly, I get errors when the robot moves up and down, changing its altitude. In order to semplify the problem, my robot has no dynamics (true, inertial properties set to small values) and it is velocity controlled.
