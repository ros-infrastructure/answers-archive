Change timestampt of tf between base_link and map

Hello,

As part of a project I am trying to connect a different simulator to Autoware.Auto to integrate both in a Hardware-in-the-loop AVP demonstration. My goal is to connect Autoware.Auto, running on a seperate linux PC with powerful GPU, to a simulator that is running on a separate windows PC. This simulator is MATLAB/Simulink based, and is able to publish ROS1 messages. On the Linux PC I am receiving these ROS1 messages, and using the ROS1_ROS2 bridge to port the messages to Autoware.Auto.

To make life easy I am mimicking the LGSVL messages as much as possible, so that I can reuse the LGSVL_interface node. Currently I am able to receive all LGSVL messages in Autoware.Auto (send by my windows simulator), and I have successfully tested several perception and localization nodes.

My next goal is to launch the navigation/planning nodes, and close the loop. To do so, I am using the following launch file 

ade$ stdbuf -o L ros2 launch autoware_demos avp_sim.launch.py

as described in this link

https://autowarefoundation.gitlab.io/autoware.auto/AutowareAuto/behavior-planner-howto.html

The problem I am currently facing is the following. After having launched both the visualization launch file and the launch file above, and having initialized the initial position of my vehicle with 2D pose estimate in rviz2, I am getting the following error when starting the simulator. 

[p2d_ndt_localizer_exe-4] [ERROR] [1629816024.537506678] [localization.p2d_ndt_localizer_node]: Lookup would require extrapolation at time 16.600000, but only time 1629816000.575948 is in the buffer, when looking up transform from frame [base_link] to frame [map]

The 16.60000 is the current simulation time of my simulator, being send to Autoware.Auto via the message /LGSVL/Clock. However, the ndt localizer node is not using this clock signal, but the internal clock of the Linux machine. I have noticed that the robot state publisher is also publishing its tf's using the internal Linux clock.

So my question is, how can I change the settings of the ndt localizer so that it uses the simulation clock of my windows simulator? I have been going to the param files, but haven't found a setting that solves the issue.

Thanks a lot for reading my question and possibly giving me some guidance.

Answers

The clock topic being produced by LGSVL is designed to provide a simulation clock for every node just like replaying a bag file would. For this to work, it must be published in the root namespace (i.e. /clock - no namespace). In addition, each node that is running must be told to use this clock instead of the system clock with the parameter use_sim_time. Unfortunately, in ROS2, this must be set for every node individually in order for it to work as expected. Additionally, each node must be using the ROSTime time source (see this design article for details). My recommendation is that you create a LaunchArgument in the launch file for whether or not you want to use sim time and then add something like the following for each node:

... (beginning of launch file)
use_sim_time_arg = DeclareLaunchArgument(
    'use_sim_time',
    default_value=False,
    description='Whether or not to use the /clock topic'
)
...
node_name = Node(
    ...
    parameters=[('use_sim_time', LaunchConfiguration('use_sim_time'))]
... (rest of launch file)

Don't forget to add use_sim_time_arg to the LaunchDescription at the bottom of the file so you can use the argument. Then, just enable it with: 

ros2 launch package_name launch_file.launch.py use_sim_time:=True
