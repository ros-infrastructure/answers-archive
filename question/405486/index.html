Asked by Magda on 2022-08-25 07:17:06 UTC

The delay is calculated as curr_rostime.to_time() - msg.header.stamp.to_time(). In other words, it uses the current time of the subscriber node and subtracts it to the time available in the message header. Please see here for the implementation. A similar discussion is available here.

BTW, I noticed that you are running the subscriber inside Virtual Box. If the camera publisher is running on a different machine (in your case, the host machine), then you need time synchronization. In simple words, the host and guest machine must have the same time. At present, I suspect that this time is different.

Asked by ravijoshi on 2022-08-25 20:20:09 UTC

Answers

All your ros nodes need to read the same value for use_sim_time when the node starts up, or you are going to see weird problems like this. You need to restart all nodes if you change this parameter.

I suspect you started some ros nodes when the value was true, and others when it was false.
