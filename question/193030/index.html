robot_pose_ekf diverges with GPS data

Hello,

I use the viso2ros visual odometry, IMU, wheel odometry and GPS data for robotposeekf. By using VO, IMU and wheel I receive excellent results whereas when I also want to add my forwarded GPS-odometry topic (from navsat msg with gpscommon->utmodometrynode, from an xsens sensor) the filter diverges

https://docs.google.com/document/d/1sB3IhNM4IfkGDFQl2i3V1q9V4cTqohasaL7TQXZTZI0/edit https://docs.google.com/document/d/1CiiJJfNfPFd0Iij4OJGH6-BeQZS7aNa06zLL4bx-KeU/edit

I tried for some time now to manage this problem. As far I can see robotposeekf interprets all topics as absolute measurements (using StampedTransform/Transform current minus last epoch). What looks weird ist that:

gpscommon->utmodometry_node sets the orientation to (quaternion): x = 1 y = 0 z =0 w = 0

which is weird since this is not the identity quaternion (x = 1 y = 0 z =0 w = 1 ). Also the x-axis bears the East-coordinates and not the North coordinates.

Has anybody experienced the same problems?
