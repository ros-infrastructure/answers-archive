ROS2 Compositions and intra-process communication

According to efficient intra-process communication documentation, efficient intra-process communcation happens because the nodes are running in the same thread, and both of them are using unique_ptr, so the pointer may be reused in both nodes.

With this thinking, I thought that compositions should be doing this out of the box because they are also running in the same thread, so there is nothing to add/change other than using unique_ptr’s. I implemented an example to try it out, and I observed that it is actually the case. But I couldn’t observe any speed difference. If talker and listener are in different nodes, or in the same composition, I observed that the topic hz is still around 11500. Anyone has any thoughts on this? Am I hitting another bottleneck in 11500 hz?

I tried it in Ubuntu 20.04 Foxy, installed by apt.

Answers

I found the answer! The thing was FastDDS, the default DDS implementation of Foxy. FastDDS already uses shared memory for communication if the nodes are in the same computer by default. So, whether you use composable nodes or not, you already have the maximum performance, and your messages goes with shared memory.
