Doubts regarding gmapping

This question has also been migrated to Robotics StackExchange as https://robotics.stackexchange.com/questions/46486/doubts-regarding-gmapping.

Hi. I have some doubts regarding gmapping. On the wiki page, it is stated that gmapping make use of both laserscan and odometry data to build a map. However,it seems that the slammapping node only subscribe to “scan” topic but not to “odom” topic. So, is it that we only need to set the “odomframe” parameter when launching gmapping to “odom” so that the gmapping receive odometry data? Thank you.

Asked by ChengXiang on 2012-12-11 17:13:09 UTC

Comments

Answers

gmapping receives the odometry information in the form of a transform from the odom frame to the base_link frame. You need another package (for example robot_pose_ekf) publishing that transform in order for gmapping to work.

Odometry is a stream of messages on the /odom topic. But in ROS, an odometry node is also supposed to continuously publish the transform odom -> base_link and that's what, for instance, the robot_pose_ekf node does after fusing /odom and IMU data.
