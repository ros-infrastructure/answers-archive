SimpleActionClient(c++) lost goals

Hi,

We are working with a multi-thread motion plan/execution using ActionServers (not the SimpleActionServer). Though we do not use a SimpleActionServer, we do use a SimpleActionClient to communicate with the server. It mostly works fine but sometimes we lose the goal, by that I mean the action client sends a goal sendGoal() and then waits waitForResult(), but it keeps waiting forever. After debugging our implementation of the ActionServer, the GoalHandle is set to Accepted and the result is published as it can be seeing in the ROS topic *action_server_name*/result, so it seems the server works fine. However, the action client never seems to receive/update the goal status, thus it waits forever. This issue is not easy to reproduce but it happens fairly often.

Does anyone has an idea of why a goal can be lost like this?

According to the discussion on the pages @gvdhoorn pointed you toward, in the c++ SimpleActionClient the default subscriber queue size for the result topic is set to 1. (This issue does not affect the python client, where size defaults to unlimited.)

Remember that all your clients are listening on a single result topic. This means if your action server sends two result messages rapidly, then one is discarded by all the c++ clients because their queues are full.

If this is the cause of your issue, you can fix it using the node parameter ~actionlib_client_sub_queue_size
