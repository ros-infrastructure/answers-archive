rosrun apparently is not aware your .pyc file is executable, or more specifically, it (more likely the shell it uses to start the program) doesn't appear to know it should use python3 as the interpreter.

The .pyc is then attempted to be run as a script, which leads to the errors you see.

I don't believe this is really a ROS problem. rosrun doesn't really try to do anything 'smart' here I believe. If your shell cannot directly execute .pycs, rosrun wouldn't either. Can you run the .pyc directly (ie: without rosrun)?

It's worth checking the source of rosrun: perhaps it has some special cases which make it attempt to start something as a shell script.
