I also struggled with this behaviour. When I ran 'gazebo --verbose' it turned out the reason was that another gazebo server was running in the background:

[Err] [Master.cc:96] EXCEPTION: Unable to start server[bind: Address already in use]. There is probably another Gazebo process running.

Checking the running processes (ps -x | grep gazebo) I found:

4525 pts/2 Sl 14:44 gzserver -s /opt/ros/kinetic/lib/libgazebo_ros_paths_plugin.so -s /opt/ros/kinetic/lib/libgazebo_ros_api_plugin.so

Killing this process (kill -9 4525) solved the problem.
