Not really an objection per se, but would contributing support for your cameras to pylon_camera not be an acceptable approach? That would keep things together.

If you're worried about branding: perhaps refactoring pylon_camera in a common (genicam) part and per-camera brand/type specific pkgs could be an option.

Reason I suggest this would be that by keeping things together issues have to be fixed (ideally) only once, instead of in "all" packages again.

Have you tried discussing this with the pylon_camera developers?
