Asked by fhoerb on 2020-08-31 05:01:57 UTC

I replaced the first part of the file with that of another bag file with the same setup.

That works to 'silence' the errors, but not to make the bag usable. The bag header structure is located in that "first part" and it actually contains important information about the data in the .bag. Without that information, rosbag will not be able to find anything in it.

I've tried a few things, and I've gotten a bit further, but there is something really strange about the .bag. It's as-if rosbag (or any of the underlying OS systems) decided to distribute the contents (ie: bytes) of some blocks all around the file at random locations. I'm not entirely sure yet, but it's strange to "suddenly" see some bytes (which appear to belong to a CHUNK_INFO record fi) appear in the middle of a list of INDEX_DATA records.

The .bag format is pretty resilient to corruption, but there are some parts which are essential. If those are missing/corrupted, it's going to be difficult to recover it.

If someone happens to run into the same problem, then to conclude the topic, it can be said that recovery was still possible.

It was possible to get all the events (total 284394) from this particular bag. And computer going to sleep was also confirmed, approx. 24 seconds in sleep mode.
