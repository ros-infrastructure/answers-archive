How to implement a rclpy node which continuously reads data from a driver library and publishes messages using that data

I am fairly new to ROS2 so I'm not exactly sure how to implement this. Essentially I have a python library that is in serial communication with an expansion board (it is outside of ROS, installed on linux based device), and I've written an ROS2 node (pclpy) which reads data from the library, and publishes various messages (ie. twist) using that data. The node class contains a function that is essentially in an infinite loop (while rclpy.ok(): .... rclpy.spinonce(self)) , and I call that function from the main function of the node. I would rather it call rclpy.spinsome, to allow the callbacks to be executed until the queues are drained, but this is not implemented in rclpy at the moment.

My idea was to create a future that does an asyncio.sleep for some slice of time to allow some number of callbacks to be completed, before another iteration of the while loop. I'm wondering if there is better solution to the problem. The code for my solution would look something like this

async def set_after(fut, delay, value):
# sleep for *delay* seconds.
await asyncio.sleep(delay)
# set *value* as a result of *fut* Future.
fut.set_result(value)

def create_future(self, delay):
# get the current event loop.
loop = asyncio.get_running_loop()
# create a new Future object.
fut = loop.create_future()
# run "set_after()" coroutine in a parallel Task.
# we are using the low-level "loop.create_task()" API here because
# we already have a reference to the event loop at hand.
# otherwise we could have just used "asyncio.create_task()".
loop.create_task(self.set_after(fut, delay, True))
return fut

# Publish the speed of the robot, gyroscope data, and battery voltage
def publish_data(self):
while rclpy.ok():
    # spin once for callbacks
    rclpy.spin_until_future_complete(self, self.create_future(0.5))

Would this even work? Or is there a better route to take?
