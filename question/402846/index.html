vox_nav is a project that is aimed for navigation in unstructured/uneven terrains.

See, the robot navigating in uneven terrain with vox_nav; https://youtu.be/ZQdy22LmeP0

So far I have used the project only where GPS is available, the pointcloud map is geo-referenced. I assume in your case there is no GPS ?,there could be some work in order to accommodate replacement of GPS localization with your SLAM based localization. But I would like to work on that and make this possible. Feel free to contact me or use the issue tracker in vox_nav repo to test the project, I am interested to see how vox_nav could be useful to your case.

Disclaimer; vox_nav is still a research project and is far from stable/reliable, so you should expect certain amount of hassle while trying to use vox_nav.

Asked by marpeja on 2022-06-28 03:11:49 UTC

You can see an example robot configured with vox_nav botanbot. By geo-referencing the map, I meant that, given a GPS sensor on robot and datum of the map (defined in vox_nav_default_params.yaml), vox_nav's map_server will place your map W.R.T initial pose of robot, hence, you do not need to manually do anything, but you do need a GPS sensor and map datum for this to work. Place GPS sensor as close as possible to the sensor you constructed map with, its camera in your case ? I am not too familiar with RTABMap, but typically SLAM algorithms have a pure-localization mode, where the algorithm provides you map->base_link transform, you can include this as a pseudo sensor info and include it in robot_localization to improve your localization accuracy. You should use OptimalElevationPlanner . The best way for me to help you would be that you open source your project or add me as contributor, Unfortunately configuring this is very
