Gazebo fails to execute multiple trajectories sent back to back

Hey guys, I am facing a tricky situation in Gazebo.. Im working on a Turtlebot with a PhantomX Pincher Arm.. My program effectively solves the IK and the corresponding trajectories are successfully sent to the motion planner to be executed..

This works perfectly on the physical robot as well as Gazebo.. The problem occurs when I send back to back trajectories to perform a pick and place task.. I have written my own piece of code to execute pick and place.. Essentially, The IK looks for a solution with respect to the current joint position, if it finds a solution, the motion planner commands the arm to go there.. It picks up the object and then proceeds to go to the drop off (place) position in the same way as above..

This works PERFECTLY on the physical robot meaning I can pick-place objects as many times and from as many locations I want and the actual/physical robot executes it perfectly.. HOWEVER, when I run the same code in Gazebo, it only executes the FIRST trajectory (in my case it is the trajectory that tells the motion planner to go from the current position to the Pick Up Location).. After this, the arm just stops in that location in Gazebo.. I mean that the IK finds the Place location (or ANY reachable location for that matter), the motion planner even sends a command to the action goal that updates the new goal position and everything; BUT the arm just doesnt execute it..

Ive been stuck on this problem for a couple of days now and no matter what I do, it doesnt work in Gazebo while the same exact code works perfectly on the actual phantomx arm..

In my opinion (and I could be completely wrong), I feel that it is something to do with the PID controllers.. I feel that perhaps (even after fine tuning it a LOT) the controllers fluctuate.. Which means that while the IK from the current position successfully finds the goal and the motion planner takes this trajectory from the IK Planner, our current position essentially changes (due to the unstable PID or the gazebo environment) and hence it never manages to execute the thing.. I even put a 20 second sleep each time before and after it searches for an IK solution but it hasnt helped..

I would therefore be very grateful if anyone can help me with this situation.. I really appreciate it..

Thank you so much..
