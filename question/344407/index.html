When running rqt in another terminal you'll likely run the one that is in /opt/ros/[kinetic|melodic]/bin/rqt. The one that you are modifying is in a catkin workspace, right? I haven't built rqt, but I'd guess it uses a catkin build process. In which case you may want to run "catkin build" instead of cmake CMakeList.txt. (I'm still learning my way around catkin and cmake, so take that with a grain of salt.) Once built, your new rqt would be run in that catkin workspace by first doing "source devel/setup.bash". Then run rqt. The setup.bash modifies the local shells paths so that it'll find your newly built package before looking in the system ros directories.
