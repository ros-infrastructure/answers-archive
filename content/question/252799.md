  body_markdown: |-
    Yes, the file `base_local_planner_params.yaml` will control the turning speed (as well as the longitudinal speed). Specifically, the parameters: `max_vel_theta`, `min_vel_theta`, and `min_in_place_vel_theta`. These are standard parameters for the base_local_planner package. You will find their definitions [here](http://wiki.ros.org/base_local_planner#Parameters).

    The second file you reference contains parameters for the costmap, which you can read more about [here](http://wiki.ros.org/costmap_2d).

    However, the maximum velocity setting may not be you problem. When turning on carpet you could be power limited, or also be experiencing excessive slip, which will not only lengthen the turning time, but also add time just for the localization to realize the robot has not turned sufficiently far.
