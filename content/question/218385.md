  body_markdown: "The documentation of the method is\n\n    void setSucceeded (const\
    \ Result &result=Result(), const std::string &text=std::string(\"\")) \n\nSo that\
    \ you are always calling the same function, but default parameters are given if\
    \ you don't give any. If you call `as_.setSucceeded(result_)` you have to opportunity\
    \ to return a result from the action. However, if you call `as->setSucceeded();`\
    \ your result message will be all zeros."

Hi,

in [actionLib tutorial](http://wiki.ros.org/actionlib_tutorials/Tutorials/SimpleActionServer%28GoalCallbackMethod%29) it uses `as_.setSucceeded(result_);` to notify success

but [in actionLib wiki pages](http://wiki.ros.org/actionlib) it uses `as->setSucceeded();` to notify success.

However, in the [Simple action server document](http://docs.ros.org/api/actionlib/html/classactionlib_1_1SimpleActionServer.html), there is only the first method mentioned, not the second one. But the second method can be compiled successfully.

Then I'm wondering since they all sent success notification to the client, which way is better if there is only a `bool` variable stands for action success or not in my `file.action`?
