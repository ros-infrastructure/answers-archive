  body_markdown: "Parmaters are not like topics, as you said they are loaded into\
    \ the parameter server. In the introduction of the [wiki](http://wiki.ros.org/Parameter%20Server)\
    \ :\n\n> A parameter server is a shared,\n> multi-variate dictionary that is\n\
    > accessible via network APIs. Nodes use\n> this server to store and retrieve\n\
    > parameters at runtime. As it is not\n> designed for high-performance, it is\n\
    > best used for static, non-binary data\n> such as configuration parameters. It\n\
    > is meant to be globally viewable so\n> that tools can easily inspect the\n>\
    \ configuration state of the system and\n> modify if necessary.\n> \n> The Parameter\
    \ Server is implemented\n> using XMLRPC and runs inside of the\n> ROS Master,\
    \ which means that its API\n> is accessible via normal XMLRPC\n> libraries.\n\n\
    So it's not a node that stores the parameters and publish them to the other nodes.\
    \ The parameters can be read/set via your code or with the tool [rosparam](http://wiki.ros.org/rosparam)\
    \ . \n\nSo instead of `rostopic list` you can see the parameters with `rosparam\
    \ list`. For example if you want to check the value of all your parameters at\
    \ once you can use `rosparam get /structure/` that will return  `{angle: 120,\
    \ bras: 3, longueur: 550}`"

     * /structure/longueur: 550
