    \ posted. Recently I had the same problem as the one that Joe reports in his question.\
    \ I don't own a PR2 (yet! ;P) but I was having trouble executing MIT Kinect Demo's\
    \ hand_detector in a no-monitor environment. So, I would like to share the solution\
    \ just in case anybody else has the same problem.\n\nAs Joe said, the file main.cpp\
    \ inside skeletal_tracker has a bunch of calls to OpenGL/GLUT code. The problem\
    \ is that if you do this:\n\n    //glInit(&argc, argv);\n    //glutMainLoop();\n\
    \    ros::spin();\n\n Then the function *glutDisplay* will never be called. And\
    \ inside that function is where they get all the data from kinect, process it\
    \ and publish the skeleton topics.\n\nSo the solution could be: create a new function\
    \ to do the same as *glutDisplay* but without all the GUI stuff. The new function\
    \ would look like this:\n\n    void publishSkeletons(void)\n    {\n      xn::SceneMetaData\
    \ sceneMD;\n      xn::DepthMetaData depthMD;\n      g_DepthGenerator.GetMetaData(depthMD);\n\
    \t\n      //Read next available data\n      g_Context.WaitAndUpdateAll();\n  \
    \    ros::Time tstamp = ros::Time::now();\n\n      //Process the data\n      g_DepthGenerator.GetMetaData(depthMD);\n\
    \      g_UserGenerator.GetUserPixels(0, sceneMD);\n      std::vector<mapping_msgs::PolygonalMap>\
    \ pmaps;\n      body_msgs::Skeletons skels;\n      getSkels(pmaps,skels);\n  \
    \    ROS_DEBUG(\"skels size %d \\n\",pmaps.size());\n      if(pmaps.size()){\n\
    \n        skels.header.stamp=tstamp;\n        skels.header.seq = depthMD.FrameID();\n\
    \        skels.header.frame_id=\"/openni_depth_optical_frame\";\n        skel_pub.publish(skels);\n\
    \        pmaps.front().header.stamp=tstamp;\n        pmaps.front().header.seq\
    \ = depthMD.FrameID();\n        pmaps.front().header.frame_id=\"/openni_depth_optical_frame\"\
    ;\n        pmap_pub.publish(pmaps[0]);\n      }\n    }\n\nAnd then change the\
    \ unwanted calls to OpenGL/GLUT stuff\n\n    glInit(&argc, argv);\n    glutMainLoop();\n\
    \nfor this other calls:\n\n\tros::Rate loop_rate(30);\n\t\n\twhile (ros::ok())\n\
    \t{\n\t  \n\t  publishSkeletons();\n\t  ros::spinOnce();\n\t  loop_rate.sleep();\n\
    \t \n\t}\n\nIt works perfectly for me, I hope somebody else finds it useful."

Has anyone gotten hand_detector.launch (the MIT hand detection Kinect library) to run on a PR2 robot?

I've worked through some minor problems with our PR2 running Diamonback:

1. The solution from this post: http://answers.ros.org/question/688/skeletal_tracker-crashes helps solve one problem.

2. The file main.cpp inside of skeletal_tracker (which must be run with this package) has a bunch of calls to OpenGL/GLUT code. You can't run it locally on the PR2 (no monitor), and I've found you can't pipe it over ssh -X for some technical reasons with GLUT (at least that's what I've been able to gather through google). I fixed this situation by modifying main.cpp as follows:

//glInit(&argc, argv);

//glutMainLoop();

ros::spin();


As you can see I just replaced the OpenGL callbacks with a ros::spin. I'm not really sure what the graphical window in this package is for. I'm guessing it's important.

SO ...
Now I can run the code on our PR2 robot without it crashing/complaining, but no messages ever get published to the topics /hands/ /hand0_fullcloud /hand1_fullcloud. I'm not really sure where to go from here. Suggestions?
