    > I want to install ros-base pkg [..] on [..] Debian Stretch Image. [..] Firstly there are no melodic nor kinetic packages available after updating

    Both the installation instructions ([wiki/kinetic/Installation](http://wiki.ros.org/kinetic/Installation)) as well as `REP-3` ([Platforms by Distribution: Kinetic Kame (May 2016 - May 2021)](http://www.ros.org/reps/rep-0003.html#kinetic-kame-may-2016-may-2021)) state that only Debian Jessie is supported for Kinetic.

    Melodic should be supported ([REP-3](http://www.ros.org/reps/rep-0003.html#melodic-morenia-may-2018-may-2023)), provided you are using a platform for which binary pkgs are being built. Only `amd64` and `arm64` (or ARMv8) are supported (as can be seen on the [installation page](http://wiki.ros.org/melodic/Installation) for Melodic).

    If I'm not mistaken, a Beaglebone Black comes with a [Cortex-A8](https://en.wikipedia.org/wiki/ARM_Cortex-A8) processor, which is a 32-bit CPU supporting ARMv7. The ROS buildfarm does not build binary pkgs for that afaik.

    > Instead I can install ros-core, ros-base

    This is most likely because of [wiki/UpstreamPackages](http://wiki.ros.org/UpstreamPackages).

    ---

    Edit: as `REP-3` mentions, packages *are* provided for `arm32` for Melodic (and Lunar, and Kinetic). Those are grouped under the "hard float" moniker on the buildfarm. However, those are only built for the Ubuntu OS compatible with that architecture.

    See also the various status pages available at [repositories.ros.org/status_page](http://repositories.ros.org/status_page).

    The mapping used there:

     - `default`: Ubuntu (at the version targeted by the specific ROS release, and on `amd64`)
     - `dj`: Debian Jessie (on `amd64`)
     - `djv8`: Debian Jessie on ARMv8
     - `uxhf`: Ubuntu Xenial on Hard Float (ie: ARMv7 / 32bit)
     - `uxv8`: Ubuntu Xenial on ARMv8

    Then `ub` is Ubuntu Bionic, `ds` is Debian Stretch, and so on.
