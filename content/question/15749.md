  body_markdown: "I'll try to answer with an example:\n\nLet's assume that you want\
    \ to debug some code in the `LinearBatteryPlugin` that is shipped with Gazebo.\
    \ You can launch Gazebo with the `linear_battery_demo.world` for loading the plugin.\
    \ Let's also assume that your goal is to inspect the member variable `LinearBatteryPlugin::q`\
    \ within the function `LinearBatteryPlugin::OnUpdateVoltage()`. Here are the steps\
    \ for doing it using `gdb`:\n\n- Make sure that you compiled Gazebo (or your plugin)\
    \ with debug symbols. See [this reference tutorial](http://gazebosim.org/tutorials?tut=install_from_source).\n\
    - Start `gdb` specifying `gzserver` as the executable program:\n\n        gdb\
    \ gzserver\n\n- Start `gzserver` with (assuming that your current directory is\
    \ the top level directory of the Gazebo repository):\n\n        run worlds/linear_battery_demo.world\n\
    \n- You should see some `gdb` messages indicating that the program has started.\n\
    - Interrupt the execution of `gzserver` by pressing `CTRL-C`.\n- We're going to\
    \ create a breakpoint on a function. We can double check that `gdb` has the definition\
    \ of the function (note that we have to indicate the entire namespace):\n\n  \
    \      list gazebo::LinearBatteryPlugin::OnUpdateVoltage(const gazebo::common::BatteryPtr&)\n\
    \n\n- `gdb` should show a partial view of the source code:\n\n        123  this->Init();\n\
    \        124\t}\n        125\t\n        126\t/////////////////////////////////////////////////\n\
    \        127\tdouble LinearBatteryPlugin::OnUpdateVoltage(const common::BatteryPtr\
    \ &_battery)\n        128\t{\n        129\t  double dt = this->world->GetPhysicsEngine()->GetMaxStepSize();\n\
    \        130\t  double totalpower = 0.0;\n        131\t  double k = dt / this->tau;\n\
    \        132\t\n\n- Now, you can create your breakpoint:\n\n        break gazebo::LinearBatteryPlugin::OnUpdateVoltage(const\
    \ gazebo::common::BatteryPtr&)\n\n\n- `gdb` should confirm that the breakpoint\
    \ was created. It's time to resume the `gzserver` execution:\n\n        continue\n\
    \n- Your execution should be interrupted when the code entered `OnUpdateVoltage()`\
    \ and `gdb` should tell you that your breakpoint was hit:\n\n        Continuing.\n\
    \        [Switching to Thread 0x7fff797f7700 (LWP 20446)]\n    \n        Thread\
    \ 31 \"gzserver\" hit Breakpoint 1, gazebo::LinearBatteryPlugin::OnUpdateVoltage\
    \ (this=0x7fff44005a40, \n        _battery=\n        std::shared_ptr (count 4,\
    \ weak 1) 0x180ed20) at \n        /home/caguero/workspace/gazebo/plugins/LinearBatteryPlugin.cc:128\n\
    \        128\t{\n\n- Now you can inspect your `q` variable:\n\n        print q\n\
    \n- And `gdb` should tell you the value:\n\n        (gdb) print q\n        $1\
    \ = 1.1660311540299606\n\n\nHopefully this is what you're looking for. Alternatively,\
    \ if you're using Gazebo 8 we put in place an introspection system that is described\
    \ in [this tutorial](http://gazebosim.org/tutorials?tut=introspection&branch=introspection)\
    \ (currently under review)."

  - body_markdown: |-
      Try using LD_PRELOAD. Assuming your sharedlib has debug symbols/etc, the source file absolute paths are encoded in the .debug_info section so gdb *will* find them. It may be that the sharedlibrary is not loaded until your URDF is loaded and the plugin is requested. You can use LD_PRELOAD environment variable to preload your libs (ex. libmyplugin.so) and include the path to your plugin in LD_LIBRARY_PATH. (Separate multiple files/paths by colons.)
