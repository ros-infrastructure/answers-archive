    \n> It\u2019s important to understand how permissions work robot_upstart:\n\n\
    > 1. The upstart job invokes its `jobname-start` bash script as root.\n\n> 1.\
    \ The script sets up environment variables, and then uses setuidgid to execute\
    \ roslaunch as an unprivileged user. This is by default the user who ran the install\
    \ script, but it can also be specified explicitly via a flag.\n\n> 1. **The roslaunch\
    \ which executes does not have its user\u2019s group memberships**. This means\
    \ that it will **not have access to serial ports with the `dialout` group**, or\
    \ locations in /var/log owned by root, etc. Any filesystem resources needed by\
    \ your ROS nodes should be chowned to the same unprivileged user which will run\
    \ ROS, or should set to world readable/writeable, for example using udev.\n\n\
    So `jobname-start` starts out as user `root`, but then quickly drops all privileges\
    \ and continues as a regular user (that is not a member of the `dialout` or any\
    \ other group). There may be some more configuration required.\n"
