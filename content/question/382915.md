  body_markdown: |-
    ROS makes no guarantee that your subscriber gets all messages. You need to write your code so that it does something sensible **when** a message is lost. For example, networks go down. Also, you don't control the startup order of nodes, so your subscriber may not receive the first published messages.

    As a completely separate subject, your subscriber buffer size should be based on your estimate of the arriving message rate, and how bad it will be for the system if a huge number of messages are queued up, waiting. For a sort-of-real-time system like ROS, both too much data or stale sensor data can cause problems, so it can be an advantage to size the subscriber queue small enough to discard both categories of undesired messages.
