  body_markdown: "**Question number one has a few answers:**\n\nIf your measurement\
    \ error is constant, you can define it using the [ros paramater server](http://wiki.ros.org/Parameter%20Server)\
    \ in your [launchfile](http://wiki.ros.org/roslaunch) for your robot. Then read\
    \ the error paramater from the parameter server and insert it into the orientation\
    \ covariance matrix in a [geometry_msgs/PoseWithCovariance](http://docs.ros.org/api/geometry_msgs/html/msg/PoseWithCovariance.html).\
    \ You probably want to include that message as part of a [nav_msgs/Odometry](http://docs.ros.org/api/nav_msgs/html/msg/Odometry.html)\
    \ message.\n\nIn the following example, the parameter `z_rotation_covariance`\
    \ is defined in the launchfile:\n\n    <launch>\n      <param name=\"z_rotation_covariance\"\
    \ value=\"0.05\" />\n    </launch>\n\nTo use the parameter value in code, you'll\
    \ want to use the [rosparam api](http://wiki.ros.org/rospy/Overview/Parameter%20Server)\
    \ for your client. \n\nIf your error is a calculated or accumulated error, you\
    \ will want to set up a [service](http://wiki.ros.org/Services) to calculate the\
    \ changes as a function on some input and store the error in [rosbag](http://wiki.ros.org/rosbag)\
    \ and another service to retrieve the error from `rosbag` whenever you need to\
    \ use it in the orientation covariance matrix in a [geometry_msgs/PoseWithCovariance](http://docs.ros.org/api/geometry_msgs/html/msg/PoseWithCovariance.html).\
    \ You probably want to include that message as part of a [nav_msgs/Odometry](http://docs.ros.org/api/nav_msgs/html/msg/Odometry.html)\
    \ message.\n\nYou will need to [subscribe](http://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers)\
    \ to whatever topics are [publishing](http://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers)\
    \ the parameters of your error estimation function, probably using a [message_filter](http://wiki.ros.org/message_filters)\
    \ to combine the messages of several different topics into a single callback.\
    \ `ApproximateTimeSynchronizer` is a good filter for doing this. Then when your\
    \ filter callback is called, call your error calculation/accumulation service\
    \ to calculate and store your error, then you can retrieve it from rosbag at any\
    \ time using your error retrieval service.\n\n**Question number two is simpler:**\n\
    \nYou will want to model your robot using [urdf](http://wiki.ros.org/urdf). URDF\
    \ [joint tags](http://wiki.ros.org/urdf/XML/joint) allow you to specify joint\
    \ upper and lower limits, efforts, types, etc. You might look into using [Gazebo](http://gazebosim.org/tutorials?tut=ros_roslaunch&cat=connect_ros)\
    \ instead of Stage. It allows you to add several additional tags to your urdf\
    \ to model the physics properties of your robot during simulation."
