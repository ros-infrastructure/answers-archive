    I see two errors in your build log.

     1. rosdep is failing because it cannot detect your OS
     1. rospack (and therefore rosmake) cannot find the `sensor_msgs` package

    Solutions (I hope):

     1. Since Linaro is just an Ubuntu by another name, you could try the [ROS_OS_OVERRIDE](http://www.ros.org/wiki/ROS/EnvironmentVariables#ROS_OS_OVERRIDE) environment variable to tell ROS which Ubuntu distro it is derived from (and therefore pick up the right apt package names for the rosdep dependencies).
     1. Do you have a base ROS installation correctly installed? For example, diamondback-desktop-full or some other variant that includes things like ros_comm and sensor_msgs? You'll need to have some variant of Diamondback installed properly before installing the `camera_drivers` stack. Obviously, this will have to be installed from source as well since you are on the ARM board. If ROS is installed, is your `.bashrc` properly setup? If so, can you do `rospack find sensor_msgs` in a terminal?

  body_markdown: "After much poking and prodding, I was able to get camera_drivers,\
    \ image_pipeline, vision_opencv, et. al to compile.  I haven't tested whether\
    \ or not they function correctly, but I wanted to let everyone know.  Here's what\
    \ I did:\n\n`export ROS_OS_OVERRIDE=ubuntu:11.04`\n\nThis fixes the issue with\
    \ rosdep being unable to detect os.  I then found a base ROS installation that\
    \ contained all of the stacks I needed, the perception install, available here:\
    \ \n\n[http://packages.ros.org/cgi-bin/gen_rosinstall.py?rosdistro=diamondback&variant=perception&overlay=no](http://packages.ros.org/cgi-bin/gen_rosinstall.py?rosdistro=diamondback&variant=perception&overlay=no)\n\
    \nI edited out some packages I didn't need, but you can just as easily keep them\
    \ all.  I then used rosinstall to download everything:\n\n    rosinstall ~/ros\
    \ \"http://packages.ros.org/cgi-bin/gen_rosinstall.py?rosdistro=diamondback&variant=perception&overlay=no\"\
    \n\nNext, I compiled ros:\n\n    rosmake -i ros\n\nThen, I compiled the camera_drivers\
    \ package and others:\n\n    rosmake --rosdep-install camera1394 camera_calibration\
    \ image_proc\n\n Which, after many hours, compiled successfully.  \n\n---------------------------------------------------------------------------------------------\n\
    **Update:**\n\nI now have the camera up and running, publishing to a number of\
    \ image topics quite happily.  After getting the various bits of code required\
    \ compiled, it was fairly straightforward.  \n\nIn essence, you have to create\
    \ a udev rule.  With your favorite text editor, create a file in:\n\n    /etc/udev/rules.d/10-descriptivename.rules\n\
    \nAdd the following:\n\n    # udev rules file for CAMERA_NAME_HERE\n    BUS==\"\
    usb\", SYSFS{idVendor}==\"XXXX\", SYSFS{idProduct}==\"YYYY\", GROUP=\"admin\"\n\
    \nWhere CAMERA_NAME_HERE is the name for your camera (mine was Point Grey FireflyMV),\
    \ XXXX is your Vendor ID, and YYYY is your Product ID.  Both Vendor and Product\
    \ IDs can be found using\n\n    lsusb\n\nWith your camera plugged in.   \n\nOne\
    \ thing to note is that the group I'm using here is admin instead of plugdev.\
    \  Normally for security reasons, you would use plugdev, but on this particular\
    \ Linaro build, there is no plugdev group, and setting it up is somewhat of a\
    \ chore.  Admin works just fine, if you don't mind the small security threat it\
    \ poses.  \n\nAfter that, you can just `rosrun` your camera driver, and you're\
    \ off to the races.  I did find that the publishing rate for the image was about\
    \ half that of the frame rate of the camera.  I'm looking in to why the camera1394\
    \ node is running so slowly.  \n\nThanks for all the help!\n\n-Bradley Powers\n\
    \n"
