    \ were compiled for Python 2 rather than Python 3, which is needed for ROS 2.\n\
    \nFrom the [OpenCV chocolatey package description](https://chocolatey.org/packages/OpenCV):\n\
    \n> This package installs precompiled OpenCV binaries. This does not allow you\
    \ to customize the features compiled into your installation. This download is\
    \ about 193 MB.\nIf you wish to customize the features compiled in your installation,\
    \ then you must compile OpenCV yourself. \n\nI didn't see anything in the description\
    \ of the chocolatey package which hints at the target python interpreter for current\
    \ releases. If they've switched to Python 3, we may be able to deprecate our custom\
    \ binary distribution in favor of the chocolatey package."

  body_markdown: |-
    IIRC the Python bindings are not used by ROS 2 (though it could change in the [near future](https://github.com/ros2/demos/pull/107).
    At the time we weren't able to use the Chocolatey packages, not sure if they were non-existent or not built with VS2017.
    Another motivation for building a custom version was also to have (for internal testing) and to ship (to users) the debug libraries.

    As it looks like the Chocolatey packages came a long way in the last couple years, it may be worth reconsidering the chocolatey packages (and checking if they're built with Python 3 bindings for future-proofness). Though the debug libraries will likely not be included so users building in Debug would need to either build their own or ROS 2 releases could keep shipping a custom built archive.
