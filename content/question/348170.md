    According to [packages.debian.org](https://packages.debian.org/search?keywords=python-pycryptodome), `python-pycryptodome` is available starting in `stretch-backports`, and fully in `buster`. In Ubuntu it's available starting with `bionic` ([here](https://packages.ubuntu.com/search?keywords=python-pycryptodome)).

    Debian 9.12 would be Stretch. So it should at least be available in the backports repository.

    If you don't want to use that, you could append `--skip-keys="python-pycryptodome"` to the `rosdep` invocation.

    ---

    Edit: I just checked, and it seems [ros/rosdistro#22011](https://github.com/ros/rosdistro/pull/22011) added `pycryptodome` to the `rosdep` DB. @Dirk Thomas comments there:

    > On Debian Stretch the package is only available when using `stretch-backports`: [..]

    and:

    > We imported the package for Debian Stretch from the backports repo into the ROS repos: [ros-infrastructure/reprepro-updater#69](https://github.com/ros-infrastructure/reprepro-updater/pull/69).

    This seems to imply that if:

     - you have `packages.ros.org` configured as an `apt` repository on your system, and
     - you run one of the architectures for which the package has been imported

    you should be able to resolve the `python-pycryptodome` dependency using `apt`.

    Do you have the ROS repositories configured? What is the output of `apt-cache policy python-pycryptodome`?
