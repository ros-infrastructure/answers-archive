  body_markdown: "You have this in the `.launch` file you edited:\n\n>     <!-- start\
    \ this controller -->\n    <rosparam file=\"$(find ur_gazebo)/controller/arm_controller_ur5.yaml\"\
    \ command=\"load\"/>\n    <node name=\"arm_controller_spawner\" pkg=\"controller_manager\"\
    \ type=\"controller_manager\" args=\"spawn arm_controller\" respawn=\"false\"\
    \ output=\"screen\"/>\n>     \n    <!-- load other controllers -->\n    <node\
    \ name=\"ros_control_controller_manager\" pkg=\"controller_manager\" type=\"controller_manager\"\
    \ respawn=\"false\" output=\"screen\" args=\"load joint_group_position_controller\"\
    \ />\n>     \n    <node name=\"simple_controller\" pkg=\"controller_manager\"\
    \ type=\"controller_manager\" respawn=\"false\" output=\"screen\" args=\"load\
    \ prac\" />\n\nThe `simple_controller` node (which is essentially a `controller_manager`)\
    \ only `load`s the controller settings with the name `prac`.\n\nYou don't actually\
    \ *start* the controller. For that, you'd need to run the `controller_manager`\
    \ with the `spawn` argument.\n\nNote: with the current `.launch` file, the `arm_controller`\
    \ is `spawn`ed.\n\nYou cannot start two controllers for the same joint (*resource*\
    \ really) at the same time. That would lead to conflicts, and is specifically\
    \ prohibited.\n\nYou'll have to stop the running controller and then start your\
    \ `prac` controller. You could either do that in separate steps, or use the [switch_controller\
    \ service](http://wiki.ros.org/controller_manager#Services).\n\nNote also: because\
    \ your `prac` controller controls only a single joint, I expect the rest of the\
    \ robot to flail around in Gazebo."
