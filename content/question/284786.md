  body_markdown: "JetBrains now offers their own instructions on how to setup ROS\
    \ with CLion: [see here](https://www.jetbrains.com/help/clion/2018.3/ros-setup-tutorial.html)\n\
    ========================================\n\n----------\n\n\nCLion is a nice tool\
    \ but for me it did not work out of the box as claimed sometimes. This should\
    \ be a beginner (primary targeting students) friendly guide on how to use CLion\
    \ with ROS.\n\n\nHow to setup CLion with ROS (kinetic) [as simple as possible]:\n\
    ----------------\n\n\n*Note: this how to is tested on Ubuntu 16.04 with CLion\
    \ 2017.1.3 and 2017.3.2, the process might be different with other versions.\n\
    \nI recommend to check if `catkin_make` runs properly in your workspace before\
    \ you start with this guide. In this way you know CLion is the problem, not ROS.*\n\
    \n - Start CLion from the terminal to ensure everything is sourced properly. You\
    \ can alternatively edit the `.desktop` file, see below).\n - Click \"Import Project\
    \ from Sources\"\n - Select the `<your workspace path>/src` folder in your workspace\n\
    \ - Click \"Open Project\" - code editor should open\n - Go to \"File\" - \"Settings\"\
    \ - \"Build, Execution, Deployment\" - \"CMake\"\n - Set the generation Path to\
    \ `<your workspace path>/build` and apply\n - Finally you should right-click on\
    \ your top level `CMakeList.txt` file in CLion and select \"Reload CMake Project\"\
    \n\nCLion should work properly now.\n\n**Always start CLion from terminal unless\
    \ you changed the `.desktop` file!**\n\nRename Project/Workspace:\n----------------\n\
    \nAt the restart of CLion the Project will be shown at the recent projects with\
    \ the name \"src\". \nThe project/workspace can be renamed by renaming the `<your\
    \ workspace path>/src/.idea/src.iml` to `<your workspace name>.iml` and changing\
    \ the path to it in `<your workspace path>/src/.idea/modules.xml` and by creating\
    \ a file `<your workspace path>/src/.idea/.name` (containging only a name for\
    \ the project).\n\n    cd src/.idea\n    NEW_NAME=my_workspace\n    mv src.iml\
    \ $NEW_NAME.iml\n    sed -i -e \"s/src/$NEW_NAME/g\" modules.xml \n    printf\
    \ \"$NEW_NAME\" >  .name\n\n\nIf CLion shows you the info \"This file does not\
    \ belong to any project target\" right-click the `includes` folder an click \"\
    Mark Directory as\" and select \"Project Sources and Headers\". \n\nSetup debugging:\n\
    ----------------\n\n - Go to \"Run\" - \"Edit Configurations\" and click the add\
    \ button\n - Set a name\n - Select a \"Target\" and the according \"Executable\"\
    , keep the \"Configuration\" on Debug and apply\n\nNow you can run and debug from\
    \ the terminal. This does not work with `.launch` files\n\nHighlighting in `.launch`\
    \ files:\n--------------------------------\n\nCLion does not recognize `.launch`\
    \ files as XML files by default.\n\n - Go to \"File\" - \"Settings\" - \"Editor\"\
    \ - \"File Types\"\n - Search for XML in the recognized files list\n - add `*.launch`\n\
    \n.launch files should now have proper highlighting and autocomplete\n\n\nChange\
    \ the `.desktop` file:\n---------------------------\n\n - Go to `<your home folder>/.local/share/applications`\n\
    \ - change the according line the `.desktop` file for your CLion version to:\n\
    \n    `Exec=bash -i -c \"<clion installation path>/bin/clion.sh\" %f`\n\nNote:\n\
    -----\n\nCLion is free for students:  [students click here](https://www.jetbrains.com/student/)"
