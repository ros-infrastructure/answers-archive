  body_markdown: "So, as there has been no answer - I am posting the solution I found\
    \ myself...\nIt seems the \nWe wrote a code to `teleop_twist_keyboard` doesn't\
    \ give the quadrotor linear z velocity to go upward. So, if you start the quadrotor\
    \ at a height (let's say 1000 m) ... while it falls down you can move left/right\
    \ and so on.\n\nWe wrote our own [module](https://github.com/Quadrotor-RL/quadrotor_controller/tree/79e4ee4dd8b05cb1cc874c9b02d0af727f49963b)\
    \ to test it out which works. Here's the code :\n\n\n    #!/usr/bin/env python\n\
    \    \n    import rospy\n    import Tkinter as tk\n    import threading\n    import\
    \ thread\n    import time\n    from geometry_msgs.msg import Twist\n    import\
    \ pygame, sys\n    \n    def talker():\n        global clock\n    \n        pub\
    \ = rospy.Publisher('cmd_vel', Twist, queue_size=10)\n        rospy.init_node('controller',\
    \ anonymous=True)\n        rate = rospy.Rate(10) # 10hz\n        while not rospy.is_shutdown():\n\
    \            msg = Twist()\n            for event in pygame.event.get():\n   \
    \             if event.type == pygame.QUIT:\n                    pygame.quit()\n\
    \                    sys.exit()\n    \n            array = pygame.key.get_pressed()\n\
    \            if array[pygame.K_UP]:\n                msg.linear.z = 1;\n     \
    \       elif array[pygame.K_DOWN]:\n                msg.linear.z = -1;\n     \
    \       \n            if array[pygame.K_w]:\n                msg.linear.y = 1;\n\
    \            elif array[pygame.K_s]:\n                msg.linear.y = -1;\n   \
    \         \n            if array[pygame.K_d]:\n                msg.linear.x =\
    \ 1;\n            elif array[pygame.K_a]:\n                msg.linear.x = -1;\n\
    \    \n            rospy.loginfo(msg)\n            pub.publish(msg)\n        \
    \    rate.sleep()\n        \n    \n    pygame.init()\n    size = [100, 100]\n\
    \    screen = pygame.display.set_mode(size)\n    clock = pygame.time.Clock()\n\
    \    \n    if __name__ == '__main__':\n        # threading.Thread(target=tk_func())\
    \    \n        try:\n            talker()\n        except rospy.ROSInterruptException:\n\
    \            pass"

 I'm using `hector_quadrotor`, and am trying to get a simple quadrotor moving in it using my keyboard.

I run the demo using `roslaunch hector_quadrotor_demo outdoor_flight_gazebo.launch` and it gives out a few messages which can be seen [here](http://pastebin.com/ds5z8VJp) (There are no errors, but a few warnings are there)

Then I run `rosrun teleop_twist_keyboard teleop_twist_keyboard.py` which gives out the following [output](http://pastebin.com/wKERiyFf)

When i press u,i,o,j,k,l,m ... nothing happens

My understanding is that they send/recv messages on `/cmd_vel` to talk to each other. So, I read that I can see that using `rostopic info /cmd_vel` and i get :

	Type: geometry_msgs/Twist

	Publishers:

	Subscribers:

	Is /clock being published?
	linear: 
	  x: 0.5
	  y: 0.0
	  z: 0.0
	angular: 
	  x: 0.0
	  y: 0.0
	  z: 1.0
	---

when I press `u` in the `teleop_twist_keyboard`. So, it seems to be sending, but the `hector_quadrotor_demo` isn't catching it.

I am using Ubuntu 14.04 and ROS indigo. I installed all packages using the Ubuntu ppa for ROS and apt-get.
