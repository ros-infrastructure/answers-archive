    > Maybe the problem is in the unsupported distortion model "KANNALA_BRANDT"?

    That is a likely cause, yes.

    As [sensor_msgs/CameraInfo](http://docs.ros.org/api/sensor_msgs/html/msg/CameraInfo.html) mentions, legal values for that field are defined in `sensor_msgs/distortion_models.h`. Looking at that file shows (from [here](https://github.com/ros/common_msgs/blob/4804aa31c4df20c2143c7a09627a09039dafc1e0/sensor_msgs/include/sensor_msgs/distortion_models.h#L45-L47)):

    >     const std::string PLUMB_BOB = "plumb_bob";
        const std::string RATIONAL_POLYNOMIAL = "rational_polynomial";
        const std::string EQUIDISTANT = "equidistant";

    `KANNALA_BRANDT` is not in that list.

    It looks like it's also called a *fisheye* distortion model, and for that model there are several PRs open. The one against `ros/common_msgs` would be [ros/common_msgs#151](https://github.com/ros/common_msgs/pull/151).

    You may be able to get an idea of the current state of support for this particular distortion model from the linked issues and PRs.
