  body_markdown: "According to the tf python api docs [here](http://docs.ros.org/hydro/api/tf/html/python/tf_python.html#transformlistener)\
    \ for waitForTransform, it tells you \"*Waits for the given transformation to\
    \ become available. If the timeout occurs before the transformation becomes available,\
    \ raises tf.Exception.*\" Common thing alot of people have is that there is a\
    \ delay in the broadcasted tf messages being sent somewhere in your tf tree. Could\
    \ that somehow be a possibilty in your case?\n\n\n----------\n**EDIT:** \nWith\
    \ the pictures that you have posted, it shows that you have two base_link frame:\
    \ \n\n - Pioneer3AT/Pioneer3AT/base_link\n - Pioneer3AT/base_link\n\n'Pioneer3AT_Gazebo'\
    \ is broadcasting a transform from Pioneer3AT/odom --> **Pioneer3AT/base_link**\
    \ (the tf tree on the right side of the image), but all of your wheels, sensors,\
    \ top plate, axels, etc. are all being transformed into the frame **Pioneer3AT/Pioneer3AT/base_link**.\
    \ This is where your problem is. \n\nYou can simply fix this by changing your\
    \ Pioneer3AT_tf_broadcaster node to publish a transform from your sonars, axels,\
    \ and top plate to frame id Pioneer3AT/base_link *instead* of Pioneer3AT/Pioneer3AT/base_link.\n\
    \nShould look something like this for the Pioneer3AT/front_sonar --> Pioneer3AT/base_link:\n\
    \n    broadcaster.sendTransform(\n\t\t\t\ttf::StampedTransform(tf::Transform(tf::Quaternion(x,\
    \ y, z, w), tf::Vector3(x, y, z)),\n  \t\t        ros::Time::now(),\"Pioneer3AT/base_link\"\
    , \"Pioneer3AT/front_sonar\"));\n\nHope that fixes it. Take out the Pioneer3AT/Pioneer3AT/base_link\
    \ frame, switch it with Pioneer3AT/base_link, and your tf tree should be connected\

**Solution**

Using the launch/core/urdf.launch listed here: https://github.com/dawonn/ros-pioneer3at/blob/1ac3f552a487495c049333fa5c51bc37c8b5dd75/launch/core/urdf.launch on git. A user needs to Look at line 6: <param name="tf_prefix" type="string" value="Pioneer3AT"/> This puts a prefix on published transforms from this node. Removing it or changing value to "", takes out undesired "Pioneer3AT".

A possible second fix, modify xacro file listed here: https://github.com/dawonn/ros-pioneer3at/blob/1ac3f552a487495c049333fa5c51bc37c8b5dd75/urdf/pioneer3at.xacro  on line 12, chassis link already has Pioneer3AT in its name. Try renaming it just to "base_link" after cloning the ros-pioneer3at repo to the workspace and modify it there. I will update with second fix for a cleaner solution provided by Gustavo Adolfo Velasco Hernández.
