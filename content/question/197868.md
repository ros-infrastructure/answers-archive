  body_markdown: "Yes. A node can be a subscriber and a client at the same time.\n\
    \nWe needed a node that could subscribe to a topic and call a service request\
    \ from another node at any given time. I couldn't find any solutions (probably\
    \ because it is a relatively simple concept)... but I think there should be some\
    \ documentation for other people stuck with the same problem. \n\n**The problem\
    \ we were having:** Most of the service request examples have the service request\
    \ being called from inside the main function. When we tried to do this, we were\
    \ only able to request a service once and then the node would be caught in a spin\
    \ loop. To avoid this error, we decided to move the service request into the subscriber\
    \ callback function. This way it would be called whenever the subscriber heard\
    \ a message.\n\n**The basic idea:**  The client is instantiated in the main function,\
    \ but it needs to be used in the callback function. I made a ros::ServiceClient\
    \ pointer at a global level (w.r.t. the node) and then gave it the address of\
    \ the client. In the callback function I dereference the client pointer and use\
    \ it to request a service. \n\n \n\n     void SUBSCRIBE_CALLBACK_FUNCTION (const\
    \ PACKAGE_NAME::MESSAGE_NAME::ConstPtr& msg);\n        ros::ServiceClient *clientPtr;\
    \ //pointer for a client\n        \n        int main (int argc, char **argv)\n\
    \        {\n        \n        \tros::init(argc, argv, \"MY_NODE\");\n        \t\
    ros::NodeHandle n;\n        \tros::ServiceClient client = n.serviceClient<PACKAGE_NAME::SERVICE_NAME>(\"\
    SERVICE_NAME\"); //create the client\n        \t\n        \tclientPtr = &client;\
    \ //give the address of the client to the clientPtr\n        \n        \tros::Subscriber\
    \ sub = n.subscribe<PACKAGE_NAME::MESSAGE_NAME>(\"TOPIC_NAME\",1000,SUBSCRIBE_CALLBACK_FUNCTION);\
    \ //subscribing\n        \n        \tros::spin();\n        \n        \treturn\
    \ 0;\n        \n        }\n        \n        void SUBSCRIBE_CALLBACK_FUNCTION\
    \ (const PACKAGE_NAME::MESSAGE_NAME::ConstPtr& msg)\n        {\n        \tPACKAGE_NAME::SERVICE_NAME\
    \ srv;\n        \tsrv.request.someBool= false; //just some variables to give the\
    \ service some structure.\n        \tsrv.request.someFloat = 4;\n        \tsrv.request.someFloat\
    \ = 30;\n        \t\n        \tros::ServiceClient client = (ros::ServiceClient)*clientPtr;\
    \ //dereference the clientPtr\n        \n        \tif(client.call(srv)) //request\
    \ service from the client\n        \t{\n        \t\tROS_INFO(\"Success = %d\"\
    , srv.response.success);\n        \t}\t\n        \telse\n        \t{\n       \
    \ \t\tROS_ERROR(\"Failed to call service from motor_control_node\");\t\n     \
    \   \t}\n        \n        }\n\n\n\n"

  body_markdown: "I think the answer to your primary question is clear, Yes they can\
    \ have / be both!\n\nThere are several tutorials which describe the background,\
    \ I dont think a all in one tutorial is needed. \n\nLook at this tutorial for\
    \ the ros main-loop behaviour:\nhttp://wiki.ros.org/ROS/Tutorials/WritingPublisherSubscriber%28c%2B%2B%29\n\
    \nLook at this tutorial for the server-client stuff:\nhttp://wiki.ros.org/ROS/Tutorials/WritingServiceClient%28c%2B%2B%29\n\
    \nIf putting both together you will have a basic understanding to find the solution\
    \ for your problem. Of course you can also use Nodelet's but they are more C++\
    \ object oriented style, so there you don't have a main-loop anymore, you can\
    \ only use callbacks which includes timer callbacks desribed here:\n\nhttp://wiki.ros.org/roscpp/Overview/Timers\n\
    \nAnd now some notes regarding your code:\n\n 1. Why dereference pointer, you\
    \ can also do clientPtr->call(srv). You don't have to use a ptr at all.\n 2. You\
    \ don't have to call ros::spin(), you can also use ros::spinOnce(), so you will\
    \ have your main loop to call the service.\n 3. Make sure that you know when and\
    \ how often you want to call the service. Everytime you got a incoming message\
    \ (subscribed topic callback), every frame in your main loop (inside spinOnce\
    \ main-loop), or maybe every x seconds (Timer callbacks). And this are only the\
    \ synchronious ones.\n\n \n\n"
