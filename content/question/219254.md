  body_markdown: " Let's say node A has created it's publisher using something like\
    \ \n\n    ros::Publisher pub = node.advertise<std_msgs::Twist>(\"turtle1/cmd_vel\"\
    , 100);\n\nand node B has subscribed using something like\n\n    ros::Subscriber\
    \ sub = node.subscribe(\"cmd_vel\", 100, datacb);\n\nI believe that is the situation\
    \ you are describing. Then the question is how to get the subscriber in B to successfully\
    \ subscribe to the topic published by A. This is fundamentally a question of how\
    \ [ROS Names are resolved](http://wiki.ros.org/Names#Resolving). Below are a few\
    \ possible solutions. The correct solution depends on your specific application:\n\
    \n- **Remapping** You could use \"ROS Remapping\" to either remap the publisher\
    \ or the subscriber to be the correct topic. This can be done with `rosrun` via\
    \ [Remapping Arguments](http://wiki.ros.org/Remapping%20Arguments), or in `roslaunch`\
    \ via the [remap tag](http://wiki.ros.org/roslaunch/XML/remap).\n- **Namespaces**\
    \ You could modify the namespace that node B is in so that it runs in the `turtle1/`\
    \ namespace. Then its subscriber would automatically resolve to `turtle1/cmd_vel`.\
    \ This could be done using the `ns` attribute of either the [node tag](http://wiki.ros.org/roslaunch/XML/node)\
    \  or the [group tag](http://wiki.ros.org/roslaunch/XML/group). You could also\
    \ modify the namespace of a node at the command line with the [ROS_NAMESPACE](http://wiki.ros.org/ROS/EnvironmentVariables#ROS_NAMESPACE)\
    \ environment variable."
