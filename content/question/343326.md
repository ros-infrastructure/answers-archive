  body_markdown: "**EDIT**\n\nThere is new discussion about this answer not being\
    \ able to interact with GDB because launch doesn't allow a process to access stdin.\
    \ That discussion is [on an issue in the launch_ros repo](https://github.com/ros2/launch_ros/issues/165#issuecomment-686635595).\
    \ \n\n[One workaround is to add `xterm -e` to the start of the prefix](https://github.com/samsung-ros/gdb_test_pkg/pull/1/files)\
    \ to open an new xterm window with the process. In this case, use the prefix `xterm\
    \ -e gdb -ex=r --args`.\n\nThere's another very similar question and answer in\
    \ #q267261\n\n---\n**Original answer**\n\n`launch_ros.actions.Node` inherits from\
    \ `launch.actions.ExecuteProcess`, and it passes extra arguments given to `__init__`\
    \ to it. I think you're looking for [prefix](https://github.com/ros2/launch/blob/4333910ba41977f3ab9867082c86a8698ada3a16/launch/launch/actions/execute_process.py#L101).\n\
    \nSave this file as `gdb_pub_launch.py`\n\n    from launch import LaunchDescription\n\
    \    from launch import LaunchService\n    \n    import launch_ros.actions\n \
    \   \n    \n    def generate_launch_description():\n        \"\"\"Run demo nodes\
    \ via launch.\"\"\"\n        ld = LaunchDescription([\n            launch_ros.actions.Node(\n\
    \                package='demo_nodes_cpp', node_executable='talker', output='screen',\n\
    \                remappings=[('chatter', 'my_chatter')],\n                prefix=['gdb\
    \ -ex=r --args'],\n            )\n        ])\n        return ld\n\n\nAnd run with\n\
    \n    ros2 launch gdb_pub_launch.py"

 ROS 1 launch files allowed to run nodes in a debugger, e.g. using `launch_prefix="gdb --args"`. I tried to use it with ROS 2 by adding this parameter to `launch_ros.actions.Node`, but it just caused parsing errors. Is there still a way to specify such a prefix in ROS 2 launch files?
