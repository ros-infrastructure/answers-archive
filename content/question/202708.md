  body_markdown: "Why would you want to use AnyMsg if you know the topic name and\
    \ topic type? In that case, you could use a simple subscriber:\n\n    import rospy\n\
    \    from sensor_msgs.msg import Imu\n    \n    def cb(msg):\n        print msg\n\
    \        \n    rospy.init_node('mynode')\n    rospy.Subscriber('/imu', Imu, cb)\n\
    \    rospy.spin()\n\n\nBut even if you don't know topic name and type beforehand,\
    \ you can subscribe to any topic and get the deserialized messages. I've written\
    \ a small script to demonstrate this:\n\n    import rospy\n    import rostopic\n\
    \    import rosgraph\n\n    rospy.init_node('mynode')\n\n    topics = [t for t,\
    \ _ in rosgraph.Master('/mynode').getPublishedTopics('') if not t.startswith('/rosout')]\n\
    \n    for t in topics:\n        msg_class, _, _ = rostopic.get_topic_class(t)\n\
    \        msg = rospy.wait_for_message(t, msg_class)\n        print \"\\n\\n================================================================================\"\
    \n        print \"received a message on topic %s:\" % t\n        print msg\n\n\
    The script simply gets one message from each published topic and prints it. The\
    \ `msg` object is a fully deserialized message, so you can do anything with it;\
    \ for example, if the message has a `header` field, you can access it via `msg.header`.\
    \ If you're interested in all messages from a topic (instead of just a single\
    \ one), simply use a `rospy.Subscriber` instead of `rospy.wait_for_message()`."

        from roslib.message import get_message_class
        from rospy.msg import AnyMsg
        ...
                self._sub = rospy.Subscriber('~input', AnyMsg, self._cb)

            def _cb(self, anymsg):
                topic_types = self._master.getTopicTypes()
                msg_name = [ty for tp, ty in topic_types if tp == self._sub.name][0]
                msg_class = get_message_class(msg_name)
                msg = msg_class().deserialize(anymsg._buff)

    I used it in a subscriber bootstrapping technique where an AnyMsg is subscribed to, then there is a check to see if the message has a header, then that first subscriber is unsubscribed and a second subscriber that is of the proper type is created (but I didn't give much example code) #q230676

    In other cases I've used it to subscribe to topics where a warning is generated if the topic hasn't published recently, the AnyMsg prevents deserialization overhead and I can subscribe to any number of different types of topics using the same code.  That is similar to the bandwidth calculation.

    (One thing to note is that rospy doesn't like two concurrent subscribers in the same node on the same topic with different types- if one is AnyMsg and the other is the full topic type- the message is delivered to both callbacks as an AnyMsg, https://github.com/ros/ros_comm/issues/1351)
