  body_markdown: "The key is the imports from the move_base_msgs.msg\n\nA simple example\n\
    \n    import actionlib\n    import rospy\n    from move_base_msgs.msg import MoveBaseAction,\
    \ MoveBaseGoal, MoveBaseFeedback, MoveBaseResult\n    \n    rospy.init_node('send_client_goal')\n\
    \    \n    client = actionlib.SimpleActionClient('/move_base', MoveBaseAction)\n\
    \    rospy.loginfo(\"Waiting for move base server\")\n    client.wait_for_server()\n\
    \    \n    goal = MoveBaseGoal()\n    goal.target_pose.header.frame_id = 'map'\
    \ \n    goal.target_pose.pose.position.x = -0.063\n    goal.target_pose.pose.position.y\
    \ = -9.035\n    goal.target_pose.pose.orientation.z = 0.727\n    goal.target_pose.pose.orientation.w\
    \ = 0.686\n    \n    client.send_goal(goal)\n    client.wait_for_result()\n\n\
    \    goal.target_pose.header.frame_id = 'map' \n    goal.target_pose.pose.position.x\
    \ = new value\n    goal.target_pose.pose.position.y = new value\n    goal.target_pose.pose.orientation.z\
    \ = new value\n    goal.target_pose.pose.orientation.w = new value\n    \n   \
    \ client.send_goal(goal)\n    client.wait_for_result()\n\nand so on you can use\
    \ a loop to make it move from goal to goal also. \n\nThere are two simple ways\
    \ to get valid positions and orientations for the environment you're robots in:\n\
    \n1. Use RViz and set the 2D pose followed the the 2D goal go back to where you\
    \ launched RViz and the goal position should print out.\n2. This is the simple\
    \ method use: rosrun tf tf_echo /map /base_link and this will print position/orientation\
    \ the entire time the robot is moving. \n \nYou can also create a feedback callback\
    \ and get the result with:\n\n    client.wait_for_result()\n    result = client.get_result()\n\
    \nYou can send any number of goals without creating multiple goals:\n\njust place\
    \ the `client.wait_for_result()` between calls\n\nHope this helps."
