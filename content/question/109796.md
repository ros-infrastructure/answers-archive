  body_markdown: "1. ROS isn't technically a computer operating system, as it requires\
    \ some other operating system as a base. However, it can be considered analogous\
    \ to an operating system in that it provides a standardized way of interacting\
    \ with and developing for a variety of hardware types. \nThis is similar to how\
    \ Windows and Linux can run on machines with different processors, memory, peripherals\
    \ etc.\nIt also is designed to be easily extensible, such that new software can\
    \ be developed to work in conjunction with ROS.\n\n2. ROS is designed to be an\
    \ object-based, parallel control system. This means that each node in ROS can\
    \ be doing its own thing, but can communicate with other nodes where necessary.\
    \ ROS allows for sensors, actuators, and software components to run (effectively)\
    \ simultaneously. If you were attempting to program a robot in say, C,  (as for\
    \ a micro controller) you would have to create a control loop which periodically\
    \ checked sensors, adjusted actuators and performed calculations. Managing the\
    \ delicate timing required for real time operation in such an environment is complicated\
    \ to say the least.\nROS nodes communicate primarily through Topics and Services.\
    \ Topics can be thought of as putting up a poster - you don't know when someone\
    \ has read it, but anyone who wants to read it can find it.\nServices are more\
    \ like organizing a meeting - both nodes connect, exchange information and then\
    \ disconnect. They know for certain that the information has gone through, and\
    \ can know who knows it.\n\n3. ROS distributions usually come with an assortment\
    \ of drivers for some common hardware, but the true capacity of ROS is realized\
    \ in the drivers and support offered by the User-Community. I'd head to the [ROS\
    \ wiki](http://wiki.ros.org) to start to find out about the range of hardware\
    \ for which there is development."
