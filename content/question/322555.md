  body_markdown: "The problem is in your void `void QNode::run()` function.   The\
    \ while loop in this function makes this a \"blocking function\" meaning that\
    \ the processor never gets handed back to the GUI to update.   The way I usually\
    \ deal with this problem is by using a qTimer.   \n\nBasically you want to create\
    \ a timer in your main_window tells ROS things to happen.   In between timer calls\
    \ the GUI will be able to update properly.\n\nAdd the following member to your\
    \ main_window.hpp\n\n    #include <QTimer>\n    ...\n    class MainWindow : public\
    \ QMainWindow{\n    ...\n\n    private slots:\n        void spin_ros();\n    private:\n\
    \        QTimer *rosTimer;\n    ...\n    }\n\n**In your main_window.cpp**\n\n\
    in your constructor add: \n\n    rosTimer = new QTimer(this);\n    connect(rosTimer,\
    \ SIGNAL(timeout()), this, SLOT(spin_ros()));\n    rosTimer->start(10);  // set\
    \ your spin rate here\n\nimplement the `spin_ros()` function we declared in the\
    \ header.   This will be the function that does the body of your while loop in`void\
    \ QNode::run()`function.\n\n    void MainWindow::spin_ros(){\n        myQnode.runOnce();\
    \   // you will need to modify QNode::run so it only does one loop iteration when\
    \ called!\n    }\n\nPlausible function for QNode::runOnce():\n\n    void QNode::runOnce()\
    \ {\n            if(ros::ok() && rawpacketpolling())\n            {\n        \
    \        pub_topicmsg_.publish(topicmessage);\n\n                Q_EMIT logunitsmessages(topicmessage.msg1,\
    \ topicmessage.msg2); // EMIT after messages is decoded.\n\n                ros::spinOnce();\n\
    \                loop_rate.sleep();\n            }\n    }\n"
