  body_markdown: "I am also working on something similar to run repetitive experiments.\
    \ Some things that helped my in addition to similar things in the last answer\
    \ are the following:\n\n* I have a [very simple ROS node](https://github.com/uuvsimulator/uuv_simulator/blob/master/uuv_assistants/scripts/unpause_simulation.py)\
    \ that I always start with my simulation to unpause the simulation at every iteration\
    \ to make sure all nodes have time to start.\n* To end every iteration after a\
    \ fixed max. simulation time, I start also [this node](https://github.com/uuvsimulator/uuv_simulator/blob/master/uuv_assistants/scripts/set_simulation_timer.py)\
    \ with a timer using the simulation time with the `required=\"true\"` option to\
    \ kill all nodes in the launch file once the timeout is reached.\n* I wrote a\
    \ [`simulation runner` script](https://github.com/uuvsimulator/uuv_simulation_evaluation/blob/master/uuv_simulation_wrapper/src/uuv_simulation_runner/simulation_runner.py)\
    \ that starts the [launch file with all my nodes, including Gazebo](https://github.com/uuvsimulator/uuv_simulation_evaluation/blob/master/uuv_evaluation_examples/uuv_smac_example/launch/start_smac_task.launch)\
    \ and then makes sure to store log files and the ROS bag in a user-defined folder,\
    \ being also possible to override some of the input arguments of the launch file\
    \ using [this YAML configuration](https://github.com/uuvsimulator/uuv_simulation_evaluation/blob/master/uuv_evaluation_examples/uuv_smac_example/smac_config/task.yml)\
    \ in order to allow an optimizer, for example, to change the parameters of the\
    \ simulation run. This [simulation pool](https://github.com/uuvsimulator/uuv_simulation_evaluation/blob/master/uuv_smac_utils/src/uuv_smac_utils/simulation_pool.py)\
    \ also orchestrates the different runs just in case you want to have multiple\
    \ simulations running in parallel. \n\nI have found out that the number of Gazebo\
    \ instances running at the same time cannot be too high, otherwise they start\
    \ having Seg Faults, showing some errors that are related to the rendering. I\
    \ still haven't figured out why that happens.\nIf you pack your simulation in\
    \ a Docker container, you might also control that by setting, for example, the\
    \ number of CPUs used, that helped my simulations a little bit so I could run\
    \ multiple instances on the same machine.\n\nI would just advise you not to use\
    \ Gazebo 9 right away because of [this issue](https://github.com/ros-simulation/gazebo_ros_pkgs/issues/751).\
    \ The `gzserver` is not being finished correctly after the `gazebo_ros` node dies,\
    \ so it starts building up a bunch of processes with each iterations. Starting\
    \ `ROS_MASTER_URI` and `GAZEBO_MASTER_URI` with different ports every time like\
    \ done here in the [`simulation wrapper` script](https://github.com/uuvsimulator/uuv_simulation_evaluation/blob/master/uuv_simulation_wrapper/src/uuv_simulation_runner/simulation_runner.py#L216)\
    \ is really important, especially if you want to still keep working on other things\
    \ and running simulations manually while your simulations run in the background."
