    The typical answer to this would be to make use of [ros_buildfarm](https://github.com/ros-infrastructure/ros_buildfarm) and related packages to setup your own private instance of a ROS buildfarm (similar to [build.ros.org](http://build.ros.org/)). Nothing would have to be public in that case (although setting up deployments from private GH/BitBucket/etc repositories is something that has a few rough edges (see the [issue tracker](https://github.com/ros-infrastructure/ros_buildfarm/issues))).

    There have been a number of presentations about the ROS buildfarm at ROSCon, [The ROS build farm - what it can do for me](https://vimeo.com/187705230) ([slides](https://roscon.ros.org/2016/presentations/ROSCon2016%20Build%20Farm.pdf)) is one of those. It's from ROSCon'16, but probably still provides a good overview.

    There are various alternatives to the buildfarm, ranging from manually `catkin build`-ing a workspace and tarring that, all the way to using deployment platforms like [snap](https://docs.snapcraft.io/ros-applications/7822) and [mender](https://mender.io/) to ["bundles"](https://vimeo.com/187705228) ([slides](https://roscon.ros.org/2016/presentations/ros-bundling.pdf)), [buildbot-ros](https://github.com/mikeferguson/buildbot-ros), multi-stage Docker setups ([Hermetic Robot Deployment Using Multi-Stage Dockers](https://vimeo.com/293626218) ([slides](https://roscon.ros.org/2018/presentations/ROSCon2018_multistage_docker_for_robot_deployment.pdf))) and many more.

    Which one of these approaches works best for you is something I don't believe we can answer here, but if you have specific questions about any of them, I'd suggest you post additional questions either here or on the trackers of the respective projects.

I'm currently investigating ways to manage ROS packages between development machines and runtime machines. Ideally we would like to version and deploy our ROS packages to a private registry (or public, depending on the package) as a library, such that we can configure our runtime machine with specific versions of the packages that it can find on these private or public registries.

In other words, a system akin to npm, pip or maven for ROS packages. Is this available for ROS? Are there plans to make it available in case it isn't right now? Or are there specific reasons against using such a system?
