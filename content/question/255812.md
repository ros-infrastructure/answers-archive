  body_markdown: "    In summary how does the UCTF game concept function?\n\nUCTF\
    \ is flying N vehicles at a time simulating as closely as possible real flight\
    \ configurations. Such as running the real autopilots. This is an active subproject\
    \ of the SASC project, and under active development. At the end I hope to fully\
    \ document how to run it for public consumption but right now we're focused on\
    \ supporting others inside the project.\n\n\n    How can I find the publisher\
    \ for each UAV for the mavros topics : mavros/state and /mavros/global_position/global\
    \ e.g /iris_5/mavros/state and /iris_5/mavros/global_position/global?\n\nEach\
    \ vehicle has it's own ROS master on which it talks. If you watch the console\
    \ output of the startup you can see the masters come up on specific ports.\n\n\
    \    How can I send waypoints to a UAV separately e.g iris_5?\n\nContact each\
    \ drone on it's own master URI. You have full contact there. Or you can use QGroundControl\
    \ or other ground station. https://github.com/osrf/uctf/tree/master/doc/run_example#use-qgroundcontrol\n\
    \n    Why does the state of each UAV not published to mavros e.g /iris_5/mavros/state\n\
    \nI'm not sure I understand this question. I think in general you're missing that\
    \ there are multiple masters. \n\n    How can I find where the system publishes\
    \ of each UAV of /mavros/state and /mavros/global_position/global?\n\nAgain see\
    \ each individual master. \n\nAlso if you're just wanting to simulate multiple\
    \ drones and not the full SASC setup I recommend using the --no-payload option,\
