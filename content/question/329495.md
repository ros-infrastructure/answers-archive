I was perplexed on a recent commit preview to see this symbol on github after a `.srv` file with no return:

![image description](https://i.stack.imgur.com/Cuix4.png)

I posted [a question](https://stackoverflow.com/questions/57228265/red-circle-with-slash-through-it-and-carriage-return-symbol-in-pull-request-chan) on SO, which turned out to be a duplicate of [this one](https://stackoverflow.com/questions/34271528/what-is-little-red-arrow-and-no-sign-in-github-desktop/34273643#34273643), which enlightened me via [this one](https://stackoverflow.com/questions/5813311/no-newline-at-end-of-file/5813359#5813359) and a subsequent [link](https://stackoverflow.com/questions/729692/why-should-text-files-end-with-a-newline) in a comment that apparently lines not ending in a newline may not be lines at all!

Re-quoting their [POSIX standard](https://pubs.opengroup.org/onlinepubs/9699919799/basedefs/V1_chap03.html#tag_03_206) citation for convenience:
> 3.206 Line

> A sequence of zero or more non- <newline> characters plus a terminating <newline> character.

[The answer](https://stackoverflow.com/questions/5813311/no-newline-at-end-of-file/5813359#5813359) to one of these questions advises:

>Note that it is a good style to always put the newline as a last character if it is allowed by the file format. Furthermore, for example, for C and C++ header files it is required by the language standard.

I can't find anything stating 1) whether or not any downsides occur to having a newline in `.msg` files, 2) if it's explicitly permitted (presumably so) or 3) if it's advised to always use them.
