  body_markdown: "tl;dr: there is no *mobile* variant. So the error you receive would\
    \ seem to be expected.\n\n---\n\nAll variants are defined in [REP 150: ROS Melodic\
    \ and Newer Metapackages](https://www.ros.org/reps/rep-0150.html).\n\nFor ROS\
    \ Melodic, they include:\n\n - `ros_core`\n - `ros_base`\n - `robot`\n - `perception`\n\
    \ - `simulators`\n - `viz`\n - `desktop`, and\n - `desktop_full`\n\n`mobile` is\
    \ not a defined variant.\n\nWhere did you see it mentioned?\n\n> it does not include\
    \ navigation stack and what I would consider other mandatory packages\n\nThe navigation\
    \ packages are not included in any variant. Or at least, not in a variant defined\
    \ by REP 150.\n\n---\n\nEdit:\n\n> Thanks for pointing out REP 150. I was not\
    \ aware of that REP, as I was simply following what appears in: http://wiki.ros.org/Installation/Source\n\
    > \n> ie. \"In addition to the 3 variants above, more are defined in **REP 131**\
    \ such as robot...\"\n\nLooks like that page needs to be updated for Melodic and\
    \ should point to REP 150.\n\n> Note that REP 131 DOES include \"mobile\" (and\
    \ also navigation!). \n\nYes, it does.\n\n> I am surprised to find that REP 150\
    \ contains no variant that includes navigation. What is the thinking behind that?\n\
    \nI'm not sure. It looks like `mobile` (and some of the other variants) already\
    \ didn't appear any more in REP-142 (which was submitted in [ros-infrastructure/rep#71](https://github.com/ros-infrastructure/rep/pull/71)).\n\
    \nI've tried to find related discussions on the old ROS mailing lists, but nothing\
    \ really turns up.\n\nPerhaps @tfoote remembers why those variants were removed.\n\
    \n> How should I build from source to include navigation?\n\nThe top-level (ie:\
    \ meta) package for navigation appears to be called [navigation](http://wiki.ros.org/navigation)\
    \ (who'd have thought? ;)).\n\nSo you should be able to do something like this:\n\
    \n    rosinstall_generator --rosdistro=kinetic --tar --deps navigation > navigation.rosinstall\n\
    \nThat should get you all packages in the `navigation` metapackage.\n\n**But**:\
    \ please make sure you actually need to build things from source. You state you\
    \ are running \"ROS Melodic, Ubuntu 18.04 (64-bit)\" on an RPi. If I'm not mistaken,\
    \ that would be `bionic` on `arm64` (or ARMv8). According to [this page](http://repositories.ros.org/status_page/ros_melodic_ubv8.html)\
    \ there are plenty of binary packages available for that combination.\n\nRefer\
    \ to #q320046 for information on how to figure out when something is available\
    \ as a binary package, and for which platforms.\n\n---\n\nEdit 2:\n\n>  Thanks\
    \ for the comments and suggestions. Yes, I do indeed actually need to build from\
    \ source. \n\nAs long as you are absolutely sure.\n\n>  And I would like the equivalent\
    \ of \"mobile\" as specified in REP 131. But regarding your suggestion:\n\n> \
    \    rosinstall_generator --rosdistro=kinetic --tar --deps navigation > navigation.rosinstall\n\
    \n> ... the above just gives me the navigation sources and omits everything else.\
    \ So, manually merge the two 'src' trees (obtained from variants navigation and\
    \ base)? Or what?\n\nthere is no need to manually do anything. Either:\n\n - ask\
    \ `wstool` to `merge` in the new `.rosinstall` file, or\n - supply `rosinstall_generator`\
    \ with more package names instead of just the one. Like so:\n\n        rosinstall_generator\
    \ --rosdistro=kinetic --tar --deps robot navigation slam_gmapping laser_pipeline\
    \ perception_pcl > robot_and_navigation.rosinstall\n\nRefer to the `rosinstall_generator\
    \ --help` for more information on which combinations of options can be used.\n\
