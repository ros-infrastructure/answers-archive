  body_markdown: "The cause behind this unrealistic interaction (that is, this lack\
    \ of friction) is the use of `PositionJointInterface` for the UR10 joints.  [Here](https://github.com/ros-industrial/universal_robot/commit/6c4318a3c0024be31e919cdd30741456f4eaf778#comments)'s\
    \ a decent explanation of the phenomenon: \n\n> ... using 'set position' or 'set\n\
    > velocity' in gazebo forces the physics\n> simulation to try and accomplish this,\n\
    > which results in strange behavior.\n> It's actually preferable, according to\n\
    > the Gazebo team members I'm working\n> with, to always use 'set force' in\n\
    > Gazebo because that allows a more\n> normal interaction when the commanded\n\
    > force of an arm joint puts the arm in\n> contact with the environment.\n\n \
    \ Following [an example](https://github.com/ros-industrial/universal_robot/commit/6c4318a3c0024be31e919cdd30741456f4eaf778),\
    \ I made local changes to the `universal_robot` package to use `EffortJointInterface`\
    \ instead.  [Some gain values from ARIAC](https://bitbucket.org/osrf/ariac/src/de9f92a60aab743c6c7f8bf273cb732c34a51320/osrf_gear/launch/ur10/arm_controller_ur10_custom.yaml?at=ariac_2017&fileviewer=file-view-default#arm_controller_ur10_custom.yaml-21:28)\
    \ provide decent performance.  Thanks to everyone who contributed suggestions!"
