  body_markdown: "Hi,\nI believe this is a perfectly valid question still in 2022,\
    \ and not immediately clear from the tf/tf2 documentation and papers or REP 103,\
    \ due to lack of the \"intrinsic\" and \"extrinsic\" rotation in the terminology.\n\
    \nFirstly, verbal overview in http://wiki.ros.org/tf/Overview/Transformations\
    \ states that \n\n> \"the rotation of the frame A in W's coordinate system.\"\n\
    \nwhich hints that rotation of A is represented in the external coordinate system\
    \ of W, hence **extrinsic rotation**\n\nSecondly, doing a bit reverse-engineering,\
    \ one could see that \n\n    static_transform_publisher x y z yaw pitch roll frame_id\
    \ child_frame_id\nway of using static tf, calls the following lines: https://github.com/ros/geometry2/blob/c73b5939723db078c9bbe18523230ad54f859682/tf2_ros/src/static_transform_broadcaster_program.cpp#L80\
    \ \n\n    tf2::Quaternion quat;\n    quat.setRPY(atof(argv[6]), atof(argv[5]),\
    \ atof(argv[4]));\n    msg.transform.rotation.x = quat.x();\n    msg.transform.rotation.y\
    \ = quat.y();\n    msg.transform.rotation.z = quat.z();\n    msg.transform.rotation.w\
    \ = quat.w();\nwhich in turn calls : https://github.com/ros/geometry2/blob/c73b5939723db078c9bbe18523230ad54f859682/tf2/include/tf2/LinearMath/Quaternion.h#L95\n\
    \n\n      /**@brief Set the quaternion using fixed axis RPY\n       * @param roll\
    \ Angle around X \n       * @param pitch Angle around Y\n       * @param yaw Angle\
    \ around Z*/\n      void setRPY(const tf2Scalar& roll, const tf2Scalar& pitch,\
    \ const tf2Scalar& yaw)\n    \t{\n    \t\ttf2Scalar halfYaw = tf2Scalar(yaw) *\
    \ tf2Scalar(0.5);  \n    \t\ttf2Scalar halfPitch = tf2Scalar(pitch) * tf2Scalar(0.5);\
    \  \n    \t\ttf2Scalar halfRoll = tf2Scalar(roll) * tf2Scalar(0.5);  \n    \t\t\
    tf2Scalar cosYaw = tf2Cos(halfYaw);\n    \t\ttf2Scalar sinYaw = tf2Sin(halfYaw);\n\
    \    \t\ttf2Scalar cosPitch = tf2Cos(halfPitch);\n    \t\ttf2Scalar sinPitch =\
    \ tf2Sin(halfPitch);\n    \t\ttf2Scalar cosRoll = tf2Cos(halfRoll);\n    \t\t\
    tf2Scalar sinRoll = tf2Sin(halfRoll);\n    \t\tsetValue(\t sinRoll * cosPitch\
    \ * cosYaw - cosRoll * sinPitch * sinYaw, //x\n                         cosRoll\
    \ * sinPitch * cosYaw + sinRoll * cosPitch * sinYaw, //y\n                   \
    \      cosRoll * cosPitch * sinYaw - sinRoll * sinPitch * cosYaw, //z\n      \
    \                   cosRoll * cosPitch * cosYaw + sinRoll * sinPitch * sinYaw);\
    \ //formerly yzx\n    \t}\n\nThis is the exact notation in https://en.wikipedia.org/wiki/Conversion_between_quaternions_and_Euler_angles#Euler_angles_to_quaternion_conversion,\
    \ which is indicated as lab1-2-3 sequence, where lab frame is **fixed** during\
    \ the rotation. Therefore, it seems that it's following **extrinsic rotation**\n\
    \nFurthermore, in REP103 (https://www.ros.org/reps/rep-0103.html#axis-orientation),\
    \ it's mentioned that the rotation convention is *\"fixed axis roll, pitch, yaw\"\
    *. Although, this does not make it immediately clear, since fixed axis could also\
    \ be interpreted as rotation around a fixed axis of a rigid body. \n\nA nice summary\
    \ of the conventions used in similar 3d tools can be found in:\nhttps://rock-learning.github.io/pytransform3d/transformation_ambiguities.html"

I am very confused by the coordinate frame in this [tutorial](http://wiki.ros.org/tf#static_transform_publisher).

In this command line syntax

    rosrun tf static_transform_publisher x y z yaw pitch roll frame_id child_frame_id period_in_ms

 1. Does the value `x y z yaw pitch roll` represents the transform from `child_frame_id` to `frame_id`? Or the other way around?
 2. And what is the relationship between `frame_id` and `child_frame_id`? What is the order of the yaw pitch row in the transformation? Which one is the correct relationship?

  - *Extrinsic* rotation (occurs about the axes of the fixed coordinate system):
     - `child_frame_id = R(yaw) * R(pitch) * R(roll) * frame_id + [x,y,z]`
     - `child_frame_id = R(roll) * R(pitch) * R(yaw) * frame_id + [x,y,z]`

  - *Intrinsic* rotation (occurs about the axes of a coordinate system XYZ attached to a moving body):
     - `child_frame_id = frame_id * R(yaw) * R(pitch) * R(roll) + [x,y,z]`
     - `child_frame_id = frame_id * R(roll) * R(pitch) * R(yaw) + [x,y,z]`
