  body_markdown: "Have you seen the [Creating a Dual-Arm System (Indigo+)](http://wiki.ros.org/motoman_driver/Tutorials/Creating%20a%20Dual-Arm%20System)\
    \ page? It's not perfect, but it should show you how to setup a configuration\
    \ file for a multi-group system.\n\nI would also recommend using a `.launch` file\
    \ instead of starting things manually. That will be much more convenient.\n\n\
    The specific errors you show are basically caused by the fact that the driver\
    \ is unaware of the configuration of your controller.\n\n---\n\nEdit: partial\
    \ example (created from memory: I'm away from my computer so I can't test it):\n\
    \nlaunch file:\n\n    <?xml version=\"1.0\"?>\n    <launch>\n      <arg name=\"\
    robot_ip\" default=\"192.168.0.20\" />\n      <arg name=\"controller\" default=\"\
    fs100\" />\n    \n      <param name=\"robot_description\"\n        textfile=\"\
    $(find motoman_mh5_support)/urdf/dual_motoman_mh5/dual_motoman_mh5.urdf\"/>\n\
    \    \n      <!-- the yaml file could obviously be anywhere -->\n      <rosparam\
    \ command=\"load\" file=\"$(find motoman_mh5_support)/config/motion_interface.yaml\"\
    \ />\n    \n      <include file=\"$(find motoman_driver)/launch/robot_multigroup_interface_streaming_$(arg\
    \ controller).launch\">\n        <arg name=\"robot_ip\" value=\"$(arg robot_ip)\"\
    \ />\n      </include>\n\n      <!-- if you already have one external to this\
    \ launch file, then don't add this one -->\n      <node type=\"robot_state_publisher\"\
    \ pkg=\"robot_state_publisher\" name=\"robot_state_publisher\" />\n\n    </launch>\n\
    \nYou may also need a `joint_state_publisher` to gather and merge all the `joint_state`\
    \ topics that the driver publishes, but I can't check right now (and it also depends\
    \ on your use-case(s)).\n\nthe referenced `motion_interface.yaml`:\n\n    topic_list:\n\
    \      - name: r1 # might have to be switched with the 'ns' key\n        ns: mh5\n\
    \        group: 0\n        joints: [r1_joint_s, r1_joint_l, r1_joint_u, r1_joint_r,\
    \ r1_joint_b, r1_joint_t]\n      - name: r2 # might have to be switched with the\
    \ 'ns' key\n        ns: mh5\n        group: 1\n        joints: [r2_joint_s, r2_joint_l,\
    \ r2_joint_u, r2_joint_r, r2_joint_b, r2_joint_t]\n\nYou'll obviously have to\
    \ check whether the `group: 0` and `group: 1` are correct."

      Well, yes.

      The groups defined in the `topic_list` parameter must be matched by the configuration of MoveIt.

      The `topic_lists` I suggested does not have a single group with all joints. It has two groups, each with the joints of the respective robot. You'll have to update MoveIt's configuration to match.
