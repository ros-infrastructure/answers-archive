  body_markdown: "There is a problem with the maps inside LGSVL when OpenPlanner try\
    \ to create the network for planning. \nOpenPlanner has two parser (ver 1 and\
    \ ver2). \nit decide which version to use depending on the existence or absence\
    \ of data. \n\nIn short, OpenPlanner load LGSVL vector maps with version 2 but\
    \ it should be loaded with version 1. \n\nThis problem exists in each node that\
    \ loads the map to OpenPlanner. \n\n**op_global_planner**\nhttps://gitlab.com/autowarefoundation/autoware.ai/core_planning/-/blob/master/op_global_planner/nodes/op_global_planner_core.cpp\n\
    **op_local_planner: op_trajectory_selector, op_motion_predictor**\nhttps://gitlab.com/autowarefoundation/autoware.ai/core_planning/-/blob/master/op_local_planner/nodes/op_motion_predictor/op_motion_predictor_core.cpp\n\
    https://gitlab.com/autowarefoundation/autoware.ai/core_planning/-/blob/master/op_local_planner/nodes/op_behavior_selector/op_behavior_selector_core.cpp\n\
    **kf_contour_tracker:** \nhttps://gitlab.com/autowarefoundation/autoware.ai/core_perception/-/blob/master/lidar_kf_contour_track/nodes/lidar_kf_contour_track/lidar_kf_contour_track_core.cpp\n\
    \n\n**Solution:** \n\nlook for this line: \nif(m_MapRaw.GetVersion()==2)\nif(m_MapRaw.GetVersion()==1)\n\
    change 2->1 \nchange 1->2\nThis will work only with some maps which they have\
    \ this problems. \n\nHope that will be enough. \n\n"

  - body_markdown: "OpenPlanner identify the version by currently available files.\
      \ \nmainly if you have Nodes data or not. \n\nThe problem is LGSVL maps have\
      \ Nodes data, but the connection between these nodes are not consistent with\
      \ the original version 2 map. \n\nSo open planner correctly select version 2.\
      \ but when it construct the map this error appears. \n\nI found by accident\
      \ that when loading with version 1 it solve the problem. because, this version\
      \ ignores the nodes data and try to connect using the center line information\
      \ only. \n\nFinally , I am not willing to write new parser just for these map\
      \ specially if a work around is available."
