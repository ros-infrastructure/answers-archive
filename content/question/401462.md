In that case, if you look at the [d435](https://github.com/rickstaa/realsense-ros/blob/da38e309c2fbe88e45e6148bf5d944486b3e8e98/realsense2_description/urdf/_d435.urdf.xacro#L161) urdf, you will see that it calls the Gazebo plugin file that you linked.     EDIT 2:

    So I took a look at that [sensor_d435](https://github.com/rickstaa/realsense-ros/blob/development-gazebo/realsense2_description/urdf/_d435.urdf.xacro) macro and I noticed something.

    All the links that you're missing (everything after `camera_link`) is due to a (honestly kinda weird) setting. The parameter `use_nominal_extrinsics`. There is an [if statement](https://github.com/rickstaa/realsense-ros/blob/da38e309c2fbe88e45e6148bf5d944486b3e8e98/realsense2_description/urdf/_d435.urdf.xacro#L92) that doesn't include the `camera_depth_optical_frame` and all the others if set to false.

    Guess what the [default value](https://github.com/rickstaa/realsense-ros/blob/da38e309c2fbe88e45e6148bf5d944486b3e8e98/realsense2_description/urdf/_d435.urdf.xacro#L17) is set to? False.

    So you need to change your macro to:

        <xacro:sensor_d435 name="camera" parent="base_link" use_nominal_extrinsics="true">
            <origin xyz="0.1 0.0 -0.03" rpy="0 0 0"/>
        </xacro:sensor_d435>

    The weird thing is, *they set it to true themselves* in the [launch file](https://github.com/rickstaa/realsense-ros/blob/da38e309c2fbe88e45e6148bf5d944486b3e8e98/realsense2_description/launch/view_d435_model.launch#L2), so why they set it to false by default (or why it even exists to be honest) I do not understand.
