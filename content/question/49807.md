  body_markdown: "As far as I know, gmapping maintains occupancy values internally.\
    \ However, the ROS wrapper thresholds them into binary free/occupied values.\n\
    \nTake a look at this file:\n\n[slam_gmapping.cpp](http://ros.org/doc/fuerte/api/gmapping/html/slam__gmapping_8cpp_source.html)\n\
    \nStarting at line 625:\n\n    for(int x=0; x < smap.getMapSizeX(); x++)\n   \
    \ {\n      for(int y=0; y < smap.getMapSizeY(); y++)\n      {\n        GMapping::IntPoint\
    \ p(x, y);\n        double occ=smap.cell(p);\n        assert(occ <= 1.0);\n  \
    \      if(occ < 0)\n          map_.map.data[MAP_IDX(map_.map.info.width, x, y)]\
    \ = -1;\n        else if(occ > occ_thresh_)\n        {\n          //map_.map.data[MAP_IDX(map_.map.info.width,\
    \ x, y)] = (int)round(occ*100.0);\n          map_.map.data[MAP_IDX(map_.map.info.width,\
    \ x, y)] = 100;\n        }\n        else\n          map_.map.data[MAP_IDX(map_.map.info.width,\
    \ x, y)] = 0;\n      }\n    }\n\nThe default value for `occ_thresh_` is 0.25.\
    \ It appears that if you want the occupancy values, you can simply revert the\
    \ line which was commented out, and change the code to:\n\n    map_.map.data[MAP_IDX(map_.map.info.width,\
    \ x, y)] = (int)round(occ*100.0);\n    //map_.map.data[MAP_IDX(map_.map.info.width,\
    \ x, y)] = 100;\n\nI have created a [ticket](https://code.ros.org/trac/ros-pkg/ticket/5589)\
    \ here.\n\n**EDIT**: response to comment\n\nI'm not sure whether amcl currently\
    \ assumes binary values or not. \n\nWith laser sensors, you typically reach saturation\
    \ probabilities (0 or 1) pretty fast, since lasers have a small uncertainty spread.\
    \ My intuition is that since the nav stack is mainly developed for laser-equipped\
    \ ground robots, the binary value is a good approximation."
