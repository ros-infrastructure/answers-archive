  body_markdown: "The topic name has been remapped from `turtlebot_teleop_keyboard/cmd_vel`\
    \ to `cmd_vel_mux/input/teleop`. See [keyboard_teleop.launch](https://github.com/turtlebot/turtlebot/blob/melodic/turtlebot_teleop/launch/keyboard_teleop.launch#L6).\
    \ So try `/cmd_vel_mux/input/teleop` instead of `/cmd_vel`.\n\n---\nEdit: <br\
    \ />\nSince you\u2019ve asked another question- #q349325 and you've referred to\
    \ this [tutorial](https://learn.turtlebot.com/2015/02/03/5/), I assume you are\
    \ also referring to that link here. \n\nHave you terminated your `keyboard_teleop.launch`\
    \ before running\n\n    rostopic pub /cmd_vel_mux/input/navi geometry_msgs/Twist\
    \ '{linear: {x: 10, y: 0, z: 0}, angular: {x: 0, y: 0, z: 0}}'\n\nA very possible\
    \ reason that your turtlebot did not move is your teleop command (`/cmd_vel_mux/input/teleop`)\
    \  published by node `turtlebot_teleop_keyboard` overwrote your navi stack\u2019\
    s command (`/cmd_vel_mux/input/navi`). \nKobuki's control system uses `cmd_vel_mux`\
    \ to manage multiple incoming velocity commands and to determine which input is\
    \ going to be prioritized according to a `YAML` file- [mux.yaml](https://github.com/turtlebot/turtlebot/blob/melodic/turtlebot_bringup/param/mux.yaml)\
    \ (in this case):\n\n    subscribers:\n      - name:        \"Safe reactive controller\"\
    \n        topic:       \"input/safety_controller\"\n        timeout:     0.2\n\
    \        priority:    10\n      - name:        \"Teleoperation\"\n        topic:\
    \       \"input/teleop\"\n        timeout:     1.0\n        priority:    7\n \
    \     - name:        \"Switch\"\n        topic:       \"input/switch\"\n     \
    \   timeout:     1.0\n        priority:    6\n      - name:        \"Navigation\"\
    \n        topic:       \"input/navi\"\n        timeout:     1.0\n        priority:\
    \    5\n\nAs you can see, the topic `input/navi` has lower priority than `input/teleop`.\n\
    Therefore, you either terminate the`keyboard_teleop.launch` and then use one among\
    \ these four topics, or publish velocity command only to`/cmd_vel_mux/input/safety_controller`\
    \ or `/cmd_vel_mux/input/teleop` to control your turtlebot while running `turtlebot_teleop_keyboard`\
    \ node.\nFor more information about control system of Kobuki/Turtlebot2, please\
    \ see [kobuki/Tutorials/Kobuki's Control System](http://wiki.ros.org/kobuki/Tutorials/Kobuki%27s%20Control%20System#Components).\n\
    \nIn fact, if you only have velocity commands from one source, you don\u2019t\
    \ really need `cmd_vel_mux` to multiplex your velocity commands. You can publish\
    \ velocity-command messages directly to `/mobile_base/commands/velocity` which\
    \ is the topic gazebo node receives/subscribes."
