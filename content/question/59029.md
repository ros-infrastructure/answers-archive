  body_markdown: "hi,\nas this topic is very interresting, see view-count :) i will\
    \ answer it by myself.\n\nIf you use the cmdline tool \"rosservice\" with the\
    \ command \"call\" you can specify, e.g. when calling /gazebo/apply_joint_effort\
    \ service, the duration. This duration is of type ros::duration. You can check\
    \ this by calling:\n\nrosservice info gazebo/apply_joint_effort\nNode: /gazebo\n\
    URI: rosrpc://ros:43892\nType: gazebo_msgs/ApplyJointEffort\nArgs: joint_name\
    \ effort start_time duration\n\nThe type gazebo_msgs/ApplyJointEffort contains\
    \ ros::duration as type of the duration.\n\nBut when you can e.g. (with -v for\
    \ verbose outpt):\n\nrosservice call -v gazebo/apply_joint_effort '{joint_name:\
    \ myjoint, effort: 100, start_time: 0, duration: 100000}'\n\nyou can see, that\
    \ rosservice uses the 100000 as nanoseconds:\n\nduration: \n  secs: 0\n  nsecs:\
    \ 100000\n\nBut if you use the ros::ServiceClient and set the duration with:\n\
    \ngazebo_msgs::ApplyJointEffort r;\nr.request.duration = ros::Duration(100000.);\n\
    \nyou set 100000. seconds.\n\nIf you print out the values in seconds from inside\
    \ gazebo_ros_api_plugin.cpp:GazeboRosApiPlugin::applyJointEffort() function, you\
    \ get with rosservice call:\n\nduration >0.000100<\n\nand with ros::duration(100000.)\
    \ you get:\n\nduration >100000.000000<\n\nSo if you know this, adjust your values\
    \ and it will work.\n\nflo"
