  body_markdown: "Sure. You are free to do anything you want in a ROS node. Just open\
    \ a UDP socket (using basic C/C++ std runtime support, or Boost, or X ..) and\
    \ use it like you would normally do.\n\nThe only 'restriction' would be that you'd\
    \ have to give ROS a chance to process its events and do some bookkeeping once\
    \ in a while. A typical pattern for that is something like:\n\n    while (your_own_termination_condition\
    \ && ros::ok())\n    {\n       handle_your_udp_traffic();\n    \n       // other\
    \ stuff\n       ..\n    \n       // let ROS do its thing\n       ros::spinOnce();\n\
    \    \n       // maybe sleep a little (but that depends on your application)\n\
    \       ..\n    }\n\nIf I understand your [other question](http://answers.ros.org/question/207671/made-urdf-file-whats-next/)\
    \ correctly, the 'other stuff' would probably include things like converting the\
    \ odometry data from your motor controller into proper ROS msgs, and any incoming\
    \ ROS msgs (most likely [geometry_msgs/Twist](http://docs.ros.org/api/geometry_msgs/html/msg/Twist.html))\
    \ into data you can send to your motor controller over your UDP socket.\n\n---\n\
    \nEdit: you might also be interested in using [ros_control](http://wiki.ros.org/ros_control)\
    \ to base your own node on. Instead of implementing all of the ROS side yourself,\
    \ you provide `ros_control` with a `hardware_interface` (which in your case would\
    \ implement the communication with your motor controller over UDP) and 'the rest'\
    \ (twist controllers, differential drive velocity calculation, and the associated\
    \ ROS API) will be provided for you. If I'm not mistaken, the [husky_control](http://wiki.ros.org/husky_control)\
    \ pkg is similarly implemented.\n\nSee [davetcoleman/ros_control_boilerplate](https://github.com/davetcoleman/ros_control_boilerplate)\
    \ for an example of how to set this up.\n\nI sort of assumed here that you're\
    \ trying to create a differential-drive mobile robot (as you talk about odometry),\
    \ but if not, `ros_control` can still be useful.\n"
