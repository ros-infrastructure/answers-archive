  body_markdown: "For Q1, see #q205541 and the link [to this page](http://wiki.ros.org/msg#Fields)\
    \ therein. In short: in msg/srv definition you need to use `float64` as this is\
    \ a \"ROS built-in type\". Those are used to autogenerate the code for different\
    \ languages. In C++ use `double`. \n\nQ2: this is expected behavior, as you are\
    \ now using C++. This is, `double` is a C++ primitive type, whereas `string` is\
    \ not. Use `std::string` instead. No fault with QTCreator there.\n\n---\nEdit:\n\
    \n`std::string` is the C++ string type, whereas `std_msgs::String` is the C++\
    \ representation of a ROS standard message that only contains a `string` (ROS\
    \ built-in type) / `std::string` (C++ type) as a field. Check the `std_msgs/String`\
    \ message definition [here](http://docs.ros.org/api/std_msgs/html/msg/String.html).\n\
    \nI.e., manipulating the respective `data` field of the `std_msgs::String` with\
    \ `c_str()` will work.\n\nE.g. (using `std::string`s `empty()` method for sake\
    \ of brevity)\n\n    std_msgs::String string_msg;\n    std::string cpp_string;\n\
    \    cpp_string.empty(); // compiles\n    string_msg.empty();  // does not compile\n\
    \    string_msg.data.empty(); // compiles"
