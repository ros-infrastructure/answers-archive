  body_markdown: "From a really high-level: remapping makes the ROS middleware return\
    \ a *different resource* when a *graph participant* asks for *a resource* with\
    \ a certain name.\n\nIn other words: if there is a remap from `name_a` to `name_b`\
    \ and `node_x` asks for `name_a`, it will actually be returned whatever is registered\
    \ with `name_b`.\n\nTo make it more concrete (with two examples):\n\n - for a\
    \ publisher: if `node_x` wants to publish to topic `chatter`, but there is a remap\
    \ `chatter->other_topic`, then it may advertise a `chatter` publisher, but it\
    \ will actually be publishing to topic `other_topic`\n - for a subscriber: if\
    \ `node_x` subscribes to `chatter`, but there is a remap `chatter->other_topic`,\
    \ it will request a subscription to `chatter`, but in reality it will subscribe\
    \ to `other_topic`\n\nThese remaps are completely transparent (ie: invisible)\
    \ to `node_x`, they are processed by the ROS middleware.\n\nThe \"only requirement\"\
    \ is of course that `chatter` and `other_topic` are of the same message type.\
    \ Remapping is not magic, it changes names, not types (that would be message *transformation*).\n\
    \n---\n\nThe power here is that I can write a `node_x` and you can write a `node_y`\
    \ and we can both **hardcode** the topic names we want to use. \n\nIf we used\
    \ different topic names, but one of our users wants to \"connect\" our two nodes\
    \ together, they only have to provide a remapping. Either:\n\n - make `node_x`\
    \ use the topic name that `node_y` expects\n - make `node_y` use the topic name\
    \ that `node_x` expects\n - remap both to a third name, different from what `node_x`\
    \ and `node_y` use internally\n\n---\n\nEdit: you've probably already seen it,\
    \ but just for completeness: see the [Remapping Arguments](http://wiki.ros.org/Remapping%20Arguments)\
    \ on the wiki for some more information.\n\nAnd although it's an article about\
    \ ROS 2, the [Remapping Names](https://design.ros2.org/articles/static_remapping.html)\
    \ article on the ROS2 design website might provide some additional background.\
    \ It also has a section on ROS 1 remapping."
