  body_markdown: "I'm pretty sure you're running into this issue: [[PyQt] QPushButton.text()\
    \ ampersand issue](https://riverbankcomputing.com/pipermail/pyqt/2015-October/036499.html):\n\
    \n> I'm having an issue getting the text from a QPushButton.The text of the \n\
    button is set with:\n\n>     statusButton = QPushButton(translator.translate('rb',\
    \ \"Start\"), self)\n\n> the text appears normally on the button (i.e. without\
    \ an ampersand), but \nwhen I get the text with:\n\n>     status = statusButton.text()\n\
    \n> the string returned is \"&Start\" instead of \"Start\".\n\nThe most likely\
    \ reason is that Qt automatically makes the first (non-special) character of a\
    \ string set as the label in a `QCheckBox` the *shortcut character* ([docs](http://doc.qt.io/qt-5/qcheckbox.html#details)\
    \ for `QCheckBox`, search for \"shortcut\").\n\nIf you then ask for the label\
    \ using `.text()`, the return value is the text *with* the `&`, as that is how\
    \ you would normally indicate which character should be the one registered as\
    \ the shortcut for that UI element.\n\n---\n\nEdit: to avoid this the nicest approach\
    \ would probably be to go with an MVC implementation, where the model is a list\
    \ of strings and the view creates a `QCheckBox` instance for each entity in the\
    \ model. You would then interact with the model instead of with the `QCheckBox`\
    \ labels directly."

I'm trying to fix [an issue](https://gitlab.com/InstitutMaupertuis/rqt_bag_exporter/issues/21) that appeared on ROS Melodic, I cannot reproduce this on ROS Kinetic.

# In short
- I'm using `QCheckBox` objects and setting the text to a ROS topic name.
- I then retrieve this topic name (from the `QCheckBox`) but ampersand characters randomly appear in the strings.

# Details
Use the [ampersand branch](https://gitlab.com/InstitutMaupertuis/rqt_bag_exporter/tree/ampersand) to reproduce this bug:

- Compile / launch with command line (`roslaunch rqt_bag_exporter gui.launch`)
- Open [this bag file](https://ufile.io/vhyho)
- Tick `/topic/dog` topic to be exported
- Export

On my machine it fails with:
![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15293308971441412.png)

The service fails because the topic name has an extra ampersand (`&`) character after the first slash (`/`), I cannot find where this character comes from.
