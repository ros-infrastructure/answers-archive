    Usually, you would encode CR and LF as the XML entities &amp;#13; and &amp;#10; respectively. However, roslaunch trims whitespace (including CR/LF) from the beginning and the end of a parameter string value (which is unfortunate and possibly a bug), and seems to apply the XML end-of-line handling (convert CR+LF and CR to LF) even to these encoded entities (which would be a bug in the XML parser).
