    For a long time i386 was the most common platform since it was the default install for Ubuntu.

    Almost all ROS packages work find on both I386 and arm32(armhf) packages. We have only recently turned off i386 builds for the latest ROS distro due to lack of use: http://www.ros.org/reps/rep-0003.html#lunar-loggerhead-may-2017-may-2019 But as it says packages are still expected to build on i386.

  body_markdown: "We have Tinker Board 2S (64-bit) and Tinker Board S (32-bit).\n\n\
    For 2S, I installed Tinker Board 2 Debian 10 V2.0.0 and then tried to install\
    \ ROS Noetic by following Debian instructions [here](http://wiki.ros.org/noetic/Installation/Debian).\
    \ However, I came across a couple of issues including invalid key and unmet dependencies.\
    \ Eventually, I was able to install ROS Noetic on 2S.\n\nFor S, it has 32-bit.\
    \ So, as [tfoote](https://answers.ros.org/users/3/tfoote/) mentioned above, you\
    \ need to build it from source. [Here](http://wiki.ros.org/noetic/Installation/Source)\
    \ is the link for the ROS Noetic source installation.\n\nI saw some people suggest\
    \ using Armbian or Lubuntu on Tinker Board but there is no ready-to-use (e.g.,\
    \ with u-boot) Armbian or Lubuntu images for Tinker Board 2S. This means you need\
    \ to prepare your operating system, for example Armbian, image by [building it\
    \ from source](https://docs.armbian.com/Developer-Guide_Build-Preparation/) and\
    \ adding u-boot. Otherwise, the device will not boot. On the other hand, there\
    \ is Armbian image for Tinker Board S [here](https://www.armbian.com/tinkerboard/).\
    \ For our S model, I installed Armbian and then built ROS from source. \n\n "
