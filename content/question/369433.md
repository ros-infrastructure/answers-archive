  body_markdown: "I don't know about doing this in C++ specifically, but at least\
    \ the [Connection header](http://wiki.ros.org/ROS/Connection%20Header) appears\
    \ to have a field which encodes whether:\n\n> publisher is in latching mode (i.e.\
    \ sends the last value published to new subscribers) \n\nThe [wiki/rospy/Overview/Publishers\
    \ and Subscribers: Subscribing to a topic - Connection Information](http://wiki.ros.org/rospy/Overview/Publishers%20and%20Subscribers#Connection_Information)\
    \ shows how to access this in `rospy`.\n\nIn `roscpp`, you can get the header\
    \ from the [MessageEvent](https://docs.ros.org/en/api/roscpp_traits/html/classros_1_1MessageEvent.html)\
    \ (`getConnectionHeader()`, via [MessageEvent [ROS 1.1+]](http://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers#MessageEvent_.5BROS_1.1.2B-.5D)).\n\
    \nI would expect `rosbag` to have other options to get the connection header though,\
    \ seeing as it already deals with connections.\n\n---\n\nEdit: [this comment](https://github.com/ros/rosbag_snapshot/issues/6#issuecomment-666364534)\
    \ in the issue you commented on links to [ros/ros_comm/tools/topic_tools/src/relay.cpp](https://github.com/ros/ros_comm/blob/f781defbf6f46ced0d940bea2ac977e18238586b/tools/topic_tools/src/relay.cpp#L92)\
    \ which actually shows how to do this:\n\n    boost::shared_ptr<const ros::M_string>\
    \ const& connection_header =\n      msg_event.getConnectionHeaderPtr();\n    \n\
    \    [..]\n    \n    // If the input topic is latched, make the output topic latched,\
    \ #3385.\n    bool latch = false;\n    if (connection_header)\n    {\n      ros::M_string::const_iterator\
    \ it = connection_header->find(\"latching\");\n      if((it != connection_header->end())\
    \ && (it->second == \"1\"))\n      {\n        ROS_DEBUG(\"input topic is latched;\
    \ latching output topic to match\");\n        latch = true;\n      }\n    }"
