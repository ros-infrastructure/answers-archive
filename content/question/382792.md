**Specific question** <br>
Do I need to publish a `static_transform publisher` from one link frame to another when I already have a `joint` defined in my URDf file between those 2 links?

**Scenario** <br> 
I'm trying to attach a `Velodyne VLP-16` lidar on top of a MAV. I'm using the [RotorS simulator](https://github.com/ethz-asl/rotors_simulator) ROS package for this purpose. I included the description xacro file for the lidar in [this](https://github.com/ethz-asl/rotors_simulator/blob/master/rotors_description/urdf/firefly_base.xacro) mav's file and initialised the `<VLP-16>` macro. The [macro](https://bitbucket.org/DataspeedInc/velodyne_simulator/src/master/velodyne_description/urdf/VLP-16.urdf.xacro) establishes a `joint` between the `base_link` of the LIDAR and the `base_link` of the MAV. 
I realized I could not visualize the LIDAR data in RViz just by doing this. I had to run a static_transform_publisher node too, from the `base_link` of the LIDAR and the `base_link` of the MAV. 
Shouldn't there be any need for the `transform` between two `frames` when I already have a `joint` between the two `links`?
