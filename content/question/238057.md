I'm new to the [ros_control](http://wiki.ros.org/ros_control) package and I'm a bit confused as to how it coordinates itself. I've mainly been playing with the [Jackal](https://www.clearpathrobotics.com/assets/guides/ros/ROS%20Navigation%20Basics.html) simulation and what I've gathered is:

- Gazebo creates simulated hardware interfaces [from URDF](https://github.com/jackal/jackal/blob/indigo-devel/jackal_description/urdf/jackal.urdf.xacro#L66).
- The `jackal_control` package [instantiates controllers](https://github.com/jackal/jackal/blob/indigo-devel/jackal_control/launch/control.launch#L5) which use [parameters](https://github.com/jackal/jackal/blob/indigo-devel/jackal_control/config/control.yaml#L5) that specify hardware resources by name, which match the URDF.
- The physical real Jackal [registers hardware interfaces](https://github.com/jackal/jackal_robot/blob/indigo-devel/jackal_base/include/jackal_base/jackal_hardware.h#L65).

What I don't understand is how does the [controller_manager](http://wiki.ros.org/controller_manager) magically know what hardware resource interfaces are available? It appears that you need to register them in separate nodes, but where is this communication happening?

In ROS I'm used to seeing topics, services, and parameters all publicly listed and accessible. But this hardware resource communication is invisible to me.

I appreciate any help / pointers. Thanks!
