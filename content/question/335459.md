  body_markdown: "tl;dr: you create a special `message_filters.Subscriber`, which\
    \ you pass to `message_filters.Cache`. This will cause the `Cache` to be updated\
    \ with *every* incoming message. In addition, you register your own callback (ie:\
    \ `self.ReturnRateData`) that also gets called for every new incoming message.\n\
    \nBut that callback is a regular ROS subscribers callback, so it receives the\
    \ message that was received by the special `Subscriber` you created earlier.\n\
    \nIn your callback signature, you call that argument `Cache`, and treat it as\
    \ if it is the `message_filters.Cache` instance (by calling `getElemBeforeTime(..)`\
    \ on it).\n\nThat won't work, as it's actually a `geometry_msgs.PoseStamped` message\
    \ (that was just received).\n\nYou'll have to keep a reference to `cache` around\
    \ and access *that* in your `ReturnRateData(..)` (perhaps store your `Cache` instance\
    \ as a member variable of your `OptitrackReceive` class).\n\n---\n\nLonger: you\
    \ have this:\n\n    def __init__(self):\n      [..]\n      self.sub = message_filters.Subscriber('/vrpn_client_node/TestTed/pose',PoseStamped)\n\
    \      cache = message_filters.Cache(self.sub, 2,allow_headerless=False)\n   \
    \   cache.registerCallback(self.ReturnRateData)\n    \n    [..]\n    \n    def\
    \ ReturnRateData(self, Cache):\n      self.rate_previous = Cache.getElemBeforeTime(Cache.getOldestTime())\n\
    \      self.rate_current = Cache.getElemAfterTime(Cache.getLatestTime())\n   \
    \   [..]\n\nThe `Cache` argument that `ReturnRateData(..)` receives is not a `message_filters.Cache`,\
    \ but a `PoseStamped`.\n\nThis is described on the wiki page of `message_filters`\
    \ ([here](http://wiki.ros.org/message_filters#Cache)):\n\n>     sub = message_filters.Subscriber('my_topic',\
    \ sensor_msgs.msg.Image)\n    cache = message_filters.Cache(sub, 100)\n\n> In\
    \ this example, the Cache stores the last 100 messages received on `my_topic`,\
    \ and `myCallback` is called on the addition of every new message. The user can\
    \ then make calls like `cache.getInterval(start, end)` to extract part of the\
    \ cache. \n\nAnd from the *Message Filters API documentation* ([here](https://docs.ros.org/api/message_filters/html/python/#message_filters.Cache)):\n\
    \n> `message_filters.Subscriber.registerCallback(cb, *args)`\n> \n> Register a\
    \ callback function cb to be called when this filter has output. The filter calls\
    \ the function `cb` with a filter-dependent list of arguments, followed by the\
    \ call-supplied arguments `args`."
