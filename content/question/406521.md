    You have this:

        #cmd_vel
        def callback_cmd(cmd):
            rospy.loginfo("/cmd_vel: %s", str(cmd.linear))
            car.throttle = cmd.linear

    As you can see [in the documentation](http://docs.ros.org/en/noetic/api/geometry_msgs/html/msg/Twist.html), a `geometry_msgs/Twist` message has the following structure:

    >     Vector3  linear
        Vector3  angular

    So `linear` is not a simple value, but a `geometry_msgs/Vector3` object, which contains (from [here](http://docs.ros.org/en/noetic/api/geometry_msgs/html/msg/Vector3.html)):

        float64 x
        float64 y
        float64 z

    The error message you show states:

    > The 'throttle' trait of a NvidiaRacecar instance must be a float, but a [..] <class 'geometry_msgs.msg._Vector3.Vector3'> was specified.

    this is correct: `cmd.linear` is indeed a (Python version of a) `geometry_msgs/Vector3`. It's not a `float`.

    To solve your problem, you'll have to convert the `cmd_vel.linear.x` into an appropriate value for `NvidiaRacecar.throttle`, expressed as a `float`.

    If `NvidiaRacecar.throttle` accepts values representing metres/second of the race car, that would be easy. Otherwise, a conversion would be important, as `cmd_vel.linear` is a vector and encodes the commanded translational velocity in metres/second. It's not a normalised value from `[min, max)` or something like that.
