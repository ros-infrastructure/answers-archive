  body_markdown: "One thing that helps me is to write each nodelet/node so that it\
    \ can be built either (or indeed both!) ways. Put all your functionality into\
    \ a class with a constructor that takes both the public and private node handles.\n\
    \nWe then have this template that generates a thin interface class between the\
    \ `Nodelet` code and our implementation:\n    \n    namespace nodelet_helper{\n\
    \        template<typename T>\n        class TNodelet: public nodelet::Nodelet\n\
    \        {\n        public:\n            TNodelet() {};\n    \n            void\
    \ onInit() {\n                NODELET_DEBUG(\"Initializing nodelet\");\n    \n\
    \                m_theT = std::unique_ptr<T>(new T(getNodeHandle(), getPrivateNodeHandle()));\n\
    \            }\n    \n        private:\n            std::unique_ptr<T> m_theT;\n\
    \        };\n    } // End nodelet_helper namespace\n\nThen, to use it we have\
    \ code like this:\n\n    namespace my_vision_tasks {\n        using VisionTaskOneNodelet\
    \ = nodelet_helper::TNodelet<VisionTaskOne>;\n        using VisionTaskTwoNodelet\
    \ = nodelet_helper::TNodelet<VisionTaskTwo>;\n    }\n    \n    PLUGINLIB_EXPORT_CLASS(my_vision_tasks::VisionTaskOneNodelet,\
    \ nodelet::Nodelet)\n    PLUGINLIB_EXPORT_CLASS(my_vision_tasks::VisionTaskTwoNodelet,\
    \ nodelet::Nodelet)\n\nFinally, the XML is:\n\n    <library path=\"lib/libstructure_from_motion_v2_nodelet\"\
    >\n      <class name=\"my_vision_tasks/VisionTaskOneNodelet\" type=\"my_vision_tasks::VisionTaskOneNodelet\"\
    \ base_class_type=\"nodelet::Nodelet\">\n        <description>Task one</description>\n\
    \      </class>\n    \n      <class name=\"my_vision_tasks/VisionTaskTwoNodelet\"\
    \ type=\"my_vision_tasks::VisionTaskTwoNodelet\" base_class_type=\"nodelet::Nodelet\"\
    >\n        <description>Task two</description>\n      </class>\n    </library>"
