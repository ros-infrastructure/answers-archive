  body_markdown: "> Can someone please explain what approximate solution actually\
    \ is\n\nAn approximate solution is a path that gets closer (in terms of the joint\
    \ state space) to the goal, but still doesn't reach it. The path is still feasible/not\
    \ in collision, but it doesn't actually get to the goal, it will just stop somewhere\
    \ in the middle.\n\n>why can't it be executed\n\nJust a guess, but there's no\
    \ good reason to try to execute an approximate motion. Say I asked a robot to\
    \ pick up a cup of water. Then it finds an approximate motion that stops while\
    \ the gripper still 5 feet away from the robot. As a user, I would be very confused\
    \ what it was doing and why didn't actually pickup the glass. \n\nAs far as why\
    \ you are only finding approximate solutions, this is probably because you are\
    \ only running RRT* for 5 seconds: depending on the complexity of your environment\
    \ this might not be enough. Try running for longer (in Rviz there is a parameter\
    \ you can use to set the planning time). \n\n>Is there an option to force moveit\
    \ to execute the approximate solution?\n\nGiven that I found this question by\
    \ trying to google for this option, I would guess not. :)\nAfter actually looking\
    \ at the [source code](https://github.com/ros-planning/moveit/blob/eac013bf67751a3030f891456675506f8be4049f/moveit_planners/ompl/ompl_interface/src/model_based_planning_context.cpp#L598),\
    \ in MoveIt!, I can confirm that there is currently no easy to execute an approximate\
    \ solution."
