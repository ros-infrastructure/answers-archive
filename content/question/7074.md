Dear all,

As I'm currently trying to tune the dynamic behaviour of my robot modelled in a urdf(.xacro) file, I investigated the various urdf and gazebo tags available in order to see their effect to the simulation respectively.

This thread mainly deals with the conversion from urdf to sdf format using the gzsdf tool. So this thread is probably the first of several threads.  

In the following I state my observations and would kindly ask someone to confirm them...or give explanations otherwise ;-)

I use the following setup: Trusty, Indigo, gazebo2\_2.2.3-1~trusty\_amd64
The robot I'm trying to tune is the Schunk lwa4p_extended. URDFs can be found here [URDFs](https://github.com/ipa-fxm/schunk_modular_robotics/tree/indigo_dev/schunk_description/urdf/lwa4p_extended "URDFs") and [launch files](https://github.com/ipa-fxm/schunk_robots/tree/indigo_dev/schunk_lwa4p_extended "launch").  
Other related links: [gazebo-urdf-tutorial](http://gazebosim.org/tutorials/?tut=ros_urdf "tutorial") and [sdf1.4](http://osrf-distributions.s3.amazonaws.com/sdformat/api/1.4.html "sdf1.4").

I will number the questions so that answers can be referenced accordingly.


----------

General questions  

 1. The SDF version used in my setup (trusty, indigo, gazebo2) is SDF1.4?
 1. Where is SDF1.5 used? With gazebo3? Or gazebo4?
 1. You can convert a urdf.xacro file to sdf uding the following commands

    rosrun xacro xacro.py robot_lwa4p_extended.urdf.xacro > robot_lwa4p_extended.urdf  
    gzsdf print robot_lwa4p_extended.urdf > robot_lwa4p_extended.sdf  

 1. When spawning a robot in gazebo using `gazebo_ros/spawn_model` the same `gzsdf` is used to convert the parameter `/robot_description` to sdf format which is then used in gazebo?
 1. Within a urdf gazebo tag (referencing a link or joint), I can use all tags listed in the [gazebo-urdf-tutorial](http://gazebosim.org/tutorials/?tut=ros_urdf "tutorial")? I.e.:

     - material, gravity, dampingFactor, maxVel, minDepth, mu1, mu2, fdir1, kp, kd, selfCollide, maxContacts, laserRetro for links  
     - kp, kd, stopCfm, stopErp, provideFeedback, cfmDamping, fudgeFactor for joints

 1. Within a urdf gazebo tag (referencing a link or joint), I can also use sdf tags from [sdf1.4](http://osrf-distributions.s3.amazonaws.com/sdformat/api/1.4.html "sdf1.4") directly?


----------

Tag specific questions

 1. `gravity`, `selfCollide` and `self_collide` (gazebo tag for links)  
    Adding one of the tags above for a link, an additional tag is added to the resulting sdf file, i.e. there are then **two** `gravity` tags for the same link in the sdf file where the first is always set to true (1) and the second sdf tag holds the value set in the urdf. I assume that when gazebo parses the sdf file, it always finds the first tag using their value, thus always neglecting what has been set in the urdf.  
 1. `kp`, `kd`, `mu1`, `mu2`, `maxVel`, `minDepth`, `fdir1`, `maxContacts`, `laserRetro`, `dampingFactor` (gazebo tag for links)  
    All those tags seem to be converted to sdf correctly.  
 1. `damping` and `friction` (urdf tag for joints)  
    `friction` is currently ignored, i.e. it's value is not even converted into the sdf file?  
 1. Empty gazebo tag referencing a joint  

        <gazebo reference="${name}_1_joint">
        </gazebo>

        is converted into 

        <physics>
          <ode>
            <limit>
              <cfm>0</cfm>
              <erp>0.2</erp>
            </limit>
          </ode>
        </physics>

 1. `stopCfm`, `stopErp` (gazebo tag for joint)  

        <gazebo reference="${name}_1_joint">
          <stopCfm>0.3</stopCfm>
          <stopErp>0.4</stopErp>
        </gazebo>

        is converted into 

        <physics>
          <ode>
            <limit>
              <cfm>0.3</cfm>
              <erp>0.4</erp>
            </limit>
          </ode>
        </physics>
 1. `cfmDamping`, `implicitSpringDamper`, `cfm_damping`, `implicit_spring_damper` (gazebo tag for joint)  
    `cfmDamping` is marked deprecated?  
    Both `cfmDamping` and `implicitSpriingDamper``are converted into  

        <physics>
          <ode>
            <implicit_spring_damper>1</implicit_spring_damper>
            <cfm_damping>1</cfm_damping>
            <limit>
              <cfm>0</cfm>
              <erp>0.2</erp>
            </limit>
          </ode>
        </physics>

 1. `kp`, `kd` (gazebo tag for joint)  
    Not converted into sdf. Why?  
 1. `provideFeedback`, `fudgeFactor` (gazebo tag for joint)  
    All those tags seem to be converted to sdf correctly.
