  body_markdown: "Hallo avicenna,\n\nactually in occupancy grid maps like in gmapping\
    \ you dont speak of (x,y) coordinates you are speaking of cells. Of course you\
    \ can assume that the middlepoint of a cell are you coordinates. \n\nSo the Occoupancy\
    \ Grid map is defined [here](http://docs.ros.org/kinetic/api/nav_msgs/html/msg/OccupancyGrid.html)\
    \ but the most important is:\n\n> The map data, in row-major order, starting with\
    \ (0,0).  Occupancy probabilities are in the range [0,100].  Unknown is -1.\n\n\
    GMapping follows a maximum likelihood convention where a occupancy grid map is\
    \ a Tri-State:\n\n-1: Unknow\n\n0: Free\n\n100: Occupied\n\nSo what you need actually\
    \ to do is iterating over the cells, check if the probability is 100 and if so\
    \ print the location: \n\n        for (int width=0; width < occupancy_grid->info.width;\
    \ ++width)\n        {\n            for (int height=0; height < occupancy_grid->info.height;\
    \ ++height)\n            {\n                if(occupancy_grid->data[height*occupancy_grid.info.width\
    \ + width] > 0)\n                {\n                   x = width * occupancy_grid->info.resolution\
    \ + occupancy_grid->info.resolution / 2;\n                   y = height * occupancy_grid->info.resolution\
    \ + occupancy_grid->info.resolution / 2;\n                }\n            }\n \
    \       }\n\nBe careful with is code! I write it out of my memory and its not\
    \ optimized, with datatypes or even correct. Just an illustration how you can\
    \ do it.  occupancy_grid is here a pointer to a nav_msgs/OccupancyGrid Object.\
    \ \n\nThe code also assumes that your (x,y)-origin is at (0,0). When its not you\
    \ have to add it to x and y. \n\n\n\n\n"
