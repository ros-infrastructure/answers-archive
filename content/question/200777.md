    >  Is it possible to run joint trajectory action while keeping ability to command value to each joint?

    By commanding individual joints you mean the specific ROS API of `JointPositionController`?.

    These are the options that currently exist:

    * Use the `controller_manager/switch_controller` service to stop the `joint_trajectory_controller` and start the `joint_position_controller` to change the currently running controllers.

    * If you normally use the `joint_trajectory_controller`, but sometimes want to change to the `joint_position_controller`, you  can setup a launch file consisting of a [`spawner`](http://wiki.ros.org/controller_manager#spawner) that starts the `joint_position_controller` and an [`unspawner`](http://wiki.ros.org/controller_manager#unspawner) for inhibitting (stopping) the `joint_trajectory_controller`. When you kill the roslaunch process and the `spawner+unspawner` die, you will revert back to the original controller configuration.

    * You can use only the `joint_trajectory_controller`. Because it only accepts commands for _all_ controller joints and not _some_, you can write a small node that takes in commands and adds the current joint state to the missing joints.

    Solutions that don't yet exist:

    * Propose an enhancement to the `joint_trajectory_controller` so it can take trajectories not involving all group joints. There are likely subtle points to figure out to get the implementation right.

    Solutions that I don't recommend, but you can implement if you want to:

    * Override the default [resource conflict policy](https://github.com/ros-controls/ros_control/blob/indigo-devel/hardware_interface/include/hardware_interface/robot_hw.h#L73), so resource access is non-exclusive. Take into account that aloowing two controllers to send position commands to the same joint is not the best idea.

  body_markdown: "Based on the advice from Adolfo Rodriguez T. this worked for me:\n\
    \n    <?xml version=\"1.0\"?>\n    <launch>\n    \n        <!-- to switch arm\
    \ sim from trajectory controller to position controller during runtime -->\n \
    \       \n        <!-- unspawn arm sim trajectory controller -->\n        <node\
    \ pkg=\"controller_manager\" type=\"unspawner\" name=\"traj_ctrl_unspawner\" args=\"\
    left_arm_traj_controller\" />\n    \n        <!-- spawn arm sim position controller\
    \ -->\n        <node pkg=\"controller_manager\" type=\"spawner\" name=\"pos_ctrl_spawner\"\
    \n              args=\"left_arm_joint0_position_controller\n                 \
    \   left_arm_joint1_position_controller\n                    left_arm_joint2_position_controller\n\
    \                    left_arm_joint3_position_controller\n                   \
    \ left_arm_joint4_position_controller\n                    left_arm_joint5_position_controller\n\
    \                    left_arm_joint6_position_controller\" />\n    \n    </launch>\n\
    \nThen an alias:\n\n```\nalias enable_pos_ctrl='roslaunch mbot_gazebo_control\
    \ switch_from_traj_to_pos_ctrl.launch'\n```\n\nOnce you kill the launch file it\
    \ returns to its original controller (trajectory ctrl in my case)."
