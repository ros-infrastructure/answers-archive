    \n> ## Introduction\n> \n> ROS2 introduces the concept of managed\n> nodes, also\
    \ called LifecycleNodes. In\n> the following tutorial, we explain the\n> purpose\
    \ of these nodes, what makes\n> them different from regular nodes and\n> how they\
    \ comply to a lifecycle\n> management. Managed nodes are scoped\n> within a state\
    \ machine of a finite\n> amount of states. These states can be\n> changed by invoking\
    \ a transition id\n> which indicates the succeeding\n> consecutive state. The\
    \ state machine\n> is implemented as described at the\n> ROS2 design page.\n>\
    \ \n> Our implementation differentiates\n> between Primary States and Transition\n\
    > States. Primary States are supposed to\n> be steady states in which any node\
    \ can\n> do the respected task. On the other\n> hand, Transition States are meant\
    \ as\n> temporary intermediate states attached\n> to a transition. The result\
    \ of these\n> intermediate states are used to\n> indicate whether a transition\
    \ between\n> two primary states is considered\n> successful or not. Thus, any\
    \ managed\n> node can be in one of the following\n> states:\n> \n> Primary States\
    \ (steady states):\n> \n>     unconfigured\n>     inactive\n>     active\n>  \
    \   shutdown\n> \n> Transition States (intermediate\n> states):\n> \n>     configuring\n\
    >     activating\n>     deactivating\n>     cleaningup\n>     shuttingdown\n>\
    \ \n> The possible transitions to invoke\n> are:\n> \n>     configure\n>     activate\n\
    >     deactivate\n>     cleanup\n>     shutdown\n\n- https://design.ros2.org/articles/node_lifecycle.html\
    \ (ROS2 Design for LN)\n\n- https://index.ros.org/p/lifecycle/github-ros2-demos/\
    \ (demo example)\n\n- https://www.youtube.com/watch?v=ikmTPO9GoJc (short video\

  body_markdown: "As @ljaniec has mentioned before, we can use Lifecycle nodes to\
    \ achieve the behaviour required. I did a bit more reading on this, and found\
    \ a very simple example in ros2_control's [controller_manager](https://github.com/ros-controls/ros2_control/blob/master/controller_manager/src/controller_manager.cpp)\
    \ node. \n\nSince I essentially needed a timeout to ensure that the database node\
    \ has started before the GUI node in my example provided in the question, I chose\
    \ to go ahead with event handlers in ROS 2. This decision was mainly influenced\
    \ by the fact that event handlers are implemented on the launch file, so we do\
    \ not have to change the source code of the ROS node in any way. Also, at some\
    \ point if we want to roll back to a simpler launch file - let's consider that\
    \ we have done some magic on the database node and now we can guarantee that it\
    \ will always start before the gui starts, we can simply continue to reuse the\
    \ previous launch file. \n\nMaybe if I had to do the entire thing all over again,\
    \ I would end up using Lifecycle nodes, because I like the finer grain of control\
    \ we have over the node's behaviour that way. \n\nI would also like to mention\
    \ that these two methods are not interchangeable AFAIK, it's just two methods\
    \ of acheiving the same result. Proceed with caution. Thanks again to  @ljaniec\
    \ for introducing me to Lifecycle nodes."
