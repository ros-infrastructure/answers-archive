  body_markdown: "Some (long) hours later, here's an answer for those new to ROS who\
    \ might face the same questions.\n\n The basic idea behind avahi is... you can\
    \ resolve and connect to ROS machines without worrying about the IP they're behind.\
    \ This particularly when moving from one LAN to another (e.g lab to field, lab\
    \ to investor, etc). For e.g. theoretically, you could just connect your robot\
    \ and laptop to a hotspot on your phone and demo your kit.\n\nHint: a lowercase\
    \ system hostname/avahi hostname will serve you well! Ssh issue avoided later.\n\
    \n**Avahi setup**\n\tThere are a number of good tutorials out there. \n\tYour\
    \ machines would look like something.local and somethingelse.local\n        In\
    \ my case it was remote.local and local.local\n\tDo bi-directional ping tests\
    \ so both machines can ping and resolve the avahi hostnames\n\t\n**/etc/hosts**\n\
    \tIn my opinion, this should be vanilla Ubuntu something like this:\n\t\n\t  \
    \  127.0.0.1\tlocalhost\n\t\t# The following lines are desirable for IPv6 capable\
    \ hosts\n\t\t::1     ip6-localhost ip6-loopback\n\t\tfe00::0 ip6-localnet\n\t\t\
    ff00::0 ip6-mcastprefix\n\t\tff02::1 ip6-allnodes\n\t\tff02::2 ip6-allrouters\n\
    \t\n**SSH Issues:**\n\tAs some threads have noted, roslaunch uses an ssh lib that\
    \ requires an RSA key (default is now ECDSA-SHA2).\n\nIMPORTANT: Check your machine\
    \ hostname is lowercase. ssh-server defaults to lowercase in the authorized keys\
    \ file so your remote machine will keep asking you for a password when you punch\
    \ in your upper case hostname. \n\t\n    $ ssh user@remote.local -oHostKeyAlgorithms=\u2019\
    ssh-rsa\u2019\n\nFollow the prompts and say \u201Cyes\u201D  \t\n\n    user@remote\
    \ $ exit\n    $ ssh-keygen\n\nFollow the prompt and generate a public-private\
    \ key at ~/.ssh/\nProvide a password \n\n    $ ssh-copy-id -i ~/.ssh/id_rsa.pub\
    \ ssh user@remote.local \n\nThis copies your public key to the ~/.ssh/authorized_keys\
    \ file on the other machines\n\n    $  ssh user@remote.local\n\nConfirm a passwordless\
    \ entry is possible\nRepeat for local.local from remote.local\n\n**~/.bashrc**\n\
    \tI\u2019ve setup my ~/.bashrc like so\n\t\n\tsource /opt/ros/kinetic/setup.bash\n\
    \texport ROS_MASTER_URI=http://local.local:11311\n\texport ROS_IP=local.local\n\
    \texport ROS_HOSTNAME=local.local\n\n This allows me to launch roscore and nodes\
    \ on my development machine when needed and \tremote connect from remote.local\
    \ as well. You can replicate the script as you please on remote.local\n\nI use\
    \  env-loader from roslaunch to setup environment variables on both machines\n\
    \nEnvironment-loader script somewhere on remote.local:\n\n\texport ROS_IP=remote.local\n\
    \texport ROS_MASTER_URI=http://remote.local:11311\n\texport ROS_HOSTNAME=remote.local\n\
    \texec \"$@\"\n\t# Anything else you need\u2026.\n\nEnvironment-loader script\
    \ somewhere on local.local:\n\n\texport ROS_IP=local.local\n\texport ROS_MASTER_URI=http://remote.local:11311\n\
    \texport ROS_HOSTNAME=local.local\n\texec \"$@\"\n\t# Anything else you need\u2026\
    .\n\nAgain, above, my ros master needs to be on the remote robot so it\u2019s\
    \ alive even if the link dies.\n\nBTW these scripts MUST be read-writeable for\
    \ the user you\u2019re ssh-ing into\n\nFor the launch file:\n\t   \n\n       \
    \ <launch>\n             <!-- Setup environment -->\n            <arg name=\"\
    machine_bot\" default = \"remote\"/>\n            <arg name=\"machine_c2i\" default\
    \ = \"local\"/>\n            <arg name=\"ip_bot\" default = \"remote.local\"/>\n\
    \            <arg name=\"ip_c2i\" default = \"local.local\"/>\n            <arg\
    \ name=\"machine_bot_user\" default = \"abc\"/>\n            <arg name=\"machine_c2i_user\"\
    \ default = \"xyz\"/>\n            <machine name=\"$(arg machine_bot)\"\n    \
    \                 address=\"$(arg ip_bot)\"\n                     user=\"$(arg\
    \ machine_bot_user)\"\n                     env-loader=\"path_to/script.sh\u201D\
    \n            <machine name=\"$(arg machine_c2i)\"\n                     address=\"\
    $(arg ip_c2i)\"\n                     user=\"$(arg machine_c2i_user)\"\n     \
    \                env-loader=\"path_to/script.sh\u201D\n                     timeout=\"\
    10.0\"\n                     default=\"never\" >\n            </machine> \t\n\
    \    <!-- ALL OTHER NODES GO HERE -->\n     </launch>   \n \n\n$ roslaunch your_package\
    \ your_launch.launch\n\neh voila! No more static IP management. I hope it works\
    \ for you."

How do you setup a local and remote ROS system to launch a roscore and nodes on two machines with avahi/zeroconf, i.e. without hard coding IP addresses on your LAN?

In my case, the requirements are:

 1. Local machine: some nodes for image visualization and slam
 2. Remote robot: roscore, platform specific nodes, sensor publishers 
 3. Avoid hard coding IPs in  .launch, .bashrc and shell scripts - robot and laptop
 4.  should find each other by a hostname without editing /etc/hosts
