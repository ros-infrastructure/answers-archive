  body_markdown: "I believe the naming of these images -- and their contents -- follows\
    \ the *variants* defined in [REP-150: ROS Melodic and Newer Metapackages](https://ros.org/reps/rep-0150.html)\
    \ (for ROS 2, it's [REP-2001: ROS 2 Variants](https://ros.org/reps/rep-2001.html)).\n\
    \nFor `ros_core` for instance:\n\n> The ros_core metapackage composes the core\
    \ communication protocols. It may not contain any GUI dependencies.\n> \n>   \
    \  - ros_core:\n>          packages: [catkin, class_loader, cmake_modules, common_msgs,\
    \ gencpp,\n                    geneus, genlisp, genmsg, gennodejs, genpy, message_generation,\n\
    \                    message_runtime, pluginlib, ros, ros_comm,\n            \
    \        rosbag_migration_rule, rosconsole, rosconsole_bridge,\n             \
    \       roscpp_core, rosgraph_msgs, roslisp, rospack, std_msgs,\n            \
    \        std_srvs]\n\nthat's why you only see `apt-get install [..] ros-noetic-perception`\
    \ in the `Dockerfile`.\n\nIt just installs the `perception` variant.\n\nThe `focal`\
    \ and `buster` suffixes are indeed to differentiate between the different OS supported\
    \ by a particular ROS version.\n\nROS Noetic supports both Ubuntu Focal and Debian\
    \ Buster. But the `ros_core` variant is part of both of those.\n\nSo to differentiate\
    \ between them, the OS code name was added, which makes it\n\n> The `ros_core`\
    \ variant of ROS Noetic on Ubuntu Focal\n\nand similar for Debian Buster.\n\n\
    Those `Dockerfiles` are not written by hand, but generated using the scripts in\
    \ the [osrf/docker_images](https://github.com/osrf/docker_images) repository.\
    \ Those scripts parse a large `.yaml` file which contains information on all the\
    \ different OS + ROS version + variant combinations. See [osrf/docker_images/ros/manifest.yaml](https://github.com/osrf/docker_images/blob/85f686512bdfb0ddf2dd187d9aea95c9cebdfc0c/ros/manifest.yaml#L331-L379)\
    \ for the information used to generate the ROS Noetic images.\n\nThe tags for\
    \ each image are also generated based on this information:\n\n>     noetic:\n\
    \      eol: 2025-05\n      os_names:\n        ubuntu:\n          os_code_names:\n\
    \            focal:\n              <<: *DEFAULT_ROS1\n              archs:\n \
    \               - amd64\n                - arm32v7\n                - arm64v8\n\
    \              tag_names:\n                ros-core:\n                  aliases:\n\
    \                    - \"$release_name-ros-core\"\n                    - \"$release_name-ros-core-$os_code_name\"\
    \n        debian:\n          [..]\n\nSee the `aliases` key, which is responsible\
    \ for the `noetic-ros-core`, `noetic-ros-core-focal` images you found (and which\
    \ indeed contain the same packages)."
