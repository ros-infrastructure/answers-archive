  body_markdown: "The logs are quite clear: your global cost map is waiting for map\
    \ -> base_link transformation available. Usually this transformation need two\
    \ others to be calculated:\n\n - map -> odom, broadcasted by amcl;\n - odom ->\
    \ base_link, broadcasted by odometry.\n\nRun\n\n    rosrun tf view_frames\n\n\
    to check your tf tree.\n\n## UPDATE ##\n\nAs I supposed odom -> base_link transformation\
    \ is missing!! \n\n> And why I can't see the laser scan ?\n\nThis is crucial since\
    \ you set RViz to use map as fixed frame. Laser scan is attached to base_laser_link\
    \ and, in order to show it in map frame, a transformation is needed but, as you\
    \ can see from the tree, there is no linkage from base_laser_link and map.\n\n\
    Next question should be: why odom -> base_link is missing? I have no experience\
    \ with neato robot but from you log I can see:\n\n    NODES\n      /\n       amcl\
    \ (amcl/amcl)\n       map_server (map_server/map_server)\n       move_base (move_base/move_base)\n\
    \nIt seems that the neato node (who have to publish odom -> base_link transformation,\
    \ odom and laser data) was not started! Please use\n\n    rqt_graph\n\nand post\
    \ the result (this tool will show all running node and published/subscribed topic).\
    \ Try also:\n\n    rostopic list\n\nto check all published topics.\n\n## UPDATE\
    \ ##\n\nneato node is running, this is ok. base_scan is published too but not\
    \ subscribed by gmapping (as shown by rqt_graph)  since it expect it as scan topic.\
    \ You have to remap base_scan to scan when launch gmapping.\n\nFurthermore try:\n\
    \n    rostopic echo base_scan\n\nThis will print out the published laser scan\
    \ data. With this command we can be sure some data is published and you can also\
    \ check (in the printed message header) to which frame the laser data is attached\
    \ to. Set this frame as fixed frame in RViz and you should be able to see scan\
    \ data."
