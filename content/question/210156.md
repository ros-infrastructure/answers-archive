  body_markdown: "[This tutorial](http://wiki.ros.org/dynamic_reconfigure/Tutorials/HowToWriteYourFirstCfgFile)\
    \ provides a short description.  Another short discussion is [here](https://answers.ros.org/question/9883/what-are-the-semantics-of-reconfiguration-level-for-dynamic-reconfigure/).\
    \  To summarize, the `level` is just a bit mask that allows you to group reconfigurable\
    \ parameters for your own use in the service callback.  For posterity, I found\
    \ this tidbit (from the second link) useful for understanding:\n\n> I had this\
    \ discussion with Blaise\n> Gassend a year or so ago. He said the\n> `level` parameter\
    \ is just a bit mask. It\n> can be used to classify sets of\n> parameters in any\
    \ way that is\n> convenient to the package defining the\n> server. The bits for\
    \ all parameter\n> classes that have changed will be `OR`ed\n> together for the\
    \ service callback.\n> \n> One useful classification scheme is\n> suggested by\
    \ the `driver_base` states:\n> \n>   1. Parameters that can only be changed while\
    \ the device is closed.\n>   2. Parameters that can be changed while the device\
    \ is not streaming.\n>   3. Parameters that can be changed while the device is\
    \ open and\n> streaming.\n> \n> But, servers are free to classify\n> their parameters\
    \ any way they like."

  body_markdown: "I did not find a satisfying answer in other threads. \nSo i am writing\
    \ one here if somebody still requires it. \n\nSo the \"level\" parameter is a\
    \ int variable, where each bit can be representing a reconfigurable parameter.\
    \ For example if i have 3 parameters, level value can be set to \"0,1,2\" for\
    \  the 3 parameters in the cfg file.so the 0,1,2 bits of variable \"level\" will\
    \ be set depending on what parameter has been changed in rqt reconfigure. If parameter1\
    \ has been changed, the corresponding bit in the \"level\" will be set to 1. \n\
    \nThis variable \"level\" is passed in the reconfigure callback. So we know which\
    \ variable is changed, and update accordingly, instead of updating all of them.\
    \ \nHope this explains it. If any improvements to be made please comment."
