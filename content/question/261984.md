  body_markdown: "Adapted from this [wiki](http://wiki.ros.org/opencv3):\n\nIf you\
    \ have `OpenCV2` and `OpenCV3` installed, find_package(OpenCV) in CMake will first\
    \ find `OpenCV3`. \n\nIf you want to explicitly link to `OpenCV2`, use `find_package(OpenCV\
    \ 2)`.\n\nIf you have `OpenCV2` and `OpenCV3` installed, `OpenCV3` is not on your\
    \ path: libraries and headers are renamed to only be visible through `CMake`.\
    \ Python is the only exception but you can use the guide below to get your code\
    \ to work with both.\nJust like with any library, you have to be careful that\
    \ your binary does not link/includes directly or indirectly (through a dependency)\
    \ to both `OpenCV2` and `OpenCV3`.\n\n`Python`:\n\n        import cv2\n      \
    \  from distutils.version import LooseVersion\n        if LooseVersion(cv2.__version__).version[0]\
    \ == 2:\n        # Whatever OpenCV2 code\n        else:\n         # Whatever OpenCV3\
    \ code\n\n`C++:`\n\n       #include \"opencv2/core/version.hpp\"\n       #if CV_MAJOR_VERSION\
    \ == 2\n       // do opencv 2 code\n       #elif CV_MAJOR_VERSION == 3\n     \
    \ // do opencv 3 code\n      #endif\n\n`CMake`:\n\n    if(OpenCV_VERSION VERSION_LESS\
    \ \"3.0\")\n    # use 2.4 modules\n    else()\n    # use 3.x modules\n    endif()\n\
    \n`Package.xml`:\n\nInstead of depending on opencv3, you should depend on cv_bridge\
    \ or image_geometry. Depending on one of those two keys transitively makes you\
    \ depend on libopencv-dev on Jade and below, or opencv3 on Kinetic and above.\n\
    \nimage_pipeline will only pull in sensor_msgs as an extra dependency while cv_bridge\
    \ will also pull in boost, python and rosconsole so it depends on whether you\
    \ go for something small or something you need.\n\n**Building the OpenCV package**\n\
    \nSee this [wiki](http://wiki.ros.org/opencv3#Building_the_Package)."

Hello! I am using ROS Kinetic on Ubuntu 16.04 Xenial 64bit. I have installed both opencv2 (by libopencv-dev) and opencv3 (by ros-kinetic-opencv3). A project of mine depends on cv_bridge, the problem is: by compilation opencv3 is always linked instead of opencv2 that is acutally needed, although in CMakeLists.txt I have explicitly indicated to use opencv2:

find_package(OpenCV 2.4.9.1 EXACT REQUIRED) 

I also tried:

find_package(OpenCV 2 REQUIRED)

but it failed too. If I remove the dependency of cv_bridge in CMakeLists.txt, opencv2 is correctly linked, but the compilation complains the lack of cv_bridge library. Any suggestion or experience on this issue? Thanks in advance!

PS: when I output the path where the opencv2 header files are found to be stored in CMakeLists.txt:

message( STATUS "OpenCV Include Dir: " ${OpenCV_INCLUDE_DIRS} )

it gives me a weird result:

/usr/include/opencv/usr/include

although it does not break the compilation when the dependency on cv_bridge is removed.
