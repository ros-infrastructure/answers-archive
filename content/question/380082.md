I am now working on a ROS local network. For now, we have 2 computers: 

 1. Simulation computer  is the HOST and publishes images from Gazebo (a depth camera model) to ROSTopics; 
 2. Computation/offboard computer receives the image topics and does some machine learning. 

However I notice some issues concerning the network latency which depends on the physical configurations:

 1.  Using a network switch (TPlink 10/100): I use the commande ping and find out an average delay of 1.5 ms. As a result, the  image_transport of cv_bridge cannot catch all frames (color rgb + depth 32fc1 generated together with same time stamp)  and it also blockes my code in the frame-searching loop due to time stamp condition. 
 2. Using an ethernet crossover  cable: delay reduces to 0.3-0.4 ms and I dont have any problem to receive the image.

So, there is any solution for first case ? The wire connection may lead to this problem ? In fact, we would like to expand the ROS network in the future, so there will be more topics with lots of data and of course latency has to be minimized to ensure all the computation.
