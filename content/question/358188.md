  body_markdown: "In that case, personally, I'd lean towards constructing a `tf2::Matrix3x3`\
    \ from the `cv::Mat`. Then you can construct a `tf2::Transform` from the `Matrix3x3`,\
    \ and then use `tf2::toMsg` to convert to a `geometry_msgs/Pose` directly. You\
    \ could also call `getRotation` as I mentioned earlier to get a Quaternion directly,\
    \ and then fill out the components of the `pose.orientation` with the components\
    \ of the quaternion.\n\nA quick Google also found this which might be helpful:\
    \ https://gist.github.com/shubh-agrawal/76754b9bfb0f4143819dbd146d15d4c8\n\n**EDIT**\n\
    \nSince this became the accepted answer, I figured I'd post a little example of\
    \ what I described. Something like the following should work:\n\n    #include\
    \ <opencv2/calib3d.hpp>\n    #include <opencv2/core.hpp>\n    #include <tf2/LinearMath/Matrix3x3.h>\n\
    \    #include <tf2/LinearMath/Transform.h>\n    #include <tf2/LinearMath/Vector3.h>\n\
    \    #include <tf2_geometry_msgs/tf2_geometry_msgs.h>\n    \n    // Build identity\
    \ rotation matrix as a cv::Mat\n    cv::Mat rot(3, 3, CV_64FC1);\n    cv::Rodrigues(cv::Vec3d({0.0,\
    \ 0.0, 0.0}), rot);\n    // Convert to a tf2::Matrix3x3\n    tf2::Matrix3x3 tf2_rot(rot.at<double>(0,\
    \ 0), rot.at<double>(0, 1), rot.at<double>(0, 2),\n                          \
    \ rot.at<double>(1, 0), rot.at<double>(1, 1), rot.at<double>(1, 2),\n        \
    \                   rot.at<double>(2, 0), rot.at<double>(2, 1), rot.at<double>(2,\
    \ 2));\n    // Create a transform and convert to a Pose\n    tf2::Transform tf2_transform(tf2_rot,\
    \ tf2::Vector3());\n    geometry_msgs::Pose pose_msg;\n    tf2::toMsg(tf2_transform,\
    \ pose_msg);"
