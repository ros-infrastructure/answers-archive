  body_markdown: "Loading things up in gazebo isn't exactly a walk in the park it\
    \ seems they need things to be in a very specific layout which I detail below.\n\
    \n\n    \u2514\u2500\u2500 simple_box\n        \u251C\u2500\u2500 model.config\n\
    \        \u251C\u2500\u2500 simple_box.dae\n        \u251C\u2500\u2500 simple_box.sdf\n\
    \        \u2514\u2500\u2500 simple_box.urdf\n\nThe following gazebo command will\
    \ convert files, provide warnings about what is wrong, and print a converted file\
    \ out on the command line: \n\n\n    gz-8.1.1 sdf -p ~/src/bullet3/data/kuka_iiwa/kuka_with_gripper.urdf\n\
    \n\nThe printout which can be redirected to overwrite the original sdf file, for\
    \ example:\n\n    gz-8.1.1 sdf -p ~/src/bullet3/data/kuka_iiwa/kuka_with_gripper.urdf\
    \ >  ~/src/bullet3/data/kuka_iiwa/kuka_with_gripper.sdf \n\n\n### Models\n\nHere\
    \ are some very simple models I've compressed for convenience, plus an updated\
    \ `simple_box.zip`, these all load in both gazebo and V-REP except V-REP doesn't\
    \ seem to support textures:\n- [simple_box.zip](https://github.com/bulletphysics/bullet3/files/1053603/simple_box.zip)\
    \ your simple_box updated to load in gazebo and V-REP\n- [ball_bearing.zip](https://github.com/bulletphysics/bullet3/files/1053568/ball_bearing.zip)\
    \ should be dark gray, has a material definition (a V-REP option), and is otherwise\
    \ very simple\n- [bookshelf.zip](https://github.com/bulletphysics/bullet3/files/1053569/bookshelf.zip)\
    \ includes a texture and is composed of several simple boxes\n- [cinder_block.zip](https://github.com/bulletphysics/bullet3/files/1053606/cinder_block.zip)\
    \ includes a collada mesh\n\nThe materials spec they have also seems to be important\
    \ if there is to be a shelf made of wood:\n```\n\n        <material>\n       \
    \   <script>\n            <uri>file://media/materials/scripts/gazebo.material</uri>\n\
    \            <name>Gazebo/Wood</name>\n          </script>\n        </material>\n\
    ```\n\nAnd gazebo won't load model/mesh files next to the sdf file unless it is\
    \ specified with `model://model_folder_name/model_mesh_file.dae`, as you can see\
    \ in this working version of `simple_box.dae`:\n\n    <sdf version='1.6'>\n  \
    \    <model name='cube'>\n        <link name='baseLink'>\n          <pose frame=''>0\
    \ 0 0 0 -0 0</pose>\n          <inertial>\n            <pose frame=''>0 0 0 0\
    \ -0 0</pose>\n            <mass>1</mass>\n            <inertia>\n           \
    \   <ixx>1</ixx>\n              <ixy>0</ixy>\n              <ixz>0</ixz>\n   \
    \           <iyy>1</iyy>\n              <iyz>0</iyz>\n              <izz>1</izz>\n\
    \            </inertia>\n          </inertial>\n          <collision name='baseLink_collision'>\n\
    \            <pose frame=''>0 0 0 0 -0 0</pose>\n            <geometry>\n    \
    \          <box>\n                <size>1 1 1</size>\n              </box>\n \
    \           </geometry>\n          </collision>\n          <visual name='baseLink_visual'>\n\
    \            <pose frame=''>0 0 0 0 -0 0</pose>\n            <geometry>\n    \
    \          <mesh>\n                <scale>1 1 1</scale>\n                <uri>model://simple_box/simple_box.dae</uri>\n\
    \              </mesh>\n            </geometry>\n          </visual>\n       \
    \ </link>\n      </model>\n    </sdf>\n\nIt seems part of the solution is that\
    \ the models don't need to define the `world`, they can simply be a `model` like\
    \ the files above. An additional requirement for gazebo is the `model.config`\
    \ file, which specifies the name of the object and the path to the sdf file. Gazebo\
    \ also requires model file (like collada).\n\n### Simulations aka World\n\nThe\
    \ `world` definition is what has all those extra requirements such as specifying\
    \ gravity, light sources, simulation refresh rate, etc. You may want to support\
    \ simulation definitions, but it should likely not be used for simple model definitions.\n\
    \nHere is everything needed for a basic simulation world definition but note that\
    \ there seems to be a [small bug in the saved vs loaded dimensions as specified\
    \ in gazebo 8.1.1](https://bitbucket.org/osrf/gazebo/issues/2292/world-does-not-save-and-load-consistently).\n\
    \n- [brick_box_world.zip](https://github.com/bulletphysics/bullet3/files/1053693/brick_box_world.zip)\
    \ A world containing default settings and a brick box\n- [brick_box_3x1x3.zip](https://github.com/bulletphysics/bullet3/files/1053694/brick_box_3x1x3.zip)\
    \ the brick box model in the above world\n\nThis answer adapted from https://github.com/bulletphysics/bullet3/issues/1156#issuecomment-306367636"
