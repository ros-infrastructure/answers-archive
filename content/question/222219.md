  body_markdown: "I have only limited experience with doing SLAM using a Velodyne\
    \ (or other point cloud sensor), but I have some observations and suggestions\
    \ that may help:\n\n* The PCAP data will probably not be sufficient for good SLAM\
    \ performance. You want to at least save Odomentry data, along with the sensor\
    \ output.\n\nThe easiest way to do that is with [rosbag record](http://wiki.ros.org/rosbag/Commandline#record).\
    \ Save the raw ``/velodyne_packets`` topic published by the [velodyne_driver](http://wiki.ros.org/velodyne_driver#Published_Topics),\
    \ along with the robot's odomentry (usually published in the ``/odom`` topic),\
    \ the robot's coordinate transforms in ``/tf``, and perhaps some IMU data. \n\n\
    * You need to massage the data into the format accepted by your chosen SLAM implementation.\n\
    \nThe familiar [ROS gmapping package](http://wiki.ros.org/gmapping) requires your\
    \ point cloud to be converted into a 2D laser scan message. That's not as silly\
    \ as it may sound, if you are making a 2D map anyway. The [ROS point cloud to\
    \ laser scan package](http://wiki.ros.org/pointcloud_to_laserscan) will handle\
    \ that conversion for you, squashing points from a selected 3D region into a 2D\
    \ [sensor_msgs/LaserScan](http://docs.ros.org/api/sensor_msgs/html/msg/LaserScan.html). "
