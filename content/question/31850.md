  body_markdown: "Hello,\n\nOMPL itself does support the functionality you would like\
    \ to test (In fact, we are just about to push some changes to the OMPL repository\
    \ that allow outputting GraphML structures for the trees OMPL planners generate).\n\
    \nHowever, that functionality is not exposed through the ompl_ros_interface package\
    \ in ROS Electric. This functionality is implemented for Fuerte, part of the upcoming\
    \ MoveIt project (not yet released). \n\nSo.. the way to do this with ROS Electric\
    \ will require adding some local hacks on your side:\nIn the ompl_ros_interface\
    \ package, the file src/ompl_ros_planning_group.cpp contains the call to the solve()\
    \ function of an OMPL planner:\n\n{{{\n  bool solved = planner_->solve(request.motion_plan_request.allowed_planning_time.toSec());\n\
    }}}\n\nThis is Line 446 for me.\n\nAfter that line, you can do something like\
    \ this:\n\n{{{\n\nconst ompl::base::PlannerData &pd = planner_->getPlannerData();\n\
    \nplanning_models::KinematicState \nkstate(*collision_models_interface_->getPlanningSceneState());\n\
    \nfor (std::size_t i = 0 ; i < pd.states.size() ; ++i)\n{\n\nomplStateToKinematicStateGroup(pd.states[i],\
    \ ompl_state_to_kinematic_state_mapping_\n                           kstate->getJointStateGroup(physical_joint_state_group_));\n\
    \nkstate->getJointStateGroup(physical_joint_state_group_)->updateKinematicLinks();\n\
    \nbtTransform bt = kstate->getLinkState(\"some link\")->getGlobalLinkTransform();\n\
    \n// do whatever with this; a NodeHandle is available in the class, so this can\
    \ be published.\n\n}\n\n}}}\n\nThe only catch with the above code is that ompl_state_to_kinematic_state_mapping_\
    \ is not available in that class, so you have to change the planner class(es),\
    \ e.g. ompl_ros_joint_planner.cpp, to pass that variable to the planning group.\n\
    \nI'm sorry this is so complicated right now, but for the next version things\
    \ should be easier.\n\n"
