    This is the purpose of robot_upstart package:

    http://wiki.ros.org/robot_upstart

    I tested it and For me it worked quite nice. It sets Up a service that automatically starts your launch file as the machine is started. The doc can be found here:

    http://docs.ros.org/jade/api/robot_upstart/html/

    **Edit in reply to comment:**

    See the doc of the install script for HowTo set ROS_MASTER and HOST_NAME:

    http://docs.ros.org/jade/api/robot_upstart/html/install.html

    An important *NOTE* for the use of the `--interface` option of the install script is that the interface you bind it to (e.g. eth0) has to be up before the service running your roslaunch file is started. This means that you have to configure it using the `/etc/network/interfaces` file and not using the NetworkManager. If you only configure it using the NetworkManager it will be up to late and the ROS connection won't work.

  body_markdown: "Another option is to use `systemd`. A simple example:\n\nContents\
    \ of `/lib/systemd/system/robot.service`:\n\n    [Unit]\n    Description=My Robot\n\
    \    \n    [Service]\n    User=root\n    ExecStart=/home/me/catkin_ws/src/robot/scripts/start_robot.sh\n\
    \    \n    [Install]\n    WantedBy=multi-user.target\n\nContents of `/home/myaccount/catkin_ws/src/robot/scripts/start_robot.sh`:\n\
    \n    bash -c \"source /home/me/catkin_ws/devel/setup.bash && roslaunch robot\
    \ robot.launch\"\n\nThen use `systemctl` to control it:\n\n    sudo systemctl\
    \ start robot.service # start\n    sudo systemctl stop robot.service # stop\n\
    \    sudo systemctl enable robot.service # start on boot\n    sudo systemctl disable\
    \ robot.service # disable start on boot\n\n(Edit to add some debugging notes.)\n\
    \nNote that you can set \"User=<any user>.\" Debugging will be easier if you can\
    \ use your typical login. Of course, you should never use root unless you absolutely\
    \ have to.\n\nDebugging a boot-time launch can be annoying, since you need to\
    \ rely on logging. I typically use `roslaunch --screen` from the command line\
    \ to develop and debug, then move to manual start/stop to do system tests, then\
    \ only when when I'm ready to do a full end-to-end test do I enable start at boot.\n\
    \nA few tricks for debugging:\n\nSet `output=\"log\"` on all nodes. (The default\
    \ is output to log, so you can just remove the `output=\"screen\"` option as well.)\
    \ This will send all ROS_INFO messages to log files so that they don't clutter\
    \ up the `systemd` logs.\n\nAdd `stdbuf -oL` to your command line invocations:\n\
    \n    bash -c \"source /home/myaccount/catkin_ws/devel/setup.bash && stdbuf -oL\
    \ roslaunch robot robot.launch\"\n\nThis will flush the output buffers after every\
    \ line so that you see log messages quickly.\n\nTo see errors, run `systemctl\
    \ status robot.service`. To see ROS_INFO messages, run `tail -f ~/.ros/log/latest/mynode-*-stdout.log\"\
    `."
