  body_markdown: "I could solve the problem. \nIt was caused by the python version.\
    \ I have Python 3.9(Anaconda) and Python 3.10(ROS) on my PC. Somehow there was\
    \ a mismatch and ROS used Anaconda but needed a python 3.10 version. By creating\
    \ a new environment with only Python 3.10 running, all worked fine. \n(I think\
    \ updating python3 to 3.10 should solve the problem)\n\nThe terminal doesn't exactly\
    \ explain this in its error message, it rather could say :\n\n    [spawn_entity.py-5]\
    \ The C extension '/opt/ros/humble/lib/python3.10/site-packages/_rclpy_pybind11.cpython-39-x86_64-linux-gnu.so'\
    \ isn't present on the system. Please refer to 'https://docs.ros.org/en/humble/Guides/Installation-Troubleshooting.html#import-failing-without-library-present-on-the-system'\
    \ for possible solutions\n\nThe key word here is `rclpy` which is then explained\
    \ in the provide debug link :\nhttps://docs.ros.org/en/humble/How-To-Guides/Installation-Troubleshooting.html\n\
    \nHowever, the link doesn't provide a good explanation on how to fix it. \n\n\
    Tips for the new environment: \nI tried to build it with \"conda\", but this didn't\
    \ work flawless, so instead I used \"venv\". \nFor me: \n\n    sudo apt update\n\
    \    sudo apt install python3.10 python3.10-venv python3.10-dev\n    python3.10\
    \ -m venv my_ros_env_py310\n    source my_ros_env_py310/bin/activate\n\nMaybe\
    \ you need some packages afterwords but you do not have to reinstall whole ROS\
    \ just source it in the new environment."
