    Afaict, there is no `libcurlpp-dev` in the current `rosdep` [db](https://github.com/ros/rosdistro/blob/758f24e2bfc27f3ccb1ebaf5b273534596f18024/rosdep/base.yaml).

    The only keys which contain the `libcurl` substring are `libcurl` and `libcurl-dev`.

    `libcurlpp-dev` does not exist. Only `curlpp-dev` ([here](https://github.com/ros/rosdistro/blob/758f24e2bfc27f3ccb1ebaf5b273534596f18024/rosdep/base.yaml#L706-L711)).

    Seeing the traceback though, it would appear this is not a problem with the `rosdep` side of things, but while actually installing packages (in this case the `.deb`): `curlpp-dev` maps to `libcurlpp-dev` for `debian`. According to [this](https://packages.debian.org/search?suite=all&searchon=names&keywords=libcurlpp-dev), that package only exists in `bullseye`, `bookworm` and `sid` (if you include Debian Unstable).

    If it doesn't exist in other releases, the `curlpp-dev` key might have to be specialised further for the `debian` OS entry.
