  body_markdown: "You can set cartographer to publish odometry, or else you can generate\
    \ odometry using some other algorithms. But you cannot do both at the same time.\
    \ \n\nYou may need to know that odometry which provided by wheel encoder is odom->base_link,\
    \ map->odom is the drift error and provided by mapping process.\n\nreference:\
    \ https://google-cartographer-ros.readthedocs.io/en/latest/configuration.html\n\
    \nIf you only want to use cartographer with your lidar and IMU, and do not want\
    \ to use a supplementary odometry, set use_odometry to false, and published frame\
    \ should be base_footprint or base_link. Because a mapping procedure normally\
    \ publish tf from map to odom, which indicates the drift error. The drift error\
    \ plus a raw odometry we will have the pose of base_link w.r.t. map. \n\nThen\
    \ you can configure whether you want cartographer provide the odom frame. set\
    \ provide_odom_frame to false the mapping process will give you base_link to map\
    \ directly, however as a convention, better set provide the odom frame to true\
    \ and the odom frame will be published. Then you can have the odom info from cartographer.\
    \ \n\n\n\n      map_frame = \"map\",\n      tracking_frame = \"IMU_link\",\n\n\
    \      use_odometry = false,\n      published_frame = \"base_footprint\",\n\n\
    \      provide_odom_frame = true,\n      odom_frame = \"odom\",\n\n\n\nAs you\
    \ have already disabled odometry, you could set imu to true, this gives better\
    \ SLAM result.\n\n      TRAJECTORY_BUILDER_2D.use_imu_data = true\n\n\nAnother\
    \ case is that you can use some other method to generate odom instead of cartographer.\
    \ For example if you use velodyne you can try https://github.com/laboshinl/loam_velodyne,\
    \ or rplidar you can try https://github.com/MAPIRlab/rf2o_laser_odometry\n\nif\
    \ you have wheel encoder, it is similar configuration. if you set provide odom\
    \ frame to true, cartographer node wont die but the odom frame will oscillating\
    \ because tf to odom is broadcasted by two nodes. In this case,  odom_frame has\
    \ no use.\n\nEven if you set imu to true, it will not adjust the perception according\
    \ to imu readings.  Sensor readings are attached to base_link which is provided\
    \ by odom->base_link which is provided by odometry.\n\n      map_frame = \"map\"\
    ,\n      tracking_frame = \"base_footprint\",\n\n      use_odometry = true,\n\
    \      published_frame = \"odom\",\n\n      provide_odom_frame = false,\n    \
    \  odom_frame = \"odom\",\n\n\n(Some conclusion is not fully tested but I think\
    \ it will be.)\n\nIf you are interested in the full code, I am busy updating an\
    \ racecar project recently. you could check this out: https://github.com/tianbot/tianracer"
