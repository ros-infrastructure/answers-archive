  body_markdown: "Solution: \nI wrote my own get_mark_next_dbase_task_of_type(), which\
    \ worked and added grasps to the database successfully for GRASP_PLANNING and\
    \ GRASP_CLUSTERING tasks. I did not test it with the other two types (GUIDED_GRASP_PLANNING,\
    \ VELO_GRASP_PLANNING). It is written based on the get_mark_next_dbase_task()\
    \ from the *0.5_electric*.backup file.\n\n<pre>\n-- Function: get_mark_next_dbase_task_of_type(text[])\n\
    \n-- DROP FUNCTION get_mark_next_dbase_task_of_type(text[]);\n\nCREATE OR REPLACE\
    \ FUNCTION get_mark_next_dbase_task_of_type(IN dbasetasktype text[])\n  RETURNS\
    \ integer AS\n$BODY$\nDECLARE next_id INTEGER;\n BEGIN\n SELECT dbase_task_id\
    \ INTO next_id FROM dbase_task\n        WHERE dbase_task_type = ANY ($1)\n   \
    \     LIMIT 1 FOR UPDATE;\n UPDATE dbase_task SET dbase_task_outcome_name = 'RUNNING'\n\
    \        WHERE dbase_task_id = next_id;\n return next_id;\n END;\n$BODY$\n  LANGUAGE\
    \ plpgsql VOLATILE\n  COST 100;\nALTER FUNCTION get_mark_next_dbase_task_of_type(text[])\n\
    \  OWNER TO willow;\n</pre>\n\nChange willow in the last line to whatever your\
    \ username is.\n\nAnother thing I had to do before the grasps would calculate\
    \ correctly was to rescale our model to be much smaller. Rule of thumb is that\
    \ both the object and the arm you're using should show up in GraspIt. Manually\
    \ running GraspIt Eigengrasp Planner to see what's supposed to happen helps (\
    \ www.cs.columbia.edu/~cmatei/graspit/html-manual/graspit-manual_12.html#id5 ).\
    \ The ROS GraspIt plugin uses the Eigengrasp Planner with Search Space Complete\
    \ and simulated annealing to output the [tx ty tz qw qx qy qz].\n"
