    For your information, i do not use rosbridge for them to communicate in a localhost\

    \ I believe it is easier than rosbridge. That's why I provide this suggestion.\
    \ \n\nIt enables you to publish and subscribe topic among machines that setup\
    \ in localhost env. So far, it i working fine for me. Below shows the steps required\
    \ to set this up. Hopefully, it is useful for you.\n\nStep\n\n1) After connected\
    \ to localhost,at master, export ROS_MASTER_URI with master's ifconfig address\
    \ along with 11311 port.\n\n2) roscore\n\n3) may start some nodes at master (Optional)\n\
    \n4) SSH to slave, export ROS_MASTER_URI with master's ifconfig address along\
    \ with 11311 port (After the slave connected to the localhost).\n\n5) export ROS_HOSTNAME\
    \ *Slave's IP addr*\n\n6) export ROS_IP *Slave's IP addr*\n*Slave's IP addr will\
    \ be used for both ROS_HOSTNAME and ROS_IP*\n\n7) SSH to slave and you may start\
    \ some nodes at slave by using rosrun or roslaunch\n\nUsage:\n\nAll nodes connected\
    \ to the Master may access all the data.\nBy using ssh from workspace (Ex. ssh\
    \ 192.168.1.17), we may control other machines such as initialize nodes.\n\n\n\
