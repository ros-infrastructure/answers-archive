  body_markdown: |-
    Your projects are setup correctly (mostly), you just need to run `catkin_make` with no arguments.

    First update `foo`:

        cmake_minimum_required(VERSION 2.8.3)
        project(foo)

        find_package(catkin REQUIRED COMPONENTS foo_msgs)

        catkin_package()

        include_directories(include ${catkin_INCLUDE_DIRS})

        add_executable(foo_node src/foo_node.cpp)
        add_dependencies(foo_node foo_msgs_generate_messages_cpp)

    Using `add_dependencies(...)` is by design or necessity, however you look at it, because we cannot know or assume that `foo`'s targets (executables or libraries) use and therefore depend on the messages which are getting generated by `foo_msgs`.

    Then just execute `catkin_make` with no arguments.

    If you want to build `foo_msgs` explicitly (not the whole workspace) then as of pull request [ros/catkin#352](https://github.com/ros/catkin/pull/352) you can do `catkin_make --pkg foo_msgs`.

    Calling `catkin_make foo_msgs` is not sufficient because that is instructing `catkin_make` to invoke the `foo_msgs` make target which does not exist. tkruse's solution simply adds a `foo_msgs` target which depends on the `foo_msgs_generate_messages_cpp` target, allowing it to be callable and causing the `foo_msgs_generate_messages_cpp` target to be generated. This is not something we do by default because packages often define targets with the same name as the project which would immediately cause a conflict.

    The only reliable way to build an entire package (including all of its targets) is to go to the package's build space and invoke `make [all]`, which is what `catkin_make --pkg` does.

    I setup an example repository here:

    https://github.com/wjwwood/catkin_demos/tree/ros_answers_52744

title: How to specify dependencies with "foo_msgs" catkin packages
upvote_count: 25
---
Say I have two catkin packages, <code>foo</code> and <code>foo_msgs</code>, in my workspace.  Here's how I currently have them set up:

<pre>
project(foo_msgs)
find_package(catkin REQUIRED COMPONENTS message_generation)
add_message_files(
  DIRECTORY msg
  FILES foomsg.msg
)
generate_messages()
catkin_package(CATKIN_DEPENDS message_runtime)
</pre>

<pre>
project(foo)
find_package(catkin REQUIRED COMPONENTS foo_msgs)
catkin_package()
include_directories(include ${catkin_INCLUDE_DIRS})
add_executable(foo foo.cpp)
</pre>

I find that if I <code>catkin_make foo</code>, the message isn't generated.  Indeed, <code>catkin_make foo_msgs</code> is a no-op.  <code>catkin_make foo_msgs_gencpp</code> works, however.  In order to get <code>foo</code> to build correctly, I must add the following line to its <code>CMakeLists.txt</code>:

<pre>
add_dependencies(foo foo_msgs_gencpp)
</pre>

Is this by design?  I'd expect that building the package <code>foo_msgs</code> would automatically generate all its messages.  Is there a way to make that happen?

**Edit:** I've approved WilliamWoodall's answer, although KruseT's was just as useful.  (I also added the <code>include_directories()</code> line to <code>foo</code>'s <code>CMakeLists.txt</code>, which I initially forgot.)

It turns out my solution is correct; the <code>foo_msgs_gencpp</code> auto-target should be added as a dependency of the <code>foo</code> target.  Note that there is some disagreement about whether a different solution should be supported by catkin; KruseT started a discussion on the topic [here](https://groups.google.com/d/topic/ros-sig-buildsystem/dvVO5QCHBLM/discussion).

Since this type of explicit dependency auto-target (<code>_gencpp</code> and <code>_genpy</code>) is necessary for using ROS messages/actions/services in any executable, library, or script, I think it should be better documented (I found no reference to it in [catkin/migrating_from_rosbuild](http://www.ros.org/wiki/catkin/migrating_from_rosbuild)).  KruseT opened a related rosdistro issue [here](https://github.com/ros/rosdistro/issues/439).
