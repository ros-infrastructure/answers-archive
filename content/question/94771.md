  body_markdown: "The problem is caused by the tr1 prefix on the headers that is not\
    \ supported in libc++. That is used in OSX 10.9. \n\nThe solution is to explicitly\
    \ specify libstdc++ by adding the following lines to ./src/octomap/CMakeLists.txt\
    \ and other corresponding CMakeLists.txt\n\n    SET(CMAKE_CXX_FLAGS \"${CMAKE_CXX_FLAGS}\
    \  -stdlib=libstdc++\")\n    SET(CMAKE_EXE_LINKER_FLAGS \"${CMAKE_EXE_LINKER_FLAGS}\
    \  -stdlib=libstdc++\")\n\n* Edit this is not really a good solution as clang\
    \ moving towards libc++."

    \ Fix ###\n\nThere is a problem with OROCOS KDL API that is incompatible with\

    \ and [PR 19](https://github.com/orocos/orocos_kinematics_dynamics/pull/19). You\
    \ will need to patch KDL source using both of these pull requests.\n\n    cd <ROS\
    \ WORKSPACE DIR>/src/orocos_kinematics_dynamics\n    curl https://github.com/orocos/orocos_kinematics_dynamics/pull/4.patch\
    \ | patch -p1\n    curl https://github.com/orocos/orocos_kinematics_dynamics/pull/19.patch\
    \ | patch -p1\n    # it is not a problem if the following step fails\n    cd ..\
    \ && rm -r build_isolated/orocos_kdl\n\nYou will also need to patch several dependent\
    \ ROS packages. For the necessary [robot model changes](https://github.com/ros/robot_model/pull/43):\n\
    \    \n    cd <ROS WORKSPACE DIR>/src/robot_model\n    curl https://github.com/ros/robot_model/pull/43.patch\
