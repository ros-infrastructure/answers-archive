  body_markdown: "The ROS laser message format allows you to specify a minimum valid\
    \ range. Is your driver filling this in right? \nhttp://www.ros.org/doc/api/sensor_msgs/html/msg/LaserScan.html\n\
    Clients that get data bigger than max or less than min should know to discard\
    \ it. \n\nAfter having a look to see if you can specify this in the sensor parameters\
    \ in the costmap2d:\nhttp://www.ros.org/wiki/costmap_2d\nThere isn't anything\
    \ specified about minimum ranges as opposed to maximum ones. However that's somewhat\
    \ expected, as that information should already be present in the laser scan message.\
    \ Typically you're only interested in discarding large value ranges as they have\
    \ the most uncertainty because of robot rotation. \n\nTo start, I'd check your\
    \ laser messages, and see if the minimum range is set correctly by the driver. "

Hi all,

I'm trying to use navigation stack with a laser scanner which gives points from at least one meter distance. Move_base works fine but, when the robot (Pioneer) is close to an obstacle, the obstacle disappear from laser data, obstacle is cleared from costmap and robot hits it. Is there any possible solution? I'm using ROS Groovy and hydro-devel branch of navigation stack.
