The robot is setup to use Nav2 for navigation and the local cost map (Voxel Layer) plugin generates a warning periodically. The following warning is generated on start-up and the `X` and `Y` coordinate changes as the robot roams the map.

    [local_costmap.local_costmap]: Sensor origin: (0.22, 0.00, 1.00), out of map bounds. The costmap can't raytrace for it.

The following is my local cost map configuration:

    local_costmap:
      local_costmap:
        ros__parameters:
          update_frequency: 1.0
          publish_frequency: 1.0
          global_frame: odom
          robot_base_frame: base_link
          use_sim_time: True
          rolling_window: true
          width: 3
          height: 3
          resolution: 0.05
          robot_radius: 0.65
          plugins: ["voxel_layer", "inflation_layer"]
          inflation_layer:
            plugin: "nav2_costmap_2d::InflationLayer"
            cost_scaling_factor: 3.0
            inflation_radius: 0.65
          voxel_layer:
            plugin: "nav2_costmap_2d::VoxelLayer"
            enabled: True
            publish_voxel_map: True
            origin_z: 0.0 
            z_resolution: 0.05
            z_voxels: 16
            max_obstacle_height: 2.0
            mark_threshold: 0
            observation_sources: depth
            depth:
              topic: /camera/points
              max_obstacle_height: 2.0
              clearing: True
              marking: True
              data_type: "PointCloud2"
          static_layer:
            map_subscribe_transient_local: True
          always_send_full_costmap: True

With this configuration, I can see the local cost map is being updated in RViz as the robot moves closer to the obstacle. 

The whole system is setup in ROS2 Foxy with Ubuntu 20.04.

I'm not entirely sure how to fix this warning and the impact it has on the navigation. Any suggestion would be greatly appreciated! Thanks!
