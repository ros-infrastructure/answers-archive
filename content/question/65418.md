  body_markdown: "Here is the answers for the above stated problems. To calibrate\
    \ stereo camera without hardware synchronisation, the `approximate=0.01` flag\
    \ should be used. If it's set up then this problem becomes the original calibration\
    \ problem with monocular camera.\nTo solve it you have to  rename cv_bridge_boost.dylib\
    \ to cv_bridge_boost.so. After you will start seeing the calibration window, however\
    \ it will not respond to mouse clicks. To solve this you have to rebuild opencv\
    \ with GTK as a backend. These are the steps I took to successfully build opencv\n\
    \nI had to modify CMakeLists.txt in opencv folder as follows\n\n    Line 129:\n\
    \    OCV_OPTION(WITH_GTK            \"Include GTK support\"                  \
    \       OFF  )\n    \n    LINE 135:\n    OCV_OPTION(WITH_OPENGL         \"Include\
    \ OpenGL support\"                      ON  IF (NOT ANDROID) )\n    \n    LINE\
    \ 617:\n            status(\"    Carbon:\" NO)\n    LINE 616:\n            status(\"\
    \    Carbon:\" NO)\n    \n    LINE 140:\n    OCV_OPTION(WITH_QT             \"\
    Build with Qt Backend support\"               OFF  IF (NOT ANDROID AND NOT IOS)\
    \ )\n\nThen gtk should be installed\n\n    brew install gtk+\n    brew install\
    \ gtkglext\n\nand /opt/X11/lib/pkgconfig should be added to ~/.profile\n\n   \
    \ export PKG_CONFIG_PATH=/usr/local/lib/pkgconfig:/opt/X11/lib/pkgconfig:$PKG_CONFIG_PATH\n\
    \nafter building opencv, I could run stereo calibration without a problem.\n\n\
    PS: I hope I did not forget to mention any steps.\n\n"
