  body_markdown: "I've also encountered this problem when trying to run the pointcloud_to_laserscan\
    \ launch files. I've got working launch files for an ordinary ROS node and a ROS\
    \ nodelet (below), both of which are based on the sample launch files provided\
    \ [in the source code](https://github.com/ros-perception/pointcloud_to_laserscan/tree/indigo-devel/launch).\
    \ \n\nHowever, these sample files assume that you are deriving your point cloud\
    \ from a RGBD camera, which is why the sample files launch an OpenNI2 node first.\
    \ In my application I wanted to use pointcloud_to_laserscan on PointCloud2 data\
    \ from a 3D LiDAR unit, and cut out all the OpenNI2 stuff.\n\n## pointcloud_to_lasercan\
    \ node ##\n\nThe code I used for an ordinary pointcloud_to_laserscan node is:\n\
    \n    <launch>\n        <!-- run pointcloud_to_laserscan node -->\n        <node\
    \ pkg=\"pointcloud_to_laserscan\" type=\"pointcloud_to_laserscan_node\" name=\"\
    pointcloud_to_laserscan\">\n\n            <remap from=\"cloud_in\" to=\"<YOUR\
    \ INPUT POINTCLOUD2 TOPIC>\"/>\n            <rosparam>\n                target_frame:\
    \ <THE FRAME OF YOUR POINTCLOUD2 TOPIC> \n                transform_tolerance:\
    \ 0.01\n                min_height: 0.0\n                max_height: 1.0\n\n \
    \               angle_min: -3.14 # -M_PI\n                angle_max: 3.14 # M_PI\n\
    \                angle_increment: 0.0087 # M_PI/360.0\n                scan_time:\
    \ 0.3333\n                range_min: 0.45\n                range_max: 10.0\n \
    \               use_inf: true\n\n                # Concurrency level, affects\
    \ number of pointclouds queued for processing and number of threads used\n   \
    \             # 0 : Detect number of cores\n                # 1 : Single threaded\n\
    \                # 2->inf : Parallelism level\n                concurrency_level:\
    \ 0\n            </rosparam>\n        </node>\n    </launch>\n\nThis will launch\
    \ a `pointcloud_to_laserscan` node that will immediately start converting and\
    \ outputting data on the `/scan` topic. Note that if you delete the target_frame\
    \ line or leave that parameter blank, you may get errors like I did. I found it\
    \ best to explicitly keep the target_frame the same as the frame of the input\
    \ PointCloud2 data. You can of course set the target frame to another frame entirely.\n\
    \n## pointcloud_to_laserscan nodelet ##\n\n[Nodelets](http://wiki.ros.org/nodelet)\
    \ (as per gvdhoon's comments) are more efficient than regular nodes and offer\
    \ reduced CPU usage, latency and jitter. In addition, the nodelet will not publish\
    \ anything to the `/scan` topic unless it detects something subscribing to the\
    \ topic, such as Rviz or \"rostopic echo /scan\".\n\nThe code I used to launch\
    \ a pointcloud_to_laserscan nodelet is:\n\n    <launch>\n\n        <!-- Create\
    \ a manager becuase nodelets wont launch without one-->\n        <node pkg=\"\
    nodelet\" type=\"nodelet\" name=\"pointcloud_to_laserscan_manager\" output=\"\
    screen\" respawn=\"true\" args=\"manager\"/>\n\n        <!-- push pointcloud_to_laserscan\
    \ nodelet into the dummny manager above-->\n        <node pkg=\"nodelet\" type=\"\
    nodelet\" name=\"pointcloud_to_laserscan_worker\" args=\"load pointcloud_to_laserscan/pointcloud_to_laserscan_nodelet\
    \ pointcloud_to_laserscan_manager\">\n\n            <remap from=\"cloud_in\" to=\"\
    <YOUR INPUT POINTCLOUD2 TOPIC>\"/>\n            <rosparam>\n                target_frame:\
    \ <THE FRAME OF YOUR POINTCLOUD2 TOPIC> \n                transform_tolerance:\
    \ 0.01\n                min_height: 0.0\n                max_height: 1.0\n\n \
    \               angle_min: -3.14 # -M_PI\n                angle_max: 3.14 # M_PI\n\
    \                angle_increment: 0.0087 # M_PI/360.0\n                scan_time:\
    \ 0.3333\n                range_min: 0.45\n                range_max: 10.0\n \
    \               use_inf: true\n\n                # Concurrency level, affects\
    \ number of pointclouds queued for processing, thread number governed by nodelet\
    \ manager\n                # 0 : Detect number of cores\n                # 1 :\
    \ Single threaded\n                # 2->inf : Parallelism level\n            \
    \    concurrency_level: 0\n            </rosparam>\n       </node>\n    </launch>\n\
    \nThese launch files work for me, so hopefully they'll help anyone else with this\
    \ problem."
