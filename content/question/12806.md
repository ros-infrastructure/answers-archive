  body_markdown: "I once did a dirty hack in rviz to republish the selected points,\
    \ this was done in a hurry and not well. So what I did was : I hooked into the\
    \ updateProperties method of the SelectionHandle  rviz/src/selection/selection_handler.cpp.\
    \ I felt this should be called everytime the selection changes.\nYou can then\
    \ iterate over the bounding boxes and will get the center coordinates of the selected\
    \ points in the currently set fixed_frame.\nAs I said, it's dirty, doesn't get\
    \ you RGB but only XYZ, but maybe it's of help for you. \n\nA cleaner way would\
    \ be to create Interactive Markers to select and area and then in an external\
    \ node that gets the coordinates of the markes and the scan in, cut out the points\
    \ yourself and republish/save them. Of course this will be hard if you want to\
    \ add/remove from the selection with modifier keys, therefor i also hope we will\
    \ one day get a feature like this built into rviz.\n\n    int publish_counter\
    \ = 0;\n\n    void SelectionHandler::updateProperties()\n    {\n      V_Property::iterator\
    \ it = properties_.begin();\n      V_Property::iterator end = properties_.end();\n\
    \n      for (; it != end; ++it)\n      {\n        propertyChanged(*it);\n    \
    \  }\n\n      ROS_INFO(\"boxes LENGTH %i\", boxes_.size());\n      M_HandleToBox::iterator\
    \ iit = boxes_.begin();\n      M_HandleToBox::iterator iend = boxes_.end();\n\n\
    \      publish_counter++;\n\n      // you dont want to take each update since\
    \ updateProperties seems to be called at each frame \n      if (publish_counter\
    \ % 20 == 0)\n      {\n         std::vector<Ogre::Vector3> pts;\n         for\
    \ (; iit != iend; ++iit)\n         {\n           Ogre::WireBoundingBox *box =\
    \ (*iit).second.second;\n           Ogre::AxisAlignedBox aabb = box->getBoundingBox();\n\
    \           Ogre::Vector3 center = aabb.getCenter();\n           pts.push_back(center);\n\
    \           // here we get the Points, the coordinate system differs between ogre\
    \ and ros:\n           //ROS_INFO(\"CENTER: %f %f %f\", -center.z, -center.x,\
    \ center.y); \n         }\n         //I made a little class SelectionPublisher\
    \ that would convert to a\n         // PointCloud2 MSG and publish it, took it\
    \ out here\n         //SelectionPublisher::publish(pts);\n       }\n    }"
