    From the wiki on DWAPlannerROS,

    > odom - Odometry information that gives the local planner the current speed of the robot

    So the planner uses odom only for the instantaneous velocities. While it could extract the robot_pose from amcl_pose, it actually does this using the tf library (/tf topic) instead.

    In more detail, the plugin doesn't actually obtain the pose itself, but actually gets the pose from move_base's [costmap](https://github.com/ros-planning/navigation/blob/hydro-devel/dwa_local_planner/src/dwa_planner_ros.cpp#L254).

    ---

    Also going by the wiki, [amcl](http://wiki.ros.org/amcl) publishes `/particlecloud` as a `PoseArray`, which would be why you can't visualize it directly in rviz. You should be able to tap into the topic using `rostopic echo` though.
