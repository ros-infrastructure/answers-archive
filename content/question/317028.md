  body_markdown: "An update to this old question:\n\n- _Currently_, MoveIt does not\
    \ support executing multiple trajectories via a `MoveGroupInterface` or `Commander`\
    \ interface.\n- Sending planned trajectories directly to the robot controllers\
    \ is possible, but MoveIt will not ensure that there are no collisions between\
    \ the trajectories. This is dangerous and should be done at your own risk.\n-\
    \ It is possible to move multiple arms at the same time, but they both need to\
    \ be part of one planning group and trajectory. They cannot start and stop their\
    \ motion independently of the other. When planning, you need to set a goal for\
    \ each arm (or group of joints). [This project](https://github.com/o2ac/o2ac-ur)\
    \ has some examples (check the lines in the `o2ac_routines` package that use the\
    \ planning group `ab_bot`).\n- In [the same project](https://github.com/o2ac/o2ac-ur),\
    \ we also [forked MoveIt](https://gitlab.com/o2ac/moveit) to make a single `move_group`\
    \ move multiple PlanningGroups independently. This is the functionality requested\
    \ in the original question.\n- [This open PR](https://github.com/ros-planning/moveit/pull/2810)\
    \ should bring the changes into upstream MoveIt and enable multiple trajectory\
    \ execution. Finishing this big PR is the subject of a Google Summer of Code project,\
    \ tracked [here](https://github.com/ros-planning/moveit/issues/3156). It is a\
    \ big change, so you can support it by reviewing and following the issue and PR. "
