    \ able to install RTI Connext non-interactively during a Docker build. If instead\
    \ you're not interested in installing RTI Connext at all, that would be a different\
    \ question.\n\n---\n\nYou could take a look at how the [ros-tooling/setup-ros](https://github.com/ros-tooling/setup-ros)\
    \ Github Action does this.\n\nIt [supports installing RTI Connext](https://github.com/ros-tooling/setup-ros/tree/62f29fb65eec1f3238e08e4c39e654a1dbdfb0e4#Including-RTI-Connext)\
    \ from the same `.deb` as you refer to. Only thing needed is to add `install-connext:\
    \ true` to the Actions configuration `.yaml`.\n\nFrom [ros-tooling/setup-ros/src/package_manager/apt.ts](https://github.com/ros-tooling/setup-ros/blob/4a84c396ce7d91588206bbd01fe37f1320439ec4/src/package_manager/apt.ts#L4-L14):\n\
    \n>     const CONNEXT_APT_PACKAGE_NAME = \"rti-connext-dds-5.3.1\"; // RTI Connext\n\
    \    \n>     const aptCommandLine: string[] = [\n    \t\"DEBIAN_FRONTEND=noninteractive\"\
    ,\n    \t\"RTI_NC_LICENSE_ACCEPTED=yes\",\n    \t\"apt-get\",\n    \t\"install\"\
    ,\n    \t\"--no-install-recommends\",\n    \t\"--quiet\",\n    \t\"--yes\",\n\
    \    ];\n\nThe important bit here is of course `RTI_NC_LICENSE_ACCEPTED=yes`.\n\
    \n> user interactivity isn't possible...the DEBIAN_FRONTEND variable is supposed\
    \ to fix that, but it appears not to be respected\n\nI don't believe this is necessarily\
    \ always true. I've encountered other (commercially distributed) `.deb`s which\
    \ also needed special interaction sequences which would not support `noninteractive`."
