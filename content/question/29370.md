  body_markdown: "I assume by \"better estimate height\" you mean \"provide a 2D pose\
    \ estimate\"? :)\nYour height estimate has to come from a different source, like\
    \ ultrasonic, barometric, mirrors mounted to your laser scanner, or a fused combination\
    \ thereof.\n\n/edit: I just read your other question. So you try to do scanmatching\
    \ on a vertical 2D slice of the enviroment? That\xB4s not a good idea, as hector_mapping\
    \ matches scans against the existing map and the \"vertical map\" will change\
    \ significantly when the platform travels around.\n\nThe \"syscommand\" topic\
    \ is used by [Team Hector\xB4s](http://www.gkmm.tu-darmstadt.de/rescue/) robots\
    \ to reset all nodes in a system to a initial state (and some other tasks), but\
    \ is not required for hector_mapping to work.\n\nThe output looks like the scan\
    \ topic isn\xB4t properly set up. You might also want to have a look at [this\
    \ brand new tutorial on quadrotor based indoor SLAM in simulation using hector_mapping](http://www.ros.org/wiki/hector_quadrotor/Tutorials/Quadrotor%20indoor%20SLAM%20demo).\
    \ It should give you an idea on how you can set it up."
