  body_markdown: "The Debian package `libopencv-dev` installs a cmake project config\
    \ file. It sets CMake variables after `find(OpenCV)` is called.\n\n    $ dpkg\
    \ -L libopencv-dev | grep cmake\n    /usr/lib/x86_64-linux-gnu/cmake\n    /usr/lib/x86_64-linux-gnu/cmake/opencv4\n\
    \    /usr/lib/x86_64-linux-gnu/cmake/opencv4/OpenCVConfig-version.cmake\n    /usr/lib/x86_64-linux-gnu/cmake/opencv4/OpenCVConfig.cmake\n\
    \    /usr/lib/x86_64-linux-gnu/cmake/opencv4/OpenCVModules-release.cmake\n   \
    \ /usr/lib/x86_64-linux-gnu/cmake/opencv4/OpenCVModules.cmake\n\nHave a look inside\
    \ the main one\n\n    $ vim /usr/lib/x86_64-linux-gnu/cmake/opencv4/OpenCVConfig.cmake\n\
    \nA CMake variable that looks interesting is `OpenCV_INSTALL_PATH`.\n\n    # \
    \   Advanced variables:\n    #      - OpenCV_SHARED                   : Use OpenCV\
    \ as shared library\n    #      - OpenCV_INSTALL_PATH             : OpenCV location\n\
    \    #      - OpenCV_LIB_COMPONENTS           : Present OpenCV modules list\n\
    \    #      - OpenCV_USE_MANGLED_PATHS        : Mangled OpenCV path flag\n\nOn\
    \ Ubuntu Focal with OpenCV4 it resolves to `/usr/`, so one might think the path\
    \ to the classifier is\n\n    ${OpenCV_INSTALL_PATH}/share/opencv4/haarcascades/haarcascade_frontalface_alt.xml\n\
    \nHowever, [Debian Buster with OpenCV 3.2 it's a different path](https://packages.debian.org/buster/all/opencv-data/filelist)\n\
    \n    /usr/share/opencv/haarcascades/haarcascade_frontalface_alt.xml\n\nIt looks\
    \ like just the directory in `share` is different. That [should be solvable with\
    \ `file(GLOB ...)`](https://cmake.org/cmake/help/latest/command/file.html#glob)\n\
    \n    file(GLOB haarcascade_file_path \"${OpenCV_INSTALL_PATH}/share/*/haarcascades/haarcascade_frontalface_alt.xml\"\
    )\n\nThen you can use [CMake configure_file](https://cmake.org/cmake/help/v3.10/command/configure_file.html)\
    \ to generate `classifier.yaml` from a new `classifier.yaml.in` file\n\n     classifier_filename:\
    \ ${haarcascade_file_path}\n\nand the CMake\n\n    configure_file(classifier.yaml.in\
    \ classifier.yaml)\n    \nThe generated file is in [CMAKE_CURRENT_BINARY_DIR](https://cmake.org/cmake/help/v3.10/variable/CMAKE_CURRENT_BINARY_DIR.html#variable:CMAKE_CURRENT_BINARY_DIR),\
    \ so you'll need to install it to the `param` folder from the build folder\n\n\
    \    install(FILES \"${CMAKE_CURRENT_BINARY_DIR}/classifier.yaml\"\n         \
    \   DESTINATION ${CATKIN_PACKAGE_SHARE_DESTINATION}/param\n    )"

Short version: How do I find the path to `haarcascade_frontalface_alt.xml` provided by opencv? 

Long version: 
I'm working on getting the `face_detector` package to work in noetic. In the past, the path to the classifier has been hardcoded, but in noetic, since the build has to work on Ubuntu and Debian, the hardcode isn't cutting it. My failing PR is here: https://github.com/wg-perception/people/pull/88

I feel like there should be some environment variable like `$OPENCV_SHARED_DATA_DIR` but I can't find a good resource on what that would be. How can I configure my launch/param/source code to find this file on both Ubuntu and Debian?
