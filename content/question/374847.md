    \ days to figure it out.\nI commited my WIP code so u can see an exampled.\nhttps://github.com/DeborggraeveR/ros2-mecanum-bot\n\
    \nThis is a simular approuch as my ROS1 robot which is using the RobotHW interface\
    \ and communicates with arduiono: \nhttps://github.com/DeborggraeveR/ampru\n\n\
    I don't have a tutorial yet, but here is a quick summary of what i done so far\n\
    \n**Visualize the robot**\nCreate the mecanumbot_description package with urdf\
    \ model\nCreate the mecanumbot_bringup package with launch file for robot_state_publisher\
    \ & join_state_publisher to be able to visualize the robot model in rviz2\n\n\
    **Add the hardware interface**\nCreate the mecanumbot_hardware package and implement\
    \ a \"hardware_interface::SystemInterface\" class.\nMost important line in this\
    \ class is:\n\n    hardware_interface::CommandInterface(\n                info_.joints[i].name,\
    \ hardware_interface::HW_IF_VELOCITY, &velocity_commands_[i]\n            )\n\n\
    If the joint name = wheel_joint, we map /joint_state/wheel_joint/velocity to \"\
    velocity_command_\"\nSo if the velocity changes, the value will be stored in the\
    \ \"velocity_command_\" which u can read during the \"write\" call.\nImportant\
    \ on making this package work:\n\n - Add the plugin xml on the root of the package\n\
    \ - Add the \"PLUGINLIB_EXPORT_CLASS\" in your hardware class\n - Add the \"pluginlib_export_plugin_description_file\"\
    \ in your CMakeList file\n\nNext you need to define the joints used by the hardware\
    \ in the URDF file (see bottom of my URDF => ros2_control node)\nI also added\
    \ the controller config file to the description package\n\n**Use the hardware\
    \ class**\nNext i removed the \"joint_state_publisher\" from the bringup package\
    \ launch files and added ros2_control\nWhen u launch this, it wont work.\nU can\
    \ call \"ros2 control list_hardware_interfaces\" to see your hardware and notice\
    \ all joint are unclaimed\nU can call \"ros2 control list_controllers\" to see\
    \ there are no active controllers\n\nNext is to get your joint state published,\
    \ this seems to do the same as the \"joint_state_publisher\" which is now commented\
    \ out in my launch files\n\n    ros2 control load_start_controller joint_state_controller\n\
    \nStill the hardware is unclaimed.\nI tried with running \"ros2 control load_start_controller\
    \ diffbot_base_controller\" to launch the DiffDriveController.\nI found example\
    \ of this in PR or ros2_control_demos repo:\nhttps://github.com/BorgesJVT/ros2_control_demos/tree/demo_diff_drive_controller\n\
    \n**Custom controller**\nAs i'm working on a mecanum bot, i also created a mecanumbot_controller\
    \ package, which contains the controller.\nImportant part of the controller is\
    \ that it subscribes to \"/cmd_vel\".\nRun \"ros2 run teleop_twist_keyboard teleop_twist_keyboard\"\
    \ to publish those messages\nThe controller added the joints used by the hardware\
    \ in the \"command_interface_configuration\" method. This causes running this\
    \ controller to claim the joins (ros2 control list_hardware_interfaces)\n\nDuring\
    \ the update of the controller i set the velocity as value of the \"hardware_interface::LoanedCommandInterface\"\
    \nThis causes the variable mapped in the hardware to be updated.\n\n**Auto launch\
    \ controllers**\nI have a open question here on the board on how to spawn the\
    \ controllers trough launch files.\nAs workaround i added the mecanumbot_control\
    \ packages, where the main method is the same as the ros2_control controller_manager\
    \ main and where i add, configure & start my controllers\n\n**Final**\nWhen i\
    \ run the teleopt_twist_keyboard and \"move\" the robot around, the \"hardware::write\"\
    \ method will log the velocity of the wheel has change :)\n\nKind regards,"
