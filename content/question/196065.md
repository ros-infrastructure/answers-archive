  body_markdown: "EDIT: The original question asked, in short \"Can I subscribe and\
    \ pass the same callback to multiple subscribers\". I assumed you wanted to process\
    \ different messages with different types in the same way, using the same callback.\n\
    \nThe original answer was:\n\n> That looks like it should work, bug beware\n>\
    \ that your callback will be called with\n> different messages with different\n\
    > types, so you'll have to check the\n> message type and do something\n> different\
    \ for each type.\n> \n> Alternately, you could define a\n> different callback\
    \ for each topic,\n> have each callback parse the message\n> into a common format,\
    \ and then pass\n> that to a common method which\n> implements the actual program\
    \ logic.\n\nEDIT:\n\nI'm no longer sure what you're expecting ROS to do for you.\n\
    \n * Do you want a callback whenever you get either message?\n * Do you want a\
    \ callback only when both topics are updated?\n * Are you just trying to avoid\
    \ keeping a copy of each most recent message?\n\nEDIT:\n\nYou can use [message_filters](http://wiki.ros.org/message_filters)\
    \ to subscribe to multiple topics and get a callback when all topics have new\
    \ messages. Unless your publishers are explicitly publishing messages with identical\
    \ timestamps, you'll probably want to use the [ApproximateTimeSynchronizer](http://docs.ros.org/api/message_filters/html/python/#message_filters.ApproximateTimeSynchronizer)."
