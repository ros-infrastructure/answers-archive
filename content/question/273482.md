  body_markdown: "Actually, there is a kind of repulsive force applied on the band.\n\
    The teb approach deforms the trajectory by solving an optimization problem rather\
    \ than applying forces directly.\nThere is not much difference, since the solver\
    \ determines forces implicitly (e.g. gradient of the objective/cost function).\n\
    The objective function term for obstacle avoidance is just the penalization of\
    \ the euclidean distance between the\nobstacle and the robot. Note, obstacle shape\
    \ and robot shape might differ from points with a much higher computational burden.\n\
    The optimization problem is defined and implemented in terms of a hyper-graph\
    \ to speed up sparse Jacobian computation. You can find the corresponding Edge\
    \ for obstacle avoidance in `edge_obstacle.h`.\n\nThe fundamental algorithm is\
    \ as follows (you already mentioned the first steps in your question):\n\n1. Initialize\
    \ or update trajectory\n2. Repeat for a number of iterations\n 1. If necessary,\
    \ resize trajectory (similar to insertion and deletion of bubbles in the classical\
    \ elastic band, but here based on the temporal domain.\n 2. Build graph (here\
    \ you can find which poses are associated with which obstacles, there are two\
    \ different strategies currently. Ideally, you would connect all obstacles with\
    \ all poses each, but however, we want to speed up optimization).\n 3. Solve optimization\
    \ problem defined by the previously created graph (stop after some iterations)\n\
    \nThe repetition of resizing, obstacle association (in the graph building stage)\
    \ and some actual optimization steps (3.) \nleads to the overall band deformation.\
    \ \n"
