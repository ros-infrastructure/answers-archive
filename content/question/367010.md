    \ as mentioned in [this recent question](https://answers.ros.org/question/366812/ubuntu-1604-kinetic-update-no-rule-to-make-target-libvtkproj/).\
    \ You are right,  a change was pushed to Ubuntu and OSRF apt repositories that\
    \ introduced this issue. Here are a few related bug reports:\n\n - https://github.com/ros-perception/perception_pcl/issues/318\n\
    \ - https://github.com/tfoote/vtk6-release/issues/1\n - https://bugs.launchpad.net/ubuntu/+source/vtk6/+bug/1573234\n\
    \nCurrent recommended fix is to pin your apt repos to prefer the versions of VTK\
    \ packages on OSRF's repositories over the ones on Ubuntu's repositories (as mentioned\
    \ in [this answer](https://answers.ros.org/question/366812/ubuntu-1604-kinetic-update-no-rule-to-make-target-libvtkproj/?answer=366913#post-id-366913)).\
    \ To do this, create a file called `/etc/apt/preferences.d/ros-pin` with the following\
    \ content\n\n    Package: *\n    Pin: origin packages.ros.org\n    Pin-Priority:\
    \ 1000\n\nThen `apt-get update` and `apt-get upgrade` can be used to switch you\
    \ to the OSRF versions. Also note, that you may need to manually install `libproj-dev`.\
    \ Hopefully this is a temporary issue that is fixed soon.\n\n**UPDATE** \n\nAs\
    \ mentioned on [this ROS discourse](https://discourse.ros.org/t/new-packages-for-kinetic-kame-2020-12-07/17786)\
    \ thread, an update to the ROS Kinetic packages that depend on VTK was just released\
    \ to the package repositories. Users should be able to unpin any pinned packages\
    \ (e.g. delete file created above), and then run `apt-get` update/upgrade to install\
    \ the latest packages, and this error should disappear."
