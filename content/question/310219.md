  body_markdown: "Sorry to be answering my own question but I found the solution,\
    \ and in the absence of other instructions I want to make it available to other\
    \ users ever encountering the same problem.\n\nThe Astra Pro launch file loads\
    \ the Astra driver (publishing the depth and IR images only). It uses a third\
    \ party node called rgbd_launch [found here along with partial reference info](http://wiki.ros.org/rgbd_launch).\
    \ This node does most of the real job - listening to depth and RGB images to create\
    \ point clouds and registered point clouds.\n\nIn order to do so, everything has\
    \ to be aligned. In the astrapro launch file, the nodes are published under the\
    \ /camera namespace. The default namespaces for the depth, IR and RGB publications\
    \ are as depicted, and are the same for both the astra driver and rgbd_launch\
    \ nodes. What needs to be done (in addition to the short instructions given at\
    \ the [orbbec ros astra wrapper git](https://github.com/orbbec/ros_astra_camera)\
    \ ) is as follows:\n\n1. Create both an RGB and depth calibration files because\
    \ rgbd_launch has to rectify the data before registering. Default location for\
    \ these files, so I've heard, is in the ${ROS_HOME}/camera_info/${NAME.yaml},\
    \ so I actually created and empty package named camera_info and put the files\
    \ in the root directory (so that I could use $(find camera_info) in the launch\
    \ file. In these files, see to it that the name of the cameras are: depth_Astra_Orbbec\
    \ / rgb_Astra_Orbbec respectively, I don't remember why anymore but I got an error\
    \ about it from one of the launched nodes / nodelets.\n\n2. Launch a node that\
    \ would publish an image topic named /rgb/image_raw and the camera calibration\
    \ info (taken from the calibration files) into /rgb/camera_info, both have to\
    \ be in the same namespace where the rgbd_launch node is running (because it's\
    \ listening to it). The images must be raw, not rectified. Also, the frame_id\
    \ in the header must match the one used in the camera driver. In our case, the\
    \ usb_camera node publishes the topics as /camera/rgb/image_raw and /camera/rgb/camera_info\
    \ (\"camera\" because of the namespace they are all running at, and \"rgb\" because\
    \ thats what we chose for the rgb image namespace). The frame id is the default\
    \ one, \"camera_rgb_optical_frame\".\n\n3. Make sure the following parameters\
    \ for rgbd_launch are true: \"rgb_processing\", \"depth_processing\", \"sw_registered_processing\"\
    \ and \"depth_registered_processing\". Also make sure that \"hw_registered_processing\"\
    \ is false, I received errors stating that the device is not calibrated. Perhaps\
    \ I'll dig into it, maybe it is possible to upload a calibration file to the device\
    \ flash? maybe this is unsupported? who knows. Also not sure how the pipeline\
    \ would work if it did. BTW, other processing flags in rgbd_launch seems to have\
    \ little to no connection with the publishing registered pointclouds.\n\nThis\
    \ creates a namespace where /depth/camera_info, /depth/image_raw, /rgb/camera_info,\
    \ and /rgb/image_raw are all published together along with a running rgbd_launch\
    \ node, listening to them and publishing (among others) the /detph/points and\
    \ /depth_registered/points topics.\n\n\nEDIT: This modified-default launch file\
    \ should give an example of how to implement:\n\n    <launch>\n    \n      <!--\
    \ \"camera\" should uniquely identify the device. All topics are pushed down\n\
    \           into the \"camera\" namespace, and it is prepended to tf frame ids.\
    \ -->\n      <arg name=\"camera\" default=\"camera\" />\n      <arg name=\"rgb_frame_id\"\
    \   default=\"$(arg camera)_rgb_optical_frame\" />\n      <arg name=\"depth_frame_id\"\
    \ default=\"$(arg camera)_depth_optical_frame\" />\n    \n      <!-- device_id\
    \ can have the following formats:\n             \"#n\"            : the nth device\
    \ found, starts from 1\n             \"2@n\"           : the nth device on USB\
    \ bus 2, n starts from 1\n             \"2bc5/0401@1/6\" : uri in format <vendor\
    \ ID>/<product ID>@<bus number>/<device number>\n             \"15120410023\"\
    \   : serial number -->\n      <arg name=\"device_id\" default=\"#1\" />\n   \
    \   <arg name=\"bootorder\" default=\"0\" />\n      <arg name=\"devnums\" default=\"\
    1\" />\n    \n      <!-- By default, calibrations are stored to file://${ROS_HOME}/camera_info/${NAME}.yaml,\n\
    \           where ${NAME} is of the form \"[rgb|depth]_[serial#]\", e.g. \"depth_B00367707227042B\"\
    .\n           See camera_info_manager docs for calibration URL details. -->\n\
    \      <arg name=\"rgb_camera_info_url\"   default=\"file://$(find camera_info)/rgb_Astra_Orbbec.yaml\"\
    \ />\n      <arg name=\"depth_camera_info_url\" default=\"file://$(find camera_info)/depth_Astra_Orbbec.yaml\"\
    \ />\n    \n      <!-- Hardware depth registration -->\n      <arg name=\"depth_registration\"\
    \ default=\"false\" />\n    \n      <!-- Driver parameters -->\n      <arg name=\"\
    color_depth_synchronization\"     default=\"false\" />\n      <arg name=\"auto_exposure\"\
    \                   default=\"true\" />\n      <arg name=\"auto_white_balance\"\
    \              default=\"true\" />\n    \n      <!-- Arguments for remapping all\
    \ device namespaces -->\n      <arg name=\"rgb\"              default=\"rgb\"\
    \ />\n      <arg name=\"ir\"               default=\"ir\" />\n      <arg name=\"\
    depth\"            default=\"depth\" />\n    \n      <!-- Optionally suppress\
    \ loading the driver nodelet and/or publishing the default tf\n           tree.\
    \ Useful if you are playing back recorded raw data from a bag, or are\n      \
    \     supplying a more accurate tf tree from calibration. -->\n      <arg name=\"\
    load_driver\" default=\"true\" />\n      <arg name=\"publish_tf\" default=\"true\"\
    \ />\n      <!-- Processing Modules -->\n      <arg name=\"rgb_processing\"  \
    \                default=\"true\"  />\n      <arg name=\"debayer_processing\"\
    \              default=\"false\" />\n      <arg name=\"ir_processing\"       \
    \            default=\"false\" />\n      <arg name=\"depth_processing\"      \
    \          default=\"true\" />\n      <arg name=\"depth_registered_processing\"\
    \     default=\"true\" />\n      <arg name=\"disparity_processing\"          \
    \  default=\"false\" />\n      <arg name=\"disparity_registered_processing\" default=\"\
    false\" />\n      <arg name=\"hw_registered_processing\"        default=\"true\"\
    \ if=\"$(arg depth_registration)\" />\n      <arg name=\"sw_registered_processing\"\
    \        default=\"false\" if=\"$(arg depth_registration)\" />\n      <arg name=\"\
    hw_registered_processing\"        default=\"false\" unless=\"$(arg depth_registration)\"\
    \ />\n      <arg name=\"sw_registered_processing\"        default=\"true\" unless=\"\

    >\n    \t\t  <arg name=\"name\" value=\"$(arg manager)\" />\n    \t\t  <arg name=\"\
    debug\" value=\"$(arg debug)\" />\n    \t\t  <arg name=\"num_worker_threads\"\
    \  value=\"$(arg num_worker_threads)\" />\n    \t\t</include>\n    \n        <!--\
    \ Load driver -->\n        <include file=\"$(find astra_launch)/launch/includes/device.launch.xml\"\
    \ if=\"$(arg load_driver)\">\n          <arg name=\"manager\"                \
    \         value=\"$(arg manager)\" />\n          <arg name=\"device_id\"     \
    \                  value=\"$(arg device_id)\" />\n          <arg name=\"bootorder\"\
    \                       value=\"$(arg bootorder)\" />\n          <arg name=\"\
    devnums\"                         value=\"$(arg devnums)\" />\n          <arg\
    \ name=\"rgb_frame_id\"                    value=\"$(arg rgb_frame_id)\" />\n\

    \ />\n          <arg name=\"rgb_camera_info_url\"             value=\"$(arg rgb_camera_info_url)\"\
    \ />\n          <arg name=\"depth_camera_info_url\"           value=\"$(arg depth_camera_info_url)\"\
    \ />\n          <arg name=\"rgb\"                             value=\"$(arg rgb)\"\
    \ />\n          <arg name=\"ir\"                              value=\"$(arg ir)\"\
    \ />\n          <arg name=\"depth\"                           value=\"$(arg depth)\"\
    \ />\n          <arg name=\"respawn\"                         value=\"$(arg respawn)\"\
    \ />\n          <arg name=\"depth_registration\"              value=\"$(arg depth_registration)\"\
    \ />\n          <arg name=\"color_depth_synchronization\"     value=\"$(arg color_depth_synchronization)\"\

    >\n          <arg name=\"manager\"                         value=\"$(arg manager)\"\

Hi all. I am using Ubuntu 16.04 with ROS kinetic. Fresh install with upgrades for both.
 
I have purchased an Astra Pro unit (unknowingly that it has completely separate RGB and depth units inside.... its a shame they don't tell that before you buy one). 

I have installed their driver as per instructed, with udev rules and everything. When I launch the astrapro.launch file I can see the depth point cloud and depth image in Rviz. The Astra driver does not publish a color image but I am able to watch it through the usb_cam node so it is operational. 
The thing is, that the astra driver has a "/camera/depth_registered/points" topic, but echoing it results in nothing. The terminal running the launch pops up the message:

> [ INFO] [1544185697.502299836]:
> Starting depth stream. [ INFO]
> [1544185697.698366710]: camera
> calibration URL:
> file:///home/steve/catkin_ws/src/camera_info/depth_Astra_Orbbec.yaml

I did make a calibration file for both the rgb and the depth, put them in the default ${ROS_HOME}/camera_info/${NAME.yaml}, and added the paths to the astrapro launch file.

I have tried various launch argument combinations and solutions from the internet but with no avail. Orbbec did not answer mails as well.

Am I missing something here? Do I need a third node to match the RGB and D? All I want is to be able to view a registered pointcloud in Rviz using the Astra Pro, even if a workaround is needed. Don't care about synchronization delay.

Hope I'm not the only one having this exact problem. Thank you all in advance.
