  body_markdown: "I'm not entirely sure what you mean by \n\n>  i just put a couple\
    \ of points in a straight line\n\nbut I think I understand where the confusion\
    \ is coming from. When the costmap receives the cloud, each point in your pointcloud\
    \ will be processed as an *observation*. If marking is enabled, the costmap will\
    \ then mark an obstacle at the point. If clearing is enabled, it will raytrace\
    \ clear space inbetween the robot and the point. So if you send an empty pointcloud,\
    \ nothing at all will happen, because you have no *observations*. Similarly, a\
    \ lack of points along a direction does not automatically clear the space either.\
    \ This may not be obvious from the documentation, so it helps to dig into the\
    \ [source](https://github.com/ros-planning/navigation/blob/hydro-devel/costmap_2d/plugins/obstacle_layer.cpp#L315)\
    \ when something isn't clear.\n\nYou may think 'no points means no obstacles',\
    \ however the pointcloud doesn't actually contain any information about how much\
    \ space it contains, only the points that are present. An empty cloud may also\
    \ represent a sensor malfuntion, or a blind spot in the sensor's FOV, so the costmap\
    \ can't assume clear space and clear the obstacles.\n\nThe way I got around this\
    \ issue is to convert the pointcloud into a laserscan, with max_sensor_range along\
    \ rays where no point is detected. This is essentially you doing your own raytracing.\
    \ Sadly, the pointcloud_to_laserscan package that used to do this doesn't exist\
    \ anymore (used to be in the original turtlebot repo), but I've added it back\
    \ to [perception_pcl](https://github.com/ros-perception/perception_pcl). These\
    \ changes aren't released into ROS yet, so you can clone and compile the pointcloud_to_laserscan\
    \ package yourself."

  body_markdown: "Obstacles get cleared between the camera and a measurement point.\
    \ Every measurement point with a \"normal\" value (includes 0 and everything except\
    \ infinity and NaN) is an obstacle.\nSo what you did is basically say there is\
    \ an obstacle at each point in front of the robot and its value (which can mean\
    \ e.g. color) is 0.\n\nDepending on what kind of \"camera\" you will be using\
    \ later, set the points and their values as following:\n\n- Depth camera which\
    \ also can return measurements like out of range, too close, invalid etc:\nThe\
    \ best thing is to put the values as described in REP 117 (http://www.ros.org/reps/rep-0117.html#specification).\
    \ In case of out of range detections put the infinity value at the point of the\
    \ measurement ray where the ray leaves the measurement range. This way everything\
    \ from the camera position to the end of measurement range will be cleared.\n\
    (code: https://github.com/ros-planning/navigation/blob/hydro-devel/costmap_2d/plugins/obstacle_layer.cpp#L428)\
    \ \n\n- \"Visual camera\" (stereo camera?) which _always_ outputs valid measurement\
    \ points:\nJust input your point cloud with the points you get from the camera.\
    \ The space between the camera position and the points in the pointcloud get cleared.\n\
    \nIn both cases check if the settings of the obstacle cloud are set to clearing\
    \ (It can be clearing and markign at the same time, http://wiki.ros.org/costmap_2d/hydro/obstacles)"
