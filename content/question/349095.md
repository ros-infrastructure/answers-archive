  body_markdown: "Short answer:\nset ROS_MASTER_URI and ROS_IP on both of your Raspberry\
    \ Pi and PC using IP address rather than hostname. It should work just fine.\n\
    \n Long answer:\nWe only discuss connection in local area network. \nFirst we'd\
    \ better fully understand the communication steps. \nIn brief\n\n - roscore is\
    \ started.\n - Publisher is started. Looking for master based on ROS_MASTER_URI.\
    \ If the publisher and master are on the same PC, you could use localhost, 127.0.0.1,\
    \ IP, hostname. \n - Publisher need to register its IP on master, based on ROS_IP.\
    \ if ROS_IP is not explicitly set, it should be hostname. This is very important,\
    \ because most of the time this part is the cause of improper multi-machine connection.\n\
    \ - Subscriber is started. Looking for master and master give back the publisher's\
    \ IP. \n - Subscriber connect to publisher. \n\nSo, if all nodes are running on\
    \ the same PC, there won't be any problem. \n\nIf you only setup the ROS_MASTER_URI\
    \ correctly, you can check the rostopic list on your client PC, because all the\
    \ topic names are already registered on ROS Master. \n\nTherefore, whether you\
    \ can rostopic echo or not on your client PC, is determined by the ROS_IP registered\
    \ on master by the publisher. \n\nNow we only focus on the ROS_IP setup on the\
    \ publisher's PC, mostly the master PC (to be more clear, publisher's PC is where\
    \ the publisher runs). This is quite tricky. The pros and cons of IP address is\
    \ that you can definitely connect using IP, but it may change. Hostname is more\
    \ user friendly, but your router still need to  parse hostname to IP address,\
    \ and sometimes it doesn't work (The router DNS server just does not work perfectly\
    \ and I really don't know how to solve this). If you are under a quite stable\
    \ network and you know that your router can always parse hostname, only setup\
    \ the ROS_MASTER_URI on both PCs will do.\n\nSo setup ROS_IP using IP address\
    \ rather than hostname, most of the time will solve the communication problem.\n\
    \nLast but not least, understand how to setup the ROS_MASTER_URI and ROS_IP. \n\
    ROS_MASTER_URI is only to provide the address of master, you can always set it\
    \ on your master PC to http://localhost:11311. But you MUST setup the ROS_IP using\
    \ a LAN IP, i.e. 192.168.1.xxx,  so a remote subscriber can find the publisher\
    \ well. \n\nPay more attention to the ROS_IP on master PC, users often forget\
    \ to setup the ROS_IP because they take for grant that the subscriber can connect\
    \ to the publisher on master PC, as it can connect to the master. In fact, ROS_MASTER_URI\
    \ on subscriber machine guarantee that it can connect to master, and ROS_IP on\
    \ publisher machine guarantee subcriber can connect to publisher.\n\n***\nHowever,\
    \ this seems does not explain your case when you set all ROS_MASTER_URI and ROS_IP\
    \ to Pi but your PC's publisher works well. Better check again and give me some\
    \ feedback..\n***\n\nI think this problem is not well discussed in Wiki. However,\
    \ in ROS2 this should not be a problem any more .."

    \ but don't run it yet till configurations are done.\n\n- Has an IP of `192.168.1.10`\n\
    \n1- Run the following in the terminal:\n\n1.1- `export ROS_MASTER_URI=http://192.168.1.10:11311`\n\

    \n\nMachine2 {SLAVE}\n\n- Will NOT run roscore.\n- Has and IP `192.168.1.15`\n\
