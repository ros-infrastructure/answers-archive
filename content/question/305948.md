  body_markdown: "Personally, I think your solution is fine. Option 1 is heavy because\
    \ you're creating and destroying the connections each time its called and delayed\
    \ from waiting for the next message to arrive. This second way will incur a copy,\
    \ another way of doing this might be to pass the callback a constptr of the msg,\
    \ for instance franka_msgs::FrankaStateConstPtr. This will stop 2 copies so you'll\
    \ only have 1, if my understanding of it is correct. \n\nEssentially what you're\
    \ doing has 1 copy to get into the callback, then another to your variable since\
    \ storing it out of the scope of the function. The constptr is a boost shared\
    \ pointer so you don't incur the second copy. \n\nEven running at 30 hz just copying\
    \ over shouldn't be too horrible for your application unless you're trying to\
    \ run on something super weak (raspberry pi, etc). If you're on a desktop, this\
    \ is fine. \n\nThere's no good support for \"on demand\" messages from a topic\
    \ at the moment. I'm sure you could make one with a message filter or wrapping\
    \ up the subscriber class yourself, but nothing out of the box that I am aware\
    \ of. "

I would like to read a topic (which is published at ~30hz) at specific moments in the execution of my code. [This Q&A](https://answers.ros.org/question/170361/read-topic-without-callback/) shows I have 2 ways to proceed:

 - waitForMessage (from [here](https://answers.ros.org/question/170361/read-topic-without-callback/?answer=170386#post-id-170386)) which is a "fairly heavy operation" and requires "frequent publishing" (how heavy? how frequent?);
 - subscribing and updating a class member via the subscriber's callback, and using said member directly (from the second part of [this](https://answers.ros.org/question/170361/read-topic-without-callback/?answer=170371#post-id-170371)).

I went the second way but realized I don't understand how to pass-by-reference (not good enough, at least, and I have found [this](https://stackoverflow.com/questions/3408804/c-operator-method-for-const-references) which is related, but isn't working), so I went with:

    void MyClass::frankaStateCallback(const franka_msgs::FrankaState& msg)
    {
      current_franka_state_ = msg;
    }

where `current_franka_state_` is of type `franka_msgs::FrankaState` (i.e. [here](http://docs.ros.org/kinetic/api/franka_msgs/html/msg/FrankaState.html)) which is not the simplest/lightest of messages.

I'm therefore wondering if I should use the other way or if someone could help me with understanding how to properly use a pointer in this case.

**EDIT**: as per lucascoelho's request

    sub_franka_states_ = nh.subscribe("franka_state_controller/franka_states", 1, &MyClass::frankaStateCallback, this);

This is in the body of the constructor (wrote it following [this page](http://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers#Subscribing_to_a_Topic)), but I don't understand how the problem would lie here.
