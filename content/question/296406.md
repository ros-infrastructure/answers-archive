  body_markdown: "The global planner of the navigation stack makes use of a costmap\
    \ to make its global plan, provided by the [costmap_2d](http://wiki.ros.org/costmap_2d?distro=melodic)\
    \ plugin. You can change the parameters that are provided to costmap_2d to take\
    \ the footprint of the robot into account, by either passing the `robot_radius`\
    \ or `robot_footprint` parameter to the move_base_node when you launch it. \n\n\
    You can see how this could be done by taking a look at the [turtlebot_navigation](https://github.com/turtlebot/turtlebot_apps/tree/indigo/turtlebot_navigation)\
    \ package, specifically how parameters are passed to the move_base_node in the\
    \ [move_base.launch.xml](https://github.com/turtlebot/turtlebot_apps/blob/indigo/turtlebot_navigation/launch/includes/move_base.launch.xml#L16-L19)\
    \ file. \n\nIn this package, the `robot_radius` parameter is set in the [costmap_common_parameters.yaml](https://github.com/turtlebot/turtlebot_apps/blob/indigo/turtlebot_navigation/param/costmap_common_params.yaml#L4)\
    \ file."

      If I understand correctly- for simplicity and efficiency reasons, default global planner assumes the robot is circular and generates the global plan in configuration space. By that, it adds the radius buffer along all the static/dynamic obstacles, and treat the robot as a single point object in the planning algorithm. That's why it seems to only honor circular footprint instead of a polygon one.
