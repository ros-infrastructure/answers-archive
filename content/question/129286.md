    I managed to call/receive services using C++ types with a similar (undocumented) strategy as for messages. You should define a class for the service itself (eg. ExampleService) and the corresponding request/response classes (ExampleService::Response/Request). The Request/Response classes must have message_traits as per ROS's tutorial (note: use the same MD5SUM por both). Then, the final step is to provide the same traits (MD5Sum and DataType) but for the ExampleService class itself, but under the service_traits namespace.
    Finally, you need to provide serialization methods for the Request/Response classes.

    With this, you can simply use the classes in services as per usual.

  body_markdown: "There is sort of a simple rule to keep in mind when thinking about\
    \ publish/subscribe custom class, you must always have a defined `.msg` for each\
    \ topic.\n\nIn you original question you mentioned that you have a message `item_test.msg`\
    \ defined as:\n\n    Item item\n\nWhere `Item` is only otherwise defined as a\
    \ C++ class. This will not work, you must have a corresponding `.msg` definition\
    \ of the `Item` class. This will generate C++ and Python (others) code for the\
    \ `Item.msg` message definition, but in your code you can use your own `Item`\
    \ class and then use the message traits to have a custom serialization for your\
    \ custom implementation of the `Item` class.\n\nFor instance, you might define\
    \ the `Item.msg` file as:\n\n    string name\n    uint32 id\n\nThis will produce\
    \ some C++ code like this (simplified):\n\n    namespace your_package_name {\n\
    \    struct Item_\n    {\n        std::string name;\n        uint32_t id;\n  \
    \  };\n    typedef Item_ Item;\n    }\n\nBut then you could make your own `Item`\
    \ class:\n\n    namespace my_item_class {\n    class Item {\n      public:\n \
    \       void setName(std::string name) {name_ = name;}\n        std::string getName()\
    \ {return name_;}\n        void setId(size_t id) {id_ = id;}\n        size_t getId()\
    \ {return id_;}\n      private:\n        std::string name_;\n        size_t id;\n\
    \    };\n    }\n\nThen you could write the necessary message traits to allow you\
    \ to publish and subscribe to topics using your custom type (this is an \"all-in-one\"\
    \ version):\n\n    namespace ros\n    {\n    namespace message_traits\n    {\n\
    \    template<> struct IsFixedSize<my_item_class::Item> : public TrueType {};\n\
    \    template<> struct IsSimple<my_item_class::Item> : public TrueType {};\n \
    \   \n    template<>\n    struct MD5Sum<my_item_class::Item>\n    {\n      static\
    \ const char* value()\n      {\n        return MD5Sum<your_package_name::Item>::value();\n\
    \      }\n    \n      static const char* value(const my_item_class::Item& m)\n\
    \      {\n        return MD5Sum<your_package_name::Item>::value(m);\n      }\n\
    \    };\n    \n    template<>\n    struct DataType<my_item_class::Item>\n    {\n\
    \      static const char* value()\n      {\n        return DataType<your_package_name::Item>::value();\n\
    \      }\n    \n      static const char* value(const my_item_class::Item& m)\n\
    \      {\n        return DataType<your_package_name::Item>::value(m);\n      }\n\
    \    };\n    \n    template<>\n    struct Definition<my_item_class::Item>\n  \
    \  {\n      static const char* value()\n      {\n        return Definition<your_package_name::Item>::value();\n\
    \      }\n    \n      static const char* value(const my_item_class::Item& m)\n\
    \      {\n        return Definition<your_package_name::Item>::value(m);\n    \
    \  }\n    };\n    } // namespace message_traits\n    \n    namespace serialization\n\
    \    {\n    template<>\n    struct Serializer<my_item_class::Item>\n    {\n  \
    \    template<typename Stream, typename T>\n      inline static void allInOne(Stream&\
    \ stream, T item)\n      {\n        stream.next(item.getName());\n        uint32_t\
    \ id = static_cast<uint32_t>(item.getId());\n        stream.next(id);\n      }\n\
    \    \n      ROS_DECLARE_ALLINONE_SERIALIZER;\n    };\n    } // namespace serialization\n\
    \    } // namespace ros\n\nThe majority of the above code is just associating\
    \ your custom class, `my_item_class::Item`, with the generated, `my_package_name::Item`,\
    \ message class. This association allows you to use the types interchangeably\
    \ in your code, but tools and other nodes will always interpret it as a `my_package_name::Item`\
    \ unless they use the same message trait code above to receive it as the custom\
    \ class too.\n\nAgain the thing to remember is that in order to send something\
    \ over a topic in ROS you need to have a fully defined message (`.msg` file) with\
    \ which to associate your custom class."
