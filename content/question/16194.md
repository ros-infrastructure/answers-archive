  body_markdown: "Hi, dalbar. I think I've encountered the similar issue.\n\nI've\
    \ got my custom sdf model, where I use my own material script. The approach I\
    \ use is based on the [**SDF**](http://sdformat.org/spec?ver=1.6&elem=visual)\
    \ models available [here (beer model as an example)](https://bitbucket.org/osrf/gazebo_models/src/default/beer/),\
    \ see also [related tutorial](http://gazebosim.org/tutorials?tut=model_structure).\n\
    \nTo be able to *insert* the model to the scene I've edited the ~/.gazebo/gui.ini,\
    \ \n\n\n    [geometry]\n    x=0\n    y=0\n    [model_paths]\n    filenames=<YOUR_MODELS_ROOT_FOLDER_PATH>\n\
    \n\nwhich **seemed to be enough**. The model was visible in the 3D scene with\
    \ the texture (just like in your case).\n**However**, when I ran the camera preview\
    \ using the script similar to the one below\n\n    rosrun image_view image_view\
    \ image:=/some_path/camera1/image_raw\n\nthe camera got stucked every time I had\
    \ added my custom model to the scene before launching the camera script.\n\n---\n\
    \n**TL;DR**\n\ninstead of editing the `gui.ini` file (if you do it), try to append\
    \ to your `~\\.bashrc file the following lines`\n\n   \n\n    #Gazebo\n    export\
    \ GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:/<YOUR_MODELS_ROOT_FOLDER_PATH>\n\n\nto\
    \ be sure it works run\n\n     source ~/.bashrc\n\nand check if the `$GAZEBO_MODEL_PATH`\
    \ variable contains the directory"
