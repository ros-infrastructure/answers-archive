  body_markdown: "What you see is the exit code of the move_group process. It has\
    \ nothing to do with error codes in`MoveItErrorCodes`. See also [this answer](http://answers.ros.org/question/11064/list-of-possible-exit-codes-from-roslaunch/).\
    \ A exit code of -11 essentially means that the process segfaulted. Now why it\
    \ does that on Intel Edison is a interesting question.\n\nYour second problem\
    \ looks like some malformed launch-prefix line. Not completely sure, but it looks\
    \ like you're trying to execute (-x) a \"gdb_settings.gdb\" file. which looks\
    \ wrong. Have you tried using\n\n    launch-prefix=\"gdb -ex run --args\" \n\n\
    as suggested on [How to Roslaunch Nodes in Valgrind or GDB](http://wiki.ros.org/roslaunch/Tutorials/Roslaunch%20Nodes%20in%20Valgrind%20or%20GDB)?\n\
    \n/edit: For Eigen to work correctly on 32 bit systems, allocators that properly\
    \ align data always have to be used. Consistently adding that throughout all code\
    \ can be a pretty big task (and in some cases is not trivial).\nSee the [Explanation\
    \ of the assertion on unaligned arrays](http://eigen.tuxfamily.org/dox-devel/group__TopicUnalignedArrayAssert.html)\
    \ page. The easy thing you can try is switching off vectorization as explained\
    \ on the bottom of the page."
