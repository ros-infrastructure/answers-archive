  body_markdown: "I think the problem is that gazebo is in an entirely different namespace\
    \ than the rest of your nodes (particularly robot_state_publisher). Try setting\
    \ them all to use the same namespace and see if that helps. \n\n\n**EDIT**: When\
    \ I'm launching multiple objects at the same time, I like to use [xacro](http://www.ros.org/wiki/xacro)\
    \ to define the objects that I want to create. So instead of the urdf containing\
    \ link names, I can parameterize all of the link names so that I can launch as\
    \ many as I want simultaneously. For example, instead of using: \n\n    <link\
    \ name=\"dummy_link\" />\n\nI would use:\n\n    <link name=\"${name}_dummy_link\"\
    \ />\n\nso that to add a new object, I just need to pass it a unique \"name\"\
    \ variable. \n\nXacro might be the solution you're looking for. If it isn't, I\
    \ might be interpreting your problem incorrectly and I can amend my answer. \n\
    \n**EDIT**: For multiple objects, you will end up with separate tf trees. The\
    \ way to get around this is to make sure that all objects share one (and only\
    \ one) tf frame. (I use the \"/world\" frame). "

    \ therefore showing model error of not transformed links. When the tf_prefix is\
    \ entered (either manually or via .vcg configuration) there is update of links\
