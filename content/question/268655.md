  body_markdown: "The problem is that `gazebo_ros_control` is looking for `/robot_description`,\
    \ but that hasn't been set. You set `/first_pelican/robot_description` instead.\n\
    \nThe solution is to change\n\n    <node name=\"mybot_spawn\" pkg=\"gazebo_ros\"\
    \ type=\"spawn_model\" output=\"screen\"\n        args=\"-urdf -param robot_description\
    \ -model mybot_$(arg ns_1)\n                    -x $(arg x) -y $(arg y) -z $(arg\
    \ z)\n                    -R $(arg roll) -P $(arg pitch) -Y $(arg yaw)\" respawn=\"\
    false\" />\n\nto \n\n    <node name=\"mybot_spawn\" pkg=\"gazebo_ros\" type=\"\
    spawn_model\" output=\"screen\"\n        args=\"-urdf -param /first_pelican/robot_description\
    \ -model mybot_$(arg ns_1)\n                    -x $(arg x) -y $(arg y) -z $(arg\
    \ z)\n                    -R $(arg roll) -P $(arg pitch) -Y $(arg yaw)\" respawn=\"\
    false\" />\n\n<hr>\n\n**Edit:**\n\nThis warning may be the culprit\n\n    The\
    \ root link chassis has an inertia specified in the URDF, but KDL does not support\
    \ a root link with an inertia. As a workaround, you can add an extra dummy link\
    \ to your URDF.\n\nTry adding a dummy link and move the inertia to that one. https://answers.ros.org/question/192817/error-msg-the-root-link_base-has-an-inertia-specified-in-the-urdf-but-kdl/?answer=192861#post-id-192861\n\
    \n<hr>\n\n**Edit 2:**\n\nI'm not too familiar with URDF so this may not be *exactly*\
    \ the solution but it should be a good starting point:\n\n    <link name=\"chassis_dummy\"\
    >\n      <inertial>\n        <mass value=\"15.0\"/>\n        <origin xyz=\"0 0\
    \ 0\" rpy=\" 0 0 0\"/>\n        <inertia\n            ixx=\"0.1\" ixy=\"0\" ixz=\"\
    0\"\n            iyy=\"0.1\" iyz=\"0\"\n            izz=\"0.1\"\n        />\n\
    \      </inertial>\n    </link>\n\n    <joint name=\"chassis_to_chassis_dummy\"\
    \ type=\"fixed\">\n      <parent link=\"chassis\"/>\n      <child link=\"chassis_dummy\"\
    />\n    </joint>\n\nAnd remove the `inertial` tags and everything between them\
    \ (in the chassis link only!) because I moved it into this dummy link. For additional\
    \ help refer to the [URDF tutorials](http://wiki.ros.org/urdf/Tutorials) (which\
    \ is how I came up with this).\n\n\n----------\n\n**Edit 3:**\n\nI was finally\
    \ able to get your robot to load in Gazebo by setting the `robot_description`\
    \ parameter *outside* of the `<group>` tags. I then loaded (spawned) the URDF\
    \ (robot) in Gazebo *inside* the `<group>` tags:\n\n    <arg name=\"robot_description\"\
    \n         default=\"$(find urdf_test_pkg)/model/robot.xacro\"/>\n    <param name=\"\
    /robot_description\"\n       command=\"$(find xacro)/xacro --inorder $(arg robot_description)\
    \ namesapce_deploy:=$(arg ns_1)\"/>\n\n    <group ns=\"$(arg ns_1)\">\n      \
    \  <node name=\"mybot_spawn\" pkg=\"gazebo_ros\" type=\"spawn_model\" output=\"\
    screen\"\n        args=\"-urdf -param /robot_description -model mybot_$(arg ns_1)\n\
    \                    -x $(arg x) -y $(arg y) -z $(arg z)\n                   \
    \ -R $(arg roll) -P $(arg pitch) -Y $(arg yaw)\" respawn=\"false\" />\n\n    \
    \    <!-- convert joint states to TF transforms for rviz, etc -->\n        <!--\
    \ Notice the leading '/' in '/robot_description' -->\n        <node name=\"robot_state_publisher\"\
    \ pkg=\"robot_state_publisher\" type=\"robot_state_publisher\" respawn=\"false\"\
    \ output=\"screen\">\n            <remap from=\"/joint_states\" to=\"/$(arg ns_1)/joint_states\"\
    \ />\n        </node>\n    </group>\n\n\nNotice when I'm spawning the robot I\
    \ specifically attach the leading `/` to `/robot_description`. This causes the\
    \ spawner to grab the global parameter `/robot_description`. This should solve\
    \ the issue of spawning the robot."
