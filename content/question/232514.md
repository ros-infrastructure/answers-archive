  body_markdown: "I guess you are using the default move_base configuration, that\
    \ only calls conservative clear costmap that cleans costmaps only further than\
    \ 3 meter from your robot. You can also include the aggressive version, that clears\
    \ costmaps from 0 meters (so full costmaps). Add something like this to your move_base.yaml:\n\
    \n    recovery_behaviors:\n      - name: 'conservative_reset'\n        type: 'clear_costmap_recovery/ClearCostmapRecovery'\n\
    \      - name: 'aggressive_reset'\n        type: 'clear_costmap_recovery/ClearCostmapRecovery'\n\
    \    \n    conservative_reset:\n      reset_distance: 3.0\n    \n    aggressive_reset:\n\
    \      reset_distance: 0.0\n\nBut I don't think this will work neither, because\
    \ the lower door is farther than 3 meters from the robot and still not cleared!\n\
    \nWhat will surely work is to call clear_costmaps move_base's service, that will\
    \ reset both local and global costmaps."
