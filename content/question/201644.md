Rather then trying to figure out where your Python code should go on every different system and variation we rely on the setuptools infrastructure to give us the right answer.

    Obviously this is not working for you out of the box, but looking at the error it seems mostly confused about where the `package.xml` is.   body_markdown: "**EDIT:**\n\nI've found a cleaner way to solve it. \n\nIdeally `setup.py`\
    \ and `package.xml` should be in the same dir. However, this does not happens\
    \ inside a `tox` venv unless you tell it what files should be included. To do\
    \ so [you need to create a `MANIFEST.in`](https://docs.python.org/2/distutils/sourcedist.html#the-manifest-in-template)\
    \ in the same dir as `setup.py` and list there all the files you want to include\
    \ in your source distribution. \nHere is what I put in my `MANIFEST.in`:\n\n \
    \   include package.xml\n\nAnd my `setup.py` now is the barebones `setup.py` listed\
    \ in the [Catkin documentation](http://docs.ros.org/indigo/api/catkin/html/user_guide/setup_dot_py.html):\n\
    \n    from distutils.core import setup\n    from catkin_pkg.python_setup import\
    \ generate_distutils_setup\n    \n    d = generate_distutils_setup(\n        #\
    \ #  don't do this unless you want a globally visible script\n        # scripts=['bin/myscript'],\n\
    \        packages=['rospy_utils'],\n        package_dir={'': 'src'}\n    )\n \
    \   \n    adminstrosetup(**d)\n\n\nIt seems that every ROS-related file that you\
    \ don't include in the `MANIFEST.in` won't be included in the source distribution\
    \ that is put into the `tox` virtual env. I guess that, if you need to do some\
    \ rostests, use some ROS msgs, etc., you might need to include them here as well.\n\
    \n---\n**Just for future reference, I leave the old answer here:**\n\nAs @William\
    \ points out, it seems that the `generate_distutils_setup` included in the `setup.py`\
    \ needs to know the location of the `package.xml` file. The call has [an optional\
    \ parameter that defaults to `os.path.curdir`](https://github.com/ros-infrastructure/catkin_pkg/blob/master/src/catkin_pkg/python_setup.py#L46)\
    \ which is usually ok since `setup.py` is included in the same dir as `package.xml`.\n\
    \nHowever, it seems that `tox` runs the `setup.py` in a virtual environment located\
    \ in `/tmp/`. Therefore, if you don't tell `generate_distutils_setup` that you\
    \ are running in a separate dir it will fail.  \n\nI've modified my `setup.py`\
    \  to tell it where to find the real path of the `package.xml` file and now I\
    \ can run my `tox` commands perfectly. That's how my `setup.py` looks like now:\n\
    \ \n    #!/usr/bin/env python\n    \n    from distutils.core import setup\n  \
    \  from catkin_pkg.python_setup import generate_distutils_setup\n    \n    import\
    \ rospkg\n    THIS_PKG = 'rospy_utils'\n    rospack = rospkg.RosPack()\n    pkg_path\
    \ = rospack.get_path(THIS_PKG)\n    \n    d = generate_distutils_setup(\n    \
    \    # #  don't do this unless you want a globally visible script\n        # scripts=['bin/myscript'],\n\
    \        packages=['rospy_utils'],\n        package_dir={'': 'src'},\n       \
    \ package_xml_path=pkg_path\n    )\n    \n    adminstrosetup(**d)\n "
