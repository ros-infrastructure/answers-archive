  body_markdown: "No this is not at all the rviz error. The issue comes from the *gazebo_plugins*\
    \ package and in your particular case from the *gazebo_ros_laser* plugin.\n\n\
    Current implementation in *gazebo_ros_laser.cpp* is as follows:\n\n    240: //\
    \ Add Frame Name\n    241: this->laserMsg.header.frame_id = this->frameName;\n\
    \nand earlier\n\n    100: this->frameName = _sdf->GetElement(\"frameName\")->GetValueString();\n\
    \nThis means that laser scans in the field *frame_id* of *LaserMsg* header got\
    \ whatever you put in the *frameName* of your gazebo controller declared in urdf.\n\
    \n\n      <controller:gazebo_ros_laser name=\"gazebo_ros_laser_controller\" plugin=\"\
    libgazebo_ros_laser_relative.so\">\n        <hokuyoMinIntensity>101.0</hokuyoMinIntensity>\n\
    \        <gaussianNoise>0.005</gaussianNoise>\n        <alwaysOn>true</alwaysOn>\n\
    \        <updateRate>20</updateRate>\n        <topicName>scan</topicName>\n  \
    \      <frameName>hokuyo_link</frameName>\n        <interface:laser name=\"gazebo_ros_laser_iface\"\
    \ />\n      </controller:gazebo_ros_laser>\n\nAnd therefore rviz looks how to\
    \ tansform scans from the link *hokuyo_link* but it can only find */summit_one/hokuyo_link*\
    \ and */summit_two/hokuyo_link*.\n\nI can see in your launch file that you try\
    \ to handle that with:\n\n    <remap from=\"hokuyo_laser_link\" to=\"summit_one/hokuyo_laser_link\"\
    \ />\n\nbut remapping works only for nodes and topics names, not for tf transformations,\
    \ we use *tf_prefix* for that.\n\nThe  quick and dirty workaround for your problem\
    \ is to make two copies of your urdf file: one declaring */summit_one/hokuyo_link*\
    \ as *frameName* and the other with */summit_two/hokuyo_link*.\n\nHowever the\
    \ proper solution is to introduce tf resolving in *gazebo_ros_laser* before storing\
    \ *frame_id* in message header. \n\nThis discussion is also valid for the rest\
    \ of plugins in *gazebo_plugins* package. I will issue a ticket for this.\n"

I have some troubles to see the laser_scan in a simulation with two robots which have the same description file (urdf) in different group with different namespace.

I launch both in gazebo and works quite good, the robots looks ok but when I launch rviz to see the laser, I select the fixed frame and the target frame of the robot one, I select the robot_description of the robot one and the tfprefix of the robot one. The tf looks great.

I see the robot one in the center of the visual space in rviz. When I try to see the laser_scan, I select the correct topic but I nothing appear, the error is the next:

    Transform [sender=/gazebo]
    For frame [hokuyo_laser_link]: Frame [hokuyo_laser_link] does not exist

I think the problem come to rviz. Rviz look for the frame described in the urdf robot description and not look for the tf_prefix.

Here my launch file and my tree of tf:

    <launch>
      <!-- send summit_xl.urdf to param server -->
      <group ns="summit_one">
    	  <param name="robot_description" textfile="$(find summit_xl_description)/urdf/summit_xl.urdf" />

    	  </node>
    
    	  <!-- Controller manager parameters -->
    	  <param name="pr2_controller_manager/mechanism_statistics_publish_rate" value="1.0" />

    	  <!-- Robot state publisher -->

    		<param name="publish_frequency" type="double" value="50.0" />
    		<remap from="hokuyo_laser_link" to="summit_one/hokuyo_laser_link" />
    		<param name="tf_prefix" type="string" value="summit_one" />
    	  </node>
    
    	  <!-- Diagnostics -->
    	  <node pkg="pr2_mechanism_diagnostics" type="pr2_mechanism_diagnostics" name="pr2_mechanism_diagnostics_one" />

    	  <param name="pr2_controller_manager/mechanism_statistics_publish_rate" value="1.0" />
