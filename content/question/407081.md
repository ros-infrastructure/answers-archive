  body_markdown: "Perfect odometry with zero slip would yield no difference between\
    \ odometry and map coordinates, **provided** odometry was initialized to be correct\
    \ with the map when the robot was started. \nWhen robot comes on it assumes the\
    \ odometry starts at `(0, 0, 0)` and `(0, 0, 0, 0)` but that isn't where the robot\
    \ really is, usually.\n\nThe correction expression you're looking for is the `map\
    \ -> odom` transform. It is the correction vectors between map and odom frames.\n\
    \nRelated questions with answers:\n\n- https://answers.ros.org/question/401747/publishing-map-odom-transform-using-custom-localization-and-slam-algorithms/\n\
    \n- https://answers.ros.org/question/329980/relationsship-between-map-odom-and-base_link-coordinate-frames/\n\
    \nGood tutorial:\n\n- https://automaticaddison.com/coordinate-frames-and-transforms-for-ros-based-mobile-robots/\
    \ (especially **Map to Odom** part)"
