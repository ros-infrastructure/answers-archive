Hello everyone, I am trying to control a KUKA kr10r1100sixx robot with moveit on ubuntu 20.04 with ROS Noetic.

For application purpose the robot can handle a camera, a scanner or nothing. 
So I need to be able to attach/detach a specific tool in a "real time" context.
To do this, I naively did the following (as in turorial https://ros-planning.github.io/moveit_tutorials/doc/move_group_interface/move_group_interface_tutorial.html):

    // Define collision object ROS message.
    moveit_msgs::CollisionObject robot_attached_object;
    robot_attached_object.header.frame_id = "flange";
    robot_attached_object.id = "camera";
    robot_attached_object.meshes.push_back(camera_mesh);
    robot_attached_object.mesh_poses.push_back(pose);
    robot_attached_object.operation = robot_attached_object.ADD;
    
    // Apply the collision object to the planning scene.
    planning_scene_interface.applyCollisionObject(robot_attached_object);
    // Attach Object to robot
    move_group_interface.attachObject(robot_attached_object.id, "flange", std::vector<std::string>{ "flange", "link_6"});

It worked in a certain way. 
I can see my tool in rviz and if I call:

    move_group_interface.setStartStateToCurrentState();
    success = (move_group_interface.plan(my_plan) == moveit::planning_interface::MoveItErrorCode::SUCCESS);

The planning goes well without any collisions.

But sometimes in my application I need to plan from a start state that is not the current state. 
Let's take an example that should do the same as previously:

    move_group_interface.setStartState(*move_group_interface.getCurrentState());
    success = (move_group_interface.plan(my_plan) == moveit::planning_interface::MoveItErrorCode::SUCCESS);

Now the planning does not consider the tool and has collisions. Indeed,  `move_group_interface.getCurrentState()` return a roboState which does not contain any attached objects unlike `_considered_start_state` used when calling `setStartStateToCurrentState()`.

I tried to add an attached object to the current robot step with `RobotState::attachBody ( AttachedBody * attached_body)` method.
There is not compilation error, but firstly, I dont see my tool in rviz when planning (while I can see it when using `setStartStateToCurrentState()`).
And secondly, I am not sure if the attached object that I added in current State is exactly the same as in `_considered_start_state`.

One idea would be to make a copy of a robot state that know the attached object, and then change the position of the joints with `setJointGroupPositions()`.
Since I couldn't find a way to get `_considered_start_state` what can I do to force the current state to know the attached object when I call `move_group_interface.attachObject()`. 

More generally, does anyone have an idea of the best practice to define a startState that takes into account the tool attached to the robot for collision-free planning.

Thank you in advance, any answer would help.
