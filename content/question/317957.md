    I'm not aware of a available solution for this, but here are a few options:

     - The
       [image_to_rtsp](https://gitlab.com/Humpelstilzchen/ros_image_to_rtsp)
       node(let) taks in ROS images and
       provides a RTSP stream based on them.
     - You could connect a gstreamer
       pipeline to that RTSP server You
       could take [the code from the
       previously named
       package](https://gitlab.com/Humpelstilzchen/ros_image_to_rtsp/blob/master/src/image2rtsp.cpp#L72)
       as inspiration and push the ROS image
       data into a gstreamer appsrc pad and
       connect other gstreamer pads for
       compression/file writing to that.
     - Instead of running a ROS driver for
       the cam, you could run a gstreamer
       pipeline with a
       [v4l2src](https://gstreamer.freedesktop.org/data/doc/gstreamer/head/gst-plugins-good/html/gst-plugins-good-plugins-v4l2src.html)
       connecting to the camera and s[plit
       the
       pipeline](https://gstreamer.freedesktop.org/data/doc/gstreamer/head/gstreamer-plugins/html/gstreamer-plugins-tee.html)
       into a file writer and a part that
       feeds data to the
       [gscam](http://wiki.ros.org/gscam)
       node that provides the ROS image
       topic. In fact, it might be possible
       to do that directly within the gscam
       pipeline config (never tried that).
