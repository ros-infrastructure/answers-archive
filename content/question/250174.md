  body_markdown: "It should be more or less straightforward:\n\n 1. Setup SocketCAN\
    \ (you already have this running): http://wiki.ros.org/socketcan_interface#Initialize_NIC\n\
    \ 2. Prepare URDF with sane limits (this is required for now, will be optional\
    \ in the future): http://wiki.ros.org/urdf/Tutorials/Create%20your%20own%20urdf%20file\n\
    \ 3. Prepare EDS/DCF, take special care for the PDO mapping (http://wiki.ros.org/canopen_402),\
    \ use transmission type 1 (every sync)\n 4. Prepare driver config\n   - prepare\
    \ chain config (http://wiki.ros.org/canopen_chain_node#Configuration)\n   - configure\
    \ motor-specific settings, especially unit conversions (http://wiki.ros.org/canopen_motor_node)\n\
    \ 5. Prepare controller config\n   - list of controllers (documentation varies,\
    \ http://wiki.ros.org/ros_controllers)\n   - add a `required_drive_mode` to each\
    \ motion controller, it takes the number of the mode to be used (http://wiki.ros.org/canopen_402#Drive_operation_modes)\
    \ \n 6. Prepare a launchfile for canopen_motor_node\n   - upload driver config\
    \ as private parameters\n   - upload controller config into namespace\n   - upload\
    \ robot description\n 7.  rosservice call [/namespace]/driver/init (http://wiki.ros.org/canopen_chain_node#Services)\n\
    \ 8. start/switch the controllers (rqt_controller_manager, ontroller_manager,\
    \ spawner etc.)\n\nThe EDS file parser is not really bullet proof (and EDS file\
    \ format is rather flexibel) and might fail with some error indication.\nIn addition\
    \ `ros_canopen` enforces strict typing, some EDS files list non-standard types\
    \ for some objects (e.g. signed instead of unsigned). This must be fixed as well\
    \ in the EDS.\n\nA basic driver config looks like:\n\n    bus:\n      device:\
    \ can0\n    sync:\n      interval_ms: 10  # 100Hz\n      overflow: 0\n    defaults:\n\
    \      eds_pkg: my_package\n      eds_file: \"config/MyDescription.dcf\" # the\
    \ parser reads EDS and DCF\n    nodes:\n      my_joint:\n        id: 1 \n\ncontroller\
    \ config example: https://github.com/ipa320/canopen_test_utils/blob/indigo-devel/config/rig1_controller.yaml\n\
    \nFairly complex examples: https://github.com/ipa320/schunk_robots/\n\nIt would\
    \ be great if you could turn this into a tutorial on ROS Wiki based on your experiences\
    \ :)"
