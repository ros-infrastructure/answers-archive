  body_markdown: "What's happening is your robot model is \"exploding\": see [here](http://answers.ros.org/question/30993/how-to-fix-pr2_kinect_empty_world-broken-when/),\
    \ [here](http://answers.ros.org/question/38774/issue-with-collision-model-in-gazebo/),\
    \ and [here](http://answers.ros.org/question/38774/issue-with-collision-model-in-gazebo/)\
    \ for what I mean by exploding. \n\nEssentially, what's happening is the model\
    \ (the PR2 in your case) is colliding with something (either itself or the plane\
    \ since its and empty world) and the physics engine is not updating fast enough\
    \ to catch the collision. The models wind up slightly inside of each other and,\
    \ in an effort to fix the collision, the physics engine pushes the two models\
    \ away from each other (sometimes at VERY high speeds making the mode \"explode).\
    \ That explains why the PR2 is disappearing. When this happens, the physics engine\
    \ essentially stop working properly and causes the error message you are seeing.\
    \ Try modifying your world file with the parameters defined [here](http://gazebo.willowgarage.com/wiki/sdf_physics).\
    \ In particular, contact_max_correcting_vel defaults at 100 and can be lowered\
    \ to a smaller value (e.g., 1) to slow down this violent collision correction.\
    \ You can also update the update rate of the physics engine (iters)."

    \ to put all links at the same location (overlapping each other), this is definitely\
    \ a bug, but you can add the following definition to avoid this behavior:\n\n\
    \    model_state = gazebo.msg.ModelState()\n    model_state.model_name = 'pr2'\n\
    \    model_state.pose.position.x = 1\n    model_state.pose.position.y = 2\n  \
    \  model_state.pose.position.z = 0\n    model_state.pose.orientation.x = 0\n \
    \   model_state.pose.orientation.y = 0\n    model_state.pose.orientation.z = 0\n\

    \ I've reference above.\n"
