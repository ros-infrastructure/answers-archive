  body_markdown: "**Plugin**  \nAssuming it isn't well documented on a wiki, the most\
    \ straightforward way to understand a plugin's XML declaration is to look at the\
    \ source code:  \nhttps://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp\n\
    \n----------\n**Questions**  \n\n> *I'm not sure what how the axis are supposed\
    \ to be set* \n\nLooking at the [source code](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp)\
    \ for `gazebo_ros_skid_steer_drive`, it does not allow the wheel joint axes to\
    \ be set via SDF/URDF. \n\nBased on this [section](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp#L377-L389),\
    \ the plugin assumes that all 4 wheel axes are oriented in the same direction:\n\
    \n    void GazeboRosSkidSteerDrive::getWheelVelocities() {\n      boost::mutex::scoped_lock\
    \ scoped_lock(lock);\n\n      double vr = x_;\n      double va = rot_;\n\n   \
    \   wheel_speed_[RIGHT_FRONT] = vr + va * wheel_separation_ / 2.0;\n      wheel_speed_[RIGHT_REAR]\
    \ = vr + va * wheel_separation_ / 2.0;\n\n      wheel_speed_[LEFT_FRONT] = vr\
    \ - va * wheel_separation_ / 2.0;\n      wheel_speed_[LEFT_REAR] = vr - va * wheel_separation_\
    \ / 2.0;\n\n    }\n\n> *and what some of the required variables truly mean e.g\
    \ torque (not sure which number I should give as input)*\n\n`gazebo_ros_skid_steer_drive`\
    \ uses Gazebo Joint Motors to rotate each wheel joint at the desired velocity.\n\
    \nFrom the [Setting Velocity on Links and Joints Tutorial](http://gazebosim.org/tutorials?tut=set_velocity#SetJointVelocityUsingJointMotors):\n\
    \n> Configuring a joint motor is done using Joint::SetParam().\n\n          this->model->GetJoint(\"\
    orange_joint\")->SetParam(\"fmax\", 0, 100.0);\n          this->model->GetJoint(\"\
    orange_joint\")->SetParam(\"vel\", 0, 1.0);\n\n> It accepts three parameters:\
    \ key, axis, and value. The key parameter is a string that names the parameter\
    \ to be changed. The axis parameter is an index that may be 0 or 1.  \n...  \n\
    Setting up a joint motor requires requires two calls. The first call sets the\
    \ key vel to the velocity the joint should travel at. It is meters per second\
    \ for prismatic joints and radians per second for all others. The other call sets\
    \ the key fmax. It is the maximum force or torque a joint motor may apply during\
    \ a time step. Set it larger than the force required to be at the target velocity\
    \ at the next time step. Set it smaller to apply a force over many time steps\
    \ until the velocity is reached. Stop applying force by setting fmax back to zero.\n\
    \nIn the `gazebo_ros_skid_steer_drive` plugin, these two steps occur [here](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp#L289-L292)\
    \ and [here](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp#L352-L355).\n\
    \n> *or broadcastTF (not sure why I should not want to broadcast)*  \n\nTwo possible\
    \ reasons that come to mind:\n\n 1. You aren't interested in odometry and want\
    \ to reduce resource usage / bandwidth.\n 2. You want to publish your own tf data\
    \ in lieu of Gazebo's like [this user](https://answers.ros.org/question/229722/how-to-stop-gazebo-publishing-tf/).\n\
    \n> *At the moment I can drive backwards and forwards but it the robot does not\
    \ turn.* \n\nI recommend an incremental testing strategy. First, test your robot\
    \ while its suspended in the air by temporarily adding a fixed joint from the\
    \ world link to your base link:\n\n    <link name=\"world\" />\n    <joint name=\"\
    world_to_base_link=\" type=\"fixed\">\n      <parent link=\"world\"/>\n      <child\
    \ link=\"base_link\"/>\n    </joint>\n\nTest to make sure your wheels are rotating\
    \ as desired. Once you've got the `skid_steer_drive_plugin` working in the air,\
    \ you can remove fixed joint (and possibly start debugging collision/friction\
    \ issues with ground).\n\n> *Here is the xacro that I'm using at the moment:*\n\
    \nTwo things that jump out at me:\n\n 1. You are using identity inertial matrices\
    \ for all links. Those inertial values are too high. I recommend reducing them\
    \ by an order of magnitude for now, i.e.: **inertia ixx=\"0.1\" ixy=\"0.0\" ixz=\"\
    0.0\" iyy=\"0.1\" iyz=\"0.0\" izz=\"0.1\"**. Later on you can [calculate more\
    \ accurate inertial matrices](https://en.wikipedia.org/wiki/List_of_moments_of_inertia#List_of_3D_inertia_tensors)\
    \ or use a tool like [Meshlab](http://gazebosim.org/tutorials?tut=inertia).\n\
    \ 2. You're not setting basic Gazebo physics properties for links/joints. I'd\
    \ start messing with these last (the defaults are often sufficient for a working\
    \ - though usually unrealistic - model). Check out the [Using a URDF in Gazebo\
    \ Tutorial](http://gazebosim.org/tutorials/?tut=ros_urdf).\n\n----------\nNote\
    \ 1: It's worth mentioning that there exist two primary repositories for \"official\"\
    \ plugins:  \n\n 1. https://bitbucket.org/osrf/gazebo/src/default/plugins/ which\
    \ contains \"pure\" Gazebo plugins\n 2. and https://github.com/ros-simulation/gazebo_ros_pkgs/tree/kinetic-devel/gazebo_plugins\
    \ which contains Gazebo plugins with ROS bindings.\n\nFor example, the `osrf/gazebo`\
    \ repo contains [SkidSteerDrivePlugin](https://bitbucket.org/osrf/gazebo/src/default/plugins/SkidSteerDrivePlugin.cc)\
    \ and the `ros-simulation/gazebo_ros_pkgs` repo contains [gazebo_ros_skid_steer_drive](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_skid_steer_drive.cpp).\
    \ These plugins are similar but they have different XML declarations, parameters,\
    \ and implementations *(e.g. they will turn the same robot model in opposite directions\
    \ given the same angular velocity command).*\n\n\n\n\n\n"
