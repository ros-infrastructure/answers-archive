  body_markdown: "Hi,\n\nSo I worked on solving this issue. It was mainly two problems:\n\
    \n1) The Gazebo client wasnt being launched. Thats because this simulation version\
    \ is intended for use in ROSDevelopementStudio, so by default the GUI isnt launched\
    \ for performance reasons. But even if you launched the version that should open\
    \ the gui, current versions of gazebo just crash, at least in Kinetic Gazebo7.\n\
    \n2) The Environment variables that set up where the models and plugins are in\
    \ this particular simulation are set outside the ros package system, so this causes\
    \ other issues, like not appearing the parrot drone mesh or not having any collisions.\n\
    \nAll these issues are explained with detail in this video: [VIDEO](https://youtu.be/dwdVwwngMow)\n\
    \nThe repo updated with the solution you can find it here: [DRONE CONSTRUCT GIT,\
    \ kinetic-gazebo7 Branch](https://bitbucket.org/theconstructcore/parrot_ardrone/src/kinetic-gazebo7/drone_construct/)\n\
    \nYou will also need to download this package **Spawn_robot_tools**:\n[Spawn Robot\
    \ Tools](https://bitbucket.org/theconstructcore/spawn_robot_tools/src/master/)\n\
    \nTo make it work, I created a script called **start_simulation_localy.sh** inside\
    \ **drone_construct/scripts** that sets the local variables correctly and launched\
    \ the simulation with the GUI enables and the simulation unpaused:\n\n\n    #!/bin/sh\n\
    \n    #find where the 'sjtu_drone' is\n    pack_path=$(rospack find sjtu_drone)\n\
    \n    #export the gazebo pathes\n    export GAZEBO_MODEL_PATH=$pack_path/models:$GAZEBO_MODEL_PATH\n\
    \    export GAZEBO_RESOURCE_PATH=$pack_path:/usr/share/gazebo-3.0:/usr/share/gazebo-\
    \ \n    4.0:/usr/share/gazebo_models:$GAZEBO_RESOURCE_PATH\n    export GAZEBO_PLUGIN_PATH=$pack_path/plugins:$GAZEBO_PLUGIN_PATH\n\
    \n    #call the client of Gazebo\n    roslaunch drone_construct main.launch gui:=true\
    \ paused:=false\n\nAnd the **sjtu_drone** package has been modified to use a different\
    \ gazebo launch system to avoid problems localy. This is because the original\
    \ simulation uses gazebo binaries to launch everything and not **gazebo_ros**.\n\
    \nSo you just have to do the following and it should work:\n\n     mkdir -p ~/parrot_ws/src;cd\
    \ ~/parrot_ws/src\n     git clone https://RDaneelOlivaw@bitbucket.org/theconstructcore/parrot_ardrone.git;cd\
    \ parrot_ardrone;git checkout kinetic-gazebo7;~/parrot_ws/src\n     git clone\
    \ https://RDaneelOlivaw@bitbucket.org/theconstructcore/spawn_robot_tools.git\n\
    \     cd ~/parrot_ws\n    catkin_make;source devel/setup.bash;rospack profile\n\
    \    rosrun drone_construct start_simulation_localy.sh\n\nYou should then get\
    \ something like this:\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/gazebosim/15670850816992192.png)\n\
    \nYou can then make the drone take off and land publishing in these topics:\n\n\
    \     rostopic pub /drone/takeoff std_msgs/Empty \"{}\"\n     rostopic pub /drone/land\
    \ std_msgs/Empty \"{}\"\n\nAnd then move it around with this ros binary ( go up\
    \ , stop and down with T , G and B keys. The other keys are the standard keyboard\
    \ teleop use):\n\n     rosrun teleop_twist_keyboard teleop_twist_keyboard.py\n\
    \n\nHope this was usefull."
