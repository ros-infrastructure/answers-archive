    Sounds a valid, common confusion regarding ROS/Catkin software written in Python. Both Python and ROS/Catkin define "package", in the way I'd say essentially the same, at least from folder structure perspective.

    - See [Python packages (docs.python.org)](https://docs.python.org/3/tutorial/modules.html#packages) for Python package concept.
    - See [Catkin conceptual overview](http://wiki.ros.org/catkin/conceptual_overview) for `Catkin` package concept.

    The repo in question consits of 2 folders at the time of writing.
    - [motor_control_bus folder](https://github.com/TiderFang/motor_control_bus/tree/master/motor_control_bus) seems to be NOT a ROS/Catkin package. It's missing [minimal files that are required to be a Catkin package](http://wiki.ros.org/ROS/Tutorials/CreatingPackage#ROS.2FTutorials.2Fcatkin.2FCreatingPackage.What_makes_up_a_catkin_Package.3F).
    - [diff_car_controller](https://github.com/TiderFang/motor_control_bus/tree/master/diff_car_controller) seems to be a Catkin package (I haven't tried building/running it).

    What you can do to use `motor_control_bus folder` via ROS is to make it "catkinized" by adding the missing required files (so that the folder can be "built" by `Catkin`, then Python modules in the folder will be accessible via ROS tools, e.g. `rospack, rosrun, roslaunch`).
