  body_markdown: "> I should see the parameters defined in\n> that file listed when\
    \ I run ros2 param\n> list, correct?\n\nNot necessarily. ROS 2 parameters machinery\
    \ is slightly different from ROS 1 and in your case I guess that the main difference\
    \ that you have to be aware of is that parameters have to de 'declared'. See for\
    \ instance the [list_parameters.cpp](https://github.com/ros2/demos/blob/master/demo_nodes_cpp/src/parameters/list_parameters.cpp#L32)\
    \ demo, or e.g.\n\n    node->declare_parameter(\"foo\");\n\nWithout this bit,\
    \ the `foo` parameter from your yaml file **will not** be loaded and that's probably\
    \ your issue at the moment. It is still parsed, as you verified yourself, but\
    \ still not loaded as you'd expect.\n\nIf it happened that you can't know all\
    \ of the parameters beforehand, then you can pass a particular config when instantiating\
    \ your node so that it `allow_undeclared_parameters`. See an example at the [parameter_blackboard.cpp](https://github.com/ros2/demos/blob/master/demo_nodes_cpp/src/parameters/parameter_blackboard.cpp#L28)\
    \ demo.\n\nNotice that the same functionality exists in Python (rclpy) too.\n\n\
    > I'm also a little confused on the expected node name within the parameters file\
    \  \n> Does it need to match exactly the node name I provide\n\nYes, the node\
    \ name in the yaml file should match the name of your node, e.g. [\"parameter_blackboard\"\
    ](https://github.com/ros2/demos/blob/master/demo_nodes_cpp/src/parameters/parameter_blackboard.cpp#L25)\
    \ in the \n[parameter_blackboard.cpp](https://github.com/ros2/demos/blob/master/demo_nodes_cpp/src/parameters/parameter_blackboard.cpp)\
    \ demo."
