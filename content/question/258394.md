    I don't know anything about this code, but I think I've spotted the bug. The callback is getting `std_msgs.msg.String` objects (note the capital `S`), which are actually a ROS [std_msgs/String](http://docs.ros.org/api/std_msgs/html/msg/String.html) message that wraps a python string, but `splitlines` is only valid on python's built-in `string` type (note the lowercase `s`). You probably need to pass the `data` member from the incoming message into `filter_caffe_message`.
