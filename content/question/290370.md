  body_markdown: "`range` is the distance the sensor measures in metres. I hate to\
    \ state the obvious, but that is what the docs for the field also state: `range\
    \ data [m]`.\n\n> Distance from what?\n\nFrom the sensor's 'origin', wherever/however\
    \ that is defined by the manufacturer. \n\nIf the driver for your sensor has been\
    \ written properly, it should set that in the `header.frame_id` field. This is\
    \ the same for any other sensor msg that has a `Header`.\n\n> From the sensor's\
    \ origin to what?\n\nYou are serious, right?\n\nDistance to whatever distant point\
    \ the range sensor is measuring the distance to. So for a sonar that would mean\
    \ half the distance between the sonar emitter, the reflecting surface and the\
    \ sonar detector. Refer to [wikibooks/Robotics/Sensors/Ranging Sensors](https://en.wikibooks.org/wiki/Robotics/Sensors/Ranging_Sensors)\
    \ for some examples or ranging sensors.\n\n> Yes, I am serious. I am getting weird\
    \ values. All the range values of the sensors, if they are not detecting anything,\
    \ should all be equal, but not in my case.\n\nWell I can't help you with that.\
    \ I also don't believe they should all necessarily be equal. There is always noise,\
    \ and especially with multiple sensors the possibility that they are detecting\
    \ each other (at least with sonars), reflections, etc, etc."
