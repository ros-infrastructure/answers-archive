  body_markdown: "Hi,\n\nIf you want to play PCAP data on ROS, see this page: \nhttps://dominoc925.blogspot.com/2019/05/displaying-velodyne-pcap-data-in-ros.html\n\
    \nFor an example with [RTAB-Map](https://introlab.github.io/rtabmap/) (>=0.20.7\
    \ built with [libpointmatcher](https://github.com/ethz-asl/libpointmatcher) support),\
    \ based on this [ouster example](http://official-rtab-map-forum.206.s1.nabble.com/Ouster-drive-under-the-rain-td6496.html),\
    \ you can try the following:\n\n1) Play a PCAP (I tried the 1.4 GB one): \n\n\
    \    roslaunch velodyne_pointcloud 32e_points.launch pcap:=$HOME/Downloads/velodyne/2016-05-28hdl32.pcap\
    \ read_once:=true rpm:=1200\n\n2) Add a `base_link` to make x-axis of the car\
    \ forward (lidar is looking right)\n\n    rosrun tf static_transform_publisher\
    \ 0 0 0 -1.570796327 0 0 base_link velodyne 100\n\n3) Start mapping:\n\n    roslaunch\
    \ rtabmap_ros rtabmap.launch    \\\n       use_sim_time:=false \\\n       depth:=false\
    \ \\\n       subscribe_scan_cloud:=true \\\n       frame_id:=base_link \\\n  \
    \     scan_cloud_topic:=/velodyne_points \\\n       scan_topic:=/disabled \\\n\
    \       scan_cloud_max_points:=34750  \\\n       scan_cloud_assembling:=true \\\
    \n       scan_cloud_assembling_time:=0.5 \\\n       scan_cloud_assembling_voxel_size:=0.5\
    \ \\\n       icp_odometry:=true \\\n       approx_sync:=false \\\n       args:=\"\
    -d  \\\n          --RGBD/CreateOccupancyGrid false \\\n          --RGBD/ProximityMaxGraphDepth\
    \ 0 \\\n          --RGBD/ProximityPathMaxNeighbors 5 \\\n          --RGBD/LocalRadius\
    \ 30 \\\n          --RGBD/ProximityMaxPaths 1 \\\n          --Rtabmap/DetectionRate\
    \ 0 \\\n          --Icp/PM true \\\n          --Icp/VoxelSize 0.5   \\\n     \
    \     --Icp/MaxTranslation 10   \\\n          --Icp/MaxCorrespondenceDistance\
    \ 1.5 \\\n          --Icp/PMOutlierRatio 0.7 \\\n          --Icp/Iterations 30\
    \ \\\n          --Icp/PointToPlane true \\\n          --Icp/PMMatcherKnn 3 \\\n\
    \          --Icp/PMMatcherEpsilon 1 \\\n          --Icp/PMMatcherIntensity true\
    \ \\\n          --Icp/Epsilon 0.0001 \\\n          --Icp/PointToPlaneK 10 \\\n\
    \          --Icp/PointToPlaneRadius 0 \\\n          --Icp/CorrespondenceRatio\
    \ 0.2 \\\n          --Icp/PointToPlaneGroundNormalsUp 0.8 \\\n          --Icp/PointToPlaneMinComplexity\
    \ 0.0\" \\\n       odom_args:=\"\\\n          --Odom/ScanKeyFrameThr 0.7 \\\n\
    \          --OdomF2M/ScanMaxSize 10000  \\\n          --OdomF2M/ScanSubtractRadius\
    \ 0.5   \\\n          --Icp/Iterations 10 \\\n          --Icp/CorrespondenceRatio\
    \ 0.01 \\\n          --Icp/MaxTranslation 2   \\\n          --Icp/PMOutlierRatio\
    \ 0.4 \\\n          --Icp/PointToPlane false\"\n\nHere are some results:\n![image\
    \ description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1606612774809087.jpg)\n\
    \nColored with intensity from LiDAR:\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/16066127897494943.jpg)\n\
    \nLiDAR Odometry-only (red lines are loop closures):\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/16066128024786581.jpg)\n\
    \nWith loop closure optimization:\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/16066128144335288.jpg)\n\
    \nTo distinguish the track and the grass, the velodyne's intensity channel can\
    \ give a good idea. We can see it more clearly in this video: https://youtu.be/hmtdcxV-0NU\n\
    \nThe parameters above are quite very for this dataset to close the loops without\
    \ a camera. Combining with a stereo camera could help to detect loop closures\
    \ more robustly.\n\n**EDIT**\n\nIntegrating a stereo camera is possible (assuming\
    \ it is already calibrated, synchronized between left and right cameras and provide\
    \ [common stereo topics](http://wiki.ros.org/rtabmap_ros/Tutorials/StereoHandHeldMapping)).\
    \ You could add to `rtabmap.launch` command above:\n\n    stereo:=true \\ \n \
    \   rgbd_sync:=true \\\n    approx_sync:=true \\\n    approx_rgbd_sync:=false\
    \ \\\n    left_image_topic:=/stereo_camera/left/image_rect \\\n    right_image_topic:=/stereo_camera/right/image_rect\
    \ \\\n    left_camera_info_topic:=/stereo_camera/left/camera_info \\\n    right_camera_info_topic:=/stereo_camera/right/camera_info\n\
    \nThis will synchronize stereo data with Lidar data. You may also do stereo visual\
    \ odometry instead of LiDAR odometry, I think it would be a little more robust\
    \ because of the lack of geometry in this kind of environment. To use stereo odometry,\
    \ remove `icp_odometry:=true` above and set back `--Rtabmap/DetectionRate 2`.\
    \ As I did for Lidar, there could be some tunings for visual parameters depending\
    \ on the resolution of the cameras and this kind of environment. If you want to\
    \ use external odometry from another visual odometry package, add:\n\n    visual_odometry:=false\
    \ \\\n    odom_topic:=/my_visual_odometry_topic"
