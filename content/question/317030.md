    \nAs of right now (ie: 2019-02-28) my answer/assumption would be: no, not on a\
    \ system that installs ROS from the `.deb` packages provided by the OSRF buildfarm.\
    \ `roscpp` has not seen a Melodic release since 2018-08-06, which is two days\
    \ (2018-08-08) before [ros/ros_comm#1425](https://github.com/ros/ros_comm/pull/1425)\
    \ was merged.\n\nThe changelog for Melodic can be found here: [ros/ros_comm/clients/roscpp/CHANGELOG.rst](https://github.com/ros/ros_comm/blob/melodic-devel/clients/roscpp/CHANGELOG.rst)\
    \ (note: this is not a permalink, on purpose). You can find the latest release\
    \ in there, at the top of the list.\n\nThe commit date of the merge of [ros/ros_comm#1425](https://github.com/ros/ros_comm/pull/1425)\
    \ can be seen at the bottom of the GH page for that PR, or on [ros/ros_comm@678ad4f2](https://github.com/ros/ros_comm/commit/678ad4f239926111c7684c20f39ed91644aa1c13)\
    \ or from the commit itself (`git show --no-patch --no-notes --pretty='%cd' 678ad4f2399`).\n\
    \n> *The general question is:*\n\n> How can I relate the version of a given Ubuntu\
    \ ROS package to the changes I can see in the ROS package git repo?\n\nIt's most\
    \ likely easiest to read the changelog of a package (note that those are also\
    \ accessible from the wiki: [here](http://docs.ros.org/melodic/changelogs/roscpp/changelog.html)\
    \ for `roscpp` in Melodic fi and in `/usr/share/doc/ros-kinetic-roscpp` on Ubuntu/Debian\
    \ systems). As above (in the answer to your specific question), lookup the PR\
    \ number or description for the change and match it with the version section headings.\n\
    \nIf the package is hosted as a `git` repository (and `ros_comm` is) then an alternative\
    \ could be to use `git` itself. The version nrs of ROS pkgs on your machine are\
    \ derived from the git tags that were created as part of the release process.\n\
    \nA crude way to find the tag that \"contains\" a specific commit would be (where\
    \ `$HASH` is the commit hash of the change you're looking for):\n\n    git tag\
    \ --contains $HASH\n\nFor `ros/ros_comm#1425` that doesn't return anything (as\
    \ there hasn't been a release with that yet), but just as an example (I chose\
    \ a random other PR that *was* included in a Melodic release):\n\n    git tag\
    \ --contains ea850205e87\n\nreturns:\n\n    1.14.0\n    1.14.1\n    1.14.2\n \
    \   1.14.3\n\nwhich tells us that the merge commit for [ros/ros_comm#1393](https://github.com/ros/ros_comm/pull/1393)\
    \ is included in 4 releases and appeared first in `1.14.0`.\n\nThe same information\
    \ can be gleaned from the GH page for that commit ([ros/ros_comm@ea850205](https://github.com/ros/ros_comm/commit/ea850205e87ff0d56a6eeec95d119a8a7399ee11)):\n\
    \n![github page for ea850205 showing tags 'containing' it](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15513626296583241.png)"
