    \nA bit more generic answer:\n\nThe error `Could not find parameter robot_description_semantic\
    \ and ...`  can happen (not limited to the referenced tutorial). I keep getting\
    \ it.\n\nPotential root causes: A MoveGroup node is unable to \"get (ROS) parameter\"\
    \ `robot_description*` somehow.\n\nRecommended steps to narrow down a root cause\
    \ and solve: \n\n**Step-1**. Identify which node the error is happening in. In\
    \ terminal output you should see the node name along with the error. In the following\
    \ example, I can see `robot-laputa` node:\n\nEg.\n\n    [robot-laputa-24] [ERROR]\
    \ [1685818539.857625507] [robot-laputa]: Could not find parameter robot_description_semantic\

    \ SRDF XML File. Error=XML_ERROR_EMPTY_DOCUMENT ErrorID=15 (0xf) Line number=0\n\
    \    [robot-laputa-24]          at line 694 in /tmp/binarydeb/ros-galactic-srdfdom-2.0.3/src/model.cpp\n\
    \    [robot-laputa-24] [ERROR] [1685818539.863908388] [moveit_rdf_loader.rdf_loader]:\
    \ Unable to parse SRDF                                      \n    [robot-laputa-24]\
    \ [FATAL] [1685818539.864152922] [move_group_interface]: Unable to construct robot\
    \ model. Please make sure all needed information is on the parameter server.\n\
    \    [robot-laputa-24] terminate called after throwing an instance of 'std::runtime_error'\n\
    \    [robot-laputa-24]   what():  Unable to construct robot model. Please make\
    \ sure all needed information is on the parameter server.\n\n**Step-2**. Try 'get\
    \ parameter' by yourself before the error occurs, if you could, to see what parameters\
    \ are set or not. In my case when this error is happening, `ros2 param get` tends\
    \ to fail with another errors though.\n\n**Step-3**. Fix where params set e.g.\
    \ `.launch.py` if any. You may have something like the following.:\n\nE.g.\n\n\
    \    _node_motion = Node(\n        package=\"foo\", executable=\"node_exec\",\
    \ arguments=[],\n        name=\"node_exec_name\",\n        parameters=[\n    \
    \        robot_description,\n            robot_description_semantic,\n       \
    \     robot_description_kinematics,\n        ],        \n    )\n\nMake sure the\
    \ specific parameter that is causing an error is generated as expected. Also make\
    \ sure parameter names are correct (one of my error modes was I was passing a\
    \ wrong key name, e.g. In the following, key \"robot_desc\" is not what Moveit\
    \ is looking for, but this as a ROS parameter is totally valid so setting it doesn't\
    \ cause any error. Moveit returns the error because there's simply no parameter\
    \ with a key \"robot_description\")..\n\n    robot_description = {\"robot_desc\"\
    : robot_description_config.toxml()}\n\nBtw for how those parameters are generated,\
    \ as a ROS2 learner I've been seeing 2 ways to generate these params in `.launch.py`.\
    \ I'm listing them up here since I haven't seen anywhere where these are summarized.\n\
