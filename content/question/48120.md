  body_markdown: "Hey,\n\nI couldn't get this working either. I looked through the\
    \ source and it seems that there is a bug in the graspitGUI.cpp code for loading\
    \ plugins on the command line. The problem is here starting at **line 155 in graspitGUI.cpp**:\n\
    \n    //look for plugins of the form plugin:name in the arguments\n    for (int\
    \ i=1; i<argc; i++) {\n    QString arg(argv[i]);\n    if (arg.section(',',0,0)==\"\
    plugin\") {\n      QString libName = arg.section(',',1,1);\n\t  std::cout << \"\
    Processing arguments \\n \";\n      PluginCreator* creator = PluginCreator::loadFromLibrary(libName.toStdString());\t\
    \  \n      if (creator) {\n        mPluginCreators.push_back(creator);\n     \
    \ } else {\n        DBGA(\"Failed to load plugin: \" << libName.latin1());\n \
    \     }\n    }\n  \nThis shows that \"**if (arg.section(',',0,0)==\"plugin\")**\"\
    \ and \"**QString libName = arg.section(',',1,1);**\" are actually looking for\
    \ an argument of the form \"**plugin,name**\" versus \"plugin:name\"\n\nSo, just\
    \ change your argument to \"**plugin,name**\" to get it to run for now I guess...\
    \ Or, recompile with the commas replaced with colons.\n\n-Michael"
