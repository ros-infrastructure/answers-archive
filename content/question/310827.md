  body_markdown: "The [Motion Planning API tutorial](http://docs.ros.org/api/moveit_tutorials/html/doc/motion_planning_api/motion_planning_api_tutorial.html)\
    \ does not answer this, because it stops at visualizing the trajectory.\n\nAs\
    \ commented in [this question](https://answers.ros.org/question/305963/followjointtrajectoryaction-feasibility-checking/),\
    \ you can still use the move_group's `execute` function with your own plan, for\
    \ example like this:\n\n    // [(continued from the tutorial)...]  \n    context->solve(res);\
    \ \n    moveit_msgs::MotionPlanResponse response; \n    res.getMessage(response);\
    \ \n    \n    // Construct a move_group plan from the planned trajectory\n   \
    \ moveit::planning_interface::MoveGroupInterface::Plan myplan;\n    myplan.trajectory_\
    \ = response.trajectory; \n    group.execute(myplan);\n\nOtherwise, my understanding\
    \ is that you can use the interface of your robot/motors, most commonly a `JointTrajectoryController`\
    \ advertising a `FollowJointTrajectoryAction` that you send your trajectory to. "

when we use movegroup interface we can execute a plan using

    move_group.move();

and in python movegroup intertace we use:

    group = moveit_commander.MoveGroupCommander(group_name)
    plan = group.go(wait=True)
    group.execute(plan, wait=True).

how about when we use motion planning interface?
