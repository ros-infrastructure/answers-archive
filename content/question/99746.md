  body_markdown: "hi, dannyknoll. I didn't solve the problem yet.\n\nbut, I know why\
    \ the service call of win_ros is too slow.\n\nit is why the persistent option\
    \ of winros service client is not set.\n\nlet's see the case of above example\
    \ what i wrote (HelloDude example), \n\nyou can see the follow sentence(code).\
    \ \n\n**ros::ServiceClient client = n.serviceClient<custom_msgs::HelloDude>(\"\
    dude_service\");**\n\nthe root form of the ros::NodeHandle::serviceClient is that\
    \ the bellow sentence.\n\n**NodeHandle::serviceClient (const std::string &service_name,\
    \ bool persistent=false, const M_string &header_values=M_string())**\n\nthe second\
    \ parameter is the persistent option and the default value is \"false\".\n\nif\
    \ the persistent option is set false, the service client alwase try to re-connect\
    \ to the server when the request function is called. \n\notherwise, the persistent\
    \ option is set \"true\", the connection doesn't try to reconnect to the server,\
    \ \n\nbut if any problem of network would be occurred, the connection would be\
    \ broken(it is exception of program and cause of error).\n\nif you want to know\
    \ more details, you can refer to the document bellow.\nhttp://docs.ros.org/api/roscpp/html/classros_1_1NodeHandle.html\n\
    \nas a result, if you want to grow up the speed of service client, you should\
    \ set the persistent parameter to \"true\" of the NodeHandle::serviceCleint()\
    \ function, \nbut you should overcome the network problem yourself.\n**ros::ServiceClient\
    \ client = n.serviceClient<custom_msgs::HelloDude>(\"dude_service\", true);**\n\
    \nIn my case, I set the persistent parameter set \"true\", \nand catch the network\
    \ exceptions using the try{}catch{} code block.\n\n\nI want the information what\
    \ I wrote above to help you.\ngood luck.."
