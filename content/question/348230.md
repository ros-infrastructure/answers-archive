  body_markdown: "My understanding is that \"stack and packages\" are ROS packages\
    \ that are on your ROS_PACKAGE_PATH.\nBy default RPP just points to your ROS installation\
    \ so you'd expect to already have all the dependencies of those packages installed.\n\
    So if there is no package.xml on your RPP with the name you request, commands\
    \ like `rosdep install` will return \"resource missing\"\n\nBy opposition \"rosdeps\"\
    \ are things that are in your rosdep cache, they can be rosdep keys for system\
    \ dependencies or ROS package names that are released in a given rosdistro.\n\n\
    \n## When to use `rosdep install <package_name>` ?\n\nDisclaimer: It's unclear\
    \ to me what the correct ROS2 way of using it is as ROS2 it's not supposed to\
    \ rely on RPP but AMENT_PREFIX_PATH instead (https://github.com/ros-infrastructure/rosdep/issues/724)\n\
    \n`rosdep install <package_name>` comes in handy when you have an entire workspace\
    \ of cloned repositories but you only want to install the dependencies of some\
    \ packages.\n\nSo if you have a workspace with let's say the `rviz2` and the `navigation2`\
    \ repositories but want to install only the dependencies of the package named\
    \ `rviz2`, you'll\n- add your ws directory to the RPP\n\n    export ROS_PACKAGE_PATH=/my/ws:$ROS_PACKAGE_PATH\n\
    - install rviz2 dependencies\n\n    rosdep install rviz2 \nThis will install the\
    \ dependencies of the package names rviz2 but not the others.\n\nIf you run the\
    \ same command but adding `--from-paths /my/ws` it will install all the deps of\
    \ the workspace\n\nEdit: there are likely other use cases for it but that's the\
    \ only case I ever had to use `rosdep install` without --from-paths\n\nEdit 2:\
    \ an alternative I use often for ROS 2 when I have the full `ros2.repos` cloned\
    \ but want to install only the dependencies I need for my build is to ask colcon\
    \ to give me the list of paths. E.g. the following command allows me to install\
    \ all the dependencies to build rviz2 and it's' dependencies\n\n    rosdep install\
    \ -y --from-paths `colcon list --packages-up-to rviz2 -p` --ignore-src\n    colcon\
    \ build --packages-up-to rviz2"

    \n``from-paths`` is going to let you install all the dependencies in the path\
    \ defined. So if `/src/` then it'll recursively look at the package's `package.xml`\
    \ files, look up the keys, and install them such that you can then build whatever\
    \ package in your `/src/` directory. \n\nIf you do something like `rosdep install\
    \ --from-paths rviz2`, what you're asking is: Can you please install all the dependencies\
    \ in the directory rviz2 relative to run dir? To my understanding, just ask `rosdep\
    \ install <pkg>`, requires that `<pkg>` is in your `ROS_PACKAGE_PATH`, which won't\
    \ be the case if you haven't built it before.  \n\nThe `ignore-src` is to make\
    \ it so you don't install binaries of packages you've built yourself. `r` and\
