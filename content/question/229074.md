    ```octomap_server``` is a standalone node belonging to [octomap_ros](https://github.com/OctoMap/octomap_ros) that is completely independent of moveit. The octomap library is used inside moveit (or more precise, the ```move_group``` node) for representing environment geometry, but that does not mean that loading a octomap into ```octomap_server``` automatically makes it known to moveit.

    One option to feed the octomap to moveit is using the planning scene ROS API described in [this tutorial](http://docs.ros.org/indigo/api/pr2_moveit_tutorials/html/planning/src/doc/planning_scene_ros_api_tutorial.html). Using that you can send new octomap collision geometry to moveit as part of the [moveit_msgs/PlanningSceneWorld](http://docs.ros.org/jade/api/moveit_msgs/html/msg/PlanningSceneWorld.html) message inside the [moveit_msgs/PlanningScene](http://docs.ros.org/jade/api/moveit_msgs/html/msg/PlanningScene.html) message.

    Another (perhaps easier) option is to update the internal moveit octomap directly using your sensors, see [moveit 3D Perception/Configuration](http://docs.ros.org/indigo/api/pr2_moveit_tutorials/html/planning/src/doc/perception_configuration.html).
