  body_markdown: "That is a relatively complex problem, involving differential equations\
    \ plus feedback control.\n\nYou don't mention the initial speed of the robot.\
    \ Assuming it was stopped, the simplest solution is to send steadily increasing\
    \ velocity commands until a desired velocity is achieved, then send that constant\
    \ velocity until you reach a point from which the desired stopping point can be\
    \ reached using an appropriate constant deceleration. In other words, the velocity\
    \ commands trace out a trapezoid.\n\nFor stopping at a desired point, the dynamical\
    \ system is:\n\n    x_dot = -k * sqrt(x)\n\nSolving analytically with initial\
    \ condition x(0) = D and v(0) = V yields these equations of motion:\n\n     x(t)\
    \ = (sqrt(D) - V*t/(2*sqrt(D)))**2\t(parabolic drop)\n     v(t) = dx/dt = (V**2/2*D)*t\
    \ + V\t\t(linear velocity)\n     a(t) = dv/dt = V**2/(2*D) = A\t\t(constant deceleration)\n\
    \nNote that the initial velocity V is negative in these equations, because it\
    \ represents motion from positive x to zero.  The system stops in finite time\
    \ T = -2*D/V, with x(T) = 0, and v(T) = 0.\n\nFor example, when D = 10m from stop\
    \ line and V = -5m/s, the vehicle stops in 4 seconds at a constant 1.25m/s/s deceleration.\n\
    \nFor a more advanced implementation with smoother movement, instead of constant\
    \ accelerations limit the \"jerk\" (first derivative of acceleration, third derivative\
    \ of position) to some reasonable value. \n\nSince the robot will never exactly\
    \ achieve your commanded velocity (even in simulation), you will need some kind\
    \ of feedback controller to monitor progress and adjust your commands. The common\
    \ solution is a [PID controller](http://en.wikipedia.org/wiki/PID_controller),\
    \ using the velocity from the [odometry](http://ros.org/doc/api/nav_msgs/html/msg/Odometry.html)\
    \ (`twist.twist.linear.x`) for feedback."
