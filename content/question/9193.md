  body_markdown: "If you're following the tutorial then you'll be using:\n`roslaunch\
    \ vslam_system stereo_vslam.launch`\n\nIf you look at the `stereo_vslam.launch`\
    \ file, it has:\n\n    <node name=\"stereo_vslam_node\"...\n\nThis is launching\
    \ the binary compiled from the source  `vslam_system/src/nodes/stereo_vslam_node.cpp`.\
    \  If you check that file, you'll see that it *only* subscribes to these topics:\
    \ \n\n    // Synchronize inputs\n    l_image_sub_.subscribe(it_, \"left/image_rect\"\
    , 1);\n    l_info_sub_ .subscribe(nh_, \"left/camera_info\", 1);\n    r_image_sub_.subscribe(it_,\
    \ \"right/image_rect\", 1);\n    r_info_sub_ .subscribe(nh_, \"right/camera_info\"\
    , 1);\n    sync_.connectInput(l_image_sub_, l_info_sub_, r_image_sub_, r_info_sub_);\n\
    \nSo to answer your question, there's no tf inputs needed. You may be able to\
    \ get it to broadcast odometry data as tf's if you provide the `base_footprint`\
    \ transform. However that code (in the latest svn) is disabled with an `if (0)`."
