    > 1 . Does [rosbridge](http://wiki.ros.org/rosbridge_suite) come with user authentication and role-dependent access levels?

    No. `rosbridge_suite` only deals with providing the infrastructure to bridge into a ROS nodegraph, nothing more. It is not a web application itself nor is it exclusively used for that.

    > 2 . Can I limit what [rosbridge](http://wiki.ros.org/rosbridge_suite) exposes or is every ROS topic and service available for any (malicious) user?

    re: limit: yes, in a way: see the [rosapi/readme](https://github.com/RobotWebTools/rosbridge_suite/blob/2150e26c1a0d8ab662e383a09088d149e84b8357/rosapi/README.md). `rosapi` (the component responsible for interfacing with the ROS nodegraph) uses an 'opt-in' list of resources to expose.

    This is not linked to any user auth afaik though.

    > 3 . [ros_auth](http://wiki.ros.org/rosauth) seems to address some of this, but will it do the job?

    I've not used this myself, but it would seem `rosauth` provides a way to do authentication for `rosbridge_suite`. I could not find any documentation on the wiki, but [this comment](https://github.com/GT-RAIL/rosauth/issues/3#issuecomment-24206754) on the issue tracker is rather descriptive:

    > [..] rosbridge will wait for an [auth op code](https://github.com/RobotWebTools/rosbridge_suite/blob/2150e26c1a0d8ab662e383a09088d149e84b8357/ROSBRIDGE_PROTOCOL.md#33-authentication-message) to come in. If this is not the first message to come in, or if an invalid token is given, the connection is dropped.

    It does seem to have the concept of user *levels*, which does not necessarily translate to role, but is a start.

    The UI side of all this is out-of-scope of `rosbridge_suite` though, so that will probably have to be developed. The various `rosjs` and related libraries can probably help there.
