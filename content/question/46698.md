  body_markdown: "Self response. Not a `ROS` general guideline/rule/best practice\
    \ or anything but I found this could be a good example: \n\n[`rqt`'s API review](http://www.ros.org/wiki/rqt/Reviews/2012-06-20_API_Review)\
    \ says,\n\n    2. Question / concerns / comments\n    :\n    2\n    (Dirk) I would\
    \ propose to not integrate logging functionality into ROS GUI. All ROS plugins\
    \ can use the ROS-specific logging functionality provided by the client libraries.\
    \ A plugin similar to rxconsole can then be used to show/filter all these messages.\
    \ Non-ROS plugins can decide if they want to use logging library or stick with\
    \ the Qt functions qDebug, qWarning, qCritical. \n    :\n    3. Conclusion\n \
    \   :\n    ROS GUI does not provide logging funtionality but relies on either\
    \ the Qt or the ROS logging functions (following the KISS principle)\n\nSo at\
    \ least `rqt` doesn't restrict which logging system to use. \n\nMeanwhile in `qt_gui_core`,\
    \ `Qt`'s command `qDebug` is in use http://goo.gl/Oz5uU.\n\nDon't know if this\
    \ attitude holds for the entire `ROS` system though."
