  body_markdown: "> If I mistaken understanding of these comand-line tool\n\nI believe\
    \ so.\n\n`tf_echo` merely *prints* the value of the transform `<source-frame>\
    \ -> <target-frame>`. From its [wiki page](http://wiki.ros.org/tf#tf_echo):\n\n\
    > Print information about a particular transformation between a `source_frame`\
    \ and a `target_frame`.\n\nSo this doesn't alter the TF tree, just prints information\
    \ retrieved from it.\n\n`static_transform_publisher` actually *publishes* (ie:\
    \ broadcasts) a TF transform. Again, the [wiki page](http://wiki.ros.org/tf2_ros#static_transform_publisher):\n\
    \n> Publish a static coordinate transform to tf2\n\nThis adds new transforms to\
    \ the TF tree.\n\n---\n\nEdit:\n\n> So `tf_echo` is like subset of `static_transform_publisher`?\
    \ (output wise). \n\nNo, I would not say this is correct.\n\n`tf_echo` is for\
    \ humans. It displays information about the TF tree.\n\n`static_transform_publisher`\
    \ is for broadcasting a new TF frame and adds it to the TF tree.\n\nThose are\
    \ two fundamentally different operations.\n\n> in addition to transformation between\
    \ two frames, `static_transform_publisher` also creates a new node. ok got it.\
    \ \n\nIf with \"new node\" you mean \"it creates a ROS node (temporarily)\", then\
    \ yes, that would be correct, but only to be able to create a `tf2_ros::TransformBroadcaster`.\n\

    \ to the TF tree?\n\nThis would seem to come down to a basic understanding of\

    \ would help here. Adding new information to the TF tree is an essential operation\

1) `rosrun tf tf_echo <source-frame> <target-frame>`

2) `rosrun tf2_ros static_transform_publisher <X Y Z qX qY qZ qW> <source-frame> <target-frame>`

`tf_echo` gives a transformation between source and target link. While `static_transform_publisher` also gives a transform between two links.
