  body_markdown: "Here is a very simple example with the comments inline:\n\n    #include\
    \ <ros/spinner.h>\n    #include <ros/callback_queue.h>\n    \n    #include <std_msgs/Header.h>\n\
    \    #include <std_msgs/String.h>\n    \n    // callbacks to be added to internal\
    \ ROS queue\n    void headerCallback(const std_msgs::Header::ConstPtr& msg)\n\
    \    {\n      ROS_INFO(\"stamp.sec: %d\", msg->stamp.sec);\n    }\n    \n    //\
    \ callbacks to be added to user queue\n    void stringCallback(const std_msgs::String::ConstPtr&\
    \ msg)\n    {\n      ROS_INFO(\"string: %s\", msg->data.c_str());\n    }\n   \
    \ \n    int main(int argc, char** argv)\n    {\n      ros::init(argc, argv, \"\
    my_queues\");\n    \n      ros::NodeHandle n;\n      // nothing special for internal\
    \ ROS queue\n      ros::Subscriber sub1 = n.subscribe(\"/header_topic\", 10, headerCallback);\n\
    \    \n      // define user callback queue\n      ros::CallbackQueue string_queue;\n\
    \      // create options for subscriber and pass pointer to our custom queue\n\
    \      ros::SubscribeOptions ops =\n        ros::SubscribeOptions::create<std_msgs::String>(\n\
    \          \"/string_topic\", // topic name\n          10, // queue length\n \
    \         stringCallback, // callback\n          ros::VoidPtr(), // tracked object,\
    \ we don't need one thus NULL\n          &string_queue // pointer to callback\
    \ queue object\n        );\n      // subscribe\n      ros::Subscriber sub2 = n.subscribe(ops);\n\
    \    \n      // spawn async spinner with 1 thread, running on our custom queue\n\
    \      ros::AsyncSpinner async_spinner(1, &string_queue);\n      // start the\
    \ spinner\n      async_spinner.start();\n    \n      while (ros::ok())\n     \
    \ {\n        // process one message from ROS internal queue\n        ros::spinOnce();\n\
    \        ROS_INFO(\"Press Enter to process available messages from ROS internal\
    \ queue\");\n        // wait for user input\n        getchar();\n      }\n   \
    \ \n      return 0;\n    }\n\nEDIT: The custom queue is handled in parallel thread\
    \ without interruption and handles messages that arrive on `/string_topic`, while\
    \ internal queue is processed once user presses Enter in terminal. To check it,\
    \ just publish to these topics from terminal with `rostopic pub`. You will see,\
    \ that `/string_topic` outputs continuously, but `/header_topic` waits for user\
    \ input."

 Hello, I'm using a ROS node to read from several topics calling ros::spinOnce in a loop.

Every time I call spinOnce it checks **every** topic to which the node is subscribed, what I want instead is to check specific topics at different points in my code.
I've seen [here](http://wiki.ros.org/roscpp/Overview/Callbacks%20and%20Spinning) that I can achieve it using different callback queues, but when it comes to explain how to assign different callbacks to different queues the link refers to subscribers API and I got lost.
Can someone post an example of how to assign, let's say, Callback_1 to queue_1 and Callback_2 to queue_2?
