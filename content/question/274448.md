  body_markdown: |
    `pkill` is an OS utility that uses OS infrastructure to forcibly terminate the process that is your node. The node gets notified that this is going to happen via various [signals](https://en.wikipedia.org/wiki/Signal_(IPC)), which it can use to perform pre-shutdown operations. See also [pkill(1)](https://linux.die.net/man/1/pkill).

    `rosnode kill` will use the XML-RPC server in each node to send it (something akin to) a service request (`shutdown(..)`, see [ROS/Slave_API](http://wiki.ros.org/ROS/Slave_API)) that will set some client-lib internal variable(s) that eventually cause it exit any `while(ros::ok()) { .. }` or `ros::spin()` loops. The node may then perform any cleanup actions it has defined.

    > I'm just curious if there's a preferred way to kill a node or if it's all the same underneath.

    No, it's not the same, and I would say it is *probably* nicer to use `rosnode kill`, as the signals that `pkill` uses may not make it to the process hosting your node, but even if they do, they may not give your node (and the middleware infrastructure running in the same process) enough time to gracefully shut down.
  comments:
