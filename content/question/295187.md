  body_markdown: "The `CMAKE_BUILD_TYPE` variable is used to specify a build type.\
    \ Typically, the selected option (by default empty, but it can be `Release`, `Debug`,\
    \ or some others) is used to figure out what options to use/flags to set when\
    \ cmake actually calls the compiler.\n\nIn short, `Release` tells the compiler\
    \ to do optimization and omit debug information that `Debug` would tell it to\
    \ keep. I've seen some people recommend using `-DCMAKE_BUILD_TYPE=Release` for\
    \ better performance.\n\nCalling `catkin_make` (and not specifying a value for\
    \ `CMAKE_BUILD_TYPE`) results in something similar to using the `Debug` value.\n\
    \nSee:  \nhttps://codeyarns.com/2015/05/14/build-types-in-cmake/  \nhttps://cmake.org/cmake/help/v3.0/variable/CMAKE_BUILD_TYPE.html"

      +1 to use `Release` for better performance. It depends on the source how much the gain is but I had cases where a release build was running around 100 times faster than a debug build. So as a rule of thumb: Always use `Release` except when debug symbols are explicitly needed.
