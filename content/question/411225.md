  body_markdown: "Hi, I am at the moment struggling with the same problem, and eventually\
    \ I come down to this conclusion:  \n\n - If you want to be able to control the\
    \ velocity of the robot, you need to load a controller that accepts also joint\
    \ velocity commands (not only position).\n - With UR10e, the ScaledJointTrajectoryController\
    \ accepts both joint positions and velocities, which is good, but it cannot be\
    \ used for servoing (check this [issue](https://github.com/ros-planning/moveit2/issues/2136)\
    \ I posted. Otherwise you will experience jerkiness, which comes down to the same\
    \ problem of not being able to control the joint velocity.  \n - With that said,\
    \ position_controllers/JointGroupPositonController works well with moveit_servo\
    \ for position control, but position_controllers/JointGroupVelocityController\
    \ from my experience does not work for velocity control. Why exactly I am trying\
    \ to understand myself, but it might be that is because it not supported yet.\n\
    \nOn the side note, I also had problems with position_controllers/JointGroupPositonController\
    \ with moveit_servo (MoveIt version 2.2.3), when the robot joints would drift\
    \ even when not controlled. Then I updated my while environment to ROS2 Humble\
    \ distribution (ROS2, MoveIt and UR driver), and now it works well."

Hello.
I am trying to use Moveit_servo teleoperation and pose tracking with a UR10e robotic arm. The problem which I am trying to solve is that, when operating both teleoperation and pose tracking, the actual speed of the robotic arm is very much different from the Twist commands sent to it by either the teleoperation code or by the PID controller of the Moveit servo pose tracking algorithm. 

In the example shown below I have sent a velocity command of 0.5 m/s for the Z axis via a TwistStamped message to the moveit_servo node and after measuring the speed of the end effector on the Z axis the velocity was 0.22 m/s (around 1/(2.11) ratio between the required velocity and the actual velocity)

![image description](https://drive.google.com/file/d/1ePGhj9jQR0EyilJ0nqVrDTw7MRe2n9jQ/view?usp=share_link)

Also, when sending a velocity command of 0.25 m/s for the Z axis via a TwistStamped message to the moveit_servo node and after measuring the speed of the end effector on the Z axis the velocity was 0.118 m/s (around 1/(2.36) ratio between the required velocity and the actual velocity)

This problem also persists when conducting pose tracking via the example in the moveit_servo package (pose_tracking_example.launch.py).  And appears both in simulation in rviz and in the real world. 

I would love it if someone would be able to brainstorm some ideas regarding the origin of this problem and to give me some ideas regarding where i should check for a possible solution

System specs:

 - ROS version: foxy
 - Computer architecture: X86 (intel i7) 
 - Robotic arm: Universal-robots UR10e
