    > If it's simply that `rosdep` keys for `colcon`-related packages are missing, that's easy

    There are indeed [no rules for Colcon](https://github.com/ros/rosdistro/blob/36b9d77b343a5f751557d797fd3c2d212554d485/rosdep/python.yaml) currently.

    As to why you don't see `colcon` as a `buildtool_depend`: afaik, Ament is the replacement / successor to Catkin -- the CMake side to it, that is.

    Colcon is the successor to Catkin -- the build tool, that is.

    The two Catkins are related, but not identical.

    Compare how "Catkin packages" can be built using plain CMake (`mkdir build && cd build && cmake ..`), `catkin_make`, `catkin_make_isolated` and `catkin_tools` (and Colcon).

I'm still on ROS1K (about to EoL). Only occasionally trying newer stuff.

If I want to reference `colcon` as a dependency in `rosdep`-sphere, what's the right way to do assuming doing so is NOT out of the range of ROS2 and/or `colcon` framework?

A bit of motivation for me is to allow developers to specify build-tool/system and use `package.xml` for that so that you don't need to specify required/preferred build-tool/system separately (hope I'm interpreting the intent of [buildtool_depend](https://www.ros.org/reps/rep-0127.html#buildtool-depend-multiple) right).

Trying to find existing references,

- in `rclcpp` (that appeared at the top on `github.com/ros2` org at the time I went there, so I assumed it's up-to-date to the status of ROS2 framework) [it still? uses `ament` in buildtool_depend](https://github.com/ros2/rclcpp/blob/f5afe380d5f2af5b84b2e64ec54d9afe22ceda99/rclcpp/package.xml#L13). I couldn't find any pkg that refers to `colcon` in buildtool_depend.
- [docs.ros.org/en/foxy/Tutorials/Creating-Your-First-ROS2-Package](https://docs.ros.org/en/foxy/Tutorials/Creating-Your-First-ROS2-Package.html#customize-package-xml) shows `ament` for `buildtool_depend`.

So far I've tried:
- Add ros.org to apt source.
- Add `python3-colcon-common-extensions` (took it from [installation section in colcon.readthedocs.io](https://colcon.readthedocs.io/en/released/user/installation.html)) and a few others in `<buildtool_depend>`.

If it's simply that `rosdep` keys for `colcon`-related packages are missing, that's easy. But I'm just not sure if that's the plan.
