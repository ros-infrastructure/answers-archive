  body_markdown: "Using  rosbuild there is no install target.  I highly recommend\
    \ if you're building/packaging things to go into /opt/ros you build them in place.\
    \  That is effectively how we build the debian packages which we release.  (There's\
    \ some magic to work through chroots etc in the debbuild system). \n\nThis is\
    \ one of the primary features driving the development of the new build system,\
    \ catkin.  To see how the debian building happens see the [rosdeb package](https://code.ros.org/svn/ros/stacks/ros_release/trunk/rosdeb/)\
    \ single_deb.py is being used for rosbuild stacks in fuerte and groovy.  \n\n\
    It's invocation is like this: \n\n    #!/bin/bash -x\n    OS_PLATFORM=precise\n\
    \    ARCH=amd64\n    STACK_NAME=arm_navigation_experimental\n    PACKAGE_NAME=ros-groovy-arm-navigation-experimental\n\
    \    DISTRO_NAME=groovy\n    \n    echo $DISTRO_NAME\n    echo $STACK_NAME\n \
    \   echo $OS_PLATFORM\n    echo $ARCH\n    \n    sudo apt-get install pbuilder\
    \ git-core python-rospkg python-vcstools -y\n    \n    cat > $WORKSPACE/build.bash\
    \ << DELIM\n    source /opt/ros/cturtle/setup.sh\n    export ROS_PACKAGE_PATH=$WORKSPACE/ros_release:$WORKSPACE/release:$ROS_PACKAGE_PATH\n\
    \    \n    #noupload while testing\n    rosrun rosdeb single_deb.py $DISTRO_NAME\
    \ $STACK_NAME $OS_PLATFORM $ARCH\n    DELIM\n    \n    bash $WORKSPACE/build.bash\n\
    \nThere's lots of state setup on the build machine to support this.  There are\
    \ people who have replicated some or all of this, but it's definitely not designed\
    \ to be deployed externally and will not be a focus of development.  The new buildsystem\
    \ does have a goal of supporting external projects deploying the infrastructure\
    \ behind firewalls.  "
