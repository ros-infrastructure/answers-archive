  body_markdown: "Normally, when trying to build ROS packages from source (which includes\
    \ ROS 1 and ROS 2), you'd follow a certain workflow, one of the steps of which\
    \ would be the make sure all package dependencies are present.\n\nAn example workflow\
    \ is described in #q252478 (ignore the specific versions of Ubuntu and ROS: it's\
    \ a generic workflow).\n\nThe important step that takes care of dependencies is\
    \ the `rosdep` invocation.\n\nIt would appear however that `rmf_traffic` does\
    \ not state the dependency on `fcl` anywhere in its [package.xml](https://github.com/osrf/rmf_core/blob/197b74f4e0d4509ec52ed26e0e7ab34c13fae9c9/rmf_traffic/package.xml).\
    \ Without that information, `rosdep` would not be aware of the dependency and\
    \ cannot help you.\n\nIn this particular case, you'd have to investigate the `CMakeLists.txt`\
    \ of each package, identify the used packages/libraries (ie: see which `find_package(..)`\
    \ lines there are) and manually install the corresponding Ubuntu/Debian packages.\n\
    \nIn addition: it would be nice if you could report this on [the issue tracker](https://github.com/osrf/rmf_core/issues)\
    \ and it would be even nicer if, after you've identified all dependencies, you\
    \ could update the package manifests with this information and then submit a Pull\
    \ Request to `osrf/rmf_core` that would fix this for everyone.\n\nRefer to the\
    \ [catkin documentation \xBB How to do common tasks \xBB Package format 2 (recommended)\
    \ / Overview / Resolving dependencies](http://docs.ros.org/melodic/api/catkin/html/howto/format2/index.html#resolving-dependencies)\
    \ section in the Catkin documentation for information on which particular sections\
    \ would need to be added to the manifests.\n"
