    Communication to hardware using topics, services, or actions is not and will not be possibly off-the-shelf. If you really need them, you can initialize a node in your hardware interface implementation. But **this is not recommended**.

    Hardware interfaces now (end Feb 2022) implement lifecycle from lifecycle node interfaces. Those can be controlled externally from services of controller manager. For more details, check [this comment](https://github.com/ros-controls/ros2_control/issues/551#issuecomment-947174795).

    This means that you should implement those actions to be triggered by additional command interfaces or lifecycle methods.
    An example for using additional commanding interface can be seen in UR driver:

    - [description](https://github.com/UniversalRobots/Universal_Robots_ROS2_Description/blob/a8ac97b4cb6afa554af7f4928c934ce531f648f4/urdf/ur.ros2_control.xacro#L167-L296)
    - [implementation in driver](https://github.com/UniversalRobots/Universal_Robots_ROS2_Driver/blob/781d7f86ef7b7643c45a7b4ffda05f3931a0d5d3/ur_robot_driver/src/hardware_interface.cpp#L152-L168)
    - [custom controller](https://github.com/UniversalRobots/Universal_Robots_ROS2_Driver/blob/781d7f86ef7b7643c45a7b4ffda05f3931a0d5d3/ur_controllers/src/gpio_controller.cpp#L76-L121)
