    Hello Jordan:

    As Nate has mentioned in the comments, you will need an xserver running to be able to render camera data. In order to have an xserver running with a headless setup and assuming that you are using an Nvidia card, you could use ([starting with 331.* driver series](https://devtalk.nvidia.com/default/topic/585014/how-to-configure-x-server-to-work-headless-as-well-with-any-monitor-connected-/)):

    `nvidia-xconfig --allow-empty-initial-configuration`

    This should generate the following configuration in your Xorg.conf file:

        Section "Screen"
            Identifier     "Screen0"
            Device         "Device0"
            Monitor        "Monitor0"
            ...
            Option         "AllowEmptyInitialConfiguration" "True"
            ...
        EndSection

    Hope it helps. Thanks for sharing the feedback in the ROSCon!

    \ our VMs aren't running NVidia drivers as a rule, I wanted to explore some other\
    \ options before attempting Jose's solution.  Based on Nate and Jose's comments,\
    \ I went digging into virtual xservers and found \n[this old comment](http://answers.gazebosim.org/question/2153/drcsim-cant-figure-out-how-to-run-gazebo-on-remote-machine-and-get-vision-input/?answer=2159#post-id-2159),\
    \ which led me to Xvfb.  With Xvfb, I was able to do the following:\n\n<pre><code>$\
    \ Xvfb :1 -screen 0 1600x1200x16  &\n$ export DISPLAY=:1.0\n$ roslaunch etc etc.launch\n\
    </code></pre>\n\n...which let me run the camera plugin headlessly on a VM with\
    \ no problems.  Here's a screen grab from the camera, taken remotely by connecting\
    \ RQT to the robot on the VM:\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/gazebosim/14779382884694106.png)\

Hello,

We are looking to run a camera sensor headless on a VM, however when we do so several of the camera's image topic (notably, `camera/image_raw`) are not published.  At ROSCon, I spoke briefly with Jose, who indicated that this could be done fairly painlessly, and is actually used for Gazebo's CI tests.  How would I go about enabling that capability?

To clarify, we already have a camera plugin that runs just fine on a display-enabled machine.  Our robot is defined in a URDF and launched using roslaunch.  However, note that the "headless" option exposed by `gazebo_ros_pkgs` doesn't actually work - see https://github.com/ros-simulation/gazebo_ros_pkgs/issues/491

I also don't see an explicit "headless" option list [in the Gazebo code](https://bitbucket.org/osrf/gazebo/src/192a57657ec0d4873f695a3dec026064aec0240e/gazebo/gazebo_main.cc?at=default&fileviewer=file-view-default#gazebo_main.cc-45:68).  The Gazebo devs did mention that such a mode was possible, I just can't figure out how.

(Running Gazebo 7 and ROS Indigo)
