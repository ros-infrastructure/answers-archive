  body_markdown: "I will answer about \"how wf_simulator localizes with gnss\".\n\n\
    In the `wf_simulator`, the GNSS info is used for the initialization as a code,\
    \ but in fact, it is used to move the vehicle position by GNSS in the simulation.\n\
    \nBy connecting the GNSS to the `wf_simulator`, the vehicle position is constantly\
    \ updated when the GNSS data is received. This will drive the simulator and some\
    \ topics that other Autoware modules need is published (e.g. `/current_pose`,\
    \ `current_velocity`, `vehicle_status`, and TF from map to base_link).\n\nThe\
    \ following is how to connect the GNSS data to the `wf_sinulator`.\n\n1. launch\
    \ the runtime manager.\n2. setup data (load pcd map, vector map, TF (world_to_map\
    \ and baselink_to_localizer). Please follow the [ROSBAG Demo document](https://github.com/Autoware-AI/autoware.ai/wiki/ROSBAG-Demo).\n\
    3. run the Rviz and select the autoware config file following the document.\n\
    3. run the rosbag including the gnss data (the `sample_moriyama_150324.bag` of\
    \ the ROSBAG demo includes `/nmea_sentence` topic)\n4. run the `nmea2tfpose` node\
    \ in the runtime manager. (with the `sample_moriyama_150324.bag`, you need click\
    \ the [app] button and select the `7` for the Plane number.) Then, the `nmea2tfpose`\
    \ node starts and publishes the `/gnss_pose` topic.\n5. run the `wf_simulator`\
    \ in the runtime manager with initialize source being `GNSS` (select on [app]\
    \ window). \n\nThen, you will see the lidar sensor data is visualized on the Rviz\
    \ (not as well localized as the NDT).\n\nIf you want to use the GNSS data with\
    \ only for the initialization, you need to stop publishing the `/gnss_pose` after\
    \ initialization is done (just kill the node by clicking the checkbox again).\
    \ \n\nI hope this would be helpful for you.\n\n"
