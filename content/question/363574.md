    \ <node> tag in your launch file?\n\nFor instance\n\n    <launch>\n      <node\
    \ name=\"usb_cam\" pkg=\"usb_cam\" type=\"usb_cam_node\" output=\"log\"/>\n  \
    \  </launch>\n\nFrom the documentation at http://wiki.ros.org/roslaunch/XML/node:\n\
    \n> `output=\"log|screen\"(optional)`  \n> If 'screen', stdout/stderr from the\n\
    > node will be sent to the screen. If\n> 'log', the stdout/stderr output will\n\
    > be sent to a log file in\n> $ROS_HOME/log, and stderr will\n> continue to be\
    \ sent to screen. The\n> default is 'log'."

  body_markdown: "More than two years later, I came into the same issue with the `usb_cam`\
    \ package. Below I propose two solutions, a general one, and a package-specific\
    \ one.\n\n##General solution to mute `rosrun` output\nA possible solution when\
    \ launching a node from the command line, is to redirect the output (find a brief\
    \ introduction to the topic and a useful cheat-sheet [here](https://www.redhat.com/sysadmin/linux-shell-redirection-pipelining))\
    \ of the node by using\n\n```\nrosrun package_name node_name 2>&- \n```\n\nWith\
    \ this, one can run the node and see the `[INFO]` messages, while muting the unwanted\
    \ warnings/errors.\n\n##Avoid `usb_cam_node` errors passing the right params at\
    \ launch\nInspecting the [`usb_cam-test.launch`](https://github.com/ros-drivers/usb_cam/blob/develop/launch/usb_cam-test.launch)\
    \ file, I have noticed the following parameters being passed to the `usb_cam_node`\
    \ at launch:\n\n    <node pkg=\"usb_cam\" name=\"usb_cam_node\" type=\"usb_cam_node\"\
    >\n            <param name=\"video_device\" value=\"/dev/video0\" />\n       \
    \     <param name=\"image_width\" value=\"640\" />\n            <param name=\"\
    image_height\" value=\"480\" />\n            <param name=\"pixel_format\" value=\"\
    yuyv\" />\n            <param name=\"color_format\" value=\"yuv422p\" />\n   \
    \         <param name=\"camera_frame_id\" value=\"usb_cam\" />\n            <param\
    \ name=\"io_method\" value=\"mmap\"/>\n     </node>\n\nIn my case, this set of\
    \ params solved the warning messages.\n\nAny explanation of the meaning of the\
    \ parameters (and possibly of those to be held accountable for the warnings) \
    \ is very welcome! I will do my best to update the answer with more insights if\
    \ I have the occasion to dig a little bit more into this topic.\n\n"
