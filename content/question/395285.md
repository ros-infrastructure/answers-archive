  body_markdown: "When running the command from an interactive terminal session in\
    \ the container, you are effectively running the session after the default entrypoint\
    \ script for the container's image has been executed, which transitively sources\
    \ the ROS environment for you (I'm assuming you are using the official library\
    \ images of ROS from the Docker Hub). By overriding the default entrypoint inherited\
    \ by the base image, you replace the entrypoint with your own, and thus you will\
    \ need to source the existing `/ros_entrypoint.sh` script at the beginning of\
    \ your own entrypoint, or source the equivalent ROS setup yourself.\n \nSee the\
    \ source Dockerfiles of the official library images of ROS for reference:\n\n\
    https://github.com/osrf/docker_images/blob/master/ros/noetic/ubuntu/focal/ros-core/Dockerfile#L38\
    \  \nhttps://github.com/osrf/docker_images/blob/master/ros/noetic/ubuntu/focal/ros-core/ros_entrypoint.sh"

I have a Docker image for my ROS environment which has been working fine. I can run catkin_make and do everything else I need to do. I wanted to do a bit of automation so wrote a very simple bash script that just runs the catkin_make command. I tried running the script inside the container, and it worked. So far, so good. Next I wanted to make the script the entry point for the image so running the container will just run the script. When I do so, I get "catkin_make: not found". Why would the script work perfectly when run from terminal inside container, but not when run as entrypoint to container?
