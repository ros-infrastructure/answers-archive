  body_markdown: "Sometimes it's a permission problem. Or a lib problem.\n\nHere the\
    \ same Streaming Exeption is given:\n\nhttp://www.softkinetic.com/support/Forum/aft/1702\n\
    \n\n\nI've solved it by checking this:\n\n(From the link)\n> I export the DepthSense\
    \ Library with\n> \"export\n> LD_LIBRARY_PATH=/opt/softkinetic/DepthSenseSDK/lib/\"\
    , with \"echo $LD_LIBRARY_PATH\" I get\n> this line:\n> \n> /opt/softkinetic/DepthSenseSDK/lib/.\n\
    > \n> All seem ok!\n\n\nThen you should look into your /opt/softkinetic/DepthSenseSDK/lib\
    \ folder\n\n\nMine looks like this:\n\n    libDepthSensePlugins.so@    libDepthSensePlugins.so.1.4.5\
    \  libDepthSense.so.1@     libturbojpeg.so  libusb-1.0.so.0\n    libDepthSensePlugins.so.1@\
    \  libDepthSense.so@              libDepthSense.so.1.4.5  libusb-1.0.so    libusb-1.0.so.0.1.0\n\
    \nThe \"libDepthSensePlugins.so\" file links to the \"ibDepthSensePlugins.so.1\"\
    , same thing with the libDepthSense files.\n\nI remember that i had to create\
    \ that one myself to fix an issue. Can't seem to find the documentation where\
    \ that solution is found. But credits go to him :-p\n\nTo create the links \n\n\
    \    ln -s /opt/softkinetic/DepthSenseSDK/lib/libDepthSensePlugins.so.1 /opt/softkinetic/DepthSenseSDK/lib/libDepthSensePlugins.so\n\
    \    ln -s /opt/softkinetic/DepthSenseSDK/lib/libDepthSense.so.1 /opt/softkinetic/DepthSenseSDK/lib/libDepthSense.so\n\
    \n\n\n"
