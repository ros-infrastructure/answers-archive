  body_markdown: "That package was originally written in 2007 for the DARPA Urban\
    \ Challenge competition [[Beeson et al., JoPhA, March 2008]](http://personal.traclabs.com/~pbeeson/publications/b2hd-Beeson-jopha-08.html).\
    \ A substantial subset of it was later ported to ROS without changing the basic\
    \ design. \n\nThe design is quite specific to the Urban Challenge rules and file\
    \ formats. I don't expect it would help much for an indoor robot. Most of the\
    \ navigation is for driving down road segments using GPS and a Road Network Definition\
    \ File (i.e. road map) defined by DARPA, while obeying California traffic laws.\
    \ \n\nWe would like `art_nav` to use more generic map interface than the `art_map`\
    \ package currently provides. Working with several other ROS development groups,\
    \ we are designing an experimental [Geographic Information API](http://www.ros.org/wiki/cartography/Reviews/2011-06-18_API_Review)\
    \ for satellite-based mapping and navigation. That does not apply to indoor robots,\
    \ either, but you are welcome to participate if your other interests intersect.\n\
    \nThe code works on our car, and could probably be ported to another with reasonable\
    \ effort. It depends on lower-level packages (`art_pilot`, `art_servo`) which\
    \ provide fairly generic car-like interfaces (brake, shifter, Ackermann steering,\
    \ throttle). Servo drivers for those devices would need to be written. \n\nI am\
    \ interested in working with you or other ROS developers on generic navigation\
    \ for 4-wheeled vehicles using Ackermann drive. While some of our existing code\
    \ might be useful and you are welcome to it, I expect a generic package to involve\
    \ substantial redesign.\n"
