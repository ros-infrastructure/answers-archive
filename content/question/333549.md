I am using meshes as my collision objects in moveit!, following this [tutorial](https://github.com/Danfoa/invite-robotics/wiki/Tutorial---Simulation-Scene-Objects). The meshes are displayed in a "smooth" or "vertex" mode in rviz. The smooth shading gives meshes an unrealistic gradient: [the scene from the tutorial](https://github.com/Danfoa/invite-robotics/wiki/Tutorial---Simulation-Scene-Objects#loading-of-the-default-simulation-scene), [bunny](https://i.ibb.co/L80Dv0m/smooth.png).

"Flat" and "appearance/textured" shading are available in rviz for moveit!: In PlanningScene, Scene Robot can be displayed in terms of Visual and Collision. "Show Robot Visual" displays .dae meshes with appearances, and "Show Robot Collision"


robot's visual mesh (in *.dae) can be displayed with customized appearance, and robot's collision mesh (in *.stl) can be displayed in "flat" shading:

- "Appearance/textured" shading: It seems that moveit! does not support appearance for **collision objects**. moveit! uses [moveit_msgs/CollisionObject](http://docs.ros.org/melodic/api/moveit_msgs/html/msg/CollisionObject.html) messages to store collision objects (primitives, meshes, etc), and moveit_msgs/CollisionObject uses [shape_msgs/Mesh](http://docs.ros.org/kinetic/api/shape_msgs/html/msg/Mesh.html) message to store meshes. shape_msgs/Mesh only stores triangles and vertices, so appearance/materials stored in a .dae file are discarded. I have converted a .stl mesh to COLLADA(.dae) format and added appearance, but moveit! parse it into a mesh with no appearance information, producing the same look as using a .stl mesh.

- "Flat" shading: I would like to know if it is possible to display the mesh with "flat" or "face" shading: [bunny with a flat shading](https://i.ibb.co/qCsGGdb/flat.png).

Can anyone shed light on this?
