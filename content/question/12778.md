  body_markdown: "The parameters you mention for odometry scale correction are probably\
    \ the least of your worries until you have a working base platform.  The `turtlebot_node`\
    \ package is heavily dependent on the `turtlebot_driver` package which is essentially\
    \ an iRobot Create/Roomba SCI/OI driver.  What you propose is to replace the iRobot\
    \ Create with essentially a custom base platform.  \n\nWhat you'll find is that\
    \ there's not much code to reuse from `turtlebot_node` outside of parts of the\
    \ \"compute_odom\" method and possibly a few others (maybe gyro.py if you're using\
    \ the same gyro?).  The code for interfacing with the analog and digital IOs will\
    \ have to change, as well as the code for bumpers, batteries and \"safe\"/\"passive\"\
    /\"full\" modes.  \n\nOf course once you have all the low-level drivers re-implemented\
    \ for whatever motor controller/encoder package you choose, nothing stops you\
    \ from outputting compatible messages like Odometry and BatteryState, etc that\
    \ would allow you to work with other sections of the turtlebot stack.  You can\
    \ even reuse-the calibration node since there's nothing particularly turtlebot-specific\
    \ about it--then you can incorporate those scaling parameters into your new driver\
    \ node.  Unfortunately, replacing the Create means rewriting the code to interface\
    \ with Twist and Odometry messages (most of `turtlebot_driver` and `turtlebot_node`).\n"
