  body_markdown: "The problem is, that you can't use the spin_node_until_future_complete()\
    \ command inside the outer callback. \nThe solution is to use an MultiThreadedExecutor\
    \ and different callback groups.\nThen you can call the inner service by giving\
    \ it a callback function (instead of waiting for the return code with spin_node_until_future_complete).\n\
    \nIf you want to wait for the result from the inner service call before the outer\
    \ service callback finishes you need to block the thread with a while(return_from_inner_service\
    \ == false) loop.\nThis is important if your outer callback is from a service,\
    \ because then you want to receive the inner service result and use it to compute\
    \ the result of the outer service.\nBut this is bad design, because you block\
    \ the spin() call from the outer service. \nLuckily we can still handle other\
    \ callbacks with the MultiThreadedExecutor as long as we assign them to a different\
    \ callback group.\nIf the outer callback is from a topic you don't want to block\
    \ the callback, just handle the inner service call inside the assigned callback\
    \ function. It will execute asynchronous.\n\nHere is some code example in C++\n\
    (assuming all necessary headers included and ROS services created)\n\nCreate the\
    \ MultiThreadedExecuter and an instance of the Node in main:\n\n    int main(int\
    \ argc, char *argv[])\n    {\n        rclcpp::init(argc, argv);\n        rclcpp::executors::MultiThreadedExecutor\
    \ executor;\n        auto node = std::make_shared<Communication>();\n        executor.add_node(node);\n\
    \        executor.spin();\n        rclcpp::shutdown();\n        return 0;\n  \
    \  }\n\nCreate seperate Callback group and assign it to the inner service client\
    \ (inside the Node/class constructor):\n\n    callback_group_input_ = this->create_callback_group(rclcpp::callback_group::CallbackGroupType::MutuallyExclusive);\n\
    \    get_input_client_ = this->create_client<petra_core::srv::GetInput>(\"GetInput\"\
    , rmw_qos_profile_services_default, callback_group_input_);\n\nInside the outer\
    \ callback from a topic or service, send the inner_request and define a callback\
    \ for it:\n\n    int choice = -1;\n        auto inner_client_callback = [&,this](rclcpp::Client<petra_core::srv::GetInput>::SharedFuture\
    \ inner_future)\n            { \n                auto result = inner_future.get();\n\
    \                choice = stoi(result->input);\n                RCLCPP_INFO(this->get_logger(),\
    \ \"[inner service] callback executed\");\n            };\n        auto inner_future_result\
    \ = get_input_client_->async_send_request(inner_request, inner_client_callback);\n\
    \nIf it is necessary to wait inside the outer callback for the result block the\
    \ thread:\n\n    // Wait for the result.\n        while (choice < 0 && rclcpp::ok())\n\
    \        {\n            std::this_thread::sleep_for(std::chrono::milliseconds(10));\n\
    \        }\n\nI hope it helps you, or whoever has the same problem. I was stuck\

  body_markdown: "I was stuck on this for whole day, so I'm adding my solution in\
    \ case anyone else runs into a similar problem. The previously mentioned solutions\
    \ are on the right track, but they are incomplete. There is an official solution\
    \ in [the ros docs](https://docs.ros.org/en/foxy/How-To-Guides/Using-callback-groups.html),\
    \ which I am pasting here just in case the link breaks.\n\nNote that this problem\
    \ is not unique to calling a service client from within a subscriber callback.\
    \ This problem occurs whenever you have to call a callback from within a callback.\
    \ Therefore the example of calling a service from within the timer callback is\
    \ effectively the same as calling a service from within a subscription callback,\
    \ or calling a service from within a service callback.\n\nThe solution is to put\
    \ your nested callbacks in different callback groups (see the link above) and\
    \ to use `std::future::wait_for()` instead of `rclcpp::spin_until_future_complete()`.\n\
    \n\n    #include <chrono>\n    #include <memory>\n    #include \"rclcpp/rclcpp.hpp\"\
    \n    #include \"std_srvs/srv/empty.hpp\"\n    \n    using namespace std::chrono_literals;\n\
    \    \n    namespace cb_group_demo\n    {\n    class DemoNode : public rclcpp::Node\n\
    \    {\n    public:\n        DemoNode() : Node(\"client_node\")\n        {\n \
    \           client_cb_group_ = this->create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive);\n\
    \            timer_cb_group_ = this->create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive);\n\
    \            client_ptr_ = this->create_client<std_srvs::srv::Empty>(\"test_service\"\
    , rmw_qos_profile_services_default,\n                                        \
    \                            client_cb_group_);\n            timer_ptr_ = this->create_wall_timer(1s,\
    \ std::bind(&DemoNode::timer_callback, this),\n                              \
    \                  timer_cb_group_);\n        }\n    \n    private:\n        rclcpp::CallbackGroup::SharedPtr\
    \ client_cb_group_;\n        rclcpp::CallbackGroup::SharedPtr timer_cb_group_;\n\
    \        rclcpp::Client<std_srvs::srv::Empty>::SharedPtr client_ptr_;\n      \
    \  rclcpp::TimerBase::SharedPtr timer_ptr_;\n    \n        void timer_callback()\n\
    \        {\n            RCLCPP_INFO(this->get_logger(), \"Sending request\");\n\
    \            auto request = std::make_shared<std_srvs::srv::Empty::Request>();\n\
    \            auto result_future = client_ptr_->async_send_request(request);\n\n\
    \            // Do this instead of rclcpp::spin_until_future_complete()\n    \
    \        std::future_status status = result_future.wait_for(10s);  // timeout\
    \ to guarantee a graceful finish\n            if (status == std::future_status::ready)\
    \ {\n                RCLCPP_INFO(this->get_logger(), \"Received response\");\n\
    \                std::shared_ptr<ServiceT::Response> response = result_future.get();\n\
    \                // Do something with response \n            }\n        }\n  \
    \  };  // class DemoNode\n    }   // namespace cb_group_demo\n    \n    int main(int\
    \ argc, char* argv[])\n    {\n        rclcpp::init(argc, argv);\n        auto\
    \ client_node = std::make_shared<cb_group_demo::DemoNode>();\n        rclcpp::executors::MultiThreadedExecutor\
    \ executor;\n        executor.add_node(client_node);\n    \n        RCLCPP_INFO(client_node->get_logger(),\
    \ \"Starting client node, shut down with CTRL-C\");\n        executor.spin();\n\
    \        RCLCPP_INFO(client_node->get_logger(), \"Keyboard interrupt, shutting\
    \ down.\\n\");\n    \n        rclcpp::shutdown();\n        return 0;\n    }"
