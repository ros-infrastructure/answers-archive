In the launch file this [line](https://github.com/ROBOTIS-GIT/turtlebot3_simulations/blob/627856619241833f0394861771f79a5008d69ea3/turtlebot3_gazebo/launch/turtlebot3_world.launch#L16) is loading the [Robot description](https://github.com/ROBOTIS-GIT/turtlebot3/tree/master/turtlebot3_description) in the ROS parameter server and [this one](https://github.com/ROBOTIS-GIT/turtlebot3_simulations/blob/627856619241833f0394861771f79a5008d69ea3/turtlebot3_gazebo/launch/turtlebot3_world.launch#L18) is lauching a script to spawn the robot in a Gazebo world.

    If you look at any of the Xacro files you will see that they are already loading a Diff drive [plugin](http://gazebosim.org/tutorials?tut=ros_gzplugins#DifferentialDrive) to control the robot base.This plugin is reading from the `/cmd_vel` topic to command twist msgs.

- body_markdown: |-
    Hi @mattewthep,

    Why you would want to do that?

    The plugin itself is already implementing the diff drive kinematics, thus when you publish a twist on the topic the plugin will apply the kinematic equations to split the command between the two robot wheels. If you want to have two control topics, one for each wheel you may need to implement your own controllers since in the `driff_drive_controller` the command is used for both wheels at the same time programatically.
