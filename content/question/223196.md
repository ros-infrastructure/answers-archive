    \ hacked.. \n\nSo basically to at least be able to use ros_control to control\
    \ 2 actuators (cant view it in rviz since its a closed linkage) you need 2 robot_description\
    \ parameters. ros_control loads from `robot_description` so you need to specify\
    \ the path to your URDF file (if you only have a SDF, you can reference my answer\
    \ [here](http://answers.ros.org/question/210501/about-urdf-and-sdf/#210545) about\
    \ converting from SDF to URDF). \nYou need to specify the URDF file so that you\
    \ can insert the <transmission> tags and associate which joints you want to use.\
    \ If you convert URDF -> SDF or vis versa, you will still have all the same joint\
    \ and link names, for example: \n\nIn my URDF file:\n\n      <joint\n        name=\"\
    left_mid_actuator_joint\"\n        type=\"prismatic\">\n        <origin\n    \
    \      xyz=\"-0.5588 -0.010351 0\"\n          rpy=\"0 0 -3.9443E-31\" />\n   \
    \     <parent\n          link=\"left_top_actuator_link\" />\n        <child\n\
    \          link=\"left_bot_actuator_link\" />\n        <axis\n          xyz=\"\
    -1 0 0\" />\n        <limit effort=\"100.0\" lower=\"0\" upper=\"1.4\" velocity=\"\
    0.2\"/>\n      </joint>\n\n    <transmission name=\"tran1\">\n      <type>transmission_interface/SimpleTransmission</type>\n\
    \      <joint name=\"left_mid_actuator_joint\">\n        <hardwareInterface>EffortJointInterface</hardwareInterface>\n\
    \      </joint>\n      <actuator name=\"motor1\">\n        <hardwareInterface>EffortJointInterface</hardwareInterface>\n\
    \        <mechanicalReduction>1</mechanicalReduction>\n      </actuator>\n   \
    \ </transmission>\n\nand then you can see in my SDF file that i will have the\
    \ same joint name `left_mid_actuator_joint`\n\n\n    <joint name='left_mid_actuator_joint'\
    \ type='prismatic'>\n      <child>left_bot_actuator_link</child>\n      <parent>left_top_actuator_link</parent>\n\
    \      <axis>\n        <xyz>-0.685505 -4.48206e-15 -0.728068</xyz>\n        <limit>\n\
    \          <lower>0</lower>\n          <upper>1.4</upper>\n          <effort>100</effort>\n\
    \          <velocity>0.2</velocity>\n        </limit>\n        <dynamics/>\n \
    \     </axis>\n    </joint>\n\nYou then want to load **both** the SDF to spawn\
    \ the model in gazebo (this actually eventually gets converted into URDF anyway)\
    \ and the URDF so that `ros_control` can find the `<transmission>` tags. Make\
    \ sure the URDF is loaded into `robot_description` and the SDF is loaded into\
    \ some other parameter which you then pass as an arguement to `spawn_model`\n\n\
    \    <param name=\"robot_description\" textfile=\"$(find rmc_simulation)/surus_sim/robots/surus_sim.URDF\"\
    \ />\n    <param name=\"robot_description_sdf\" textfile=\"$(find rmc_simulation)/surus_sim/robots/surus_sim.sdf\"\
    \ />\n\n    <node\n      name=\"spawn_model\"\n      pkg=\"gazebo_ros\"\n    \
    \  type=\"spawn_model\"\n      args=\"-sdf -param robot_description_sdf -model\
    \ surus_sim -x 0 -y 0.6 -z 0.3\"\n      output=\"screen\">\n    </node>\n\n  \
    \  <rosparam file=\"$(find rmc_simulation)/gazebo_config/control/surus_control.yaml\"\
    \ command=\"load\"/>\n\n\t<node name=\"controller_spawner\" \n\t\tpkg=\"controller_manager\"\
    \ \n\t\ttype=\"spawner\" respawn=\"false\" output=\"screen\"\n\t\targs=\"joint1_position_controller\
    \ joint2_position_controller joint_state_controller\"/>\n\nWhere my yaml is:\n\
    \n      # Publish all joint states -----------------------------------\n     \
    \ joint_state_controller:\n        type: joint_state_controller/JointStateController\n\
    \        publish_rate: 50  \n    \n      # Position Controllers ---------------------------------------\n\
    \      joint1_position_controller:\n        type: effort_controllers/JointPositionController\n\
    \        joint: right_mid_actuator_joint\n        pid: {p: 100.0, i: 0.01, d:\
    \ 10.0}\n      joint2_position_controller:\n        type: effort_controllers/JointPositionController\n\
    \        joint: left_mid_actuator_joint\n        pid: {p: 100.0, i: 0.01, d: 10.0}\n\
    \nLike i said, this is NOT the proper way of doing this. If someone could still\
    \ post an answer as to how to directly include ros_control into a sdf, that would\
    \ be splendid. "
