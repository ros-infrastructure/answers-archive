  body_markdown: "> Can I just use socketcan_bridge and socketcan_interface ROS packages,\
    \ basically the CAN layer, to communicate with motor controllers using ROS?\n\n\
    While it is possible to use raw CAN messaging via `socketcan_bridge`, I would\
    \ not recommend it.\nROS messaging is not deterministic and this might result\
    \ in timing-related problem during control.\n\nAs an alternative you could implement\
    \ your own control (ROS) node, which uses `socketcan_interface` for low-level\
    \ communication.\n\n> Or do I have to use a CAN protocol like CANopen? \n\nYou\
    \ don't have to used CANopen, but it is widely adopted.\n`canopen_master` offers\
    \ C++ classes for building your own CANopen master node.\n\n`canopen_chain_node`\
    \ even offers a ROS-based implementation for interfacing with CANopen nodes that\
    \ is meant to be subclassed to support higher-level profiles (like `canopen_402`).\n\
    \n> In the case that the motor controller I'm planning to use uses a different\
    \ CAN protocol, like SAE J1939, or different CANopen profile than 402 which is\
    \ the one that ros_canopen package implements.\n\n`canopen_motor_node` uses `canopen_402`\
    \ by default, but you create your own CANopen-based motor plugin ([`canopen::MotorBase`](https://github.com/ros-industrial/ros_canopen/blob/melodic-devel/canopen_402/include/canopen_402/base.h))\n\
    \nHowever, for SAE J1939 (not CANopen-based) you would need to write your custom\
    \ implementation.\n\n\n\n"
