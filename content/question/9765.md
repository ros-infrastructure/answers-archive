  body_markdown: "`cv::Mat` by itself does not contain all of the information that\
    \ `sensor_msgs::Image` does, namely the encoding (e.g. bgr8 vs rgb8) and the header\
    \ (time stamp and tf frame). So you create a `cv_bridge::CvImage` object to convert:\n\
    \n    #include <cv_bridge/cv_bridge.h>\n    #include <sensor_msgs/image_encodings.h>\n\
    \n    cv_bridge::CvImage out_msg;\n    out_msg.header   = in_msg->header; // Same\
    \ timestamp and tf frame as input image\n    out_msg.encoding = sensor_msgs::image_encodings::TYPE_32FC1;\
    \ // Or whatever\n    out_msg.image    = sal_float_image; // Your cv::Mat\n  \
    \  \n    saliency_img_pub.publish(out_msg.toImageMsg());\n\nIt's a little verbose;\
    \ in the future we could add constructors to `CvImage` to streamline this. Note\
    \ that forgetting to set the header fields is a common bug when using the old\
    \ `CvBridge`."

I was wondering about how to publish cv:Mat. The tutorial wiki
http://www.ros.org/wiki/cv_bridge/Tutorials/UsingCvBridgeToConvertBetweenROSImagesAndOpenCVImages
didn't give me an answer and following code seems working, but I suppose there are a way to do this
without using old CvBridge interface.

            IplImage out_msg = sal_float_image;
            sensor_msgs::CvBridge bridge_;
            sensor_msgs::Image::Ptr saliency_msg = bridge_.cvToImgMsg(&out_msg, "passthrough");

            saliency_img_pub.publish(saliency_msg);
