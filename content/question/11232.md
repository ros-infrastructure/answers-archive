  body_markdown: "One quick way to do this would be to use the [laser_geometry](http://www.ros.org/wiki/laser_geometry)\
    \ node. It provides functionality for converting laser scans directly into PointCloud\
    \ or PointCloud2 messages in the frame of your choice. That's what I use, and\
    \ it's quite simple to do. I hope this helps. \n\n**EDIT:** To use this functionality,\
    \ you could do something like this:\n\nIn the class definition:\n    \n    #include\
    \ <ros/ros.h>\n    #include <tf/transform_listener.h>\n    #include <laser_geometry/laser_geometry.h>\n\
    \n    class My_Filter {\n         public:\n            My_Filter();\n        \
    \    void scanCallback(const sensor_msgs::LaserScan::ConstPtr& scan);\n      \
    \   private:\n            ros::NodeHandle node_;\n            laser_geometry::LaserProjection\
    \ projector_;\n            tf::TransformListener tfListener_;\n\n            ros::Publisher\
    \ point_cloud_publisher_;\n            ros::Subscriber scan_sub_;\n    };\n\n\
    \    My_Filter::My_Filter(){\n            scan_sub_ = node_.subscribe<sensor_msgs::LaserScan>\
    \ (\"/scan\", 100, &My_Filter::scanCallback, this);\n            point_cloud_publisher_\
    \ = node_.advertise<sensor_msgs::PointCloud2> (\"/cloud\", 100, false);\n    \
    \        tfListener_.setExtrapolationLimit(ros::Duration(0.1));\n    }\n\nIn the\
    \ callback function:\n\n    void My_Filter::scanCallback(const sensor_msgs::LaserScan::ConstPtr&\
    \ scan){\n        sensor_msgs::PointCloud2 cloud;\n        projector_.transformLaserScanToPointCloud(\"\
    base_link\", *scan, cloud, tfListener_);\n        point_cloud_publisher_.publish(cloud);\n\
    \    }\n\nAnd the main:\n\n    int main(int argc, char** argv)\n    {\n      \
    \  ros::init(argc, argv, \"my_filter\");\n\n        My_Filter filter;\n\n    \
    \    ros::spin();\n\n        return 0;\n    }\n\nWhere \"base_link\" is the frame\
    \ that you'd like to see all the scans in, *scan is the reference to the incoming\
    \ laser scan, cloud is the sensor_msgs::PointCloud2 that you'd like to be your\
    \ output (this can also be a regular sensor_msgs::PointCloud), and tfListener_\
    \ is your transform listener. \n\nYou must also add the following to your manifest.xml:\n\
    \n    <depend package=\"laser_geometry\"/>\n    <depend package=\"tf\"/>\n   \
    \ <depend package=\"sensor_msgs\" />\n\nThat's how I build my LaserScans into\
    \ point clouds. I can provide a more specific example if you need it. \n\n**EDIT**:\
    \ I have updated the code snippets such that if you paste all of the code into\
    \ a .cpp file, build the file, and run it, it will work 100%. You should change\
    \ \"/scan\" to the topic that your laser publishes, and you should change \"/cloud\"\
    \ to the topic you wish to view the cloud on. In Rviz, add a new PointCloud2 visualizer\
    \ and point it to the topic you chose for \"/cloud\" and it should work. This\
    \ node also assumes that there is a tf from the frame of the laser to the target\
    \ frame (\"base_link\" in this example). "

  body_markdown: "Hi,\n\nUsing Python to do the conversion simplifies a lot. Let's\
    \ see how to do that using the `laser_geometry` package.\n\nFirst, you need to\
    \ launch the `laser_geometry` package from a launch file, properly configured.\
    \ Here a suggested launch file:\n\n    <launch>\n    <node type=\"laser_scan_assembler\"\
    \ pkg=\"laser_assembler\"\n        name=\"my_assembler\">\n    <remap from=\"\
    scan\" to=\"laser_scan\"/>\n    <param name=\"max_scans\" type=\"int\" value=\"\
    400\" />\n    <param name=\"fixed_frame\" type=\"string\" value=\"my_robot_link_base\"\
    \ />\n     </node>\n      <node type =\"laser2pc.py\" pkg=\"laser_to_pcl\" name=\"\
    laser2pc\"/>\n    </launch>\n\nThat file launches the `laser_geometry` package\
    \ indicating that the frame from which the transform will be done is the `my_robot_link_base`\
    \ (that is whatever tf link of your robot you want the point cloud to be refered\
    \ from). Another parameter is the `max_scans` which indicates the max number of\
    \ last scans that will be take into account for the computation of the point cloud\
    \ ( this is useful in case your laser is rotating, so you can generate a full\
    \ 3D cloud).\n\nThe launch file above also launches a second node that is the\
    \ one you have to create to get the data and publish it into your selected topic.\
    \ What should be the code of such a node? Check the following:\n\n    #!/usr/bin/env\
    \ python\n\n    import rospy \n    from laser_assembler.srv import AssembleScans2\n\
    \    from sensor_msgs.msg import PointCloud2\n\n    rospy.init_node(\"assemble_scans_to_cloud\"\
    )\n    rospy.wait_for_service(\"assemble_scans2\")\n    assemble_scans = rospy.ServiceProxy('assemble_scans2',\
    \ AssembleScans2)\n    pub = rospy.Publisher (\"/laser_pointcloud\", PointCloud2,\
    \ queue_size=1)\n\n    r = rospy.Rate (1)\n\n    while (True):\n        try:\n\
    \            resp = assemble_scans(rospy.Time(0,0), rospy.get_rostime())\n   \
    \         print \"Got cloud with %u points\" % len(resp.cloud.data)\n        \
    \    pub.publish (resp.cloud)\n    \n        except rospy.ServiceException, e:\n\
    \            print \"Service call failed: %s\"%e\n    \n        r.sleep()\n\n\
    The code shows how to subscribe to the `assemble_scans2` service. That is the\
    \ one that will provide the point cloud on its answer. The code also shows that\
    \ the point cloud will be published on a topic of type `PoinCloud2`. basically,\
    \ the while loop what it does is, first, call to the service, then publish the\
    \ answer of the service into a topic.\n\nI have created a video (https://youtu.be/GvilxcePD64)\
    \ showing how to use the laser_geometry with Python with a practical example.\n\
    \nHope it helps."
