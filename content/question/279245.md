  body_markdown: "The error message \"Unable to sample any valid state for goal tree\"\
    \ usually means that either there is a collision for the position you requested,\
    \ or the position cannot be reached for whatever reason.\n\nThe most common error\
    \ for this is that the orientation of your end effector pose is not what you expect\
    \ it to be. Check that your start and goal poses are similar by publishing them\
    \ using [rviz_visual_tools](https://github.com/PickNikRobotics/rviz_visual_tools):\n\
    \n    #include <rviz_visual_tools/rviz_visual_tools.h>\n    \n    rviz_visual_tools::RvizVisualToolsPtr\
    \ visual_tools_;\n    visual_tools_.reset(new rviz_visual_tools::RvizVisualTools(\"\
    world\",\"/rviz_visual_markers\"));\n    visual_tools_->publishAxis(pose_not_stamped);\n\
    \    visual_tools_->trigger();\n\n(Don't forget to include rviz_visual_tools in\
    \ your CMakeLists.txt and package.xml, and adding a MarkerArray subscribed to\
    \ `/rviz_visual_markers` to your Rviz window.)\n\nWhen debugging `move_group.getCurrentPose()`,\
    \ it is wise to do a sanity check by outputting (or visualizing) the pose, or\
    \ you might get mixed up between different frames of reference:\n\n    ROS_INFO_STREAM(\"\
    PoseStamped ps in \" << ps.header.frame_id << \" is: \" << ps.pose.position.x\
    \ << \", \" << ps.pose.position.y << \", \" << ps.pose.position.z);\n\nNote that\
    \ `setTargetPose()` by default sets the target pose for the frame that is defined\
    \ as the end of your kinematic chain or end effector for your robot. Which frame\
    \ is it? What is its orientation? You can check in the srdf of your robot, by\
    \ using the `moveit_setup_assistant`, by showing the TF frames in Rviz, or by\
    \ using the `getEndEffectorLink()` function of the MoveGroupInterface.\n\nLastly,\
    \ make sure you are not sending multiple conflicting goals to the robot. Check\
    \ the `getPoseTargets()` and `clearPoseTargets()` functions of the MoveGroupInterface."
