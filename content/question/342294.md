Hi, 

I am using `ros-melodic` and `MoveIt`. I have started using the `Move Group Interface`. I can do the following: 

 - create simple motion plans such as, specifying a pose of the end-effector and planning motion to that pose goal, or specifying a goal in the joint space and planning motion to that pose, 
 - I can visualize the planned trajectory (arm movements) within `Rviz`. 

I would like to send these movement goals to the real robotic arm `ur5`. 

Previously, I used the `ur_modern_driver` with `MoveIt`. I followed this sequence, 

    roslaunch ur_modern_driver ur5_bringup_compatible.launch robot_ip:="192.168.0.103"	
    roslaunch ur5_moveit_config ur5_moveit_planning_execution.launch
    roslaunch ur5_moveit_config moveit_rviz.launch

I was able to **plan** motions in rviz and **plan and execute** and see these motions on real robotic arm.  For this case, the package `ur5_moveit_config` is present inside the `universal_robot` repository under my `catkin_ws`. The repository `universal_robot` has been downloaded from the following [link](https://github.com/ros-industrial/universal_robot). So far, it is good. But, it only shows that we are able to connect `MoveIt!` with `ur5` manipulator, but through standard repositories code, and **not** using own development with  `Move Group Interface` .   

For this purpose, as a first step, I have generated a configuration using `MoveIt Setup Assistant`. The URDF file of `ur5` needed for the `Setup Assistant` was taken from the following location 

    ~/catkin_ws/src/universal_robot/ur_description/urdf/ur5.urdf.xacro

The resulting configuration (consisting of several configuration files and launch scripts) was placed inside own workspace and ros package which I name `ur5_moveit_path_planner`.  Currently, I can visualize, simple motion plans generated by my program wihtin `rviz`. However, now I face the problem of to send these motions to `ur5`. 

after reading through different posts, I make the following observations. 

 - The configuration generated by
   `MoveIt! Setup Assistant` is not
   enough to control a real-robot
   through the code.
 - It has to be done through a through a
   **controller manager**

currently, I added the following file `controllers.yaml` in the following path    

    my_ws/src/ur5_moveit_path_planner/config/controllers.yaml

and its contents look like

    controller_list:
     - name: /vel_based_pos_traj_controller #or /pos_based_pos_traj_controller
       action_ns: follow_joint_trajectory
       type: FollowJointTrajectory
       default: true
       joints:
          - shoulder_pan_joint
          - shoulder_lift_joint
          - elbow_joint
          - wrist_1_joint
          - wrist_2_joint
          - wrist_3_joint


Also, I made a small modification within `ur5_moveit_controller_manager.launch.xml` and now it looks like

    <launch>
      <!-- loads moveit_controller_manager on the parameter server which is taken as argument 
        if no argument is passed, moveit_simple_controller_manager will be set -->
      <arg name="moveit_controller_manager" default="moveit_simple_controller_manager/MoveItSimpleControllerManager" />
      <param name="moveit_controller_manager" value="$(arg moveit_controller_manager)"/>
    
      <!-- loads ros_controllers to the param server -->
      <!--
      <rosparam file="$(find ur5_moveit_path_planner)/config/ros_controllers.yaml"/>
      -->
      <rosparam file="$(find ur5_moveit_path_planner)/config/controllers.yaml"/>
    </launch> 


And, to test the motion plans, I created a launch file `smp_planning_execution.launch`


    <launch>
      <!--
      <rosparam command="load" file="$(find ur5_moveit_path_planner)/config/joint_names.yaml"/>
      -->
      <include file="$(find ur5_moveit_path_planner)/launch/planning_context.launch" >
    
         <arg name="load_robot_description" value="true" />
    
      </include>
    
      <node name="joint_state_publisher" pkg="joint_state_publisher" type="joint_state_publisher">
    
        <param name="/use_gui" value="false"/>
    
        <rosparam param="/source_list">[/joint_states]</rosparam>
    
       </node>
    
      <include file="$(find ur5_moveit_path_planner)/launch/move_group.launch">
    
         <arg name="publish_monitored_planning_scene" value="true" />
    
      </include>
    
       <include file="$(find ur5_moveit_path_planner)/launch/moveit_rviz.launch">
    
        <arg name="config" value="true"/>
    
       </include>
    
       <node name="ur5" pkg="ur5_moveit_path_planner" type="ur5" respawn="false" output="screen" args="$(arg args1)"/>
    
     </launch>



Coming to my questions. 

when I run my program using

    roslaunch ur5_moveit_path_planner smp_planning_execution.launch args1:="2"

I receive the following errors. 

 1. Action client not connected:

 2. [ERROR] [1579890971.574317699]:

However, I can see, my manipulator following a trajectory within rviz to the desired joint space goal. 

Which command sequence do I need to follow to send the same motion on the real manipulator.
