  body_markdown: "I'd recommend just going through any docker orchestration tutorial,\
    \ e.g. docker swarm/stacks or even kubernetes if your feeling bold, as starting\
    \ processes from cluster of docker hosts isn't very ros specific.\n\nhttps://docs.docker.com/get-started/swarm-deploy/\n\
    \nOne catch may be on how you expose the container to each other via the software\
    \ define networking bridged across the docker hosts. The simplest avenue would\
    \ be to ensure any ros related containers on any host are all interfaced to the\
    \ same virtual network, as port forwarding is of little use with ros.\n\nhttps://docs.docker.com/network/overlay/\n\
    \nNote that the software defined network layer may have side effects on your QoS\
    \ settings, given the transport layer would be wrapped by whatever abstraction\
    \ swarm or kubernetes is configured to use in securing the virtual network traffic\
    \ between docker hosts in the cluster.\n\n(Old post, back from 2016)  \nhttps://www.percona.com/blog/2016/08/03/testing-docker-multi-host-network-performance/\n\
    \nhttps://docs.docker.com/network/overlay/#encrypt-traffic-on-an-overlay-network\
