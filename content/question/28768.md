  body_markdown: "You can use the ros libraries and plugins. You add a controller\
    \ in gazebo which listens to a topic, e.g. gazebo_ros_force. For your case you\
    \ might want to use gazebo_ros_p3d, to change the position instead of force.\n\
    \nAdd a controller to your urdf file like so:\n\n    <controller:gazebo_ros_force\
    \ name=\"controller_name\" plugin=\"libgazebo_ros_force.so\">\n      <alwaysOn>true</alwaysOn>\n\
    \      <updateRate>1000.0</updateRate>\n      <topicName>force1</topicName>\n\
    \      <bodyName>body_name</bodyName>\n    </controller:gazebo_ros_force>\n\n\
    This is a force controller which listen to the topic /force1.\n\nYou then use\
    \ the roscpp api to publish and subscribe to the gazebo topics. You can find a\
    \ good guide for creating these publisher and subscribers [here](http://www.ros.org/wiki/roscpp/Overview/Publishers%20and%20Subscribers).\n\
    \nBut you change the example for publishing wrenches and listening to gazebo link\
    \ states. Like i did with a force controller:\n\n\n       ros::NodeHandle nh;\
    \ \n       pub = nh.advertise<geometry_msgs::Wrench>(\"force1\", 5);\n       sub\
    \ = nh.subscribe<gazebo_msgs::LinkStates>(\"gazebo/link_states\", 1000, linkstatesCallback);\
    \ //ROS gazebo publishes all joint states, you can use these.\n\nI publish forces\
    \ and i listen to positions and create a feedback loop. It is obviously easier\
    \ to just change position with a different controller if that is what you are\
    \ after.\n\nPublishing is easy and goes like this:\n\n     pub.publish(wrench);\n\
    \     ros::spinOnce();\n\n\nYou can also work around ROS by using the actual gazebo\
    \ API, however in my opinion the documentation for the older version is limited.\
    \ I would not recommend this unless you really need direct access to the simulator.\n\
    \n*Combine these snippets with the tutorials it should work*"
