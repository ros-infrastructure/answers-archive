  body_markdown: "The issue is most likely related to the path that you were using.\
    \ What directory were you in when the commands used to work? If you happened to\
    \ be in the base path of the `urdf_tutorial` package, then it makes sense that\
    \ a command like \n\n    roslaunch urdf_tutorial display.launch model:=urdf/04-materials.urdf\n\
    \nwould work correctly. If you inspect the [display.launch](https://github.com/ros/urdf_tutorial/blob/indigo/launch/display.launch)\
    \ file on Indigo, you'll see that the `model` arg gets passed directly to the\
    \ `robot_description` parameter. The relative path in the above command will only\
    \ work if your current working directory is correct. Note that this is discussed\
    \ in the [One Shape](http://wiki.ros.org/urdf/Tutorials/Building%20a%20Visual%20Robot%20Model%20with%20URDF%20from%20Scratch#One_Shape)\
    \ section of the tutorial originally linked.\n\nIf you instead used a command\
    \ like\n\n    roslaunch urdf_tutorial display.launch model:='$(find urdf_tutorial)/urdf/04-materials.urdf'\n\
    \nthe error would disappear.\n\n**EDIT**\n\nLooking at the changes in the urdf_tutorials\
    \ package, I noticed that in commit [f2db517470](https://github.com/ros/urdf_tutorial/commit/f2db517470448e76ff3e7b541a54aedc01ab2a6a)\
    \ the contents of the `display.launch` file changed quite a bit. If you were using\
    \ a copy of the urdf_tutorials package from GitHub and you were on the master\
    \ branch, this could explain why you are seeing references to xacro. The newest\
    \ version of `display.launch` uses xacro even when you are just using a regular\
    \ URDF.\n"
