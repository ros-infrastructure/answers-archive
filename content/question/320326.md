  body_markdown: "You can use the aid of a map to identify obstacles. since you have\
    \ a 3D sensor, I can recommend [octomap](http://wiki.ros.org/octomap). Octomap\
    \ is a 3D occupancy grid, and it is lightweight. So if you need to identify obstacles,\
    \ you can simply look for occupant cells in the grid. \n If you are only looking\
    \ forward to identify obstacles in robot's 2D navigation plane, you can refer\
    \ to the robot's `projected map`. \n\nThere are several other mapping mechanisms\
    \ used in ROS ([RTABMap,](http://wiki.ros.org/rtabmap_ros) `gmapping` etc.) **Using\
    \ a map can be useful in your future implementations like navigation**. \n\nYou\
    \ can get more ideas from `ROS navigation stack` too. See how it identifies obstacles\
    \ within a map."

  - body_markdown: "No. Those techniques are originally mapping techniques. They are\
      \ popularly used in navigation stack to identify obstacles. They process the\
      \ `point cloud` generated by Kinect sensor and arrange them into 3D (solid)\
      \ representation of the environment. Basically they can identify `obstacles`\
      \ and `free space` and represent them in a map. \n\nIf you are not looking for\
      \ a map, you can process the `Point cloud` output from the `Kinect` sensor using\
      \ the [PCL](http://wiki.ros.org/pcl_ros) library. I think the given tutorial\
      \ has instructions for a simple program to handle a point cloud. You can study\
      \ the parameters included in a point cloud. (hopefully rgb values, distance,\
      \ angle etc.)\n\nI suggested the mapping techniques because they easily lead\
      \ you to the next level of the system. But if you are not looking for navigation\
      \ using a map, then it will not be useful."

  - body_markdown: "I have not directly used PCL. Since it's a very popular library,\
      \ there should be a lot of tutorials, and examples available. As you are going\
      \ to detect and record the obstacle cells by yourselves, you should remember\
      \ to mark them relative to your `world coordinate frame`. for this you have\
      \ to understand `coordinate frames` in your system. \n\n1. The position values\
      \ obtained from the `point cloud` are relative to the kinect sensor. they are\
      \ in the camera's coordinated frame.\n2. The robot's pose should be updated\
      \ relative to the `world coordinate frame`, which means the starting position\
      \ of the turtlebot. Robot's pose in the world coordinate frame can be obtained\
      \ from `odometry` data. \n3. consider the physical x,y,z distance and rotation\
      \ between robot's `base` and the camera. \n\nUse [tf](http://wiki.ros.org/tf)\
      \ transforms between frames."
