  body_markdown: "Please correct me if I am wrong; I am making the following observations\
    \ based on my experiential results.\n\n##  MoveIt! Pick and Place Pipeline\n<br/>\n\
    Here for opening and closing the gripper, precise joint control is used. Hence\
    \ if you specify the complete closing position of the gripper upon grasp, the\
    \ entire pipeline comes to a halt as the **final position is never achieved**\
    \ in a setup where you feel the resistance to doing so, like in Gazebo and not\
    \ in RViz, for instance.\n<br/>\n\nThe logical fix would be specifying the closing\
    \ angles to match the object's width. However, this method is not robust as it\
    \ would not work for every object and would require knowing the width of the grasping\
    \ object in advance.\n\n### Fix 1 - Hacking the pipeline\n<br/>\nIf you do not\
    \ set the gripper width to match the object width on close, the pipeline gets\
    \ stuck during close. To bypass this, you can **set the grasp posture to be open\
    \ instead of close** so that it achieves the trajectory and the retreat distance\
    \ to be zero. Then you can set orientation constraints and traverse to goal to\
    \ your desired vector of retreat of choice.\n\n * Set gripper to be open when\
    \ picking instead of closing and failing:\n\n        openGripperJointAngles(grasps[0].grasp_posture);\n\
    \n * Set retreat distance to be zero: \n\n        grasps[0].post_grasp_retreat.direction.header.frame_id\
    \ =\n          move_group_.getPlanningFrame();\n        grasps[0].post_grasp_retreat.direction.vector.z\
    \ = 1.0;\n        grasps[0].post_grasp_retreat.min_distance = 0.0;\n        grasps[0].post_grasp_retreat.desired_distance\
    \ = 0.0;\n\n * Call the MoveIt! Pick function:\n\n        // This ignores place\
    \ collision from object and table\n        move_group_.setSupportSurfaceName(\"\
    table\");\n\n        // Start the Pick Pipeline\n        move_group_.pick(\"object\"\
    , grasps);\n\n * Close the gripper using GripperCommandActionGoal.\n\n * Match\
    \ the orientation constraint to your retreat direction vector and target orientation:\n\
    \n        // Function definition\n   \n        void setupOrientationConstraints()\
    \ {\n          moveit_msgs::OrientationConstraint ocm;\n          ocm.link_name\
    \ = move_group_.getEndEffectorLink();\n          ocm.header.frame_id = move_group_.getPlanningFrame();\n\
    \        \n          tf2::Quaternion fixed_orientation;\n          // example\
    \ orientation\n          fixed_orientation.setRPY(1.5707, 0, 1.5707);\n      \
    \    fixed_orientation.normalize();\n        \n          ocm.orientation = tf2::toMsg(fixed_orientation);\n\
    \          // example tolerances and weight\n          ocm.absolute_x_axis_tolerance\
    \ = 0.075;\n          ocm.absolute_y_axis_tolerance = 0.075;\n          ocm.absolute_z_axis_tolerance\
    \ = 0.075;\n          ocm.weight = 1.0;\n        \n          moveit_msgs::Constraints\
    \ test_constraints;\n          test_constraints.orientation_constraints.push_back(ocm);\n\
    \          move_group_.setPathConstraints(test_constraints);\n        }\n\n  \
    \      // Function call\n        setupOrientationConstraints();\n\n * Plan a goal\
    \ pose matching the earlier retreat grasp position.\n * Finally clear the orientation\
    \ constraints:\n\n        move_group_.clearPathConstraints();\n\n * There are\
    \ no changes to the place pipeline as the open gripper posture faces no restrictions.\n\
    \n### Fix 2 - Setting up your pipeline\n<br/>\n\n * Instinctively, traverse to\
    \ the pre-grasp and grasp positions.\n\n * Close the gripper using the GripperCommandActionGoal\
    \ Action.\n\n * Use the move group's attach function and specify the links that\
    \ touch the object upon pick up.\n\n        move_group_.attachObject(\"object\"\
    , move_group_.getEndEffectorLink(), touch_links_);\n\n * Apply orientation constraints\
    \ to keep the object in the same pose as desired.\n\n * Retreat to post-grasp\
    \ and move to pre-place and the place position.\n\n * Open the gripper using the\
    \ GripperCommandActionGoal Action.\n\n * Detach the object from the gripper:\n\
    \n        move_group_.detachObject(\"object\");\n\n * Clear all the path constraints\
    \ as the object is placed.\n\n * Disable collisions between the object and support\
    \ surface, for instance a table:\n\n        void PickAndPlace::ignoreCollisions()\
    \ {\n          robot_model_loader::RobotModelLoaderPtr robot_model_loader(\n \
    \           new robot_model_loader::RobotModelLoader(\"robot_description\"));\n\
    \          planning_scene_monitor::PlanningSceneMonitorPtr planning_scene_monitor(\n\
    \            new planning_scene_monitor::PlanningSceneMonitor(robot_model_loader));\n\
    \        \n          planning_scene_monitor->startSceneMonitor();\n          planning_scene_monitor->startWorldGeometryMonitor();\n\
    \          planning_scene_monitor->startStateMonitor();\n        \n          planning_scene_monitor::LockedPlanningSceneRW\
    \ ls(planning_scene_monitor);\n          collision_detection::AllowedCollisionMatrix&\
    \ acm =\n            ls->getAllowedCollisionMatrixNonConst();\n          acm.setEntry(\"\
    object\", \"table\", false);  // false disables collisions.\n\n          moveit_msgs::PlanningScene\
    \ diff_scene;\n          diff_scene.robot_state.is_diff = true;\n          ls->getPlanningSceneDiffMsg(diff_scene);\n\
    \        \n          planning_scene_interface_.applyPlanningScene(diff_scene);\n\
    \        }\n \n * Retreat to the post-place position after disabling the collision.\n\
    \n * Finally, enable collisions between the support surface and the object.\n\n\
    \n### References:\n\n * [Disabling collision in AllowedCollisionMatrix removes\
