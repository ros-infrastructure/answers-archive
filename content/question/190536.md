  body_markdown: "Sourcing in the correct order does not actually guarantee workspaces\
    \ will be chained correctly, and the ROS_PACKAGE_PATH may have repeated entries\
    \ (as described in the question). The details can be found [here](http://wiki.ros.org/catkin/Tutorials/workspace_overlaying#Chaining_catkin_workspaces).\
    \ This link also describes the limitations in chaining catkin workspaces.\n\n\
    It is all down to which ROS installation and user workspace(s) were already sourced\
    \ at the time the new workspace was created.\n\nTo illustrate that, suppose the\
    \ `.bashrc` file is only sourcing my hydro (or indigo) installation:\n\n    source\
    \ /opt/ros/hydro/setup.bash\n    \nWe can check the environment variable:\n\n\
    \    $ echo $ROS_PACKAGE_PATH\n    /opt/ros/hydro/share:/opt/ros/hydro/stacks\n\
    \nThen, in `terminal #1` we create a workspace named `A`, build and source it:\n\
    \n    $ mkdir -p ~/A/src\n    $ cd ~/A/src\n    $ catkin_init_workspace\n    ...\n\
    \    $ cd ../\n    $ catkin_make\n    ...\n    $ source devel/setup.bash\n\nIf\
    \ we check the environment variable again:\n\n    $ echo $ROS_PACKAGE_PATH\n \
    \   /home/user/temp/A/src:/opt/ros/hydro/share:/opt/ros/hydro/stacks\n\nIn (a\
    \ new) `terminal #2`, we create another workspace, named B (remember, only the\
    \ system-wide ROS installation is being sourced in my .bashrc). After building\
    \ and sourcing it in `terminal #2`, if we check the env. variable in this case:\n\
    \n    $ echo $ROS_PACKAGE_PATH\n    /home/user/temp/B/src:/opt/ros/hydro/share:/opt/ros/hydro/stacks\n\
    \nSo far so good. Let us now add the necessary lines to the `.bashrc` file in\
    \ order to source workspaces A and B:\n\n    source /opt/ros/hydro/setup.bash\n\
    \    source /home/user/temp/A/devel/setup.bash\n    source /home/user/temp/B/devel/setup.bash\n\
    \nAgain, in (a new) `terminal #3`, if we check the env. variable:\n\n    $ echo\
    \ $ROS_PACKAGE_PATH\n    /home/user/temp/B/src:/opt/ros/hydro/share:/opt/ros/hydro/stacks\n\
    \nOnly workspace `B` (as well as the system-wide installation) was sourced. This\
    \ shows that sourcing in the correct order does not imply in chaining workspaces\
    \ correctly (as documented in the link above).\n\nNow, back to `terminal #1`,\
    \ where workspace `A` is properly sourced, let us create workspace `C`, build\
    \ and source it. Then, let us check the environment variable:\n\n    $ echo $ROS_PACKAGE_PATH\n\
    \    /home/user/temp/C/src:/home/user/temp/A/src:/opt/ros/hydro/share:/opt/ros/hydro/stacks\n\
    \nThis time, workspace `C` was correctly chained with workspace `A`, and the reason\
    \ for that to have worked as expected is because workspace `A` was already sourced\
    \ in `terminal #1`, which was not the case in `terminal #2`.\n\nTo be more pedantic\
    \ with my explanation, if one tried the sequence of commands above and ran a diff\
    \ (say, using meld) between the automatically generated files `/home/user/temp/A/devel/_setup_util.py`,\
    \ `/home/user/temp/B/devel/_setup_util.py` and `/home/user/temp/C/devel/_setup_util.py`,\
    \ one would find that those files from workspaces `A` and `B` are identical, whilst\
    \ in the file referring to workspace `C`, line 255, the `CMAKE_PREFIX_PATH` variable\
    \ would include `/home/user/temp/A/devel`, because workspace `A` was already sourced.\n\
    \nI hope this helps others to avoid having the issues I had in the past."

  body_markdown: "The problem is the assumption that sourcing chains workspaces. This\
    \ is not the case. If it were sourcing multiple `setup.sh` files will leave you\
    \ in an undefined state depending on whatever you did before. Here is your problem:\n\
    \n    source /usr/share/ros/workspaceA/devel/setup.bash\n    source ~/ros/workspaceB/devel/setup.bash\n\
    \    cd ~/ros/workspaceB/\n    catkin_make\n\nThis activates workspaceB before\
    \ building. Thus you do not overlay workspaceA.\nCheck out the tutorial on [chaining\
    \ workspaces](http://wiki.ros.org/catkin/Tutorials/workspace_overlaying#Chaining_catkin_workspaces).\
    \ Note the lines along:\n<pre>\n## THIS IS THE CRUCIAL PART FOR OVERLAYING\n$\
    \ source ~/overlay_ws/devel/setup.bash\n$ catkin_make\n</pre>\n\nYou probably\
    \ at some point sourced workspaceA and `catkin_make` in workspaceB leading to\
    \ this:\n<pre>\n-- This workspace overlays: ~/ros/workspaceB/devel;/usr/share/ros/workspaceA/devel;~/ros/workspaceB/devel;/opt/ros/indigo\n\
    </pre>\n\nTry removing the build/devel folders in workspaceB and then:\n<pre>\n\
    source /usr/share/ros/workspaceA/devel/setup.bash\ncd ~/ros/workspaceB/\ncatkin_make\n\
    source ~/ros/workspaceB/devel/setup.bash\n</pre>\nThis should lead to the setup\
    \ you want. From now on it is sufficient to \n`source ~/ros/workspaceB/devel/setup.bash`\
    \ in your .bashrc. This will lead to the correct overlays."
