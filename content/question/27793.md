  body_markdown: "Looking at the source code, it looks [like L8 and L_INT8 set `bpp`\
    \ to 8](https://github.com/osrf/gazebo/blob/cc06796b135f03066a96c68dfa4e2f89d5f76b3a/gazebo/common/Image.cc#L131-L133),\
    \ which is used by [`FreeImage_ConvertFromRawBits()`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/common/Image.cc#L166-L167)\
    \ as [the bit-depth](https://documentation.help/FreeImage.NET/M_FreeImageAPI_FreeImage_ConvertFromRawBits.htm):\n\
    \n> bpp\n> Type: SystemUInt32\n> The bit depth (bits per pixel) of the raw bitmap.\n\
    \nI have a hunch that the renderer is producing an RGB image by default, and the\
    \ `L8` option is just taking the first 8 bits of each pixel, i.e. the Red channel\
    \ only. \n\nCertainly more efficient than averaging over the 3 channels for each\
    \ frame, but it feels a bit misleading... I'll open an [issue on the Gazebo github](https://github.com/osrf/gazebo/issues/3168),\
    \ but given the massive issue backlog I have doubts anything will come of it.\
    \ For my purposes I will likely end up writing a plugin to average RGB images\
    \ into grey scale. "

Is there a proper way to simulate monochrome / greyscale camera in Gazebo?

The [answer to question #3470](https://answers.gazebosim.org/question/3470/quick-question-what-is-color-descption-and-format-in-sdf/) suggests setting the `<format>` tag to `L8`. This almost works as expected, but I noticed that the output image *only uses the red channel of the rendered scene*. Thus a blue object would appear as black, as shown below: 

![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/gazebosim/1644025430847031.png)

Is there a way to get the sensor to output the mean greyscale value (e.g. `(R+G+B)/3`)?
