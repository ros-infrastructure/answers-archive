    As long as the robot is already set up and has a standard `geometry_msgs/Twist` interface, all you need is a node that translates the `sensor_msgs/Joy` message (assumption, as this is how those drivers are usually implemented) into a respective `twist` message. There are many packages out there doing things like that, usually something called `teleop`.

    Or you could directly send out the twist message from the node.

      Yes, either directly use a [geometry_msgs/Twist](http://docs.ros.org/en/api/geometry_msgs/html/msg/Twist.html) message (or, depending on the interface of the simulated robot, [geometry_msgs/TwistStamped](http://docs.ros.org/en/api/geometry_msgs/html/msg/TwistStamped.html), use `rostopic list` and `rostopic info` to have a look at the available topics), or use a [sensor_msgs/Joy](http://docs.ros.org/en/api/sensor_msgs/html/msg/Joy.html) message and use one of the available, or a custom, `teleop_node` (e.g. [this one](http://wiki.ros.org/cob_teleop)) to translate the joystick message to a proper twist message.
