Hello,

I am using ROS2 Foxy on Ubuntu 20.04.

This is a problem that would be difficult to explain! I will do my best. Please kindly ask me for any clarification.

I have a differential drive robot with arms. I am trying to use:

1) A "forward_command_controller/ForwardCommandController" to control the arms and the neck.

2) A "diff_drive_controller/DiffDriveController" and "bt_navigator" (nav2) with SLAM for the motion control.

In the examples that I have found, people use the "/robot_state_publisher" node to publish the robot transformations to "/tf" and "/tf_static". This is all okay, but the other nodes that I need for control of the wheels and navigation also publish to the same topics!

The "/robot_state_publisher" publishes all of the joint transformations (robot_foot_print, robot_base, arms, and neck) on /tf and /tf_static. A LiDAR is on the head that sits on the neck, so the "scan_link" frame transformation depends on all the transformations from the neck to the robot_foot_print.

Then, the "diff_drive_controller" node, publishes to the same topic /tf, I am not sure what that one publishes.

Then, the "bt_navigator" node subscribes to the same topic /tf, I am not sure what it looks for in that topic. 

Then, the "slam_toolbox" node publishes to the same topic /tf. It seems that it only publishes the "odom" and "map" frames..

It seems like, on each separate run, at random each of the above nodes may start publishing first, and dominating the /tf topic. If the robot_state_publisher gets to initialize the /tf topic first, all is well. 

When this happens, the /tf tree in RVIZ shows all the coordinate frames from the "robot_foot_print" to "scan_link". The navigation works fine.

If any other three of the above mentioned nodes start publishing to the /tf topic first, nothing works. I get the following message:

  [sync_slam_toolbox_node-11] [INFO] [1668984486.138684884] [slam_toolbox]: Message Filter dropping message: frame 'scan_link' at time 1668984485.947 for reason 'Unknown'

When this happens, the /tf tree in RVIZ only shows two coordinate frames "odom" and "robot_foot_print" and the navigation does not work.
