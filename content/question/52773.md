    \ <!-- -*- xml -*- -->\n    <!--\n       Record HRP-2 data automatically in three\
    \ separate rosbags:\n       - cameras images\n       - hrpsys information (IMU,\
    \ force sensors, robot position)\n       - diagnostics (node output, diagnostics)\n\
    \      -->\n    \n    <launch>\n      <arg name=\"record_cameras\" default=\"\
    true\" />\n      <arg name=\"record_hrpsys\" default=\"true\" />\n   \n     <!--\
    \ Are we on the robot (hrp2_14) or simulating (sim)? -->\n     <arg name=\"robot_machine_profile\"\
    \ default=\"hrp2_14\" />\n   \n     <!-- Load the robot model and machine description\
    \ -->\n     <include file=\"$(find hrp2_bringup)/launch/common.launch\">\n   \
    \    <arg name=\"robot_machine_profile\" value=\"$(arg robot_machine_profile)\"\
    \ />\n     </include>\n   \n     <node pkg=\"rosbag\" type=\"record\" name=\"\
    rosbag_record_cam\"\n           args=\"record -o /tmp/hrp2-cameras /wide/left/image_raw\
    \ /wide/left/camera_info    /wide/right/image_raw /wide/right/camera_info /narrow/left/image_raw\
    \ /narrow/left/camera_info    /narrow/right/image_raw /narrow/right/camera_info\"\
    \n           if=\"$(arg record_cameras)\" />\n   \n     <node pkg=\"rosbag\" type=\"\
    record\" name=\"rosbag_record_hrpsys\"\n           args=\"record -o /tmp/hrp2-hrpsys\
    \ /imu /joint_states /joint_command /force_0 /force_1 /force_2 /force_3 /base_link\"\
    \n           if=\"$(arg record_hrpsys)\" />\n   \n     <node pkg=\"rosbag\" type=\"\
    record\" name=\"rosbag_record_diag\"\n           args=\"record -o /tmp/hrp2-diag\
    \ /diagnostics /rosout\"/>   \n    </launch>\n\nPlease note that if you pass \"\
    -o\" instead of \"-O\" then it becomes only a prefix and not the full bag filename.\
    \ In this case, the timestamp is then used as a suffix to build the full filename.\n\
    \nYou can write into a package directory using \"$(find mypkg)\" BUT if you will\
    \ not be able to release your stack. I.e. if your stack get, at some point, installed\
    \ through a Debian package, the directory will be owned by root and be read-only\
    \ for you so your launch file will not work.\n\nEven if rosbuild and others ROS\
    \ tools behaves badly w.r.t this issue, the source directory of any package should\
    \ always be considered as **read-only**."

I want to use *rosbag record* in my launch file with the parameters linking to a ros package.  Normally, you can get a package path in a launch file by using ${find mypackage}, but this does not work in this case, I presume because the *${find pkg}* command doesn't work in the *args* statement of the launch file (?).

    <node name="record" pkg="rosbag" type="record" args="-a -O $(find mypkg)/subdir"/>

The error in the log shows that the rosbag node is trying to subscribe to topics named *${find* and *mypkg}/subdir*, which clearly is not what is intended.

I definitely don't want to use an absolute path.  Is there any way to specify the relative path here?
