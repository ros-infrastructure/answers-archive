    \ \n\n> 2 Global Planner\n\n> 2.1 Global Planner Selection \n\n> To use the move\
    \ base node in navigation\n> stack, we need to have a global\n> planner and a\
    \ local planner. There are\n> three global planners that adhere to\n> nav core::BaseGlobal\
    \ Planner\n> interface: carrot planner, navfn and\n> global planner.\n\n> 2.1.1\
    \ carrot planner \n\n> This is the simplest one. It checks if the given\n> goal\
    \ is an obstacle, and if so it\n> picks an alternative goal close to the\n> original\
    \ one, by moving back along the\n> vector between the robot and the goal\n> point.\
    \ Eventually it passes this valid\n> goal as a plan to the local planner or\n\
    > controller (internally). Therefore,\n> this planner does not do any global\n\
    > path planning. It is helpful if you\n> require your robot to move close to\n\
    > the given goal even if the goal is\n> unreachable. In complicated indoor\n>\
    \ environments, this planner is not very\n> practical.\n\nYou would have to modify\
    \ the code of `carrot_runner` (ROS Wiki page: http://wiki.ros.org/carrot_planner)\
    \ to use something similar to [the Shim Controller from Nav2 in ROS2](https://navigation.ros.org/tutorials/docs/using_shim_controller.html#overview)\
    \ already mentioned here in the other answer. Your robot would go as close as\
    \ possible to the goal point (`carrot_runner`), then it should rotate adequately\
    \ to the next goal position, so it would move in the straight path."
