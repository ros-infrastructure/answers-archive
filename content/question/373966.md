  body_markdown: "Plugins in Gazebo publish data to a coordinate frame. This frame\
    \ is defined inside the `<frameName>` tag, which is inside the corresponding `<plugin>`\
    \ tag. \n\nSo look what's inside your plugin's `<frameName>`, it could be `camera_link`\
    \ or `camera_rgbd_frame` or something else.  \n\nNext you will have set a different\
    \ orientation for the **joint** that connects to a **link** with this frame name.\
    \ \n\n- Find the urdf/xacro file that defines the corresponding joint and link.\
    \ This could be defined inside a file called `kinect.xacro` or inside any other\
    \ URDF or XACRO file of your robot.  \n\nLook for where the joint and link are\
    \ defined, it should look similar to this:\n\n\n    <joint name=\"camera_rgb_joint\"\
    \ type=\"fixed\">\n      <origin xyz=\"0 0 0\" rpy=\"1.57079 3.14159 1.57079\"\
    />\n      <parent link=\"kinect_baselink\"/>\n      <child link=\"camera_rgbd_frame\"\
    \ />\n    </joint>\n    <link name=\"camera_rgbd_frame\"/>\n\nModify the values\
    \ inside the tag `<origin xyz=\"0 0 0\" rpy=\"1.57079 3.14159 1.57079\"/>`.: \
    \   \n\n- The values under `xyz` specify the distance of the image with respect\
    \ to the surface to which the camera is fixed.  \n- The values under the attribute\
    \ name `rpy` specify the rotation (in radians) of the image (depth cloud).\n\n\
    \n\nIf your point cloud is not correctly oriented in Rviz try with different `rpy`\
    \ values until a good match is reached."
