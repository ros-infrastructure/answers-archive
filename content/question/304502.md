  body_markdown: "The navsat_transform node, as the name suggests, performs a transform.\
    \ In this case it transforms the GPS data to robot\u2019s world frame coordinates\
    \ (i.e., the frame with its origin at the robot\u2019s start position).\n\nThis\
    \ transformed data can then be fused with another state estimate - in your case\
    \ the state estimate is provided by an ekf_localization_node which fuses data\
    \ from the IMU sensors. So you need 3 nodes:\n\n1. Kalman filter node to fuse\
    \ together data from sensors like IMU, wheel encoder etc. Lets call this `state_estimate_local`.\n\
    2. Navsat transform node to transform GPS data to robot's world frame coordinates.\n\
    3. Another instance of kalman filter to fuse the transformed GPS data with `state_estimate_local`.\n\
    \nIn general for a robot with an IMU and a wheel encoder (or any other source\
    \ of odometry) the node graph should look like this:\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1538750868577828.jpeg)\n\
    \nRight now you are missing the second kalman filter node. If you are just using\
    \ the heading information from the IMU then you can skip the first kalman filter\
    \ node and directly fuse the IMU data with the transformed GPS data."
