    \ my customized rviz panel**, but I was using **CMAKE_AUTOMOC** for my qt objects.\
    \ (Working on Ubuntu 14.04, ROS indigo)\n\nMy file system structure is like this:\n\
    \n    pkg_folder\n    \\-  config\n    \\-  include/rviz_panel.h\n    \\-  src/rviz_panel.cpp\n\
    \    \\-  CMakeLists.txt\n    \\-  package.xml\n    \\-  package_description.xml\n\
    \nThe core parts for add_library is:\n\n    catkin_package()\n    include_directories(include)\n\
    \    set(CMAKE_AUTOMOC ON)\n    set(HEADER_FILES\n       include/FrameFabRvizPanel.h\n\
    \    )\n    set(SRC_FILES\n        src/FrameFabRvizPanel.cpp\n        #src/FrameFab.cpp\n\
    \        #src/FrameFabRenderWidget.cpp\n        #src/WireFrame.cpp\n        )\n\
    \    **add_library(${PROJECT_NAME} ${SRC_FILES})**\n    target_link_libraries(\n\
    \        ${PROJECT_NAME} ${QT_LIBRARIES} ${catkin_LIBRARIES}\n    )\n\nUsing this\
    \ cmake file and package xml and description xml following official [rviz plugin\
    \ tutorial](https://github.com/ros-visualization/visualization_tutorials/tree/kinetic-devel/rviz_plugin_tutorials),\
    \ I went through catkin_make process smoothly and harvest my lib_pkg.so successfully.\n\
    \nThen launching process for Rviz went on smoothly, and I can even see my panel\
    \ in the add_new_panel list.\n\nBut when I click on it to open it, ROS pumped\
    \ out an ERROR:\n\n    PluginlibFactory: The plugin for class 'framefab_mpp/FrameFabRvizPanel'\
    \ failed to load.  Error: Failed to load library /home/yijiangh/catkin_ws/devel/lib//libframefab_mpp.so.\
    \ Make sure that you are calling the PLUGINLIB_EXPORT_CLASS macro in the library\
    \ code, and that names are consistent between this macro and your XML. Error string:\
    \ Could not load library (Poco exception = /home/yijiangh/catkin_ws/devel/lib//libframefab_mpp.so:\
    \ undefined symbol: _ZTVN8framefab17FrameFabRvizPanelE)\n\n(Exactly the same symptom\
    \ @mcholewi has encountered in [his thread](http://answers.ros.org/question/215487/could-not-load-panel-in-rviz-pluginlibfactory-the-plugin-for-class/?answer=215543#post-id-215543))\n\
    \nWhen using `rospack plugins --attrib=plugin rviz`, I can successfully see the\
    \ `plugin_description.xml` address for my pkg.\n\nAfter getting stuck for 3 days,\
    \ I happened to see [this thread in stackoverflow](http://stackoverflow.com/questions/37151163/cmake-automoc-with-files-on-different-folders).\
    \ And it just saved huge amount of my time!\n\nSo change my CMakeLists.txt file\
    \ like this:\n\nchange this line:\n\n    **add_library(${PROJECT_NAME} ${SRC_FILES})**\n\
    \ninto \n\n    **add_library(${PROJECT_NAME} ${SRC_FILES} ${HEADER_FILES})**\n\
    \n*And everything just works like a charm.*\n\nI think the reason can be found\
    \ at CMake AUTOMOC official doc:\n\n> If an #include statement like #include \"\
    moc_foo.cpp\" is found, **the Q_OBJECT class declaration is expected in the header**,\
    \ and moc is run on the header file. A moc_foo.cpp file will be generated from\
    \ the source\u2019s header into the CMAKE_CURRENT_BINARY_DIR directory. This allows\
    \ the compiler to find the included moc_foo.cpp file regardless of the location\
    \ the original source. **However, if multiple source files in different directories\
    \ do this then their generated moc files would collide. In this case a diagnostic\
    \ will be issued.**\n\nSo in my previous mistake, the QObject declaration cannot\
    \ be found thus pluginlib found my customized panel (FrameFabRvizPanel in my case)\
    \ is undefined.\n\nThus the solution would be:\n\n- You can put cpp and header\
    \ files for your rviz related plugin together in one folder\n- or use the technique\
    \ stated above (link both source and header to your created library)"
