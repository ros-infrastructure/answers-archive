  body_markdown: "If the sensor does not see new objects, it will not clear the object\
    \ out of the map and retains the previous valid information it received. The costmap\
    \ will retain the previous data (retain the presence of the previous obstacle)\
    \ until it gets fresh data from it's sensor indicating that there is no obstacle.\
    \ \n\nOne way to get around this is to create a node that would fill the rest\
    \ of the laser scan with max range (~20m) so that the maps would be cleared. This\
    \ is code for the node -\n\nhttps://github.com/clubcapra/Ibex/blob/master/src/capra_lidar/scripts/max_range.py\n\
    \nHowever you must keep in mind that it isn't completely safe - if something blocks\
    \ the laser or it fails your robot will drive straight into things, which is why\
    \ it's not the default."

  body_markdown: "Sidd is correct. The costmap aims to keep the map up to date with\
    \ the most recent information it got. If it sees obstacles and then moves away\
    \ without clearing them, it will keep that information forever (or until new sensor\
    \ data clears the obstacles). \n\nIf this causes no path to be found, the recovery\
    \ behaviors should trigger to clear the obstacles. \n\nIf you wish not to remember\
    \ this data at all, you can remove the obstacles layer from your global costmap,\
    \ and the obstacle layer in the local costmap will keep you from hitting obstacles. "
