  body_markdown: "Hello guys,\n\nI've suffered from the same problem until discovering\
    \ a pretty clear way to do it. First, we have to configure the project \"build\"\
    \ and \"run\" parameters that can be accessed through the section \"Projects\"\
    \ in the right sidebar.\n\n![\"Projects\" section ](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15402950255679515.jpg)\n\
    \nAfter access the \"Projects\" section, we need to set up all parameters related\
    \ to the build process as the following steps:\n\n1) Remove the current catkin_make\
    \ configuration (this configuration is just an execution of the conventional process\
    \ that we are already used to). To remove it just hover your arrow near \"Details\"\
    , hence an \"X\" will appear.\n\n![remove catkin_make](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15402965959241804.png)\n\
    \n2) After removing the current build step configuration, click on \"Add build\
    \ step\" and choose the option \"Custom Process Step\" and fill the blanks according\
    \ to your workspace environment.\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15402970617731665.png)\n\
    \nAbove I filled in the blanks considering the tips I found [here](http://wiki.ros.org/catkin/Tutorials/using_a_workspace)\
    \ and my workspace build directory location (in order to have it already done\
    \ at this step you have to run the \"catkin_make\" command at least once before\
    \ it). In my case, my build directory is located at `/home/matheus/rosworks/build`.\
    \ \n\nMoreover, the arguments that I used were:\n\n`../src -DCMAKE_INSTALL_PREFIX=../install\
    \ -DCATKIN_DEVEL_PREFIX=../devel -DCMAKE_BUILD_TYPE=Debug`.\n\nNotice that the\
    \ `-DCMAKE_BUILD_TYPE=Debug` CMake argument is used aiming to allow us to attach\
    \ to the ROS application in runtime.\n\n4) Once the MakeFile is generated by the\
    \ CMake, we are able to run the `make` command, to achieve it we must add other\
    \ \"Custom Process Step\".\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15403830053686103.png)\n\
    \nAbove, the argument ''-j12\" specifies the  number of process to run simultaneously.\n\
    \nIf an application requires an install step, other \"Custom Process Step\" with\
    \ a `make` command and `install` argument can be added.\n\n5) Now, you should\
    \ be able to build your project. To accomplish it easier we can type `ctrl+b`\
    \ to build and afterwards `alt+4` to keep up with the compilation.\n\nNow, in\
    \ order to perform the debug just pressing `F5` we need to configure the \"run\"\
    \ section of the IDE. For it, follow the next steps:\n\n1) On the \"Project\"\
    \ section select the \"run\" tab.\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/154029810396289.png)\n\
    \n2) Click on \"Add\" and then on \"Custom Executable\".\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1540298303609989.png)\n\
    \n3) Now, add the path to your ROS executable that probably is placed in `your_workspace/devel/lib/your_package_name`\
    \ and the path to your build directory as well. \n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15402985292162488.png)\n\
    \nCongratulations!!\n\nNow you must be able to set up your breakpoints and press\
    \ `F5` to debug your ROS application. \n\nPlease, if it was useful for anyone\
    \ or if you still have a remaining doubt, please let me know that. \n\nBest regards\
    \ for all."
