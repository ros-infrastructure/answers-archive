    As stated in the [Xacro wiki](http://wiki.ros.org/xacro#Rospack_commands), you can use an `xacro:arg` the same as an [`arg` in a launch file](http://wiki.ros.org/roslaunch/XML#substitution_args).  Your Xacro file may look something like this:

        <xacro:arg name="link1_length" default="1.0"/>

        <link ...>
          ...
            <cylinder length="$(arg link1_length)" radius="0.2" />
          ...
        </link>

    Then, in your launch file:

        <param name="robot_description" command="$(find xacro)/xacro robot_model.urdf.xacro link1_length:=1.5" />

    [This answer](https://answers.ros.org/question/282902/pass-parameters-to-xacro-from-launch-file-or-otherwise/?answer=291570#post-id-291570) to #q282902 shows another example.

    \ explains that process. \n\n**2**\nYou can also load a yaml file as a dictionary\
    \ that can be accessed within a xacro. This allows you to put all your variables\
    \ in a single file, and load it as a single argument to the xacro (as compared\
    \ to having an argument for every variable you want to set). Then to change configurations,\
    \ just load a different yaml.\n\nFor an example of this method, consider a package\
    \ with the following structure:\n\n    test_pkg\n    |-- launch\n    |   |-- description.launch\n\
    \    |-- params\n    |   |-- parameters.yaml\n    |-- xacro\n        |-- test_model.xacro\n\
    \n**description.launch**\n\n    <?xml version=\"1.0\"?>\n    <launch>\n    <!--\
    \ Build the robot description for a xacro and parameter(yaml) file, serve it up\
    \ for consumption -->\n    <!-- Note: params_path will be passed into the xacro\
    \ and accessible as a dictionary for procedural generation of model features -->\n\
    \n    <arg name=\"model_path\" default=\"$(find test_pkg)/xacro/test_model.xacro\"\
    /> \n    <arg name=\"params_path\" default=\"$(find test_pkg)/params/parameters.yaml\"\
    /> \n\n    <!-- Load the robot_description on the ROS param server using xacro\
    \ to generate the model description -->\n    <param name=\"robot_description\"\
    \ command=\"$(find xacro)/xacro $(arg model_path) params_path:=$(arg params_path)\
    \ \" />\n    \n    <!-- Start nodes for serving the model description and joint\
    \ states-->\n    <node name=\"robot_state_publisher\" pkg=\"robot_state_publisher\"\
    \ type=\"robot_state_publisher\" />\n    <node name=\"joint_state_publisher\"\
    \ pkg=\"joint_state_publisher\" type=\"joint_state_publisher\" />\n\n    </launch>\n\

    \   y: 0\n      z: 5\n\n    tire:\n      mass: 1.0\n      width: 0.5\n      radius:\
    \ 0.75\n\n**test_model.xacro**\n\n    <?xml version=\"1.0\"?>\n    <robot name=\"\

    \ the top level xacro for generating a model from a parameter file -->\n\n   \

    \        Kinda stupid way to import external parameters, open to better options.\n\
