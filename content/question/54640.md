    Nate, the suggested method was to wrap a system call.

    See this node: <BR>
    http://www.ros.org/wiki/webots_run  <BR>
    for an example of running an executable from a ROS package.

    Two useful behaviours are: <BR>
    **1.** This node launches with required="true" and the source code doesn't ros::spin. The result is that if you launched everything from one launch file, when you close the simulator, it will drop back to console. (this is good once the system is complete) <BR>
    **2.** Alternatively, you can start roscore in 1 terminal, this node to launch the simulator in a 2nd terminal, then in the 3rd terminal you can keep re-launching your controller nodes while you debug them, without taking down the simulator front-end each time.

    Refs:  <BR>
    http://answers.ros.org/question/33772/run-shell-command-from-launch-script/  <BR>
    http://answers.ros.org/question/51474/can-i-run-a-bash-script-using-roslaunch/  <BR>
