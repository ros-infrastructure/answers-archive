    Dust,


    #####PCD creation
    I don't really know the details of pcd export but can't you decide the format you want to use (binary or acsii)?

    Did you create your pcd file by in the same way as in [this](http://www.ros.org/wiki/pcl/Tutorials/Write%20a%20Point%20Cloud%20to%20a%20PCD%20file) tutorial?
    That way, you could save the pcd file directly inside RGBD-SLAM and not use a bag file.
    This should give you a better control on the pcd file you create.

    Also have a look inside pcl/io, you will find the functions used to write pcd files from point clouds, maybe you can find how to force ascii mode.


    ----------
    #####Importing in Meshlab

    I asked my colleague who actually used some point clouds I had generated with Kinect in Meshlab. All he did was:

     - Edit the pcd file (remove header and extra columns)
     - Change extension of the file to .asc

    But as you said, you need a ascii format.


    good luck :)

    Raph

  body_markdown: "As to answering my own question:\n\nI made a small .ply recorder\
    \ that listens to a topic and writes out any received PointClouds to a .ply file.\n\
    \n    Usage: pcl_plyrecord <topic name>\n\ncommon usage for rgbdslam would be:\n\
    ./pcl_plyrecord /rgbdslam/batch_clouds\n\nNow you will typically start rgbdslam\
    \ and record something with it (CTRL+P).\nNow, to get it to record a usable .ply\
    \ file, \"send\" the data with the rgbdslam tool (CTRL+S).\nThis will send the\
    \ acquired point cloud to the previously mentioned topic and will make it record\
    \ to a .ply file.\n\nIt will output to output.ply\n\nCTRL+C to stop the program\
    \ (try to stop it when no new data is coming in, or your output file might miss\
    \ some)\n\nWARNING: It will overwrite output.ply every time you start the program!\n\
    \nThe program records xyzrgb type pointclouds, like the ones rgbdslam outputs.\
    \ If you import the .ply in meshlab you will have a pointmap with color. Just\
    \ what we need! :)\n\nYou can find the [source package here.](http://duststorm.ulyssis.be/stuff/pcl_plyrecord.tar.gz)\n\
    It contains the source and a buildscript and readme for quick compiling. (read\
    \ the readme!!)\n\nOr for those who just want to have a look at the source:\n\n\
    pcl_plyrecord.cpp\n\n    #include <ros/ros.h>\n\t#include <pcl_ros/point_cloud.h>\n\
    \t#include <pcl/point_types.h>\n\t#include <boost/foreach.hpp>\n\t#include <stdio.h>\
    \ \n\t#include \"pcl_plyrecord.h\"\n\t#include <math.h>\n\t//#include \"rply.h\"\
    \n    \n\ttypedef pcl::PointCloud<pcl::PointXYZRGB> PointCloud;\n\n\tint count\
    \ = 0;\n\tFILE *file;\n\tlong int HEADER_COUNT_POS = 0;\n\n\t/**\n\t * Add one\
    \ point to output .ply file\n\t * Point will be omitted if it contains NaN coordinates\n\
    \t **/\n\tvoid addPoint(const float x, const float y, const float z, const float\
    \ rgb)\n\t{\n\t\t// Filter out points with NaN coordinates\n\t\tif(isnan(x) ||\
    \ isnan(y) || isnan(z) || isnan(rgb))\n\t\t\treturn;\t// one of the values is\
    \ NaN\n\t\n\t\tRGBValue color = RGBValue();\n\t\tcolor.float_value = rgb;\n\t\t\
    unsigned char red = color.Red;\n\t\tunsigned char green = color.Green;\n\t\tunsigned\
    \ char blue = color.Blue;\n\n\t\tfprintf(file, \"%f %f %f %u %u %u\\n\", x, y,\
    \ z, red, green, blue);\n\t\tcount++;\n\t}\n\n\t/**\n\t * Write initial header\
    \ of .ply file\n\t * Vertices count will be set to 0\n\t **/\n\tvoid writeheader(void)\n\
    \t{\n\t\tfprintf (file, \"ply\\n\");\n\t\tfprintf (file, \"format ascii 1.0\\\
    n\");\n\t\tfprintf (file, \"comment Created with pcl_plyrecord\\n\");\n\t\tHEADER_COUNT_POS\
    \ = ftell(file); // store location of vertices count\n\t\tfprintf (file, \"element\
    \ vertex %-10i\\n\", 0); // with extra padding for easy overwrite later on\n\t\
    \tfprintf (file, \"property float x\\n\");\n\t\tfprintf (file, \"property float\
    \ y\\n\");\n\t\tfprintf (file, \"property float z\\n\");\n\t\tfprintf (file, \"\
    property uchar red\\n\");\n\t\tfprintf (file, \"property uchar green\\n\");\n\t\
    \tfprintf (file, \"property uchar blue\\n\");\n\t\tfprintf (file, \"end_header\\\
    n\");\n\t}\n\n\t/**\n\t * Overwrite the vertices count in the header at the top\
    \ of the .ply file\n\t * Because of extra padding to the number, larger numbers\
    \ can always be written in-place\n\t * File pointer is set to the end of the file\
    \ again afterwards\n\t **/\n\tvoid correctHeader(void)\n\t{\n\t\tfseek(file, HEADER_COUNT_POS,\
    \ SEEK_SET);\n\t\tfprintf (file, \"element vertex %-10i\\n\", count);\n\t\tfseek(file,\
    \ 0, SEEK_END);\n\t}\n\n\t/**\n\t * Process a new incoming pointcloud\n\t * After\
    \ adding all points of the cloud the vertices count in the header is altered\n\
    \t * Interrupting the program before the header is altered will only make available\n\
    \t * the vertices up to the previous fully processed pointcloud.\n\t **/\n\tvoid\
    \ callback(const PointCloud::ConstPtr& msg)\n\t{\n\t//\tprintf (\"Cloud: width\
    \ = %d, height = %d\\n\", msg->width, msg->height);\n\t\tBOOST_FOREACH (const\
    \ pcl::PointXYZRGB& pt, msg->points)\n\t\taddPoint(pt.x, pt.y, pt.z, pt.rgb);\n\
    \n\t\tcorrectHeader();\n\t}\n\n\tint main(int argc, char** argv)\n\t{\n\t\tif(argc\
    \ < 2) {\n\t\t\tprintf (\"Specify topic to record as parameter.\\n\");\n\t\t\t\
    exit(0);\n\t\t}\n\t\t\n\t\tros::init(argc, argv, \"pcl_plyrecord\");\n\n\t\tfile\
    \ = fopen(\"output.ply\", \"w\");\n\t\twriteheader();\n\n\t\tros::NodeHandle nh;\n\
    \t\tros::Subscriber sub = nh.subscribe<PointCloud>(argv[1], 1, callback);\n\t\t\
    ros::spin();\n\t}\n\npcl_plyrecord.h\n\n\ttypedef union\n\t{\n\t\tstruct /*anonymous*/\n\
    \t\t{\n\t\t\tunsigned char Blue;\n\t\t\tunsigned char Green;\n\t\t\tunsigned char\
    \ Red;\n\t\t\tunsigned char Alpha;\n\t\t};\n\t\tfloat float_value;\n\t\tlong long_value;\n\
    \t} RGBValue;\n\n\nThe most 'twiddly' part was to update the header of the .ply\
    \ file, since the number of vertices has to be known at the start of the file.\
    \ The header is updated after every full pointcloud that is processed. This means\
    \ that if you CTRL + C before a pointcloud is fully processed, the header won't\
    \ be updated and meshlab will only import vertices till the last full pointcloud\
    \ that got processed."
