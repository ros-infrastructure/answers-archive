  body_markdown: "I think you can use constants in ROS messages:\n\nhttp://www.ros.org/wiki/msg#Constants\n\
    \nThey don't map explicitly to higher-level enum types in programming languages,\
    \ but they generally let you deal with the same issues.\nE.g.\n\n    string eStop\
    \            # Enum {autoAck, manual, remote, none} Acknowledge-Type of eStop:\
    \ \n                            # autoAck: autoacknowledgeable e-stop is activated\
    \ e.g. by bumper or protective field\n                            # manual: e-stop\
    \ has to be acknowledged manually at the vehicle \n                          \
    \  # remote: facility estop has to be acknowledged remotely \n               \
    \             # none: no e-stop activated\n    bool fieldViolation     # Protective\
    \ field violation. True: field is violated False: field is not violated \n   \
    \ \n    # Enums for eStop\n    string AUTO_ACK=autoAck\n    string MANUAL=manual\n\
    \    string REMOTE=remote\n    string NONE=none\n\n In your case, there is also\
    \ a naming error - fields cannot just have numbers as their name:\n\n> Field names\
    \ must be translated by\n> message generators to several target\n> languages,\
    \ so we restrict field names\n> to be an alphabetical character\n> followed by\
    \ any mixture of\n> alphanumeric and underscores, i.e.\n> [a-zA-Z][a-zA-Z1-9_]*.\
    \ It is\n> recommended that you avoid using field\n> names that correspond to\
    \ keywords in\n> common languages -- although those\n> names are legal, they create\
    \ confusion\n> as to how a field name is translated.\n\nfrom 2.1.2 there: https://wiki.ros.org/msg\n\
    \n\n> I want to use only the numbers from 0\n> to 100 at the end. In the example\n\
    > above there was only a section from 0\n> to 10.\n\nIf you want to filter published\
    \ messages by a range of accepted values, this should be done on the publisher/subscriber\
    \ side, e.g. in the callback. AFAIK there is no filtering mechanism for this in\
    \ ROS1 by message definition (and even in ROS2 it's only for the size of a bounded\
    \ dynamic array: `a bounded dynamic array is described by the suffix [<=N] where\
    \ N is the maximum size of the array`, not its values)."
