  body_markdown: "With respect to the diagram:\n\n- `handle_goal` is called when a\
    \ goal is received (before ACCEPTED).\n\n If `handle_goal` returns \"accept\"\
    , then the goal state is set to ACCEPTED. The ACCEPTED state tells us (and the\
    \ action client) that the goal is queued for execution. It's possible that the\
    \ action server chooses to defer execution (e.g. queue the goal for later), hence\
    \ we don't always jump straight to EXECUTING. The \"ACCEPT_AND_EXECUTE\" return\
    \ code is a convenient shortcut if we want to skip straight to EXECUTING.\n\n\
    - `handle_accepted` is called after a goal enters the ACCEPTED state.\n\n This\
    \ is a convenient way to let the code know that a particular goal handle *could*\
    \ be executed. It is up to the action server to explicitly transition the goal\
    \ to the EXECUTING state.\n\nCANCELING and CANCELED work in a similar way:\n\n\
    - `handle_cancel` is called when a cancel request is received (before CANCELING).\n\
    \n If the cancel request is accepted, then the goal enters in to the CANCELING\
    \ state.\n Note, however, this does not mean the goal has been completely canceled\
    \ yet. There may be a time delay between entering CANCELING and transitioning\
    \ to CANCELED. It is up to the action server to explicitly signal that the goal\
    \ is canceled.\n\n- Calling `canceled()` on the goal handle is the signal to transition\
    \ the state to CANCELED.\n\n  I.e. `canceled()` indicates that the action server\
    \ is finished canceling the goal.\n\nPerhaps the [demo code](https://github.com/ros2/demos/blob/ed0299dc808f94b3c995dd4530680560e07226ff/action_tutorials/action_tutorials_cpp/src/fibonacci_action_server.cpp#L98-L103)\
    \ makes this more concrete:\n\n    if (goal_handle->is_canceling()) {\n      result->sequence\
    \ = sequence;\n      goal_handle->canceled(result);\n      RCLCPP_INFO(this->get_logger(),\
    \ \"Goal canceled\");\n      return;\n    }\n\nAbove, the goal execution thread\
    \ checks if a cancel request has been accepted (`goal_handle->is_canceling()`),\
    \ and if so it immediately transitions the goal to CANCELED (`goal_handle->canceled()`).\
    \ In practice, it's possible the code might do something more complex before calling\
    \ `goal_handle->canceled()` (e.g. wait for a robot should put down an object it\
    \ is grasping).\n\n  "
