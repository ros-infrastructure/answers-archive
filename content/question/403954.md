  body_markdown: "I assume your data is from a ROS odometry \"pose\": is that where\
    \ you got it from ? or where from ?\n\nNormally a robot's pose is broadcast as\
    \ a ROS tf transform, which is well visualised in RVIZ: so if that was the source,\
    \ just select it in RVIZ.\n\nIf from other source, you can use python to put it\
    \ into tf-format, broadcast it, and then see in RVIZ.\n\nIf this is of interest,\
    \ I can post some sample code to put odom pose into a tf. e.g. this worked for\
    \ me:\n\n    #!/usr/bin/env python3\n    \n    import rospy\n    import tf2_ros\n\
    \    from nav_msgs.msg import Odometry\n    from geometry_msgs.msg import TransformStamped\n\
    \    \n    rospy.init_node(\"posetf\")\n    tf_buffer = tf2_ros.Buffer(cache_time=rospy.Duration(4))\n\
    \    tf_listener = tf2_ros.TransformListener(tf_buffer)\n    br = tf2_ros.TransformBroadcaster()\n\
    \    \n    def get_odom(msg):                      # CallBack: at ~ 30 Hz nav.message\
    \ ...\n        # ================ broadcast new tf : transout =======\n      \
    \  transout = TransformStamped()\n        transout.header.stamp = msg.header.stamp\n\
    \        transout.header.frame_id = msg.header.frame_id          # e.g. this is\
    \ likely \"odom\" frame\n        transout.child_frame_id = \"newpose\"\n     \
    \   transout.transform.translation = msg.pose.pose.position\n        transout.transform.rotation\
    \ = msg.pose.pose.orientation\n        br.sendTransform(transout)\n    \n    #\
    \ ===================================  Start subscribers etc ... ========================================\n\
    \    rospy.Subscriber('/odom', Odometry, get_odom, queue_size=1)     # nav_msgs/Odometry\n\
    \    rospy.spin()\n\nThe \"newpose\" tf then simply appears in RVIZ list of TF\
    \ Frames ... easy to see as it moves around...\n"
