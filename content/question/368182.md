  body_markdown: "I would suggest setting up a base global planner for the global\
    \ path and teb local planner for the local one since\nteb local planner actually\
    \ supports points. \n\nSee http://wiki.ros.org/teb_local_planner\n\ntake a look\
    \ at the subscribed topics you'll find \"via_points (nav_msgs/Path)\" in the optimization\
    \ parameters you can weight the local planner to follow the via points more. \n\
    \nNote: You'll need to set global path via point seperation to a negative number.\
    \ Otherwise the planner will strictly follow the global path since it is supplying\
    \ the via points now.\n\n\nIt should be fairly simple to implement that behavior.\n\
    \nEDIT:\n\nI just thought about it again, if you run into timing problems between\
    \ supplying the goal and the via points it might be an option to set everything\
    \ from one node. Using the actionlib you can provide the goal and a simple publisher\
    \ can publish your points. Then you can define precise timings and prevent a edgecase\
    \ where you are supplying waypoints from the past."
