     Hi,

    The twist values were added not so long ago (see this [commit](https://github.com/introlab/rtabmap_ros/commit/97b7b0ccf4c426c79658252beba3e9e54b30cb04)). If you build the package from source, you should get the twist values in odometry messages. If you don't want to rebuild the package, you can set the twist values like in the referred commit (using the stamps for dt) with a second node.

    Yes, move_base [uses twist values](https://github.com/ros-planning/navigation/blob/d9e701e42b9d757b58893ca248d13faa8a3880da/base_local_planner/src/trajectory_planner_ros.cpp#L548-L551), though I think it may still work with null twist values (the [rtabmap's navigation example](http://wiki.ros.org/rtabmap_ros/Tutorials/StereoOutdoorNavigation) worked with stereo_odometry (same as rgbd_odometry) node and null twist values)

I am using [rtabmap rgbd_odometry](http://wiki.ros.org/rtabmap_ros#rgbd_odometry) to get odometry for my robot and now want to make use of [move_base](http://wiki.ros.org/move_base) to get `cmd_vel` commands. When I receive the velocity commands though, I'll need to make sure my motor controller follows the command sent by move_base using a control loop which means I need information on the sensed Twist of the robot. But in the odometry message from rgbd_odometry, there is only position data (from what I've gathered, this is so because rtabmap does not require Twist to work).

Is there any option to turn on Twist calculation in rgbd_odometry or should I calculate this myself based on the position data (dx/dt, dy/dt and dtheta/dt)?
