  body_markdown: "> I suppose Vrep has to publish some message to the `/follow_joint_trajectory/goal`\
    \ topic but i have some problem understanding how to compose the message to publish.\
    \ \n\nProvided you are using `ur_gazebo` (or a similar package) which exposes\
    \ a `FollowJointTrajectory` action server, you'd have to write something that\
    \ instantiates and populates a [control_msgs/FollowJointTrajectory](http://docs.ros.org/api/control_msgs/html/action/FollowJointTrajectory.html)\
    \ goal and then submits it to the action server.\n\nThe goal is not that difficult\
    \ to create. Something like this would do it:\n\n    from control_msgs.msg import\
    \ FollowJointTrajectoryAction, FollowJointTrajectoryGoal\n    from trajectory_msgs.msg\
    \ import JointTrajectory, JointTrajectoryPoint\n\n    ...\n\n    # using the action\
    \ namespace you mentioned in your question here\n    client = actionlib.SimpleActionClient('follow_joint_trajectory',\
    \ FollowJointTrajectoryAction)\n    client.wait_for_server()\n\n    goal = FollowJointTrajectoryGoal()\n\
    \    goal.trajectory = JointTrajectory()\n\n    # NOTE: order matters here! This\
    \ HAS to correspond to how the\n    #       values in your VREP trajectory are\
    \ ordered\n    goal.trajectory.joint_names = [\n      'shoulder_pan_joint',\n\
    \      'shoulder_lift_joint',\n      'elbow_joint',\n      'wrist_1_joint',\n\
    \      'wrist_2_joint',\n      'wrist_3_joint'\n    ]\n\n    # not entirely sure\
    \ how your 'points' list (array?) is built up. I'm\n    # assuming a list of tuple(float,\
    \ float, float, float, float, float)\n    # here. Adjust as necessary.\n\n   \
    \ for p in points:\n      goal.trajectory.points.append(\n        JointTrajectoryPoint(\n\
    \          positions=list(p),\n          velocities=...,\n          accelerations=...,\n\
    \          effort=...,\n          time_from_start=rospy.Duration(...)))\n\n  \
    \  # finally: submit the goal for execution\n    client.send_goal(goal)\n\n  \
    \  # optional\n    client.wait_for_result()\n\nYou'll want to make sure to specify\
    \ proper velocities, as I expect the controller to stop at each point in your\
    \ trajectory if you don't."
