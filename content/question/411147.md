  body_markdown: "Yes, you can see [here](https://automaticaddison.com/sensor-fusion-using-the-robot-localization-package-ros-2/)\
    \ on the picture below, where the robot info goes.\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/16732018001573048.jpg)\n\
    \nYes, you can get it from `/tf` topic. \n\nYou can read more about the state\
    \ estimate here, in Nav2 documentation:\n\n- https://navigation.ros.org/concepts/index.html?highlight=odom#state-estimation\n\
    \nThe goal of odometry is to provide a smooth and continuous local frame based\
    \ on the robot's motion. However, it will drift over time as errors accumulate.\
    \ \n\nOn the other side, transformation `map->odom` can \"jump\" between values,\
    \ but is usually more precise - it is provided by the positioning system (localization,\
    \ mapping, SLAM).\n\nI don't know about any differences between the mentioned\
    \ versions of ROS2 (Foxy, Galactic, Humble) - the interface is really similar\
    \ or overall the same."
