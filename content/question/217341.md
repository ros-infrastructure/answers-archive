  body_markdown: " I figured out what the problem was.  \n\nIn the function parse(),\
    \ the program does not add the counter for buffer exactly. To fix this error we\
    \ need to add\n\nseek(2);\n\nafter the line \n\n//skip mean marker error \n\n\
    seek(sizeof(float));\n\nThis is in the for loop that keeps iterating for each\
    \ rigid bodies. \nSince after the 1st rigid body the counter was not at the right\
    \ place, the function\n \nread_and_seek(model.rigidBodies[m].NumberOfMarkers);\n\
    \nwould return a value like 24533 instead of 3. \n\nSo after the 1st rigid body\
    \ the function\n\nmodel.rigidBodies[m].marker = new Marker [model.rigidBodies[m].NumberOfMarkers];\n\
    \nwould allocate more memory and the functions\n\nsize_t byte_count = model.rigidBodies[m].NumberOfMarkers\
    \ * sizeof(Marker);\nmemcpy(model.rigidBodies[m].marker, packet, byte_count);\n\
    \nSo the value for bytecount was more than 60000 when it should have been 36 (since\
    \ i have 3 markers), and this would lead the memcpy to acces data out of the buffer\
    \ which caused the crash\n\nSo we correct this by adding the seek(2) which will\
    \ get everything to the right indices"
