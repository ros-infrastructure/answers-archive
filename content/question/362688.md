  body_markdown: "I think, in general, the odom->base_link transform is published\
    \ pretty fast, but the map->odom transform is in general always published much\
    \ slower (see [REP-105 Coordinate Frames For Mobile Platforms](https://www.ros.org/reps/rep-0105.html)\
    \ for a breakdown of the frame conventions if you are unsure). \n\nThe reason\
    \ for this is that data sources that can provide globally (read: map) referenced\
    \ information like a laser scanner (read: amcl) or GPS (read: [navsat_transform_node](http://docs.ros.org/jade/api/robot_localization/html/navsat_transform_node.html))\
    \ generate data at a much slower rate.\n\nWheel encoders and IMUs, which are generally\
    \ used for the odom->base_link transform generally produce data much more quickly\
    \ and therefore can produce the transform much faster. So in general, it will\
    \ not be possible to get a globally corrected map->odom transform as fast as you\
    \ get odom->base_link.\n\nRead Tom Moore's answer to this question [robot_localization\
    \ dual-EKF:How the two ekf nodes work together](https://answers.ros.org/question/318328/robot_localization-dual-ekfhow-the-two-ekf-nodes-work-together/)\
    \ for more context."
