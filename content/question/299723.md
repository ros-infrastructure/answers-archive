  body_markdown: "I found the problem.\n\nRTI interprets unbounded string as `MAX_SIZE_INT32`\
    \ which is `2147483647`. I had a variable in `header` as `string frame_id`. To\
    \ establish communication between ROS2 and native DDS, the types should be same.\
    \ So, in the QoS.xml, I gave the `maxStringLength = 2147483647`. This gave an\
    \ error `create DataWriter buffer pool`. Refering to the RTI community, I created\
    \ an extra `QoS setting for the data_writer and data_reader` : \n\n        <datawriter_qos>\n\
    \            <property>\n                <value>\n                    <element>\n\
    \                    <name>dds.data_writer.history.memory_manager.fast_pool.pool_buffer_max_size</name>\n\
    \                    <value>2147483647</value>\n                    </element>\n\
    \                </value>\n            </property>\n        </datawriter_qos>\n\
    \        <datareader_qos>\n            <property>\n                <value>\n \
    \                   <element>\n                    <name>dds.data_writer.history.memory_manager.fast_pool.pool_buffer_max_size</name>\n\
    \                    <value>2147483647</value>\n                    </element>\n\
    \                </value>\n            </property>\n        </datareader_qos>\n\
    \nThis somehow lead to improper memory management and ROS2 wasnt able to subscribe\
    \ any messages (not enterin the callback). I reduced the buffer size of the `datawriter\
    \ to 2046` and now it works perfectly fine.\n\nQuestion : Although I have found\
    \ out the error, I am still not sure what are the possible reasons for it. Is\
    \ it only memory creation problem ?"
