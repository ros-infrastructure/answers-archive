  body_markdown: "If you have a ROS driver for the laser scanner on your robot, then\
    \ you should also have laser scan messages published on a specific topic name.\n\
    Find out the topic and then look for the message type.\nNormally planar laser\
    \ scans are published using the `LaserScan` message which is defined in the `sensor_msgs`\
    \ package.\nSee here:  \n\n[sensor_msgs/LaserScan Message](http://docs.ros.org/en/melodic/api/sensor_msgs/html/msg/LaserScan.html)\n\
    \nYou will see that the message *does not* contain the angle of each measurement,\
    \ but the **start angle** of the scan and the **angle increment**.  \n\nTaking\
    \ everything into account, these are the main steps to get the **distance** and\
    \ **angle** for each ray in a  `LaserScan` message:  \n\n\n - Create a ros node\
    \ that subscribes to your laser scanner topic\n - Specify a callback function\
    \ to run when the subscriber receives a message\n - Upon incoming messages, iterate\
    \ over all laser rays\n - Skip laser rays with the value 'inf' (rays that didn't\
    \ hit anything)\n - To have your measurements in polar coordinates (distance and\
    \ angle w.r.t. your device):  \n \n  Use the fields `angle_min`, the start angle\
    \ of the scan [rad] and `angle_increment`, the angular distance between measurements\
    \ [rad], to get each's ray angle, like this:  \n `ray_angle = angle_min + (i *\
    \ angle_increment)` , where `i` is the loop counter that change with each iteration\
    \ of the loop\n\n  Get the distance of the corresponding ray from the data field\
    \ `ranges[i]`\n\nThis is how to find the position of a detected obstacle in polar\
    \ coordinates in the reference frame of your sensor.\nMost probably you will also\
    \ want to transform these values to get cartesian coordinates from polar ones.\n\
    Also consider if you want to transform these into the global frame or not.  \n"
