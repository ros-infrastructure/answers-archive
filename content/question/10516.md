  body_markdown: "The advantage of using OpenCV is that you'll be able save you image\
    \ in a variety of formats using just one or two lines.\n\nIf you want to avoid\
    \ using OpenCV then you either have to roll your own code for saving an image\
    \ in your chosen format, or use one of the standard libraries such as libJPEG.\
    \ The choice you make depends upon the amount of time you have to write, test\
    \ and debug your own code versus any aversion you may have to linking in another\
    \ library.\n\nA quick and dirty solution that I sometimes use when I just want\
    \ to dump an image out is to use one of the [Netpbm](http://en.wikipedia.org/wiki/Netpbm_format)\
    \ ASCII formats. This will result in huge files, but it's not meant to be an elegant\
    \ solution. ;)\n\nSomething like this should work for you. Use a filename with\
    \ a .ppm extension and Ubuntu or the GIMP will be able to open it.\n\n    void\
    \ SaveImageAsPPM( const sensor_msgs::ImageConstPtr& msg, const char* filename\
    \ )\n    {\n      if ( msg->encoding != \"rgb8\" )\n      {\n        return; \
    \ // Can only handle the rgb8 encoding\n      }\n\n      FILE* file = fopen( filename,\
    \ \"w\" );\n    \n      fprintf( file, \"P3\\n\" );\n      fprintf( file, \"%i\
    \ %i\\n\", msg->width, msg->height );\n      fprintf( file, \"255\\n\" );\n  \
    \  \n      for ( uint32_t y = 0; y < msg->height; y++ )\n      {\n        for\
    \ ( uint32_t x = 0; x < msg->width; x++ )\n        {\n          // Get indices\
    \ for the pixel components\n          uint32_t redByteIdx = y*msg->step + 3*x;\n\
    \          uint32_t greenByteIdx = redByteIdx + 1;\n          uint32_t blueByteIdx\
    \ = redByteIdx + 2;\n           \n          fprintf( file, \"%i %i %i \", \n \
    \           msg->data[ redByteIdx ], \n            msg->data[ greenByteIdx ],\
    \ \n            msg->data[ blueByteIdx ] );\n        }\n        fprintf( file,\
    \ \"\\n\" );\n      }\n    \n      fclose( file );\n    }"
