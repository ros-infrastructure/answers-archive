    Considering that RRbot has [continuous joints](https://github.com/ros-simulation/gazebo_ros_demos/blob/master/rrbot_description/urdf/rrbot.xacro), the `error` value is being computed [here](https://github.com/ros-controls/ros_controllers/blob/indigo-devel/effort_controllers/src/joint_position_controller.cpp#L187). It's very likely that floating point computation errors are the culprit. I encountered a similar situation when implementing the `joint_trajectory_controller`, and I ended up [resolving it locally](https://github.com/ros-controls/ros_controllers/blob/indigo-devel/joint_trajectory_controller/include/joint_trajectory_controller/joint_trajectory_segment.h#L265-L271). It might make sense to open an enhancement ticket to the [angles](https://github.com/ros/angles/issues) package to allow an optional tolerance parameter to the `shortest_angular_distance` method. This way the issue would get fixed once and for all.
