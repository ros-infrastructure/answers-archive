    \ several modules. The modules contain classes which represent the various parts\
    \ of either messages, services or actions.\n\nFor a service definition, the top\
    \ part (above the `---`) gets used to generate the *request*, while the bottom\
    \ part (below the `---`) generates the *response*. See [Service definitions, request\
    \ messages, and response messages](http://wiki.ros.org/rospy/Overview/Services#Service_definitions.2C_request_messages.2C_and_response_messages)\
    \ for a more detailed description.\n\nService server *handlers* (ie: the callback\
    \ you register when instantiating a `rospy.Service`) get passed the incoming request\
    \ as the first argument to the function you registered. That function is expected\
    \ to return an instance of the response, and that return value will then be passed\
    \ back to the client.\n\nThe tutorial you mention shows how this is done:\n\n\
    >     def handle_add_two_ints(req):\n        ...\n        return AddTwoIntsResponse(...)\n\
    \n`req` is an instance of `AddTwoIntsRequest` and the response is an instance\
    \ of `AddTwoIntsResponse`.\n\n> I don't understand how to get multiple response\
    \ in one service.\n\nWhere I believe the confusion comes from is the particular\
    \ *style* used in the tutorial:\n\n>     return AddTwoIntsResponse(req.a + req.b)\n\
    \nthis shows Python's [positional arguments](https://problemsolvingwithpython.com/07-Functions-and-Modules/07.07-Positional-and-Keyword-Arguments/#positional-arguments)\
    \ used to pass the result of the addition (of the service request fields `a` and\
    \ `b`) to the constructor of the `AddTwoIntsResponse` instance. This makes it\
    \ look like only a single return value is possible, but that's not the case: the\
    \ `AddTwoIntsResponse` constructor just takes a single argument, as the service\
    \ definition (as defined in the `.srv` file), only has a single field in the response\
    \ part (ie: `sum`). But that's just how that service is defined.\n\nA different\
    \ style (ie: [*keyword* arguments](https://problemsolvingwithpython.com/07-Functions-and-Modules/07.07-Positional-and-Keyword-Arguments/#keyword-arguments))\
    \ would perhaps have already provided a hint on how to deal with multiple fields\
    \ in the response part. The following is equivalent to what the tutorial shows:\n\
    \n    return AddTwoIntsResponse(sum=(req.a + req.b))\n\nthis explicitly refers\
    \ to the service field `sum`.\n\nIn the same way you can provide values for any\
    \ of the other fields which may be part of a service response. Just specify their\
    \ name and provide a value.\n\nAnother alternative would have been:\n\n    resp\
    \ = AddTwoIntsResponse()\n    resp.sum = req.a + req.b\n    return resp\n\nThis\
    \ results in the exact same `AddTwoIntsResponse` instance being returned to the\
    \ client.\n\nHow to populate other fields in a service response should be clear\
    \ now. To use your example (with `multi` a second field in the response object):\n\
    \n    return AddTwoIntsResponse(sum=(req.a + req.b), multi=(req.a * req.b))\n\n\
    or:\n\n    resp = AddTwoIntsResponse()\n    resp.sum = req.a + req.b\n    resp.multi\
    \ = req.a * req.b\n    return resp\n\n**Note**: you cannot use `AddTwoIntsResponse(req.a\
    \ + req.b, req.a * req.b)` as that's explicitly not supported (only services with\
    \ *single-argument responses* can use that shortcut).\n\nRefer to [wiki/rospy:\
    \ Providing services](http://wiki.ros.org/rospy/Overview/Services#Providing_services)\
    \ for more information on the supported ways of returning service responses from\
    \ service server callbacks."
