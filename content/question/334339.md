  body_markdown: "Hello !\n\nFirst you should take a look at @LeoE link in the comment,\
    \ there is all you need to know about tf, take a look at this answers if you want\
    \ some image.\n\nI you want to fuse the sensor data, you don't want them to have\
    \ the same Frame as they don't have the same location.\n\nWhen you publish a Frame,\
    \ you actually tell Tf that there is 2 frames : The source frame and target frame.\n\
    \nFor example, here is the frame from the \"rgbd_launch\" package (you can see\
    \ it with `rosrun tf view_frames`:\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15699555455312338.png)\
    \ \n\neach broadcaster is broadcasting the target and the source. The Camera link,\
    \ the source of all frame, is never broadcasted, instead ROS is waiting for an\
    \ another node (the application node) to tell where is this frame.\n\nIf you launch\
    \ your lidar node, you should have something like this (I don't have a lidar so\
    \ I just assumed a single tf was published, I used `static_transform_publisher`\
    \ : \n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1569955752713369.png)\n\
    \nIn this case, lookuptransform will fail, as the tf tree are not connected.\n\
    \nIn your application you should tell Tf where are located the camera to the lidar\
    \ (or the inverse), or even better if you have a reference point (A robot chassis\
    \ ?) for the camera and the lidar\n\nFor example, I can tell TF that the lidar\
    \ is 20cm above the camera (Z-axis) with `rosrun tf static_transform_publisher\
    \ 0 0 0.2 0 0 0 camera_link laser_base 10`:\n ![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15699560511538702.png)\n\
    \nOr if both the camera and the lidar are connected to the same robot, I can tell\
    \ tf too : \n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15699561888272862.png)\n\
    \nYou can use different way to tell tf the transform between your sensors, the\
    \ best way (I think) is an URDF with robot_state_publisher : \n\nhttp://wiki.ros.org/tf/Tutorials\n\
    \nhttp://wiki.ros.org/robot_state_publisher/Tutorials\n\nhttp://wiki.ros.org/urdf/Tutorials\n"

  body_markdown: "For the question, \nFirst you need to transform from one source\
    \ frame to target frame using the available functions. \nFor example if you are\
    \ working with pointcloud data then the function would be something like below:\n\
    \n    tf::StampedTransform transform;\n    try{\n            transform_listener.lookupTransform(target\
    \ frame as a string, source frame as a string, ros::Time(0), transform);\n   \
    \     }\n        catch (tf::TransformException ex){\n            ROS_ERROR(\"\
    %s\",ex.what());\n        } \n\n    pcl_ros::transformPointCloud(message_without_transformed,\
    \ final_transformed_message, transform);\n\nThe you need to change the frame if\
    \ of the transformed message which is \n`final_transformed_message.header.frame_id\
    \ = \"your required name\"`\n\nHope that helps and I am not too late!!"
