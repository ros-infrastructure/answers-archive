  body_markdown: "At the very end, this is how remapping is implemented (in [roscpp/libros/names.cpp](https://github.com/ros/ros_comm/blob/eb7e686a9a58109087c956eed3cfa6f2ed3eec3d/clients/roscpp/src/libros/names.cpp#L123-L134)):\n\
    \n    std::string remap(const std::string& name)\n    {\n      std::string resolved\
    \ = resolve(name, false);\n    \n      M_string::const_iterator it = g_remappings.find(resolved);\n\
    \      if (it != g_remappings.end())\n      {\n        return it->second;\n  \
    \    }\n    \n      return name;\n    }\n\nIn words: for a given `name`, lookup\
    \ the mapping from `name` to some other `string`, and if there is such a mapping\
    \ registered, return the \"other `string`\".\n\nOtherwise, return the `name` we\
    \ were given.\n\nThe Python implementation does something similar.\n\nThis function\
    \ is used by other functions such as [ros::names::resolve(..)](https://github.com/ros/ros_comm/blob/eb7e686a9a58109087c956eed3cfa6f2ed3eec3d/clients/roscpp/src/libros/names.cpp#L142-L185)\
    \ ([documentation](https://github.com/ros/ros_comm/blob/89ca9a7bf288b09d033a1ab6966ef8cfe39e1002/clients/roscpp/include/ros/names.h#L47-L56))\
    \ which are used throughout the ROS codebase to resolve local names to global\
    \ ones.\n\n> Is it possible to directly have nodes run without wrapping them in\
    \ launch files and still have topic remapping abilities?\n\nYes. See [wiki/Remapping\
    \ Arguments](http://wiki.ros.org/Remapping%20Arguments) for information on that.\
    \ Any argument to a `rosrun` invocation that is not prefixed with a `_` or `__`\
    \ is assumed to be a remap argument."
