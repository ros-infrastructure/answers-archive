  body_markdown: "One option (which has nothing to do with ROS internals) is to set\
    \ the ulimit on core file to be non-zero and then analyze the core after the crash.\
    \ (By default the core size limit is set to 0 in Ubuntu)\n\nSet to unlimited:\n\
    \n    ulimit -c unlimited\n\nThis will cause the OS to produce a \"core file\"\
    \ each time there is a crash which contains some of the info needed to recreate\
    \ a stack trace. The other portion of the info is contained in the executable\
    \ which crashed.\n\nThe core file ends up in ` ~/.ros` and can be analyzed with\
    \ gdb like so:\n\n    gdb --core=~/.ros/core  /path/to/stack/package/bin/mynode\
    \  \n\n... where a backtrace can be obtained by using the \"`backtrace`\" or \"\
    `bt`\" command"
