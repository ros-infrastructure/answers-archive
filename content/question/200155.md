  body_markdown: "You probably want to take a look at [roslaunch/Tutorials/Roslaunch\
    \ Nodes in Valgrind or GDB](http://wiki.ros.org/roslaunch/Tutorials/Roslaunch%20Nodes%20in%20Valgrind%20or%20GDB).\
    \ Make sure to build proper Debug binaries.\n\nBtw: this is not really specific\
    \ to `catkin_make`. The `launch-prefix` just makes this convenient when starting\
    \ things from launch files. For single nodes (and an already running master),\
    \ you can also just do:\n\n    gdb --args /path/to/your/node/binary\n\n>  [..]\
    \ I haven't found anything regarding this on the internet so far.\n\nThe tutorial\
    \ I linked was actually the first result after searching for [ros gdb](https://www.google.com/?q=ros+gdb)\
    \ on Google.\n\n---\n\nEdit:\n\n> I have tried starting gdb directly with the\
    \ executable but it says `no debugging symbols found`.\n> \n> I have also tried\
    \ to do `set(CMAKE_CXX_FLAGS \"${CMAKE_CXX_FLAGS} -g -O0 -std=c++11 -march=native\"\
    \ )` without success.\n\nThis has been answered before, see fi [Cmake debug option](http://answers.ros.org/question/155581/cmake-debug-option/):\n\
    \n> This will set -g for you:\n> \n>     catkin_make -DCMAKE_BUILD_TYPE=Debug\n\
    \ncatkin is just a thin layer on top of CMake in this case.\n\nAnd if you need\
    \ optimisation with debug symbols, see [catkin_make's option for optimization](http://answers.ros.org/question/172950/catkin_makes-option-for-optimization/):\n\
    \n> For a release configuration with opmizations and no debugging symbols, you\
    \ can use the `Release` build type:\n> \n>     catkin_make -DCMAKE_BUILD_TYPE=Release\n\
    > \n> For a release with debug configuration, with optimizations and debug symbols,\
    \ you can use the `RelWithDebInfo` build type:\n> \n>     catkin_make -DCMAKE_BUILD_TYPE=RelWithDebInfo\n\
    > \n> CMake's [useful variables](http://www.cmake.org/Wiki/CMake_Useful_Variables#Compilers_and_Tools)\
    \ page gives more information about build types.\n"
