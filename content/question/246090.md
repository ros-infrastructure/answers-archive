  body_markdown: "(I wouldn't call it *realtime priority*, but ..)\n\nI haven't done\
    \ it myself, but you can probably use `roslaunch`'s  `launch-prefix` together\
    \ with the Linux `nice` utility to start a node at a higher nice value.\n\nSomething\
    \ like `launch-prefix=\"nice -n N\"` (where `N` is the nice value).\n\nSee [How\
    \ to bind a node to a specific cpu core?](http://answers.ros.org/question/202712)\
    \ for a related Q&A.\n\nSee [roslaunch/XML/node - Attributes](http://wiki.ros.org/roslaunch/XML/node#Attributes)\
    \ for more info on `launch-prefix`.\n\n---\n\nEdit: as mentioned in the comments,\
    \ using `nice` to increase priority of a process (ie: use negative values) requires\
    \ `sudo`. But `roslaunch` doesn't play nice with `sudo` as a `launch-prefix` due\
    \ to the password prompt.\n\nConfiguring passwordless `sudo` just for `nice` and\
    \ a specific user could be an option here.\n\nAn alternative could be to configure\
    \ the `ulimit`s for `nice` for a specific user, as explained in [How can I allow\
    \ a user to prioritize a process to negative niceness?](https://unix.stackexchange.com/a/102954)\
    \ on SE.\n\nTo avoid a link-only answer, here is a quote:\n\n> The pam_limits.so\
    \ module can help you there.\n> \n> It allows you to set certain limits on specific\
    \ individual users and groups or wildcards or ranges of users and groups.\n> \n\
    > The limits you can set are typically ulimit settings but also on the number\
    \ of concurrent login sessions, processes, CPU time, default priority and maximum\
    \ priority (renice). Check the limits.conf man page for more.\n> \n> For example\
    \ you can configure your mindcraft group to have all their processes started with\
    \ an increased default priority and you can allow them to use the nice and renice\
    \ commands to increase the priority of their important jobs manually as well instead\
    \ of only reducing priority.\n> \n>     # /etc/security/limits.conf\n>     # increase\
    \ default and max prio for members of the mindcraft group\n>     @mindcraft  \
    \ hard priority -10\n>     @mindcraft   hard nice     -18\n\nRelevant comment\
    \ from that answer:\n\n> I've worked it out! It was using `hard` that caused the\
    \ problems. I changed it to `-` instead and all works fine now. [This answer](https://unix.stackexchange.com/a/300066/83666)\
    \ helped me get to the bottom of it. I think the problem was that I had a soft\
    \ limit that was getting in the way, perhaps overriding the hard limit somehow.\
    \ Anyway, `-` instead of `hard` fixed it"

Is there any built-in mechanism to control the nice value for a ROS node?

I have a node that exposes a simple service for generating speech via espeak. Usually, the generated speech sounds fine, but sometimes when the CPU is under load, the speech will sound slow and stuttering.

I can improve this by manually setting my speech node to run in near-realtime via nice, but that feels hacky. Is there a formal way to do this in ROS?
