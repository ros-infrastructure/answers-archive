    You won't win any awards for what I'm about to suggest, but it does provide a way :)

    It's not clear what type of sensors you're intending, but... if you have a sensor suite that is based on the pose of each robot, then you could via the [standard magic](http://www.ros.org/wiki/ROS/NetworkSetup) have multiple machines that subscribe to the odom or the simulation states of the robots that you need, perform the processing in their local environment (i.e. on that machine) and then publish so any node that needs to have sensor information from that machine can have it (since they're all connected to the same ROS master)..

I would like to simulate a number of robots (up to let's say 10) in real time, each with a significant sensor suite. Is it possible to distribute sensors as slaves to the physics simulation across multiple machines? If it's not right now, does the architecture readily support it? I could imagine a plugin to the main server to broadcast world changes, and a "fake" physics that passes that on to the local sensors on each slave machine.
