  body_markdown: "The base_local_planner , for example the DWA planner uses \n\n*\
    \ The dwa sampling control to compute the velocity commands if the robot is **not**\
    \ near the goal.\n* The \"stop and rotate control\" If the robot is near the goal.\n\
    \nRefer to this function: `bool DWAPlannerROS::dwaComputeVelocityCommands(...)`\
    \ in [dwa_planner_ros.cpp](https://github.com/ros-planning/navigation/blob/0d61d2adf21d6b71fd83edc5febbd6b781d76c9e/dwa_local_planner/src/dwa_planner_ros.cpp).\n\
    \nThe `bool DWAPlannerROS::dwaComputeVelocityCommands(...)` function calls `DWAPlanner::findBestPath(...)`\
    \ function ([src](https://github.com/ros-planning/navigation/blob/0d61d2adf21d6b71fd83edc5febbd6b781d76c9e/dwa_local_planner/src/dwa_planner.cpp))\
    \ which uses the odom (`nav_msgs/Odometry`) to initialize a `base_local_planner::SimpleTrajectoryGenerator`\
    \ and prepare the cost function. Then it calls the `SimpleScoredSamplingPlanner::findBestTrajectory(...)`\
    \ function computes the trajectory for the robot from which the velocities are\
    \ calculated. I guess this is what you call to be the \"better estimate of the\
    \ command velocity\".\n\n\nRefer to [simple_scored_sampling_planner](https://github.com/ros-planning/navigation/blob/0d61d2adf21d6b71fd83edc5febbd6b781d76c9e/base_local_planner/src/simple_scored_sampling_planner.cpp)\
    \ for the trajectory generation. The \"trajectory planner\" takes care of generating\
    \ the \"path\" in addition to planning how to move based on the kinematics of\
    \ the robot, velocity and the time. This can be seen analogous to P/PID controllers.\n\
    \nHope it helps! Post back if you are still unclear.\nThanks.\n"
