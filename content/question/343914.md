  body_markdown: "At the moment this does not seem to be implemented, but the pin\
    \ domain can be set with the `ur_hardware_interface/script_command` topic. Example\
    \ code:\n\n    // include\n    from std_msgs.msg import String \n\n    // the\
    \ function \n    def apply_vacuum(self):\n    rospy.init_node(\"apply_vacum_node\"\
    ) \n    publisher1 = rospy.Publisher('/ur_hardware_interface/script_command',\
    \ String, queue_size=2)\n\n    try:\n       // first 1 is the pin number and second\
    \ number is the state of the pin \n        message = \"sec MyProgram():\" + \"\
    \\n\" + \"set_standard_digital_out(1,1)\" + \"\\n\" + \"end \" + \"\\n\"\n   \
    \     publisher1.publish(message)  \n    except rospy.ServiceException, e:\n \
    \       print \"Something went wrong: %s\"%e\n\nthis will work but make sure you\
    \ read the [scripting manual](https://www.universal-robots.com/download/?option=15649#section15646)\
    \ for the functions that you can use in this format. make sure that you input\
    \ the correct information. The format i used can be seen [here](https://www.universal-robots.com/how-tos-and-faqs/how-to/ur-how-tos/secondary-program-17257/).\n\
    \nyou only need to the use the required function for the pin domain that you can\
    \ find in the mentioned scripting manual in said post."

Hi, I am currently working with a UR10 robot and i want to set the pin mode or domain as it is called to voltage instead of current for the analog output pins. In the [ur_msgs/Analog](http://docs.ros.org/kinetic/api/ur_msgs/html/msg/Analog.html) documentation you can see that the Analog message has a pin and a domain which sets the pin mode to either voltage or current. This is not included in the [ur_msgs/setIO service](http://docs.ros.org/kinetic/api/ur_msgs/html/srv/SetIO.html) of the [Universal_robot_driver](https://github.com/UniversalRobots/Universal_Robots_ROS_Driver) far as i could see. Am i correct in this or am i not looking at it correctly? If this is not implemented, would it be a good idea to write a program to sets up a temporary socket connetion to the UR robot to force the pin mode/domain to voltage? Would ROS reset this when i would write a value to that pin with the ur_msgs/setIO service? 

p.s. i am only talking about the Analog outputs of the UR10
