  body_markdown: "The conversion to and from PCL datatypes is quite computationally\
    \ expensive.  I have observed something like 100ms for a conversion of a Kinect\
    \ frame on a 1Ghz Atom core.  \n\nTo avoid this you can use direct publication\
    \ of pcl datatypes and [nodelets](http://ros.org/wiki/nodelet).  A very simple\
    \ example of a nodelet which does this is in the pointcloud_to_laserscan package\
    \ is [cloud_throttle.cpp](https://kforge.ros.org/turtlebot/turtlebot/file/2154e9c1c701/pointcloud_to_laserscan/src/cloud_throttle.cpp)\n\
    \nWhen publishing over the network the Kinect data was unusable.  \n\nUsing nodelets\
    \ I was able to take processing of the Kinect from 10Hz and 150% cpu to 30Hz and\
    \ 87% cpu on an Atom by publishing using the exact same data type.  Here's  a\
    \ [launch file](https://kforge.ros.org/turtlebot/turtlebot/file/2154e9c1c701/turtlebot_bringup/robot.launch)\
    \ which brings up the kinect and processes the data inside the same process using\
    \ nodelets.  "

Hi,

When working with PointClouds, I usually subscribe to a `sensor_msgs::PointCloud2` topic, and convert to a `pcl::PointCloud` inside my code. Then, once I'm done mainpulating the cloud, I convert it back to a `sensor_msgs::PointCloud2` to publish it, using these functions:

    pcl::fromROSMsg
    pcl::toROSMsg

My first question is: what is the cost of using these functions? I am assuming there's a memcpy involved, which (when dealing with kinect data) is probably not negligible.

Second: is there a way to avoid this, by directly subscribing/publishing `pcl::PointCloud ` types? I believe that there is a publisher/subscriber for pcl types, but I'm not sure whether it *actually* saves time, or does the same conversion/memcpy behind the scenes.
