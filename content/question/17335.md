  body_markdown: "**Why are most examples of the physics always within plugins i.e.\
    \ virtual implementations?**  \nThe short answer is it's generally easier/better\
    \ to implement an empirical behavioral model for an entire subsystem (e.g. a drive\
    \ train) using a plugin, then it is to painstakingly model the subsystem part-by-part\
    \ in a physics simulator.\n  \nMore moving parts = more complexity, slower simulation,\
    \ more things that can break (explode) in your model.  \n  \n**Is Gazebo capable\
    \ of implementing the above using pure geometry and joints?**  \nBased on my (albeit)\
    \ limited experience so far, yes! You should be able to implement both Ackermann\
    \ steering and wishbone suspension using Gazebo. That being said, the end result\
    \ may not be pretty/stable...\n  \nI think the critical questions for you are:\
    \  \n1) *can a Gazebo implementation provide value over and above a quick-and-dirty\
    \ plugin implementing an empirical behavioral model* and  \n2) *is it worth the\
    \ time/effort?*  \n  \n**Are there implementations of this?**  \nNot that I know\
    \ of. Every project I've seen so far uses plugins to represent suspensions, fluidic\
    \ effects, steering, etc...  \n  \n**Further Resources**  \nI highly recommend\
    \ checking out the Gazebo URDF tutorial: http://gazebosim.org/tutorials/?tut=ros_urdf\
    \  \nskimming the Open Dynamics Engine (ODE) User Guide: http://www.ode.org/ode-latest-userguide.html\
    \  \nand watching this 2014 ROSCON talk by Steve Peters about the different Physics\
    \ engines: https://vimeo.com/107517366  \nto get a better understanding of Gazebo's\
    \ underlying mechanisms.  \n  \nFinally, good luck!\n  \nEDIT:  \nYou may also\
