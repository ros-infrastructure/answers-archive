  body_markdown: "Using the following;\n\n    rosmake --pre-clean\n\nusually does\
    \ the job for the packages in which `ROS_NO_BUILD` tag exists, which is most of\
    \ the 'big' packages. The permission error is just because the package exists\
    \ somewhere like `/opt/.../` which is protected. \n\nTo patch the package, I would\
    \ recommend checking it out onto a folder where permissions are not an issue like\
    \ around the `$HOME` or so, then add that path to the `ROS_PACKAGE_PATH` like\
    \ so;\n\n    export ROS_PACKAGE_PATH=$ROS_PACKAGE_PATH:<put the path here>\n\n\
    or do it the `bashrc` way."

    sudo rosmake doesn't work because you're not getting your environment variables.  You can see that by doing 'printenv | grep ROS' and then 'sudo printenv | grep ROS'.  If you do su - to switch to root, then source your usual ~/.bashrc (or whatever file you use to set your ROS_ROOT and all that), you should be able to use rospack commands as root.  I would not recommend trying to re-build inside debs, though.  You should always overlay if you want to change and re-build.
