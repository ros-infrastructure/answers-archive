  body_markdown: "These two packages serve different goals, and cannot really be compared.\n\
    \nFrom [wiki/rosserial](https://wiki.ros.org/rosserial):\n\n> [rosserial](https://wiki.ros.org/rosserial)\
    \ is a [protocol](http://wiki.ros.org/rosserial/Overview/Protocol) for wrapping\
    \ standard ROS serialized messages and multiplexing multiple topics and services\
    \ over a character device such as a serial port or network socket. \n\nFrom [wjwwood/serial](https://github.com/wjwwood/serial/blob/33e5a31ab77011504c8e37d7e9c3b9fa4229e625/README.md):\n\
    \n> This is a cross-platform library for interfacing with rs-232 serial like ports\
    \ written in C++. It provides a modern C++ interface with a workflow designed\
    \ to look and feel like PySerial, but with the speed and control provided by C++.\n\
    \nso the former is an implementation of a *protocol*, while the latter is a C++\
    \ library which intends to make using serial ports easier.\n\n`rosserial` makes\
    \ it possible for resource constraint environments (fi: micro controllers) to\
    \ communicate with a regular ROS node graph (ie: `roscpp` / `rospy` based nodes),\
    \ without having to run Linux.\n\n`wjwwood/serial` is \"simply\" a serial port\
    \ wrapper, it doesn't do anything but provide functions to read from and write\
    \ to a serial port. *What* you read from or write to those serial ports (ie: the\
    \ data) would not be something `wjwwood/serial` could help you with.\n\n> Why\
    \ is the one from wjwwood so popular?\n\nThis question only makes sense if you\
    \ consider the use-cases.\n\nIf you'd like to be able to have your Arduino \"\
    talk ROS\" (for example), `wjwwood/serial` wouldn't really help much.\n\nIf you'd\
    \ like to be able to read and write arbitrary binary data from/to a serial port,\
    \ `rosserial` wouldn't really help much."
