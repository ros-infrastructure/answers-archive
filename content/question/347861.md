  body_markdown: "That is quite easy - there is a standard powerful way ROS community\
    \ has opened up ROS to the web technologies - [roslibjs](http://wiki.ros.org/roslibjs)\
    \ \n\nIn a nutshell you need take 3 key steps:\n\n**1)** Install `ros-melodic-rosbridge-server`\
    \ package (adopted from [this tutorial](http://wiki.ros.org/rosbridge_suite/Tutorials/RunningRosbridge)\
    \ ):\n\n     $ sudo apt-get install ros-melodic-rosbridge-server\n\n**2)** Include`rosbridge_websocket.launch`\
    \ into the launch of your system along with turtlebot launch (adopted from [this\
    \ tutorial](http://wiki.ros.org/rosbridge_suite/Tutorials/RunningRosbridge) ):\n\
    \     <launch>\n       <include file=\"$(find rosbridge_server)/launch/rosbridge_websocket.launch\"\
    \n          <arg name=\"port\" value=\"8080\"/>\n       </include>\n     </launch>\n\
    \n**3)** Include `rolslib.js` or `rolslib.min.js` into your HTML page and you\
    \ will be able to easily publish/subscribe to/from topics, work with action servers\
    \ as well as execute other ROS functionality like setting/getting parameters,\
    \ etc. See [this tutorial](http://wiki.ros.org/roslibjs/Tutorials/BasicRosFunctionality).\
    \ \n\nFor example, publishing to a topic is as simple as following code:\n\n \
    \    //declare reference to the topic that already exists in ROS backend\n   \
    \  var cmdVel = new ROSLIB.Topic({ros : ros,  \n                             \
    \       name : '/cmd_vel', \n                                    messageType :\
    \ 'geometry_msgs/Twist' });\n     \n     //create command message\n     var command\
    \ = new ROSLIB.Message({\n         linear : {\n           x : 0.1,\n         \
    \  y : 0.2,\n           z : 0.3\n         },\n         angular : {\n         \
    \  x : -0.1,\n           y : -0.2,\n           z : -0.3\n         } });\n    \
    \ \n     //publish the command to the topic \n     cmdVel.publish(command);\n\n\
    \n**EDIT:** important note about **3)**:\n\nWebsocket server in ROS Melodic version\
    \ of rosbridge-server enforces more web security then older versions. Therefore,\
    \ you are not able to connect to the rosbridge-server from a HTML page that is\
    \ not served from the same origin. For example, if you simply try to open your\
    \ HTML page directly from a file on your local PC then websocket connection will\
    \ fail because websocket server inside of rosbridge-server will refuse such connection.\
    \ to\n\nThe way to solve connection issue is to have a web server serving your\
    \ HTML page which you want to do eventually for your system anyway. \n\nHere you\
    \ have options. For example:\n\n1) For simple tests running on your local Ubuntu\
    \ 18.04 you can serve your HTML page(s) by running simple HTTP server provided\
    \ by Python3 on your Ubuntu (see [this answer](https://askubuntu.com/questions/1102594/how-do-i-set-up-the-simplest-http-local-server))\n\
    \n    cd /my/html/files  #directory where your HTML page is located\n    python3\
    \ -m http.server 8080\n\nThen you can run your page by pointing any browser to\
    \ http://localhost:8080/your_page.html  (tested in both FireFox and Chrome)\n\n\
    2) Eventually if would like to have ROS-based system using this technology you\
    \ can consider using [roswww ROS package](http://wiki.ros.org/roswww) to serve\
    \ your application's HTML pages. We have been successfully using it for a few\
    \ years now"
