  body_markdown: " I answered myself this question in the PCL forum. I post the answer\
    \ also here because it is a problem related to ROS and PCL. \n\nThis post has\
    \ NOT been accepted by the mailing list yet.\nOkay, this one was tricky. \n\n\
    Back then, when I made the question my redaction was pretty bad. Probably that\
    \ is the reason nobody could help me. Anyway, for anyone having this problem,\
    \ first I will explain again the problem I had, and then the way I solved it!\
    \ \n\n**Objective**\nI had a *.bag file with point clouds in 'pcd' format and\
    \ the goal was to extract each of the point clouds. In order to do this I used\
    \ the bag_to_pcd node. \n\n**Procedure** \nOnce I extracted the files with ROS,\
    \ I came back to PCL, and I used the \"loadPCDFile\" function in order to open\
    \ such files. My intuition was to use a cloud with 'XYZRGB' points. This had send\
    \ because by looking into the \"bag_to_pcd\" code, the clouds contained in the\
    \ *.bag are opened as PointCloud2 and then they are transformed by using pcl_ros::transformPointCloud.\
    \ \n\n**Problem**\nThe situation is that, as strange as it may sound, I could\
    \ just see the depth data, but I could not see the RGB color: I was getting a\
    \ message saying: \"failed to find a match for field 'rgb'. This had actually\
    \ no sense because the clouds had color indeed, and I could see it using rviz.\
    \ Also I had already used the same procedure to convert a *bag dataset I downloaded\
    \ from the CV group at TUM. So, why was this not working just for one *.bag file????\n\
    \n**Solution**\nTo came to a solution, I tried several things, but I noticed that\
    \ if I opened one of those clouds using \"pcl_viewer\" from the terminal, and\
    \ I pressed then 5, I could see the color!!! \nImmediately, I went inside the\
    \ pcl_viewer.cpp code, and I noticed that the clouds are declared with the format\
    \ PointCloud2. \nMy logic was to open the clouds in the same way and then transform\
    \ them to 'XYZRGB' points. I tried both, the ROS and PCL functions to do so, but\
    \ nothing worked!!! \nThen I carefully read the whole pcl_viewer.cpp, and noticed\
    \ that they took a particular approach to color images!!! The trick is that the\
    \ PointCloud2 is just converted into a cloud with XYZ points, then a color handler\
    \ takes information directly from the cloud with format PointCloud2. Finally this\
    \ handler can be used together with the 'XYZ' cloud to color it!. \n\n**The recipe**\n\
    1.- Initialize two clouds: \npcl::PCLPointCloud2::Ptr cloud (new pcl::PCLPointCloud2);\
    \ \npcl::PointCloud<pcl::PointXYZ>::Ptr cloud_xyz (new pcl::PointCloud<pcl::PointXYZ>);\
    \ \n\n2.-  Declare a Color handler with the  'PCLPointCloud2' format: \ntypedef\
    \ pcl::visualization::PointCloudColorHandler<pcl::PCLPointCloud2> ColorHandler;\
    \ \nColorHandler::Ptr color_handler; \n\n3.- Open the cloud of interest using\
    \ the cloud with PCLPointCloud2 format: \npcl::io::loadPCDFile(\"name.pcd\", *cloud);\t\
    \n\n4.-  Use the color handler to get the RGB data: \ncolor_handler.reset (new\
    \ pcl::visualization::PointCloudColorHandlerRGBField<pcl::PCLPointCloud2> (cloud));\
    \ \n\nNow you will be able to add and see depth and color in a PCL visualizer.\
    \ \n\nI really struggled with this one, and I hope I can save some hours to someone\
    \ having the same problem. \n\nBest, \n\nRafael \n\n\n"
