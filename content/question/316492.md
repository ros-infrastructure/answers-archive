  body_markdown: "Note sure I understand well the question, but there is what you\
    \ can do with a database:\n \n1) Play database like a rosbag (though it is recommended\
    \ to use directly a rosbag if it is what you want to do): \n   \n `$ rosrun rtabmap_ros\
    \ data_player _database:=~/my_map.db --clock`\n\n 2) Start rtabmap with the database\
    \ as input, then subscribe to `/rtabmap/cloud_map` and call service `/rtabmap/publish_map`\
    \ to get the map:\n\n    $ roslaunch rtabmap_ros rtabmap.launch database_path:=~/my_map.db\n\
    \    $ rostopic echo /rtabmap/cloud_map\n    $ rosservice call /rtabmap/publish_map\
    \ 1 1 0\n\n**EDIT**\n\n3) Without rtabmap.launch:\n\n    $ roscore\n    $ export\
    \ ROS_NAMESPACE=rtabmap && rosrun rtabmap_ros rtabmap _database_path:=~/my_map.db\n\
    \    $ rostopic echo /rtabmap/cloud_map\n    $ rosservice call /rtabmap/publish_map\
    \ 1 1 0\n\n4) For RVIZ with [rtabmap_ros/MapCloud](http://wiki.ros.org/rtabmap_ros#Map_Cloud_Display)\
    \ display, launch rtabmap node in rtabmap namespace, then in RVIZ's MapCloud plugin\
    \ should be able to click on Download Map:\n\n    $ roscore\n    $ export ROS_NAMESPACE=rtabmap\
    \ && rosrun rtabmap_ros rtabmap _database_path:=~/my_map.db\n    $ rviz\n\n5)\
    \ For rtabmapviz, we can do something similar:\n\n    $ roscore\n    $ export\
    \ ROS_NAMESPACE=rtabmap && rosrun rtabmap_ros rtabmap _database_path:=~/my_map.db\n\
    \    $ export ROS_NAMESPACE=rtabmap && rosrun rtabmap_ros rtabmapviz"
