  body_markdown: "You are confusing the data types (well, they are confusing indeed).\n\
    \nThere is `geometry_msgs::TransformStamped` and `tf::StampedTransform` in ROS.\
    \ The first is just a container (C++ ROS message representation) used for data\
    \ serialization, while the second is a full-featured class that allows to manipulate\
    \ transformation matrices etc.\n\nThe code you gave the link to is using `tf::StampedTransform`.\
    \ Also it uses the old `tf` methods, where `lookupTransform` accepts only `tf`\
    \ data types and has the following signature:\n\n    void lookupTransform(const\
    \ std::string& target_frame, const std::string& source_frame,\n              \
    \             const ros::Time& time, StampedTransform& transform) const;\n\nwhile\
    \ the one you are trying to use is from `tf2`:\n\n    virtual geometry_msgs::TransformStamped\
    \ \n        lookupTransform(const std::string& target_frame, const std::string&\
    \ source_frame,\n                        const ros::Time& time, const ros::Duration\
    \ timeout) const;\n\nP.S. Most of the examples you find on ROS Answers are likely\
    \ to be for previous version of `tf`.\n\n----------\nEDIT:\n\nIf the only thing\
    \ you need is Euler angles, then it is enough. Though, if you are going to work\
    \ with the whole transform, then it is better to convert the whole `geometry_msgs::TransformStamped`\
    \ to `tf::StampedTransform`, or acquire the latter directly with `tf::lookupTransform`\
    \ (in tf1).\n\n"

EDIT:
this code works for me, if there is better way, please tell me:


     double r,y,p;
     double d1,d2,d3;
     geometry_msgs::Quaternion q = transformStamped.transform.rotation;
     tf::Quaternion tfq;
     tf::quaternionMsgToTF(q, tfq);
     tf::Matrix3x3(tfq).getEulerYPR(y,p,r);
     d1 = angles::to_degrees(y);
     d2 = angles::to_degrees(p);
     d3 = angles::to_degrees(r);
     ROS_INFO("euler-angles::to_deg y >%f<, p >%f<, r >%f<", d1, d2, d3);
