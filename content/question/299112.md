    Until ROS Bouncy, the full topic names were constructed as follow:
    `<ROS_PREFIX>/<NAMESPACE>/<TOPIC_NAME>` where:

    `ROS_PREFIX` is one of the prefixes defined [here](https://github.com/ros2/design/blob/9d971dd155be6e9c74f4e5fa4d7613a946b7d7d5/articles/140_topic_and_service_name_mapping.md#ros-specific-namespace-prefix)

    Some examples can be found [here](https://github.com/ros2/design/blob/9d971dd155be6e9c74f4e5fa4d7613a946b7d7d5/articles/140_topic_and_service_name_mapping.md#examples-of-ros-names-to-dds-concepts)

    The partition value is everything before the last forward slash. In you case I assume that the namespace is `ros`, resulting in a fully qualified topic name `rt/ros/my_topic`. This leads to the partition `rt/ros` and the topic name `my_topic`.

    Note that as of ROS Bouncy the partitions [are not used anymore](https://github.com/ros2/design/pull/170) so for the topic `rt/ros/my_topic` the partition will be an empty string and the DDS topic name will be `rt/ros/my_topic`
