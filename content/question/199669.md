    Since I'm not all that familiar with <code>rqt</code> (nor <a href="http://wiki.ros.org/rqt_image_view">rqt_image_view</a>) and I think that you may be looking for more than <a href="http://wiki.ros.org/image_view">image_view</a>, I'll have to leave it to someone else to provide an answer there. I (currently) do most of my UI work using <code>librviz</code>, which allows incorporating the various RViz pieces directly into a Qt application. The <a href="http://docs.ros.org/groovy/api/librviz_tutorial/html/">librviz tutuorial</a> is quite instructive if you choose to go this route.

    First, I'd note that image display width, height, and screen position is not really dependent on the incoming image message, but rather the graphical container, so you're thinking about that wrong. Now, with a reference to the <code>rviz::VisualizationManager</code>, you can do this:
    <pre><code>rviz::VisualizationManager* visMan;
    QString dispName("MyImage");
    QString dispPlugin("rviz/Image");
    QString imgTopic("/image/topic");
    ...
    rviz::Display *disp = visMan->createDisplay(dispPlugin, dispName);
    disp->subProp("Image Topic")->setValue(imgTopic);
    </code></pre>
    Or, if you prefer to work a little closer to basic Qt, you might do something like this:
    <pre><code>// NOTE: I'm guessing at the image format; change as needed
    // NOTE: I'm assuming the image will be displayed in a QLabel
    QLabel* m_imgLabel;<br>
    void MyClass::imageCb(const sensor_msgs::ImageConstPtr &msg) {
       // read message contents into QImage
       const unsigned char* databeg = &(msg->data.front());
       QByteArray imgData = QByteArray((char*)databeg, msg->data.size());
       QImage* qimg((uchar*)imgData.data(), msg->width, msg->height, QImage::Format_RGB32);<br>
       // stuff QLabel with QPixmap derived from the QImage
       int w = m_imgLabel->width(), h= m_imgLabel->height();
       QPixmap* qpxm;
       qpxm->convertFromImage(*qimg);
       qpxm = qpxm->scaled(w, h, Qt::KeepAspectRatio);
       m_imgLabel->setPixmap(qpxm);
    }</code></pre>
    That's just a sketch, not a full definition, and there are complexities that need to be handled (e.g., <code>QImage</code> documentation states that the data buffer must remain valid throughout the life of the <code>QImage</code>).

    It may also be instructive to look at a post (that I answered) concerning the use of <a href="http://answers.ros.org/question/188263/how-do-i-find-occupancygrid-message-data-and-how-do-i-use-it-with-qimage/">occupancy grids with QImage</a> and a post about setting up <a href="http://answers.ros.org/question/197143/multiple-views-in-a-single-rviz-instance-rqt">multiple, unadorned views in RViz</a> (that doesn't really have a solution yet).
