  body_markdown: "After comparing the configuration files in `/turtlebot_rviz_launchers/rviz`\n\
    \n> \n\n I found what seems to be a solution. When you run \n\n \n\n    roslaunch\
    \ turtlebot_rviz_launchers view_navigation.launch\n\nIt uses a configuration file\
    \ `navigation.rviz`, if you compare that to the file used by \n\n \n\n    roslaunch\
    \ turtlebot_rviz_launchers view_robot.launch \n\nwhich is `robot.rviz`, you see\
    \ that `robot.rviz` has  lines in it to add the class `rviz/InteractiveMarkers`,\n\
    evidently you can not simply add interactive markers from rviz gui, it must be\
    \ declared in the configuration file first. The file `navigation.rviz` did not\
    \ have these lines so I added them:\n\n    - Class: rviz/InteractiveMarkers\n\
    \      Enabled: false\n      Name: InteractiveMarkers\n      Show Axes: false\n\
    \      Show Descriptions: true\n      Show Visual Aids: false\n      Update Topic:\
    \ /turtlebot_marker_server/update\n      Value: false\n\nOnce I did this and launched\
    \ rviz again with above commands, the interactive marker was in rviz and when\
    \ I clicked on the interactive button, I could navigate using interactive markers\
    \ while mapping was taking place. Of course you still have to run \n\n    roslaunch\
    \ turtlebot_interactive_markers interactive_markers.launch --screen \n\n \n\n\
    I do not really understand the syntax in the *.rviz files. I could attach my modified\
    \ `navigation.rviz` so others can do a diff and see where I changed it, but I\
    \ don't have enough points.  Maybe someone can tell me if what I did is the correct\
    \ way to fix this issue or not. \n\n\n\n\n"
