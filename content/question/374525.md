I tried to control [ROSbot2.0 Pro](http://wiki.ros.org.jsk.imi.i.u-tokyo.ac.jp/Robots(2f)ROSbot(2d)2(2e)0(2d)PRO.html) by Autoware.AI. However, I can not control ROSbot2.0 Pro.

### Software Version

- Ubuntu 18.04
- Autoware.AI 14.0
- ROS melodic

### The Procedure is as follows.

1. Create ROSBAG data which contains /points_raw from RPLIDAR3 by control ROSbot2.0 PRO.
I use teleop_twist_keyboard (slow right turn).
As RPLIDAR3 publish /scan, I used laser_geometry and change topic name (/points_raw) and frame id (velodyne).
2. Create PCD map data from ROSBAG data using [blam](https://github.com/naisy/blam).
3. Create Waypoint data (csv file) from ROSBAG data and PCD map data using Autoware.AI.
4. Control ROSbot2.0 Pro by Waypoint data using Autoware.AI. As x coordinate of waypoint data is minus, I use

```
rosrun topic_tools transform vehicle_cmd /cmd_vel geometry_msgs/Twist 'geometry_msgs.msg.Twist(linear=geometry_msgs.msg.Vector3(x=abs(m.twist_cmd.twist.linear.x)),angular=geometry_msgs.msg.Vector3(z=m.twist_cmd.twist.angular.z))' --import geometry_msgs.
```

### Result

- First, ROSbot2.0 Pro does not move when I put a check mark to `ndt_matching` on Autoware runtime manager.
- And then, ROSbot2.0 Pro suddenly go straight ahead off the waypoint.

### Question

I want to know how to control this device using Autoware.AI and have some question.

1. Why is x coordinate of waypoint data is minus?
2. I think `ndt_matching` does not work well. What parameters do I need to change to make it work?
