    Nodes used in tutorials such as the [simple\_grasp.py nodes](https://bitbucket.org/osrf/sandia-hand/src/a0ba2b5fa320/ros/sandia_hand_teleop/control_nodes/simple_grasp.py?at=default) is a demonstration and may change over time.  But the underlying ROS API as specified in the [DRCSim User Guide](http://gazebosim.org/wiki/DRC/UserGuide#ROS_APIs) will be supported throughout VRC.  We'll try our best to keep the set of interfaces as stable as possible.

    We dropped the use of PR2 style controller manager given we are trying to mimic controller interface on the actual Atlas robot.  One can wrap the functionalities of [gazebo\_ros\_controller_manager](https://bitbucket.org/osrf/drcsim/src/45a23d87af80af8bbc467a58382dba903f8572d7/ros/atlas_msgs/gazebo_ros_controller_manager.h?at=default) into a [library](https://bitbucket.org/osrf/drcsim/src/670ef33a637c/ros/atlas_msgs/atlas_ros_controller_manager.h?at=joint_position_controllers) invoked through a [standalone ros node](https://bitbucket.org/osrf/drcsim/src/670ef33a637ccb7b8c9b6073f857652a92a007ec/ros/atlas_msgs/atlas_control.cpp?at=joint_position_controllers) and still be able to use the functionality offered by [pr2\_controllers](http://ros.org/wiki/pr2_controllers) and [pr2\_controller\_manager](http://ros.org/wiki/pr2_controller_manager) (e.g. FollowJointTrajectoryAction controller).

    The simple\_grasp controllers were purely intended for demonstration, just to show the hands moving in the simulator. Presumably the grasp controllers would need to be much more sophisticated to accomplish the range of tasks of the VRC. Importantly, real grasp controllers would likely need to use more features of osrf\_msgs::JointCommands messages (e.g., torque limits).

    The source for the simple\_grasp controller is [here](https://bitbucket.org/osrf/sandia-hand/src/a0ba2b5fa320e66327473d7090e809742c35fbf6/ros/sandia_hand_teleop/control_nodes/simple_grasp.py?at=default]). It's pretty short. It just does a minimal eigengrasp implementation of a few canonical grasps: cylindrical, spherical, and prismatic.

    I have updated the wiki to clarify that this is only a strawman implementation for tutorial purposes.
