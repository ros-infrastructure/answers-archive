  body_markdown: "I think this is a very interesting discussion. \nROS at the moment\
    \ neither is a realtime robotic framework nor has integration with any of these\
    \ Real Time OS. AFAIK the only you can do is send strategical/non-realtime orders\
    \ to a real-time system (ie: realtime microcontroller like arduino) and it would\
    \ be the responsable to acomplish the real time goals. See: [http://www.ros.org/wiki/rosserial](http://www.ros.org/wiki/rosserial).\
    \ Of course the realtime contstraints wouldn't be warranted until the rt-microcontroler\
    \ has received the commands (since the rosserial communications are not realtime).\n\
    \nThere are other robotic software frameworks like looks more prepared to work\
    \ for real time systems like: YARP or OROCOS.\nSee this [paper](http://www.sciencedirect.com/science/article/pii/S0921889012000322)\
    \ to know which operative systems they support.\n\nHowever there are some packages\
    \ that looks prepared to work for real time systems:\n[http://www.ros.org/wiki/pr2_mechanism?distro=groovy](http://www.ros.org/wiki/pr2_mechanism?distro=groovy)\n\
    It's not to much well explained how these mechanisms work in real time over a\
    \ non-real time system like ubuntu-linux (Perhaps they don't run on ubuntu. The\
    \ PR2 experts should know it)"
