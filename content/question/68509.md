  body_markdown: "You should subscribe to a topic - services are mostly used when\
    \ you want data infrequently, or care that the recipient is ready to process it.\
    \ For this type of communication, it's OK if messages get dropped, and you always\
    \ want to be executing the most recent command. \n\nI think that there are two\
    \ reasonable options for pre-defined messages to use:\n\n1) [turtlesim/Velocity](http://www.ros.org/doc/api/turtlesim/html/msg/Velocity.html)\n\
    \nThis is the simplest possible message, designed for a robot that can either\
    \ move forward or rotate in place. If your robot's motion is more complicated,\
    \ then this isn't an option. The advantage of this is that it's compatible with\
    \ the turtlesim tutorials, and you can use [turtle_teleop](http://ros.org/wiki/turtle_teleop)\
    \ to immediately drive your robot around. (But writing your own teleop node is\
    \ really easy!)\n\n2) [geometry_msgs/Twist](http://www.ros.org/doc/api/geometry_msgs/html/msg/Twist.html)\
    \ (traditionally published on the \"/cmd_vel\" topic)\n\nThis is what's used in\
    \ the [navigation stack](http://www.ros.org/wiki/navigation/Tutorials/RobotSetup),\
    \ and can be used to describe more complicated motion. It's probably the most\
    \ common message used for this purpose. Here's one example for a [sphero](https://github.com/mmwise/sphero_ros),\
    \ and a [stupid-simple driver for an m3pi](https://github.com/lindzey/m3pi_ros/blob/master/src/m3pi_ros.py)\
    \ that I recently wrote."
