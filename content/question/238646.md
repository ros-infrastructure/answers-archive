    \ documentation.\n\n---\n\ntl;dr: you can install ROS Indigo for `amd64` from\

    \ 14905).\n\nedit: it could be that things will improve after the Anniversary\
    \ Update (from [Microsoft/BashOnWindows#567](https://github.com/Microsoft/BashOnWindows/issues/567#issuecomment-228145474)):\n\
    \n> We are working to enhance the networking/socket level support post Anniversary\
    \ update release. Stay tuned!\n\n---\n\n(**note**: the following text is left\
    \ here for reference only. Most of the comments about the networking stack don't\
    \ apply to recent builds any more)\n\nIt's perfectly possible to install ROS on\
    \ WSL as you found out: just follow the Ubuntu Trusty installation tutorial. No\
    \ need to build from source actually, WSL supports the `amd64` architecture, which\
    \ is well supported by the ROS buildfarm.\n\nThe problem is that for ROS to be\
    \ really useful (other than just using it as a build infrastructure on a Windows10\
    \ machine) the networking support in WSL needs to be extended significantly /\
    \ finished.\n\nOne of the major problems is that raw / netlink socket support\
    \ is absent currently (build 14376 as of writing, see the WSL [release notes](https://msdn.microsoft.com/en-us/commandline/wsl/release_notes)),\
    \ which makes `getifaddrs(..)` not work. That is the cause of the backtrace @Mahmoud\
    \ Abdul Galil posts in his answer. MS is aware of this (see [Microsoft/BashOnWindows#118](https://github.com/Microsoft/BashOnWindows/issues/118),\
    \ [Microsoft/BashOnWindows#134](https://github.com/Microsoft/BashOnWindows/issues/134)\
    \ and [Microsoft/BashOnWindows#308](https://github.com/Microsoft/BashOnWindows/issues/308)),\
    \ and there is a [User Voice topic](https://wpdev.uservoice.com/forums/266908-command-prompt-console-bash-on-ubuntu-on-windo/suggestions/13383789-enable-network-interface-enumeraration)\
    \ for this, which you can vote on. I'd recommend you do that.\n\nTo get around\
    \ `getifaddrs(..)` not working, I wrote [gavanderhoorn/getifaddrs_preload](https://github.com/gavanderhoorn/getifaddrs_preload.git),\
    \ which `LD_PRELOAD`s itself and returns the minimal data needed to get `netifaces.interfaces()`\
    \ to work. This just always returns `127.0.0.1`, *and* whatever you have `ROS_IP`\
    \ set to.\n\nTo get `roscore` to start, do the following (in a WSL Bash terminal):\n\
    \n    $ export ROS_IP=<your actual IP>\n    $ export ROS_MASTER_URI=http://<your\
    \ actual ip>:11311/\n    $ source /opt/ros/indigo/setup.bash\n    $ LD_PRELOAD=/path/to/_getifaddrs.so\
    \ roscore\n\nThis `roscore` is perfectly usable: other Linux and OSX machines\
    \ can use it as well, `rostopic list`, `rosservice list` etc all work correctly.\n\
    \nBut at this point things become less interesting: as @m4k mentions, WSL doesn't\
    \ have an X server, which means no RViz, no RQT etc. WSL does have an X *client*\
    \ though (or more precisely, the Ubuntu root fs that is used does, after you install\
    \ ROS), so a Windows X-Server (such as the ones @petermitrano suggests) is enough\
    \ to get basic X working (`export DISPLAY=:0 && xcalc` fi). At this point, RQT\
    \ and RViz still crash however. I haven't put any more time in this, but I suspect\
    \ something is either not implemented in WSL, or it's running into things like\
    \ what [ros-visualization/qt_gui_core#62](https://github.com/ros-visualization/qt_gui_core/pull/62)\
    \ was meant to address. I suspect issues with getting OpenGL to work after these\
    \ are fixed as well.\n\nIgnoring GUI applications, the next limitation is in the\
    \ socket support: publishing, subscribing and service invocation typically fail\
    \ with an error such as:\n\n    Inbound TCP/IP connection failed: connection from\
    \ sender terminated before handshake header received. 0 bytes were received. \
    \ Please check sender for additional details.\n\nI've had intermittent success,\
    \ but things like `rostopic pub -r1 /chatter std_msgs/String \"data: 'bla'\"`\
    \ most of the times result in the error above, and no data being exchanged. Pub\
    \ or sub from remote machines fail similarly (but that is to be expected).\n\n\
    As to the netlink / raw socket support: there is a (small) chance that it might\
    \ have gotten more priority for the WSL dev team after [Microsoft/BashOnWindows#468](https://github.com/Microsoft/BashOnWindows/issues/468)\

Hello, everyone. 

This is rather a documentation of what I came across while messing around. Windows 10 in the latest release in April features an internal Ubuntu OS in the build, This holds the possibility for installing ROS on Ubuntu directly. 

In order to install it, I followed the instructions on building ROS from source on the wiki :
[ROS Indigo Source Installation](http://wiki.ros.org/indigo/Installation/Source)

The version of Ubuntu in Windows 10 is 14.04, so Indigo and earlier versions will work, most likely. 

Try it out, and if you face problems, please document them here.
