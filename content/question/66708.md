    The subscriptions don't block the control flow in ``main()``, so you don't need to put them in threads.  All that they do is to register the callback with the callback manager (which will not fire then until you run ``spin()``).  So, the following should work

        int main() {
          // These will not block.
          subscribe to topic X with callback X_callback
          subscribe to topic Y with callback Y_callback

          [other stuff]

          spin();
        }

  body_markdown: "The easiest way to do what you're looking for is to call `spinOnce`\
    \ in a loop.  This is non-blocking, and allows you to do other operations in \"\
    parallel\" with the callback processing.  Note that this is not truly parallel,\
    \ since this is a single-threaded model, but many applications are fine without\
    \ truly multi-threaded operations.\n\nSee [here](http://www.ros.org/wiki/roscpp/Overview/Callbacks%20and%20Spinning)\
    \ for more discussion of various spinning methods.\n\nTry something like this:\n\
    \n    my_callback(){something};\n    \n    int main(){\n      sub = node.subscribe(\"\
    topic\", &my_callback);\n\n      ros::Rate r(10); // 10 hz\n      while (ros::ok())\n\
    \      {\n        do_callback_independent_processing();\n\n        if (new_callback_data)\n\
    \          do_callback_dependent_processing();\n\n        ros::spinOnce();\n \
    \       r.sleep();\n      }\n    }\n\n**Edit:**<BR>\nIf you don't like the idea\
    \ of calling `spinOnce` in a loop, then probably the next-best choice is to use\
    \ `ASyncSpinner`.  Trying to use multiple threads and multiple calls to `ros::spin()`\
    \ is messy, and probably won't work.  `ros::spin` explicitly states that it is\
    \ designed for single-threaded nodes only.\n"
