    Is this occurring the first time after the ros master is run, or are you restarting ros nodes that were previously shut down? When a node shuts down, it may not be given enough time to unregister itself with the master, so the master thinks it is still alive. That situation causes these kinds of log messages.

    While debugging, you can use `rosnode cleanup` to check for this situation.

We sometimes experience this on a system where one of our nodes is missing (which node varies).
Looking in the logs the exit-code was 0 and apparently the node was asked to shutdown, since  a `new node registered with same name`.

However, the node that shuts down has a very different name... What could cause such name collisions?

I.e. in the log from a node named 'ssd_monitor' we see: 

    [rospy.impl.masterslave][INFO] 2023-03-08 10:51:05,684: external shutdown request from [/master]: [/rgb_light_effects] Reason: new node registered with same name
    [rospy.core][INFO] 2023-03-08 10:51:05,685: signal_shutdown [external shutdown request from [/master]: [[/rgb_light_effects] Reason: new node registered with same name]]

We do keep our roscore alive when restarting the nodes and most of the time everything starts fine. Also, the node that shuts down is different everytime, so it doesn't seem like a real name collision. But then what could cause the rosmaster to be confused like this?
Any thoughts would helpful! Thanks in advance!
