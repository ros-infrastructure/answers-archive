  body_markdown: "Hi, \n\nI have encoutered the same problem. This may possible be\
    \ caused by the name space inconsistency between robot urdf defintion and the\
    \ controller manager spawner in Gazebo. \n\nHave a check of **the robot urdf file**\
    \ first.  Find the following lines: \n\n    <gazebo>\n        <plugin filename=\"\
    libgazebo_ros_control.so\" name=\"gazebo_ros_control\">\n          <robotNamespace>/rrbot</robotNamespace>\n\
    \          <robotSimType>gazebo_ros_control/DefaultRobotHWSim</robotSimType>\n\
    \        </plugin>\n    </gazebo>\n\n\nNoticet that the **name  space** for robot\
    \ to load **gaze_ros_control** is **/rrbot**. That means that the **controller_manager\
    \ ROS interface** will be loaded in the space **/rrbot**.\n\nThen check the **launch\
    \ file that initializes the robot controller**, and find the following lines:\
    \ \n\n    <node name=\"controller_spawner\" \n          pkg=\"controller_manager\"\
    \ \n          type=\"spawner\" respawn=\"false\"\n\t      output=\"screen\" \n\
    \          ns=\"/rrbot\" \n          args=\"joint_state_controller  joint1_position_controller\
    \  joint2_position_controller\"\n    />\n\n\nHere the name space for initializing\
    \ the node (ns=\"/rrbot\") is also **/rrbot**. Then the gazebo can find the correct\
    \ controller_manager ROS interface. If this ns for **controller_manager** is different\
    \ from the above ns in **gazebo_ros_control**, then the problem occurs, i.e.,\
    \ Controller Spawner couldn't find the expected controller_manager ROS interface.\n\
    \nMake sure the name for these two name spaces are exactly same, and then restart\
    \ everything. The Controller Spawner will work properly. \n\nHope this helps you\
    \ :)"
