  body_markdown: "I think this is all explained in [wiki/catkin/workspaces](http://wiki.ros.org/catkin/workspaces).\n\
    \n> [..] build has got a folder with the package's name in which there is a CMakefiles\
    \ folder [..]\n\nFrom the wiki (emphasis mine):\n\n> 1.2 Build Space\n> \n> The\
    \ build space is where CMake is invoked to build the catkin packages in the source\
    \ space. CMake and catkin **keep their cache information and other intermediate\
    \ files here**.\n\nSo the files you found under `build/$pkg_name` are the files\
    \ that CMake (and to a certain extend Catkin) generate during what CMake calls\
    \ the *configure phase* ([random link](http://www.aosabook.org/en/cmake.html)\
    \ to a page explaining this, I couldn't find something on the CMake site. Refer\
    \ to *5.2.1 - The CMake Process - The Configure Step*). Examples are things like\
    \ `CMakeCache.txt` and friends. These are all placed in separate directories,\
    \ as mixing them wouldn't work.\n\n> [..] and a installspace folder which has\
    \ a .pc file by the package's name.\n\nFrom the wiki:\n\n> 1.3 Development (Devel)\
    \ Space\n> \n> The development space (or devel space) is **where built targets\
    \ are placed** prior to being installed. The **way targets are organized in the\
    \ devel space is the same as their layout when they are installed**.\n\nSo the\
    \ `devel` and the `install` space have their files and directories layed out in\
    \ similar ways, and they only contain *the results* of the build. For the `devel`\
    \ space that is limited to things that were generated and compiled (ie: shared\
    \ libraries and binaries) for the `install` space that includes everything that\
    \ was included in an `install(..)` statement in the `CMakeLists.txt` (and some\
    \ additional things like msg headers, but they have `install(..)` targets automagically\
    \ added).\n\nThe `.pc` files you specifically mention are [pkg-config](https://en.wikipedia.org/wiki/Pkg-config)\
    \ [files](https://people.freedesktop.org/~dbn/pkg-config-guide.html). They are\
    \ generated by the `catkin_package(..)` statement in your `CMakeLists.txt` and\
    \ include information needed by packages to successfully use and link to other\
    \ packages.\n\n> [..] devel space has got a share folder in which there is a CMake\
    \ folder with .cmake files [..]\n\nThose `.cmake` files are CMake [config files](https://cmake.org/cmake/help/v3.0/manual/cmake-packages.7.html#package-configuration-file).\
    \ They have a similar function as the `.pc` files and were also generated by `catkin_package(..)`.\n\
    \n\n> [..] and the install and src folders are untouched .\n\nI'm not sure I understand\
    \ this last bit.\n\n---\n\nFinally, you might want to read [A Gentle Introduction\
    \ to Catkin](https://jbohren.com/articles/gentle-catkin-intro#catkin-generates-pkg-config-and-cmake-config-files)\
    \ by @jbohren. Based on your previous questions I think you'll find it enlightening."
