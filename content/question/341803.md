  body_markdown: "> I don't understand why Mylib is required by package B if Package\
    \ A loaded it without problems\n\nWell, package A doesn't load the shared library\
    \ `Mylib`. You specify that whatever you compile in package A should dynamically\
    \ link to `Mylib.so`. It is not included in package A in any way.\n\nNow, if you\
    \ use whatever you compile in package A in package B, you need to tell package\
    \ B that it needs to link against whatever package A needs to link to as well.\
    \ You don't have to explicitly do this, you can actually do this as in \"hey package\
    \ B, just link against everything that package A links against\", by specifying\
    \ this correctly in the `CMakeLists.txt` of package A.\n\nThis should explain\
    \ why it is not working. If you want to know how to make it work, please post\
    \ a new question and don't forget to include a copy of your `CMakeLists.txt`,\
    \ ideally of both packages (and please remove any comments). \n\n---\n**Update**\n\
    \n> How can I say\n> \n> > \"hey package B, just link against everything that\
    \ package A links against\"?\n\nYou've already done that, via `find_package(catkin\
    \ REQUIRED COMPONENTS ... PackageA)` and `target_link_libraries(some_PackageB_cpp\
    \ ${catkin_LIBRARIES})`.\nYou don't have to specify `package_A_launcher` there\
    \ explicitely.\n\nMinor note on the `CMakeLists.txt` of PackageB: you should have\
    \ `PackageA` specified as a `CATKIN_DEPENDS`, not as a `DEPEND` in the `catkin_package`\
    \ macro. Other than that, this one seems fine. (Though I wonder why you use `mpicc`\
    \ in packageA, but not in B. Maybe this also has some influence?)\n\n\n\nYou need\
    \ to properly specify PackageA, though. I.e. you have to export to catkin/cmake,\
    \ which libraries you provide from your PackageA. Otherwise, package B cannot\
    \ find them.\n\nYou do this also in the `catkin_package` call by adding the `LIBRARIES`\
    \ and `INCLUDE_DIRS` sections. See the [catkin docs](http://docs.ros.org/melodic/api/catkin/html/howto/format2/building_libraries.html#exporting).\n\
    \nAs you provide `myLib` as a compiled `.so`, you'll have to work around a few\
    \ things, though.\nI'd recommend investigating if there is another way, e.g.\n\
    \n1. Check, if you can get it from `apt` (you'll probably have done that, though)\n\
    1. If it is a cmake project, follow the advice from #q246012\n1. If it is something\
    \ else, you're probably best of by providing a wrapper package for this. Take\
    \ [cob_extern/libntcan](https://github.com/ipa320/cob_extern/tree/indigo_dev/libntcan)\
    \ as an example on what needs to be done...\n1. you can also do the above within\
    \ your package, but I'd recommend keeping those two (PackageA and MyLib) separate..."
