    If you want to drive around on a map you need one (and usually can build one). However, to just somehow drive around for testing you can configure the global costmap the same like the local costmap or just use an empty map. Obviously global planning will only be as good as what you provide it with data, but we've used this setup to quickly test navigation controllers on our robots successfully.

  body_markdown: "It is not mandatory to have a map in order to use the Navigation\
    \ Stack (move_base).  \nIf your configuration files in YAML format use pre-Hydro\
    \ parameters (as many examples do) make sure you have set the following:  \n\n\
    \       global_costmap:\n           # Static map vs. rolling window is basically\
    \ whether to feed the costmap with a map \n           # (and have a fixed origin)\
    \ or a small rolling window centered on the robot\n    \n           # determines\
    \ whether or not to load an existent map provided by the map_server\n        \
    \   static_map: false\n    \n           # set to true to effectively remove the\
    \ need for an a priori map\n           rolling_window: true\n\nIf your configuration\
    \ files define Hydro+ features such as layered costmaps you should define empty\
    \ plugins to not load any map from the map server:\n\n    global_costmap:\n  \
    \       plugins: [] \n\nIn this case you can remove the static_map parameter as\
    \ it has been deprecated.\n"

I would like to mess around with the ROS navigation stack with a custom robot that I've built. I'm trying to figure out if it can be used to navigate in a previously unknown environment. The [tutorial for setting up a robot to use the nav stack](http://wiki.ros.org/navigation/Tutorials/RobotSetup#Mapping_.28map_server.29) states that a map is not required. But [this page on map building](http://wiki.ros.org/navigation/MapBuilding) says that it does requires a static map. Aren't these statements contradictory? Which is true?
