    \ a publisher using String. and don't bother defining the string. Sends an empty\
    \ message and it triggers the event I want.\n\nThere is an [Empty](http://docs.ros.org/en/api/std_msgs/html/msg/Empty.html)\
    \ message in `std_msgs`, perhaps you could use that. You'd still be publishing\
    \ something, it just doesn't have any contents.\n\nAlthough if you're not looking\
    \ for fire-and-forget semantics, using a service may be better. There's [Empty](http://docs.ros.org/en/api/std_srvs/html/srv/Empty.html)\
    \ there as well, and [Trigger](http://docs.ros.org/en/api/std_srvs/html/srv/Trigger.html).\n\
    \n> However, I can't imagine there isnt a simple signal that can be linked like\
    \ pub/sub that doesn't require a data_class, unlike Publishers. \n\nI'm not entirely\
    \ sure how to take this comment. Nodes can communicate in three ways:\n\n 1. topics\n\
    \ 1. services\n 1. actions (sort-of a hybrid, or asynchronous services with feedback)\n\
    \nin all cases, *something* will have to be exchanged. There is no other way.\n\
    \nAnd all of it is only done because the publisher or client has the intention\
    \ to communicate.\n\nEven in Qt (which I believe you're referring to in your question),\
    \ there is data exchanged. It may not be visible to you at the API/application\
    \ level, but it's certainly there (invoking a function / method is essentially\
    \ data exchange).\n\nPublish-subscribe can be used to implement an Observer pattern,\
    \ but it's not the same thing.\n"
