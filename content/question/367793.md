  body_markdown: "I think this question is also related so I recommend to check it\
    \ out first: \nhttps://answers.ros.org/question/319867/ros2-colcon-build-not-getting-subfolders/\n\
    \nWhen ROS2 builds the src files with colcon, it puts the python files into `workspace/install/lib/python3.8/site-packages/<package_name>`.\
    \ This folder is considered as the root of python packages in the given ROS 2\
    \ package. \n\nIf you can find the python files there, then you can use the following\
    \ import statement: `import .<file_name>`. Note the `.` at the start of the import.\
    \ You don't have to edit nothing else.\n\nIf you want to put the imported files\
    \ into submodules, then you have to achieve that they show up in the `workspace/install/lib/python3.8/site-packages/<package_name>/<submodule_name>`\
    \ folder. This can be done by replacing the `packages` argument in the `setup.py`\
    \ file to the following: `packages=[\"<package_name>\", \"<packages_name>/<submodule_name>\"\
    ]`. This way the import statement is `import .<submodule_name>.<file_name>`.\n\
    \nExample file structure to import with submodule:\n\n    workspace\n    |-> ...\n\
    \    |-> src\n          |-> mypackage\n                 |-> mypackage\n      \
    \                  |-> submodules\n                               |->__init__.py\n\
    \                               |-> imported.py\n                        |-> __init__.py\n\
    \                        |-> main.py\n                 |-> resource\n        \
    \                |-> ...\n                 |-> test\n                        |->\
    \ ...\n                 |-> package.xml\n                 |-> setup.cfg\n    \
    \             |-> setup.py\n    \n`setup.py`:\n\n    from setuptools import setup\n\
    \    \n    package_name = 'mypackage'\n    submodules = \"mypackage/submodules\"\
    \n    \n    setup(\n        name=package_name,\n        version='0.0.0',\n   \
    \     packages=[package_name, submodules],\n        data_files=[\n           \
    \ ('share/ament_index/resource_index/packages',\n                ['resource/'\
    \ + package_name]),\n            ('share/' + package_name, ['package.xml']),\n\
    \        ],\n        install_requires=['setuptools'],\n        zip_safe=True,\n\
    \        maintainer='TODO',\n        maintainer_email='TODO@email.com',\n    \
    \    description='TODO: Package description',\n        license='TODO: License\
    \ declaration',\n        tests_require=['pytest'],\n        entry_points={\n \
    \           'console_scripts': [\n                'main = mypackage.main:main',\n\
    \            ],\n        },\n    )\n\n`main.py`:\n\n    from .submodules.imported\
    \ import function\n    \n    \n    def main():\n        function()\n    \n   \
    \ \n    if __name__ == '__main__':\n        main()\n\n`imported.py`:\n\n    def\
    \ function():\n        print(\"hello world\")"

It was designed to be used in the "ROS" way: you have to build the workspace first, then you can run your program with the `ros2 run` command. As far as I know, it is not really compatible with "just running files". The build system is not allowing it to see the submodules in the usual way. I agree this is a disadvantage as it slows down development and makes things more complicated, but for now, this is the cost of the necessary build tool due to platform independentness.
      To correct this issue, either colcon should be changed, or ROS 2 should use a different build tool or build method.
