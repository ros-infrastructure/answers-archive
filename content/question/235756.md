  body_markdown: "There are actually quite a lot of cheesy things in your configuration\
    \ files.\n\nIn ekf_localization_node:\n\n    <param name=\"map_frame\" value=\"\
    /odometry/gps\"/> \n    <param name=\"world_frame\" value=\"/odometry/gps\"/>\n\
    \n`map_frame` and `world_frame` should be the world reference frame (typically\
    \ \"map\"). If you have a map and are fusing GPS, both should be the same. `/odometry/gps`\
    \ doesn't look like a reference frame, but a topic.\n\nAlso, when using GPS, I\
    \ think \n\n    <param name=\"odom0_differential\" value=\"true\"/>\n\nshould\
    \ be false.\n\nStart by fixing these issues and check back.\n\nEDIT:\n\nAnother\
    \ issue I see is that you are using only one EKF node, and using in the navsat\
    \ as odometry input the output from this EKF. That is not correct, since the EKF\
    \ uses as input the output from the navsat, and as both need the output from the\
    \ other, no one is going to publish anything.\n\nI think you should at least use\
    \ another source of odometry for the EKF in order for it to start. It can be a\
    \ fake one with a very high covariance.\n\nAlso, I'm not sure if something is\
    \ providing the odom-->base_link transformation, which would also be necessary.\n\
    \nFinally, altough you see that nodes are linked in the graph, that doesn't mean\
    \ that messages are being published. Only that they are subscribed/publishing\
    \ the correct topics.\n"
