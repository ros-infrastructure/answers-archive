    This happens when processing takes more time than the one set by the controller frequency. As a result the calculated velocities do no match the preset publish frequencies and you notice jerks in movement.
    Could you monitor your CPU usage?
    If you see this happen after running for a while, it might be the case that your CPU usage is higher due to other processes.
  comments:
  - body_markdown: |-
      Actually i found the problem and it was that in the amcl parameters i set `transform_tolerance` too low so it does not match the TF publishing frequency and that causes the delay in the controller loop. So i solved the problem by setting the `transform_tolerance` to 0.3 and everything works fine.
