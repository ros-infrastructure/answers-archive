  body_markdown: "Follow up of answer given at https://answers.ros.org/question/299305/how-is-the-size-of-a-string-allocated-in-ros2-idl/?answer=299311#post-id-299311\n\
    \nThe way unbounded string are generated for connext is by using the `-unboundedSupport`\
    \ flag of the connext generator: https://github.com/ros2/rosidl_typesupport_connext/blob/d3fd38825c4e460e156718c360886b43b20cc0c8/rosidl_typesupport_connext_cpp/rosidl_typesupport_connext_cpp/__init__.py#L79.\n\
    \nBy not passing this flag when generating the connext code it should default\
    \ to 255 as per their help message\n\n    -unboundedSupport Generates code that\
    \ supports unbounded sequences and \n            strings.\n            This option\
    \ is not supported in ADA.\n            When the option is used the command-line\
    \ options sequenceSize and\n            stringSize are ignored.\n            This\
    \ option also affects the way unbounded sequences are deserialized. \n       \
    \     When a sequence is being received into a sample from the DataReader's\n\
    \            cache, the old memory for the sequence will be deallocated and memory\n\
    \            of sufficient size to hold the deserialized data will be allocated.\n\
    \            When initially constructed, sequences will not preallocate any \n\
    \            elements having a maximum of zero elements.\n    -stringSize <Unbounded\
    \ strings size>: Size assigned to unbounded strings\n            The default value\
    \ is 255\n\nNote that based on the help message the size of the string allocated\
    \ should be `0` and reallocated when needed so you should never reach the point\
    \ where you allocate `2147483647 bytes`.\n\nA maybe easier way to fix your issue\
    \ is to use the same ` -unboundedSupport` flag when generating code for your native\
    \ DDS application, this way you don't need to modify either the msg files or the\
    \ Connext code generation within ROS 2."

I am currently interfacing ROS2 with native RTI DDS Connext through RTI Connector for python.

In my ROS2 node, I have a custom message type which uses `header` messages from `std_msgs`. Now the `header` has a member `string frame_id_`. When the idl is generated for this msg, the size of the string is allocated as `2147483647 bytes`. I can see this in the RTI Admin console. Now to match the Types in native DDS and ROS2, I need to give the same string size in RTI Connext through a QoS.xml file. But the problem is, this is too big a size for RTI to handle and the program crashes.

As a workaround, I modified the `header_.idl` in ROS2 lying in `ROS2_base_ws/install/std_msgs/dds_connext/Header_.idl` as `string<255> frame_id_` i.e. I limited the max size of this string.

I recompiled it and ran the same node, but it always has the previous size i.e. `2147483647 bytes` 

Any other workaround ?
