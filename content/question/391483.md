  body_markdown: "Hi @Masoum, the following are definitions from the [robot_localization\
    \ package](http://docs.ros.org/en/kinetic/api/robot_localization/html/state_estimation_nodes.html#process-noise-covariance)\n\
    \n\n> The **estimate covariance**, commonly\n> denoted **P or R**, defines the\
    \ error in the\n> current state estimate. The parameter\n> allows users to set\
    \ the initial value\n> for the matrix, which will affect how\n> quickly the filter\
    \ converges. For\n> example, if users set the value at\n> position [0,0] to a\
    \ very small value,\n> e.g., 1e-12, and then attempt to fuse\n> measurements of\
    \ X position with a high\n> variance value for X, then the filter\n> will be very\
    \ slow to \u201Ctrust\u201D those\n> measurements, and the time required\n> for\
    \ convergence will increase. Again,\n> users should take care with this\n> parameter.\
    \ When only fusing velocity\n> data (e.g., no absolute pose\n> information), users\
    \ will likely not\n> want to set the initial covariance\n> values for the absolute\
    \ pose variables\n> to large numbers. This is because\n> those errors are going\
    \ to grow without\n> bound (owing to the lack of absolute\n> pose measurements\
    \ to reduce the\n> error), and starting them with large\n> values will not benefit\
    \ the state\n> estimate.\n> \n> The **process noise covariance**, commonly\n>\
    \ denoted Q, is used to model\n> uncertainty in the prediction stage of\n> the\
    \ filtering algorithms. It can be\n> difficult to tune, and has been\n> exposed\
    \ as a parameter for easier\n> customization. This parameter can be\n> left alone,\
    \ but you will achieve\n> superior results by tuning it. In\n> general, the larger\
    \ the value for **Q**\n> relative to the variance for a given\n> variable in an\
    \ input message, the\n> faster the filter will converge to the\n> value in the\
    \ measurement.\n\nThere are many methods to initialize the covariances. As stated\
    \ in the robot_localization package, one approach is to use trial and error, others\
    \ call it engineer's intuition. You can start by working with very small values\
    \ and measure the results based on time to converge. For the process noise covariance,\
    \ you can tune by starting 'high' and lowering until you are satisfied. The disadvantage\
    \ of this method is that is time consuming and there are many combinations possible.\
    \ You will be optimizing one parameter at the time.\n\nIf you are looking for\
    \ a systematic approach, you can use the proposed method in this paper:\nhttps://arxiv.org/ftp/arxiv/papers/1702/1702.00884.pdf.\
    \ The paper proposes for example to use the ratio of Q/R looking for smallest\
    \ SME (square mean error) to find the best performance, rather than optimizing\
    \ one parameter at the time. But it's not the only proposed approach in this paper,\
    \ there are more. I'd highly recommend reading it. \n\nAnother approach I have\
    \ seen is to use PSO (Particle Swarm Optimization) for EKF tuning with great results:\
    \ https://www.naun.org/main/NAUN/circuitssystemssignal/cssp-101.pdf. This is a\
    \ more consistent approach to finding parameters, however is more complex to implement."
