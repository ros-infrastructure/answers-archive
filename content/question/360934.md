I am setting the PR2 model to random start configurations using /gazebo/set_model_state by first stopping the PR2 controllers then doing

        // set base in gazebo
        set_gazebo_model_state(name_, currentBaseTransform_);

        // set joint position in gazebo
        gazebo_msgs::SetModelConfigurationRequest model_configuration;
        model_configuration.urdf_param_name = "robot_description";
        model_configuration.model_name = (std::string) name_;
        model_configuration.joint_names = joint_names_;
        model_configuration.joint_positions = current_joint_values_;

        gazebo_msgs::SetModelConfiguration srv2;
        srv2.request = model_configuration;
        if (!set_model_configuration_client_.call(srv2)) {
            ROS_INFO("set_model_configuration_client_ failed");
        };

then re-starting the controllers.

In the gazebo GUI this leads to the correct robot configuration being displayed, both visually and when selecting the joints.

But listening to `/joint_states` (as e.g. moveit does to plan trajectories), most joint values appear to be those that I've set. Except that there are always one or two with unrealistically high values. It appears to me that these are shifted by a multiple of pu (e.g. if I set the joint to 0.28, it will read `0.28 + x*pi` with some random x).

I don't know why it would do this, but it seems that this leads the controllers to fail when trying to execute plans in joint space as joint values are now out of bound.
Any help as to how I might correct this would be greatly appreciated  (or whether actually something completely else is the problem).

I'm using ROS melodic on Ubuntu 18.04.
