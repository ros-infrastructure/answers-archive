  body_markdown: " 1. [visio2_ros](http://wiki.ros.org/viso2_ros) has a [kinetic branch](https://github.com/srv/viso2)\
    \ in github. It supports kinetic. \n 2. Bucketing parameters : If you extract\
    \ features from an image, usually a feature rich environment would produce most\
    \ of the features and the other parts of the image will be underrepresented. Therefore\
    \ image is gridded into **buckets** and at most *n* number of features from each\
    \ bucket are extracted. Once you understand this concept, `~max_features`, `~bucket_width`,\
    \ `~bucket_height` are self explanatory parameters.\n 3. Matcher parameters are\
    \ used to configure the feature matching algorithm. For an example, `~nms_n` and\
    \ `~nms_tau` parameters are used in the [non-maxima-suppression](https://en.wikipedia.org/wiki/Canny_edge_detector#Non-maximum_suppression).\
    \ It is a good idea to start with default values if you don't have insight into\
    \ what these parameters mean.\n 4. Monocular visual odometry can't solve scale.\
    \ This is why you need to give the camera height and camera pitch as parameters.\
    \ You can read the pitch from your IMU and height from your sonar (I believe you\
    \ have previously asked a question with that setup and I assume you haven't changed\
    \ the setup). You can dynamically change the parameters using the [cpp API](http://wiki.ros.org/roscpp/Overview/Parameter%20Server#Setting_Parameters).\
    \ Alternatively, there is a Python API as well. \n 5. As for where these parameters\
    \ need to be set, all static parameters can be set in the launch file using a\
    \ parameters.yaml. [This](https://riptutorial.com/ros/example/24423/launch-ros-nodes-and-load-parameters-from-yaml-file)\
    \ is a good tutorial. \nYou can set the dynamic parameters using the cpp API as\
    \ meantioned in [4]."

  body_markdown: |-
    Viso2 has been developed for forward looking cameras in cars. For mono VO it needs the camera pitch and distance to the ground to estimate the scale (it does a ground plane estimation with those parameters). For downward looking cameras from drones [lsd_slam](https://github.com/tum-vision/lsd_slam) should be better suited.
    See also http://www.ros.org/news/2014/12/ardrone-autonomous-indoor-navigation-by-3d-slam.html
