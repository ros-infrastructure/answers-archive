  body_markdown: "I'll give answering this a try:\n\nThe long story short is `StringConstPtr`\
    \ is just a shortcut  to `String::ConstPtr` and can be used interchangeably. There\
    \ may be some implications but I have not found them yet.\n\nFor the longer answer\
    \ we have to look at the relevant code. If you have a strong grasp of cpp you\
    \ can probably pick out what is going on in the code which looks like this (in\
    \ ROS1) from `std_msgs/String.h`:\n\n    namespace std_msgs\n    {\n    template\
    \ <class ContainerAllocator>\n    struct String_\n    {\n      typedef String_<ContainerAllocator>\
    \ Type;\n\n      String_()\n        : data()  {\n        }\n      String_(const\
    \ ContainerAllocator& _alloc)\n        : data(_alloc)  {\n      (void)_alloc;\n\
    \        }\n\n      typedef std::basic_string<char, std::char_traits<char>, typename\
    \ ContainerAllocator::template rebind<char>::other >  _data_type;\n      _data_type\
    \ data;\n\n      typedef boost::shared_ptr< ::std_msgs::String_<ContainerAllocator>\
    \ > Ptr;\n      typedef boost::shared_ptr< ::std_msgs::String_<ContainerAllocator>\
    \ const> ConstPtr;\n\n    }; // struct String_\n\n    typedef ::std_msgs::String_<std::allocator<void>\
    \ > String;\n\n    typedef boost::shared_ptr< ::std_msgs::String > StringPtr;\n\
    \    typedef boost::shared_ptr< ::std_msgs::String const> StringConstPtr;\n  \
    \  }\n\n\nIf you don't have a strong grasp on cpp (or at least templating), I\
    \ will try and explain below.\n\nThe following block of code defines the template\
    \ of a struct that represents our string message. It is templated based on the\
    \ type of allocator you give it. It internally has some type definitions, constructors,\
    \ and the storage of our message data (named `data` in this case).\n\n    template\
    \ <class ContainerAllocator>\n    struct String_\n    {\n      typedef String_<ContainerAllocator>\
    \ Type;\n\n      String_()\n        : data()  {\n        }\n      String_(const\
    \ ContainerAllocator& _alloc)\n        : data(_alloc)  {\n      (void)_alloc;\n\
    \        }\n\n      typedef std::basic_string<char, std::char_traits<char>, typename\
    \ ContainerAllocator::template rebind<char>::other >  _data_type;\n      _data_type\
    \ data;\n\n      typedef boost::shared_ptr< ::std_msgs::String_<ContainerAllocator>\
    \ > Ptr;\n      typedef boost::shared_ptr< ::std_msgs::String_<ContainerAllocator>\
    \ const> ConstPtr;\n\n    }; // struct String_\n\n\nThe next line gives that template\
    \ an allocator of type `std::allocator<void>` and allows you to access the resulting\
    \ struct through the type `String`. Note that internally the struct gives us the\
    \ `Ptr` and `ConstPtr` type. Combined this gives us the `String::Ptr` and `String::ConstPtr`\
    \ types. \n\n    typedef ::std_msgs::String_<std::allocator<void> > String;\n\n\
    The final two lines are essentially the shortcuts. They are redundant to the types\
    \ defined in the struct.\n\n    typedef boost::shared_ptr< ::std_msgs::String\
    \ > StringPtr;\n    typedef boost::shared_ptr< ::std_msgs::String const> StringConstPtr;\n\
    \nIt should be noted that **ALL** of these are creating the message using the\
    \ default allocator `std::allocator`. It is possible to create custom allocators\
    \ but that is probably beyond the scope of this question.\n"
