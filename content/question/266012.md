    \ I used #q189299 as a starting point:\n\n    XmlRpc::XmlRpcValue list1;\n   \

    \ it = list1.begin();\n        it != list1.end(); ++it)\n    { \n      ROS_INFO_STREAM(it->first);\n\
    \      XmlRpc::XmlRpcValue list2 = it->second;\n      for(XmlRpc::XmlRpcValue::ValueStruct::const_iterator\
    \ it2 = list2.begin();\n          it2 != list2.end(); ++it2)\n      { \n     \
    \   XmlRpc::XmlRpcValue xml_rpc_value = it2->second;\n        if (xml_rpc_value.getType()\
    \ != XmlRpc::XmlRpcValue::TypeDouble)\n          continue;\n\n        const double\
    \ value = static_cast<double>(xml_rpc_value);\n        ROS_INFO_STREAM(it2->first\
    \ << \" \" << value);\n      }\n    }\n\n\nWhat is maybe less efficient but uses\
    \ more familiar standard C++ string operations instead of xmlrpc is to use getParamNames\
    \ to get **all** the parameters then search through them for the tree you want\
    \ ('home') and populate your map of maps manually.\n\n      std::vector<std::string>\
    \ keys;\n      nh.getParamNames(keys);\n    \n      // or provide via param, or\

    ;   // don't forget the leading slash\n\n      ROS_INFO_STREAM(ns);\n    \n  \
    \    for (size_t i = 0; i < keys.size(); ++i)\n      {\n        ... if keys[i]\
    \ doesn't have a substring match of base_namespace then continue\n        ...\
    \ remove base_namespace from keys[i]\n        ... split keys[i] into a vector\
    \ of strings using '/' as a delimiter\n        ... test if there are more or less\
    \ split keys than expected (!= 3)\n        // populate the nested maps \n    \
    \    ... create route_home[split_keys[0]] if it doesn't already exist, then\n\
    \        route_home[split_keys[0]][split_keys[1]] = split_keys[2];\n      }\n\n\

I am writing a node that will read a YAML file (loaded from roslaunch) with the following structure:

    home:
      1:
        "x": 0.0
        "y": 0.0
        "z": 0.0
        "qx": 0.0
        "qy": 0.0
        "qz": 0.0
        "qw": 0.0
      2:
        "x": 0.0
        "y": 0.0
        "z": 0.0
        "qx": 0.0
        "qy": 0.0
        "qz": 0.0
        "qw": 0.0

This is the relevant code on the node side:

    class RouteParserNode
    {
        public:
            RouteParserNode() :
                nh_private_("~")
            {
                nh_private_.getParam("home", route_home);
            };
            ~RouteParserNode();
         private:
            std::map<int, std::map<std::string, double>> route_home;
            ros::NodeHandle nh_private_;
    };

However, the above node cannot be compiled and gives the following error:

    error: no matching function for call to ‘ros::NodeHandle::getParam(const char 
    [5], std::map<int, std::map<std::basic_string<char>, double> >&)’
                 nh_private_.getParam("home", route_home);

which I assume is because getParam does not work for nested std::maps.

I am currently on ROS Indigo.

Is there a workaround for this, or another way for me to parse the file? My ultimate goal is to supply a list of goals (geometry_msgs/PoseStamped, but only primitive types were allowed for the std::map method hence the above yaml structure).
