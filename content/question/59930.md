  body_markdown: "In case of crashes, please do the following (not specific to rgbdslam):\n\
    \n\n- In your launchfile, set the launch-prefix in the rgbdslam node-tag to a\
    \ debugger and\n- Set the \"output\" attribute of the node-tag to \"screen\" e.g.\
    \ `<node pkg=\"rgbdslam\" type=\"rgbdslam\" name=\"rgbdslam\" cwd=\"node\" required=\"\
    true\" output=\"screen\"  launch-prefix=\"/usr/bin/xterm -rv -e gdb -ex run -args\"\
    > `\n\n- Launch the launch-file. An extra terminal \"xterm\" will be opened.\n\
    - When the program crashes, check the error message in the xterm window\n- In\
    \ the xterm window, run `backtrace`. Also helpful:\n 1. jump to the first frame\
    \ (lowest number) where the path of the file location contains \"rgbdslam\". In\
    \ the above question post, this would be done by `frame 2`\n 1. use `list` to\
    \ print some of the source code of that frame, centered at the line that provoked\
    \ the crash.\n 1. use `print <variablename>` to inspect values of variables that\
    \ may be involved in the crash (e.g., pointer values, array indices...)\n- Post\
    \ the output of these commands and some output of rgbdslam before\n- Format it\
    \ as code (the button with the 1s and the 0s)\n\nThanks for helping\n\nEdit:\n\
    \n> Hm, the backtrace is interesting. The\n> segfault happens in the visualization\n\
    > code, which explains, why it works\n> (longer) in headless mode. I can not\n\
    > reproduce the problem. However, here are some\n> thoughts:\n>   \n> - I've found\
    \ and fixed a bug concerning the deletion of clouds. Please update (you\n> are\
    \ using the code from the\n> alufr-ros-pkg repository on google\n> code, I assume)\
    \ and recompile. It may\n> be the source of your problem.\n> - If you are running\
    \ low on main memory, you could try to uncomment\n> `#ADD_DEFINITIONS(-DRGB_IS_4TH_DIM)\
    \ `\n> in CMakeLists.txt an recompile. This\n> effectively halves the size of\
    \ the\n> clouds in memory, but requires rgbdslam\n> to compute the cloud itself\
    \ from rgb image and\n> depth image, which means you may not subscribe to the\
    \ \".../points\" topic.\n> - Setting values > 1 for the parameter visualization_skip_step\
    \ in your\n> launchfile will also reduce the impact\n> on memory (including the\
    \ memory of the\n> graphics card)\n> - Exit code -6 is fine (it's a workaround\
    \ to a deadlock on exit), -11\n> is memory access releated.\n> - If you want the\
    \ GUI, but don't need the 3D view set the parameter\n> \"use_glwidget\" to false\n\
    \nEdit2:\n\nConcerning the second traceback: This error is very weird, in particular\
    \ as it occurs after the 430th frame. I've never had this problem, opencv should\
    \ choose the data type on its own. Since it doesn't do so, try the following.\
    \ At the end of the file src/node.cpp, could you please replace\n\n    cv::reduce(descriptors,\
    \ sums_vec, 1 /*sum over columns*/, CV_REDUCE_SUM);\n\nby\n\n    cv::reduce(descriptors,\
    \ sums_vec, 1 /*sum over columns*/, CV_REDUCE_SUM, CV_32FC1);\n\nThen recompile."
