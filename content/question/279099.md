  body_markdown: "If that is your launch file, I believe you are missing some important\
    \ parameters for this to work correctly.\n\nThe [launch file](https://github.com/ros-teleop/teleop_twist_joy/blob/3e39c1304b4351c61674c18d663b8befa4eef627/launch/teleop.launch)\
    \ for `teleop_twist_joy` sets (among others) the `autorepeat_rate` parameter for\
    \ the `joy_node` node, which is probably what is causing the issues here.\n\n\
    > Is it a problem with the publishing rate in hertz?\n\nIn a way: yes. Without\
    \ `autorepeat_rate`, joysticks in event mode will not cause any msgs to be sent\
    \ without any changes being detected to any of the axes. If you maintain stick\
    \ position (ie: angles), nothing will change (due to filtering/deadzone), causing\
    \ no msgs to be published. No messages -> auto stop (in well-written mobile base\
    \ drivers, that is, see [here](https://github.com/ros/ros_tutorials/blob/138eb3b66a51261457fda764e0b5d3bb74a170e0/turtlesim/src/turtle.cpp#L146-L150)\
    \ for how this is implemented in `turtlesim`).\n\nFrom the [joy](http://wiki.ros.org/joy)\
    \ wiki page:\n\n> `~autorepeat_rate` (`double`, default: 0.0 (disabled))\n> \n\
    > Rate in Hz at which a joystick that has a non-changing state will resend the\
    \ previously sent message. \n\nI would recommend to alter your launch file to\
    \ `include` the `teleop_twist_joy/launch/teleop.launch` file, instead of starting\
    \ the node directly (note that you also don't need to start the `joy_node` itself\
    \ anymore in that case). That will set all parameters as they should be, and things\
    \ should start working a whole lot better. See also the [teleop_twist_joy](http://wiki.ros.org/teleop_twist_joy)\
    \ documentation on the ROS wiki.\n\nIncluding provided launch files is in general\
    \ always a good strategy btw, as typically launch files configure parameters that\
    \ the node needs. Defaults can work, but they are always going to be sub-optimal.\n\
    \n---\n\nEdit: and if you want to go a step further, you could look into including\
    \ some of the packages from the Turtlebot, such as [yocs_cmd_vel_mux](http://wiki.ros.org/yocs_cmd_vel_mux)\
    \ (multiplexing between different `Twist` sources) and [yocs_velocity_smoother](http://wiki.ros.org/yocs_velocity_smoother)\
    \ (filter for `Twist` inputs)."
