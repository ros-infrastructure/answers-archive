    \ in your project you might have a node that reads sensor data -let's call it\
    \ `read_temp`- and another that processes it (`process_temp`). You write the code\
    \ for each node independently and set them up such that the `read_temp` sends\
    \ data to `process_temp`: **ROS facilitates modularity**. \n \nThis node reads\
    \ gyro and accelerometer data from a MPU9250 sensor. I'm using a library called\
    \ `FaBo9Axis_MPU9250` written for raspberry pi to do exactly that. Note that the\
    \ library itself has nothing to do with ROS-it's simply an interface to the sensor.\
    \     \n\n    #!/usr/bin/env python\n    from math import pi\n    import rospy\n\
    \    import FaBo9Axis_MPU9250\n    from sensor_msgs.msg import Imu\n    \n   \
    \ mpu9250 = FaBo9Axis_MPU9250.MPU9250()\n    rospy.init_node('imu')\n    \n  \
    \  pub = rospy.Publisher('imu/data_raw',Imu, queue_size = 1)\n    \n    msg =\
    \ Imu()\n    msg.orientation_covariance[0] = -1\n    msg.header.frame_id = 'imu'\n\
    \    rate = rospy.Rate(100)\n    \n    while not rospy.is_shutdown():\n    \t\
    accel = mpu9250.readAccel()\n    \tgyro = mpu9250.readGyro()\n    \t\n    \tmsg.header.stamp\
