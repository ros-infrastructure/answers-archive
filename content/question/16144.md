    I think this happens because of the [<state>](https://gist.github.com/lobachevzky/9ab925fcf50997ae4e50d427e51017d4#file-shifty-world-L707) tag in your world file.

    Basically, when Gazebo loads the world, it first loads the `<world>` tag and then applies the state changes described in `<state>`. When you reset the world, it goes back to before the states, so the world looks different from when you first loaded it.

    The solution is to remove the state tags and apply those changes directly in the first world description.

    (You might have generated this world by saving it through the Gazebo UI, correct? I just ticketed an [issue](https://bitbucket.org/osrf/gazebo/issues/2278/saved-worlds-have-a-tag-which-mess-up) about this)
