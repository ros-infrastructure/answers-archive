  body_markdown: "Please see [wiki/ROS/MultipleMachines](http://wiki.ros.org/ROS/Tutorials/MultipleMachines).\n\
    \nYou only run a single master, so both `ROS_MASTER_URI` variables should point\
    \ to the same IP (ie: the one running your `roscore`).\n\nAdditionally: the value\
    \ of `ROS_HOSTNAME` is used by ROS nodes to identify who is 'talking' to them.\
    \ But `localhost` is a special hostname, that will (should?) always resolve to\
    \ the local machine (at `127.0.0.1`). It is therefore not usable to configure\
    \ a distributed (ie: networked) ROS nodegraph.\n\nMake sure to use either globally\
    \ resolvable hostnames *or* don't set `ROS_HOSTNAME`, but set `ROS_IP` to the\
    \ IP of the network interface that you use to connect both computers to the same\
    \ network.\n\n---\n\nEdit: the first version of your question used `localhost`\
    \ everywhere, the second `c3po` and `r2d2` and your last version now uses `alpha`\
    \ and `betha`. Can you confirm that those hostnames actually resolve to IPs? The\
    \ values you set for `ROS_HOSTNAME` have to actually be existing hosts on your\
    \ network, you cannot just make something up.\n\nOn `alpha`, what is the output\
    \ of `ping betha` (or on `c3po`, what is the output of `r2d2`)?\n\n---\n\n>  \
    \   export ROS_HOSTNAME=r2d2 \n    export ROS_MASTER_URI=http://c3po:11311\n\n\
    Edit 2: just making sure: you are `export`ing those variables in all terminals\
    \ that you start ROS programs in? Or do you have those `export` lines added to\
    \ your `.bashrc`?\n\nIf you haven't, add the `export` lines to your `.bashrc`\
    \ on both machines (for now, at least). Close all terminals.\n\nNow on `c3po`:\n\
    \n - open a new terminal: start `roscore` in it\n - open a new terminal: run the\
    \ following:\n\n        rostopic pub -r1 /chatter std_msgs/String \"something\"\
    \n\nNow on `r2d2`:\n\n - open a new terminal: run the following:\n\n        rostopic\
    \ echo /chatter\n\nyou should now see `rostopic` printing \"something\" once per\
    \ second.\n\nTo make sure everything us working, do the reverse (so start `rostopic\
    \ pub -r1 ..` on `r2d2` and `rostopic echo ..` on `c3po`).\n\nIf you don't get\
    \ any output from `rostopic echo ..` on `r2d2`, your network setup is not correct.\
    \ In that case, try a `rosnode ping /rosout` on `r2d2`."
