  body_markdown: "Yep, I'm having the same problem.  It looks like what's happening\
    \ is that when we update the servo command with a new command, it simply ORs the\
    \ bits together.  \n\nIn other words, if your first command was 5, which is 00000101\
    \ in binary, and you send over 3 as your next command, which is 00000011 in binary,\
    \ the next value will be 7, which is 00000111 in binary.\n\nIt looks like this\
    \ problem has already been solved here\n\nhttps://kforge.ros.org/rosserial/hg/rev/10cb30606b34\n\
    \nbut I don't know how to apply it.\n\nI've removed the old copy of rosserial\
    \ in /opt/ros/electric/stacks and added the new version from the trunk into my\
    \ ROS package path, but I still get the same error.\n\nAny thoughts?\n\n\n\n(I'm\
    \ also running Electric.)\n\nUPDATE:  Whoop--it looks like I've discovered the\
    \ answer! Here's what I did:\n\nNote: I've only gotten this to work with *electric*.\n\
    \n 1. Remove the old version of *rosserial*.\n 2. acquire the updated version\
    \ of *rosserial* using mercurial here:\nhttps://kforge.ros.org/rosserial/hg/\n\
    \ 3. **rosmake** it and put the *libraries* folder in your Arduino *sketchbook*.\n\
    \ 4. Make sure you're using Arduino 1.0\n\n(My problem was that I was still running\
    \ version 022.)\n\nHope this helps!\n\n(Thanks, Mike Ferguson!)"
