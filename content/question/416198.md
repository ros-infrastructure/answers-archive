  body_markdown: "Sounds like you're making your software as \"ament-compatible package\"\
    \ or just \"ament package\" (*1) as you use `colcon` to build. `colcon` and `ament`\
    \ are IINM made along with primarilly ROS2 framework in mind, but they are independent\
    \ from ROS2, so using them for software that are not ROS-dependent is totally\
    \ a valid usecase IMO, if that's what you're doing.\n\n> 1. What do I need to\
    \ add to CMakeLists.txt so I can include modbus inside motor.hpp?\n\n[Adding Dependencies](https://docs.ros.org/en/humble/How-To-Guides/Ament-CMake-Documentation.html#adding-dependencies)\
    \ section in the tutorial is a good resource.\n\nGoing a little step-by-step.\
    \ 1st, define dependencies that your cmake target needs to depend on.\n\n    set(DEPS\n\
    \      ament_cmake\n      rclcpp\n      %YOUR_CHOICES%\n    )\n    foreach(dep\
    \ IN ITEMS ${DEPS}) find_package(${dep} REQUIRED) endforeach()\n\nDefine a cmake\
    \ target for your program. This line differs depending on whether you're making\
    \ an executable or a library.\n\n    add_executable(%YOUR_TARGET% %PATH_TO_YOUR_CPP%)\n\
    \    add_library(%YOUR_TARGET% %PATH_TO_YOUR_CPP%)\n\nThen, using the approaches\
    \ explained in the tutorial, set dependency to your cmake target. The tutorial\
    \ doesn't seem to clarify cases where either approach is more sutaible though,\
    \ I'd say normally use `ament_target_dependencies` that does multiple things at\
    \ once.\n\n    ament_target_dependencies(%YOUR_TARGET% ${DEPS})\n\n(I experienced\
    \ a case where I could only get my app working with `target_link_libraries`, which\
    \ I [asked in robotics.stackexchange.com#24837](https://robotics.stackexchange.com/questions/24837/ament-target-dependencies-not-linking-an-upstream-ament-package),\
    \ fyi).\n\n> 2 . How should I configure CMakeLists.txt so that I can include the\
    \ motor class in another ros2 package?\n\nFor this question, I don't see much\
    \ difference from the 1st one, so I assume this 2nd one is about \"how to add\
    \ dependency in \"ament pkg\" than just configuring CMakeLists.txt.\n\nDefining\
    \ dependency for `ament package` is 2-fold:\n\n- Dependency in packaging:\n  \
    \ - Define in `package.xml`, then use a tool called `rosdep`. [Tutorial (docs.ros.org/en/humble)](https://docs.ros.org/en/humble/Tutorials/Intermediate/Rosdep.html).\n\
    \   - [What if my library isn\u2019t in rosdistro?](https://docs.ros.org/en/humble/Tutorials/Intermediate/Rosdep.html#what-if-my-library-isn-t-in-rosdistro)\n\
    - Dependency in building software (using `cmake` via `ament_cmake`) --> Explained\
    \ in the answer for question-1.\n\n----\n\nIn your case, I'm not sure which `apt/deb`\
    \ package you use for `libmodbus`, but in the `rosdep` key list on `rosdistro`,\
    \ there's [libmodbus-dev (rosdistro/rosdep/base.yaml#L4047)](https://github.com/ros/rosdistro/blob/e2a76e1041209ac2f601a24b3c8e9ededd9fdf6e/rosdep/base.yaml#L4047)\
    \ and `libmodbus5` (note the link is permalink so the info you see may be outdated).\
    \ If either of those are what you need, add it in your package.xml\n\n*1...I haven't\
    \ seen yet much of these expression in `ament` world though. Back in ROS1, \"\
    catkin package\" was commonly mentioned in order to describe a software that is\
    \ packaged using `package.xml`, `CMakeLists.txt` in the way Catkin defines.\n\n\
    ----\n\n**UPDATE** Inspired by this thread, I opened [ros2_documentation!3719](https://github.com/ros2/ros2_documentation/pull/3719)\
    \ to add more explanation in `rosdep`'s tutorial. If anyone can review and leave\
    \ comments there, that will help review."
