  body_markdown: "This looks very similar to [this](https://answers.ros.org/question/10238/unable-to-contact-my-own-server/)\
    \ issue.\nMaybe you have a similar configuration error?\n\nIt is not clear from\
    \ your problem description whether this is a network issue or an configuration\
    \ issue.\n\nSo the first thing I would suggest is to check for full connectivity\
    \ using pin/netcat.\nKeep in mind that ROS requires full bi-directional connectivity\
    \ between all pairs of machines, on all ports.\n\nMoreover, make sure your `ROS_MASTER_URI`,\
    \ `ROS_HOSTNAME` / `ROS_IP` are set correctly on all machines.\n\n - In general\
    \ `ROS_MASTER_URI` has to be set on each remote machine to`ROS_MASTER_URI=http://<hostname>:<used\
    \ port>` or `http://<master ip>:<used port>`\n - On the machine running the master\
    \ you do not necessarily have to set `ROS_MASTER_URI` as it defaults to `http://localhost:11311`,\
    \ however, if using a custom port (as in your case) set it to `http://localhost:<used\
    \ port>`\n - `ROS_HOSTNAME`only has to be set manually on a machine if your systems\
    \ default host names is not resolvable. \n - Alternatively to avoid taking care\
    \ of the name resolution you can set `ROS_IP` to your external IP Address on each\
    \ machine without a resolvable host name.\n\nA basic tutorial on how to test and\
    \ setup your network for ROS can be found [here](http://wiki.ros.org/ROS/NetworkSetup).\n\
    \nFor a more specific answer please provide more details about your network configuration\
    \ and your ROS environment."

Error message:

    Unable to contact my own server at [http://192.168.0.2:38315/].
    This usually means that the network is not configured properly.
    
    A common cause is that the machine cannot ping itself.  Please check
    for errors by running:
    
    	ping 192.168.0.2
    
    For more tips, please see
    
    	http://www.ros.org/wiki/ROS/NetworkSetup
