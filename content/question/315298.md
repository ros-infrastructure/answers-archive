  body_markdown: "I made a node a while ago for almost exactly the same task, except\
    \ mine only re-published either the left or the right but not both. Here is a\
    \ quick copy paste of my node, you should be able to modify it fairly easily so\
    \ it achieves what you what.\n\n    #include <ros/ros.h>\n    #include <opencv2/imgproc/imgproc.hpp>\n\
    \    #include <opencv2/highgui/highgui.hpp>\n    #include <cv_bridge/cv_bridge.h>\n\
    \    #include <sensor_msgs/image_encodings.h>\n    #include <image_transport/image_transport.h>\n\
    \    \n    // global controlling which half of the image will be re-published\n\
    \    std::string side;\n    \n    // size of the output image\n    int outputWidth,\
    \ outputHeight;\n    \n    image_transport::Publisher rePublisher;\n    \n   \
    \ // Image capture callback\n    void imageCallback(const sensor_msgs::ImageConstPtr&\
    \ msg)\n    {\n    \t// get double camera image\n        cv_bridge::CvImagePtr\
    \ cvImg = cv_bridge::toCvCopy(msg, \"rgb8\");\n        cv::Mat image = cvImg->image;\n\
    \        \n        // if there are any subscribers to the topic then publish image\
    \ on it\n        if (rePublisher.getNumSubscribers() > 0)\n        {\n    \t\t\
    // define the relevant rectangle to crop\n    \t\tcv::Rect ROI;\n    \t\tROI.y\
    \ = 0;\n    \t\tROI.width = image.cols / 2;\n    \t\tROI.height = image.rows;\n\
    \    \t\tif (side == \"left\")\n    \t\t\tROI.x = 0;\n    \t\telse\n    \t\t\t\
    ROI.x = image.cols / 2;\n    \n    \t\t// crop image and publish\n    \t\tcv::Mat\
    \ croppedImage = cv::Mat(image, ROI);\n    \n    \t\tcv::Mat scaledImage;\n  \
    \  \t\tcv::resize(croppedImage,\n    \t\t\t\t   scaledImage,\n    \t\t\t\t   cv::Size(outputWidth,\
    \ outputHeight) );\n    \n    \t\tcv_bridge::CvImage cvImage;\n    \t\tcvImage.image\
    \ = scaledImage;\n    \t\tcvImage.encoding = \"bgr8\";\n    \t\trePublisher.publish(cvImage.toImageMsg());\n\
    \        }\n    }\n    \n    int main(int argc, char** argv)\n    {\n    \tros::init(argc,\
    \ argv, \"half_image_publisher_node\");\n    \tros::NodeHandle nh(\"~\");\n  \
    \  \n    \timage_transport::ImageTransport it(nh);\n    \n    \t// load node settings\n\
    \    \tstd::string inputTopic, outputTopic;\n      \tnh.param(\"image_side\",\
    \ side, std::string(\"left\"));\n      \tnh.param(\"input_topic\", inputTopic,\
    \ std::string(\"not_set\"));\n      \tnh.param(\"output_topic\", outputTopic,\
    \ std::string(\"not_set\"));\n      \tnh.param(\"width\", outputWidth, 640);\n\
    \      \tnh.param(\"height\", outputHeight, 480);\n    \n      \t// register publisher\
    \ and subscriber\n      \tros::Subscriber imageSub = nh.subscribe(inputTopic.c_str(),\
    \ 2, &imageCallback);\n    \n      \trePublisher = it.advertise(outputTopic.c_str(),\
    \ 1);\n    \n      \t// run node until cancelled\n    \tros::spin();\n    }"

 I am experimenting with a cheap stereo webcam (ELP-960P2CAM-V90-VC https://www.amazon.com/gp/product/B078TDLHCP ) that publishes the stereo image as a single side-by-side image that is double wide.  It is trivial with OpenCV/Numpy to split out the left and right images as array slices.  From searching around here it seems that it should be simple to write a small node that reads /dev/videoN and republishes on stereo/left/* and stereo/right/* image and camera_info topics. Yet, it does not seem that this node exists, nor is sXs video supported by libuvc_camera. 

Does anyone have pointers to something that I have missed?  Might it make sense to add this functionality directly to libuvc_camera?
