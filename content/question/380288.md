title: Best way to add package's models path to GAZEBO_MODEL_PATH in ROS2?
upvote_count: 2
---
In ROS1, you could add your package's `models` path to the `GAZEBO_MODEL_PATH` in `package.xml` (e.g. [as shown here](https://github.com/sloretz/gazebo_model_path_example/blob/457fdcb01831a3045f95be8ea0f43bee31fc791e/gazebo_model_path_example/package.xml#L14-L17)).

It doesn't seem like the same functionality (provided by [gazebo_ros_paths_plugin.cpp](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_ros/src/gazebo_ros_paths_plugin.cpp)) exists in ROS2. So is there a preferred alternative?

I know you can set environment variables [using launch substitutions](https://answers.ros.org/question/343220/ros2-extend-env-vars-in-launch-file-instead-of-overwriting/), but this would have to be done for each launch file. 

Is there a way to set the environment variable at the package level (or at the workspace level, e.g. when sourcing your `setup.bash`)? Or would that be bad form?
