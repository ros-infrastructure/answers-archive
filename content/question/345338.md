  body_markdown: "To re-use functions that have been implemented in another `cpp`\
    \ file you need to have this file compiled as a library. That's exactly what `catkin_make`\
    \ tells you with the error `undefined reference to ...`. Basically, during the\
    \ compilation all the directives `#include` get replaced by the content of the\
    \ included file, so here you end up with `node_1` having the declaration and implementation\
    \ of the function `my_test_func` in the executable but not for `node_2`. So when\
    \ you call `my_test_func()` in `node_2` you don't know its implementation. What\
    \ you need to do is having `node_1.cpp` compiled as a library. In that case you\
    \ will link the library to `node_2.cpp` that will get the implementation of the\
    \ function.\n\nYour `CMakeLists.txt` should be :\n\n    # Declare the library\
    \ node_1\n    add_library(node_1 src/node_1.cpp)\n    target_link_libraries(node_1\
    \ ${catkin_LIBRARIES})\n    add_dependencies(node_1 hric_sys_generate_messages_cpp)\n\
    \    \n    # Declare the executable node_2 and link it to node_1\n    add_executable(node_2\
    \ src/node_2.cpp)\n    target_link_libraries(node_2 ${catkin_LIBRARIES} node_1)\n\
    \    add_dependencies(node_2 hric_sys_generate_messages_cpp)\n    \n    # Declare\

      In my example the library `node_1` allows you to use the methods from `node_1.cpp` (thanks to `add_library.(..))` if other nodes need it but you can also use `rosrun package node_1_exe` to run `node_1.cpp` alone (thanks to `add_executable(..)`).
