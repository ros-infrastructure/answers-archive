    Having the robot figure out where it is on startup is known as the "kidnapped robot problem" in robotics. AMCL does not solve it, so you'll have to set the pose manually or find a different localization package that does solve this problem.

    You can set the robot's pose manually using the "2D Pose Estimate" tool in rviz.

  body_markdown: "AMCL provides the \"global_localization\" service for this use case\
    \ (see [AMCL wiki page](http://wiki.ros.org/amcl#Services)). It disperses particles\
    \ randomly in the given map and hopefully finds the correct robot pose after the\
    \ robot moved around a little bit, pruning \"bad\" particles. You\xB4ll have to\
    \ test how well that works for your scenario, though. I haven\xB4t played around\
    \ with it much, but I\xB4d expect that huge and redundant looking environment\
    \ (e.g. with lot of places looking the same) will be a challenge. If you are able\
    \ to set the initial_pose, that definitely would be the more reliable method."

  body_markdown: "This is the method to automatically position the robot on the map.\
    \ (Alternative of 2D pose button)\n\nOpen RViz. Using pose estimate position the\
    \ robot to the required pose.\n\nrostopic echo /amcl_pose\n\nnote x and y of posotion\n\
    \npose: \n  pose: \n    position: \n      x: 0.2692\n      y: 0.0218\n      z:\
    \ 0.0\n\ngive x as initial x pose \ngive y as initial y pose\n\n  <!-- We can\
    \ position the robot in the map using initial pose tag.  -->\n  <include file=\"\
    $(find v1robot_description)/launch/amcl.launch\" >\n     <arg name=\"initial_pose_x\"\
    \ value=\"0.2692\"/>\n     <arg name=\"initial_pose_y\" value=\"0.0218\" />\n\
    \  </include>\n\nadd these values as the arguments initial_pose_x, initial_pose_y\n\
    In my case orientation was not needed(so I have not tried changing orientation)\n\
    \nSo from the next time when we load gazebo+amcl, the mobile robot automatically\
    \ positions itself on the map. So no need to manually set the home pose using\
    \ 2D pose estimate button once initial pose arguments are set. "
