  body_markdown: "The the source of the exception is almost certainly right here (which\
    \ dates from 2014):\n https://github.com/lagadic/vrep_ros_bridge/blob/a4e10d64a2dff85407a8c4e75fa2e669bcdb7c59/manipulator_handler/src/ManipulatorHandler.cpp#L394\n\
    \n    _lastPrintedMsg = ros::Time(-1.0);\n\n(and possibly there are other instances\
    \ of bad time initialization in the same package, and there's also an issue where\
    \ initializing a ros::Duration with an uninitialized double will sometimes result\
    \ in a `Duration is out of dual 32-bit range` depending on if the uninitialized\
    \ memory happens to be an acceptable Duration or not https://github.com/ros-controls/ros_controllers/pull/577):\n\
    \nHere's a simple example https://github.com/lucasw/timer_test/blob/master/src/bad_time.cpp\n\
    \n    #include <iostream>\n    #include <ros/ros.h>\n    \n    int main()\n  \
    \  {\n      const auto cur = ros::Time(-1);\n    /**\n     * this will be the\
    \ result of the above\n    terminate called after throwing an instance of 'std::runtime_error'\n\
    \      what():  Time is out of dual 32-bit range\n    Aborted (core dumped)\n\
    \    */\n      std::cout << cur << std::endl;\n      const double sec = cur.toSec();\n\
    \      std::cout << sec << std::endl;\n    }\n\nFor reference the exception is\
    \ thrown from here (though for some cases there are some similarly phrased exceptions\
    \ so it isn't always clear):\n\nhttps://github.com/ros/roscpp_core/blob/kinetic-devel/rostime/include/ros/impl/time.h#L80\n\
    \n\nMaybe a few years and ros versions ago `ros::Time(-1)` was an unofficial sentinel\
    \ value?  Then it started throwing exceptions but the people encountering the\
    \ exceptions and the rosccp_core maintainers were too many degrees separated to\
    \ realize any of this.  Or it was cleaned up in major packages that were being\
    \ actively maintained, but little time bombs are lying around elsewhere.\n\nIdeally\
    \ something could be done to make it a compiler error (or we should all move to\
    \ `rust`...)."
