  body_markdown: "If I understand you correctly, your problem is this:\n\n* robot_state_publisher\
    \ reads your URDF and publishes the TF transform `base_link` \u2192 `pico_de_gallo`.\n\
    * the ROS driver you are using (`royale_in_ros`) publishes the sensor data in\
    \ the frame_id `royale_camera_optical_frame`.\n* You don't know how to link the\
    \ two.\n\nFirst of all, I wouldn't recommend using `royale_in_ros`. It's just\
    \ a code sample that is shipped with the `libroyale` (i.e., the SDK for accessing\
    \ the pico flexx cameras). Among other things, it has the limitation that you\
    \ cannot change the `frame_id` in which the sensor data is published, so you cannot\
    \ use two different pico flexx cameras at the same time.\n\nInstead, I would recommend\
    \ using the [pico_flexx_driver](https://github.com/code-iai/pico_flexx_driver)\
    \ (full disclosure: I am a maintainer). Look at the README for all parameters.\
    \ The `pico_flexx_driver` has a parameter called `base_name_tf`, which is by default\
    \ `pico_flexx`. The sensor data is published in the `$base_name_tf` + `\"_optical_frame\"\
    `, so by default `\"pico_flexx_optical_frame\"`. If the launch file arg `publish_tf`\
    \ is `true`, the launch file also publishes TFs for `$base_name_tf` + `\"_link\"\
    ` \u2192 `$base_name_tf` + `\"_optical_frame\"`.\n\nSo what you could do is:\n\

    \ `pico_de_gallo_link`.\n* Launch the `pico_flexx_driver` with `publish_tf = true`\
    \ and `base_name = pico_de_gallo`: It will publish the TF transform `pico_de_gallo_link`\
