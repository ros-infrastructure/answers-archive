  body_markdown: "(I know this is an old one, but for future reference here is my\
    \ answer.)\n\n---\n\nThe OP was aiming to use `send_goal_and_wait` method that\
    \ has the following signature:\n\n    actionlib::simple_action_client::SimpleActionClient::send_goal_and_wait(self,\
    \ goal, execute_timeout = rospy.Duration(), preempt_timeout = rospy.Duration())\t\
    \n\nLooking at the [source code](https://docs.ros.org/diamondback/api/rospy/html/rospy.rostime.Duration-class.html#__init__),\
    \ I see that the default value for the *optional* timeout parameters is *0 seconds*\
    \ since `rospy.Duration()` initializes the duration objects with 0 seconds.\n\n\
    Moreover, it is pointed out in the [class reference](https://docs.ros.org/diamondback/api/actionlib/html/classactionlib_1_1simple__action__client_1_1SimpleActionClient.html#a3de1204015fe23bfd1b47b7fe164df34)\
    \ that calling this method would make ActionServer forget about any previous goal,\
    \ if there exists any. \n\nTherefore, calling this method several times without\
    \ any given timeout is expected to behave just as OP described. To my understanding,\
    \ this is the expected behavior.\n\n---\n\nSo the more appropriate way would be\
    \ to use this method with the necessary timeout values. For example: \n\n    exec_timeout\
    \ = rospy.Duration(10)\n    prmpt_timeout = rospy.Duration(5)\n    client.send_goal_and_wait(goal,\
    \ exec_timeout, prmpt_timeout)"
