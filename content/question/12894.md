  body_markdown: "*update*\n\n(This doesn't exactly answer the question, the noise\
    \ concerns are still valid, but possibly some searches that lead here want to\
    \ do something like this, and with rospy)\n\nI made a twist lookup from scratch,\
    \ parent frame is the fixed frame (e.g. \"map\" or \"odom\" in many cases) and\
    \ child frame is the moving frame:\n\n    # get the stamp of the most recent valid\
    \ transform\n    tfs_ref = tf_buffer.lookup_transform(parent_frame, \n       \
    \                                  child_frame,\n                            \
    \             rospy.Time(0))\n    stamp = tfs_ref.header.stamp\n    old_stamp\
    \ = stamp - rospy.Duration(duration)\n\n    tfs = tf_buffer.lookup_transform_full(child_frame,\
    \ old_stamp,\n                                          child_frame, stamp,\n\
    \                                          parent_frame)\n\n    delta_t = 1.0\
    \ / duration\n    tr = tfs.transform.translation\n    vel_vec = Vector3(tr.x *\
    \ delta_t, tr.y * delta_t, tr.z * delta_t)\n\n    rot = tfs.transform.rotation\n\
    \    quat = [rot.x, rot.y, rot.z, rot.w]\n    euler = transformations.euler_from_quaternion(quat)\n\
    \    rot_vec = Vector3(euler[0] * delta_t, euler[1] * delta_t, euler[2] * delta_t)\n\
    \    twist = Twist(vel_vec, rot_vec)\n\n\nI'm not sure about the correctness,\
    \ if it is producing the output any others desire, but visualizing it in rviz\
    \ with mostly 2D x,y, theta motions looks reasonable (as opposed to using lookupTwist,\
    \ where the twist changes as a function of angle relative to the fixed frame,\
    \ when I just want the twist relative to the moving frame).  Didn't look too closely\
    \ at the angular rates, mostly just the linear.\n\n----\n\n(couldn't get this\
    \ lookupTwist to work, even with suggested change from https://github.com/ros/geometry/issues/43)\n\
    \nFor python it requires using `tf`:\n\n    import tf\n    from geometry_msgs.msg\
    \ import Twist    \n    from geometry_msgs.msg import Vector3\n\n    tl = tf.TransformListener()\n\
    \    ...\n    # get twist relative to map calculated from the most recent\n  \
    \  # valid sample to a sample 0.5 seconds before that\n    tw = tl.lookupTwist(moving_frame_id,\
    \ \"map\",\n                        rospy.Time(0.0), rospy.Duration(0.5))\n  \
    \  twist = Twist(Vector3(tw[0][0], tw[0][1], tw[0][2]),\n                  Vector3(tw[1][0],\
    \ tw[1][1], tw[1][2]))\n\nThe return value isn't a Twist(), instead it's six values\
    \ in two tuples which are linear xyz and then angular xyz.\n\nMaybe it was intended\
    \ to be added to tf2 but the lookupTwist is commented out:\nhttps://github.com/ros/geometry2/blob/noetic-devel/tf2_py/src/tf2_py.cpp#L350-L394\n\
    \nMaybe this https://github.com/ros/geometry/blob/noetic-devel/tf/src/tf/listener.py#L115-L149\
    \ could be adapted into tf2 easily."
