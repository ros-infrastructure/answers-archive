    \ I have a working solution.  In the Subscriber class of message_filters (subscriber.h),\
    \ I have added a subscribezc method (below) that is exactly the same as the standard\

    \ topic, const rmw_qos_profile_t qos = rmw_qos_profile_default)\n      {\n   \
    \     unsubscribe();\n    \n        if (!topic.empty())\n        {\n         \
    \ topic_ = topic;\n          rclcpp::QoS rclcpp_qos(rclcpp::QoSInitialization::from_rmw(qos));\n\
    \          rclcpp_qos.get_rmw_qos_profile() = qos;\n          qos_ = qos;\n  \
    \        sub_ = node->create_subscription<M>(topic, rclcpp_qos,\n            \
    \       [this, node](std::unique_ptr<M> msg) {\n                     RCLCPP_INFO(node->get_logger(),\
    \ \"Got UP Callback %x\", msg.get());\n                     this->cb(EventType(std::move(msg)));\n\
    \                   });\n    \n          node_raw_ = node;\n        }\n      } "

upvote_count: 0

I once tried out [the tutorial of intra process communication](https://index.ros.org/doc/ros2/Tutorials/Intra-Process-Communication/) which impressed me that it can improve communication performance with zero-copy.  Afterwards, I tried to adopt this best practice in my application, but I met an issue. I need to synchronize messages from two topics with [message filters](https://github.com/ros2/message_filters). As mentioned in [the tutorial](https://index.ros.org/doc/ros2/Tutorials/Intra-Process-Communication/), we have to use std::unique_ptrs to implement zero-copy. 

> This is because we’re publishing and subscribing with std::unique_ptrs which allow ownership of a message to be moved around the system safely. You can also publish and subscribe with const & and std::shared_ptr, but zero-copy will not occur in that case.

However, the callback of message filters only accept std::shared_ptr as its parameters. Does it mean we cannot take benefits from zero-copy if we use message filters, unless some code changes need to be done from message filter side?
