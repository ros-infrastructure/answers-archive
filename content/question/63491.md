    \ this.\n\nYou can look at the method used in the [turtlesim](http://www.ros.org/wiki/turtlesim)\
    \ [teleop_turtle_key](http://ros.org/doc/groovy/api/turtlesim/html/teleop__turtle__key_8cpp_source.html).\
    \  This node is used in the [Understanding Topics](http://www.ros.org/wiki/ROS/Tutorials/UnderstandingTopics)\
    \ tutorial.\n\nAll the default built-in functions (`cin >>`, `getchar`, etc.)\
    \ block until the user presses \"enter\".  Which is probably not the behavior\
    \ you want.  So, you'll need to use some sort of OS-specific hack to read the\
    \ keys as they are pressed.\n\nSee [this](http://stackoverflow.com/questions/1798511/how-to-avoid-press-enter-with-any-getchar)\
    \ thread for suggestions on how to implement a non-blocking `getchar()` in linux.\
    \  It boils down to modifying the terminal settings to disable input buffering.\
    \  You'll want to make sure and restore the original settings when your program\
    \ exits, or else the terminal will behave oddly.   Basically, you need something\
    \ like:\n\n    int getch()\n    {\n      static struct termios oldt, newt;\n \
    \     tcgetattr( STDIN_FILENO, &oldt);           // save old settings\n      newt\
    \ = oldt;\n      newt.c_lflag &= ~(ICANON);                 // disable buffering\
    \      \n      tcsetattr( STDIN_FILENO, TCSANOW, &newt);  // apply new settings\n\
    \n      int c = getchar();  // read character (non-blocking)\n\n      tcsetattr(\
    \ STDIN_FILENO, TCSANOW, &oldt);  // restore old settings\n      return c;\n \
    \   }\n\nOnce you've got that function written, you can do something like:\n\n\
    \    while (ros::ok())\n    {\n      int c = getch();   // call your non-blocking\
    \ input function\n      if (c == 'a')\n        send message 'A'\n      else if\
    \ (c == 'b')\n        send message 'B'\n     \n      << do other processing >>\n\
    \    }"
