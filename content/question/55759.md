    That is what namespaces are for. Either set the ROS_NAMESPACE environment variable before using rosrun or make a launchfile that contains a <group ns="naoX"> tag for each robot. There you can define the parameter with the IP and, if the driver nodes work properly (i.e. subscribing to "cmd_vel" and not "/cmd_vel", the topics should now read like /naoX/cmd_vel and so on.

    If you want to use tf, you should also set the tf_prefix param and be sure that all software you use (and especially the one you develop) uses the tf methods to resolve frame_ids with the tf_prefix. Look for tf_prefix in the ros wiki.

    \nThe process involves a few different concepts:\nhardware machines, conceptual\
    \ machines, tf trees (at least).\n\nThe distinction between hardware machines\
    \ and conceptual machines is paramount:\n\n - a **hardware machine** is a unix\
    \ machine, ie a computer running your choice of OS, with a unique identifier,\
    \ to which you need to be able to ssh into.\n - a **conceptual machine** is one\
    \ of your Naos\n\nWhat does this mean?\nI don't know the Nao stack, so I am generalizing\
    \ here: most of times you have to run nodes that are local to the specific machines\
    \ (for example nodes that communicate with hardware, like motor controllers and\
    \ laser drivers) and nodes that don't need to be local (for example navigation\
    \ nodes: they fetch the data flowing over the network, but don't need to run on\
    \ the specific machine from which they are fetching their data).\n\nSo here is\
    \ a launch file example\n\n    <launch>\n        <machine name=\"Nao01\" address=\"\
    Nao01.local\" user=\"nao\" default=\"false\" env-loader=\"/opt/ros/<distro>/setup.sh\"\
    \ timeout=\"180\" />\n    </launch>\n\nThis doesn't do anything but explains how\
    \ you setup remote machines.\n\nThe next step is to determine where nodes will\
    \ run (as said before: on the core machine, or on the remote machines).\n\n  \
    \      <launch>\n            <machine name=\"Nao01\" address=\"Nao01.local\" user=\"\
    nao\" default=\"false\" env-loader=\"/opt/ros/<YOUR_DISTRO>/setup.sh\" timeout=\"\
    180\" />\n            <node pkg=\"nao-stack\" type=\"navigation\" name=\"nao_navi\"\
    \ />\n\n            <!-- == NAO 01 == -->\n    \t\t<group ns=\"nao_1\">\n    \t\
    \t<param name=\"tf_prefix\" value=\"nao_1\"/>\n    \t\t<param name=\"robot_description\"\
    \ command=\"$(find xacro)/xacro.py $(find nao_stack)/nao.urdf\" />\n    \t\t\n\
    \    \t\t<!-- Robot State Publisher -->\n    \t\t<node pkg=\"robot_state_publisher\"\
    \ type=\"state_publisher\" name=\"state_publisher\"/>\t\t\n    \n    \t\t<!--\
    \ Nao Nodes -->\n    \t\t<node pkg=\"nao_stack\" type=\"driver\" name=\"drive\"\
    \ machine=\"Nao01\"/>\n    \t\t</group>\n    \t    <!-- == END NAO 01 == -->\n\
    \    \n        </launch>\n\nThis most probably won't work (paths and names are\
    \ surely wrong) but should get you going.\n\nNote the various type of nodes and\
    \ where they are started.\n\nRemember that to use roslaunch architecture your\
    \ core machine ***MUST*** be able to log into the remote machines via ssh without\
    \ password.\nThat means loading the core ssh key into the remote machines, and\
    \ granting it authorized_key status.\n\n[This](http://wp.uberdose.com/2006/10/16/ssh-automatic-login/)\
    \ should help you get started setting up ssh."
