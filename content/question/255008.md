  body_markdown: "I FOUND A WAY!\n\nposting the answer here, behold, it may look ugly!\n\
    \nThe answer lies with the command system(command) in matlab. With that, you can\
    \ run any command that you'd run in a terminal.\n\nThe first thing one would do\
    \ is to simply run:\n\n    system('roslaunch xyz.launch');\n\nBut sadly it's not\
    \ that simple!\n\nSince matlab exports it's own little world of LD_LIBRARY_PATH,\
    \ you have the over write the LD_LIBRARY_PATH when you want to execute a command\
    \ that uses the LD_LIBRARY_PATH that is normally set in your environment outside\
    \ of matlab. If you want to know what it is, run \"echo $LD_LIBRARY_PATH\" in\
    \ a command line.\n\nfor me the output was: \"/home/XXXX/catkin_ws/devel/lib:/opt/ros/kinetic/lib:/opt/ros/kinetic/lib/x86_64-linux-gnu\"\
    . I will refer to it with the name LD_path in the examples bellow.\n\nSo to launch\
    \ the launch file you have to run:\n\n    system(['export LD_LIBRARY_PATH=\"LD_path\"\
    ;' 'roslaunch xyz.launch']);\n\nThe thing is that it will stall the execution\
    \ of any script you put it in since the command returns only after you terminate\
    \ it...\n\nTo be able to continue the script we need to use the \"&\" character\
    \ at the end of the command like the following example.\n\n    system(['export\
    \ LD_LIBRARY_PATH=\"LD_path\";' 'roslaunch xyz.launch &']);\n\nNow the program\
    \ runs in background, but you wont be able to terminate it upon then end of a\
    \ script or function.\n\nTo be able to do so, we add the \"echo $!\" string at\
    \ the end of the command. This returns the status and PID of the process. We then\
    \ can kill the process by issuing the kill command. Example bellow:\n\n    [status,cmdout]\
    \ = system(['export LD_LIBRARY_PATH=\"LD_path\";' 'roslaunch xyz.launch & echo\
    \ $!']);\n    \n    system('kill', cmdout);\n\nIf you want to make sure the process\
    \ is killed after a \"Ctrl-C\" input, the onCleanup() matlab function is pretty\
    \ useful.\nIt creates an object that executes the function passed in parameter\
    \ when the object is deleted.\n\n    finishup = onCleanup(@() myCleanupFun(cmdout));\n\
    \n\"myCleanupFun(cmdout))\" being a function I wrote as follows:\n\n    function\
    \ myCleanupFun(cmdout))\n    system('kill',cmdout)\n    end\n\nIn the case of\
    \ a script file, since the variables are not deleted upon its termination, you\
    \ have to call it inside a function. All the variables being local to the function\
    \ workspace, they are now deleted after the function is stopped thus deleting\
    \ the \"finishup\" variable and killing the process."

      Sorry for the delay... @manuelmelvin If you have a matlab script and want to follow the solution i gave to terminate the process (roslaunch xyz.launch), you have ot call you script from a function to ensure the variable "finishup" is deleted (thus triggering the execution of the "mycleanupFun()" function).

      To do so, you create a function that does:

          fucntion my_script_launcher()
          my_scipt_that_launches_the_launch_file;
          end

      If inside your script you call the `finishup = onCleanup(@() myCleanupFun(cmdout));` line, once the script finishes it will stop only the xyz.launch execution, not all nodes.
