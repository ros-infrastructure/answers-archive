  body_markdown: "This is the `main(..)` from the code you link in your question:\n\
    \n    int main(int argc, char **argv)\n    {\n        /*\n        * Main loop\
    \ of the hardware interface.\n        */\n        ros::init(argc, argv, \"hw_interface\"\
    );\n        MyRobot robot;\n        controller_manager::ControllerManager cm(&robot);\n\
    \        ros::Time time_now;\n        ros::Duration period_now;\n        ros::Rate\
    \ sleep_rate(10);\n        \n    \n        while (true)\n        {\n         \
    \   time_now = robot.get_time();\n            period_now = robot.get_period();\
    \ \n            robot.read(period_now);\n            cm.update(time_now, period_now);\n\
    \            robot.write();\n            sleep_rate.sleep();\n        }\n    }\n\
    \nThere is one thing suspiciously missing here, and that would be somewhere for\
    \ ROS to actually process events. The fact that the `controller_manager` services\
    \ do not produce any output is indicative of this.\n\nEven a `hardware_interface`\
    \ needs *some* time to process incoming and outgoing events, but you don't give\
    \ it any.\n\nYou'll either want to call `ros::spinOnce()` somewhere in your `while`\
    \ loop, or instantiate a `ros::AsyncSpinner` and start it. The latter would actually\
    \ be recommended. Something like this should do the trick:\n\n    ros::AsyncSpinner\
    \ spinner(2);\n    spinner.start();\n\nA single thread is not enough, as there\
    \ is a high potential for deadlocks.\n\nNote that this also done in the two examples\
    \ that you link: `PickNikRobotics/ros_control_boilerplate` ([here](https://github.com/PickNikRobotics/ros_control_boilerplate/blob/cc7af57a111fa4913c668da2cc362b75f7450ca3/rrbot_control/src/rrbot_hw_main.cpp#L47-L50))\
    \ and `eborghi10/my_ROS_mobile_robot` ([here](https://github.com/eborghi10/my_ROS_mobile_robot/blob/c54465ba1ab76fd69c8653f7b09c4d9cd7e043da/my_robot_base/src/my_robot_base.cpp#L29)).\n\
    \n---\n\nEdit: just noticed you have this:\n\n    while (true)\n    {\n      [..]\n\
    \    }\n\nThis is not a good idea in a ROS node -- which a `hardware_interface`\
    \ essentially is.\n\nYou'll want to check for `ros::ok()` instead."
