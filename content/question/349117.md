  body_markdown: "I think the `nodes` directory should be directly under the package\
    \ rather than `src` folder. According to [REP8-Style Guide for Python Code](https://www.ros.org/reps/rep-0008.html#installing-scripts-with-catkin),\n\
    \n\n> \"The recommended layout is to put all\n> of your package's importable Python\n\
    > code in the src folder of your package\n> and in a \"Python package\" with the\n\
    > same name as your package. In this\n> case a \"Python package\" is a folder\n\
    > which contains a `__init__.py` file,\n> indicating that the folder contains\n\
    > additional Python packages and\n> modules.\"\n\n\nThe `src` folder thus should\
    \ store Python packages and modules if you want to make them importable into other\
    \ ROS packages.\n\n\n> Also, does it matter where this file\n> is located within\
    \ the package? I've\n> seen other places where Python files\n> are in a dir called\
    \ scripts as opposed\n> to src.\n\n\nAs far as I know, technically, it does not\
    \ matter where the file is located within the package since `rosrun` is able to\
    \ find the location of the executable for a package recursively ([rosrun-source\
    \ code](https://github.com/ros/ros/blob/2b307e1854ebf3954a5b4110f891278f555e79a6/tools/rosbash/scripts/rosrun#L73)).\
    \ So as long as your executable file- python script is in the directory of your\
    \ ROS package (under `src` in the catkin workspace, since `catkin_make` command\
    \ only looks for packages under `src` dir) and your local workspace is properly\
    \ sourced, `rosrun` should be able to find that executable. \n\nHowever, conventionally,\
    \ according to an excerpt from [REP8-Style Guide for Python Code](https://www.ros.org/reps/rep-0008.html#installing-scripts-with-catkin),\
    \ \n> \"We distinguish between \"nodes\" and\n> \"scripts\" for clarity to users.\
    \ Nodes\n> are executable Python files that\n> conform to the ROS node API. Scripts\n\
    > are executable Python files that do\n> not conform to the ROS node API.\"\n\n\
    Aslo from [Installing Python scripts and modules](http://docs.ros.org/melodic/api/catkin/html/howto/format2/installing_python.html)\n\
    \n\n\n> \u201CStandard ROS practice is to place all\n> executable Python programs\
    \ in a\n> package subdirectory named nodes/ or\n> scripts/. Their usage is the\
    \ same, the\n> two names distinguish ROS nodes from\n> other executable Python\
    \ scripts.\u201D\n\n\nSo I think, conventionally, an executable python script\
    \ that contains ROS nodes should go to `nodes` folder. \n\nI guess distinctions\
    \ are the convention and good practices to make your package structure more clear.\
    \ \n\nI think the rationale for ROS users putting python scripts into `scripts`\
    \ folder is based on the common practice for python packages. In Python, people\
    \ usually put top-level executable scripts in the scripts/ (or bin/) directory\
    \ and place python packages and modules (used by scripts) into the src/ directory.\
    \ As for the distinction between nodes and scripts in ROS, I don't really know\
    \ if it's a horrible practice to not separate nodes and scripts. Tbh, personally,\
    \ I've seldom seen `nodes` folder. My guess is perhaps ROS users generally consider\
    \ nodes/ as a subset of scripts/, since scripts are any executable python scripts\
    \ for any purpose."
