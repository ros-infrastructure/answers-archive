    Other than possible differences in ROS message types between packages for Foxy and Humble, there should be no problems. Middleware abstraction will be the same, even if DDS implementations differ.

    More about it is there "[**About different ROS 2 DDS/RTPS vendors**](https://docs.ros.org/en/humble/Concepts/About-Different-Middleware-Vendors.html)".

    You should focus on starting with micro-ros with Humble, get every ROS topic/service/action as a working input/output, then you can [connect them with your PC as usual](https://roboticsbackend.com/ros2-multiple-machines-including-raspberry-pi/).

      A quick note:

      > Middleware abstraction will be the same, even if DDS implementations differ.

      the abstraction perhaps, but there is currently no guarantee of cross-vendor compatibility. Cyclone DDS and Fast-DDS are known to be incompatible for instance (see [ros2/rmw_cyclonedds#184](https://github.com/ros2/rmw_cyclonedds/issues/184)).

      This essentially means only Fast-DDS can be used with micro-ROS, unless the application does not use services nor actions (ie: only topics).

      For the OP, this wouldn't pose a problem, as both Foxy and Humble use Fast-DDS by default. But Galactic would be incompatible, and so would anyone trying to use Cyclone DDS with micro-ROS.
