  body_markdown: "Use `valgrind`'s tool named `callgrind`. Add the following prefix\
    \ to your node in launch file. \n\n    planner_server_node = Node(\n         \
    \   package='planning',\n            executable='planner_server',\n          \
    \  name='planner_server_rclcpp_node',\n            namespace='',\n           \
    \ output='screen',\n            prefix=['valgrind --tool=callgrind --dump-instr=yes\
    \ -v --instr-atstart=no'],\n            parameters=[params],\n        )\n    \n\
    Note that starting a node in\n`valgrind` can slow down the program significantly.\
    \  Therefore the above prefix does **not** start `callgrind` right after you launch.\
    \ It will listen for a command from you in order to start logging information.\
    \ To make `callgrind` to logging, in a seperate terminal do ;\n\n     callgrind_control\
    \ -i on\n\nyou should be able to see something like; \n\n    PID 237154: /home/\
    \ ...... \n      OK.\n\nindicating the success of start of logging.  Now Let your\
    \ program run for a while. After you think you have \"captured\" enough function\
    \ calls, do following to dump log file for analysis. \n\n    callgrind_control\
    \ -d\n\nA file with `callgrind.out.*` regex should be dumped to your working directory.\
    \ For me this was the `colcon_ws` directory. \n\nNow you can visually see the\
    \ analysis with gui tool kcachegrind;\n\n    kcachegrind callgrind.out.*\n\n \n\
    ![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1630426665183808.png)\n\
    \n\nAt upper left side select ELF object, locate your executable or library and\
    \ click. \nYou can now see each function call and their execution costs from ELF\
    \ object that you selected. Try to determine the function that takes unexpected\
    \ amount of time and see whether there is room for optimization.\n\nFor further\
    \ information on how to interpret the results with kcachegrind, see [here](https://stackoverflow.com/questions/23786152/how-to-interpret-results-from-kcachegrind)"
