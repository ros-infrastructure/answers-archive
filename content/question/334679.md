    You definitely can but I am not sure if that is the best way to approach this problem. You can take a look at the [rosbag API](http://wiki.ros.org/rosbag/Code%20API). You can create a [timer](http://wiki.ros.org/roscpp/Overview/Timers) that opens a bag every 30 sec to record the camera data and closes the previous opened bag.<br>

    Another way to tackle this problem is to restart the camera. You will need to check/throw an exception if the camera is disconnected and relaunch the camera node (check the [documentation](https://wiki.ros.org/roslaunch/XML/node) for `roslaunch` atribute: `respawn="true"`).

  - body_markdown: "Also, there is the rosbag command line API : \nhttp://wiki.ros.org/rosbag/Commandline#record\n\
      \n```\n\n-d, --duration\n\n    Specify the maximum duration of the recorded\
      \ bag file.\n\n    $ rosbag record --duration=30 /chatter\n    $ rosbag record\
      \ --duration=5m /chatter\n    $ rosbag record --duration=2h /chatter\n\n```\n\
      \nand : \n\n```\n\n--split\n\n    Split the bag when maximum size or duration\
      \ is reached\n\n    $ rosbag record --split --size=1024 /chatter\n    $ rosbag\
      \ record --split --duration=30 /chatter\n    $ rosbag record --split --duration=5m\
      \ /chatter\n    $ rosbag record --split --duration=2h /chatter\n\n```\n\nsomething\
      \ like : \n\n`rosbag record /my_topic --split --duration=30`\n\nThe rosbag will\
      \ be split every 30sec, thus creating a new bag file every 30sec"
