    Hi @alienmonster!

    If you check the [whycon code](https://github.com/lrse/whycon/search?utf8=%E2%9C%93&q=image_rect_color&type=), whycon is subscribing to the `/camera/image_rect_color` topic.

    I think the best way to achieve your goal in this case is to change the files [set_axis.cpp](https://github.com/lrse/whycon/blob/69892169386258d80602577de033b3d017336d0f/src/ros/set_axis.cpp#L39) and [whycon_ros.cpp](https://github.com/lrse/whycon/blob/69892169386258d80602577de033b3d017336d0f/src/ros/whycon_ros.cpp#L40) directly to subscribe to the `/main/image_raw` Topic (instead of to `/camera/image_rect_color`) and recompile the `whycon` package by running the following command on your `~/catkin_ws (Catkin Workspace)`.

    `catkin_make --pkg whycon`

    After that, just run your `roslaunch whycon whycon.launch` again ;)

  body_markdown: "Rather than editing someone else's package that's under source control,\
    \ why not just edit your own package? When the `whycon` package gets updated (and\
    \ it probably will because it looks active) anything that you changed in there\
    \ will be gone when you update (pull) it. If you change files in your own package\
    \ then you don't have to worry about that because you're in control.\n\nNow, on\
    \ to the solution. The topic names get defined in your `task_1_1.world` file.\
    \ You have two options:  \n\n1. add a `remap` tag to your `task_1.launch` (easiest/best)\
    \ \n2. change your world file (still easy).\n\n**Option 1: add a `remap` tag**\
    \ \n\nBecause the topic names are defined in your world file you should add the\
    \ `remap` tag *before* the `include` of the `gazebo` node:\n\n    <launch>\n \
    \       <remap from=\"/main/image_raw\" to=\"/camera/image_raw\"/> <!-- Add this\
    \ line -->\n    \t<include file=\"$(find gazebo_ros)/launch/empty_world.launch\"\
    >\n    \t\t<arg name=\"world_name\" value=\"$(find task_1)/world/task_1_1.world\"\
    />\n    \t\t<arg name=\"headless\" value=\"true\"/>\n    \t\t<arg name=\"gui\"\
    \ value=\"true\"/>\n    \t\t<arg name=\"verbose\" value=\"true\"/>\n    \t</include>\n\
    \    </launch>\n\nMore information about launch files and remapping can be found\
    \ in [the wiki](http://wiki.ros.org/roslaunch/XML/remap).\n\n**Option 2: modify\
    \ world file** \n\nThe topic names get defined in your `task_1_1.world` file on\
    \ line 113:\n\n    <plugin name='camera_control' filename='libgazebo_ros_camera.so'>\n\
    \      <cameraName>/main_camera</cameraName>\n      <alwaysOn>true</alwaysOn>\n\
    \      <updateRate>60</updateRate>\n      <imageTopicName>/main/image_raw</imageTopicName>\n\
    \      <cameraInfoTopicName>/main/camera_info</cameraInfoTopicName>\n      <frameName>main_camera</frameName>\n\
    \    </plugin>\n\nchange\n\n    <imageTopicName>/main/image_raw</imageTopicName>\n\
    \    <cameraInfoTopicName>/main/camera_info</cameraInfoTopicName>\n\nto\n\n  \
    \  <imageTopicName>/camera/image_raw</imageTopicName>\n    <cameraInfoTopicName>/camera/camera_info</cameraInfoTopicName>\n\
    \nNow run `rostopic list` and you'll see that you have \n\n    /camera/camera_info\n\
    \    /camera/image_raw\n    /camera/image_raw/compressed\n    /camera/image_raw/compressed/parameter_descriptions\n\
    \    /camera/image_raw/compressed/parameter_updates\n    /camera/image_raw/compressedDepth\n\
    \    /camera/image_raw/compressedDepth/parameter_descriptions\n    /camera/image_raw/compressedDepth/parameter_updates\n\
    \    /camera/image_raw/theora\n    /camera/image_raw/theora/parameter_descriptions\n\
    \    /camera/image_raw/theora/parameter_updates\n\nand you can save two versions\
    \ of your world file and you can pick and choose which one you want to use. However,\
    \ option 1 is (in my opinion) better."
