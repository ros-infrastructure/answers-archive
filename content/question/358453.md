  body_markdown: "There appear to be two potential workarounds:\n\n**HOST:**\n\nIf\
    \ you want to use host networking, you also much share the pid space so that each\
    \ DDS node can generate a unique GUID. ( All thanks go to @ruffsl, more detail\
    \ [here](https://answers.ros.org/question/296828/ros2-connectivity-across-docker-containers-via-host-driver/)\
    \ )\n\n    docker run --rm -d --net=host --pid=host <IMAGE>\n\n\n**MACVLAN:**\n\
    \nThis workaround seems to work more often than not but sometimes the container\
    \ needs to be restarted before it will see all nodes on the network. \n\n    docker\
    \ network create -d macvlan \\\n        --subnet=192.168.1.0/24 \\\n        --gateway=192.168.1.1\
    \ \\\n        --ip-range=192.168.1.64/27 \\\n        --attachable \\\n       \
    \ -o parent=enp8s0 \\\n        macnet\n\n    sudo ip link add macnet-shim link\
    \ eth0 type macvlan  mode bridge\n    sudo ip addr add 192.168.1.64/27 dev macnet-shim\n\
    \    sudo ip link set macnet-shim up\n\n    docker run --rm -d --net=macnet <IMAGE>"

How can I get ROS2 to run in docker across multiple hosts reliably?  I have two hosts, on an ethernet network:  

* Bridge networks do not support multicast 
* Overlay networks do not support multicast  
* macvlan networks cannot be accessed from the host machine (Workaround below)
* Host networks partially work, but I only see a random subset of the nodes on the network. (Workaround below)  
* Weave network performance is very poor. (A simple topic that typically runs natively at 270Hz only manages to get up to 20Hz)
