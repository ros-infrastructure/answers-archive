title: Robot keeps "floating" using Planar Move plugin
upvote_count: 0
---
 Robot's pose gets odd using `Planar Move plugin` under some circumstance, such as with terrain with ups and downs, or with collision. Specifically for example in the following video with rubbles, robot keeps "floating", or maintains linear z-value, after it hits and somehow got climbed up on the rubbles.

[youtube video 1](https://www.youtube.com/watch?v=Y-aDoaSrNnQ)

My guess is that this happens because the plugin updates the velocity of the model in the physics engine level per every loop and the [code as of today](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/7bc3d4af396274bb7956101edd4dd1a06bfb5c8c/gazebo_plugins/src/gazebo_ros_planar_move.cpp#L168) sends 0 to z, which may be conflicting against Gazebo's inherent physics computation or something.

This is actually [reported in the Gazebo-ROS plugin repo](https://github.com/ros-simulation/gazebo_ros_pkgs/issues/121).

This [sillily simple attempt](https://github.com/130s/gazebo_ros_pkgs/commit/5af4a0a90e9f0a17a95323296790a7cb94d1c8b8) seems to amend the situation.

[youtube video 2](https://www.youtube.com/watch?v=PN1Tx1nozH0&feature=youtu.be)

But I know this patch is far from ideal. What could be the best optimal solution to this?
