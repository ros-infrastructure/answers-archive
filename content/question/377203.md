  body_markdown: "Hi Thiago, I had this issue in my simulations too.... there is a\
    \ \"trick\" here to put the vehicle moving. In Autoware_AI runtime_manager in\
    \ the *mission_planning** tab you must add the following launch file: \"**my_mission_planning.launch**\"\
    :\n\n\n    <launch>\n      <arg name=\"map_source\" default=\"0\" /> <!-- Autoware=0,\
    \ Vector Map Folder=1, kml file=2 -->\n    \n    \n      <!-- dp_planner -->\n\
    \      <include file=\"$(find dp_planner)/launch/dp_planner.launch\">\n      \
    \  <arg name=\"mapSource\" value=\"$(arg map_source)\"/>\n      </include>\n \
    \   \n    \n    </launch>\n\n\n\nFor some reason, the Open Planner needs to be\
    \ fed with the dp_planner in order to work. I guess It feeds the local planner\
    \ in order to create the rollout local planners trajectory.\n\n**Regarding your\
    \ second issue: The vehicle remains stopped**\nThe trick is to add a **ROS node\
    \ from pure pursuit**, just launch the Pure Pursuit and and Twist Filter launch\
    \ files are not enough...\n\nTherefore in the motion_planning Tab, the launch\
    \ file \"**my_motion_planning.launch**\" must contain these launch files and the\
    \ pure_pursuit ROS node block (under \"--rosrun waypoint_follower pure_pursuit--\"\
    \ ):\n\n    <launch>\n    \n      <!-- Vehicle Contorl -->\n      <include file=\"\
    $(find runtime_manager)/launch_files/vehicle_socket.launch\"/>\n    \n    \n \
    \     <!-- pure_pursuit -->\n      <!-- Copied $(find pure_pursuit)/launch/pure_pursuit.launch\
    \ to use respawn attribute. -->\n      <arg name=\"is_linear_interpolation\" default=\"\
    True\"/>\n      <arg name=\"publishes_for_steering_robot\" default=\"False\"/>\n\
    \      <arg name=\"add_virtual_end_waypoints\" default=\"False\"/>\n      <arg\
    \ name=\"const_lookahead_distance\" default=\"4.0\"/>\n      <arg name=\"const_velocity\"\
    \ default=\"5.0\"/>\n      <arg name=\"lookahead_ratio\" default=\"2.0\"/>\n \
    \     <arg name=\"minimum_lookahead_distance\" default=\"6.0\"/>\n    \n     \
    \ <!-- 0 = waypoints, 1 = provided constant velocity -->\n      <arg name=\"velocity_source\"\
    \ default=\"0\"/>\n    \n      <!-- rosrun waypoint_follower pure_pursuit -->\n\
    \      <node pkg=\"pure_pursuit\" type=\"pure_pursuit\" name=\"pure_pursuit\"\
    \ output=\"log\" respawn=\"true\" respawn_delay=\"10\">\n        <param name=\"\
    is_linear_interpolation\" value=\"$(arg is_linear_interpolation)\"/>\n       \
    \ <param name=\"publishes_for_steering_robot\" value=\"$(arg publishes_for_steering_robot)\"\
    />\n        <param name=\"add_virtual_end_waypoints\" value=\"$(arg add_virtual_end_waypoints)\"\
    />\n        <param name=\"const_lookahead_distance\" value=\"$(arg const_lookahead_distance)\"\
    />\n        <param name=\"const_velocity\" value=\"$(arg const_velocity)\"/>\n\
    \        <param name=\"lookahead_ratio\" value=\"$(arg lookahead_ratio)\"/>\n\
    \        <param name=\"minimum_lookahead_distance\" value=\"$(arg minimum_lookahead_distance)\"\
    />\n        <param name=\"velocity_source\" value=\"$(arg velocity_source)\"/>\n\
    \      </node>\n    \n      <!-- twist_filter -->\n      <include file=\"$(find\
    \ twist_filter)/launch/twist_filter.launch\"/>\n    \n    </launch>\n\nI believe\
    \ now OpenPlanner must work, at least worked for me, but I used LGSVL simulator,\
    \ instead CARLA."
