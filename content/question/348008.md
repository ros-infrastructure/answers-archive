  body_markdown: "Hi @me_saw,\n\nWhen you spawn the robot in Gazebo is very important\
    \ to use the [Robot State Publisher](http://wiki.ros.org/robot_state_publisher).\
    \ The `joint_state_publisher` is like a debug node to check the joint states with\
    \ a topic while the `robot_state_publisher` is the node you need since it is the\
    \ tool that uses the robot_description to build the tf tree that rviz needs to\
    \ display your robot properly.\n\nYou can launch the robot_state_publisher to\
    \ generate a tf_tree with: \n\n    <node name=\"robot_state_publisher\" pkg=\"\
    robot_state_publisher\" type=\"robot_state_publisher\" />\n\nand check you tf_tree\
    \ with `rosrun rqt_tf_tree rqt_tf_tree`.\n\nWith this set up you will be able\
    \ to launch rviz and select in the Global Options --> Fixed Frame menu the Reference\
    \ Link of your description."

      Ok, To clarify things. When you launch Gazebo you are dealing with an abstraction of a real robot, hence you will need to provide a method to read from the joint states and publish that information. So either you have a plugin that reads from the Gazebo joints and publish the joint state information the RST publisher needs to build the TF tree, or you use already made tools like the `joint_state_controller/JointStateController` inerface provided in ROS control. You can find a tutorial [here](http://gazebosim.org/tutorials/?tut=ros_control).
      The important part is the addition of [transmissions](http://wiki.ros.org/urdf/XML/Transmission) and the load of the JointStateController controller interface.
