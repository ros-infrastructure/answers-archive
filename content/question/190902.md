    \ much into linking, so here is my naive interpretation of the problem: \nThe\
    \ boost thread header compiled in the vicon-lib is compatible to the thread symbol\
    \ for 1.5x , while ros asks for 1.4x . Since both symbols have the same name,\
    \ there is  no chance for the linker to decide which lib is the correct one to\
    \ link... Back then, I played quite a bit with linking, the result was always\
    \ the same: either the vicon sdk segfaulted or our ros interface, depending on\
    \ which boost lib the linker decided to link. \n\nThe only (but ugly) way out\
    \ I see for now, is to install a matching boost version and compile ros from source.\
    \ We did this on a few of our machines successfully, since we ran into other problems\
    \ with the old boost version. \n\nEven though the linking problem still exists,\
