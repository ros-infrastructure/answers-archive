  body_markdown: "### Protobuf intro\n\nGazebo messages are generated using Protocol\
    \ buffers (protobuf). The messages are described in `.proto` files, and Protobuf\
    \ uses that file to generate a C++ class.\n\nFor example, [this](https://bitbucket.org/osrf/gazebo/src/bae84f76b4ad7a6a7cecaeb3e76e545b8c8d5f3e/gazebo/msgs/contacts.proto?fileviewer=file-view-default)\
    \ is the description for the contacts message:\n\n    import \"contact.proto\"\
    ;\n    import \"time.proto\";\n    \n    message Contacts\n    {\n      repeated\
    \ Contact contact   = 1;\n      required Time time         = 2;\n    }\n\nYou\
    \ can see that the `contact` field is a `repeated` field of the `Contact` (singular)\
    \ message. For every repeated field, Protobuf generates a `<field_name>_size()`\
    \ function, such as the `contact_size()` one.\n\nThis is all described in the\
    \ [Protocol Buffers C++ Generated Code](https://developers.google.com/protocol-buffers/docs/reference/cpp-generated#repeatedmessage)\
    \ documentation.\n\n### Header files\n\nThis is not ideal, but personally, what\
    \ I do when I want to check a message's API, is to check its header files (who\
    \ has time to read the protobuf documentation? :P). \n\nProtobuf creates a `<message_name>.pb.h`\
    \ header for each message and installs it in your system. You can look for the\
    \ `contacts.pb.h` header like this:\n\n    find /usr | grep contacts.pb.h\n\n\
    Then you'll find something similar to this:\n\n    /usr/local/include/gazebo-7/gazebo/msgs/contacts.pb.h\n\
    \nSo you can open that file and take a look at the API:\n\n    gedit /usr/local/include/gazebo-7/gazebo/msgs/contacts.pb.h\n\
    \nDigging through header files is definitely not ideal... We do have some form\
    \ of message API documentation, but that's broken, as described on [this](https://bitbucket.org/osrf/gazebo/issues/2153/message-api-documentation-broken)\
    \ issue.\n"
