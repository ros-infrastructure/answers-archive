    In older version of gazebo (1.0.x) that was in fuerte, `index` was ignored inside of [ODEHingeJoint::SetForce](https://bitbucket.org/osrf/gazebo/src/13ac178834e050883f647b5dfb1e4ea926d1db76/gazebo/physics/ode/ODEHingeJoint.cc?at=fuerte#cl-144)):

    <pre>
    void ODEHingeJoint::SetForce(int /*index*/, double _torque)
    {
      if (this->childLink)
        this->childLink->SetEnabled(true);
      if (this->parentLink)
        this->parentLink->SetEnabled(true);
      dJointAddHingeTorque(this->jointId, _torque);
    }
    </pre>

    In latest groovy, [ODEHigneJoint::SetForce](https://bitbucket.org/osrf/gazebo/src/5a51c98465a6ecf6da278d9b2e89e28dbe9fb85f/gazebo/physics/ode/ODEHingeJoint.cc?at=default#cl-143) was fixed to use the index correctly, thus exposing the bug you are seeing.

    Error [Joint.cc:408] Invalid joint index [2] when trying to apply force

spammed to the terminal when I spawn it using Gazebo 1.3 in Groovy (using .debs from the shadow-fixed repo). The controller plugins worked fine with fuerte before.
