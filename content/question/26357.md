  body_markdown: "Solved it!\n\nThe problem was the wrong type of argument in the\
    \ callback function `cb`. i.e. `ConstSonarPtr`.\n\nI did a `gz topic -i <topic-name>`\
    \ and found that the `msg` type is actually `ConstSonarStampedPtr`.\n\n\n    $\
    \ gz topic -i /gazebo/mtp_world/mtp_robot/left_sonar/mtp_sonar_sensor_left/sonar\n\
    \    Type: gazebo.msgs.SonarStamped\n\n    Publishers:\n            192.168.1.4:39483\n\
    \    \n    Subscribers:\n        192.168.1.4:39483\n\n\n\nFInally had to make\
    \ the following changes to the `cb` callback to get the range values:\n\n    private:\
    \ void cb(ConstSonarStampedPtr &_msg) {\n        if (_msg == NULL) {\n       \
    \     return;\n        }\n        gazebo::msgs::Sonar sonarMsg = _msg->sonar();\n\
    \        std::cout << \"Range: \" << sonarMsg.range() << std::endl;\n    }\n\n\
    Thanks to a post here somewhere, I found about `gz topic -i <topic-name>` and\
    \ was able to solve the problem."

I have spent some time looking this over the internet but could not find a working solution yet. Documentation doesn't have much on Sonar sensors..

I have a very basic understanding of topics work. The message returned from the subscriber is `NULL` for this topic.
