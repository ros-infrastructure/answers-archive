    \n**26.04.2021 EDIT:**  Only the first two steps are sufficient for making it\
    \ work in ROS Melodic, the rest of the steps are important only if you try this\
    \ on a Jetson. Also you can take an already working docker container with everything\
    \ inside: `docker pull funderburger/ardrone_autonomy_ros_ubuntu_16:latest` (some\
    \ more info [here.](https://github.com/Funderburger/Hallway-self-driving-drone)\
    \ )\n\nEDIT:\n\nSo, basically, the answer I found it is not exactly what I want,\
    \ because that guy use a docker container, but for now it works. So the steps\
    \ I followed are exactly this (in case the page disappears):\n\n1. I downloaded\
    \ the docker image using: \n\n    `sudo docker pull ros:kinetic-robot-xenial`\n\
    \n And then followed this steps to run the image: [http://wiki.ros.org/docker/Tutorials/Docker][1]\n\
    \n2. Then I cloned the ardrone_autonomy package in a worksapce, from the above\
    \ link:\n\n>      mkdir -p catkin_ws/src\n>      cd catkin_ws/src\n>      git\
    \ clone https://github.com/dsapandora/ardrone_autonomy.git\n>      apt-get update\n\
    >      cd ../\n>      rosdep install --from-paths src --ignore-src -r -y\n>  \
    \    catkin_make\n\n3. After the error with `bswap` appears, edit this file: `\
    \ devel/src/ardronelib/ARDroneLib/VP_SDK/VP_Os/linux/intrin.h` and replace:\n\n\
    .\n\n     static INLINE uint32_t _byteswap_ulong(uint32_t value)\n        {\n\
    \          __asm(\"bswap %0\":\n              \"=r\" (value):\n              \"\
    0\" (value));\n        \n          return value;\n        }\n\nwith this:\n\n\
    \    static INLINE uint32_t _byteswap_ulong(uint32_t value)\n    {\n      int32_t\
    \ tmp;\n    \n      __asm __volatile(\n        \"eor        %1, %2, %2, ror #16\\\
    n\"\n        \"bic        %1, %1, #0x00ff0000\\n\"\n        \"mov        %0, %2,\
    \ ror #8\\n\"\n        \"eor        %0, %0, %1, lsr #8\"\n        : \"=r\" (value),\
    \ \"=r\" (tmp)\n        : \"r\" (value)\n      );\n    \n      return value;\n\
    \    }\n\nand comment this line: `_BitScanReverse(&index, code);`\n\n\n4. After\
    \ you do this if you try to give it a `catkin_make` it should appear the last\
    \ error which can be resolved by replacing this line (from the same file as above):\n\
    \n`\"mov        %0, %2, ror #8\\n\"`\n\nwith:\n\n`\"mov        %0, %2\\n\"`\n\n\
    and now should work just fine."
