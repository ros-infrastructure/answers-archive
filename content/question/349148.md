  body_markdown: "The former (ie: `rossrv`) is a tool to display ROS service *definitions*\
    \ (ie: the files which define them, ending in `.srv`).\n\nThe latter (ie: `rosservice`)\
    \ is a tool to interact with ROS service *servers* (ie: those running as part\
    \ of your ROS node). It allows you to call services in nodes, display the returned\
    \ result, find out about their types and find all service servers which offer\
    \ services of a specific type (see `rosservice --help` for all supported operations).\n\
    \nSo `rossrv` is an \"off-line\" tool, while `rosservice` is a tool you use with\
    \ a live, running ROS node graph.\n\n> I have `catkin_ws/src/simple_arm/srv/GoToPosition.srv`\
    \ that I see when I run `rossrv list` as\n`simple_arm/GoToPosition`\n> \n> However,\
    \ my request handler is in `catkin_ws/src/simple_arm/src/arm_mover.cpp` and I\
    \ only see it in `rosservice list` as `/arm_mover/safe_move`. Why can't I see\
    \ `/arm_mover/safe_move` under `rossrv list` if it is a service? And the inverse\
    \ with `simple_arm/GoToPosition`\n\nThis should now be clear: `rossrv` would only\
    \ show you information on (and contents of) the `GoToPosition.srv` file, while\
    \ `rosservice` will show you information about `/arm_mover/safe_move` (which is\
    \ apparently the name you've given to the service server."

 What's the difference? I see my service in `rossrv list` but not with `rosservice list`. 

From [ROS wiki](http://wiki.ros.org/Services)

> •	rossrv: displays information about .srv data structures. 

> •	rosservice: lists and queries ROS Services

I have `catkin_ws/src/simple_arm/srv/GoToPosition.srv` that I see when I run `rossrv list` as
`simple_arm/GoToPosition`

However, my request handler is in `catkin_ws/src/simple_arm/src/arm_mover.cpp` and I only see it in `rosservice list` as `/arm_mover/safe_move`. Why can't I see `/arm_mover/safe_move` under `rossrv list` if it is a service? And the inverse with `simple_arm/GoToPosition`?
