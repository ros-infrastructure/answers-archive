  body_markdown: "[Polled topics](http://www.ros.org/reps/rep-0106.html) never really\
    \ made it (unfortunately). But I'm not entirely sure that is what you want here\
    \ anyway.\n\n> [..] tell the node when to start/stop fetching from the IP Camera\
    \ rather than just continuously fetch from the IP Camera regardless of who's subscribed.\n\
    \nI'm not sure I understand completely, but if you're just worried about fetching\
    \ from the camera when there are no subscribers, this kind of Node behaviour is\
    \ typically achieved using [ros::Publisher::getNumSubscribers()](http://docs.ros.org/kinetic/api/roscpp/html/classros_1_1Publisher.html#ad56c8e954020290dcb87cd6bbd330a2b).\
    \ Something like:\n\n    [..]\n    \n    ros::Publisher my_pub = n.advertise<..>(..)\n\
    \    ros::Rate ..\n    \n    [..]\n    \n    while (ros::ok())\n    {\n      [..]\n\
    \    \n      if (my_pub.getNumSubscribers() > 0)\n      {\n        // poll IP\
    \ camera, convert data, publish msg\n      }\n      else\n      {\n        //\
    \ do nothing (or at least: don't poll IP camera)\n      }\n    \n      [..]\n\
    \    \n      rate.sleep();\n    }\n    \n    [..]\n\nAs soon as a `Subscriber`\
    \ connects, you start polling the resource. As soon as there are no more subscribers,\
    \ you stop. No explicit action required by your `Subscriber`s.\n\nAn alternative\
    \ would be to add a Service to your node (of type [std_srvs/Trigger](http://docs.ros.org/api/std_srvs/html/srv/Trigger.html))\
    \ that (en|dis)ables your Publisher, but that requires subscribing nodes to know\
    \ about that service, and to know about the flow of control required to interoperate\
    \ with your node. All of which reduces reusability.\n"

Hi,

So the GetPolledImage service from the polled_camera package (http://wiki.ros.org/polled_camera) makes a single request to the image publisher.

Is there another "core" ROS service similar to GetPolledImage that tells the image publisher to continuously publish at N Hz (ie StartPollImage) until told to stop (perhaps via a StopPollImage service)?  

Or do I just need to roll, create my own (trying not to reinvent the wheel)?

----

(edit 1/21) - I've been asked to give my use case.  I have an IP Camera and a ROS node that can HTTP request an image from the IP Camera.  A Start/StopPollImage can tell the node when to start/stop fetching from the IP Camera rather than just continuously fetch from the IP Camera regardless of who's subscribed.  Hope this makes sense.  Happy to further clarify.
