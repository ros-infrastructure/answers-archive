  body_markdown: "You can see [here](http://docs.ros.org/en/api/moveit_ros_planning_interface/html/classmoveit_1_1planning__interface_1_1MoveGroupInterface.html)\
    \ that the [Plan struct](http://docs.ros.org/en/api/moveit_ros_planning_interface/html/structmoveit_1_1planning__interface_1_1MoveGroupInterface_1_1Plan.html)\
    \ contains a [moveit_msgs::RobotInterface](http://docs.ros.org/en/api/moveit_msgs/html/msg/RobotTrajectory.html)\
    \ message, so you should be able to access each  point as follows, basing off\
    \ [this section in the tutorial](https://ros-planning.github.io/moveit_tutorials/doc/move_group_interface/move_group_interface_tutorial.html#planning-to-a-pose-goal)\
    \ something like this:\n\n    moveit::planning_interface::MoveGroupInterface::Plan\
    \ plan;    \n    move_group.plan(plan);\n    \n    int i = 0;\n    trajectory_msgs::JointTrajectoryPoint\
    \ point = plan.trajectory_.joint_trajectory.points[i];\n\nBut I am not sure why\
    \ you would want to do this, since you can already execute and visualize the trajectory\
    \ as described in [this tutorial](https://ros-planning.github.io/moveit_tutorials/doc/move_group_interface/move_group_interface_tutorial.html#visualizing-plans).\
    \ You should not need to extract a vector of joint states - you can pass the JointTrajectory\
    \ message directly to a controller (which the `MoveGroupInterface` helps you do\
    \ with the `execute` command)."
