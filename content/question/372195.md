 Hey eveyrone,

I'm trying to use a launch file on my thinkpad t480 running ROS Noetic on Ubuntu 20.04 to start a ROS node on my raspberry pi 0 W running ROS Melodic on raspbian buster (using [this](https://gist.github.com/Tiryoh/76be0ac467c09667ca51b5f8d9f4b3bc) tutorial). Here is the launch file joy_teleop_remote.launch

       <launch>
    
        <node pkg="joy" type="joy_node" name="joy_node"/>
        <node pkg="kamigami_teleop" type="joy_teleop.py" name="xbox_control"/>
    
        <machine
                name="kamigami_robot"
                address="multirobot2.local"
                env-loader="/opt/ros/melodic/env_remote.sh"
                user="pi"
        />  
    
        <node machine="kamigami_robot" pkg="kamigami_driver" type="kamigami_interface.py" name="kamigami_interface"/>
    
         </launch>

and here is the env-loader script

    #!/bin/bash
    
    export ROS_MASTER_URI=http://jaythink.local:11311
    
    source /opt/ros/melodic/setup.bash
    source ~/ros_workspaces/kamigami_ws/devel/setup.bash
    
    exec "$@

when I run `joy_teleop_remote.launch`, I get the following terminal output

I think this could be due to `--sigint-timeout` being automatically used as a command line argument, when it was only [just recently added to ROS](http://docs.ros.org/en/latest-available/changelogs/roslaunch/changelog.html) and thus not supported by the Melodic machine. I guess my question now is if anyone has suggested fixes for this, or workarounds, perhaps just to remove --sigint-timeout as an argument of roslaunch? I can always just manually ssh into the raspberry pi to start my node, but that would be a little annoying and not desirable. I unfortunately am unable to find a guide on running Noetic on the Raspberry Pi 0 W, but that is something I may look into in the next couple of months. Thank you!
