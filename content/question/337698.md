  body_markdown: "There are no \"easy\" ways, you just need to follow [the different\
    \ steps described in the wiki](http://wiki.ros.org/nodelet/Tutorials/Porting%20nodes%20to%20nodelets)\
    \ and it shouldn't be too difficult. I will expand on each point to make it clear\
    \ because I already had some trouble with it in the past (you can also check [this\
    \ really simple example](https://github.com/ros/common_tutorials/blob/indigo-devel/nodelet_tutorial_math/src/plus.cpp))\
    \ :\n\n - add the necessary #includes :\n\n        #include <nodelet/nodelet.h>\n\
    \        #include <pluginlib/class_list_macros.h>\n\n - get rid of int main()\
    \ \n\nYou don't need it anymore since your program will be run via roslaunch and\
    \ the different functions can be called from the the method `onInit()` (which\
    \ is described under). \n\n - subclass nodelet::Nodelet \n\nThis means your class\
    \ needs to inherit from `nodelet::Nodelet` like this :\n\n    class TestNodelet\
    \ : public nodelet::Nodelet\n\n - move code from constructor to `onInit()` \n\n\
    The method `onInit` is called by the `nodelet manager` to initialize every nodelet.\
    \ This method is defined as `virtual` in the Nodelet class API which means that\
    \ you **must** declare this method every time you create a nodelet (in private).\
    \ You will initialize everything in this method, like the nodehandle and your\
    \ pub/sub or even your threads if you want.\n\n - add the PLUGINLIB_EXPORT_CLASS\
    \ macro\n\nJust add this at the end of your file (but within the namespace if\
    \ you have one) :\n\n    PLUGINLIB_EXPORT_CLASS(test::TestNodelet, nodelet::Nodelet);\n\
    \n - add `<build_depend>` and `<run_depend>` dependencies on nodelet in the package\
    \ manifest. \n\nJust add this in `package.xml` :\n\n      <build_depend>pluginlib</build_depend>\n\
    \      <build_depend>nodelet</build_depend>\n      <exec_depend>pluginlib</exec_depend>\n\
    \      <exec_depend>nodelet</exec_depend>\n\n - add the `<nodelet>` item in the\
    \ `<export>` part of the package manifest \n\nStill in package.cml, add this :\n\
    \n      <export>\n          <nodelet plugin=\"${prefix}/plugins/nodelets.xml\"\
    />\n      </export>\n\n - create the .xml file to define the nodelet as a plugin\
    \ \n\nCreate a folder `plugins` and add into it the file `nodelets.cml` :\n\n\
    \    <library path=\"lib/libtest_nodelet\">\n      <class name=\"your_package/TestNodelet\"\
    \n             type=\"test::TestNodelet\"\n             base_class_type=\"nodelet::Nodelet\"\
    >\n        <description>\n          Node to nodelet test\n        </description>\n\
    \      </class>\n    </library>\n\n - make the necessary changes to CMakeLists.txt\
    \ (comment out a rosbuild_add_executable, add a rosbuild_add_library) \n\nYou\
    \ need to add the same package as in the package.cml first :\n\n    find_package(catkin\
    \ REQUIRED COMPONENTS\n      roscpp\n      pluginlib \n      nodelet \n    )\n\
    And then you just need to define the nodelet as a library and link it :\n\n  \
    \  # Nodelet library\n    add_library(test_nodelet src/test.cpp)\n    add_dependencies(test_nodelet\
    \ ${PROJECT_NAME})\n    target_link_libraries(test_nodelet ${catkin_LIBRARIES})\n\
    \n\n\nSo your code should be like this :\n\n    #include \"ros/ros.h\"\n    #include\
    \ \"std_msgs/String.h\"\n    #include <nodelet/nodelet.h>\n    #include <pluginlib/class_list_macros.h>\n\
    \  \n    namespace test {\n    \n    /*********************\n    ** Nodelet\n\
    \    **********************/\n    class TestNodelet : public nodelet::Nodelet\n\
    \    {\n        public:\n            TestNodelet()\n            {\n          \
    \  }\n    \n        private:\n            virtual void onInit()\n            {\n\
    \                ros::NodeHandle& private_nh = getPrivateNodeHandle();\n     \
    \           pub = private_nh.advertise<std_msgs::String>(\"out\", 10);\n     \
    \           sub = private_nh.subscribe(\"in\", 10, &TestNodelet::callback, this);\n\
    \            }\n            ros::Publisher pub;\n            ros::Subscriber sub;\n\
    \    \n            void callback(const std_msgs::String::ConstPtr& input)\n  \
    \          {\n                std_msgs::String output;\n                output.data\
    \ = input->data;\n                pub.publish(output);\n            }\n    };\n\
    \    PLUGINLIB_EXPORT_CLASS(test::TestNodelet, nodelet::Nodelet);\n    }\n\nNow\
    \ you just have to create a launch file with a nodelet manager and your nodelet\
    \ :\n\n    <launch>\n      <node pkg=\"nodelet\" type=\"nodelet\" name=\"nodelet_manager\"\
    \  args=\"manager\" output=\"screen\"/>\n    \n      <node pkg=\"nodelet\" type=\"\
    nodelet\" name=\"test\" args=\"load your_package/TestNodelet nodelet_manager\"\
    \ output=\"screen\"/>          \n    </launch>"

As I understand nodelets pass data around with addresses rather than chewing memory and so for a structure such as many clouds, passing this data around nodelets in the same manager would be more efficient.
