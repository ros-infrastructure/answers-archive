  body_markdown: "I think you are just having a namespace issue. By placing the `<rosparam>`\
    \ tag inside of the `get_extrinsic` node tag you are telling all of the parameters\
    \ to load up inside of the `get_extrinsic` namespace. For example, running your\
    \ launch file then the `rosparam list` command should return \n\n    /get_extrinsic/extrinsic_parameters/rotation_matrix/cols\n\
    \    /get_extrinsic/extrinsic_parameters/rotation_matrix/data\n    /get_extrinsic/extrinsic_parameters/rotation_matrix/rows\n\
    \    /get_extrinsic/extrinsic_parameters/translation_vector/cols\n    /get_extrinsic/extrinsic_parameters/translation_vector/data\n\
    \    /get_extrinsic/extrinsic_parameters/translation_vector/rows\n\nIn your code,\
    \ you look up the first one using an absolute name that agrees with the above\
    \ names.... see the following line:\n\n    if(!node.getParam(\"/get_extrinsic/extrinsic_parameters/rotation_matrix/cols\"\
    , cols))\n\nAll of the rest of your params you lookup using relative naming like\
    \ this:\n\n    if(!node.getParam(\"rotation_matrix/cols\", cols))\n\nWith your\
    \ current launch file, that will resolve to `/rotation_matrix/cols` not `/get_extrinsic/extrinsic_parameters/rotation_matrix/cols`.\
    \ Using a [private nodehandle](http://wiki.ros.org/roscpp_tutorials/Tutorials/AccessingPrivateNamesWithNodeHandle)\
    \ would be a good way to fix this. Also check out the [Names](http://wiki.ros.org/Names)\
    \ page and the [roscpp/Overview/NodeHandles](http://wiki.ros.org/roscpp/Overview/NodeHandles)\
    \ page.\n\n"
