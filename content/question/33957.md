  body_markdown: "Actually, the environment server is perfectly happy to accept an\
    \ empty collision map.  If you build and start up this executable you should see\
    \ that the environment server starts up:\n\n    #include <ros/ros.h>\n    #include\
    \ <arm_navigation_msgs/CollisionMap.h>\n    \n    int main(int argc, char** argv)\n\
    \    {\n      ros::init(argc, argv, \"empty_collision_map_publisher\");\n    \
    \  //figuring out whether robot_description has been remapped\n    \n      ros::NodeHandle\
    \ nh;\n    \n      ros::Publisher pub = nh.advertise<arm_navigation_msgs::CollisionMap>(\"\
    /collision_map_occ\", 1, true);\n    \n      while(ros::ok()) {\n        arm_navigation_msgs::CollisionMap\
    \ coll;\n        coll.header.frame_id = \"odom_combined\";\n        coll.header.stamp\
    \ = ros::Time::now();\n        pub.publish(coll);\n      }\n    \n      return\
    \ 0;\n    }\n\nThe issue is that there are checks in collider.cpp to only publish\
    \ if there are some occupied points (check out the first line of the publishCollisionMap\
    \ function).  One option is to add a parameter to collider that will cause it\
    \ to publish even if there are no points - if this is acceptable I'll add it in\
    \ and release arm_navigation_experimental.  "

title: Is it possible to configure environment server with empty collision map?
upvote_count: 0
---
I have a robot with an arm_navigation stack configured to use a collision map, and it works fine. However, if arm_navigation is started with no visible environment obstacles, the environment server will not complete its configuration sequence and disallow planning motions. This is the typical output:

    Waiting for environment server planning scene registration service /register_planning_scene

Publishing an empty point cloud does not seem to make the environment server happy, so is there a way about this use case?. Currently I'm publishing a dummy cloud with a single point outside the workspace of my robot (a hack that works in the meantime).

Further details on what's going on: An environment server instance is not completely constructed because it [gets stuck in a loop](https://kforge.ros.org/armnavigation/armnavigation/file/1e25b730b303/planning_environment/src/monitors/environment_server.cpp#l75), which requires waking up [this CollisionSpaceMonitor callback](https://kforge.ros.org/armnavigation/armnavigation/file/1e25b730b303/planning_environment/src/monitors/collision_space_monitor.cpp#l353) to break it.

**Edit**
The problem statement can be generalized to saying that apparently the collision map is not updated when an empty point cloud is published. I'm using the collider node, and with an already configured environment server, the octomap cells are not updated if I go from an environment with obstacles to one without any.

TIA.
