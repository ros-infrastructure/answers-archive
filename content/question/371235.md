  body_markdown: "> I can't enable all ports unfortunately, would enabling some of\
    \ them allow ROS to work? \n\nno, unfortunately not.\n\nThere are various Q&As\
    \ about this here on ROS Answers. The keywords are \"ephemeral ports\".\n\nIn\
    \ short: ROS nodes can (and will) use any port from the ephemeral range, both\
    \ UDP and TCP (depending on how subscribers are configured).\n\nThe only \"static\
    \ port\" (in the sense that you can control it) is the port at which the XML RPC\
    \ server listens for connections. That would be what you configure with the `ROS_MASTER_URI`\
    \ environment variable.\n\nThis is also what makes `rostopic list` and `rostopic\
    \ info` work, as those mostly use the XML RPC server.\n\n`roswtf` complaining\
    \ about connections not being there or it unable to connect to nodes running remotely\
    \ is a result of connections not being allowed.\n\nFor networks like the one you\
    \ describe, overlaying a virtual network (via VPN or some other mechanism) is\
    \ typically easiest and robust. There are various peer-to-peer VPN solutions which\
    \ could work (these don't use a central server, but connect hosts directly). One\
    \ would be [tinc](https://www.tinc-vpn.org) (OSS), there are other, commercial\
    \ options available as well. ROS Discourse has a few announcements you could look\
    \ for.\n\n> connections can only be established from robot to server\n\nI guess\
    \ this means: they can only be *initiated*. If you'd really only had one directional\

    \ network configuration, but with OpenGL and/or your X server not working and\
    \ your workspace setup not being correct."
