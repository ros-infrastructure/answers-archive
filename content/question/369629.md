  body_markdown: "1.   Actuated or not, RViz reflects the current transform tree.\
    \  If it's visualizing the robot but doesn't show updated poses, it's because\
    \ RViz doesn't know about them.  Do you have a `robot_state_publisher` node running?\
    \  Here's an example from the [tutorial](http://wiki.ros.org/robot_state_publisher/Tutorials/Using%20the%20robot%20state%20publisher%20on%20your%20own%20robot#Running_as_a_ROS_node):\n\
    \n        <launch>\n          <!-- Load the urdf into the parameter server. -->\
    \  \n          <param name=\"my_robot_description\" textfile=\"$(find mypackage)/urdf/robotmodel.xml\"\
    />\n        \n          <node pkg=\"robot_state_publisher\" type=\"robot_state_publisher\"\
    \ name=\"rob_st_pub\" >\n            <remap from=\"robot_description\" to=\"my_robot_description\"\
    \ />\n            <remap from=\"joint_states\" to=\"different_joint_states\" />\n\
    \          </node>\n        </launch>\n\n2. If there's no friction, damping, or\
    \ actuator, there's nothing to stop the joint once it starts moving, so what you\
    \ describe sounds like expected behavior.  If the behavior doesn't make sense--even\
    \ for a fricitonless world-- then some of the other physical parameters may be\
    \ off, but we'll need more information to track down the problem.  The [URDF joint\
    \ wiki](http://wiki.ros.org/urdf/XML/joint) provides information on how to add\
    \ damping or friction to a joint:\n\n        <joint name=\"my_joint\" type=\"\
    floating\">\n          <origin xyz=\"0 0 1\" rpy=\"0 0 3.1416\"/>\n          <parent\
    \ link=\"link1\"/>\n          <child link=\"link2\"/>\n    \n          <calibration\
    \ rising=\"0.0\"/>\n          <dynamics damping=\"0.7\" friction=\"0.0\"/>  #\
    \ Make one of these non-zero\n          <limit effort=\"30\" velocity=\"1.0\"\
    \ lower=\"-2.2\" upper=\"0.7\" />\n          <safety_controller k_velocity=\"\
    10\" k_position=\"15\" soft_lower_limit=\"-2.0\" soft_upper_limit=\"0.5\" />\n\
    \        </joint>\n\nIf you want to see the casters move properly, you'll need\
    \ surface friction between them and the ground.  The [Gazebo friction tutorial](http://gazebosim.org/tutorials?tut=friction)\
    \ provides an example and some helpful links.  You may also consider just modeling\
    \ them as frictionless spheres, depending on your application.\n\n----------\n\
    \n###Update 1\n\nYou can add actuators without using them, so the joint remains\
    \ free to move.  Since you're using a `JointStateController`, just add a transmission\
    \ to each movable joint in `ridgeback.urdf.xacro`.  Here's an example for `cargo_cart_joint`:\n\
    \n    ...\n\n    <joint name=\"cargo_cart_joint\" type=\"revolute\">\n      <origin\
    \ xyz=\"0 0 0.025\" rpy=\"0 0 0\" />\n      <parent link=\"tow_hitch_link\"/>\n\
    \      <child link=\"cargo_cart_link\" />\n      <axis xyz=\"0 0 1\" />\n    \
    \  <limit lower=\"-${PI/2}\" upper=\"${PI/2}\" velocity=\"0\" effort=\"0\"/>\n\
    \      <dynamics damping=\"${damping_coef}\" friction=\"${friction_coef}\" />\n\
    \    </joint>\n    \n    <transmission name=\"cargo_cart_trans\">\n      <type>transmission_interface/SimpleTransmission</type>\n\
    \      <joint name=\"cargo_cart_joint\">\n        <hardwareInterface>hardware_interface/VelocityJointInterface</hardwareInterface>\n\
    \      </joint>\n      <actuator name=\"cargo_cart_joint_actuator\">\n       \
    \ <mechanicalReduction>1</mechanicalReduction>\n      </actuator>\n    </transmission>\n\
    \n    ...\n\nThen, `ridgeback_joint_publisher` will publish the states of those\
    \ joints.  It only finds joints \"registered to a `hardware_interface::JointStateInterface`\"\
    \ as mentioned in the [`ros_control` wiki](https://wiki.ros.org/ros_control).\
    \  You'll also have to get rid of `joint_state_publisher_gui` in `empty_world.launch`\
    \ as that will collide and cause the published joint state to flip back and forth.\n\
    \n\n----------\n###Update 2\n\nI agree that revolute joints seem to behave as\
    \ expected, though I don't know why the continuous joints don't.  In any case,\
    \ I recommend adding some trailing distance to the casters to encourage \"following\"\
    \ behavior, and adding damping/friction to address the drift/skid issue. \n I\
    \ changed your URDF file as follows:\n\n    ...\n\n    <xacro:property name=\"\
    damping_coef\" value=\"0.7\" />\n    <xacro:property name=\"friction_coef\" value=\"\
    0.5\" />\n\n    ...\n\n    <joint name=\"${prefix}_${side}_cart_wheel\" type=\"\
    continuous\">\n      <parent link=\"${prefix}_${side}_wheel_holder_mid_link\"\
    />\n      <child link=\"${prefix}_${side}_cart_wheel_link\" />\n      <axis xyz=\"\
    0 1 0\" />\n      <origin xyz=\"-0.1 ${-(s_location*wheel_width/2)} -0.11\" rpy=\"\
    0 0 0\"/>  # Note x < 0\n    </joint>\n\n    ...\n\nand in `ridgeback.gazebo`\
    \ (used to set friction to zero):\n\n    ...\n    \n    <gazebo reference=\"front_left_cart_wheel_link\"\
    >\n      <material>Gazebo/DarkGrey</material>\n    </gazebo>\n\n    <gazebo reference=\"\
    front_right_cart_wheel_link\">\n      <material>Gazebo/DarkGrey</material>\n \

    \    </gazebo>\n\n    <gazebo reference=\"rear_right_cart_wheel_link\">\n    \
    \  <material>Gazebo/DarkGrey</material>\n    </gazebo>\n\n    ..."
