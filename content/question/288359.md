    This is not a ROS-specific issue, and is instead expected Python behavior when using relative module imports within a package. I just looked through a bunch of Python documentation trying to figure out somewhere where it justifies or explains this behavior, and I really couldn't find much. I might have missed something, but I found no reference to the behavior you are seeing in [PEP 328](https://www.python.org/dev/peps/pep-0328/), [official Python 2.7 Modules documentation](https://docs.python.org/2.7/tutorial/modules.html), or this [awesome SO answer on Python modules, packages, and scripts](https://stackoverflow.com/a/14132912/1082525). Eventually, I did find a few references that at least mention this behavior:

     - In the Python 3.5 documentation they added [a section on Submodules](https://docs.python.org/release/3.5.0/reference/import.html#submodules) that specifically describes this behavior.
     - Nick Coghlan's Python blog has a post on common traps of the import system, and there is a section called [The submodules are added to the package namespace trap](http://python-notes.curiousefficiency.org/en/latest/python_concepts/import_traps.html#the-submodules-are-added-to-the-package-namespace-trap)

    It seems to me that whatever package test you used, didn't properly mimic the structure of the `rosbag` package.

I noticed that in native ROS packages all available modules seem to be imported at package level always. For example let us consider the `rosbag` python package. This is the output I see when I print the list of modules imported at package-level.

    >>> import rosbag
    >>> dir(rosbag)
    ['Bag', 'Compression', 'ROSBagException', 'ROSBagFormatException', 'ROSBagUnindexedException', '__builtins__', '__doc__', '__file__', '__name__', '__package__', '__path__', 'bag', 'migration', 'rosbag_main', 'rosbagmain']

However the  `__init__.py` file of rosbag package does not explicitly import `bag`, `migration` and `rosbag_main`. How are these these modules getting imported by themselves?

In order to verify if this is something done by the catkin build system, I wrote my own ros python package. My custom package did't any modules imported at package level. So my question is what makes the ROS native python packages special to cause this behavior?

In order to understand this question better, if you want to access the rosbag source, see the link
https://github.com/ros/ros_comm/tree/lunar-devel/tools/rosbag/src/rosbag
