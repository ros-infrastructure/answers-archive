  body_markdown: "Since planner and control servers are implemented with the use of\
    \ actions in navigation2, you can specify the planner_id or controller_id to specify\
    \ a particular one in run time by specifying related fields in action definition.\
    \ \n[for instance](https://github.com/ros-planning/navigation2/blob/5a7027536068183602f10b419bd711fafdad6784/nav2_msgs/action/ComputePathToPose.action#L4)\
    \ you will see a planner_id field, fill that programmatically on run time. \n\n\
    \    #goal definition\n    geometry_msgs/PoseStamped goal\n    geometry_msgs/PoseStamped\
    \ start\n    string planner_id\n    bool use_start # If true, use current robot\
    \ pose as path start, if false, use start above instead\n    ---\n    #result\
    \ definition\n    nav_msgs/Path path\n    builtin_interfaces/Duration planning_time\n\
    \    ---\n    #feedback\n\nTake a look at how to configure planners [here](https://navigation.ros.org/configuration/packages/configuring-planner-server.html),\
    \  you will need to append the array of strings that refers to names of planner\
    \ plugins\n\n\n    planner_server:\n      ros__parameters:\n        expected_planner_frequency:\
    \ 20.0\n        planner_plugins: ['GridBased1', 'GridBased2']\n        GridBased1:\n\
    \          plugin: 'nav2_navfn_planner/NavfnPlanner'\n\n        GridBased2:\n\
    \          plugin: 'some_planner/SomePlanner'\n\nThen in the action call you would\
    \ specify planner_id as one of  `['GridBased1', 'GridBased2']` same should apply\
    \ to the controllers."
