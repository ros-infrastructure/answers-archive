    [Here](https://github.com/bgromov/brl_tools) is my first attempt on Python code.

    The `recompose.py` script allows to take a message of any(?) complexity and generate another message based on given format. The format of new message is specified by YAML string, where the values of elements are the paths (delimited by `/`) to a data in input message.

    The most valuable use case for myself is to take a complex message like [gazebo_msgs/ContactsState](http://ros.org/doc/groovy/api/gazebo_msgs/html/msg/ContactsState.html) and combine [geometry_msgs/WrenchStamped](http://ros.org/doc/groovy/api/geometry_msgs/html/msg/WrenchStamped.html). Main problem here is that we need both `std_msgs/Header` and `geometry_msgs/Wrench` to be combined in a new message. However these fields are spread across the `ContactsState`.

    So, this issue can be solve with the provided script as follows:

        rostopic echo /gazebo_bumper | recompose.py "{header: header, wrench: 'states[0]/total_wrench'}"

    Maybe I'm reinventing the wheel, but I was unable to find a ready to use solution so far.

    Hope it can be useful for others.

Is there a tool that can take a complex message from one topic, then compose a new message from some of its fields and publish it on another topic?

For instance, [JTCartesianController](http://ros.org/wiki/robot_mechanism_controllers/JTCartesian%20Controller) exposes rather complex [state](http://www.ros.org/doc/api/robot_mechanism_controllers/html/msg/JTCartesianControllerState.html), where I need only `state/x` field of type `geometry_msgs::PoseStamped`. So such magic tool should do something like:

    $ rosmagic /jt_cart_controller/state/x /robot_pose

`rostopic` is able to `echo` 'subtopics', but there is no way to republish them.

`topic_tools relay` does not work with subtopics either.

Any ideas?
