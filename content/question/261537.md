  body_markdown: "Hi matkok,\n\nwe looked into the problem, thanks for your detailed\
    \ writeup which helped tremendously.\n\nThe error is not as assumed an SDO error\
    \ which would produce a much more verbose output but (at least that is the theory)\
    \ a PDO timing error which is resulting from the way we had implemented the commutation\
    \ search.\n\nThe following lines in  [SchunkPowerballNode.cpp](https://github.com/fzi-forschungszentrum-informatik/schunk_canopen_driver/blob/master/src/icl_hardware_canopen/src/icl_hardware_canopen/SchunkPowerBallNode.cpp#L135)\
    \ (135 following) are responsible for this:\n\n      size_t counter = 50;\n\n\
    \       // Try commutation search for counter times\n      while (!calib_ok &&\
    \ counter--)\n      {\n        usleep(100000); // sleep for 100 ms\n        downloadPDOs();\n\
    \        sendSync(m_can_dev);\n        uploadPDOs();\n        calib_ok = CommutationCalibrated();\n\
    \    }\n\nThe routine waits for the commutation calibration by doing a fixed time\
    \ wait. This is not the best way to do it as no SYNC signals are sent anymore\
    \ during this time. If the sync signal is missed for a predefined number of steps\
    \ a PDO exeception (resulting in a ProtocollException) is thrown and the nodes\
    \ will enter the fault state. \n\nPlease try the following patch:\n\n      size_t\
    \ counter = 500;\n     \n       // Try commutation search for counter times\n\
    \       while (!calib_ok && counter--)\n       {\n         sendSync(m_can_dev);\n\
    \         downloadPDOs();\n         uploadPDOs();\n         calib_ok = CommutationCalibrated();\n\
    \       }\n\nThe explicit sleep is actually not relevant as the sendSync will\
    \ already take care of the wait without skipping the SYNC signal.\n\nPlease let\
    \ me know if this works or you encounter further problems.\n\n\n"

I am using Schunk LWA4P robot arm, and I recently downloaded schunk_canopen_driver package. After catkin_make_isolated, I launch standalone_interpolated.launch or some other launch file, and it crashes after trying to do "Commutation search for node  3". I'll give you my output of my cmd.

BUT, I don't know why is that, and I don't want to do it that way. I have a feeling that the id 0x2050 in bool SchunkPowerBallNode::CommutationCalibrated() doesn't pass. Any opinions?
