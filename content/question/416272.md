  body_markdown: "I have been battling the DDS / Fast DDS for two months now.  \n\
    The fast solution is to make sure that both machines are on the same LAN.  \n\
    (I would double check the .1 address, that is usually a router address.)   \n\
    (If you are using virtual box or VM make sure you are using NAT Network).\n\n\
    Try using \"ros2 multicast receive\" one one, and \"ros2 multicast send\" on the\
    \ other.\n(If the receiving gets the message it should work.)\n\nRemove ALL variables\
    \ that deal with Fast RTPS.   Make sure you set a consistent ROS_DOMAIN_ID on\
    \ both machines.\nFor me, I had to use a non-zero ROS_DOMAIN_ID, but there may\
    \ have been another problem.\nIf you are modifying your bashrc, save it and restart\
    \ the terminal.\nros2 daemon stop\nros2 daemon start\nYou should be good to go,\
    \ there can be a 2-3 second lag when a node first spins up.\n\nExample of my .bashrc\n\
    export ROS_DOMAIN_ID=44\nsource /opt/ros/iron/setup.bash\n...\nNote if you have\
    \ any fast DDSsetting it will disable the normal DDS, this was my problem.\nIn\
    \ order to use fast dds you must have the server declared, and if you want introspection\
    \ you have to specify the xml file to configure fast DDS.   The biggest problem\
    \ with fast DDS is other terminals must have it configured for local nodes to\
    \ interact with the ROS system.  I would recommend the normal DDS if you are starting\
    \ out.\n\n\nHope that helps,\nCheers,\nBM\n\n\n\n"
