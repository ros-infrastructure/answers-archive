  body_markdown: "In c++ the compiler really has two parts, the compiler and the linker.\
    \ You need to explicitly tell the compiler everything that it needs to compile.\
    \ In addition to that, you need to specify what it needs to link together. The\
    \ product of the linker is the executable that can be run.\n\nIn your example\
    \ here, you are instructing the machine to generate `receiveSerialData` and it\
    \ is telling you, \"hey where are the definitions to this code you told me I could\
    \ use\" (**undefined reference to Command::parseCommand(unsigned char)')**. There\
    \ are two parts to that statement:\n\n(1) \"hey where are the definitions\"- This\
    \ means that you never told the linker where the compiled code used by `receiveSerialData`\
    \  is actually located\n\n(2) \"code you told me I could use\"- This part you\
    \ did correctly by using the`#include \"TerminalCommand.h\"` preprocessor command.\
    \ This gave your `receiveSerialData` the declarations to the class you wanted\
    \ to use.\n\nSo you correctly told the program what code to expect with (2), BUT\
    \ you never told it where to actually find the definition of this code (1).\n\n\
    In order to do correctly do this you need to tell the compiler to generate a `library`\
    \ out of your terminalCommand.cpp. After where you declare you \"include directories\"\
    \ in your CMake add this:\n\n    ## Declare a C++ library \n    add_library(TerminalCommand\
    \ src/TerminalCommand.cpp)\n\nAt this point now you will have generated a compiled\
    \ version of your code that can now be \"linked\" with other code like your executbale.\
    \ To \"link\" this code to your executable which is the one that actually needs\
    \ access to the content in the TeminalCommand library include it in your \"target\
    \ link\" command like\n\n    ## Link the library to the executable\n    target_link_libraries(receiveSerialData\
    \ TerminalCommand ${catkin_LIBRARIES})\n     \nAnd that should be it, it will\
    \ hopefully at least compile now, not saying that your code is right :) Here is\
    \ a nice explanation from the broader C++ community explaining the issue in more\
    \ detail [link text](https://latedev.wordpress.com/2014/04/22/common-c-error-messages-2-unresolved-reference/#:~:text=Undefined%20reference%20Put%20simply%2C%20the%20%E2%80%9Cundefined%20reference%E2%80%9D%20error,files%20and%20libraries%20that%20make%20up%20your%20project.)"
