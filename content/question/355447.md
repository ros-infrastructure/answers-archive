  body_markdown: "Answering my own question here:\n\nFrom [FindPythonExtra.cmake](https://github.com/ros2/python_cmake_module/blob/master/cmake/Modules/FindPythonExtra.cmake)\
    \ I determined the culprit to be some kind of interaction between `cmake`, `python3-config`,\
    \ `brew`, `pyenv`, and `pipenv`.\n\nThis was exacerbated by the cmake cache, which\
    \ persisted incorrectly returned results from `python3-config --ldflags` between\
    \ runs.\n\nFirst, note that for debugging, it's useful to pass `--cmake-args=\"\
    \ --log-level=STATUS\" --cmake-clean-cache` to `colcon` in order to see status\
    \ messages and avoid caching broken values of the `python3-config` output between\
    \ runs.\n\nIt appears that when you're using `pyenv`+`pipenv` and your virtual\
    \ environment is pointing to a `brew`-installed python, `python3-config` returns\
    \ incorrect information. For example:\n\n    \u279C pipenv shell\n    (ros2_foxy)\
    \ \u279C which python  \n    /Users/me/ros2_foxy/.venv/bin/python\n    (ros2_foxy)\
    \ \u279C python --version        \n    Python 3.8.5\n    (ros2_foxy) \u279C which\
    \ python3-config\n    /Users/me/.pyenv/shims/python3-config\n    (ros2_foxy) \u279C\
    \ python3-config --ldflags\n    -L/Users/me/.pyenv/versions/3.7.6/lib/python3.7/config-3.7m-darwin\
    \ -lpython3.7m -ldl -framework CoreFoundation\n    (ros2_foxy) \u279C python3-config\
    \ --includes\n    -I/Users/me/.pyenv/versions/3.7.6/include/python3.7m -I/Users/me/.pyenv/versions/3.7.6/include/python3.7m\n\
    \nThis results in the ros2 _FindPythonExtra.cmake_ file failing with the error\
    \ `Could NOT find PythonExtra (missing: PythonExtra_LIBRARIES)`.\n\nOn the other\
    \ hand, if `pipenv` and `pyenv` are set up to use a `pyenv`-installed rather than\
    \ `brew`-installed version of Python in the virtual environment, things seem to\
    \ work. This can be done by explicitly setting an alternate version, e.g. \n\n\
    \    \u279C pipenv shell --python 3.7\n\nNow the results of `python3-config` are\
    \ consistent with the virtual environment:\n\n    (ros2_foxy) \u279C which python\n\
