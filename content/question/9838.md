title: how to check if there are waiting messages in a callback queue?
upvote_count: 2
---
The test case is the following: i receive images from a camera through a callback, and I want to run a loop of processing until a new image arrive. Is there any function that can tell me if there are new messages in the queue? The pseudocode would look like this (i'm looking for new_imagemsg()):

    void imagecb(imagemsg)
    {
      while(!new_imagemsg())
      {
        optimize(imagemsg);
      }
      return;
    }

I tried the following:


    void imagecb(imagemsg)
    {
      while(static_cast<ros::CallbackQueue*>(nh->getCallbackQueue())->isEmpty())
      {
        optimize(imagemsg);
      }
      return;
    }
But it looks like the function [isEmpty()](http://www.ros.org/doc/api/roscpp/html/classros_1_1CallbackQueue.html#a750d7e58bdacab3041913c0929a44142) always returns false when called from inside a callback, which makes me think that the callback is removed once the callback function finishes instead of when it enters. Unfortunately it looks like [CallbackQueue](http://www.ros.org/doc/api/roscpp/html/classros_1_1CallbackQueue.html) doesn't have a getSize function ( i would like to check if the size is bigger than one). 

Any other ideas? [clearing](http://www.ros.org/doc/api/roscpp/html/classros_1_1CallbackQueue.html#ab960789600b6a6d775249347c234019a) the queue from inside a callback function doesn't seem to work either, apart from being kind of hacky.
