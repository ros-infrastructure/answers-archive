  body_markdown: "Basically, `robot_state_publisher` only broadcasts static joints.\
    \ The joint for the wheels is dynamic, so RSP will skip that one.\n\nAs to how\
    \ you can get the TF for your wheels. There are several options. \n\nThe first\
    \ one is adding the `joint_state_publisher` as suggested by @Robo_guy. This is\
    \ a `gazebo_ros` plugin that gets the position of the join in Gazebo and broadcasts\
    \ it to the TF tree.\n\nYou can also do it using the [differential drive plugin](http://wiki.ros.org/diff_drive_controller)\
    \ from `gazebo_ros`. This is a plugin that allows you to drive the robot around\
    \ (using teleop for instance). It has the option to broadcast the odom and wheel\
    \ TFs.\n\nYou could also use `ros_control`, but it's a bit tricky to do in ROS\
    \ 1 in simulations (at least in my opinion)."
