  body_markdown: "I'll answer in the only way I know how to do this, I suspect there\
    \ are better/easier ways.\n\nSince you're discussing the navigation stack, I assume\
    \ you're using movebase.\nIf there is no valid path to the goal, like it is outside\
    \ of the mapped area (and the mapped area perimeter is continuous), move base\
    \ will update the status of the goal as aborted.\n\nIf the goal pose isn't valid\
    \ because your cat is sitting on the goal location, move base won't know that\
    \ until it moves to the goal to find the cat sitting there. Only then will movebase\
    \ realize there is no valid goal.\n\nThis is what I use to monitor the goal state\
    \ on Jade using C++ classes.\nIt may work out of the box for you, or maybe you\
    \ need to fix it up.\nNOTE: This method works for me. I suspect that using the\
    \ action client this way in a constructor may cause issues if the constructor\
    \ is called twice.  But I don't call it twice, so I never had an issue.\n\n\n\
    Define the movebase client object\n\n    #include <move_base_msgs/MoveBaseAction.h>\n\
    \    #include <actionlib/client/simple_action_client.h>     \n    typedef actionlib::SimpleActionClient<move_base_msgs::MoveBaseAction>\
    \ MoveBaseClient;\n\nSet up the needed variables\n\n    private:\n           ros::NodeHandle\
    \ n; \n           move_base_msgs::MoveBaseGoal goal;\n           //tell the action\
    \ client that we want to spin a thread by default\n           MoveBaseClient ac;\n\
    \nIn your class you need to start the movebase action client in the constructor\
    \ initializer:\n\n    class my_class\n    {\n        public:\n    \n         \
    \   my_class() : ac(\"move_base\", true)\n    ...\n\nMake sure the movebase is\
    \ up and running while in the constructor:\n\n     //wait for the action server\
    \ to come up\n     while(!ac.waitForServer(ros::Duration(5.0)))\n     {\n    \
    \     ROS_INFO(\"Waiting for the move_base action server to come up\");      \
    \      \n     }      \n         ROS_INFO(\"move_base action server is up\"); \
    \   \n\nWhen you send a goal from your code, register the callback to use on movebase\
    \ status update:\n\n     // Need boost::bind to pass in the 'this' pointer\n \
    \    ac.sendGoal(goal, boost::bind(&my_class::doneCb, this, _1), MoveBaseClient::SimpleActiveCallback());\n\
    \nProcess the status in your callback.\n\n     void doneCb(const actionlib::SimpleClientGoalState&\
    \ state)\n     {                \n        ROS_INFO(\"DONECB: Finished in state\
    \ [%s]\", state.toString().c_str());        \n        if (ac.getState() == actionlib::SimpleClientGoalState::SUCCEEDED)\n\
    \        {\n             // do something as goal was reached                 \
    \  \n        }\n        if (ac.getState() == actionlib::SimpleClientGoalState::ABORTED)\n\
    \        {\n            // do something as goal was canceled   \n        }   \
    \        \n     }"
