  body_markdown: "I can see from the list of the topics that there is no controller\
    \ topic for the wheels of your robot. \n\nIf you look into the [description](https://github.com/mario-serna/pioneer_p3dx_model/blob/master/p3dx_description/urdf/pioneer3dx_wheel.xacro)\
    \ of your robot, you should find a transmission tags that are given the names\
    \ of the drive wheels joints. Inside the [gazebo tags](https://github.com/mario-serna/pioneer_p3dx_model/blob/master/p3dx_description/urdf/pioneer3dx.gazebo)\
    \ you will find there is a plugin called `libgazebo_ros_control` loaded. This\
    \ plugin looks for the transmission tags to see what controllers it should load.\
    \ \n\nBut you also need to set the controllers yourself (I'm not sure of the causality\
    \ in this process, but this is what you need to do). So you need this [controller\
    \ configuration file](https://github.com/mario-serna/pioneer_p3dx_model/blob/master/p3dx_control/config/pioneer3dx.yaml)\
    \ and then you need to actually load it into your simulation. \n\nThat is supposed\
    \ to be done by [this file](https://github.com/mario-serna/pioneer_p3dx_model/blob/master/p3dx_control/launch/control.launch),\
    \ however in this package the loading of the controller is commented out. I'm\
    \ not sure what is the state in your local package. I cannot validate all of what\
    \ is written in this file, but given everything else is correct, the file should\
    \ look as follows:\n\n    <launch>\n      <arg name=\"name\" default=\"p3dx\"\
    />\n      <arg name=\"x\" default=\"0.0\"/>\n      <arg name=\"y\" default=\"\
    0.0\"/>\n      <arg name=\"init_yaw\" default=\"0.0\"/>\n      <arg name=\"namespace_arg\"\
    \ default=\"\"/>\n      <arg name=\"tfprefix\" default=\"\"/>\n    \n      <!--\
    \ Load joint controller configurations from YAML file to parameter server -->\n\
    \      <rosparam file=\"$(find p3dx_control)/config/pioneer3dx.yaml\" command=\"\
    load\"/>\n    \n      <!--<rosparam param=\"p3dx_velocity_controller/base_frame_id\"\
    \ subst_value=\"True\">$(arg tfprefix)/base_link</rosparam>-->\n    \n      <!--\
    \ load the controllers -->\n      <!-- THIS NEEDS TO BE UNCOMMENTED -->\n    \
    \  <node name=\"controller_spawner\" pkg=\"controller_manager\" type=\"spawner\"\
    \ respawn=\"false\" output=\"screen\" ns=\"/$(arg namespace_arg)\" args=\"joint1_position_controller\
    \ joint2_position_controller joint_state_controller\"/>\n    \n      <!-- transform\
    \ the robot's coordinates to map-->\n      <node pkg=\"tf\" type=\"static_transform_publisher\"\
    \ name=\"map_odom_broadcaster\" args=\"0 0 0 0 0 0 /map /$(arg tfprefix)/odom\
    \ 100\" />\n    \n      <!-- convert joint states to TF transforms for rviz, etc\
    \ -->\n      <node name=\"robot_state_publisher\" pkg=\"robot_state_publisher\"\
    \ type=\"robot_state_publisher\" respawn=\"false\" output=\"screen\">\n      \
    \  <remap from=\"/joint_states\" to=\"/joint_states\" />\n      </node>\n    \n\
    \    </launch>\n\nThe last step is to launch the control (the file above), which\
    \ is commonly done in the [launch file](https://github.com/mario-serna/pioneer_p3dx_model/blob/master/p3dx_gazebo/launch/pioneer3dx.launch)\
    \ where you spawn the robot. You can see the lines loading the controller launch\
    \ file are commented out in this file as well (all the way at the bottom). So\
    \ you would need to uncomment also this command.\n\n    <!-- ros_control p3rd\
    \ launch file -->\n    <!-- <include file=\"$(find p3dx_control)/launch/control.launch\"\
    \ /> -->\n\nWhat you want to see in your topic list are two topics named something\
    \ like `/p3dx/joint1_position_controller/command` and `/p3dx/joint2_position_controller/command`.\
    \ Those are the topics that any kind of keyboad operation node has to sent the\
    \ target velocities in order to move your robot."
