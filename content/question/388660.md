    `prevTime`  may sometimes initialize before the first `/clock` message, so it defaults to 0.  If you use a non-deterministic method of starting nodes, e.g., `roslaunch`, the startup order can vary, so this will happen sometimes but not others.  As noted in the [`rospy` Time overview](http://wiki.ros.org/rospy/Overview/Time#Getting_the_current_time), one workaround is to loop the assignment until it returns a non-zero value:

        prevTime = 0
        while not prevTime:
            prevTime = rospy.Time.now()
