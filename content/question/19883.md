  body_markdown: "[lines 143-144 of LiftDragPlugin.cc](https://bitbucket.org/osrf/gazebo/src/01c7f8b1d68448bc618b575ad1c7ec13fee2b87f/plugins/LiftDragPlugin.cc#lines-143,144):\n\
    \n    this->updateConnection = event::Events::ConnectWorldUpdateBegin(\n     \
    \         std::bind(&LiftDragPlugin::OnUpdate, this));\n\n----------\n*Short Answer:*\
    \  \nThis passes your Plugin's Update method (in this case, `LiftDragPlugin::OnUpdate`)\
    \ as a callback function to the Gazebo Simulator's Events class instance, allowing\
    \ Gazebo to call your Plugin's method (`LiftDragPlugin::OnUpdate`) at every simulation\
    \ time step.\n\n*Long Answer:*  \n - You write a Gazebo Plugin to affect the simulation\
    \ - in this case the `LiftDragPlugin` applies rudimentary lift and drag forces\
    \ to the attached model.  \n - In order for the `LiftDragPlugin` to apply these\
    \ forces in the simulation, it needs to, _at every simulation time step_, 1) determine\
    \ the attached model's orientation relative to gravity plane, determine model's\
    \ velocity, etc., 2) carry out some simple lift-drag calculations, and 3) apply\
    \ the appropriate lift-drag forces.  \n - Therefore, in your Gazebo Plugin, you\
    \ create a `Update`, `OnUpdate`, `RunEverySimulationTimeStep`, etc. method - here\
    \ it's `LiftDragPlugin::OnUpdate`, that contains the code that should be run at\
    \ each simulation time step, and you pass that method *(or rather a reference\
    \ to that method)* to the Gazebo Simuator's Event class instance as a callback\
    \ function: `event::Events::ConnectWorldUpdateBegin(...)`.  \n- Now at each simulation\
    \ time step, the Gazebo Simulator will call the `LiftDragPlugin::OnUpdate` method\
    \ and everybody lives happily ever after.\n\n"
