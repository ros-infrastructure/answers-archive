  body_markdown: "I more or less figured it out, so I thought I'd share my solution\
    \ in case anyone was thinking of tackling the same issue.\n\nCurrently, CHOMP\
    \ default does not support seeding; I ended up using STOMP for this reason. STOMP\
    \ seeds through the trajectory_constraints message (which is apparently unused\
    \ by MoveIt!).\n\nFirst, ensure that the robot package knows where the trajectory\
    \ optimizer package is by modifying the CMakeLists.txt and the package.xml files\
    \ (to include STOMP, I added the **stomp_core** package) .\n\nfrom **CMakeLists.txt:**\n\
    \n    find_package(catkin REQUIRED COMPONENTS\n    moveit_core\n    stomp_core\n\
    \    moveit_experimental\n    moveit_visual_tools\n    moveit_ros_planning\n \
    \   moveit_ros_planning_interface\n    pluginlib\n    geometric_shapes\n    industrial_trajectory_filters\n\
    \    )\n\n    catkin_package(\n      LIBRARIES\n        interactivity_utils\n\
    \      INCLUDE_DIRS\n        ${THIS_PACKAGE_INCLUDE_DIRS}\n      CATKIN_DEPENDS\n\
    \        moveit_core\n        stomp_core\n        moveit_experimental\n      \
    \  moveit_visual_tools\n        moveit_ros_planning_interface\n        interactive_markers\n\
    \        industrial_trajectory_filters\n      DEPENDS\n        EIGEN3\n    )\n\
    \nfrom **package.xml:**\n\n    <build_depend>stomp_core</build_depend>\n    <run_depend>stomp_core</run_depend>\n\
    \nAlso, don't forget to include the your c++ file in the CMakeLists.txt file so\
    \ that the package knows it's a node!\n\nfrom **CMakeLists.txt:**\n\n    add_executable(motion_planning_bot\
    \ src/motion_planning_bot.cpp)\n    target_link_libraries(motion_planning_bot\
    \ ${catkin_LIBRARIES} ${Boost_LIBRARIES})\n    install(TARGETS motion_planning_bot\
    \ DESTINATION ${CATKIN_PACKAGE_BIN_DESTINATION})\n\nThere's probably a bit of\
    \ redundancy in the above, but it will still work nonetheless.\n\n\nThe following\
    \ code seeds the trajectory to STOMP (*req* is a planning_interface::MotionPlanRequest\
    \ object and *response* is a moveit_msgs::MotionPlanResponse)\n\n    trajectory_msgs::JointTrajectory\
    \ seed = response.trajectory.joint_trajectory;\n    const auto dof = seed.joint_names.size();\n\
    \n    for (size_t i = 0; i < seed.points.size(); ++i) // for each time step\n\
    \    {\n      moveit_msgs::Constraints c;\n\n      if (seed.points[i].positions.size()\
    \ != dof)\n        throw std::runtime_error(\"All trajectory position fields must\
    \ have same dimensions as joint_names\");\n\n      for (size_t j = 0; j < dof;\
    \ ++j) // for each joint\n      {\n        moveit_msgs::JointConstraint jc;\n\
    \        jc.joint_name = seed.joint_names[j];\n        jc.position = seed.points[i].positions[j];\n\
    \n        c.joint_constraints.push_back(jc);\n      }\n      req.trajectory_constraints.constraints.push_back(std::move(c));\n\
    \    }\n\nI'd recommend also creating another publisher to visualize the trajectory_msg::JointTrajectory\
    \ results via the rqt plot plugin. It's a good way to visualize the effects of\
    \ the trajectory optimizer.\n\n    ros::Publisher rqt_publisher = node_handle.advertise<trajectory_msgs::JointTrajectory>(\"\
    /rqt_publisher/\", 1);      \n    for(unsigned iter = 0; iter < size2; iter++)\
    \ {\n      \tresponse.trajectory.joint_trajectory.points[iter].time_from_start\
    \ = ros::Duration(0.1*iter);\n    }\n    rqt_publisher.publish(response.trajectory.joint_trajectory);\n\
    \nMoveIt! uses geometric planners and adds time parameterization afterwards (for\
    \ velocity/acceleration obedience). The default plan obtained does not have time,\
    \ so I just spaced it out nicely to display on a graph. I haven't looked into\
    \ displaying the points after time parameterization..\n\nUnfortunately, I did\
    \ have STOMP fail to compute a plan with an initial seed frequently; it unfortunately\
    \ had a 40% success rate with FMT, and still failed 10-15% time with RRT. Not\
    \ really sure what's happening there.\n\n\n"
