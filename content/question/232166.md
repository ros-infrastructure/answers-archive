hello,
I would like to make clear about spinOnce and callback queue and this is how I understand so far: 
Every time a message comes, it is pushed back into the message queue of each individual callback (I mean each callback has its own message queue) that registers to this topic. The message queue length is specified when we do node.subscribe("/topic_name", message_queue_length, callback). Then these callbacks are added to the global callback queue. And when spinOnce() runs, it will callAvailable() through the callback queue, executing each callback there.

For example : I have a node called my_node and there is one callback called myCallback which handles the message comes from my_topic . the message queue of myCallback has length 1. 

when message1 on my_topic comes:
  message queue of myCallback will look like: [message1] ; 
  global callback queue will look like: [myCallback]

when message2 on my_topic comes:
  message queue of myCallback will look like: [message2] ; 
  global callback queue will look like: [myCallback, myCallback]

when message3 on my_topic comes:
  message queue of myCallback will look like: [message3] ;
  global callback queue will look like: [myCallback, myCallback, myCallback]

then when spinOnce() runs, callAvailable() will call the first "myCallback" in the global callback queue, which deserializes message3 in the current message queue of myCallback making the queue empty.

my questions are:

1/ when callAvailable() call next "myCallback" in the queue, there is no message left in the message queue, how does ROS handle this?

2/ When callAvailable() is executed, it repeatedly calls callOneCb(). this function might return Success, TryAgain or Invalid. does it return Invalid in my case? or it returns TryAgain?

3/ (general question) is there a limit for global callback queue length?
