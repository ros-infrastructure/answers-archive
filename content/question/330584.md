  body_markdown: "Yes, at the moment that is the expected behavior.\nIf you want to\
    \ avoid the type of the parameters to be changed, then you have to register a\
    \ validation callback to do so. \n\nhttps://github.com/ros2/rclcpp/issues/807\n\
    This is a discussion that I started  to think about how to facilitate the validation\
    \ process in some common cases as the one that you mentioned. \n\nThis is what\
    \ you can do in the validation callback to check for the type.\nNote that it has\
    \ to be done for all parameters\n\n    if (parameter.get_name().compare(\"my_parameter\"\
    ) == 0) {\n                  if (rclcpp::ParameterType::PARAMETER_INTEGER != parameter_type)\
    \ {\n                    RCLCPP_WARN(this->get_logger(),\n                   \
    \   \"Trying to set parameter '%s' with wrong type\",\n                      parameter.get_name().c_str()\n\
    \                    );\n                    result.successful = false;\n    \
    \                result.reason = \"parameter \\'\"+parameter.get_name()+\"\\'\
    \ must be an integer\";\n\n\n\nHere you find a full working example \nhttps://github.com/alsora/ros2-code-examples/blob/master/simple_parameter/src/simple_parameter_server_node.cpp\n\

is this expected behavior, that when I publish a parameter with a wrong datatype, the result is always true?  

    ros2 param set /test/my_double_value 1  

Returns success although value is written als int into the parameter.  

And inside the test node where the parameter is declared, there is also no exception:  

    declare_parameter( frequencyParamName, rclcpp::ParameterValue( 20.0 ));  

    for ( auto& changed_parameter : event->changed_parameters )
    {
          auto paramName = changed_parameter.name;
          if ( paramName == frequencyParamName )
          {
             updateFrequencyParam( changed_parameter.value.double_value );
          }
    }

Do we really need to check for correct type by ourselves or are we handling parameters wrong?
