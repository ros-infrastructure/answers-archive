  body_markdown: "I was able to solve this issue i would like to note what worked\
    \ for me.\n\nnote: I feel this answer is very specific to panda arm.\n\n**At first\
    \ why this error comes up?**\n\nIf you look into lines 541 to 552 of **joint_trajectory_controller_impl.h**,\
    \ they are as follows\n\n    00541   // Goal should specify all controller joints\
    \ (they can be ordered differently). Reject if this is not the case\n    00542\
    \   using internal::permutation;\n    00543   std::vector<unsigned int> permutation_vector\
    \ = permutation(joint_names_, gh.getGoal()->trajectory.joint_names);\n    00544\
    \ \n    00545   if (permutation_vector.empty())\n    00546   {\n    00547    \
    \ ROS_ERROR_NAMED(name_, \"Joints on incoming goal don't match the controller\
    \ joints.\");\n    00548     control_msgs::FollowJointTrajectoryResult result;\n\
    \    00549     result.error_code = control_msgs::FollowJointTrajectoryResult::INVALID_JOINTS;\n\
    \    00550     gh.setRejected(result);\n    00551     return;\n    00552   }\n\
    \nSo error comes up because there is a mismatch between controller joints and\
    \ joints on the trajectory goal which is sent by moveit.\n \n**Second point how\
    \ did i found it which joint should be removed?** \n\nUpon observing the hand.xacro\
    \  file i noticed that panda_finger_joint2 is set to mimic panda_finger_joint1.\
    \ (If someone wants to read about mimic joint then its [here](http://wiki.ros.org/urdf/XML/joint))\
    \ so i suspected that it panda_finger_joint2 is to mimic panda_finger_joint1 then\
    \ trajectory message sent by moveit should only have entry for panda_finger_joint1\
    \ .\n\nAnyone correct me on the reasoning i have given."
