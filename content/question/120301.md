  body_markdown: "Hi, I am not an expert, but this is what I think from my experience\
    \ so far:\n\n**1)** In rviz I think you can only set one goal at a time. If your\
    \ robot is navigating and you use the 2D Navigation button again, your robot will\
    \ forget what it was doing and navigate to the new goal.\n\n**2)** I have never\
    \ tried this, but I imagine if the initial pose is far off it would be difficult\
    \ for the robot to localize itself.\n\n**3)** By autonomous navigation, do you\
    \ mean this tutorial?\nhttp://wiki.ros.org/turtlebot_navigation/Tutorials/Autonomously%20navigate%20in%20a%20known%20map\n\
    \nThe tutorial includes this paragraph:\n\n> > Teleoperation\n> \n> The teleoperation\
    \ can be run\n> simultaneously with the navigation\n> stack. It will override\
    \ the autonomous\n> behavior if commands are being sent.\n> It is often a good\
    \ idea to teleoperate\n> the robot after seeding the\n> localization to make sure\
    \ it converges\n> to a good estimate of the position.\n\nSo I believe you should\
    \ be able to run both simultaneously. If you're doing the autonomous tutorial\
    \ you should already have your robot booted up, so I would think all you need\
    \ to do is open a new terminal (Ctrl+Alt+T) and type in `roslaunch turtlebot_teleop\
    \ keyboard_teleop.launch`\n(I don't know what robot you're using. I am using a\
    \ Turtlebot, so that is the teleop command for it)\n\n**4)** \nFor local_costmap_params,\
    \ \n\n    global_frame: /odom   \n    robot_base_frame: /base_footprint\n\nFor\
    \ global_costmap_params,\n\n       global_frame: /map\n       robot_base_frame:\
    \ /base_footprint\n\n\nI hope this helps!\n\n"
