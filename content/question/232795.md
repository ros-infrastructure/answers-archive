  body_markdown: "The reason you get this error is because for the *system dependencies*\
    \ that are mentioned in your error message, `rosdep` doesn't have any *rules*\
    \ that allow it to map these 'generic' names to Xenial-specific debian package\
    \ names (see [Why rosdep instead of others?](http://answers.ros.org/question/215059)).\n\
    \n> I tried to resolve those dependencies by myself and installed `libopencv-dev`\
    \ and `python-qt-binding` through `apt-get`. This did not change anything. \n\n\
    And that is expected (as I hope you understand now), as installing these manually\
    \ doesn't change the fact that `rosdep` doesn't know about them (on Xenial, that\
    \ is). See [rosdep/base.yaml :: libopencv-dev](https://github.com/ros/rosdistro/blob/88c5d1ed3ceb16bb16aa91dc246a5a701907be5d/rosdep/base.yaml#L1916-L1926)\
    \ for the current rule set for `libopencv-dev` for instance: note it's missing\
    \ a `xenial` key.\n\n\n> What should I do now?\n\nYou have a couple of options:\n\
    \n 1. wait for the rules to be updated and Xenial keys to be added: note that\
    \ this also requires those packages to actually have Xenial releases.\n 1. contribute\
    \ the missing rules yourself: see [Contributing rosdep rules](http://docs.ros.org/independent/api/rosdep/html/contributing_rules.html)\
    \ for that.\n 1. make `rosdep` resolve dependencies for Wily (or an even older\
    \ release) instead: this will require those packages to exist -- and with the\
    \ *same name* -- on Xenial, which may or may not work. Append `--os=ubunty:wily`\
    \ to your `rosdep` invocation.\n\n   **Note**: this is a work-around, and you\
    \ should only use this when trying to deal with unsupported platforms (such as\
    \ Ubuntu derivatives being identified as an unknown OS, or unsupported releases\
    \ of distributions).\n 1. ask `rosdep` to ignore the missing dependencies and\
    \ continue with whatever it does know about: you'll have to make sure you have\
    \ those dependencies installed, as otherwise you'll run into issues while configuring\
    \ / compiling, but it would let you continue. Append `-r` to your `rosdep` invocation.\n\
    \nSee [rosdep command reference - options](http://docs.ros.org/independent/api/rosdep/html/commands.html#options)\
    \ for more information on the various `rosdep` command line options.\n"

I read ros will be officially available for Ubuntu 16.04 in July, so I tried to build it from source as described [here](http://wiki.ros.org/jade/Installation/Source). Unfortunately it can't resolve some package dependencies:

    ~/ros_catkin_ws » rosdep install --from-paths src --ignore-src --rosdistro jade -y                                                                                                  
    ERROR: the following packages/stacks could not have their rosdep keys resolved
    to system dependencies:
    image_geometry: No definition of [libopencv-dev] for OS version [xenial]
    python_qt_binding: No definition of [python-qt-bindings] for OS version [xenial]
    rqt_pose_view: No definition of [python-qt-bindings-gl] for OS version [xenial]
    rqt_plot: No definition of [python-qt-bindings-qwt5] for OS version [xenial]
    qt_gui: No definition of [python-qt-bindings] for OS version [xenial]
    cv_bridge: No definition of [libopencv-dev] for OS version [xenial]

I tried to resolve those dependencies by myself and installed **libopencv-dev** and **python-qt-binding** through *apt-get*. This did not change anything. What should I do now?

**EDIT:**
There are dependencies missing to install ros under Ubuntu 16.04. Those dependencies, like pcl, need to be, too. If it is not too urgent to use ros under Ubuntu 16.04, I would recommend to wait until July, for when the official release for Ubuntu 16.04 is announced.
