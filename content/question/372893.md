  body_markdown: "> the nodes of all packages will be executed sequentially as described\
    \ in the launch file?\n\nShort answer is no, using **only** launch files there\
    \ is no guarantee of sequencing/order of execution.  \n \nAs described in this\
    \ tutorial (very much worth reading):  [Roslaunch tips for large projects](http://wiki.ros.org/roslaunch/Tutorials/Roslaunch%20tips%20for%20larger%20projects)\
    \  \nQuote: **\"Roslaunch intentionally does not provide any control on the order\
    \ or timing of node start up.\"**\n\nAnd from Jason M. O'Kane's Book \"*A Gentle\
    \ Introduction to ROS*\":  \n>An important fact about roslaunch\u2014one that\
    \ can be easy to forget\u2014is that all of the\nnodes in a launch file are started\
    \ at roughly the same time. As a result, you cannot be sure\nabout the order in\
    \ which the nodes will initialize themselves. Well-written ROS nodes don\u2019\
    t\ncare about the order in which they and their siblings start up\n\nFollowing\
    \ in line with the previous quote I would recommend to verify if controlling the\
    \ order in which you launch your nodes is the best solution to your sequencing\
    \ problem.  \n\nExamples of alternative solution are:  \n - Keep publishing a\
    \ message at a certain rate  \n - Tuning parameters, for instance a timeout parameter\
    \  \n - Wait for a single message to arrive on a topic  \n - Wait for a transform\
    \ to be available  \n - Wait for a server to come up and then start a process\
    \  \n - Use 'latching' to send a message to any future subscribers that connect\
    \  \n- Use services to ensure that a single message is delivered  \n\nIf you **really**\
    \ need/want to time the launch moment of a node, one of these two might help:\
    \  \n - Use a **Bash script** to delay a .launch file start for a given number\
    \ of seconds (or wait for the user input)  \n - Use the [roslaunch Python API](http://wiki.ros.org/roslaunch/API%20Usage)\
    \ to fully control the process of launching ROS Nodes \n\nSimple Bash scripts\
    \ are easy to learn and implement. However delaying for a fixed amount of time\
    \ is a bit of a trial and error process. \n \n The roslaunch Python API gives\
    \ you full control on starting and stopping nodes programmatically. If you additionally\
    \ couple the roslaunch Python API with your own nodes custom services / actions\
    \ and you can do pretty much everything with it."
