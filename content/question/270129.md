  body_markdown: "I explored this same question a while ago, see https://github.com/ros-planning/navigation/issues/279\n\
    \nAs you point out, to load a new map with the current *map\\_server* implementation,\
    \ you need to kill the node and reload it.\n\nA possible solution, that doesn't\
    \ require any changes in *map\\_server*  (as proposed by @david-lu), would be\
    \ to load all your different maps in separate *map\\_server* instances renaming\
    \ appropriately the */map* topic on each instance (for example /map_1, /map_2,\
    \ etc...) and use a [multiplexer](http://wiki.ros.org/topic_tools/mux) that subscribes\
    \ to all your maps and publishes the topic */map* depending on which map you want\
    \ the multiplexer to select.\n\nThe other solution would be to modify the source\
    \ code of  *map\\_server* and add a service to change the map on demand. Some\
    \ work has been done, but it hasn't been released yet. If you read through [navigation\
    \ issue #279](https://github.com/ros-planning/navigation/issues/279) you will\
    \ find the code.\n\nI hope this helps "
