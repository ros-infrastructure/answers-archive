  body_markdown: "Have a look for information about ROS Dynamic Reconfigure. That\
    \ allows you to change the resolution on-the-fly. Look at the params under the\
    \ openni driver node.\n\nOnce you have found the parameter, you should be able\
    \ to set it in a launch file like any other ROS Param.\n\n<BR>\n\nEdit:  I needed\
    \ to test this myself...\n\nFirstly test the supported parameters by changing\
    \ them on the fly and viewing the output in Rviz: <BR>\n\n    $ rosrun dynamic_reconfigure\
    \ reconfigure_gui\n\n  and selecting the node: <BR>\n{your_kinect_camera_name}/driver\n\
    \  \n  The ASUS/PrimeSense supports at least:\n\n      image_mode: 2 (640x480\
    \ VGA 30Hz)\n                  5 (320x240 QVGA 30Hz)\n                  8 (160x120\
    \ QQVGA 30Hz)\n      depth_mode: 2 (VGA 30Hz)\n                  5 (QVGA 30Hz)\n\
    \                  8 (QQVGA 30Hz)\n\n\nHere are 2 separate examples of launching\
    \ the dynamic reconfigure node to change some parameters:\n\n        <node name=\"\
    $(anon dynparam)\" pkg=\"dynamic_reconfigure\" type=\"dynparam\" args=\"set_from_parameters\
    \ tilt_hokuyo_node\">\n          <param name=\"intensity\" type=\"bool\" value=\"\
    false\" />\n          <param name=\"min_ang\" type=\"double\" value=\"-1.15\"\
    \ />\n          <param name=\"max_ang\" type=\"double\" value=\"1.15\" />\n  \
    \      </node>\n    \n      <node name=\"pr2_arm_navigation_perception_change_narrow_stereo_params_speckle\"\
    \ pkg=\"dynamic_reconfigure\" type=\"dynparam\" \n        args=\"set /narrow_stereo_textured/narrow_stereo_textured_proc\
    \ speckle_size 1000\" />\n\nOr can specify the OpenNI driver configuration via\
    \ ROS params:\n\n    <launch>\n      <arg name=\"kinect_frame_prefix\" default=\"\
    /head_mount_kinect\" />\n      <arg name=\"kinect_camera_name\" default=\"head_mount_kinect\"\
    \ />\n      <arg name=\"publish_tf\" default=\"true\" />\n    \n      <!-- Set\
    \ driver params for 320x240 at 1-2 Hz frame rate -->\n      <param name=\"/$(arg\
    \ kinect_camera_name)/driver/data_skip\" value=\"10\" /> <!-- 0 is default, 10\
    \ will drop 9/10 frames -->\n      <param name=\"/$(arg kinect_camera_name)/driver/image_mode\"\
    \ value=\"5\" /> <!-- 2 is default -->\n      <param name=\"/$(arg kinect_camera_name)/driver/depth_mode\"\
    \ value=\"5\" /> <!-- 2 is default -->\n    \n      <include file=\"$(find openni_launch)/launch/openni.launch\"\
    >\n        <arg name=\"device_id\" value=\"#1\" /> <!-- Use 1st device found,\
    \ or you can specify first device on USB Bus #2 using 2@0 -->\n        <arg name=\"\
    camera\" value=\"$(arg kinect_camera_name)\" />\n        <arg name=\"rgb_frame_id\"\
    \ value=\"$(arg kinect_frame_prefix)_rgb_optical_frame\" />\n        <arg name=\"\
    depth_frame_id\" value=\"$(arg kinect_frame_prefix)_ir_optical_frame\" />\n  \
    \      <arg name=\"publish_tf\" value=\"$(arg publish_tf)\"/>\n        <arg name=\"\
    respawn\" value=\"true\"/>\n        <arg name=\"depth_registration\" value=\"\
    true\"/>\n      </include>\n    \n    </launch>\n\n\n\n"

Is there any way of lower the Kinect RGB image resolution from 640 * 480 to 320 * 240 when using the openni_launch package? I know it can be done in the openni_camera launch file by changing the image mode but I cant use this because depth doesn't show when I do for some reason. The reason I need to lower it is because I'm using cv_bridge to opencv but with the higer resolution this part runs unacceptably slowly.
