    the `robot_description` is only used to initialize the [resource_manager_](https://github.com/ros-controls/ros2_control/blob/9f13b60aebd201a60741ec65c56ea5f05833a139/controller_manager/src/controller_manager.cpp#L130) [which is stored with `private` access](https://github.com/ros-controls/ros2_control/blob/9f13b60aebd201a60741ec65c56ea5f05833a139/controller_manager/include/controller_manager/controller_manager.hpp#L245-L248), and I am not aware of any existing interfaces to access it directly through the "hardware_interface" classes. But if you don't need the raw `robot_description` urdf output, then perhaps you can look at the accessor methods provided by [`resource_manager`](https://github.com/ros-controls/ros2_control/blob/9f13b60aebd201a60741ec65c56ea5f05833a139/hardware_interface/include/hardware_interface/resource_manager.hpp). There are public methods available to list actuators, sensors etc. But I don't think ros2_control, by default, stores any awareness of the geometry, etc

 Hello,
 
I am currently working on a `ros2_control` hardware that can be dynamically set up and assembled using module as plugin components. Is there a way to get access to the `robot_description` from inside the hardware interface in `on_configure()`? 
I would like to describe my hardware like this

    <hardware>
      <plugin>driver/Driver</plugin>
        <module>
          <plugin>plugin/Module1</plugin>
        </module>
        <module>
           <plugin>plugin/Module2</plugin>
        </module>
    </hardware>
Is this possible ? If not should I rather pass the modules as parameters like this

    <hardware>
       <plugin>driver/Driver</plugin>
       <param name="module_list">"[module1, module2]"</param>
    </hardware>

Thanks!
