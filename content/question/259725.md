    For making sure the newest message is used, you should set your topic history queues to 1. That way, every time a new message is received it will overwrite the previous one, so only the most recent is available at all times.

    For synchronising the depth and rgb images, you can use the [Time Synchronizer message filter](http://wiki.ros.org/message_filters#Time_Synchronizer). I'm not sure how this filter handles history, so you might need to experiment to make sure it only passes the most recent of both the image and depth topics.

  body_markdown: "First of all, you can't do the processing in the callback, because\
    \ it will (potentially) block the other nodelets.\n\nHere is what you can do:\n\
    \n 1. Create a [Synchronizer](http://wiki.ros.org/message_filters#ApproximateTime_Policy)\
    \ of queue size 1.\n 2. Create your own thread to do the processing. It will contain\
    \ a loop and will be waiting to be notified in order to start the processing.\n\
    \ 3. In the callback, you should check if data are being currently processed.\
    \ If yes, discrard the received data. Otherwise, store the data and notify the\
    \ processing loop.\n\nSome libraries of interest are [thread, mutex, atomic, and\
    \ condition variable](http://en.cppreference.com/w/cpp/thread). Here is how this\
    \ could translate to code:\n\n    void processingLoop() {\n      while (ros::ok())\
    \ {\n        std::unique_lock<std::mutex> lock(img_mutex);\n        if (has_new_data.load())\
    \ {\n          // do heavy processing\n        }\n        has_new_data.store(false);\n\
    \        processing_cv.wait(lock, [&] { return has_new_data.load(); });\n    \
    \  }\n    }\n    \n    void callback(const RgbConstPtr& rgb, const DepthConstPtr&\
    \ depth) {\n      std::unique_lock<std::mutex> lock(img_mutex, std::try_to_lock);\n\
    \      if (!lock.owns_lock()) return;\n    \n      img_rgb = rgb;\n      img_depth\
    \ = depth;\n      has_new_data.store(true);\n    \n      lock.unlock();\n    \
    \  processing_cv.notify_one();\n    }\n\n"
