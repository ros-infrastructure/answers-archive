  body_markdown: "This is what I did to get OpenRAVE to generate an IKFast plugin\
    \ for your urdf.\n\nI'll assume that you've already:\n\n - converted the top-level\
    \ `.xacro` to a `.urdf`, and\n - have converted it to Collada (using `rosrun collada_urdf\
    \ urdf_to_collada ..`)\n\nI decided to use the `personalrobotics/ros-openrave`\
    \ Docker image, as installing OpenRAVE from sources on recent Ubuntu / Debian\
    \ versions is not trivial, and takes quite some time (as you probably discovered).\n\
    \nWe need to tweak the image a bit though, so:\n\n    $ mkdir /tmp/prro_work &&\
    \ cd /tmp/prro_work\n    $ cat << EOF > Dockerfile\n    FROM personalrobotics/ros-openrave\n\
    \    RUN apt-get update || true && apt-get install -y --no-install-recommends\
    \ build-essential python-pip liblapack-dev && apt-get clean && rm -rf /var/lib/apt/lists/*\n\
    \    RUN pip install sympy==0.7.1\n    EOF\n    \n    # Replace `$DOCKER_IMAGE`\
    \ with some descriptive name here\n    $ docker build -t $DOCKER_IMAGE .\n\nThis\
    \ makes `pip` install an older version of `sympy` in `/usr/local`, which is then\
    \ used by OpenRAVE instead of the `sympy` that is installed by `apt`. The IKFast\
    \ generator is very specific about the version of `sympy` and this version seems\
    \ to work - in any case it works with your `.dae`.\n\nNow wait for Docker to build\
    \ the new image.\n\nThen we need a small wrapper 'robot' for OpenRAVE:\n\n   \
    \ <robot file=\"$NAME_OF_YOUR_COLLADA_FILE\">\n      <Manipulator name=\"NAME_OF_THE_ROBOT_IN_URDF\"\
    >\n        <base>base_link</base>\n        <effector>tool0</effector>\n      </Manipulator>\n\
    \    </robot>\n\nsave this as `wrapper.xml` (you can obviously change the name\
    \ if you want). OpenRAVE supports relative filenames for the `file` attribute\
    \ of the `robot` element in our `wrapper.xml`, so it's easiest if you place `wrapper.xml`\
    \ in the same directory that contains the `.dae` of your robot model.\n\nAnd make\
    \ sure to update `base_link` and `tool0` to whatever you want as your `base` and\
    \ `effector` links (these elements correspond to the `--baselink` and `--eelink`\
    \ arguments that you pass to `ikfast.py` normally, but by name, not an index).\
    \ In almost all cases these should correspond to whatever you have modelled as\
    \ those links in your urdf.\n\nNow generate the plugin:\n\n    $ cd /to/wherever/you/have/your/dae/and/your/wrapper\n\
    \    $ mkdir output\n\n    # the first volume here is the 'work dir', ie: where\
    \ we have stored the wrapper and\n    # the Collada file.\n    # \n    # the second\
    \ volume is where OpenRAVE stores the generated `.cpp`.\n    # there is no 'output\
    \ file' argument to `openrave.py --database inversekinematics ..`,\n    # so this\
    \ will have to do.\n    # \n    # make sure to replace $DOCKER_IMAGE with whatever\
    \ you used earlier\n    $ docker run -it --rm -v `pwd`:/ikfast -v `pwd`/output:/root/.openrave\
    \ $DOCKER_IMAGE openrave0.9.py --database inversekinematics --robot=/ikfast/wrapper.xml\
    \ --iktype=translationyaxisangle4d --iktests=1000\n\nBecause we installed `build-essential`\
    \ inside the image, we can ask OpenRAVE to run some IK tests for us. OpenRAVE\
    \ will automatically compile the plugin after it has generated it and run the\
    \ tests. Pay attention to the final output. On my machine it is something like:\n\
    \n    openravepy.databases.inversekinematics: testik, success rate: 1.000000,\
    \ wrong solutions: 0.000000, no solutions: 0.000000, missing solution: 0.036000\n\
    \nIf everything went well, you should now have a `ikfast71.TranslationYAxisAngle4D.0_1_2_3.cpp`\
    \ and a `ikfast.h` in the `output/` dir that we created earlier. You should be\
    \ able to continue with the tutorial now and finish creating the MoveIt IKFast\
    \ plugin.\n\n---\n\nDocumentation I used for this is basically what I referenced\
    \ in #q196753."
