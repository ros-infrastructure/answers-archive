  body_markdown: "1) First you run your world.\n\nThen you spawn robot in your map\
    \ by loading its description to a parameter server in your launch file \n\n  \
    \  <param name=\"robot_description\"\n        command=\"$(find xacro)/xacro --inorder\
    \ '$(find turtlebot_description)/urdf/turtlebot.xacro'\" />\n\nI do not know what\
    \ is the file with turtlebot description called, but the location should be something\
    \ similar for every robot. This is the standard.\n\nThen you run the spawner node\
    \ to spawn the robot in your world.\n\n    <node name=\"urdf_spawner\" pkg=\"\
    gazebo_ros\" type=\"spawn_model\" respawn=\"false\" output=\"screen\"\n      \
    \  args=\"-urdf -model turtlebot -param robot_description\"/>\n\nI do not see\
    \ into your turtlebot package, but the cmd_vel comes with the ros_control plugin.\
    \ Somewhere in the gazebo.xacro file of your robot description a controller plugin\
    \ should be loaded. You then have a choice between different controllers inside\
    \ this plugin. One of which is the differencial controller (or something like\
    \ that). This type of controller uses the cmd_vel topic to command velocity.\n\
    \n2) Most of the times I simply copy-paste what I need from already existing launch\
    \ file into a new one. Launchfile contain all the nodes that you want to be running\
    \ upon start of the simulation. Keep in mind that the order of the launching is\
    \ not specified. The node located at the last line of the launch file can be run\
    \ as first and so on. There is no way known to me how to force any order.\n\n\
    > ***An important fact about roslaunch\u2014one that can be easy to forget\u2014\
    is that all of the\nnodes in a launch file are started at roughly the same time.\
    \ As a result, you cannot be sure\nabout the order in which the nodes will initialize\
    \ themselves. Well-written ROS nodes don\u2019t\ncare about the order in which\
    \ they and their siblings start up.** (Jason M. O\u2019Kane, A Gentle Introduction\
    \ to ROS.[1])*\n\nYou can also include other launchfiles in the launchfile, define\
    \ parameters and load parameters to ROS parameter server (as shown in the tags\
    \ above). \n\nYou create Gazebo and Rviz launch files separately, because often\
    \ you do not want to launch them at the same time.\n\n----------\n\n[1] https://www.cse.sc.edu/~jokane/agitr/agitr-letter-launch.pdf"
