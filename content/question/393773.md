    Hello, I was also facing a similar problem. Then I decided to use turtlebot 4 package SLAM and I am giving you the commands that helped me solve this problem. I hope this helps you:
    The **first** step was to Install the odometry package which  is`rf2o_laser_odometry`
    The **second** step was to start the Lidar node using: `ros2 launch rplidar_ros rplidar.launch.py`
    The **third** step is to start odometry from ros2 workspace:`ros2 launch rf2o_laser_odometry rf2o_laser_odometry.launch.py laser_scan_topic:=scan`
    The **fourth** step is to do static transformation:

        ros2 run tf2_ros static_transform_publisher 0 0 0 0 0 0 base_link laser

        ros2 run tf2_ros static_transform_publisher 0 0 0 0 0 0 base_link odom

    The **fifth** step was to start the SLAM algorithm:

        ros2 launch turtlebot4_navigation slam.launch.py params:=/full/path/to/slam.yaml

    The **final** step is to Bring up the robot:

        ros2 launch turtlebot4_viz view_robot.launch.py

    This isn't ROS or Colcon specific.

    I was simply referring to the level of optimisation the compiler should perform while it's compiling your packages. This can be configured using [CMAKE_BUILD_TYPE](https://cmake.org/cmake/help/latest/variable/CMAKE_BUILD_TYPE.html#variable:CMAKE_BUILD_TYPE) (obviously only for CMake-based packages, which would be quite a few in a typical ROS 2 workspace).

    The command given in the tutorial you link (`colcon build --symlink-install`) doesn't seem to do that, which leaves it up to individual packages to configure a build type.

    The default CMake build type is 'empty', which doesn't set any flags IIRC.

    You could test whether building your workspace with the following command improves performance:

        colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo

    that would configure CMake to use `RelWithDebInfo` for all packages in that workspace.

    I'd suggest doing this in a new workspace, so caching doesn't affect the results.

**[1641398181.499569062] [slam_toolbox]: Message Filter dropping message: frame 'camera_depth_frame' at time 1641398181.448 for reason 'discarding message because the queue is full'**
