  body_markdown: |-
    You can perform a workaround by putting the delayed node into an extra launch file and run it via `timed_roslaunch`.
    Explanation goes [here](http://wiki.ros.org/timed_roslaunch).
    Script is available [here](https://github.com/warehouse-picking-automation-challenges/plocka_packa/blob/master/apc_simulator/scripts/timed_roslaunch.sh).

    In your case:

        <launch>
        <node name="talker" pkg="roscpp_tutorials" type="talker" />
        <node pkg="timed_roslaunch" type="timed_roslaunch.sh" args="1 roscpp_tutorials my_listener.launch" name="timed_roslaunch" output="screen" />
        </launch>

    Content of `my_listener.launch`

        <launch>
        <node name="listener" pkg="roscpp_tutorials" type="listener" />
        </launch>

  body_markdown: "I found a one-line solution that does not require any additional\
    \ packages (it was a bit tricky):\n\nYou can make use of launch-prefix feature\
    \ like so:\n\n    <arg name=\"node_start_delay\" default=\"1.0\" />  \n    <node\
    \ name=\"listener\" pkg=\"roscpp_tutorials\" type=\"listener\" launch-prefix=\"\
    bash -c 'sleep $(arg node_start_delay); $0 $@' \" /> \n\nthe problem with using\
    \ just launch-prefix=\"sleep 1.0; \" was that the node launching command was passed\
    \ as arguments to 'sleep'"
