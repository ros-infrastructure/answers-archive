    You can certainly wrap ROS callback functions, however I can't think of an application for that approach, since you would need to manually provide the data the callback expects (whether message or request/response arguments). If you mean, can you reuse a generic function as a ROS callback, you can also use boost::bind to [bind a function](http://answers.ros.org/question/143196/class-send-through-a-callback-function/#143221) with arbitrary arguments.
