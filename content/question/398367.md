  body_markdown: "> Is it possible to load a .xacro robot and attach an end effector\
    \ made using a .stl file or a .xaml file?\n\nno, not directly. And `.xaml` files\
    \ cannot be used at all I believe.\n\nIn a URDF (which a `.xacro` file in the\
    \ end is turned in to), you define the kinematic structure of your robot + attach\
    \ meshes to the `link` elements which are part of that structure. Those meshes\
    \ can be `.stl`s (or `.dae`, or anything supported by Assimp), but they can only\
    \ be attached *to* `link` elements. You cannot just have a `mesh` element and\
    \ attach it to the kinematic structure. That's not how URDF works (or: was designed\
    \ to be used). \n\nSo in your case, where you have a `.stl`, you'd have to create\
    \ a minimal `.xacro` which probably defines only a single `link`, the `base_link`\
    \ (this name is arbitrary, you can use whatever you want, but `base_link` is a\
    \ good ROS convention to follow). That `base_link` can then be used to attach\
    \ your `.stl` to.\n\nAs an example:\n\n    <?xml version=\"1.0\"?>\n    <robot\
    \ xmlns:xacro=\"http://wiki.ros.org/xacro\">\n      <xacro:macro name=\"my_eef\"\
    \ params=\"prefix\">\n    \n        <!-- this EEF model has only a single link:\
    \ base_link, which is used\n             to 'attach' the STL mesh to which fully\
    \ represents the geometry\n             of the real EEF.\n    \n             Note\
    \ the use of both a visual (ie: detailed) quality mesh and\n             a collision\
    \ (ie: coarse) mesh. This is to facilitate tools like\n             motion planners,\
    \ which often use coarse models to speed up mesh\n             to mesh collision\
    \ checking.\n        -->\n        <link name=\"${prefix}base_link\">\n       \
    \   <visual>\n            <origin xyz=\"0 0 0\" rpy=\"0 0 0\"/>\n            <geometry>\n\
    \              <mesh filename=\"package://my_eef_pkg/meshes/visual/base_link.stl\"\
    />\n            </geometry>\n            <material name=\"grey\">\n          \
    \    <color rgba=\"0.2 0.2 0.2 1.0\"/>\n            </material>\n          </visual>\n\
    \          <collision>\n            <origin xyz=\"0 0 0\" rpy=\"0 0 0\"/>\n  \
    \          <geometry>\n              <mesh filename=\"package://my_eef_pkg/meshes/collision/base_link.stl\"\
    />\n            </geometry>\n          </collision>\n        </link>\n    \n \
    \       <!-- a default tool frame (might be better to broadcast a static TF frame\n\
    \             for this instead, but this is just an example).\n\n            \
    \ Note: this follows conventions of industrial robotics, and rotates the\n   \
    \          frame such that Z+ points forward, X+ points up.\n        -->\n   \
    \     <link name=\"${prefix}tool_frame\" />\n        <joint name=\"${prefix}base_link-tool_frame\"\
    \ type=\"fixed\">\n          <origin xyz=\"0 0 0\" rpy=\"${pi} ${-pi/2.0} 0\"\
    \ />\n          <parent link=\"${prefix}base_link\" />\n          <child link=\"\
    ${prefix}tool_frame\" />\n        </joint>\n      </xacro:macro>\n    </robot>\n\
    \nPut your EEF `.xacro` in its own package, and now you can follow the tutorial(s)\
    \ you already linked/found.\n\nNote that this defines a `xacro:macro`. So you'd\
    \ have to instantiate it. You cannot use it directly."
