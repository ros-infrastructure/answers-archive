    You are correct: there is currently no conversion to a depth-image. If the device is stationary, that representation could be quite useful. With a moving device, perhaps not, especially when turning.

    To do that, one would need to write a package similar to [velodyne_pointcloud](http://wiki.ros.org/velodyne_pointcloud), but using a different class to unpack the raw data. The logic for unpacking the data is in [rawdata.cc](https://github.com/ros-drivers/velodyne/blob/master/velodyne_pointcloud/src/lib/rawdata.cc). Code to create a polar, cylindrical projection would be a little simpler (less trigonometry). Making a package like that is feasible, but would require significant time and effort. The existing code would definitely provide a useful starting point.

    I maintain the Velodyne ROS driver, but have not had much time to devote to it lately. I will gladly provide technical advice if you want to work on it. There are more technical details than would be worthwhile to discuss here, so please open an [enhancement issue](https://github.com/ros-drivers/velodyne/issues/new), if you wish to pursue the idea.

    Hi,

    If you subscribe run the velodyne_driver **you can subscribe** "**velodyne_packets**" (format: velodyne_msgs::VelodyneScan) topic, instead of "velodyne_points" (format: velodyne_msgs::Pointcloud2) and then you will have range of each laser, rotation, intensity and other informations nedded.

    With velodyne_points you only have the points XYZ, intensity and laser ring at least.
