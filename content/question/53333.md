  body_markdown: |-
    In ROS Fuerte, some of the core stacks/packages were converted to use a prototype version of the catkin buildsystem ([docs here](http://ros.org/doc/fuerte/api/catkin/html/)). In this version, the notions of "packages" and "stacks" were re-defined (all deps were pushed to the stack level and all manifest.xml files were made to just contain other metadata). Since `common_msgs` is one of these stacks that was catkinized, neither `rospack` nor `rosstack` in Fuerte can parse this xml file. In this case, `std_msgs` gets built and installed top `/opt/ros/fuerte/include/std_msgs` (the new FHS standard), so as long as `/opt/ros/fuerte` is in a given C++ package's include path, you will be able to include C++ headers from `std_msgs` (there's a similar setup for Python). You'll see that things like dependency specification are defined differently:

    ROS Diamondback ([rosbuild](http://www.ros.org/wiki/rosbuild))

     - [stack.xml](https://github.com/ros/common_msgs/blob/common_msgs-1.4/stack.xml): `<depend stack="ros_comm" />`
     - [manifest.xml](https://github.com/ros/common_msgs/tree/common_msgs-1.4/geometry_msgs/manifest.xml): `<depend package="rosbagmigration"/>` (gives you `std_msgs` via this dep)

    ROS Fuerte ([catkin prototype](http://ros.org/doc/fuerte/api/catkin/html/)):

     - [stack.xml](https://github.com/ros/common_msgs/blob/fuerte-devel/stack.xml): `<build_depends>std_msgs</build_depends>`, `<depends>std_msgs</depends>`
     - [manifest.xml](https://github.com/ros/common_msgs/blob/fuerte-devel/geometry_msgs/manifest.xml): No dependency information

    ROS Groovy ([new catkin](http://ros.org/doc/groovy/api/catkin/html/)):

     - [stack.xml](https://github.com/ros/common_msgs/blob/groovy-devel/stack.xml): Gone
     - [manifest.xml](https://github.com/ros/common_msgs/blob/groovy-devel/geometry_msgs/manifest.xml): Gone
     - [package.xml](https://github.com/ros/common_msgs/blob/groovy-devel/geometry_msgs/package.xml): `<build_depend>std_msgs</build_depend>`, `<run_depend>std_msgs</run_depend>`
