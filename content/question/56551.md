  body_markdown: "I don't believe this exists out-of-the-box.\n\n[Rosbag command line\
    \ tools](http://www.ros.org/wiki/rosbag/Commandline#play \"Rosbag Command line\
    \ tools\") do allow you to play back topics at a modified (possibly very slow)\
    \ constant rate with --rate.  If you want very strict control over the publishing,\
    \ this code snippet should serve:\n\n    import roslib, rospy, rosbag\n    from\
    \ std_srvs.srv import Empty\n    \n    class BagByService(object):\n        def\
    \ __init__(self, bagfile):\n            self.bag = rosbag.Bag(bagfile, 'r')\n\
    \            self.message_generator = self.bag.read_messages()\n            self.next_msgs_srv\
    \ = rospy.Service('/next_msg', Empty, self.pub_next_msg)\n    \n            #Create\
    \ a publisher for each topic\n            self.publishers = {}\n            for\
    \ con in self.bag._get_connections():\n                msg_class = roslib.message.get_message_class(con.datatype)\n\
    \                self.publishers[con.topic] = rospy.Publisher(con.topic, msg_class)\n\
    \    \n        def pub_next_msg(self, req):\n            topic, msg, time = self.message_generator.next()\n\
    \            self.publishers[topic].publish(msg)\n    \n    if __name__=='__main__':\n\
    \        import sys\n        rospy.init_node('bag_by_service')\n        bbs =\
    \ BagByService(sys.argv[1])\n        rospy.spin()\n\nRun this with the .bag file\
    \ as the only commandline argument. Calling the Empty '/next_msg' service will\
    \ publish the next message in the bag file.  Clearly, more interesting things\
    \ could be done from here (filtering by time, topic, etc.)"

Is there a way to get rosbag to publish the next message by calling a service. 
A use-case is that a node request the rosbag player to publish the next message without a fixed hz, but when the node is ready to receive new info. This will allow for a lot of flexibility during the development of complex systems.
