    \ in 2 places, the mostly ros agnostic launch framework\nhttps://github.com/ros2/launch/tree/galactic/launch/launch/event_handlers\n\
    \nand the ros specific portions of launch found in launch_ros\nhttps://github.com/ros2/launch_ros/tree/galactic/launch_ros/launch_ros/event_handlers\n\
    \nIn the launch_ros folder we find the OnStateTransition event handler which I\
    \ believe meets your needs. \nhttps://github.com/ros2/launch_ros/blob/galactic/launch_ros/launch_ros/event_handlers/on_state_transition.py\n\
    \nI've not used this before, but there is an example of it in that repo (copied\
    \ here in case the link brakes)\nhttps://github.com/ros2/launch_ros/blob/6370c127868a5056a8a02c9412c59bebdaefcf81/launch_ros/examples/lifecycle_pub_sub_launch.py#L59\n\
    \n    # When the talker node reaches the 'active' state, log a message and start\
    \ the listener node.\n    register_event_handler_for_talker_reaches_active_state\
    \ = launch.actions.RegisterEventHandler(\n        launch_ros.event_handlers.OnStateTransition(\n\
    \            target_lifecycle_node=talker_node, goal_state='active',\n       \
    \     entities=[\n                launch.actions.LogInfo(\n                  \

    \ namespace='',\n                    package='lifecycle', executable='lifecycle_listener',\

I am using ROS2 Galactic, and writing Python Launch files.

Let’s say I have a launch file, L1 that starts node L1N1.

Then I have another launch file, L2, that can start node L2N1 on a specific condition.

The way I am running these Launch files is, that I am including the launch description of L1 into L2, this means that L2 starts running L2N1, and now I want to condition the execution of my node L2N2, on the basis of the state of L1N1.

Is there a way to register an event handler on the state of node L1N1, executed by the launch file L1,
that was included inside the same launch file L2?
