We're running ROS2 on an NVIDIA Jetson device for a project. We noticed huge frame drops in the camera output and started investigating the problem.

Then we stumbled upon this issue on Github [Publishing large data is 30x-100x slower than for rclcpp](https://github.com/ros2/rclpy/issues/763). So, we profiled the actual publish and subscribe process and compared the speeds of Python and C++. The results seem very unrealistic and I wanted to get some thoughts on the problem, the results, and our methodology.

**Methodology:** Pretty straightforward, measure epoch time before the publish function call and after the subscribe function call. The difference between these times would give us the total time taken for the message to be transferred.
**Observation:** For 2MB of data transferred between the publisher and subscriber, the C++ implementation gave ~8ms and the Python gave ~24ms.

Since we are quite new to using ROS, we couldn't really reason the results we have. Any help is appreciated. We're running the Humble release on Ubuntu 22.04
