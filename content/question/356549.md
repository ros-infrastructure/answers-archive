    \ a bit, it seems like making the service fail is not currently possible (although\
    \ the [docs](https://docs.ros.org/en/rolling/Contributing/Migration-Guide.html#use-of-service-objects)\
    \ recommend to throw exceptions but that doesn't work).\n\nThe only workaround\
    \ in your case is to add a timeout on the client side and make the server not\
    \ return a response. [Here](https://github.com/ros2/ros2_documentation/issues/2341#issue-1157291175)\
    \ is an example of the migration from ROS1:\n\n    // ROS 1 style is in comments,\
    \ ROS 2 follows, uncommented.\n    // #include \"nav_msgs/GetMap.h\"\n    #include\
    \ \"nav_msgs/srv/get_map.hpp\"\n    \n    // bool service_callback(\n    //  \
    \ nav_msgs::GetMap::Request & request,\n    //   nav_msgs::GetMap::Response &\
    \ response)\n    void service_callback(\n      const std::shared_ptr<rmw_request_id_t>\
    \ request_header,\n      const std::shared_ptr<nav_msgs::srv::GetMap::Request>\
    \ request)\n    {\n      auto response = std::make_shared<nav_msgs::srv::GetMap::Response>();\n\
    \      // ...\n      if (!has_map_) {\n        // return false;\n        return;\n\
    \      }\n      // return true;\n      map_server_->send_response(*request_header,\
    \ *response);\n    }\n\nOn the client side you just add a timeout:\n\n    auto\
    \ result = client->async_send_request(request);\n    // Wait for the result.\n\
    \    if (sync_response_executor->spin_until_future_complete(result, 800ms) !=\
    \ rclcpp::FutureReturnCode::SUCCESS) {\n        RCLCPP_ERROR(get_logger(), \"\
    Service failed\");\n        return;\n    }"
