  body_markdown: "I made my own solution, for sure far from perfect but is working\
    \ for my use case. I call my (heavily modified) version of [GT-RAIL/rail_segmentation](https://github.com/GT-RAIL/rail_segmentation)\
    \ to segment the table and the objects on top. Then, I send the clusters to my\
    \ heavily modified [GT-RAIL/rail_mesh_icp](https://github.com/GT-RAIL/rail_mesh_icp)\
    \ with the following changes:\n\n- Replace ICP and template matching services\
    \ with a single action (I convine both nodes into one; ICP Matcher is now an object\
    \ of template matcher)\n- Load multiple templates, compare the target pointcloud\
    \ against all (in parallel with OpenMP), and get the best match\n- On ICP matching,\
    \ I only allow 2D transformation, appropriate for tabletop objects\n\nHere are\
    \ my changes, both thorp branch: \n- https://github.com/corot/rail_segmentation\n\
    - https://github.com/corot/rail_mesh_icp\n\nI didn't bother to PR anything into\
    \ RAIL repos cause they don't seem maintained anymore, and the changes are too\
    \ big, and possibly beyond the original purpose of the code.\n\nBtw, to recognize\
    \ your 3D meshes with rail_mesh_icp you must sample as PCD files (explained in\
    \ RAIL wiki)\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/1618937546868805.gif)\n\

Hi, [ORK](https://wg-perception.github.io/object_recognition_core/) looks dead, and so I was thinking to switch to another 3D object recognition package. I saw [this same question](
http://answers.ros.org/question/12444/best-3d-object-recognition-package) but it's 8 years old, so I ask again.

I have identified so far plenty of ROS packages that recognize objects from 2D images, and some of them complement it with depth from a 3D camera:

 - [RAIL_segmentation](http://wiki.ros.org/rail_segmentation)	segments pointclouds like tabletop, but cannot (afaik) recognize
 - [RAIL object detector](http://wiki.ros.org/rail_object_detector)	detects objects in 2D using YOLOv2 or DRFCN , no 3D info
 - [find_object_2d](http://wiki.ros.org/find_object_2d)		2D w/ OpenCV but adds 3D pose with 3D camera
 - [ros-openvino-toolkit](https://discourse.ros.org/t/ros-openvino-toolkit-release-initial-version-v0-3-0/7058)	Intel’s ROS wrapper for OpenVINO: 2D CNN-based obj. rec; no 3D info
 - [ros_openvino](https://github.com/gbr1/ros_openvino)		Same but from one guy
 - [YOLO  perception](http://wiki.ros.org/darknet_ros)	Looks very active; no 3D info
 - [ros_people_object_detection_tensorflow](https://github.com/cagbal/ros_people_object_detection_tensorflow)	similar to YOLO but adds 3D info
 - [ros_object_analytics](https://github.com/intel/ros_object_analytics)	detect and tracking, uses GPU
 - [object-recognition-node-with-monocular-camera-package](https://discourse.ros.org/t/deep-neural-net-object-recognition-node-with-monocular-camera-package-announcement/4173)   uses OpenCV’s DNN
 - ...  

But pretty sure there are more (and even more will soon appear). Looks like most approaches now involve 2D object recognition using Deep Learning and then add depth by locating the object centroid in a depth image. Am I right? Mesh-matching times are gone?

What I want is, as with ORK, tabletop segmentation and recognition of the objects on the table, with 3D pose, to run a demo like that on [this video](https://drive.google.com/file/d/0BzYjlgbSZJSWaVRVQmVKTVczY00/view). Has anyone any clue about which package looks best place to become a new "de facto" standard, or at least continue with active maintaining for the mid-term?

Thanks a lot!
