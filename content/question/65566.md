  body_markdown: "To compensate for @felix k's answer, `rqt` saves so-called `perspective`\
    \ when it's run on `rqt_gui` and closed. (I just found that it's not documented)\
    \ things that are saved include:\n\n- plugins opened \n- plugins' size and positions\
    \ within the container window (`rqt_gui`)\n- `rqt_gui`'s size and position with\
    \ respect to the computer's desktop\n\nTo run `rqt_gui`, you just run:\n\n   \
    \ $ rqt  (Groovy and later)\n    $ rosrun rqt_gui rqt_gui  (Fuerte)\n\nRunning\
    \ `rqt_gui` is the recommended usage of `rqt`, although you can run each `rqt`\
    \ plugin individually.\n\nIn response to the `RViz` example in your question,\
    \ `rqt_gui` does NOT save the configuration of each plugins as I listed above;\
    \ instead it's up to how each plugin is implemented. And the feature of `rqt`\
    \ variant of `Rviz`, [rqt_rviz](ros.org/wiki/rqt_rviz), is the same with what\
    \ `RViz` has, because `rqt_rviz` embeds `RViz`, which doesn't save the `.config`\
    \ file that was used the last time (if I remember correctly). You can open an\
    \ enhancement request [here](https://github.com/ros-visualization/rqt_robot_plugins/issues)."
