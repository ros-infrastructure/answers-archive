    You are probably missing the line

        add_dependencies(name_of_exe package_name_generate_messages_cpp)

    in your CMakeLists.txt. This line should be present after target_link_libraries for the same exe.

    If you have that, you will build the messages before the exe files.

  body_markdown: "As McMudro said you are missing some dependencies. To make it bit\
    \ clearer:\n\ncatkin creates several files which are used as flags to determine\
    \ if something has been built or not. The flags for messages are always following\
    \ the same naming convention: \n\n    package_name_generate_messages_cpp\n\nWhere\
    \ 'package_name' is of course the name of your package and '_generate_messages_cpp'\
    \ is a fixed name for the build flag and cannot be changed. One of the problems\
    \ is that if you misspell it, catkin will not complain but it also does not have\
    \ any effect. Therefore you have to make sure that you always spell it right.\n\
    \nOne example would be:\n\n    cmake_minimum_required(VERSION 2.8.3)\n    project(my_package)\n\
    \n    find_package(catkin REQUIRED COMPONENTS genmsg roscpp std_msgs geometry_msgs\
    \ ... message_generation)\n\n    ## Generate messages in the 'msg' folder\n  \
    \  add_message_files(\n      FILES\n      MyMessage.msg\n    )\n\n    generate_messages(\n\
    \      DEPENDENCIES\n      std_msgs \n      ...\n      geometry_msgs\n    )\n\n\
    \    catkin_package(\n      INCLUDE_DIRS include\n    # LIBRARIES strands_gazing\n\
    \      CATKIN_DEPENDS std_msgs geometry_msgs ...\n    # DEPENDS system_lib\n \
    \   )\n\n    include_directories(include\n      ${catkin_INCLUDE_DIRS}\n    )\n\
    \n    ## Declare a cpp executable\n    add_executable(foo foo.cpp)\n\n    ## Add\
    \ cmake target dependencies of the executable/library\n    ## as an example, message\
    \ headers may need to be generated before nodes\n    add_dependencies(foo my_package_generate_messages_cpp)\n\
    \n    ## Specify libraries to link a library or executable target against\n  \
    \  target_link_libraries(foo\n      ${catkin_LIBRARIES}\n    )\n\nWhere the important\
    \ line is this one `add_dependencies(foo my_package_generate_messages_cpp)` which\
    \ makes sure that the flag `my_package_generate_messages_cpp` exists before trying\
    \ to build `foo`. Therefore it makes sure that the message headers are generated\
    \ before building the binary.\n\nNow, what if you have custom messages in other\
    \ packages on which this package relies and which therefore have to be build first?\
    \ You could include them in the same way in the add_dependency line but it is\
    \ much more convenient to use one of catkins makros for this: `${catkin_EXPORTED_TARGETS}`\
    \ which contains all the `_generate_messages_cpp` flags for all the catkin packages\
    \ you listed in the `find_package` line. So all you have to change is:\n\n - Add\
    \ your second package to the `find_package` statement of the first one: `find_package(catkin\
    \ REQUIRED COMPONENTS my_other_package genmsg roscpp geometry_msgs ... message_generation)`\n\
    \ - Add the macro to the dependencies `add_dependencies(foo my_package_generate_messages_cpp\
    \ ${catkin_EXPORTED_TARGETS})`\n\nIn fact it can never hurt to include this macro.\n\
    \nAnother very common source of error is including the `my_other_package_generate_messages_cpp`\
    \ flag in the dependencies of `my_package` (e.g. by using the catkin macro described\
    \ above) and forgetting to add it in the package.xml file. If you do not add `my_other_package`\
    \ as a build and run dependency to the package.xml of `my_package`, catkin will\
    \ assume that both packages try to build the messages in `my_other_package` and\
    \ since you cannot have the same type of message twice it will exit with a cmake\
    \ error. So in this case your package.xml file would have to look similar to this:\n\
    \n    <?xml version=\"1.0\"?>\n    <package>\n     <name>my_package</name>\n \
    \    ...\n\n     <buildtool_depend>catkin</buildtool_depend>\n  \n     <build_depend>my_other_package</build_depend>\n\
    \     <build_depend>geometry_msgs</build_depend>\n     <build_depend>genmsgs</build_depend>\n\
    \     <build_depend>roscpp</build_depend>\n     <build_depend>std_msgs_msgs</build_depend>\n\
    \     ...\n     <build_depend>message_generation</build_depend>\n\n     <run_depend>my_other_package</run_depend>\n\
    \     <run_depend>geometry_msgs</run_depend>\n     <run_depend>genmsgs</run_depend>\n\
    \     <run_depend>roscpp</run_depend>\n     <run_depend>std_msgs_msgs</run_depend>\n\
    \     ...\n     <run_depend>message_runtime</run_depend>\n\n     <export/>\n \
    \   </package>\n\nHope that helps."
