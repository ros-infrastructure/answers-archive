  body_markdown: "Hello Balto,\n\nFirst off all, yes you can repack it, but as you\
    \ can see in [nav_msgs/Odometry](http://www.ros.org/doc/api/nav_msgs/html/msg/Odometry.html)\
    \ you also need the covariance matrix of the position/orientation (float64[36]\
    \ covariance). This includes (x|y|z|roll|pitch|yaw) * (x|y|z|roll|pitch|yaw)^T.\
    \ \n\nCopied from message description: \nRow-major representation of the 6x6 covariance\
    \ matrix.\nThe orientation parameters use a fixed-axis representation.\nIn order,\
    \ the parameters are:\n(x, y, z, rotation about X axis, rotation about Y axis,\
    \ rotation about Z axis)\n\n\nYou can directly fill the pose  part of the [nav_msgs/Odometry](http://www.ros.org/doc/api/nav_msgs/html/msg/Odometry.html)\
    \ message with your [geometry_msgs/Pose](http://ros.org/doc/api/geometry_msgs/html/msg/Pose.html)\
    \ message. Now you have to add your covariances into the pose-covariance-matrix,\
    \ this covariances normally grows during time. So every time you get a new message\
    \ from mocap you must also modify your covariances. If every covariance in the\
    \ matrix is zero, the filter thinks that your odometry doesn't produce any error\
    \ and no correction/filtering is done at this momement because the position at\
    \ this moment will be 100% correct for the filter and it didn't have to correct\
    \ it!\n\nThe twist part of the [nav_msgs/Odometry](http://www.ros.org/doc/api/nav_msgs/html/msg/Odometry.html)\
    \ message can be empty because as you can see in the source code of the [robot_pose_ekf](http://www.ros.org/wiki/robot_pose_ekf)\
    \ (odom_estimation_node.cpp lines 164-205) the robot_pose_ekf only uses position\
    \ x,y the orientation and of course the covariance matrix of pose.\nAlso the covariance\
    \ matrix of Twist can be empty for this filter.\n\nBest regards,\nThomas\n"
