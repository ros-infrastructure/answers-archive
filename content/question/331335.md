  body_markdown: "Hi. Welcome to ROS.\n\nIn your code, you just have to use regular\
    \ publishers and subscribers. The multiplexing is then done outside. So for example\
    \ if you run:\n\n    rosrun topic_tools mux sel_cmdvel auto_cmdvel joystick_cmdvel\
    \ mux:=mux_cmdvel\n\nThen you could publish in your nodes on the topics `auto_cmdvel`\
    \ or `joystick_cmdvel`\n\n    ros::Publisher pub = nh.advertise<geometry_msgs::Twist>(\"\
    auto_cmdvel\", 5);\n    geometry_msgs::Twist cmd;\n    cmd.linear.x = 1\n    pub.publish(cmd);\n\
    \nAnd in another node you can subscribe to `sel_cmdvel` (just like you would to\
    \ any other topic)\n\n    ros::Subscriber sub = nh.subscribe(\"sel_cmdvel\", 1,\
    \ callback);\n\nLook here for more info on topics in general: https://wiki.ros.org/ROS/Tutorials/UnderstandingTopics\
    \ and in cpp: https://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers\
    \ \n\n> I saw that once I created a mux I can change it with ros services from\
    \ my c++ code, but I don't know how to start the ros node except of running it\
    \ from cmd.\n\nFor this you need a launchfile: https://wiki.ros.org/ROS/Tutorials/UsingRqtconsoleRoslaunch#The_Launch_File\n\
    \n---\nedit:\n\nTo use the service, you have to follow https://wiki.ros.org/roscpp_tutorials/Tutorials/WritingServiceClient#Writing_the_Client_Node\
    \ For example to add a new input topic:\n\n    ros::NodeHandle n;\n    ros::ServiceClient\
    \ client = n.serviceClient<topic_tools::MuxAdd>(\"mux/add\");\n    topic_tools::MuxAdd\
    \ srv;\n    srv.request.topic = \"my_topic_to_add\";\n    client.call(srv)\n\n\
    But you have to start the topic_tools mux command beforehand. your code then communicates\
    \ with its services. For example in a launchfile:\n\n    <launch>\n      <node\
    \ pkg=\"topic_tools\" name=\"my_little_mux\" type=\"mux\"/>\n    </launch>\n\n\
    You'll have to try it but you can probably do all the configuration from your\
    \ cpp program, then."
