    \    export ROS_IP=169.254.1.22\n\nYou can't set `ROS_IP` to the IP of another\
    \ host. That's doesn't work. `ROS_IP` and `ROS_HOSTNAME` describe *the host your\
    \ setting them on* (ie: on \"Device A\" you set them to configure \"Device A\"\
    s properties). Only `ROS_MASTER_URI` can point to another host.\n\nAnd you don't\
    \ need both `ROS_IP` and `ROS_HOSTNAME`. If you have working DNS for all participating\
    \ hosts (ie: all hosts running ROS nodes can resolve the hostname of all other\
    \ hosts running ROS nodes), use `ROS_HOSTNAME`, if you don't, use `ROS_IP`.\n\n\

    \    export ROS_IP=169.254.1.22\n\nThis may have been unclear, but you typically\
    \ only start a single `roscore` (it's possible to start more, but that's advanced\
    \ usage, which I don't believe you need or should try just yet).\n\nChoose which\
    \ machine will run `roscore`, then set `ROS_MASTER_URI` to point to its IP. So\
    \ if \"device A\" is going to run `roscore`, set `ROS_MASTER_URI` on \"device\
    \ B\" to `http://169.254.1.21:11311` (ie: point it to \"device A\"). Now on the\
    \ other host (ie: the one not running `roscore`), set `ROS_MASTER_URI` to point\
    \ to itself, **not** to the other host.\n\nAnd as I wrote earlier: you don't need\
    \ both `ROS_IP` and `ROS_HOSTNAME`. Use `ROS_IP` (unless you have a working DNS\
    \ server).\n\nWith `roscore` on \"device A\", we'd end up with:\n\n - device A\n\
