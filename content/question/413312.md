  body_markdown: "Hi,\n\n**Re. your fist question:**\n\nI think the link you mention\
    \ might be ROS 2 python only.\nThere is currently no rotating log functionality\
    \ for c++, though it could probably be added without too much effort:\n\nIf you\
    \ are using c++, logging is configured from `rclcpp::init()`, which ultimately\
    \ calls `rcl_logging_external_initialize`, see [here](https://github.com/jrutgeer/ROS2_assorted_docs/blob/main/ROS2_core/ROS2_logging.md#external-library-spdlog).\n\
    \nExternal logging uses the spdlog library. The logger is created [here](https://github.com/ros2/rcl_logging/blob/cdef749a304f734ba275f8466a4883db6400dc75/rcl_logging_spdlog/src/rcl_logging_spdlog.cpp#L178).\n\
    Spdlog supports rotating log files, so **if you change logger creation to something\
    \ similar to [this](https://github.com/gabime/spdlog#rotating-files), you should\
    \ have rotating log files.**\n\n\nThat would obviously be a local hack, and you\
    \ need to compile ROS 2 from source. To make this into a full feature, one should:\n\
    \n- File an issue in the [rcl_logging](https://github.com/ros2/rcl_logging) repository\
    \ to discuss the best option to configure this (environment variable / command\
    \ line argument / configuration file / other?),\n \n- In case of a configuration\
    \ file: first check if there are existing implementations, e.g. [this](https://github.com/guangie88/spdlog_setup),\
    \ and discuss whether it would be best to use these or to implement something\
    \ custom (e.g. to avoid an extra dependency).\n\n- Change accordingly:\n\n  -\
    \ For environment variable: add to [`rcl_logging_external_initialize`](https://github.com/ros2/rcl_logging/blob/cdef749a304f734ba275f8466a4883db6400dc75/rcl_logging_spdlog/src/rcl_logging_spdlog.cpp#L94)\
    \ similar to [this code](https://github.com/ros2/rcl_logging/blob/cdef749a304f734ba275f8466a4883db6400dc75/rcl_logging_spdlog/src/rcl_logging_spdlog.cpp#L65-L89),\n\
    \ - For command line argument: add to [`rcl_parse_arguments`](https://github.com/ros2/rcl/blob/4eccc3cbe65f5b58981f22efaf612a65731cb2f0/rcl/src/rcl/arguments.c#L248),\
    \ see code documentation [here](https://github.com/jrutgeer/ROS2_assorted_docs/blob/main/ROS2_core/ROS2_logging.md#rclcpp-logger-initialization),\n\
    \  - For logfile: add implementation [here](https://github.com/ros2/rcl_logging/blob/cdef749a304f734ba275f8466a4883db6400dc75/rcl_logging_spdlog/src/rcl_logging_spdlog.cpp#L107-L111).\n\
    \nGiven you state that this request has \"been existing already for years\" and\
    \ it being \"really an issue\", maybe you should give it a go? :-) It shouldn't\
    \ be ultimately difficult nor time-consuming, given above info. \n\n**Possible\
    \ alternative solution**\n\n- Disable external logging through the environment\
    \ variable (refer to the docs),\n- Have something read the /rosout topic and write\
    \ it to file,\n  - I think rosbag could be used, though files are not in .csv\
    \ by default, see [here](https://answers.ros.org/question/55037/is-there-a-way-to-save-all-rosbag-data-into-a-csv-or-text-file/)\
    \ for info wrt conversion.\n- Write a script to restart your reader whenever you\
    \ want the logfile to rotate.\n- This has the benefit of being a process-agnostic\
    \ logger (i.e. gathers all log info of all nodes in a ROS 2 network, instead of\
    \ having one log file per process),\n- It **does not contain** log info from non-node\
    \ loggers (the ones created by `rclcpp::get_logger(\"name\")`), only messages\
    \ from node loggers (`node->get_logger()`).\n\n**Re. your 2nd question:**\n\n\
    You can specify loglevels on a per-name basis, e.g.:\n\n`ros2 run package node\
    \ --ros-args --log-level DEBUG --log-level rcl:=INFO --log-level rclcpp:=INFO`\n\
    \nThis sets default loglevel to DEBUG, but disables anything below INFO for rcl\
    \ and rclcpp."

Hi!

This question has seemingly been existing already for years (for ROS1), but I still haven't find any document or examples of how to split or rotate the log files in ROS2 (either from launch file, or directly from ROS2 run command line arguments, or even from code).

[This is the only example](https://github.com/ros2/launch/pull/233/files) (Issue 230: https://github.com/ros2/launch/issues/230) I found to be related to this topic, but no where is told how to properly set this **RotationHandler** in launch file (as the **launch_counters.py** example does not seem to be a proper ROS2 launch file). Attempts to define it in launch file leads either to errors or non-effective results.

This is really an issue for an automated production systems where there is no possibility to be clearing the ROS logs all the time. Even if the ROS_LOG_DIR is set with some specific value, the ~/.ros/log/ directory also fills up with logs, if ROS2 launch is used. Disabling the logging completely is also not a very good idea, as then you can't solve afterwards what went wrong with the production.

Another question: How to define a own specific logging level? Something into between INFO and DEBUG? As otherwise the DEBUG level will output way too much unnecessary **rcl** system info into the logs.
