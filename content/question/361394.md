  body_markdown: "When trying to create a header only catkin package you need to do\
    \ two things. \n\n 1. Mark the header as a required include for dependent packages\
    \ using catkin_package\n 2. Add an install tag for the header\n\nThis looks like\
    \ the following in the CMakeLists.txt file\n\n\n    catkin_package(\n      INCLUDE_DIRS\
    \ include\n    )\n    \n    install(DIRECTORY include/\n      DESTINATION ${CATKIN_PACKAGE_INCLUDE_DESTINATION}\n\
    \    )\n\nI believe the above is all you need, but if you run into issues you\
    \ can also try adding the following between your catkin_package and install tags.\
    \ \n\n    include_directories(\n      include\n    )\n\nOnce your header package\
    \ is good to go you just need to add it as a dependency for your executable\n\n\
    \    find_package(catkin REQUIRED COMPONENTS\n      my_package\n    )\n    \n\
    \    add_executable( my_executable_name src/my_source.cpp)\n    \n    add_dependencies(my_executable_name\
    \ ${catkin_EXPORTED_TARGETS})\n\nDon't forget to also add it in the package.xml\n"

    Yes, but the problem is that the compiler always throws an error if there is no cpp to compile, since you have only a header the cmake directive throws the error. For that reason a possible solution is having an empty cpp. The other one is declaring the header as interface, but when I had this particular problem I tried to use that approach and failed. As a clarification I will explain my experience with this problem.
    In one project I had a header only file and then a main node and a library, I was able to compile and execute properly the package by including the header only in the library cpp and then the library header on the main node cpp. And that is becasue the header content was copied throught the entire cpp compilation files. In [fact](https://answers.ros.org/question/308304/using-catkin-with-cmake-interface-library/) there are versions of catkin in which this is not supported.
