    \nThat shouldn't be the case. The only `tf` that `laser_scan_matcher` requires\
    \ is `base_link` -> `laser`. That can be published by a static tf publisher, or\
    \ by stage.\n\n`laser_scan_matcher` is intended as a replacement for odometry,\
    \ for robots without odom sensors. If your robot already has an odometry sensor,\
    \ then you can provide its measurements as an optional input to `laser_scan_matcher`,\
    \ and the scan matcher will refine them. The odom sensor's measurements would\
    \ need to be published on a topic (not as a `tf`). I would get the base case working\
    \ first though (no odometry) and then attempt this case.\n\nCould you describe\
