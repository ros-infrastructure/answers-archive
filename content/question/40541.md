  body_markdown: "Hello All,\n\nI know what the origin of the problem is, and how\
    \ to (at least temporarily) fix it.\n\n**The Problem**\n\nWhen using AMCL to provide\
    \ the map->odom tf-transform to move_base, everything works fine. This is because\
    \ AMCL 'future dates' the provided transform (see last sentence here: http://wiki.ros.org/amcl#Transforms).\n\
    \nHowever, when using hector_slam for localization instead of AMCL, the provided\
    \ map->odom tf-transform is not future dated. This leads to move_base throwing\
    \ the\nmentioned error:\n\n    Extrapolation Error: Unable to lookup transform,\
    \ cache is empty, when looking up transform from frame [/odom] to frame [/map]\n\
    \n\n**How to temporarily fix it**\n\nCheck out https://github.com/tu-darmstadt-ros-pkg/hector_slam.git\
    \ (catkin branch) into your own ROS workspace and modify Line 347 in file HectorMappingRos.cpp\
    \ (direct link https://github.com/tu-darmstadt-ros-pkg/hector_slam/blob/catkin/hector_mapping/src/HectorMappingRos.cpp)\
    \ as follows:\n\n    # Replace the original line 347 in HectorMappingRos.cpp\n\
    \    tfB_->sendTransform( tf::StampedTransform (map_to_odom_, scan.header.stamp,\
    \ p_map_frame_, p_odom_frame_));\n    \n    # ...with these two lines\n    ros::Duration\
    \ future_date_duration(0.3F);\n    tfB_->sendTransform( tf::StampedTransform (map_to_odom_,\
    \ scan.header.stamp  + future_date_duration, p_map_frame_, p_odom_frame_));\n\n\
    This future dates the tf-transform published by hector_mapping by 0.3s. Then compile\
    \ the package and re-run your experiment. In my case, this got rid of the error\
    \ messages.\n\nBut this has some disadvantages:\n\n - The delay of 0.3s can be\
    \ noted in the navigation/localization performance of hector_mapping in conjunction\
    \ with move_base. You can also see the updates in rviz lag behind.\n - Patched\
    \ hector_mapping is no permanent solution.\n\n@BlitherPants I suppose it is the\
    \ same reason why gmapping throws the same errors when used together with move_base.\n\
    \n**Suggested permanent fix**\n\nI can see two options:\n\n 1. move_base has to\
    \ be changed so it also accepts non-future dated map->odom transforms OR\n 2.\
    \ hector_slam and gmapping have to be modified to provide future dated map->odom\
    \ transforms\n\nI suggest we get the follwing people involved in this discussion:\n\
    \n'@David Lu' (AMCL + move_base maintainer)\n\n'@Stefan Kohlbrecher' (hector_slam\
    \ author)\n\n'@Johannes Meyer' (hector_slam maintainer)\n\n'@Brian Gerkey' (gmapping\
    \ author)\n\n\n"
