  body_markdown: "I'll try to answer the questions in order.\n\nAll assuming you use\
    \ the Standard  `move_base` structure as linked to by @gvdhoorn above.\n\n> Who\
    \ generates > nav_msg/Path local planner or global planner?\n\nBoth, but actually\
    \ just for visualization. Typically on something like `move_base/<PLANNER>/<local_/global_>plan`\
    \ topics. The local planner also generates a `geometry_msgs/Twist` message which\
    \ provides the commanded velocities to the robot.\n\n>  If it is generated by\
    \ global_planner then how local planner use it to avoid obstacle.\n\nIt is passed\
    \ from the global planner to the local planner through the [`nav_core` Interfaces](http://wiki.ros.org/nav_core?distro=lunar).\n\
    \n> Can we generate customized nav_msg/Path??\n\nSure, as both `local_planners`\
    \ and `global_planners` are [plugins](http://wiki.ros.org/pluginlib) to `move_base`\
    \ you can write your own plugin which creates the plan in a way that you want.\
    \ Some more Information about how to do this can be found [in the Tutorials](http://wiki.ros.org/navigation/Tutorials/Writing%20A%20Global%20Path%20Planner%20As%20Plugin%20in%20ROS)\
    \ or [here](https://www.springerprofessional.de/writing-global-path-planners-plugins-in-ros-a-tutorial/7458334),\
    \ for example.\n\n> Actually how exactly the communication happens between global\
    \ planner and local planner, using what topics or messages? \n\nAs stated above,\
    \ this happens through the defined [`nav_core` interfaces](http://wiki.ros.org/nav_core?distro=lunar).\
    \ For more Details, please refer to the API documentation on the wiki page.\n\n\
    > Is it black box?\n\nNo, as this is, as all of ROS, OSS. Check the links to the\
    \ API documentation as well as the github repos on the respective wiki pages."
