    \n>     rostopic pub -1 /joint_states sensor_msgs/JointState '{header: auto, name:\
    \ ['FLJ','FLJ'], position: [0,0], velocity: [1,0], effort: [0,0]}'\n\nThere is\
    \ a problem with the way you've formatted the command. Note how you start the\
    \ message contents with a single quote (ie: `'`) and end it with one.\n\nBut in\
    \ the middle, you also use single quotes for the names of the joints. That can't\
    \ work, as the shell (ie: bash) will assume you'll use `'` to demarcate the arguments\
    \ to `rostopic`. So in the end, this is what the command line ends up being:\n\
    \n - `rostopic`\n -  `pub`\n - `-1`\n - `/joint_states`\n - `sensor_msgs/JointState`\n\
    \ - ` '{header: auto, name: ['`\n - `FLJ`\n - `','` (ie: a comma in quotes)\n\
    \ - `FLJ`\n - `'], position: [0,0], velocity: [1,0], effort: [0,0]}'`\n\nthat's\
    \ probably not what you intended to do.\n\nSummarising: you cannot embed single\
    \ quotes in the YAML you want to pass to `rostopic pub`.\n\nTwo options:\n\n 1.\
    \ don't quote at all: if there are no spaces in the names, you could forgo quoting\
    \ completely (YAML actually doesn't require strings to be quoted, it just helps\
    \ avoid ambiguity)\n 1. use double quotes (ie: `\"'`) for the joint names\n\n\
    But, this most likely won't help with:\n\n> but the robot is not moving...Why?\n\
    \n`JointState` messages are meant to report on current state, not to command desired\
    \ state. The `/joint_states` topic also typically only carries current state,\
    \ not commands.\n\nWe don't know how you've setup your Gazebo simulation, so you\
    \ could have configured it such that it *does* accept `JointState` messages as\
    \ commands, but you would have to check that yourself.\n\n---\n\nEdit:\n\n> If\
