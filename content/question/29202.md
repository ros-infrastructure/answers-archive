  body_markdown: "`actuator_msgs` and `gps_msgs` are ROS packages, not Gazebo.\nAccording\
    \ to the ros index I would assume [this one](https://index.ros.org/p/actuator_msgs/github-rudislabs-actuator_msgs/#humble)\
    \ and [this one](https://index.ros.org/p/gps_msgs/github-swri-robotics-gps_umd/#humble-overview).\
    \ So you could try to install these first (either binary, or from source. In the\
    \ latter case do not forget to issue a `source install/setup.bash` for the workspace\
    \ folder).\n\nAlternatively:\n\nIf you don't need those message types, you can\
    \ disable them in the source code of `ros_gz_bridge`. It's only a few small changes:\n\
    \n- In the `CMakeLists.txt`: remove them from the `set(BRIDGE_MESSAGE_TYPES ...)`\
    \ entry,\n- In `package.xml` remove the corresponding `depend` entries,\n- In\
    \ `include/ros_gz_bridge/convert.hpp`: remove the coresponding `#include` entries,\n\
    - In `ros_gz_bridge/mappings.py`: remove them from the `MAPPINGS`\n\nE.g.:\n\n\
    \      MAPPINGS = {\n        'builtin_interfaces': [\n             Mapping('Time',\
    \ 'Time'),\n        ],\n    #    'actuator_msgs': [\n    #         Mapping('Actuators',\
    \ 'Actuators'),\n    #    ],\n      'geometry_msgs': [\n             Mapping('Point',\
    \ 'Vector3d'),\n             Mapping('Pose', 'Pose'),\n             (etc)\n\n\
    </br> \n\n And then just recompile.\n\n\n"
