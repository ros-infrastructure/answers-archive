  body_markdown: "Hi,\n\nI think the first steps to know how to publish images in\
    \ ROS is through rostopics of type **sensor_msgs/Image**.\n\nA very good example\
    \ is how the **gazebo_ros_camera** plugin does it. \n\nCheck the git of how this\
    \ is implemented to have a good example on how to publish camera info in ROS :\
    \ [camera plugin](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/kinetic-devel/gazebo_plugins/src/gazebo_ros_camera.cpp)\n\
    \nYou then have to check if its working. Here are several options, each one more\
    \ complete:\n1) rostopic hz /camera_topic_name: This is the simplest. It states\
    \ if its publishing and at what rate. Good to know if its alive at least\n2) rostopic\
    \ echo /camera_topic: To gete a stream of data. Not very practical with big image\
    \ files\n3) RVIZ: add an image element. It will show you the images registered\
    \ by your camera.\n4) RVIZ: add a **camera element**. This element is the best\
    \ because it needs TFs to be published correctly, which is vital for working with\
    \ cameras in ROS.\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15428471161527614.png)\n\
    \n5) You can use the [stereo_image_proc](http://wiki.ros.org/stereo_image_proc)\
    \ to see if your stereo cam can be used for stereo vision point cloud generation.\
    \ This is the final test, if it works, you are ready to go.\n\n![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/15428470038730153.png)\n\
    \n\nI also created a small video tutorial that explains all this in a demo [VIDEO](https://youtu.be/-lzo1LJ8fvA)\n\
    \nHere is the code for the practical example [GIT](https://bitbucket.org/theconstructcore/stereo_tests/src/master/)\n\
    \nAnd here the [ROSject](https://goo.gl/Fg7A9h) , which you can use plug and play.\n\
    \nHope it helped."
