    \      <node name=\"rplidarNode\"          pkg=\"rplidar_ros\"  type=\"rplidarNode\"\
    \ output=\"screen\">\n      <param name=\"serial_port\"         type=\"string\"\
    \ value=\"/dev/ttyUSB0\"/>  \n      <param name=\"serial_baudrate\"     type=\"\
    int\"    value=\"115200\"/>\n      <param name=\"frame_id\"            type=\"\
    string\" value=\"laser\"/>\n      <param name=\"inverted\"            type=\"\
    bool\"   value=\"false\"/>\n      <param name=\"angle_compensate\"    type=\"\
    bool\"   value=\"true\"/>\n      </node>\n    </launch>\n\nYou should use `ls\
    \ /dev/ttyUSB*` to check what's the port of your lidar. And make sure the line\
    \ below is correct.\n\n    <param name=\"serial_port\"         type=\"string\"\
    \ value=\"/dev/ttyUSB0\"/>\n\nAlso, check if your user is in the linux group `dialout`\
    \ to get access to the lidar.\n\n============================================================\n\
    \nUpdate:\n\nI think you should first take a look at the message in your /scan\
    \ topic to confirm if angle_min != -angle_max.\nhttp://docs.ros.org/api/sensor_msgs/html/msg/LaserScan.html\n\
    \nAlthough in http://geduino.blogspot.com.tr/2015/04/gmapping-and-rplidar.html,\
    \ it mentioned that\n\n    First issue regards the LaserScan expected by GMapping.\
    \ Unfortunately this is not documented anywhere and I found it only checking out\
    \ source code: on latest commits (not yet released) a new check was added to make\
    \ sure LaserScan message min angle and max angle are opposite:\n    \n    maxAngle\
    \ = - minAngle\n    \n    This condition is not satisfied by RPLidar node but,\
    \ since released version of GMapping does not include this check, is not easy\
    \ to notice.\n\nI guess your gmapping does include this check, and since the driver\
    \ didn't handle this issue, your gmapping console would complain about that.\n\
    \nYou might need to modify the rplidar_ros/src/node.cpp to let angle_min == -angle_max\
    \ and see if it works.\n\n"
