    It's not gmapping that is using only three discrete values, but the [nav_msgs/OccupancyGrid.msg ](http://www.ros.org/doc/api/nav_msgs/html/msg/OccupancyGrid.html) message format. Internally, gmapping uses probabilistic cell values, but in the [slam_gmapping.cpp](http://ros.org/doc/fuerte/api/gmapping/html/slam__gmapping_8cpp_source.html) source, starting in line 631, those are converted to above linked message format like so:

        for(int y=0; y < smap.getMapSizeY(); y++)
        {
          /// @todo Sort out the unknown vs. free vs. obstacle thresholding
          GMapping::IntPoint p(x, y);
          double occ=smap.cell(p);
          assert(occ <= 1.0);
          if(occ < 0)
            map_.map.data[MAP_IDX(map_.map.info.width, x, y)] = -1;
          else if(occ > occ_thresh_)
          {
            //map_.map.data[MAP_IDX(map_.map.info.width, x, y)] = (int)round(occ*100.0);
            map_.map.data[MAP_IDX(map_.map.info.width, x, y)] = 100;
          }
          else
            map_.map.data[MAP_IDX(map_.map.info.width, x, y)] = 0;
        }

    Haven't played around with the code, but the occ variable should hold the probability of occupancy.

    See also this [question/answer](http://questions.ros.org/question/12914/rviz-display-2d-probabilistic-map/?answer=19068) about visualization in rviz.
