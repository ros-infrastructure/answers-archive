  body_markdown: "The main concern is the button/axis mapping in the subscriber. Each\
    \ robot interprets joy messages differently. You need to know what fields you\
    \ have to emulate. For example, the Xbox 360 controller works as such:\n\n   \
    \ #define XBOX_AXIS_LHORZ\t\t0\n    #define XBOX_AXIS_LVERT\t\t1\n    #define\
    \ XBOX_AXIS_LTRIG\t\t2\n    #define XBOX_AXIS_RHORZ\t\t3\n    #define XBOX_AXIS_RVERT\t\
    \t4\n    #define XBOX_AXIS_RTRIG\t\t5\n\nIf you wanted to publish to the left\
    \ stick vertical axis (up/down) to tell the robot to go forward, you could do\
    \ the following in the publisher:\n\n    sensor_msgs::Joy joy_msg;\n    joy_msg.axes.push_back(0.0);\
    \ // Left Horizontal\n    joy_msg.axes.push_back(1.0); // Left Vertical (-1.0\
    \ through 1.0)\n    joy_msg.axes.push_back(0.0); // Left Trigger\n    joy_msg.axes.push_back(0.0);\
    \ // Right Horizontal\n    joy_msg.axes.push_back(0.0); // Right Vertical\n  \
    \  joy_msg.axes.push_back(0.0); // Right Trigger\n\n    publisher.publish(joy_msg);\n\
    \    \nThe `.push_back()` method appends a new value to the \"axes\" vector. If\
    \ you don't add to the vector, it will be empty. If it's empty when you try to\
    \ access it with `axes[i]`, you'll get a segmentation fault. The above code will\
    \ generate a new message for you to publish to your robot. "
