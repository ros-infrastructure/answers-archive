  body_markdown: "There are currently a few options for doing Visual SLAM using ROS\
    \ (in no particular order):\n\n - [viso2_ros](http://www.ros.org/wiki/viso2_ros)\
    \ is a ROS wrapper for a visual    odometry package developed at KIT, some people\
    \ had good results with this. Also can be combined with [cyphy_vis_slam](http://www.ros.org/wiki/cyphy_vis_slam)\
    \ for a full blown SLAM system including graph optimization. The latter is currently\
    \ in ongoing development from what I understand.\n   \n - [RGB-D SLAM](http://www.ros.org/wiki/rgbdslam)\
    \ performs SLAM using a handheld Kinect and also is used by quite a few people\
    \ with success.\n\n   \n\n - [ethzasl_ptam](http://www.ros.org/wiki/ethzasl_ptam)\
    \ is an adapted version of the original [PTAM](http://www.robots.ox.ac.uk/~gk/PTAM/)\
    \ for the use with ROS and on computationally constrained quadrotor MAVs. I already\
    \ used this on a simulated quadrotor in gazebo with good success.\n\n   \n\n -\
    \ [vslam](http://www.ros.org/wiki/vslam) for ROS is a experimental VSLAM implementation\
    \ that hasn't received many updates lately, so not sure if it will work with current\
    \ ROS versions.\n\nThere are also promising approaches like [ScaViSLAM](http://www.ros.org/wiki/ScaViSLAM)\
    \ or the [PCL Kinect Fusion clone](http://pointclouds.org/news/kinectfusion-open-source.html),\
    \ but these do not work with ROS out of the box AFAIK.\n\nAs for your question\
    \ about Kalman Filter based vision based SLAM: Here's a [pretty good paper](http://www.doc.ic.ac.uk/~ajd/Publications/strasdat_etal_ivc2012.pdf)\
    \ about why (Kalman) filtering isn't necessarily the best option."
