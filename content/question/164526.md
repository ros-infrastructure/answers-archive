  body_markdown: "We don\xB4t use the 2D GetDistanceToObstacle service from hector_map_server\
    \ anymore, so that\xB4s the reason why we haven\xB4t experienced this issue. You\
    \ can:\n\neither remap the `/hector_map_server/get_distance_to_obstacle` service\
    \ to just `/get_distance_to_obstacle`\n\nor\n\n you can explicitly specify the\
    \ service to use for each object class you track in your object tracker setup.\
    \ Looking [at the parameter code](https://github.com/tu-darmstadt-ros-pkg/hector_worldmodel/blob/catkin/hector_object_tracker/src/parameters.cpp#L107),\
    \ changing the [launch file](https://github.com/tu-darmstadt-ros-pkg/hector_worldmodel/blob/catkin/hector_object_tracker/launch/object_tracker.launch)\
    \ and adding this line:\n\n    victim:\n      pending_support: 1.0\n      active_support:\
    \ 10.0\n      min_height: -0.5\n      max_height: 0.15\n      marker_color: [0.8,\
    \ 0.0, 0.0]\n      distance_to_obstacle_service: /hector_map_server/get_distance_to_obstacle\n\
    \nshould also make the service connect correctly. Note I don\xB4t have time to\
    \ try this myself, but I\xB4m 90% positive both options should work ;)"
