Basically I am asking what is the best practice to merge ros1 topics from different robots each running its own ros1 master into a single ros2 instance.
All topics from each robot shall be bidirectionally mapped to and from ros2 using the robot name in the ros2 topic, like this: "<ROBOT1>/<ROS1_TOPIC>".

Is this possible using a single build of the ros1_bridge?
I would love the possibility to simply start the  node `ros1_bridge` multiple times with command-line parameters:

    ros2 run ros1_bridge dynamic_bridge --bridge-all-topics <ROS_MASTER_URI1> <mapping_config1>
    ros2 run ros1_bridge dynamic_bridge --bridge-all-topics <ROS_MASTER_URI2> <mapping_config2>

Unfortunately, a lot of configuration of ros1_bridge seems to be controlled using environment variables and global configuration files.
Any advice on this is appreciated.
