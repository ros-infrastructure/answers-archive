  body_markdown: "> Is there a reason this occurs \n\nROS1 / `catkin_make` uses `python-catkin-pkg`\
    \ to parse `package.xml`.\nIn ROS2 / `colcon` `python3-catkin-pkg` is used.\n\n\
    These 2 [packages conflict](https://github.com/ros-infrastructure/rosdep/blob/2977726b32f57205ac0985ce9eb8f44e5dbbe8bf/stdeb.cfg#L10-L11)\
    \ as they install the same scripts.\nThe libraries can be installed side by side\
    \ since some modules packages have been created:\n`python3-catkin-pkg-modules`\
    \ and `python-catkin-pkg`: https://github.com/ros-infrastructure/catkin_pkg/pull/157\n\
    \n> is it possible to install a ROS1 distro without removing python3-catkin-pkg\n\
    \nNot that I know of, as these packages conflict.\nOn the bright side I'd expect\
    \ most of these packages to be reinstalled in their python2 variant along with\
    \ ROS1.\nYou'll just end up with the python2 version of the executables instead\
    \ of the python3 one.\nIf I were you I would just run that install and then reinstall\
    \ the uninstalled modules like `python3-rosdep-modules`\n\n\nA better long term\
    \ resolution would be for packages that use the python modules but not the scripts\
    \ to declare their dependencies on `python(3)-pkg-name-modules` instead of `python(3)-pkg-name`."

I am attempting to build a ROS2 package that uses ROS1 bridge ([rosbag2_bag_v2](https://github.com/ros2/rosbag2_bag_v2)) in a GitHub Actions CI pipeline. I am able to install the dependencies for ROS1 which include `python3-catkin-pkg`. However, when I run `apt-get install ros-melodic-desktop`, it automatically removes `python3-catkin-pkg`:

```
The following packages will be REMOVED:
python3-catkin-pkg python3-rosdep python3-rosdep-modules python3-rosdistro
python3-rospkg
```

Is there a reason this occurs and is it possible to install a ROS1 distro without removing `python3-catkin-pkg`
