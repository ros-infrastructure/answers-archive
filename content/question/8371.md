    For gazebo5, we decided to add Coulomb joint friction using the ODE joint motors (see [pull request 1218](https://bitbucket.org/osrf/gazebo/pull-request/1218/change-behavior-of-odejoint-setvelocity/diff#chg-gazebo/physics/Joint.cc) and [pull request 1221](https://bitbucket.org/osrf/gazebo/pull-request/1221/implement-coulomb-joint-friction-for-ode/diff#chg-gazebo/physics/ode/ODEJoint.cc)). This raised a conflict with the `SetVelocity` and `SetMaxForce` API, which was also using the ODE joint motors. However, not all physics engines have joint motors (such as simbody), so we changed the meaning of `SetVelocity` to refer to setting the velocity state (like an initial condition), but not turning on a persistent motor controller.

    The ODE joint motors are still available using the `Joint::SetParam` API:

    <pre><code>
    joint->SetVelocity(index, velocity);
    // becomes
    joint->SetParam("vel", index, velocity);
    </code></pre>

    and

    <pre><code>
    joint->SetMaxForce(index, maxForce);
    // becomes
    joint->SetParam("max_force", index, maxForce);
    </code></pre>

    I had also changed the behavior of the some of the gazebo plugins, which was probably a bad idea. I've restored their functionality in [branch restore\_max\_force5](https://bitbucket.org/osrf/gazebo/commits/0a08678cadde3fc3594fcdef777df8ea9b12c29c). I'm guessing gazebo\_ros\_pkgs might need to be updated too.

    Let me know if this is helping. If so, I'll make a `gazebo_ros_pkgs` pull request.
