  body_markdown: "Yes, you can have many publishers and subscribers at the same time\
    \ -- the current implementation supports up to 25 of each on the Arduino (you'll\
    \ probably run out of bandwidth before you hit that though).\n\nThe following\
    \ can be found under ros_lib/examples folder as float64_test.pde:\n\n    /* \n\
    \     * rosserial::std_msgs::Float64 Test\n     * Receives a Float64 input, subtracts\
    \ 1.0, and publishes it\n     */\n    \n    #include <ros.h>\n    #include <std_msgs/Float64.h>\n\
    \    \n    float x; \n    \n    ros::NodeHandle nh;\n    \n    ROS_CALLBACK(messageCb,\
    \ std_msgs::Float64, msg)\n      x = msg.data - 1.0;\n      digitalWrite(13, HIGH-digitalRead(13));\
    \   // blink the led\n    }\n    \n    std_msgs::Float64 test;\n    ros::Subscriber\
    \ s(\"your_topic\", &msg, &messageCb);\n    ros::Publisher p(\"my_topic\", &test);\n\
    \    \n    void setup()\n    {\n      pinMode(13, OUTPUT);\n      nh.initNode();\n\
    \      nh.advertise(p);\n      nh.subscribe(s);\n    }\n    \n    void loop()\n\
    \    {\n      test.data = x;\n      p.publish( &test );\n      nh.spinOnce();\n\
    \      delay(10);\n    }\n\nHere we subscribe to \"your_topic\", and publish to\
    \ \"my_topic\". The publisher publishes at ~100hz, and the value is always the\
    \ last message received - 1.0. \n"
