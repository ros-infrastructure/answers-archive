  body_markdown: "Hi, I have been playing around with the laser_assembler package\
    \ and managed to make it work for assembling several laser scans into a single\
    \ point cloud, and publish that point cloud on a topic.\n\nWhat I have done is\
    \ the following:\n\n 1. I create a package that will\n    handle all the logic\n\
    \ 2. On the\n    launch file of that package, I\n    launch the laser_assembler\
    \ properly\n    configured and my own node\n 3. My\n    node subscribes to the\
    \ service of\n    the laser_assembler that provides\n    point clouds\n 4. Then\
    \ it calls the\n    service, gets the response, and then\n    publishes on a topic\
    \ as a single\n    PointCloud2 message\n\nHow to do it ===========\n\nUsing Python\
    \ to do the conversion simplifies a lot. Let's see how to do that using the laser_geometry\
    \ package.\n\nFirst, you need to launch the laser_geometry package from a launch\
    \ file, properly configured. Here a suggested launch file:\n\n    <launch>\n \
    \   <node type=\"laser_scan_assembler\" pkg=\"laser_assembler\"\n        name=\"\
    my_assembler\">\n    <remap from=\"scan\" to=\"laser_scan\"/>\n    <param name=\"\
    max_scans\" type=\"int\" value=\"400\" />\n    <param name=\"fixed_frame\" type=\"\
    string\" value=\"my_robot_link_base\" />\n     </node>\n      <node type =\"laser2pc.py\"\
    \ pkg=\"laser_to_pcl\" name=\"laser2pc\"/>\n    </launch>\n\nThat file launches\
    \ the laser_geometry package indicating that the frame from which the transform\
    \ will be done is the my_robot_link_base (that is whatever tf link of your robot\
    \ you want the point cloud to be refered from). Another parameter is the max_scans\
    \ which indicates the max number of last scans that will be take into account\
    \ for the computation of the point cloud ( this is useful in case your laser is\
    \ rotating, so you can generate a full 3D cloud).\n\nThe launch file above also\
    \ launches a second node that is the one you have to create to get the data and\
    \ publish it into your selected topic. What should be the code of such a node?\
    \ Check the following:\n\n    #!/usr/bin/env python\n\n    import rospy \n   \
    \ from laser_assembler.srv import AssembleScans2\n    from sensor_msgs.msg import\
    \ PointCloud2\n\n    rospy.init_node(\"assemble_scans_to_cloud\")\n    rospy.wait_for_service(\"\
    assemble_scans2\")\n    assemble_scans = rospy.ServiceProxy('assemble_scans2',\
    \ AssembleScans2)\n    pub = rospy.Publisher (\"/laser_pointcloud\", PointCloud2,\
    \ queue_size=1)\n\n    r = rospy.Rate (1)\n\n    while (True):\n        try:\n\
    \            resp = assemble_scans(rospy.Time(0,0), rospy.get_rostime())\n   \
    \         print \"Got cloud with %u points\" % len(resp.cloud.data)\n        \
    \    pub.publish (resp.cloud)\n\n        except rospy.ServiceException, e:\n \
    \           print \"Service call failed: %s\"%e\n\n        r.sleep()\n\nThe code\
    \ shows how to subscribe to the assemble_scans2 service. That is the one that\
    \ will provide the point cloud on its answer. The code also shows that the point\
    \ cloud will be published on a topic of type PoinCloud2. basically, the while\
    \ loop what it does is, first, call to the service, then publish the answer of\
    \ the service into a topic.\n\nI have created a video describing step by step\
    \ and code solution. In case you are interested, [you can find it here](http://www.theconstructsim.com/merge-laser-scans-single-pointcloud/)"
