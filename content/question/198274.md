    \n**EDIT**\n\nEditing since the original question changed. I tried the following:\n\
    \n    >> rosparam set /test/m '{\"id0\":0, \"id1\":1}'    \n    >> rosparam get\
    \ /          \n         test:   \n          m: {id0: 0, id1: 1}\n    >> rosparam\
    \ get /test/m\n         {id0: 0, id1: 1}\n    >> rosparam get /test/m/id0\n  \
    \       0\n    >> rosparam get /test/m/id1\n         1\n\nThis is explained in\
    \ http://wiki.ros.org/rosparam#rosparam_set, and it basically means that when\
    \ you give a YAML string to rosparam set, it gets converted in a dictionary of\
    \ parameters. You can see this behaviour if you do:\n\n    >> rosparam set -v\
    \ /test/m '{\"id0\":0, \"id1\":1}'\n    set parameter [/test/m/id0] to [0]\n \
    \   set parameter [/test/m/id1] to [1]\n\nTherefore the parameter you are looking\
    \ for in your code (/test//m) doesn't exist as a string, but it's a dictionary!\
    \ If you want to set a parameter to a string representing a YAML line, you can\
    \ do something like:\n\n    >> rosparam set -v /test/m \"\\\"{'id0':0, 'id1':1}\\\
    \"\"\n    set parameter [/test/m] to [{'id0':0, 'id1':1}]\n\nEven though it looks\

    I've modified my question to match the real problem and answer to it. Reading a yamlis quite heavy in C++, here's a way to read a map of arrays for instance:

                        XmlRpc::XmlRpcValue symbols;

                        if(!ros::param::get("/thr/symbols", symbols))
                            ROS_ERROR("Failed to read symbols on param server");

                        ROS_ASSERT(symbols.getType()==XmlRpc::XmlRpcValue::TypeStruct);
                        for (XmlRpc::XmlRpcValue::iterator i=symbols.begin(); i!=symbols.end(); ++i) {
                            ROS_ASSERT(i->second.getType()==XmlRpc::XmlRpcValue::TypeArray);
                            for(int j=0; j<i->second.size(); ++j) {
                                ROS_ASSERT(i->second[j].getType()==XmlRpc::XmlRpcValue::TypeDouble);
                            }
                        }
