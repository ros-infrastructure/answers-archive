  body_markdown: "One temporary workaround is:\n\n 1. Right click in Clion on the\
    \ specific include folder of the ROS package you are working with (for example\
    \ if you're working with 'eigen_conversions', then right click on the folder include/eigen_conversions\
    \ )\n 2. Then click \"Mark Directory as\" -> \"Library Files\" \n\nNow the files\
    \ should be correctly seen by Clion and you can switch between definition and\
    \ implementation."

When I use CLion on a ROS project, I get the following banner when looking at .h files: `This file does not belong to any project target, code insight features might not work properly.` Any insight?

To reproduce:

    mkdir -p ~/catkin_ws/src
    cd catkin_ws
    catkin_make
    source devel/setup.bash
    cd src
    git clone https://github.com/ros/geometry.git # Can be anything
    cd ..
    catkin_make
    ~/clion-2017.2.3/bin/clion.sh src/CMakeLists.txt

Then open any .h file to see the banner. Code completion works fine in .cpp files.
