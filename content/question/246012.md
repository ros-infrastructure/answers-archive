  body_markdown: "Update 2020-09-08: please note the answer below was written in 2016,\
    \ before \"modern CMake\" really became a thing.\n\nThese days, while the ideas\
    \ are similar, you'd probably use `target_link_libraries(..)` with a properly\
    \ setup and exported (`INTERFACE`) target or an `IMPORTED` library and other targets.\n\
    \nYou could still use those with `target_link_libraries(..)` as below, but writing\
    \ a `Find*.cmake` script may not be the go-to approach any more these days.\n\n\
    ---\n\nIn a nutshell:\n\n 1. install your third-party library as you would normally\
    \ do this (ie: to `/usr/local` or some other location)\n 1. either write a CMake\
    \ `FindYourLibrary.cmake` script (the correct way), or hard-code locations of\
    \ libraries and header files in CMake variables (ie: `lanelet_LIBRARIES`, `lanelet_INCLUDE_DIRS`,\
    \ etc)\n 1. now use those as you would any other CMake compatible library:\n\n\
    \        include_directories(\n          [..]\n          ${lanelet_INCLUDE_DIRS}\n\
    \          [..]\n        )\n\n        target_link_libraries(node\n          ${catkin_LIBRARIES}\n\
    \          [..]\n          ${lanelet_LIBRARIES}\n          [..]\n        )\n\n\
    So:\n\n> Should I add all the headers to the include_directories() macro in the\
    \ CMakeLists? \n\nNo, you should only use `include_directories(..)` to tell CMake\
    \ which *path* it should add to the compiler's include search path (see above).\n\
    \n> Should I copy all .hpp files inside, say, \"package_path/include\" and then\
    \ in the CMakeLists add \n\nNo, unless you want to create a wrapper package for\
    \ the library. As I wrote above: install the library \"system-wide\" as you would\
    \ normally do, and make your Catkin package (really: CMake) find it using the\
    \ normal means.\n\n> I have just started to \"get my hands dirty\" writing ROS\
    \ code and I recently started learning C++, so many concepts are still unclear\
    \ to me.\n\nThen please understand that Catkin is basically a bunch of CMake macros\
    \ and functions that make it easier to work with in a ROS context, but that it\
    \ is really CMake doing all the work. Whenever you think you should search for\
    \ \"how does catkin do ..\", first try \"how does cmake do ..\", especially when\
    \ dealing with headers, libraries and finding dependencies.\n\nAlso: check out\
    \ the [catkin documentation](http://docs.ros.org/indigo/api/catkin/html/), especially\
    \ the [How to do common tasks](http://docs.ros.org/indigo/api/catkin/html/howto/format2/index.html)."
