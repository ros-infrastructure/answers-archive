  body_markdown: "This does not seem to be the case.  `setModelState` calls [`Entity::SetWorldPose`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/Entity.cc#L482)\
    \ which calls [`Entity::SetWorldPoseModel`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/Entity.cc#L297)\
    \ which calls [`Entity::PublishPose`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/Entity.cc#L228)\
    \ which calls [`World::PublishModelPose`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/World.cc#L2908)\
    \ which only queues up the requested change in the model.  \n\nThe actual change\
    \ is applied in [`World::Step`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/World.cc#L685)\
    \ which calls [`World::ProcessMessages`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/World.cc#L2700)\
    \ where the requested changes is propagated to the rendering scene via [`updateScenePose`](https://github.com/osrf/gazebo/blob/gazebo11/gazebo/physics/World.cc#L2779).\n\
    \nIn my case, my sensor (Gpu Laser) uses the rendering `Scene` for updates.  Hence\
    \ it cannot be guaranteed that the scene is updated when `setModelState` returns.\
    \  Instead, one needs to wait for the next `World::Step` call.  This may also\
    \ explain why my waits seem to stop working when my computer is heavily loaded."

title: Does setModelState block such that the next sensor readings account for the
  modified scene?
upvote_count: 1
---
I am running a simulation involving many different configurations of a large number of objects.  For each "cycle", I read the required object configuration and move the objects in the scene via the `/setModelState` ROS service.  I wait (using simulated time) for what is equivalent to the sensor's publish rate (to make sure I receive the sensor measurements after moving the objects)

I am trying to track down a bug where my sensors in the scene occasionally don't register the new object positions.  This does not happen every time, and the probability of it happening seems to decrease as I increase the wait time between moving the objects and getting the sensor readings.

To help narrow down the possibilities, I'd like to know if `setModelState` block (or stop time) until the next sensor readings.  I.e. once `setModelState` returns, is it guaranteed that the next reading returned by the sensor uses the updated scene?
