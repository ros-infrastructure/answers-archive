  body_markdown: " I've found a way and tested it in ROS-Indigo:\n\n 1. The Problem:\n\
    \n   the  [`<node>`](http://wiki.ros.org/roslaunch/XML/node)-tag contains an attribute\
    \ `machine` to set the machine on wich the node should run.\n\n  If you want to\
    \ include a launch-file with the [` <include>`](http://wiki.ros.org/roslaunch/XML/include)-tag\
    \ and in this launchfile are some  [`<node>`](http://wiki.ros.org/roslaunch/XML/node)-tags,\
    \ include didn't provide a machine-Attribute for easy passing this information\
    \ -> so  normally only static launchfiles are possible.\n \n 2. **Solution**\n\
    \n\n Pass the machine with an [argument](http://wiki.ros.org/roslaunch/XML/arg)\
    \ through the \n[` <include>`](http://wiki.ros.org/roslaunch/XML/include)-tag!\n\
    \n\nHere my version:\n\n\n    <include file=/path/to/my/launchfile.launch>\n \
    \         <arg name=\"machine\" value=\"the_machine\" />\n     </include>\n\n\
    \  and here the launchfile.launch:\n\n    <launch>\n     <arg name=\"machine\"\
    \ /> \t\n     <node pkg=\"mypkg\" name=\"mypkgname\" machine=\"$(arg machine)\"\
    >\n    </node>\n    </launch>\n\nArguments are discribed [here](http://wiki.ros.org/roslaunch/XML/arg)\n\
    \n\n\n"

  body_markdown: "If anyone is still looking for an answer, I think currently the\
    \ most elegant solution is: \n\n    <launch>\n            <include file=\"local_nodes.launch\"\
    \ />\n    \n            <group>\n                <machine name=\"remote_machine\"\
    \ address=\"1.2.3.4\" default=\"true\" />\n                <include file=\"remote_nodes.launch\"\
    \ />\n            </group>\n    </launch>\n\nTested with ROS Kinectic on Ubuntu\
    \ 16.04. \n\nEdit:\nApparently the machine tag doesn't apply to a specific group,\
    \ but to any nodes/includes that come after it. So the order in which the tags\
    \ are defined is important!"
