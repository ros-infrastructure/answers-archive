    \ file using the ExecuteProcess launch action. There are several problems you're\
    \ going to face if you go this way, so here are the workarounds I used to solve\
    \ them (on Ubuntu 20.04).\n\nFirst, let's state what we are trying to achieve:\n\
    \n 1. We have a main **machine A** and a **machine B** reachable via `ssh pi@192.168.0.20`\
    \ from **machine A** (without a password, i.e. use `ssh-keygen -t rsa -b 2048\
    \ && ssh-copy-id pi@192.168.0.20` first)\n 2. We have a launch file `drinks_hmi_launch.py`\
    \ in `drinks_hmi_bringup` package on **machine B** (we can launch it from machine\
    \ B via `ros2 launch drinks_hmi_bringup drinks_hmi_launch.py`)\n 3. We have a\
    \ launch file `drinks_bringup_launch.py` in `drinks_bringup` package on **machine\
    \ A** which is supposed (among other actions) to launch `drinks_hmi_launch.py`\
    \ on **machine B**\n\nNow the following command should work from **machine A**,\
    \ i.e. it launches the nodes, prints out output and can be terminated via SIGINT\
    \ (Ctrl+C):\n\n    ssh -t pi@192.168.0.20 'bash -i -c \"ros2 launch drinks_hmi_bringup\
    \ drinks_hmi_launch.py\"'\n\nHowever, after putting it directly into `ExecuteProcess`\
    \ action in `drinks_bringup_launch.py`, the process complains about not having\
    \ a proper `tty` console and the nodes on **machine B** are not terminated after\
    \ terminating the `ros2 launch drinks_bringup drinks_bringup_launch.py` process.\n\
    \nA workaround is to call the above command inside a detached `screen` (use `sudo\
    \ apt install screen` if not present). This, however, raises two further problems:\n\
    \n - The `screen` does not pass SIGINT from calling process to inner processes,\
    \ so it does not terminate the nodes when Ctrl+C is pressed. However it can be\
    \ terminated explicitly using a `remote_launch_terminator` node which calls `screen\
    \ -S hmi -X quit` (see the complete solution below)\n - The `screen` does not\
    \ pass output from inner processes to calling process, so this needs to be done\
    \ explicitly by redirecting inner output to [outer](https://stackoverflow.com/a/40270593/4003774)\n\
    \n**The complete solution is as follows:**\n\n`/home/machine_A/drink_ws/src/launch_utils/launch_utils/remote_launch_terminator.py`:\n\
    \n    import rclpy\n    from rclpy.node import Node\n    import os\n    \n   \
    \ def main(args=None):\n        rclpy.init(args=args)\n    \n        node = Node('remote_launch_terminator')\n\
    \        node.declare_parameter('screen_pid', 'remote')\n        screen_pid =\
    \ node.get_parameter('screen_pid').get_parameter_value().string_value\n    \n\
    \        try:\n            rclpy.spin(node)\n        except:\n            pass\n\
    \    \n        print('Terminating ' + screen_pid)\n        os.system('screen -S\
    \ ' + screen_pid + ' -X quit')\n    \n    if __name__ == '__main__':\n       \
    \ main()\n\n`/home/machine_A/drink_ws/src/drinks_bringup/launch/drinks_bringup_launch.py`:\n\
    \n    import os\n    \n    from ament_index_python.packages import get_package_share_directory\n\
    \    \n    from launch import LaunchDescription\n    from launch_ros.actions import\
    \ Node\n    from launch.actions.execute_process import ExecuteProcess\n    \n\
    \    def generate_launch_description():\n        return LaunchDescription([\n\
    \            \n            # other actions\n            \n            # remote\
    \ launch\n            ExecuteProcess(\n                name='hmi',\n         \
    \       cmd=['{ outer_stdout=$(readlink -f /proc/self/fd/3); } 3>&1 && screen\
    \ -DmS hmi bash -i -c \"ssh -t pi@192.168.0.20 \\'bash -i -c \\\\\"ros2 launch\
    \ drinks_hmi_bringup drinks_hmi_launch.py\\\\\"\\' > $outer_stdout\"'],\n    \
    \            output=\"screen\",\n                shell=True,\n               \
    \ emulate_tty=True\n            ),\n            Node(\n                package='launch_utils',\n\
    \                executable='remote_launch_terminator',\n                name='remote_launch_terminator',\n\
    \                output='screen',\n                parameters=[{'screen_pid':\
    \ 'hmi'}]\n            ),\n        ])\n\nHope this helps, cheers! ;)\n\nNote:\
    \ `ExecuteProcess` action does not work inside `OnShutdown` event, that's why\
    \ the `remote_launch_terminator` must be used"

    \ **systemd**. Basically do the following:\n\nOn the target machine, the machine\
    \ you want to run remote nodes on, do the following:\n\n1. Make sure the nodes\
    \ you want to run are on the remote machine already and it's already built on\
    \ that machine.\n1. Make a bash script that executes ros2 launch and sources the\
    \ right install directory. We'll call this remote_ros.sh. This is a script because\
    \ you might want to do other things with this.\n1. Make a remote_ros.service file\
    \ that runs the remote_ros.sh script. This can be setup to start on boot or not.\n\
    \nOn the local machine, the machine you want to launch remote nodes on, do the\
    \ following:\n\n1. Make a launch script that SSHes into the remote machine and\
    \ executes `systemctl stop remote_ros` and/or `systemctl start remote_ros`. This\
    \ can be done with the ExecuteProcess launch action. \n\nStop will kill the nodes\
    \ and start will bring them up. If you don't want to stop the nodes, I believe\
    \ start is a NOOP if they are already running.\n\nI think this solution is more\
    \ straight forward than the others presented and ideally the service just runs\
    \ all the time, but you can always kill it with the systemctl stop command."
