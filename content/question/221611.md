  body_markdown: " In fact it is up to you to use [xacro](http://wiki.ros.org/xacro).\
    \ You do not have to, but especially if you have a large URDF and possible duplicate\
    \ codes it will be beneficial.\n\nxacro provides you some advantages with URDF.\
    \ As [the tutorial you linked](http://wiki.ros.org/urdf/Tutorials/Using%20Xacro%20to%20Clean%20Up%20a%20URDF%20File)\
    \ points,\n\n> It does three things that are very\n> helpful.\n\n> - Constants\n\
    > - Simple Math\n> - Macros\n\nThis way you can use constants throughout your\
    \ URDF, therefore it will be more parametrized;\n\n    <xacro:property name=\"\
    width\" value=\".2\" />\n\n Also you can do some simple math like; \n\n    <cylinder\
    \ radius=\"${wheeldiam/2}\" length=\".1\"/>\n\nAnd you can use macros like;\n\n\
    \    <xacro:macro name=\"default_origin\">\n        <origin xyz=\"0 0 0\" rpy=\"\
    0 0 0\"/>\n    </xacro:macro>\n    <xacro:default_origin />\n\nFor example in\
    \ your case, you say that you have 3 laser range finders. Therefore, possibly\
    \ without xacro, you are using same code block again and again with some little\
    \ differences like x,y,z and r,p,y. If you use xacro at this point, you can have\
    \ a macro called \"laser_scanner\" and you can just use it three times when you\
    \ need it.\n\nYou can check PAL's repo for PMB2 [in this link](https://github.com/pal-robotics/pmb2_robot/tree/indigo-devel/pmb2_description)\
    \ for such an example. \n\nAnother advantage of using xacro is that it will be\
    \ interpreted and converted to URDF on run-time if you want. Therefore it will\
    \ be a dynamic URDF file. "
