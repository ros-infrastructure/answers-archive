  body_markdown: "My recommendation is to use existing tools: If you want to reuse\
    \ the data with a ROS node, record a bagfile, e.g.:\n\n    rosbag record -o kinect-data\
    \ /tf /the-rgb-image-topic /the-depth-image-topic /the-camera-info-topic \n\n\
    If you want the raw images, use image_saver from the [image_view](http://wiki.ros.org/image_view)\
    \ package:\n\n    rosrun image_view image_saver image:=/the-rgb-image-topic &\n\
    \    rosrun image_view image_saver image:=/the-depth-image-topic\n\n\nIf you still\
    \ want to do it from your code, maybe because you need to be absolutely sure you\
    \ get every frame, you can use the sequence number of the message to check whether\
    \ you lost something. It's some integer you can access via `msg->header->seq`.\
    \ It should always increase by one.\n\nAlso have a look at the [approximate time\
    \ synchronizing message filter](http://wiki.ros.org/message_filters#ApproximateTime_Policy),\
    \ which can help you get associated rgb and depth in a single callback.\n\nYou\
    \ will record with 30Hz if your machine is fast enough. If not, there are few\
    \ things you can do.\n\nP.S: Just some general C++ advise: Don't use global variables\
    \ if you can avoid it. Static variables within the callback functions would make\
    \ more sense here."
