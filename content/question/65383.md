    ## Solution 1 ##\n\nHey, sorry for the delay. I am quite new to Gazebo and ROS,\
    \ so take everything I say with a grain of salt. The following makes sense in\
    \ my head, but I might be terribly wrong about some things. Nevertheless, it solved\

    \ similar to this one to compile your plugin into a .so file.\n\n<pre>\ncmake_minimum_required(VERSION\
    \ 2.8 FATAL_ERROR)\n\ninclude (FindPkgConfig)\nif (PKG_CONFIG_FOUND)\n  pkg_check_modules(GAZEBO\
    \ gazebo)\nendif()\n\ninclude_directories(${GAZEBO_INCLUDE_DIRS})\nlink_directories(${GAZEBO_LIBRARY_DIRS})\n\
    \nadd_library(example SHARED example.cc)\ntarget_link_libraries(example ${GAZEBO_libraries})\n\
    </pre>\n\nThe first thing I did, to solve the missing header files, was to change\
    \ the sixth and the last lines to the following.\n\n<pre>\ninclude_directories(${GAZEBO_INCLUDE_DIRS}\
    \ /path/to/ROS/include/folder)\n\t\ntarget_link_libraries(example ${GAZEBO_libraries}\
    \ ${LD_LIBRARY_PATH})\n</pre>\n\nNotice you should change /path/to/ROS/include/folder\
    \ to the correct path to your ROS include folder. In my system, the path is /opt/ros/fuerte/include/\n\
    \nNow, if you run the CMake script, the compiler should find the header files\
    \ and compile everything without problems. But, if you're using functions that\
    \ are defined in the example_package package, when you run the Gazebo plugin,\
    \ you will probably get an error saying something like \"undefined symbol\". This\
    \ is because the linker doesn't know where the code of the functions is.\n\nThe\
    \ problem here is that this code is defined in the example_package package, and\
    \ I don't know how to link a program with a ROS package. Luckily, I found the\
    \ following CMake script, which, when included in your original CMake script allows\
    \ you to do just that. Get the script from \n<blockquote> github.com/jrl-umi3218/jrl-cmakemodules\
    \ </blockquote>\n(sorry, not enough Karma to post a link).\n\nPut the script in\
    \ the same directory as your original CMake script. Now, change your script to\
    \ the following.\n\n<pre>\ncmake_minimum_required(VERSION 2.8 FATAL_ERROR)\n\n\
    include (FindPkgConfig)\nif (PKG_CONFIG_FOUND)\n  pkg_check_modules(GAZEBO gazebo)\n\
    endif()\n\ninclude (downloaded_script_name)\nADD_ROSPACK_DEPENDENCY(example_package)\n\
    \ninclude_directories(${GAZEBO_INCLUDE_DIRS} /path/to/ROS/include/folder)\nlink_directories(${GAZEBO_LIBRARY_DIRS}\
    \ ${LD_LIBRARY_PATH})\n\nadd_library(example SHARED example.cc)\nROSPACK_USE_DEPENDENCY(mrl_impep_plugin\
    \ example_package)\ntarget_link_libraries(example ${GAZEBO_libraries} ${LD_LIBRARY_PATH})\n\
    </pre>\n\nYou should change \"downloaded_script_name\" to the name you gave to\
    \ the downloaded CMake script.\n\nI had to comment lines 41 and 42 of the downloaded\
    \ CMake script, as they use undefined macros. If you have this problem, comment\
    \ the lines. Now everything should compile and link correctly, which means your\
    \ Gazebo plugin should run fine."
