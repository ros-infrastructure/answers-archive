  body_markdown: "Quoting [tf - ROS](http://wiki.ros.org/tf#static_transform_publisher),\n\
    \n> static_transform_publisher x y z yaw\n> pitch roll frame_id child_frame_id\n\
    > period_in_ms\n> \n> Publish a static coordinate transform\n> to tf using an\
    \ x/y/z offset in meters\n> and yaw/pitch/roll in radians. (yaw is\n> rotation\
    \ about Z, pitch is rotation\n> about Y, and roll is rotation about\n> X). The\
    \ period, in milliseconds,\n> specifies how often to send a\n> transform. 100ms\
    \ (10hz) is a good\n> value. \n\n> static_transform_publisher x y\n> z qx qy qz\
    \ qw frame_id child_frame_id \n> period_in_ms\n> \n> Publish a static coordinate\
    \ transform\n> to tf using an x/y/z offset in meters\n> and quaternion. The period,\
    \ in\n> milliseconds, specifies how often to\n> send a transform. 100ms (10hz)\
    \ is a\n> good value.\n\nTo answer your question : The coordinate systems of your\
    \ camera and base link are different. Each camera image needs to be transformed\
    \ into the global coordinate system. This transformation happens via the base_link\
    \ frame. If you run \n\n    rosrun tf view_frames\n\nyou will see the frames in\
    \ your system.\n\nTo set the arg values properly, identify your base_link coordinate\
    \ system origin and the camera coordinate system origin, measure the transformation\
    \ and rotation between the two systems and update x,y,z, roll, pitch, yaw accordingly."
