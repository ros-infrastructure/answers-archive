    \ client** built-in. Then, in a different node you implement a **service server**\
    \ which is responsible for calculating the path each time it gets a service request.\
    \  \n\nROS Services are explained [Here](http://wiki.ros.org/ROS/Tutorials/WritingServiceClient%28c%2B%2B%29)\
    \  \n\nThis is how to add a service client to the code shown by the [Writing A\
    \ Global Path Planner As Plugin in ROS](http://wiki.ros.org/navigation/Tutorials/Writing%20A%20Global%20Path%20Planner%20As%20Plugin%20in%20ROS)\
    \ tutorial:  \n\n**Class Header**  \n\n     //  SOME OTHER INCLUDE STATEMENTS\n\
    \     #include \"***YOUR MESSAGE TYPE HERE***\"\n        \n     namespace global_planner\
    \ {\n    \n     class GlobalPlanner : public nav_core::BaseGlobalPlanner {\n \
    \         public:\n            //  SOME CODE TO DECLARE PUBLIC MEMBERS\n     \
    \   \n          private :\n            //  SOME CODE TO DECLARE PRIVATE MEMBERS\n\
    \n            // service client declaration\n            ros::ServiceClient service_;\n\
    \      };\n    };\n\n**Class Implementation**  \n\n     void GlobalPlanner::initialize(std::string\
    \ name, costmap_2d::Costmap2DROS* costmap_ros){\n       //  OTHER INITIALIZATION\
    \ CODE\n\n       // create a client for the path planning service\n      service_\
    \ = private_nh.serviceClient<***YOUR MESSAGE TYPE HERE***>(\"plan\");\n\n    \
    \  // wait for the service to be advertised and available\n      service_.waitForExistence();\n\
    \     }\n\n\nthen send a service request from inside of the body of the function\
    \ `GlobalPlanner::makePlan()`, like so:\n\n       bool GlobalPlanner::makePlan(const\
    \ geometry_msgs::PoseStamped& start, const geometry_msgs::PoseStamped& goal, \
    \ std::vector<geometry_msgs::PoseStamped>& plan ){\n\n      // initialize a message\
    \ of your custom message type\n      **YOUR MESSAGE TYPE** message_name;\n\n \
    \      // CODE TO FILL IN YOUR CUSTOM MESSAGE\n\n      // call the path planning\
    \ service\n      service_.call(message_name);\n\n     // you must also process\
    \ the service response (not shown here)\n    }\n\nDon't forget to process the\
    \ service response and store it to the variable name `plan` which is one of the\
    \ parameters of the function  `GlobalPlanner::makePlan()`.  \n\nYou will also\
    \ have to modify your CMakeLists.txt file to include your custom message type.\
    \ All about how to create a custom service message is explained here:  [Creating\
    \ a ROS msg and srv tutorial](http://wiki.ros.org/ROS/Tutorials/CreatingMsgAndSrv)\n\
    \nNote that this is not a cut-and-paste ready-to-go example.  You will have to\
    \ additionally:  \n- **define a custom message**  \n- **create a service server**\
    \  \n- **fill in the service request**, and   \n- **process the service response**\
    \  \n\nHopefully this information is enough to get you started and that it also\
    \ answers your question."
