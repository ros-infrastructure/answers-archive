- body_markdown: "During a pointcloud generation there is a matching between the 2\
    \ images. On every step, every pixel (or set of pixels) from the left part are\
    \ searched a matching element in right image. The distance between theses 2 points\
    \ in the image is stored as depth and with this, a depth image is generated. From\
    \ here is where a pointcloud appears.\n\nUnderstanding this, you can imagine that\
    \ even with the best matching algorithm ever and with the best camera, always\
    \ will be sets of points that, by any reason, are notfound in one of both images\
    \ and this creates a hole. This hole can be represented by two ways in the pointcloud\
    \ :\n\n 1. removing it. \n 2. considering the point As NaN.\n\nThis is decided\
    \ with the optinon is_dense (True option 1, False 2)\n\nWhat i think is probably\
    \ happening you is that you are asking the pointcloud to be dense, this is the\
    \ reason why the size changes. If you use dense equals to false, pointcloud should\
    \ have the same size as the original image used."
