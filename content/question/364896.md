  body_markdown: "So to add more information to @tryan answer in which you can find\
    \ the know-how for doing this, I will post here a possible solution for your problem:\n\
    \nThe approach is to define two types of custom msgs:\n\n**The IMU data with a\
    \ key**\n\n    # Msg to contain IMU data and key (string)\n    \n    string  \
    \                key     # Key to map IMU data\n    sensor_msgs/Imu \t\tdata \t\
    # IMU data\n\n**Then the array to store those msgs:**\n\n    # Array of IMU mapped\
    \ msg\n    \n    imu_map[] \t\tdata\n\n**And use them as kind of \"map\":**\n\n\
    \    #include <ros/ros.h>\n    #include <test_pkg/custom_imu.h>\n    \n    int\
    \ main(int argc, char **argv)\n    {\n      ros::init(argc, argv, \"test_node\"\
    );\n    \n      ros::NodeHandle n;\n    \n      ros::Publisher imu_pub = n.advertise<test_pkg::custom_imu>(\"\
    test_node/imu_vector\", 1000);\n    \n      ros::Rate loop_rate(10);\n    \n \
    \     int count = 0;\n      test_pkg::custom_imu imu_vector;\n      while (ros::ok())\n\
    \      {\n        for(const auto &ii: {\"imu0\", \"imu1\", \"imu2\", \"imu3\"\
    , \"imu4\"})\n        {\n          test_pkg::imu_map imu_data;\n          imu_data.key\
    \ = ii;\n          imu_data.data = sensor_msgs::Imu(); //empty IMU msg\n    \n\
    \          imu_vector.data.push_back(imu_data);\n        }\n    \n        imu_pub.publish(imu_vector);\n\
    \    \n        ros::spinOnce();\n    \n        loop_rate.sleep();\n        ++count;\n\
    \      }\n      return 0;\n    }\n\nRemember to add the proper directive to the\
    \ `CMakeLists.txt`:\n\n    cmake_minimum_required(VERSION 3.0.2)\n    project(test_pkg)\n\
    \    \n    ## Find catkin macros and libraries\n    find_package(catkin REQUIRED\
    \ COMPONENTS\n      roscpp\n      std_msgs\n      sensor_msgs\n      message_generation\n\
    \    )\n    \n    ## Generate messages in the 'msg' folder\n    add_message_files(\n\
    \      FILES\n      imu_map.msg\n      custom_imu.msg\n    )\n    \n    ## Generate\
    \ added messages and services with any dependencies listed here\n    generate_messages(\n\
    \      DEPENDENCIES\n      std_msgs\n      sensor_msgs\n    )\n    \n    catkin_package(\n\
    \      CATKIN_DEPENDS roscpp message_runtime\n    )\n    \n    ###########\n \
    \   ## Build ##\n    ###########\n    \n    ## Specify additional locations of\
    \ header files\n    include_directories(\n      ${catkin_INCLUDE_DIRS}\n    )\n\
    \    \n    ## Declare a C++ executable\n    add_executable(test_node src/test_node.cpp)\n\
    \    \n    ## Add cmake target dependencies of the executable\n    add_dependencies(test_node\
    \ ${${PROJECT_NAME}_EXPORTED_TARGETS} ${catkin_EXPORTED_TARGETS})\n    \n    ##\
    \ Specify libraries to link a library or executable target against\n    target_link_libraries(test_node\
    \ ${catkin_LIBRARIES})\n\nHope that helps.\n\nRegards."

      This is a nice answer, except that I would not recommend using a custom message here. If `key` is supposed to encode from *which* IMU the data is coming, you should use the `header.frame_id` field for this.

      The use of the array here is also something to consider not doing, as it's perfectly OK to publish messages coming from multiple sources, or even multiple messages from a single source on a single topic.
