  body_markdown: "Rosinstall calls out to svn, git, bzr, or hg depending on what repositories\
    \ you are trying to pull down.  If you can make sure that those commands work,\
    \ then rosinstall should start working.  \n\nIf you can't get them to work using\
    \ the environment, another possibility is to setup a squid transparent proxy.\
    \  There are quite a few howtos if you [search google](https://www.google.com/search?q=squid+transparent+proxy)\n\
    \n\n----------\n\nA few notes, as I recently had to deal with this:\n\n**Git Proxies**\n\
    \nGit has it's own command line flag for proxies, and can be set by executing\
    \ the following:\n\n    git config --global http.proxy http://proxyuser:proxypwd@proxy.server.com:8080\n\
    \n**Subversion Proxies**\n\nSubversion's proxies can be set through the `~/.svn/servers`\
    \ file in the `[global]` section:\n\n    [global]\n    # http-proxy-exceptions\
    \ = *.exception.com, www.internal-site.org\n    http-proxy-host = proxy.server.com\n\
    \    http-proxy-port = 8080\n    # http-proxy-username = proxyuser\n    # http-proxy-password\
    \ = proxypwd\n\n**Wget Proxies**\n\nWget and curl both acknowledge the `http_proxy`,\
    \ `https_proxy`, and `ftp_proxy` that you mention above.\n\n**Mercurial Proxies**\n\
    \nMercurial should acknowledge the command line `http_proxy`, but if it doesn't,\
    \ you can always set up your hgrc file.\n\n[http_proxy]\nhost = proxy.server.com:8080\n\
    user = proxy user\npasswd = proxypwd\n\n**APT Proxies**\n\nApt should acknowledge\
    \ the command line `http_proxy`. \n\n**With SUDO**\n\nsudo will clear out your\
    \ proxy environment variables by default (meaning no proxy with any sudo'ed (sudid?)\
    \ commands).  To prevent this from happening, add the following to your `/etc/sudoers`\
    \ file:\n\n    Defaults env_keep = \"http_proxy https_proxy ftp_proxy\""
