  body_markdown: "The argument `pkg_arg` get substituted by the absolute path to the\
    \ package `my_pkg` which could for example be the string `/home/user/ros/my_pkg`.\
    \ Hence `rosbuild_add_roslaunch_check` could check the current ROS_PACKAGE_PATH\
    \ for the existence of this package and the file `included.launch` as roslaunch\
    \ does when executing. \nThe value for the argument is determined by the current\
    \ ROS_PACKAGE_PATH which can be checked offline in my opinion.\n\nBy the way,\
    \ the behaviour is the same as hardcoding the argument to point to `my_pkg`:\n\
    \n    <arg name=\"pkg_arg\" default=\"/home/user/ros/my_pkg\"/>\n\nSo why shouldn't\
    \ it be possible to check this?"
