    \ but with the rotation reported from the IMU.*\n\n Just use a static transform.\
    \ You don't need to constantly update the *base_link*->*imu* transform. If your\
    \ IMU is really mounted at the center of your robot, just use the tf2 (or tf)\
    \ `static_transform_publisher` and give it a transform of all zeros. \n\n 2. You\
    \ mis-spelled \"false\" in your odom0 configuration for yaw. You have:\n\n   \
    \     <rosparam param=\"odom0_config\">[false, false, false,\n               \
    \                         false, false, flase,\n                             \
    \           true,  true, false,\n                                        false,\
    \ false, true,\n                                        false, false, false]</rosparam>\n\
    \n You want:\n\n        <rosparam param=\"odom0_config\">[false, false, false,\n\
    \                                        false, false, false,\n              \
    \                          true,  true, false,\n                             \
    \           false, false, true,\n                                        false,\
    \ false, false]</rosparam>\n\n**EDIT in response to update:**\n\nIf no output\
    \ is being produced, then see my comment above about turning on debug mode. Right\
    \ now, I am actually suspecting an issue with the transforms. You have forward\
    \ slashes in the `frame_ids` in your messages, and you also put them in the configuration\
    \ for `ukf_localization_node`. This would normally be correct. However, `robot_localization`\
    \ uses `tf2`, and [we strip all forward slashes from the frame_ids](http://wiki.ros.org/tf2/Migration#Removal_of_support_for_tf_prefix)\
    \ to be compliant with it. In other words, you should do two things\n\n1. Remove\
    \ the forward slashes from the `frame_id`s in your messages.\n2. (Optional, but\
    \ you should do it anyway) Remove the forward slashes from the `frame_id`s in\
    \ your `ukf_localization_node` launch file.\n\nBy the way, if you're only fusing\
    \ velocities (like you are for *odom0*), then you don't need to turn on `relative`\
    \ mode. That's only for fusing absolute position or orientation data.\n\n**EDIT\
    \ in response to update 2:**\n\nAre you sure your IMU is outputting linear accelerations\
    \ correctly? See [this](http://wiki.ros.org/robot_localization/Tutorials/Preparing%20Your%20Sensor%20Data#IMU)\
    \ page. For the sample IMU message you posted above, was your IMU resting flat\
    \ on a table in its neutral orientation? If so, your acceleration data is wrong.\
    \ It should read **+**9.81 m/s^2 for Z when resting flat on a surface in its neutral\
    \ orientation. If you roll it +90 degrees, it should read **+**9.81 m/s^2 for\
    \ Y. If you pitch it +90 degrees (front end down), it should read **-**9.81 m/s^2\
    \ for X."
