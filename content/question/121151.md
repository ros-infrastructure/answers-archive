  body_markdown: "About the poor odometry in ROS nav stack from my own experience.\n\
    \nBoth gmapping and amcl need the odom message from the robot hardware.\n\nand\
    \ the /map->/odom tf relation should be static all the running time.\n\nSo if\
    \ the dynamic map generated by the gampping has a drift when robot doing a inplace\
    \ rotation,\n\nI suppose that means the /map->/odom tf relation has been polluted\
    \ by the real robot angular odometry output, \neven though the /map->/odom tf\
    \ is published by the gammping or amcl module, \nbut still need to debug the git\
    \ source code to confirm the real root causes.\n\nAs well as the draft  local\
    \ costmap when playing with the amcl + static map.\n\nAs for the poor translation\
    \ odometer, I guess a shifting map/local costmap will be its friends.\n\nI do\
    \ not have any solution about how to improve the hardware odom output via a software\
    \ mean."
