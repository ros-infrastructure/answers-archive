  body_markdown: "So here you have very rudimentary solution. Of course you will need\
    \ to add calibration procedures, and take extra thing into account like the blob\
    \ area to get the distance value, but this I hope gives you a starting point.\n\
    \nSo essentially you need to publish a Marker topic , with a Sphere Type of colour\
    \ red. This marker will have to be referenced to your camera link or similar.\
    \ I've done this Video as an example of how it could be done: [Video](https://youtu.be/OuYcJNlndsg)\n\
    \nThe core about solving this is creating a script that retrieves your Detection\
    \ Data and Publishes a Marker with it. Here you have the script I've used to publish\
    \ it:\n\n    #!/usr/bin/env python\n    import rospy\n    from cmvision.msg import\
    \ Blobs, Blob\n    from visualization_msgs.msg import Marker\n    from geometry_msgs.msg\
    \ import Point\n    from sensor_msgs.msg import CameraInfo\n\n\n    class MarkerBasics(object):\n\
    \n        def __init__(self):\n            self.marker_objectlisher = rospy.Publisher('/marker_redball',\
    \ Marker, queue_size=1)\n            self.rate = rospy.Rate(1)\n            self.init_marker(index=0,z_val=0)\n\
    \    \n        def init_marker(self,index=0, z_val=0):\n            self.marker_object\
    \ = Marker()\n            self.marker_object.header.frame_id = \"/camera_link\"\
    \n            self.marker_object.header.stamp    = rospy.get_rostime()\n     \
    \       self.marker_object.ns = \"mira\"\n            self.marker_object.id =\
    \ index\n            self.marker_object.type = Marker.SPHERE\n            self.marker_object.action\
    \ = Marker.ADD\n        \n            my_point = Point()\n            my_point.z\
    \ = z_val\n            self.marker_object.pose.position = my_point\n        \n\
    \            self.marker_object.pose.orientation.x = 0\n            self.marker_object.pose.orientation.y\
    \ = 0\n            self.marker_object.pose.orientation.z = 0.0\n            self.marker_object.pose.orientation.w\
    \ = 1.0\n            self.marker_object.scale.x = 0.05\n            self.marker_object.scale.y\
    \ = 0.05\n            self.marker_object.scale.z = 0.05\n    \n            self.marker_object.color.r\
    \ = 1.0\n            self.marker_object.color.g = 0.0\n            self.marker_object.color.b\
    \ = 0.0\n            # This has to be otherwise it will be transparent\n     \
    \       self.marker_object.color.a = 1.0\n            \n            # If we want\
    \ it for ever, 0, otherwise seconds before desapearing\n            self.marker_object.lifetime\
    \ = rospy.Duration(0)\n\n        def update_position(self,position):        \n\
    \            self.marker_object.pose.position = position\n            self.marker_objectlisher.publish(self.marker_object)\n\
    \n\n    class BallDetector(object):\n        def __init__(self):        \n   \
    \         self.rate = rospy.Rate(1)\n            self.save_camera_values()   \
    \     \n            rospy.Subscriber('/blobs', Blobs, self.redball_detect_callback)\
    \        \n            self.markerbasics_object = MarkerBasics()\n\n        def\
    \ save_camera_values(self):\n            data_camera_info = None\n           \
    \ while data_camera_info is None:\n                data_camera_info = rospy.wait_for_message('/mira/mira/camera1/camera_info',\
    \ CameraInfo, timeout=5)\n                rospy.loginfo(\"No Camera info found,\
    \ trying again\")\n            \n        \n            self.cam_height_y = data_camera_info.height\n\
    \            self.cam_width_x = data_camera_info.width\n            rospy.loginfo(\"\
    CAMERA INFO:: Image width==\"+str(self.cam_width_x)+\", Image Height==\"+str(self.cam_height_y))\n\
    \n        def redball_detect_callback(self,data):\n\n            if(len(data.blobs)):\n\
    \    \n                for obj in data.blobs:\n                    if obj.name\
    \ == \"RedBall\":\n                        rospy.loginfo(\"Blob <\"+str(obj.name)+\"\
    > Detected!\")\n                        redball_point = Point()\n            \
    \            # There is a diference in the axis from blobs and the camera link\
    \ frame.\n                        # We convert to percent of the screen\n    \
    \                    # TODO: Take into account the Depth distance and camera cone.\n\
    \                        rospy.loginfo(\"self.cam_width_x=\"+str(self.cam_width_x))\n\
    \                        rospy.loginfo(\"self.cam_width_x=\"+str(self.cam_height_y))\n\
    \                        rospy.loginfo(\"obj.x=\"+str(obj.x))\n              \
    \          rospy.loginfo(\"obj.y=\"+str(obj.y))\n                    \n      \
    \                  middle_width = float(self.cam_width_x)/2.0 \n             \
    \           middle_height = float(self.cam_height_y)/2.0\n                   \
    \ \n                        redball_point.x = (obj.x - middle_width) / float(self.cam_width_x)\n\
    \                        redball_point.z = (obj.y - middle_height) / float(self.cam_height_y)\
    \                    \n                        redball_point.y = 0.6         \
    \   \n                        rospy.loginfo(\"blob is at Point=\"+str(redball_point))\n\
    \                        self.markerbasics_object.update_position(position=redball_point)\n\
    \                    \n                    \n            else: \n            \
    \     rospy.logwarn(\"No Blobs Found\")\n\n\n        def start_loop(self):\n \
    \           # spin() simply keeps python from exiting until this node is stopped\n\
    \            rospy.spin()\n\n    if __name__ == '__main__':\n        rospy.init_node('redball_detections_listener_node',\
    \ anonymous=True)\n        redball_detector_object = BallDetector()\n        redball_detector_object.start_loop()\n\
    \n\nIt defines two classes, one to publish a RedSphere (MarkerBasics) and the\
    \ other retrieves and converts the blob data into something compatible with space\
    \ localization ( BallDetector) . Its here where all the calibration and adjustments\
    \ will have to be made to have a precise representation. Because in this example\
    \ the depth axis ( Y in this case ) is hardcoded, but could be calculated based\
    \ on the **Blob Area**.  \n\nAnother thing would be the fact that the conversion\
    \ of the x,y values of the BlobTRacker to meters is done here in a very simple\
    \ way, and in reallity this has to be calculated based on the focal distance and\
    \ other camera details, so bare that in mind.\n\nHope it was usefull.\n\n    "
