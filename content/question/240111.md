    You still don't mention which driver / package you are using, so I'm guessing a bit here, but:

    I'm not entirely sure, but it's possible that your trajectory is failing to execute because it does not include all the joints that you configured the motion interface with. `joint_names_yumi.yaml` contains all joints, so any instance of the `joint_trajectory_action` node (I am using ROS-Industrial `abb_driver` and `industrial_robot_client` terminology) will assume it is responsible for all those joints. [JointTrajectoryAction::goalCB(..)](https://github.com/ros-industrial/industrial_core/blob/aca48389468a53ca932373b8f94f0b3ea1bdc9db/industrial_robot_client/src/joint_trajectory_action.cpp#L110) checks incoming goals to make sure they contain the joints it has been configured for, using [industrial_utils::isSimilar(..)](https://github.com/ros-industrial/industrial_core/blob/6f83e6afdbe919d54a151eb5d784d9125a7f06ac/industrial_utils/include/industrial_utils/utils.h#L42-L54) [here](https://github.com/ros-industrial/industrial_core/blob/aca48389468a53ca932373b8f94f0b3ea1bdc9db/industrial_robot_client/src/joint_trajectory_action.cpp#L128), and it will reject goals for which that function returns `false`.

    It's likely that you have either a single instance of `joint_trajectory_action`, and are sending goals with per-arm trajectories, or have two instances but have set the parameter only once.
