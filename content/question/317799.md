  body_markdown: "> I've been looking into a way to specify a single target which\
    \ can be specified like `catkin_make --pkg <target>` such that all of the packages\
    \ required for a node on a specific end target are built.\n\n`catkin_make` should\
    \ allow you to do that, if you use the `--only-pkg-with-deps` option:\n\n    \
    \  --only-pkg-with-deps ONLY_PKG_WITH_DEPS [ONLY_PKG_WITH_DEPS ...]\n        \
    \                    Whitelist only the specified packages and their\n       \
    \                     dependencies by setting the CATKIN_WHITELIST_PACKAGES\n\
    \                            variable. This variable is stored in CMakeCache.txt\n\
    \                            and will persist between CMake calls unless explicitly\n\
    \                            cleared; e.g. catkin_make\n                     \
    \       -DCATKIN_WHITELIST_PACKAGES=\"\".\n\nAlternatively, [catkin_tools](https://catkin-tools.readthedocs.io/en/latest/index.html)\
    \ supports profiles, that in turn can be configured with specific [white and blacklists](https://catkin-tools.readthedocs.io/en/latest/verbs/catkin_config.html#whitelisting-and-blacklisting-packages)\
    \ of packages.\n\nIn addition you can ask it to build just a single package with\
    \ all it's dependencies:\n\n    catkin build <pkg_name>\n\nor even just a package\
    \ without its dependencies:\n\n    catkin build <pkg_name> --no-deps\n\nSee [catkin\
    \ build \u2013 Build Packages](https://catkin-tools.readthedocs.io/en/latest/verbs/catkin_build.html)\
    \ for the documentation of the `build` verb and the [Building Subsets of Packages](https://catkin-tools.readthedocs.io/en/latest/verbs/catkin_build.html#building-subsets-of-packages)\
    \ section."

Hello, I'm developing a multi-computer ROS project where each processor has multiple nodes running on it. We've found that builds have become quite long as we're not cross compiling yet and so some of the smaller embedded processors can take a decent amount of time to build the whole workspace despite not needing to build every package. 

I've been looking into a way to specify a single target which can be specified like `catkin_make --pkg <target>` such that all of the packages required for a node on a specific end target are built. I thought metapackages might be the answer for this, but they seem to address a different problem.

Is there a standard way to equate a catkin target to a set of packages so that the whole codebase does not need to be built? I see this as also being useful for cross compiling anyway for having a single target to cross compile.
