- body_markdown: "To support @kosmastsk comment you need to know that `ros::spin`\
    \ directive is a blocking function, hence it will block all your execution at\
    \ the `main` process. You may use `ros::spinOnce` that already implement a type\
    \ of wait/synchronization for processing messages.\n\nIf that does not fit your\
    \ set up, just change the `main` process of your program with a \n\n    bool process\
    \ = true;\n    \n    void callback_listener(const std_msgs::String::ConstPtr&\
    \ msg)\n    {\n       ROS_INFO(\"Received\");\n       if (msg == \"ok\")\n   \
    \    {\n         process = false;\n       }\n    }\n    \n    int main(int argc,\
    \ char** argv)\n    {\n     while(ros::ok())\n     {\n      if(process)\n    \
    \  {\n       //Do your process here.\n      }\n      ros::Rate(20).sleep();\n\
    \      ros::spinOnce();\n     }\n    return 0;\n    }"

- body_markdown: |-
    If you are dealing with a Qt5 project you do not need to write that in the main process where you instantiate the main Qt Window, you should have a Node running in another thread providing ROS communications with the Qt application, In that case you will have a "while" `ros::ok()` running in his own thread node, while the Qt5 application will be running in the main process. Nevertheless either you use a custom callback queue to decide when to dequeue the message and resume execution or perform a `wait` in the Qt thread to only resume the execution when `start` is called or the `wait` finishes, I am still do not know why you want to block ROS execution but there is another probable approach that you can use and that is [waitForMessage](http://docs.ros.org/diamondback/api/roscpp/html/namespaceros_1_1topic.html) which will wait until a message is received and drops connection.
