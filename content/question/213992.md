    As @cyborg-x1 mentioned, the tabbing functionality is part of Qt.

    For the following, first, a disclaimer: the UIs I've implemented have used librviz, not rqt, so I've never had to worry about inter-widget communication (I created and set up the <code>QMainWindow</code> myself). Also, all my Qt work has been strictly in C++; any pyQt is possibly different. And, rqt may incorporate/hide/expose functionality that makes everything below irrelevant...I just don't know. With that said...perhaps it'll be of assistance.

    The Qt <a href="http://doc.qt.io/qt-4.8/qmainwindow.html">QMainWindow</a> provides the ability to tabify <a href="http://doc.qt.io/qt-4.8/qdockwidget.html">QDockWidgets</a>. When a <code>QDockWidget</code>'s docking location changes, it emits a <code>dockLocationChanged</code> signal; with an appropriate Qt 'connection' to a slot, one can program reactions to widget relocations.

    Through various (rather convoluted) means, you can programmtically manipulate <code>QDockWidgets</code> through the <code>QMainWindow</code>. Not the easiest item to access, but I've successfully retrieved it in an RViz <code>Display</code> subclass via the following:
    <pre><code>QMainWindow* main = static_cast<QMainWindow*>(context_->getWindowManager()->getParentWindow());</code></pre>
    where <code>context_</code> is an (inherited from <code>Display</code>) instance of <code>rviz::DisplayContext</code> (as implemented by the <code>rviz::VisualizationManager</code>).

    I don't recommend going down this path, but if you do, that should give you a bit of a start on what will be involved.
