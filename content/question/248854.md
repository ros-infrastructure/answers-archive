  body_markdown: "The OMPL's RRTConnectkConfigDefault planner should handle this,\
    \ you just need to setup the constraint at the goal pose such that the orientation\
    \ about the desired tool axis is underconstrained, below is pseudo code of how\
    \ you'd set this up:\n\n\n      // Create the Motion Plan request object\n   \
    \   moveit_msgs::MotionPlanRequest req;\n      req.motion_plan_request.group_name\
    \ = group_name;\n      req.motion_plan_request.workspace_parameters.header.stamp\
    \ = ros::Time::now();\n      req.motion_plan_request.start_state = start_state;\n\
    \n      // Set the tool pose\n      geometry_msgs::PoseStamped stamped;\n    \
    \  stamped.pose = pose;\n      stamped.header.stamp = ros::Time::now();\n    \
    \  stamped.header.frame_id = req.motion_plan_request.workspace_parameters.header.frame_id;\n\
    \n      // defining constraints such that tool z orientation constraint has a\
    \ large tolerance of 1.0 \n      std::vector<double> pos_constraint = {1e-3,1e-3,1e-3};\n\
    \      std::vector<double> orient_constraint =  {0.01,0.01,1.0}; \n      moveit_msgs::Constraints\
    \ c = kinematic_constraints::constructGoalConstraints(\n        tool_link_name,\
    \ stamped,pos_constraint,orient_constraint);\n\n     // Add the constraint to\
    \ the motion planning service request \n     req.motion_plan_request.goal_constraints.push_back(c);\n\
    \n    // call the motion planning service\n     motion_planning_client.call(req,\
    \ res)"

 Hi,

is there a way to plan a path to a goal which is defined with a position (x, y, z) and a value for pitch and roll, but leave yaw open for variation?
For my use case the yaw angle is not relevant, so I don't want to restrict possible paths by defining a value for it.

As far as I understand not giving a value for the axis will not work, because the value is initialized to zero.

Another approach would be to set the goal_orientation_tolerance. However, this is quite unsatisfying as this sets the tolerance for the whole pose and not only one specific axis.
