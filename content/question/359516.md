  body_markdown: "Hi there,\n\nFrom my limited understanding the short answer regarding\
    \ `octomap_resolution` is no. It is specified in your `sensor_manager.launch.xml`\
    \ which looks something like this:\n\n    <launch>\n     \n      <!-- This file\
    \ makes it easy to include the settings for sensor managers -->  \n    \n    \
    \  <!-- Params for the octomap monitor -->\n      <!--  <param name=\"octomap_frame\"\
    \ type=\"string\" value=\"some frame in which the robot moves\" /> -->\n     \
    \ <!-- <param name=\"octomap_frame\" type=\"string\" value=\"odom\" /> -->\n \
    \     <param name=\"octomap_frame\" type=\"string\" value=\"odom\" />\n      <param\
    \ name=\"octomap_resolution\" type=\"double\" value=\"0.1\" /> <!-- in meters\
    \ -->\n      <param name=\"max_range\" type=\"double\" value=\"2.5\" />\n    \n\
    \      <!-- Load the robot specific sensor manager; this sets the moveit_sensor_manager\
    \ ROS parameter -->\n      <arg name=\"moveit_sensor_manager\" default=\"awesome_robot\"\
    \ />\n      <include file=\"$(find awesome_robot_moveit)/launch/$(arg moveit_sensor_manager)_moveit_sensor_manager.launch.xml\"\
    \ />\n      \n    </launch>\n It loads `awesome_robot_sensor_manager.launch.xml`\
    \ which loads `senors.yaml` to the parameter server.\nThere you may define multiple\
    \ sensors as mentioned in the tutorial. All those sensors however are contributing\
    \ to the same `octomap`. That's why I assume you can set the resolution of the\
    \ octomap as one entity. Padding however is a different story, This parameter\
    \ can be adjusted by sensor in your `sensor.yaml`. More information can be found\
    \ in the tutorials.\n\n"
