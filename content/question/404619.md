    Are you on WIFI between the RPI4 and your laptop? There could be a bandwidth issue. First you should try to do `rostopic hz ...` with your camera topics on the laptop to see if you can get a decent frequency. You can also compare with `rostopic hz ...` directly on RPI4 (if you don't even get 30 Hz on all camera topics at the same time on RPI4, it is a camera driver issue).

    Also some other documentation about remote mapping and bandwidth issues: http://wiki.ros.org/rtabmap_ros/Tutorials/RemoteMapping

I have followed this tutorial https://github.com/IntelRealSense/realsense-ros/wiki/SLAM-with-D435i succesfully, using a D435i camera attached to a PC running ROS noetic. Everything seems to work properly: enabling MapCloud tab in RViz I can see the 3D mapCloud beeing generated.

I am now trying to change my setup so that the camera is attached to a second machine (Leo rover robot running ROS noetic on a raspberry Pi4). So I have configured the network adding (ROS_MASTER_URI, ROS_HOSTNAME and ROS_IP) in .bashrc on both systems so that the master node runs on the rover.

If I start the camera on my robot using "roslauch realsense2_camera rs_camera.launch" and I run rostopic list on my PC I can see the new published camera topics, so the networks setup seems to be ok.
Now if I launch "roslauch realsense2_camera rs_camera.launch" on my rover and "roslauch realsense2_camera opensource_tracking.launch" with argument offline=true on my PC everything should continue to work properly, but it doesn't.

In rqt I don't see the 'map' and the 'odom' frames in the frames viewer. In RViz I have a Global status error: "Unknown frame map". I have tried to add a static_transformation_publisher node from map to base_link, the error disappears but still no mapcloud. If I set image topic '/camera/color/image_raw' in RVIZ, i can see the RGB image coming from the camera but again no mapcloud.

Please, what am I doing wrong and how can I make it work if that is even possible?
