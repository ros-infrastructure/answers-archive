  body_markdown: "The first method that comes to mind that I know would work, but\
    \ might not necessarily be the most elegant solution, would be to create a \"\
    line_segment\" gazebo model, of some characteristic unit length, make it static,\
    \ and just give it a visual tag (no collision or inertial needed). Then write\
    \ a node that dynamically [spawns](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/melodic-devel/gazebo_ros/scripts/spawn_model)\
    \ this model, as needed, in the desired locations. This is a bit clunky because\
    \ it will spin up a separate process for each line segment model, but for a simple\
    \ box model, should work pretty well. You could dynamically generate the model's\
    \ SDF file as well to accept variable length line segments. \n\nA second option,\
    \ that may work a bit better if your input is a hand-drawn line (i.e. as an image),\
    \ you could look at the [projector](https://answers.gazebosim.org//question/9807/how-can-i-simulate-a-line-laser/)\
    \ [plugin](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/melodic-devel/gazebo_plugins/src/gazebo_ros_projector.cpp).\
    \ This has the caveat that it will also project the line onto your robot as your\
    \ robot drives underneath the projector. \n\nA more elegant solution might be\
    \ to write a Gazebo plugin and take advantage of some of the rendering API. You\
    \ could probably use the [DynamicLines](http://osrf-distributions.s3.amazonaws.com/gazebo/api/9.0.0/classgazebo_1_1rendering_1_1DynamicLines.html)\
    \ or perhaps the [Road2d](http://osrf-distributions.s3.amazonaws.com/gazebo/api/9.0.0/classgazebo_1_1rendering_1_1Road2d.html)\
    \ class to achieve what you are looking to do. I have no experience with this,\
    \ so I'm not 100% sure it would work with the simulated camera, "
