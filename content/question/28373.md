    There is no guarantee in ROS that callbacks are not executed in parallel. This is desired behavior. If you want to avoid this kind of race condition, you need to use locks in your program code, i.e. when entering a callback a lock is acquired and when returning the lock is released again. That way, you get exclusive execution of callbacks. For python, you can use the [threading.Lock](http://docs.python.org/library/threading.html#lock-objects) class ([tutorial](http://effbot.org/zone/thread-synchronization.htm)). For C++ I suggest to use [boost::scoped_lock](http://www.boost.org/doc/libs/1_37_0/doc/html/boost/interprocess/scoped_lock.html).
