  body_markdown: "It looks like the QoS settings on the publisher and subscriber are\
    \ incompatible.\nChange the QoS settings on either the publisher or the listener\
    \ to match.\nSee the page [About Quality of Service Settings](https://index.ros.org//doc/ros2/Concepts/About-Quality-of-Service-Settings/)\
    \ for more info.\n\nThe C++ publisher is using `rclcpp::SensorDataQoS()`, which\
    \ uses the  [ sensor data QoS profile](https://github.com/ros2/rmw/blob/9f2e181306c66ac0f09674086a108d4657611766/rmw/include/rmw/qos_profiles.h#L25-L36).\n\
    The Python subscriber is just specifying the queue size, which means it uses [the\
    \ default profile](https://github.com/ros2/rmw/blob/9f2e181306c66ac0f09674086a108d4657611766/rmw/include/rmw/qos_profiles.h#L51-L62)\
    \ with the given queue size of 10.\nThe incompatibility comes from the `reliability`\
    \ setting. \nThe sensor data profile specifies `best effort` while the default\
    \ profile uses `reliable`.\nAccording to the [QoS compatibilities table](https://index.ros.org//doc/ros2/Concepts/About-Quality-of-Service-Settings/#qos-compatibilities),\n\
    \ a subscriber requiring `reliable` will not connect to a publisher providing\
    \ only `best effort` reliability."
