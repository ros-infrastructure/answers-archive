  - body_markdown: |-
      I don't think by building a custom FastDDS locally will be a feasible solution. And this should be focusing at FastDDS (ROS2 Foxy Default Middleware) rather than CycloneDDS.

      Nevertheless, I have figured this out at last.

      RMW_FAST_USE_QOS_FROM_XML=1, will require your custom.xml to include the history memory policy. This configuration is causing the "Not enough memory in the buffer stream"

      The default history memory policy of:

      - RMW ROS2:  `PREALLOCATED_WITH_REALLOC`
      - FastDDS: `PREALLOCATED_MEMORY_MODE`


      An example of the custom.xml that is working can be found [here](https://github.com/ros2/rmw_fastrtps#readme)

  body_markdown: "The critical parameters that are missing from the [official website](https://fast-dds.docs.eprosima.com/en/latest/fastdds/transport/whitelist.html)\
    \ are\n\n- `is_default_profile=\"true\"`\n- `<useBuiltinTransports>false</useBuiltinTransports>`\n\
    \nThe following is an example to whitelist specific IP address using ROS2 Foxy\
    \ FastDDS.\n`FASTRTPS_DEFAULT_PROFILES_FILE=./whitelist.xml ros2 run demo_nodes_cpp\
    \ talker`\n\n**whitelist.xml**\n\n    <?xml version=\"1.0\" encoding=\"UTF-8\"\
    \ ?>\n    <dds xmlns=\"http://www.eprosima.com/XMLSchemas/fastRTPS_Profiles\"\
    >\n        <profiles>\n    \t\t<transport_descriptors>\n    \t\t    <transport_descriptor>\n\
    \    \t\t        <transport_id>CustomUdpTransport</transport_id>\n    \t\t   \
    \     <type>UDPv4</type>\n    \t\t        <interfaceWhiteList>\n    \t\t     \
    \       <address>192.168.1.77</address>\n    \t\t            <address>192.168.1.75</address>\n\
    \    \t\t        </interfaceWhiteList>\n    \t        </transport_descriptor>\n\
    \    \t\t</transport_descriptors>\n    \t\t\n    \t    <participant profile_name=\"\
    CustomTcpTransportParticipant\" is_default_profile=\"true\">\n    \t\t    <rtps>\n\
    \    \t\t        <userTransports>\n    \t\t            <transport_id>CustomUdpTransport</transport_id>\n\
    \    \t\t        </userTransports>\n                    <useBuiltinTransports>false</useBuiltinTransports>\n\
    \    \t\t    </rtps>\n    \t\t</participant>\n        </profiles>\n    </dds>\n\
    \n\n*Note1: I'm not able to set wildcard to the address (e.g. 192.168.1.\\*),\
    \ have to explicitly states the address.\n\n*Note2: Do not set `RMW_FASTRTPS_USE_QOS_FROM_XML=1`\
    \ if you simply want to keep everything else as default (i.e. history memory policy,\
    \ publication mode, subscriber, publisher profile.)"

- Ubuntu 20.04, ROS2 Foxy
- Binary installation, FastRTPS (Default)

I was setting up multiple machines using ROS2 Foxy. 

PC 1 and PC 2:

- Ethernet with static IP address
- Wifi with DHCP

PC 1 and PC 2 are able to ping each other via Wifi DHCP and the static Ethernet IP address.

When running a publisher in PC 1, subscriber in PC 2, by default, it was observed that it uses the Wifi interface which results in a very high latency in receiving the message.

**How can I make the default to prioritize the Ethernet over Wifi network interface?** 

**Expected behavior** Communicate via Ethernet interface (lower latency)

**Actual behavior** Communicate via Wifi interface (very high latency)

My current workaround is to disconnect the Wifi on PC 2, which would force it to use the Ethernet to communicate. However this is not desirable in a long run.
