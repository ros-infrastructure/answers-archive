I have a node (call it RobotControl) that's meant to publish to some topics that control the movement of a robot. 

I want to create a way to add reinforcement learning. Effectively, I want to (1) be able to grab time synchronized world data (imu, odom, depth image), (2) be able to process that information to determine the best action and (3) publish the resulting decision back to the robot. 

I figured I could create a separate node (called EnvironmentListener) for the sake of separation of concerns. So I now have a node that's meant to send commands to the robot (RobotControl) and one that's meant to listen to relevant environment data using ApproximateTimeSynchronizer (EnvironmentListener). A problem I ran into is that you can't have multiple nodes running in the same Python process, so I separated them out into two simultaneously running Python processes. 

Now I'm trying to figure out how to get those nodes to communicate. I started adding some publishers to the EnvironmentListener node, but I realized that I'd basically just be combining the two nodes at that rate. Is it worth it in your experience to keep nodes like this separate?
