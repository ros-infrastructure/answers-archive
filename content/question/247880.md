  body_markdown: "This could either be a permission problem, or there really is no\
    \ X server running when `robot_upstart` starts your launch files.\n\nIf the first,\
    \ see [robot_upstart: could not open port /dev/ttyUSB0](http://answers.ros.org/question/207892)\
    \ as a related question. To clarify: `robot_upstart` runs your launch files under\
    \ the same user as the one that installed them, but (from [robot_upstart 0.2.0\
    \ documentation \xBB The install script - permissions](http://docs.ros.org/indigo/api/robot_upstart/html/install.html#permissions)):\n\
    \n> The roslaunch which executes does not have its user\u2019s group memberships.\n\
    \nThis could lead to the `rviz` instance not having any access rights to the X\
    \ server.\n\nThe second (and looking at the error message, likely) option is that\
    \ at the moment that your jobs are being started, the X server hasn't started\
    \ yet, and as RViz needs one, it can't continue.\n\n\n\nPS (and pedantic): technically\
    \ RViz didn't crash: one of the prerequisites for it to work is to have a working\
    \ X server. Since it can't connect to one, it can't initialise the application\
    \ successfully, and just exits (most likely [here](https://github.com/ros-visualization/rviz/blob/1be76af0a30dee736b9597640df7dabb45126aca/src/rviz/main.cpp#L46))."
