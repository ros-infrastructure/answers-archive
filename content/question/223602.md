    \ in firewall, thus using masquerading. The pubsub publisher sends the local ip\
    \ address running on the\nemulated cell phone and the emulated firewall changes\
    \ the address at host side, likely with a bridge. So the\nROS Core running on\
    \ a Ubuntu system was taking fine with HTTP thru the firewall but when I did a:\n\
    \n                                       'rostopic echo \\mychatter'\n\nit was\
    \ trying to send a direct TCP/IP connection directly to the host address inside\

      NAT-traversal (or punching) is indeed not something that is dealt with by the middleware (natively), but is considered a system configuration issue. Hence the recommendation to solve this using non-ROS tools. There are more middlewares requiring extra configuration to work across NAT or through fws.
