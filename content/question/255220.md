  body_markdown: "This is not related to the local planners directly but to the local\
    \ costmap setup (costmap_2d).\nLocal planners in the navigation stack have only\
    \ access to the local costmap, so you need to add the desired layer \nto the configuration.\n\
    \nBased on the [Robot Setup](http://wiki.ros.org/navigation/Tutorials/RobotSetup)\
    \ and [Configure and run Robot Navigation](http://wiki.ros.org/teb_local_planner/Tutorials/Configure%20and%20run%20Robot%20Navigation)\n\
    Tutorial you might try the following:\n\nE.g. in `local_costmap_params.yaml` (or\
    \ similar):\n\n      rolling_window: true\n      width: 5.0\n      height: 5.0\n\
    \      resolution: 0.1\n\n      plugins:\n       ## Without proximity sensors,\
    \ we do not need any obstacle_layer:\n       # - {name: obstacle_layer,      type:\
    \ \"costmap_2d::VoxelLayer\"}\n\n       ## Static Layer\n       - {name: static_layer,\
    \            type: \"costmap_2d::StaticLayer\"}\n       \n       # Uncomment the\
    \ following line if you want to inflate occupied cells \n       #- {name: inflation_layer,\
    \     type: \"costmap_2d::InflationLayer\"}\n\nNote, you might add more configurations\
    \ for layers (inflation_layer and static_layer) either here or in the `costmap_common_params.yaml`.\
    \ Please check the costmap_2d documentation (*static_map* topic name, service,\
    \ ...).\n\nNotice, there was an issue early 2015 (see [here](http://answers.ros.org/question/200573/static-layer-on-local-costmap/))\
    \ but it seems to be fixed according to the related merge requests on github.\
    \ If it still does not work,"
