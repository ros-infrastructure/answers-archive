  body_markdown: "The `plan` function returns an error code. You can check this error\
    \ code for success, using this example from the [tutorial](http://docs.ros.org/melodic/api/moveit_tutorials/html/doc/move_group_interface/move_group_interface_tutorial.html#planning-to-a-pose-goal):\n\
    \n    bool success = (move_group.plan(my_plan) == moveit::planning_interface::MoveItErrorCode::SUCCESS);\n\
    \    \n    ROS_INFO_NAMED(\"tutorial\", \"Plan 1 (pose goal) %s\", success ? \"\
    succeeded\" : \"FAILED\");\n\nAll the error codes are listed [here](http://docs.ros.org/melodic/api/moveit_msgs/html/msg/MoveItErrorCodes.html).\n\
    \n---\n\nThe Python interface also has a `plan` function. For reference, all the\
    \ Python move_group's functions are defined [in this file](https://github.com/ros-planning/moveit/blob/melodic-devel/moveit_ros/planning_interface/move_group_interface/src/wrap_python_move_group.cpp).\
    \ Change to the branch of your release (`melodic-devel`, `kinetic-devel`...) if\
    \ you are not building from source.\n\nThe function returns the plan instead of\
    \ an error code. To check for success, you can check that the trajectory is not\
    \ empty:\n\n    plan = move_group.plan()\n    if plan.joint_trajectory.points:\
    \  # True if trajectory contains points\n      move_success = move_group.execute(plan)\n\
    \    else:\n      rospy.logerr(\"Trajectory is empty. Planning was unsuccessful.\"\
    )\n\nThis should work in Melodic (and Kinetic, I believe), but the API might be\
    \ changing in the future (it seems like it is already different in the [master\
    \ branch](https://github.com/ros-planning/moveit/blob/master/moveit_ros/planning_interface/move_group_interface/src/wrap_python_move_group.cpp#L420)).\
    \ Feel free to add this use case to the tutorial. A pull request is very welcome.\n\
    \nPS: The errors in your post look like they are caused by your robot being in\
    \ an invalid pose. Maybe you are restricting the possible joint angles in your\
    \ `moveit_config`, and your robot arm is in a different configuration? E.g. is\
    \ the elbow flipped, or a joint at +- 2*pi? Does the robot look correct in Rviz?\
    \ Don't forget to set the orientation for your `pose_target`, too."
