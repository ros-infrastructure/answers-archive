  body_markdown: "The args string is interpreted by shlex, which uses the POSIX command-line\
    \ parsing rules.  Thus, the arg string should be identical to whatever you would\
    \ have typed in a shell.\n\nI did a test on my own setup and the following works:\n\
    \n\n    args='\"hello world\"'\n\nor\n\n    args='\"hello world'\"\n\ni.e. you\
    \ don't need to escape the quotes.  \n\nThe reason why the --args works is that\
    \ the terminal does not represent separate arguments, and roslaunch simply prints\
    \ back the arguments to the screen with a space separator.  I could attempt to\
    \ escape --args so that it preserved the argument separation, though this would\
    \ have the side-effect of making the output of --args harder to read."

I have a program that takes string as an argument, such as
<pre>
$ ./say "hello world"
</pre>
and would like to invoke this program from roslaunch.

Here is an example of the launch file:
<pre>
 < launch>
   < node name="say" pkg="say" type="say" args='\"hello world\"' />
 < /launch>
</pre>

When I check the command line argument with
<pre>
$ roslaunch say.launch --args /say
</pre>
the output is
<pre>
PYTHONPATH=/opt/ros/diamondback/ros/core/roslib/src /home/k-okada/ros/diamondback/say/say "hello world" __name:=say
</pre>
and this is ok to me.
but when I try to start this program from launch file by
<pre>
$ roslaunch say.launch
</pre>
the argument corrupts. It seems that the roslaunch divide string arugment into each words as written in the log file
<pre>
[roslaunch][INFO] 2011-07-01 13:35:10,808: process[hoge-1]: args[[u'/home/k-okad
a/ros/diamondback/say/say', '"hello', 'world"', u'__name:=
say']]
</pre>

Changing the launch file to 
<pre>
 < launch>
   < node name="say" pkg="say" type="say" args='\"hello\ world\"' />
 < /launch>
</pre>
worked, but if there are other solution, I would like to know that.
