  body_markdown: "It is not currently possible to write a parameters YAML file that\
    \ does not include the node's name.\nHowever, [there is a very recent pull request](https://github.com/ros2/launch/pull/138)\
    \ that added functionality to `launch_ros` so that parameters can be specified\
    \ in the launch file. If the node's name/namespace is modified in the launch file,\
    \ that will be taken into account.\n\nThis feature has been implemented but not\
    \ yet released; it will be included (with more documentation) in the Crystal release\
    \ at the end of 2018. If you would like to use the functionality in the meantime,\
    \ you can build ROS 2 from source using the 'master' branches as described [here](https://github.com/ros2/ros2/wiki/Linux-Development-Setup#get-ros-20-code).\n\
    This is an example of the usage today (syntax and naming may change in the future).\n\
    \n  \n    import os\n\n    from launch import LaunchDescription\n    from launch.substitutions\
    \ import EnvironmentVariable\n    import launch_ros.actions\n    \n    def generate_launch_description():\n\
    \        os.environ['MY_ENV_VAR'] ='my_env_value'\n        return LaunchDescription([\n\
    \            launch_ros.actions.Node(\n                package='demo_nodes_cpp',\
    \ node_executable='talker', node_name='my_talker', node_namespace='my_ns',\n \
    \               output='screen',\n                parameters=[\n             \
    \       {'my_param': EnvironmentVariable(name='MY_ENV_VAR')},\n              \
    \  ],\n                log_cmd=True,\n            ),\n        ])\n\n"

Is it possible to write a YAML parameter file without specifying the ROS2 node name?

The current format for a YAML file is the following:

    namespace:
        node_name:
            ros__parameters:
                general:
                    param_1: 0
                    param_2: 'a'
                    param_3: 3.14


The problem comes when I have a launch file that can dynamically change the namespace and the node_name (multi robot for example). How can the config YAML file be adapted to the dynamic change?
