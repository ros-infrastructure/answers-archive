    Just encountered the same.

    Apparently, you just need to replace all occurrences of "laser" with "ranger" (as per [this post](http://blog.aus10.org/?p=125) )

    Here's a handy one-liner to do so (for all stage files below current directory):
    <pre>`perl -p -i -e 's/laser/ranger/g' $(find . -name *.world) $(find . -name *.inc)`</pre>

    I also notice the `upgrade-world.sh` script in stage pkg... may be useful for getting rid of other deprecated stuff in your .world files?

    UPDATE: looks like you also have to wrap your laser in a "sensor" block...

    So the old sick.inc ...

    <pre>
    define sick laser
    (
        range_max 80
        fov 180.0
        samples 180
        size [ 0.156 0.155 0.19 ]
    )
    </pre>

    Has now become:

    <pre>
    define sick ranger
    (
      sensor(
        range [ 0 80 ]
        fov 180.0
        samples 180
      )
      size [ 0.156 0.155 0.19 ]
    )
    </pre>

  body_markdown: "There are several issues when using Fuerte and Stage 4.1.1 regarding\
    \ stage controllers.\n \nRe:   `warn: Model roomba.ranger:1 not found`\n\nThe\
    \ stageros wrapper only expects one ranger per robot but the wander controller\
    \ \nin Stage expects the laser to be the second ranger. The line in `wander.cc`\
    \ that causes this warning is:\n\n    robot->laser = (ModelRanger*)mod->GetChild(\
    \ \"ranger:1\" );\n\nRe:    `Segmentation fault (core dumped)`\n\nThis appears\
    \ to be related to the use of the roomba model (when I inspected the stack trace\
    \ the problem was in some drawing code) - pioneer or simple position models work\
    \ OK (once `wander.cc` has been edited).\n\nHowever, stageros will stop all robots\
    \ that have not received a velocity command in the last 0.2 seconds which is a\
    \ problem if using a stage controller to control that robot.\n\nTo address these\
    \ issues, I forked the Stage repository and edited `stage.hh` and `model.cc` to\
    \ store and expose a `uses_controller` attribute for each `Model`. I then edited\
    \ `stageros.cpp` (in a local copy of the stage stack) to make use of it, so that\
    \ robots that have stage controllers are not exposed to ROS. I also edited `wander.cc`\
    \ to get the first ranger it finds for any robot (this will break the simple.world\
    \ demo found in Stage/worlds - I've added a gsh-simple.world demo that will work)\n\
    \nMy forked repo is available at git://github.com/grahamhorn/Stage.git\n\nI've\
    \ included my edited `stageros.cpp` file in a `stageros` directory.\n\nThese commands\
    \ should get things working:\n\nFirst create an overlay for stage in your `$ROS_WORKSPACE`\n\
    \n    $ roslocate info turtlebot | rosws merge -\n    $ rosws update\n \nand build\
    \ it:\n   \n    $ rosmake stage\n    \nThen clone my Stage repo and build it:\n\
    \n    $ mkdir stage4\n    $ cd stage4\n    $ git clone git://github.com/grahamhorn/Stage.git\n\
    \    $ cmake -DCMAKE_INSTALL_PREFIX=$ROS_WORKSPACE/stage Stage\n    $ make install\n\
    \nTest:\n\nIn one terminal:\n\n    $ roscore\n\nIn a second terminal:\n\n    $\
    \ rosrun stage stageros <your path>/stage4/Stage/worlds/gsh-simple.world \n\n\
    You should see one moving robot (controlled by the wander controller) and one\
    \ static robot (exposed to ROS and waiting for commands).\n"
