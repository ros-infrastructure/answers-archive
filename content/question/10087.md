  body_markdown: "Yes I am. \nI managed to solve my problem for now using the [republish](http://www.ros.org/wiki/image_transport#republish)\
    \ command of [image_transport](http://www.ros.org/wiki/image_transport).\n\nMy\
    \ code was pretty similar to the tutorial examples. My subscriber declaration:\n\
    \n    _frameSubscriber = image_transport::ImageTransport(_nh).subscribe(\"/vision/image\"\
    , 5, &WebVision::grabFrameFromMsg, this);\n\nAnd implementation:\n\n    void WebVision::grabFrameFromMsg(const\
    \ sensor_msgs::ImageConstPtr& msg)\n    {\n    \tsensor_msgs::CvBridge bridge;\n\
    \    \t\n    \tframe = bridge.imgMsgToCv(msg, \"bgr8\");\n    \tframeTimestamp\
    \ = msg->header.stamp;\n    \t\n    \t/*rest of the code where I pass the IplImage*\
    \ frame to my functions*/\n    }\n\nSo the notion was to save bag files from the\
    \ camera input when testing, and then pass the \"video\" as input to the algorithms\
    \ to test it while offline.\n\nBut CvBridge could only listen to raw image messages\
    \ and I couldn't afford so much disk space to save long raw videos.\n\nWhat I\
    \ do now is to just run this:\n\n    $ rosrun image_transport republish compressed\
    \ in:=/vision/image _image_transport:=compressed raw out:=/vision/image\n\nand\
    \ listen to the republished topic with raw images. It could be better if I could\
    \ implement the conversion inside the code, but it solves my problem for now.\n\
    \nThanks anyway for giving it a try. :)"
