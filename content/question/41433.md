  body_markdown: "The answer is based on the *turtlebot* robot, but of course it can\
    \ be used with any robot(s).\n\nFor multiple robots the key point is to manage\
    \ the *namespaces* and *tf_prefixes*. Although usually we will set them to the\
    \ same value for each robot in this example I will you different for purpose.\n\
    \nIn setting up the navigation stack(s) each robot must operate in it's own namespace,\
    \ but they do have to share the *map* (and usually *robot_description*). So the\
    \ effect we want to achieve is:\n\n                                      /map\n\
    \           /robot1/robot_state_publisher    /robot2/robot_state_publisher\n \
    \          /robot1/robot_pose_ekf           /robot2/robot_pose_ekf\n         \
    \  /robot1/amcl                     /robot2/amcl\n           /robot1/move_base\
    \                /robot2/move_base\n\n## Simulation ##\nFirst of all we have to\
    \ launch the simulation, in our case *gazebo*.\nTo make things more readable I\
    \ split launch files in few files.\n\nLaunch file for one robot. We name it *one_robot.launch*:\n\
    \n    <launch>\n        <arg name=\"robot_name\"/>\n        <arg name=\"init_pose\"\
    />\n    \n        <node name=\"spawn_minibot_model\" pkg=\"gazebo\" type=\"spawn_model\"\
    \n         args=\"$(arg init_pose) -urdf -param /robot_description -model $(arg\
    \ robot_name)\"\n         respawn=\"false\" output=\"screen\" />\n        \n \
    \       <node pkg=\"robot_state_publisher\" type=\"state_publisher\" \n      \
    \        name=\"robot_state_publisher\" output=\"screen\"/>\n    \n        <!--\
    \ The odometry estimator, throttling, fake laser etc. go here -->\n        <!--\
    \ All the stuff as from usual robot launch file -->\n    </launch>\n\nTwo things\
    \ to mention for above launch file:\n\n * create two arguments to pass for robot\
    \ initialization: name and position\n * notice that *-param /robot_description*\
    \ is with the *slash* i.e. fully-qualified, as it will be shared.\n\nHaving the\
    \ robot declaration we can now play with the *namespaces*. Your main launch file\
    \ for \nmultiple robots should look like (*robots.launch*):\n\n    <launch>\n\
    \      <!-- No namespace here as we will share this description. \n          \
    \ Access with slash at the beginning -->\n      <param name=\"robot_description\"\
    \n        command=\"$(find xacro)/xacro.py $(find turtlebot_description)/urdf/turtlebot.urdf.xacro\"\
    \ />\n    \n      <!-- BEGIN ROBOT 1-->\n      <group ns=\"robot1\">\n       \
    \ <param name=\"tf_prefix\" value=\"robot1_tf\" />\n        <include file=\"$(find\
    \ your_pkg)/launch/one_robot.launch\" >\n          <arg name=\"init_pose\" value=\"\
    -x 1 -y 1 -z 0\" />\n          <arg name=\"robot_name\"  value=\"Robot1\" />\n\
    \        </include>\n      </group>\n    \n      <!-- BEGIN ROBOT 2-->\n     \
    \ <group ns=\"robot2\">\n        <param name=\"tf_prefix\" value=\"robot2_tf\"\
    \ />\n        <include file=\"$(find your_pkg)/launch/one_robot.launch\" >\n \
    \         <arg name=\"init_pose\" value=\"-x -1 -y 1 -z 0\" />\n          <arg\
    \ name=\"robot_name\"  value=\"Robot2\" />\n        </include>\n      </group>\n\
    \    </launch>\n\nLast thing of course is to include it in your simulation launch\
    \ file:\n\n    <launch>\n      <param name=\"/use_sim_time\" value=\"true\" />\n\
    \    \n      <!-- start world -->\n      <node name=\"gazebo\" pkg=\"gazebo\"\
    \ type=\"gazebo\" \n       args=\"$(find your_pkg)/worlds/your.world\" respawn=\"\
    false\" output=\"screen\" />\n    \n      <!-- start gui -->\n      <node name=\"\
    gazebo_gui\" pkg=\"gazebo\" type=\"gui\" respawn=\"false\" output=\"screen\"/>\n\
    \    \n      <!-- include our robots -->\n      <include file=\"$(find your_pkg)/launch/robots.launch\"\
    />\n    </launch>\n\n## Navigation ##\nFor setting up the navigation stack we\
    \ follow the tutorial [RobotSetup](http://ros.org/wiki/navigation/Tutorials/RobotSetup),\
    \ but we have to add the *namespace* tricks for it.\n\nWe use the same approach\
    \ of splitting files. First the *move_base.launch* for one robot, as from tutorial:\n\
    \n    <launch>    \n      <!--- Run AMCL -->\n      <include file=\"$(find amcl)/examples/amcl_diff.launch\"\
    \ />\n      \n      <!-- Define your move_base node -->\n      <node pkg=\"move_base\"\
    \ type=\"move_base\" respawn=\"false\" name=\"move_base\" output=\"screen\">\n\
    \        <rosparam file=\"$(find your_pkg)/costmap_common_params.yaml\" command=\"\
    load\" ns=\"global_costmap\"/>\n        <rosparam file=\"$(find your_pkg)/costmap_common_params.yaml\"\
    \ command=\"load\" ns=\"local_costmap\" />\n        <rosparam file=\"$(find your_pkg)/local_costmap_params.yaml\"\
    \  command=\"load\" />\n        <rosparam file=\"$(find your_pkg)/global_costmap_params.yaml\"\
    \ command=\"load\" />\n        <rosparam file=\"$(find your_pkg)/base_local_planner_params.yaml\"\
    \ command=\"load\" />\n\n        <remap from=\"map\" to=\"/map\" />\n      </node>\n\
    \    </launch>\n\nThe important note is to notice this remapping at the end. This\
    \ file will be wrapped with \nnamespace so we have to remove namespace from all\
    \ appearances of *map* (there is only one map).\n\nNow we can launch our multiple\
    \ navigation file:\n\n    <launch>\n      <param name=\"/use_sim_time\" value=\"\
    true\"/>\n    \n      <!-- Run the map server -->\n      <node name=\"map_server\"\
    \ pkg=\"map_server\" type=\"map_server\" args=\"$(find your_pkg)/map/map.yaml\"\
    \ >\n        <param name=\"frame_id\" value=\"/map\" />\n      </node>\n    \n\
    \      <group ns=\"robot1\">\n        <param name=\"tf_prefix\" value=\"robot1_tf\"\
    \ />\n        <param name=\"amcl/initial_pose_x\" value=\"1\" />\n        <param\
    \ name=\"amcl/initial_pose_y\" value=\"1\" />\n        <include file=\"$(find\
    \ your_pkg)/launch/move_base.launch\" />\n      </group>\n    \n      <group ns=\"\
    robot2\">\n        <param name=\"tf_prefix\" value=\"robot2_tf\" />\n        <param\
    \ name=\"amcl/initial_pose_x\" value=\"-1\" />\n        <param name=\"amcl/initial_pose_y\"\
    \ value=\"1\" />\n        <include file=\"$(find your_pkg)/launch/move_base.launch\"\
    \ />\n      </group>\n    \n      <node pkg=\"rviz\" type=\"rviz\" name=\"rviz\"\
    \ args=\"-d $(find your_pkg)/config/multi.vcg\"\n       output=\"screen\" />\n\
    \    \n    </launch>\n\nTwo points to mention here.\n\n * Notice the param *frame_id*\
    \ in *map_server* node. By default *frame_id* is set to *map*,\nand as map is\
    \ shared for all robots we need only one map and therefore we have to force\n\
    the *frame_id* to fully-qualified name */map*.\n * Localization made by *amcl*\
    \ need some help in providing the initial position on the map.\nFor this purpose\
    \ we introduce params carrying those values. Amcl node is in the robot namespace\n\
    and those the whole path should be like */robot1/amcl/initial_pose_x*, etc.\n\n\
    ## Hacking ##\nLast thing to do is to correct some plugins for gazebo.\n\n 1.\
    \ *gazebo_ros_laser.cpp* in *gazebo_plugins* package - patch for tf_prefix resolving.\
    \ Already done \nin fuerte, for electric see the ticket: [https://code.ros.org/trac/ros-pkg/ticket/5511](https://code.ros.org/trac/ros-pkg/ticket/5511)\n\
    \ 2. *gazebo_ros_create.cpp* in *turtlebot_gazebo_plugins* - two corrections needed\n\
    \   * remove initial slashes from topics: *cmd_vel*, *odom*,\n*joint_states* (staring\
    \ from line 157), \n   * and replace line 36 to *node_namespaceP_ = new ParamT<std::string>(\"\
    robotNamespace\",\"\",0);*\n\n## Visualization ##\nNow it's time to play around.\
    \ We can send your messages to */robot1/move_base_simple/goal* or via *actionlib*\
    \ to */robot2/move_base/goal*.\n\nIn *rviz* we can add several *Robot models*,\
    \ but we have to remember to put a correct *tf_prefix* for each robot_description:\n\
    \n    Robot Description: robot_description\n    TF Prefix:         robot1_tf\n\
    \nIn *rviz* configuration file we have to modify the topic for actions connected\
    \ to tool buttons (your local vcg file):\n\n    Tool\\ 2D\\ Nav\\ GoalTopic=/robot1/move_base_simple/goal\n\
    \    Tool\\ 2D\\ Pose\\ EstimateTopic=/robot1/initialpose\n\nIf we want to control\
    \ all robots from rviz we need to add more tool buttons as described [here](http://answers.ros.org/question/31559/multiple-goal-buttons-in-rviz)\n\
    \nHave fun."
