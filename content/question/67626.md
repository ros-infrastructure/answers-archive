    Wireless is slow, many images are therefore dropped. This leads to badly synchronized images. RGBDSLAM uses the [approximate time synchronizer](http://www.ros.org/wiki/message_filters/ApproximateTime) to pair color and depth image (and camera info). I assume that the synchronization of the respective images is too bad to find pairs.

    My suggestions:

     - Reduce bandwidth by using the monochrome image instead of rgb-color
     - Reduce bandwidth using [qvga](http://answers.ros.org/question/61689/problem-with-rgbdslam-and-qvga-resolution/) resolution.
     - Avoid the unsynchronized dropping of messages: Write and run a proxy node on the robot that combines color image, depth image and camera info in a custom message and sends that. Then on the other machine, write a proxy that splits the message and sends it again on three topics to rgbdslam. Then either all or nothing is dropped.
