  body_markdown: "You need to tell your compiler where the include files are, since\
    \ they are not in a \"standard\" location.  How you actually do this will depend\
    \ on how you're managing your build (with cmake, make, or just running g++).\n\
    \nEdit:  You're setting the include directory to be\n\n    /opt/ros/fuerte/stacks/navigation/costmap_2d\n\
    \nand in the code you're (presumably) doing\n\n    #include <costmap_2d/costmap_2d_ros.h>\n\
    \nwhich means that the compiler will be looking for the file\n\n    /opt/ros/fuerte/stacks/navigation/costmap_2d/costmap_2d/costmap_2d_ros.h\n\
    \nwhen what you want is\n\n    /opt/ros/fuerte/stacks/navigation/costmap_2d/include/costmap_2d/costmap_2d_ros.h\n\
    \nThe correct include directory is probably \n\n    /opt/ros/fuerte/stacks/navigation/costmap_2d/include\n\
    \nOf course, the include file you're using will include it's own files, and you'll\
    \ have to have the directories for these listed in the CMakelists.txt file, too.\
    \  ROS manages all of this behind the scenes when you build a package.  If you're\
    \ doing it on your own, you'll have to do it by hand (which might be a tedious\
    \ process).\n\nHave you considered building your code with the ROS build tools,\
    \ even though it's not ROS code?  Might be easier if there are a lot of recursive\
    \ dependencies.\n\nEdit 2:\n\nIf you're using `rosmake` (or catkin) to build things,\
    \ then you should also be updating your `manifest.xml` (or catkin equivalent)\
    \ in parallel.  This will resolve all of the locations for you automatically.\
    \  I assumed (perhaps wrongly) in the initial answer that you were just invoking\
    \ `cmake` and `make` yourself.\n"
