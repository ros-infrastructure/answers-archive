    \ I got the same results. However, since all the code from the teb_local_planner\
    \ is commented out, the issue could be related to move_base in general. But besides\
    \ that, I think it is going to be difficult to \nrun the planner at 20 Hz while\
    \ retaining a sufficient resolution of the trajectory (dt_ref) and a good horizon\
    \ length (and lots of obstacles). With some advanced parameter tuning  you could\
    \ have luck, but not generally.\n\nRegarding your second question:\n\nThe velocity\
    \ limit is not related to the navigation stack but to stage.\nStage internally\
    \ specifies velocity limits. Check out the answer [here](http://answers.ros.org/question/99901/parameters-for-move-base-and-ackerman-vehicle-simulated-in-stage/)."
