    \ system dev). That said, I think of a few ways. If OPT-1 works then that might\
    \ be preferrable as it might be extendable at lower cost.\n\nOPT-1. Call Python2\
    \ module/executable from Python3 code. I don't know if there's officially supported\
    \ Pythonic way to do this.\n\nI think finding Python interpreter with specific\
    \ version like 2.7 like this [stackoverflow.com#q27863832](https://stackoverflow.com/questions/27863832/calling-python-2-script-from-python-3)\
    \ should work (I haven't tried). Code copied from the link:\n\n    import execnet\n\
    \    \n    def call_python_version(Version, Module, Function, ArgumentList):\n\
    \        gw      = execnet.makegateway(\"popen//python=python%s\" % Version)\n\
    \        channel = gw.remote_exec(\"\"\"\n            from %s import %s as the_function\n\
    \            channel.send(the_function(*channel.receive()))\n        \"\"\" %\
    \ (Module, Function))\n        channel.send(ArgumentList)\n        return channel.receive()\n\
    \nOPT-2. Separately run Py2 executables/modules and Py3.\n[ROS being distributed\
    \ system (wiki.ros.org/ROS/Introduction)](http://wiki.ros.org/ROS/Introduction#What_is_ROS.3F)\
    \ allows each node/process to communicate over the network, meaning they can be\
    \ started separately. So divide the processes that need to run in Py2 and Py3.\n\
    A challenge is when you're currently using `roslaunch` to start all processes\
    \ by batch. I thought of separating a .launch file into a launch for Py2 and a\
    \ .launch for Py3. However, `roslaunch` starts with the Python version default\
    \ on your environment, and AFAICT there's no good way to start `roslaunch` with\
    \ a Python version that is not default on your environment (related #q340390).\
    \ In this case, I'd try (I haven't tried. Also for readability, I set Py2 is default\
    \ on your environment):\n\n- From all-in-one .launch file, move Py3 portion out.\
    \ Make Py3 portion executable without relying on ROS toolset (roslaunch/rosrun\
    \ etc.)\n- Start .launch file, and maybe wait for a second or so (to wait for\
    \ ROS Master to be available by the roslaunch) separately start Py3 portion."
