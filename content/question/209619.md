  body_markdown: "    -Effort Joint Interface\n    -Velocity Joint Interface\n   \
    \ -Position Joint Interface \n\nFrom the [respective](http://docs.ros.org/indigo/api/hardware_interface/html/c++/classhardware__interface_1_1EffortJointInterface.html)\
    \ [class](http://docs.ros.org/indigo/api/hardware_interface/html/c++/classhardware__interface_1_1VelocityJointInterface.html)\
    \ [documentation](http://docs.ros.org/indigo/api/hardware_interface/html/c++/classhardware__interface_1_1PositionJointInterface.html),\
    \ these interfaces allow reading state and commanding [effort|velocity|position]-based\
    \ joints.\n\nThe same reasoning applies to the actuator-based interfaces. Actuators\
    \ are connected to joints via mechanical transmissions, and you need to use them\
    \ if you want `ros_control` to handle the mapping between joint and actuator spaces.\n\
    \nAs to the [force-torque](http://docs.ros.org/indigo/api/hardware_interface/html/c++/classhardware__interface_1_1ForceTorqueSensorInterface.html)\
    \ and [IMU](http://docs.ros.org/indigo/api/hardware_interface/html/c++/classhardware__interface_1_1ImuSensorInterface.html)\
    \ interfaces, it's also in the docs. You can also [browse the source](https://github.com/ros-controls/ros_control/tree/indigo-devel/hardware_interface)\
    \ and test suite if you need further insights or usage examples."
