I would like to know how several Servers **for the same topic** are handled in ROS2. I do not found answers or examples nor in the documentation, neither along the community.

**USE CASE**

My use case is a kind of Node that consumes a task which consumes a lot of time. Thus, it would be good to have several Nodes of this kind.
This way, when a Client send a Task, only one of the servers will handle it.

**EXAMPLE**

This is not my exact use case, but with an example there is always easier:

*There is a Node kind PrimeCalculator that gets a number and return the Nth prime number.
In the same network there are 2 PrimeCalculators, and every time a Client node ask for the Nth Prime number, one of them (and only one) gets the request and starts processing it.*

**EXPECTED BEHAVIOUR**

Knowing DDS and the ROS2 service architecture, I would expect that every server node will receive and process the request. **However, the desired behaviour would be that only one server listens and process the request.**

**QUESTION**

How ROS2 behaves if 2 servers are listening in the same network in the same topic?
How can I design my ROS2 network to behave as the case described in USE CASE?
