    It's not well, documented, but the [roslaunch.core.Node](https://docs.ros.org/kinetic/api/roslaunch/html/roslaunch.core.Node-class.html) class supports all the same parameters that the `rosrun` and 'roslaunch' commands support.

    So, if you were to launch a node with:

        rosrun mypackage mynode.py _param1:=123 _param2:=abc

    you could do the same thing from Python with:

        import roslaunch

        node = roslaunch.core.Node(
            package='mypackage',
            node_type='mynode.py',
            name='mynode',
            args='_param1:=123 _param2:=abc',
            output='screen')
        launch = roslaunch.scriptapi.ROSLaunch()
        launch.start()
        process = launch.launch(node)
        # do stuff
        process.stop()

    I found a hacky method that works at least in kinetic and possibly a few versions earlier- the [roslaunch api for lunar looks to support arguments properly](http://wiki.ros.org/roslaunch/API%20Usage#Roslaunch_file_with_command_line-style_arguments) so that ought to be used (and hopefully it gets backported).

    (I also described this partially and probably confusingly in https://answers.ros.org/question/10493/programmatic-way-to-stop-roslaunch/)

        import sys
        ...
        # override the sys.argv in roslaunch with our own,
        # make sure there are no blank '' entries
        sys.argv = ['roslaunch', 'foo', 'bar.launch', 'arg1:=234', etc.]
        import roslaunch
        roslaunch.main()

    ([In the api](http://docs.ros.org/kinetic/api/roslaunch/html/index.html) it looks like roslaunch.main(argv) ought to work without the sys.argv overriding, but I think the call to main in `__init__` keeps that from working?)

    It is then possible to put the above into a node and then launch that node like @cerin describes, and furthermore make the list of args set by args from the scriptapi call (though making that generic to any arbitrary arguments to arbitrary launch files is more work again).

  body_markdown: "This answer is for Melodic. You'll need to pass the arguments as\
    \ individual entries in a Python list. To better understand this, take a look\
    \ at the sample code in the API documentation ([roslaunch/API Usage](http://wiki.ros.org/roslaunch/API%20Usage)):\n\
    \n    import roslaunch\n    \n    cli_args = ['/home/mosaic/catkin_ws/src/robot/launch/id.launch','vel:=2.19']\n\
    \    roslaunch_args = cli_args[1:]\n    roslaunch_file = [(roslaunch.rlutil.resolve_launch_arguments(cli_args)[0],\
    \ roslaunch_args)]\n    \n    parent = roslaunch.parent.ROSLaunchParent(uuid,\
    \ roslaunch_file)\n    \n    parent.start()\n\n`cli_args` is simply a Python list\
    \ containing the launch file as list item 0 and arguments after 0, hence `cli_args[1:]`.\
    \ Here's a modified version of their example to illustrate:\n\n    import roslaunch\n\
    \    \n    arg0 = '/home/mosaic/catkin_ws/src/robot/launch/id.launch'\n    arg1\
    \ = 'vel:=2.19'\n    arg2 = 'udp_dest:=192.168.2.100'\n    arg3 = 'mode:=2048'\n\
    \    cli_args = [arg0, arg1, arg2, arg3]\n    roslaunch_args = cli_args[1:]\n\
    \    roslaunch_file = [(roslaunch.rlutil.resolve_launch_arguments(cli_args)[0],\
    \ roslaunch_args)]\n    \n    parent = roslaunch.parent.ROSLaunchParent(uuid,\
    \ roslaunch_file)\n    \n    parent.start()\n\n(Note that you'll have to set the\
    \ `uuid` for this to work. Just look at how they do it earlier in the document.)"
