    The `libgazebo_ros_p3d` plugin as used [here](https://github.com/tu-darmstadt-ros-pkg/taurob_tracker_common/blob/master/taurob_tracker_description/urdf/tracker_chassis.gazebo.xacro.xml#L44) provides ground truth pose information as a [nav_msgs/Odometry](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/jade-devel/gazebo_plugins/src/gazebo_ros_p3d.cpp#L149) message. That topic could be fed into [message_to_tf](http://wiki.ros.org/message_to_tf) or a [robot_localization](http://wiki.ros.org/robot_localization) node to generate the appropriate tf data.

    Another related approach is using the ground truth information as odometry and then just adding a static publisher that publishes a additional identity map->odom transform. This is for instance done here: [spawn_tracker_with_ground_truth.launch](https://github.com/tu-darmstadt-ros-pkg/hector_tracker_launch/blob/master/hector_tracker_sim_launch/launch/spawn_tracker_with_ground_truth.launch#L16), [publish_ground_truth_state.launch](https://github.com/tu-darmstadt-ros-pkg/hector_tracker_gazebo/blob/master/hector_tracker_gazebo_launch/launch/publish_ground_truth_state.launch)
