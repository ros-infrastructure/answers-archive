Generally, what is mentioned about ros master is that it enables the ROS nodes to locate each other.

However, if we do not execute the command `roscore`, we cannot list active topics or the nodes in the system by using following  commands:  `rostopic list`  and `rosnode list`. Why do we have to execute `roscore` to obtain some knowledge about nodes and topics ?

I have read a comment about this. The comment says something like this: 

> The sentence that it enables the ROS nodes to locate one another is a summary. The important thing is actually underlying structure. The nodes have to register master before an execution or communication. In that time, ROS master records which and how many nodes register.

In this sentence, we can find the answer to why the command `rosnode list` does not work before executing `roscore`. Is there anyone who knows the underlying structure and can explain tasks of ROS master in detail ?
