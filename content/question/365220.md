  body_markdown: "Hey, I also encountered the same problem when porting some existing\
    \ code to the ROS `noetic`.\n\nIn my case I had a `launch` file which invoked\
    \ `rqt_gui` with a so-called perspective file, like this:\n\n    <node name=\"\
    rqt_gui\" pkg=\"rqt_gui\" \n\ttype=\"rqt_gui\" respawn=\"false\" \n\targs=\"--perspective-file\
    \ $(find cyton_gamma_300_gazebo)/config/gazebo_effort_controller.perspective\"\
    />\n\n\nThe *perspective file* in turn looked similar to the following:\n\n  \
    \      ..., \"mainwindow\": {\n      \"keys\": {\n        \"geometry\": {\n  \
    \        \"type\": \"repr(QByteArray.hex)\", \n          \"repr(QByteArray.hex)\"\
    : \"QtCore.QByteArray('01d9d')\", \n          \"pretty-print\": \"     :     I\
    \ :     I     \"\n        }, \n        \"state\": {\n          \"type\": \"repr(QByteArray.hex)\"\
    , \n          \"repr(QByteArray.hex)\": \"QtCore.QByteArray('000000ff')\", \n\
    \          \"pretty-print\": \"                 Lrqt_topic__TopicPlugin__1__TopicWidget\
    \          Xrqt_publisher__Publisher__1__PublisherWidget                     \
    \       6MinimizedDockWidgetsToolbar        \"\n        }\n      }, ....\n\nWe\
    \ are interested in the `key`-`value` pairs looking similar to the following:\n\
    \n    \"repr(QByteArray.hex)\": \"QtCore.QByteArray('000000ff')\", \n\nand change\
    \ it to the following:\n\n    \"repr(QByteArray.hex)\": \"b'000000ff'\",\n\nI.e.\
    \ after replacing the value with **only** byte content, like `b'000000ff'` and\
    \ removing `QtCore.QByteArray()` creation, the `rqt_gui` is able to start without\
    \ errors. No patching of `noetic` code required. Hope this helps!"
