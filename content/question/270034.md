  body_markdown: "[UPDATED ANSWER]\n\nHello,\n\nIf you want to update the parameters\
    \ in run-time, you should use the \"dynamic reconfigure\".\n\nBasically, what\
    \ you need is a parameter file, like below:\n**<your_package>/cfg/MyParams.cfg**\n\
    \n    #!/usr/bin/env python\n    PACKAGE = 'my_dyn_rec'\n    \n    from dynamic_reconfigure.parameter_generator_catkin\
    \ import *\n    \n    gen = ParameterGenerator()\n    \n    #list of parameters\n\
    \    gen.add('int_param', int_t, 0, \"description for the integer parameter\"\
    , 50, 0, 100)\n    gen.add('str_param', str_t, 0, \"description for the string\
    \ parameter\", \"Hello world!\")\n    \n    exit(gen.generate(PACKAGE, \"my_dyn_rec\"\
    , \"MyParams\"))\n\nThe node you want to work with the parameters, here is an\
    \ example:\n**<your_package>/src/my_node.cpp**\n\n    #include <ros/ros.h>\n \
    \   \n    #include <dynamic_reconfigure/server.h>\n    #include <my_dyn_rec/MyParamsConfig.h>\n\
    \    \n    void callback(my_dyn_rec::MyParamsConfig &config, uint32_t level) {\n\
    \        ROS_INFO(\"New values: [%d] - [%s]\", config.int_param, config.str_param.c_str());\n\
    \    }\n    \n    int main(int argc, char **argv) {\n        ros::init(argc, argv,\
    \ \"my_node\");\n        \n        dynamic_reconfigure::Server<my_dyn_rec::MyParamsConfig>\
    \ server;\n        dynamic_reconfigure::Server<my_dyn_rec::MyParamsConfig>::Callback\
    \ f;\n        \n        f = boost::bind(&callback, _1, _2);\n        server.setCallback(f);\n\
    \        \n        ros::spin();\n        \n        return 0;\n    }\n\nFinally,\
    \ you CMakeLists.txt must be configured. For this example, this should be enough:\n\
    \n    cmake_minimum_required(VERSION 2.8.3)\n    project(my_dyn_rec)\n    \n \
    \   find_package(catkin REQUIRED COMPONENTS\n      dynamic_reconfigure\n     \
    \ roscpp\n      rospy\n    )\n    \n    generate_dynamic_reconfigure_options(\n\
    \      cfg/MyParams.cfg\n    )\n    \n    include_directories(\n      ${catkin_INCLUDE_DIRS}\n\
    \    )\n    \n    add_executable(my_node src/my_node.cpp)\n    \n    add_dependencies(my_node\
    \ ${PROJECT_NAME}_gencfg)\n    \n    target_link_libraries(my_node\n      ${catkin_LIBRARIES}\n\
    \    )\n\nYou can follow some the tutorials below:\nROS wiki oficial tutorial:\n\

  body_markdown: "I guess your core question is: to dynamically change values in the\
    \ params server, using \"rosparam set XX\" in another terminal works, but using\
    \ \"load XXX.yaml\" doesn't.\nwhy would this happen? you may wondering.. since\
    \ the the documents tell us the \"load XXX.yaml\" is the same as \"rosparam set\
    \ XX\" except for it uses a file the store the values to be set.\n\nI faced the\
    \ exactly the same issue, and here's the findings:\nthe param name will be different\
    \ with different setting method: method_1: write \"load XXX.yaml\" in the launch\
    \ file and start it using the roslauch. method_2  use \"load XXX.yaml\" directly.\
    \ \nfor method_1, the generated param name will have the package name before the\
    \ param name, the exact name will be like: \"pkgname/paramname\" . While with\
    \ method_2, it will be like \"paramname\".\n\ntherefore, your code will likely\
    \ to use the name \"pkgname/paramname\", and after launching, your load params\
    \ in using \"load XXX.yaml\", the loaded name will be \"paramname\", see, they\
    \ are different. that's why your program not reacting to \"load XXX.yaml\".\n"
