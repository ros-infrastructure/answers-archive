  body_markdown: "I don't think you should remove the system cmake. This will only\
    \ lead to the problems you described. Instead, you could simply install your own\
    \ version of cmake and let it override the system cmake.\n\n    cd ~/Downloads/cmake-3.12.0-rc3/\
    \   # or wherever you downloaded cmake\n    ./bootstrap --prefix=$HOME/cmake-install\n\
    \    make \n    make install\n    export PATH=$HOME/cmake-install/bin:$PATH\n\
    \    export CMAKE_PREFIX_PATH=$HOME/cmake-install:$CMAKE_PREFIX_PATH\n\nThe two\
    \ `export` lines make sure that your updated cmake is used instead of the system\
    \ cmake. You have to make sure that those lines are executed whenever you want\
    \ to use the updated cmake. It's probably a good idea to put them into your `.bashrc`."

This identifies several ROS files and deletes them. Having done this before, I can confirm that this command will completely break your ROS distribution, requiring a full reinstall to fix. So my question is: Is there a way to update cmake without removing the previous version or by avoid deleting the ROS files?
