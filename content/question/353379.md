  body_markdown: "This is possible. There are a couple ways to generate the models\
    \ that represent the office building, but models can be combined in a `.world`\
    \ file and fed to Gazebo. The `.world` file specifies the separate models that\
    \ you want included, as well as their poses, so this will allow you to align different\
    \ parts of a building as separate models so long as they are the same scale.\n\
    \nWhen I've done this in the past, my `.world` file has looked like this:\n\n\n\
    \    </sdf>\n         </world>\n    \n           ... scene information, etc. here\
    \ ....\n    \n         <model name=\"building-east\">\n            <pose>-13.970314\
    \ -9.174326 0 0 0 0</pose>\n            <include>\n              <static>true</static>\n\
    \              <uri>3e_real</uri>\n            </include>\n        </model>\n\
    \        <model name=\"building-north1\">\n            <pose>-14.016079 25.839033\
    \ 0 0 0 0</pose>\n            <include>\n              <static>true</static>\n\
    \              <uri>3n_real</uri>\n            </include>\n        </model>\n\
    \      </world>\n    </sdf>\n\nWhere the `uri` names the model resource. By default\
    \ the model is searched for on the `GAZEBO_MODEL_PATH` or `GAZEBO_RESOURCE_PATH`\
    \ environment variables. \n\nThis is touched on in the [roslaunch gazebo tutorial](http://gazebosim.org/tutorials?tut=ros_roslaunch).\n\
    \nTo generate the models of the office building, you can use Gazebo's building\
    \ editor, or use other CAD software and export as a mesh (.dae). You can include\
    \ meshes the same way as models in the above example, and the link above goes\
    \ over that as well."
