  body_markdown: "This is probably because the publisher will publish the msg asynchronously\
    \ and forget about it. What the while loop does is keep publishing the msg again\
    \ and again so the subscribers can listen in on these msgs and get most (if not\
    \ all) of the msgs. You can circumvent this by asking the publisher to [latch](https://wiki.ros.org/roscpp/Overview/Publishers%20and%20Subscribers#line-51)\
    \ the msg. This will ensure the msg gets read in your case. \n\nYour code will\
    \ look something like this: `(notice the '1' after the queue size in the publisher)`\n\
    \n    int main(int argc, char **argv)\n    {\n        ros::init(argc,argv, \"\
    caninterface_node\");\n        ros::NodeHandle nh;\n    \n        ros::Publisher\
    \ publishertocan = nh.advertise<can_msgs::Frame>(\"sent_messages\", 100, 1);\n\
    \    \n        ros::Rate loop_rate(10);\n        int count = 0;\n    \n      \
    \  std::string can_device;\n        nh.param<std::string>(\"can_device\", can_device,\
    \ \"can0\");\n    \n        // Form can msg\n        can_msgs::Frame message;\n\
    \        message.header.frame_id = \"0\";  // \"0\" for no frame.\n        message.header.stamp\
    \ = ros::Time::now();\n        message.is_extended = false;\n        message.is_rtr\
    \ = false;\n        message.is_error = false;\n        message.id = 0x222;\n \
    \       message.dlc = 8;\n        for (uint8_t i=0; i < message.dlc; i++)\n  \
    \      {\n          message.data[i] = i;\n        }\n        // send the can_frame::Frame\

    \        loop_rate.sleep();\n        count++;\n        \n    return 0;\n    }"

  body_markdown: "It most likely is the case that your publisher is publishing your\
    \ message before any subscribers to that message have been connected. It takes\
    \ a \"non-zero\" amount of time for the \"hand-shaking\" to occur through the\
    \ ROS master and between the publisher/subscriber nodes. You can write a section\
    \ of code that will wait for a subscriber, publish the message (to that subscriber)\
    \ then shut down the node. If you immediately shutdown a node after calling publish\
    \ on a publisher it is **not** guaranteed that the message was sent and received\
    \ by the subscriber.\n\nA convenient overload to the `advertise` function provided\
    \ by the `NodeHandle` class allows a client to specify a `SubscriberStatusCallback`\
    \ function pointer that gets called when a new subscriber connects to the publisher\
    \ see the [rosdocs](http://docs.ros.org/en/noetic/api/roscpp/html/classros_1_1NodeHandle.html#ae4711ef282892176ba145d02f8f45f8d).\n\
    \nHere is a simple code example with a `std_msgs/String` topic:\n\n    #include\
    \ <std_msgs/String.h>\n    \n    #include <ros/ros.h>\n    \n    void subscriberConnectCallback(const\
    \ ros::SingleSubscriberPublisher& publisher)\n    {\n      ROS_INFO(\"Super cool\
    \ I got a new subscriber [%s] on the %s topic!\", publisher.getSubscriberName().c_str(),\n\
    \               publisher.getTopic().c_str());\n    \n      // Build the message\
    \ and publish\n      std_msgs::String msg;\n      msg.data = \"super cool\";\n\
    \      publisher.publish(msg);\n    \n      // Signal shutdown\n      ros::shutdown();\n\
    \    }\n    \n    int main(int argc, char* argv[])\n    {\n      ros::init(argc,\
    \ argv, \"test_node\");\n    \n      // Create publisher with private node handle\
    \ and bind callback to handle subscriber connection\n      ros::NodeHandle pnh(\"\
    ~\");\n      ros::Publisher publisher =\n          pnh.advertise<std_msgs::String>(\"\
    chatter\", 1, (ros::SubscriberStatusCallback)subscriberConnectCallback);\n   \
    \ \n      // Spin this node until a shutdown is triggered\n      ros::spin();\n\
    \    \n      return 0;\n    }"
