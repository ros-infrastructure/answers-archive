  body_markdown: "This cannot be done with launchfiles (directly) because the order\
    \ in which nodes are launched is not guaranteed. \nAlso, what it means for a node\
    \ to have \"started\" is not well defined in general: is it when the OS creates\
    \ the process?  it starts executing? registers with the rosmaster? After it sets\
    \ up publishers/subscribers?\n\nFrom http://wiki.ros.org/roslaunch/XML/node:\n\
    > roslaunch does not provide any guarantees about what order nodes start in. This\
    \ is intentional: there is no way to externally know when a node is fully initialized,\
    \ so all code that is launched must be robust to launching in any order. \n\n\
    You may be able to do what you want to do with the roslaunch api http://wiki.ros.org/roslaunch/API%20Usage#roslaunch_API\n\
    although it is (in my opinion) usually easier and preferable to make the nodes\
    \ not depend on start order.\n\nMaking the nodes not depend on startup order is\
    \ really the best option and the proper ROS thing to do. \n \nHowever, if you\
    \ just need a quick hack to get something done (I definitely DO NOT recommend\
    \ this long-term)\n\n1. Write a script (wait.bash) that waits for the node to\
    \ be launched (for example)\n\n        #!/usr/bin/env bash\n        roslaunch\
    \ package with_the_dependee_nodes_that_start_first & \n        until rosnode list\
    \ | grep \"node\"; do\n          :\n        done\n        echo \"done\"\n\n2.\
    \ Write the another launchfile that launches the dependent nodes (that start last)\
    \ and in that\n   launchfile, also set a parameter using the script from part\
    \ 1 as the command attribute:\n\n    < param name=\"node_start\" command=\"$(find\
    \ pkg)/scripts/wait.bash\">  \n\n \n\n3. The parameters are guaranteed to be loaded\
    \ prior to starting any nodes rhttp://wiki.ros.org/roslaunch/XML#Setting_parameters.\
    \  \n\nThus what happens is:\n\n1. The first launchfile, it tries to set the parameter\
    \ node_start by running your script. It can only start the nodes\n   after the\
    \ parameter is set (and hence after the script has completed).\n2. The script\
    \ then runs a launchfile to start the dependee nodes and waits until they have\
    \ \"started\"\n    (at least registered themselves with the rosmaster)\n3. Finally\
    \ the main launchfile begins launching the other nodes\n \n\n\n\n\n\n\n\n\n\n"
