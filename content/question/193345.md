  body_markdown: "Hi, \n\nI watched the ROSCon talk by ahendrix, and tried out few\
    \ different types of network configurations, I guess this might be helpful for\
    \ anyone who is having trouble setting up their own network with ROS. \n\nThings\
    \ needed : \n\n1. A router (DNS server), which is capable of assigning IP addresses.\
    \ \n2. connect all the devices which are part of your ROS ecosystem to this router.\
    \ (also having access to the router homepage can be handy to get the mapping of\
    \ 'devices to their respective IP address' ). if not try to use `$ ifconfig` command\
    \ to find out IP address on each device. \n3. On your **Master Device**, Just\
    \ execute the following commands, Start with  `$ roscore`, now open another terminal,\
    \ and issue the following commands,\n\n   (For eg. Assuming the IP is 192.168.1.10,\
    \ check yours and make suitable changes ) \n    \n  `$ export ROS_IP=192.168.1.10`\
    \ \n    \n   `$ export ROS_MASTER_URI=http://192.168.1.10:11311`\n\n4. Now, On\
    \ your **slave or Client device/s**, get the IP of your slave device/s and issue\
    \ the following commands. Again, assuming your slave IP is 192.168.1.5 (check\
    \ this and modify according to what you get)\n\n   `$ export ROS_IP=192.168.1.5`\n\
    \ \n   `$ export ROS_MASTER_URI=http://192.168.1.10:11311`\n\n**NOTE:** These\
    \ commands are localized to the terminal you are currently working on. So, when\
    \ you want to working on a new terminal make sure you issue these commands again.\
    \ Also, It is not necessary to export your ROS_HOSTNAME. Be sure to export only\
    \ your ROS_IP. This reduces all sort of complications.\n\n   5 . if you have done\
    \ steps 1 to 4 correctly, then there should not be any trouble with your ROS network\
    \ setup. Follow the same pattern in  all your successive  slave device/s.\n\n\
    Some of you might want to setup a direct connection between your PC and say for\
    \ eg, an embedded device like Arduino or Rpi with an Ethernet cable. In that case\
    \ make sure you follow the ROSCon video mentioned above, the last 5 or 7 minutes\
    \ of the talk will give you an Idea as to what is essential for you in your setup.\n\
    \nRegards,\n\nMurali\n            \n\n\n\n\n"

    Following the [this note](http://wiki.ros.org/ROS/EnvironmentVariables#ROS_IP.2BAC8-ROS_HOSTNAME), note that `ROS_HOSTNAME` should take precedence over `ROS_IP`, and you really shouldn't need to set both. Try instead setting `ROS_HOSTNAME` on the RPi to the hostname of the RPi (not the desktop).
