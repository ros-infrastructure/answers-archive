  body_markdown: "Right click in [image_view](http://www.ros.org/wiki/image_view)\
    \ saves the current image in the stream to file. You can use run this node with\
    \ your choice of camera driver to save images at will.\n\nEDIT: There are a number\
    \ of ways in which you can store the image in a computationally efficient manner.\
    \ If possible, try to avoid changing the driver code itself unless absolutely\
    \ necessary. You can try something like:\n\n * Use a usb cam driver that provides\
    \ a nodelet interface. I don't think [usb_cam](http://www.ros.org/wiki/usb_cam)\
    \ supports a nodelet, but I believe [uvc_camera](http://www.ros.org/wiki/uvc_camera)\
    \ does so. \n * Create a nodelet that subscribes to the image stream (sensor_msgs/Image)\
    \ produced by the camera, and an empty message (std_msgs/Empty) on a topic such\
    \ as 'save_image'. Whenever you receive an empty message, you can set a boolean\
    \ flag which saves the image using `cv::imwrite` in the image callback.\n * Launch\
    \ both nodelets in to the same nodelet manager. This should remove any copy costs\
    \ while saving the image. You can then save images by typing the following at\
    \ the command line: `rostopic pub /save_image std_msgs/Empty`\n\nThis should allow\
    \ you to save images programmatically as well if needed."
