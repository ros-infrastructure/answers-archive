 I've wrote a controller code using [ros_control_boilerplate](https://github.com/davetcoleman/ros_control_boilerplate/tree/indigo-devel ) as base, and connected it to the [Roboteq driver](https://github.com/g/roboteq) using ROS topics.
After that, I loaded a [diff_driver_controller](http://wiki.ros.org/diff_drive_controller) and was able to control the robot using twist messages, but looking at the graph generated by rqt_plot, there's a delay of more than 100ms between the twist message (ros_control) and the setpoint message (roboteq driver).

![image description](https://ftp.osuosl.org/pub/ros/download.ros.org/downloads/se_migration/ros/14985745905182186.png)

Both are running on the same machine, and using 100Hz control loop.
Is there any way to identify the bottleneck, so I can fix it? I was expecting a delay of a few ms, at worst.
