  body_markdown: "I personally use the move_base package with ROS Indigo to run both\
    \ Dijkstra and A*. In my launch file i have:\n\n    <!-- Move_Base node -->\n\
    \    <node pkg=\"move_base\" type=\"move_base\" name=\"move_base\" output=\"screen\"\
    \ >\n        <rosparam file=\"/path/to/file/costmap_common_params.yaml\" command=\"\
    load\" ns=\"global_costmap\" />\n        <rosparam file=\"/path/to/file/costmap_common_params.yaml\"\
    \ command=\"load\" ns=\"local_costmap\" />\n        <rosparam file=\"/path/to/file/local_costmap_params.yaml\"\
    \ command=\"load\" />\n        <rosparam file=\"/path/to/file/global_costmap_params.yaml\"\
    \ command=\"load\" />\n        <rosparam file=\"/path/to/file/base_local_planner_params.yaml\"\
    \ command=\"load\" />    \n    </node>\n\nInside **base_local_planner_params.yaml**\
    \ I specify\n\n    # Global Planner Parameters\n    BaseGlobalPlanner:\n     \
    \ allow_unknown: false\n      use_dijkstra: false #Use A* instead\n      use_quadratic:\
    \ true\n      use_grid_path: false\n      old_navfn_behavior: false\n\nThe use_dijikstra\
    \ parameter is the one that specifies whether A* or Dijkstra will be used. \n\n\
    **IMPORTANT NOTES:**  \n1) ROS indigo uses navfn by default, which can only do\
    \ Dijkstra. In order to use A* you must download global_planner.  \n2) Once things\
    \ are setup you should verify that the parameters are actually getting loaded\
    \ correctly by using rosparam. This type of thing won't give you an error and\
    \ so you could be using Dijkstra for a long time while thinking that your actually\
    \ using A*.    \n3) If the parameters aren't being loaded correctly, the first\
    \ thing I usually check is the namespaces (ns). They can be tricky."
