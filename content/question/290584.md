  body_markdown: "If I remember correctly, the NX100 does not support running MotoPlus\
    \ applications, and the MotoROS is a MotoPlus application. That means the NX100\
    \ is not supported.\n\n---\n\nEdit: just found [this old thread](https://groups.google.com/d/msg/swri-ros-pkg-dev/QmMVGWsKTI0/HoKEnGDL1GUJ)\
    \ in the ROS-Industrial Google Group archives. Ted Miller (one of the MotoROS\
    \ devs from Yaskawa) writes this:\n\n> Unfortunately, the NX100 is limited in\
    \ its communication abilities.  As Eric mentioned, you have to use the Data Transmission\
    \ function.  Another option is to use the MotoCom32 library.  This is a Win32\
    \ SDK (with examples and docs) that wraps around the DataTransmission function\
    \ and exposes some higher-level API calls.  However, each runtime copy requires\
    \ a license and hardware dongle.  If you implement the protocol directly, it does\
    \ not require a runtime license.\n \n> The only other option is the RS232 serial\
    \ interface.  However, this is even slower than the ethernet commands and gives\
    \ you less functionality.\n \n> If you need ROS for your controller, I would recommend\
    \ upgrading to an FS100 controller (or DX100).\n\n---\n\nEdit2:\n\nMy above answer\
    \ was with respect to whether MotoROS supports your controller. That would allow\
    \ you to do on-line motion control of your robot from ROS. There are other options,\
    \ but those would not be real-time.\n\n> Would ROS allow me to write a program\
    \ for my robot on my PC and upload it to the robot?\n\nThis is possible/feasible,\
    \ but will require you to do some work (ie: develop some software). A special\
    \ component could accept `JointTrajectory` action goals (for instance) and convert\
    \ those to INFORM code. That code could then be uploaded to the controller (using\
    \ fi the functionality Ted Miller describes in his reply on the Google Group thread)\
    \ and executed.\n\nThis would probably introduce quite some delay and would not\
    \ be on-line/real-time-ish control. But it could be one way in which you could\
    \ use ROS to do trajectory planning and all sorts of other things and then transfer\
    \ the result to the NX100.\n\n> Does ROS support vision systems for sensing with\
    \ the NX100?\n\nThis I don't know, but my immediate guess would be: no."
