Using ROS2

 I’m trying to implement a ROS interface for a robot simulator. It can have lots of robots, and I want to receive their goal through the same action server, changing just the name of the robot in the goal.

The execution of each goal takes some time, and there could be lots of goals running.
The simulator already has an event loop and I’m doing **spin_once** in each step of the simulation.

But sounds like that the **execute_callback** of the action server should be running till the robot completes the mission, the problem is that the simulator already “moves” the robot in it steps and I don’t need to have another callback running till the robot arrives, I just need to add an event to the event loop and when the robot arrives send the result to the client.

What I did was to add the event to the event loop in the **handle_accepted_callback** and to call the **execute_callback** when the robot arrives.
That doesn’t sounds good because the **execute_callback** is not “executing”, it’s just returning the result.

I’ve read here that the single thread executor runs the callbacks in round robin, but I coundn’t find how this works.
Another thing I’ve read is that I could create my own executor, is that helpful in my case?
