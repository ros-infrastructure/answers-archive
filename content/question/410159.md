  body_markdown: "To summarize the cause of the two issues, in case others come across\
    \ this question in the future:\n\n1) `ros2_control`/`gazebo` trying to load a\
    \ controller multiple times \n\nThis shouldn't happen, and in this case was caused\
    \ by multiple launch files loading the controllers.\n\n2) \"Command interface\
    \ with 'front_left_steering_joint/velocity' does not exist\"; \n\nYour controller\
    \ is looking for a `velocity` **control** interface for joint `front_left_steering_joint`,\
    \ but your `<ros2_control>` tag in your URDF is telling the `controller_manager`\
    \ that your \"hardware\" only supports `position` control for this joint. The\
    \ `diff_driver_controller` currently only supports `velocity` *commands* to the\
    \ wheels, and accepts `position` or `velocity` state interfaces (you can take\
    \ a look at the source [here for reference](https://github.com/ros-controls/ros2_controllers/blob/foxy/diff_drive_controller/src/diff_drive_controller.cpp#L115-L127)).\
    \ \n\n    <ros2_control name=\"GazeboSystem\" type=\"system\">\n      <hardware>\n\
    \        <plugin>gazebo_ros2_control/GazeboSystem</plugin> \n      </hardware>\n\
    \        <joint name=\"front_left_steering_joint\">\n          <command_interface\
    \ name=\"position\"/> <------------------- here\n          <state_interface name=\"\
    position\"/>\n          <state_interface name=\"velocity\"/>\n          <state_interface\
    \ name=\"effort\"/>\n        </joint>\n\nSince this is a gazebo question, you\
    \ can resolve this by simply changing `front_left`, `front_right`, `rear_left`\
    \ and `rear_right` joints to be `velocity` controlled in the `<ros2_control>`\
    \ block of your URDF.\n\nAll that said, based on the naming convention you used,\
    \ it sounds like you want those to be steerable joints. Perhaps you want to consider\
    \ implementing an `Ackermann` controller or similar. The `ros2_controllers` repo\
    \ has a [tricycle_controller](https://github.com/ros-controls/ros2_controllers/tree/master/tricycle_controller)\
    \ which you may find to be a good starting point. Alternately, you could take\
    \ a crack at porting either the ros1 [ackermann_controller](https://github.com/ros-controls/ros_controllers/tree/noetic-devel/ackermann_steering_controller)\
    \ or this [swerve_steering_controller](https://discourse.ros.org/t/independent-swerve-steering-controller-for-ros-control/21534/23)\
    \ to ros2. \n"

    def generate_launch_description():

        # Launch args
