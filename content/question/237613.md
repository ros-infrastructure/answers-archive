    No ROS distribution officially supports Python 3. ROS Kinetic uses Qt 5 though, e.g. for `rqt` and `rviz`.

    If you want to try it anyway you need to build everything from source (following the "normal" from source instructions). But before you will need to install all Python dependencies (e.g. `catkin_pkg`) for Python 3. Since the Debian packages are not side-by-side installable with the Python 2 version using a `virtualenv` will likely be the easiest way. The `virtualenv` will also ensure that `python` is pointing to a Python 3 interpreter. Otherwise you would need to pass a custom interpreter to the build (like `-DPYTHON_EXECUTABLE=python3`).

    Anyway if you go that route you should expect problems and will find things which simply don't work with Python 3.

    **Update:**

    things are changing with the Noetic release coming up in less than a year which does target Python 3. Please see the latest instructions in the wiki about the topic: http://wiki.ros.org/UsingPython3

    The situation changed slightly over the last two years.
    You can compile a complete ROS distribution (I tried kinetic) with

    ```
    catkin build --cmake-args -DPYTHON_VERSION=3.6
    ```

    assuming you setup a whole core workspace with something like

    ```
    rosinstall_generator --rosdistro kinetic desktop_full
    ```

    This works more or less for the core ROS system.
    I just filed a few patches to make it even work with MoveIt.

    However, Dirk's comment is still true. Sadly even in ROS-melodic (which very few people are using already)
    there is [no enforced python3 support](http://www.ros.org/reps/rep-0003.html#melodic-morenia-may-2018-may-2023). By now, this is simply hilarious. But ROS2 will of course make everything better... :/

    I had to fix a few lines of code in a number of packages I use myself (including tf), but they are all straight-forward
    python2-3 compatibility issues that are well documented.

    So everyone, feel free to try it out and file patches if you find more python2-only code somewhere!
    We are not that far away from Python3 support anymore.

  body_markdown: "This will likely become obsolete with the release of Noetic, but\
    \ as I've just had to build a version of Kinetic with Python 3 support (for the\
    \ Nth time), I figured I'd post the commands I've used here (for myself as well).\n\
    \nThis is a more copy-pastable version of @v4hn's answer (but was too long for\
    \ a comment).\n\nAssumptions:\n\n - OS: Ubuntu Xenial (16.04)\n - ROS Kinetic\
    \ is already installed on that system (the `.deb` distributed version)\n\nI always\
    \ use a virtual environment, as it's typically the case that besides ROS, there\
    \ are Python modules that need to be installed one might not want to \"pollute\"\
    \ the system with.\n\nNotes:\n\n 1. this only builds a bare-bones ROS Kinetic\
    \ with Python 3. No Open CV or other 'complex' packages/nodes. For many use-cases\
    \ this is already quite sufficient though.\n 1. as such, this is not an answer\
    \ to the general problem of how to build all of ROS 1 with Python 3 support.\n\
    \nIn any case, as follows:\n\n    # create a place for our Python3-ROS-Kinetic\
    \ to live\n    mkdir $HOME/rospy3_kinetic\n    cd $HOME/rospy3_kinetic\n    \n\
    \    # make sure these are installed\n    apt install python3-venv libpython3-dev\
    \ python-catkin-tools\n    \n    python3.5 -m venv venv3.5_ros\n    source venv3.5_ros/bin/activate\n\
    \    \n    # these modules are needed but are not automatically installed\n  \
    \  pip3 install wheel empy defusedxml netifaces\n    \n    # just the standard\
    \ build-ros-from-source dependencies\n    pip3 install -U rosdep rosinstall_generator\
    \ wstool rosinstall\n    \n    # seed the workspace with a 'ros_base' set of packages\n\
    \    rosinstall_generator --deps --tar --rosdistro=kinetic ros_base > ros_base.rosinstall\n\
    \    wstool init src -j8 ros_base.rosinstall\n    \n    # the following is somewhat\
    \ optional: I like to run this to see if\n    # something obvious is missing,\
    \ but we can't ask rosdep to 'install'\n    # things for us: it will try to use\
    \ apt to install the Python 2 version\n    # of all dependencies it sees missing.\n\
    \    \n    # this may fail if you already have done this, in that case: ignore\n\
    \    sudo rosdep init\n    rosdep update\n    \n    # I use check here to first\
    \ see what is missing. If missing dependencies are\n    # serious enough, use\
    \ 'pip3' to install into the virtual environment for\n    # Python dependencies,\
    \ 'apt' for any other dependencies\n    rosdep check --from-paths src/ -i\n  \
    \  \n    # finally build the workspace, while:\n    #  - disabling testing globally\n\
    \    #  - making sure optimisations are enabled ('Release' build type)\n    #\
    \  - forcing use of Python 3.5\n    catkin build -DCATKIN_ENABLE_TESTING=0 -DCMAKE_BUILD_TYPE=Release\
    \ -DPYTHON_VERSION=3.5\n\nAt this point `source` the `setup.bash` of the workspace.\
    \ You may choose to configure `catkin_tools` to create an install space instead\
    \ of using the devel space directly.\n\nFor regular usage you'll need to make\
    \ sure to have the virtual environment activated, or things will break.\n\nI'd\
    \ recommend using [workspace overlaying](http://wiki.ros.org/catkin/Tutorials/workspace_overlaying)\
    \ for actual development."
