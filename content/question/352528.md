  body_markdown: "I finally get it...\n\nThe [RMW_INTERFACE_FN](https://github.com/ros2/rmw_implementation/blob/master/rmw_implementation/src/functions.cpp#L144)\
    \ macro creates a function that implements each of the rmw functions and a pointer\
    \ to the shared library function symbol_{function_name}, based on the list of\
    \ functions directly below it. Each function expands the CALL_SYMBOL macro inside\
    \ of it.\n\nThe the CALL_SYMBOL macro will get the pointer to the function in\
    \ the shared library with get_symbol() and assign the address to the pointer.\
    \ If no matching symbol is found, an error is returned. If the symbol is found,\
    \ it will call the shared library function. \n\nget_symbol() will get a reference\
    \ to the shared library, via get_library() which loads the .so file based on the\
    \ RMW_IMPLEMENTATION environment variable. \n\nrmw_init() was hijacked to 'prefetch'\
    \ all of the other functions in the library before calling the real rmw_init()\
    \ function. There's a comment that this was done to avoid a race condition due\
    \ to allocating an std::string. This is what made me mistakenly think that rmw_init()\
    \ was responsible for loading all the symbols. \n\nCase Closed. :)\n"

I'm trying to understand how the DDS shared library is loaded by rclpy->rcl->rmw, and have hit a stumbling point:

It appears that [rclpy_init()](https://github.com/ros2/rclpy/blob/master/rclpy/src/rclpy/_rclpy.c#L587) calls [rcl_init()](https://github.com/ros2/rcl/blob/master/rcl/src/rcl/init.c#L213) which calles [rmw_init()](https://github.com/ros2/rmw_implementation/blob/master/rmw_implementation/src/functions.cpp#L658) and that function will load the shared library.

My confusion is that [two lines above](https://github.com/ros2/rclpy/blob/master/rclpy/src/rclpy/_rclpy.c#L585) the call to rcl_init();   It appears that [rcl_init_options_init()](https://github.com/ros2/rcl/blob/master/rcl/src/rcl/init_options.c#L52)  calls [rmw_init_options_init()](https://github.com/ros2/rmw/blob/master/rmw/include/rmw/init_options.h#L104) which is located in the shared library, *that shouldn't be loaded yet...*

What am I missing here?

I think I confirmed that the shared library is loaded before reaching rmw_init by placing some log_info() statements in rmw_fastrtps_shared_cpp / rmw_init_options_init().
