  body_markdown: "From commandline, you can run your script on debugger by:\n\n  \
    \  $ roscd %YOUR_PKG_HOME%\n    $ gdb python\n    $ run %YOUR_SCRIPT_PATH%\n\n\
    If you'd prefer to sticking to `eclipse`, one dumb workaround to utilize `make`\
    \ solution on wiki is:\n\n1 Install `pydev` on eclipse, create your `python` project\
    \ on eclipse by \"File\" --> \"New\" --> \"Pydev Project\". When successful, close\
    \ eclipse.\n\n2 Copy the `.project` file that was just generated by eclipse. Eg.\
    \ by doing:\n\n    $ roscd %YOUR_PKG_HOME%\n    $ cp .project .project.org\n\n\
    3 Run `make eclipse-project` following http://www.ros.org/wiki/IDEs#Eclipse. If\
    \ you don't have `Makefile` in the current dir, create one as the same wiki page\
    \ suggests when error occurs.\n\n4 Swap .project and remove .cproject:\n\n   \
    \ $ mv .project.org .project \n    $ rm .cproject\n\nThis sets up ROS python environment\
    \ on eclipse. You should be able to run your ROS script in debug mode.\n\nApparently\
    \ this is not smart and ideal, but works for me.\n\nThis works even on Groovy\
    \ where `make eclipse-project` generates many unnecessary files & directories.\
    \ In this case you might want to remove them & `Makefile` you no longer need by\
    \ like:\n\n    $ rm -fR catkin* CATKIN_IGNORE cmake_install.cmake devel/ gtest/\
    \ Makefile test_results/"
