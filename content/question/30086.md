  body_markdown: "I had the same issue with my own URDF model and finally I could\
    \ solve it. The robot_state_publisher needs basically only two information to\
    \ run:\n\n 1. A URDF model in XML format on the parameter server. The default\
    \ parameter is: /robot_description\n 2. A msg of the type *sensor_msgs::JointState*\
    \ on the topic */joint_states*\n\nI found this information in the [FAQ of tf](http://wiki.ros.org/tf/FAQ)\n\
    \nThe important information I forgot first by sending out my /joint_state msg\
    \ is the timestamp in the msg header! Without the time information the robot_state_publisher\
    \ is not able to calculate the tf frames for the moving joints. Inside of the\
    \ code this means the following for me:\n\n    // Setup the publisher for the\
    \ /joint_states msg\n    ros::Publisher pub_js = nh.advertise<sensor_msgs::JointState>(\"\
    /joint_states\", 100);    \n    sensor_msgs::JointState msg;            // Create\
    \ an object of the sensor_msgs::JointState\n    \n    msg.name.push_back(\"My_Joint_Name\"\
    );    // This must be the joint_name that is used inside of the URDF file\n  \
    \  msg.position.push_back(0.0);            // Set a value for this joint\n   \
    \ \n    msg.header.stamp = ros::Time::now();    // Stamp this message with the\
    \ actual time\n    pub_js.publish(msg);                    // Publish the message\n\
    \nI hope this will solve your problem as well! "
