  body_markdown: "Hi @ridwan,\n\nThe answer for your question is a bit long. \n\n\
    What you want is to generate a custom `robot_description` that can be used in\
    \ the Gazebo simulator. For this you will need to start learning about what a\
    \ `robot_description` is and how to generate one that can be used in simulation.\
    \ For this first step you can start learning about the [URDF](http://wiki.ros.org/urdf),\
    \ \"Unified Robot Description Format\" that is basically a specific format to\
    \ describe how your robot looks like. With respect this topic, you should know\
    \ that Gazebo works with its own description format, that is [SDF](http://sdformat.org/spec)\
    \ and that the URDF can be translatable to the native Gazebo format. With the\
    \ URDF you will be able to genereate all the `links` corresponding to your robot\
    \ body and all the `joints` that will help you to control it and define how each\
    \ `link` is joined and behaves. There is a nice tutorial about using URDF in Gazebo\
    \ [here](http://gazebosim.org/tutorials?tut=ros_urdf) and a huge set of ROS tutorials\
    \ that works on this [here](http://wiki.ros.org/robot_model/Tutorials).\n\nFurthermore,\
    \ when dealing with URDF you will realise that there is too much code and your\
    \ description can be a mess, for this issue, ROS has a handy XML format named\
    \ [Xacro](http://wiki.ros.org/xacro) that allows you to generate a URDF description\
    \ from a set of macros. For instance, if you have four wheels, instead of using\
    \ 4 URDF wheels descriptors, you can use only one Xacro macro defining a wheel\
    \ and instantiate 4 times the wheel to keep the code clean and organized. There\
    \ is another nice tutorial about this topic [here](http://wiki.ros.org/urdf/Tutorials/Using%20Xacro%20to%20Clean%20Up%20a%20URDF%20File).\n\
    \nOnce you have your `robot_description` you will need to decide how to control\
    \ your simulated robot. There are several approachs, here I comment two:\n\n 1.\
    \ You can use a Model [plugin](http://gazebosim.org/tutorials?tut=plugins_model&cat=write_plugin).\
    \ Since you mentioned your robot has 4 wheels, you can implement your own plugin\
    \ with the proper kinematics or use the Skid Steering Drive [plugin](http://gazebosim.org/tutorials?tut=ros_gzplugins#SkidSteeringDrive)\
    \ from Gazebo that is already implemented.\n 2. Another approach is based on using\
    \ ROS [control](http://wiki.ros.org/ros_control). For which you will need to set\
    \ up proper transmissions and PID gains for effort/speed/position controllers.\
    \ You can check this tutorial about Gazebo interactions with ROS control [here](http://gazebosim.org/tutorials/?tut=ros_control).\n\
    \nSo there you have it, hope this can help you with your tasks.\n\nRegards.\n\n"

      @Weasfas,
      I plugin this:
        <gazebo>

            <plugin name="skid_steer_drive_controller" filename="libgazebo_ros_skid_steer_drive.so">

          <updateRate>100.0</updateRate>
          <robotNamespace>/</robotNamespace>
          <leftFrontJoint>joint_left_wheel_front</leftFrontJoint>
          <rightFrontJoint>joint_right_front_wheel</rightFrontJoint>
          <leftRearJoint>joint_left_wheel</leftRearJoint>
          <rightRearJoint>joint_right_wheel</rightRearJoint>
          <wheelSeparation>0.4</wheelSeparation>
          <wheelDiameter>0.2</wheelDiameter>
          <robotBaseFrame>link_chassis</robotBaseFrame>
          <torque>20</torque>
          <topicName>cmd_vel</topicName>
          <broadcastTF>false</broadcastTF>
        </plugin>
