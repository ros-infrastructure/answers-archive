  body_markdown: "The rosjava implementation used in the android sensors app is broken\
    \ and is not properly embedding the message definitions in the message stream.\
    \ rosbag then doesn't know how what a std_msgs message type is inside the bagfile.\
    \ UGH! \n\nMy work around was to play the messages with 'rosbag play /android/imu'\
    \ and then echo the messages to a text file with 'rostopic echo /android/imu >\
    \ imu.txt'. rostopic doesn't use the message type information located withing\
    \ the topic stream, but rather uses the compiled libraries, so this works. \n\n\
    Then I convert the text file to a csv file with this ugly shinanigans:\n\n   \
    \ #!/bin/bash\n    \n    cp $1 a\n    \n    tr -d \"[a-z:_/ ,]\" < a > b\n   \
    \ sed 's/0.00.00.00.00.00.00.00.00.0//' b > a\n    tr  -s \"\\n\" \",\" < a >\
    \ b\n    sed 's/,---,/#/g' b > a\n    tr  \"#\" \"\\n\" < a > b\n    sed 's/^,//g'\
    \ b > a\n    \n    cp a $2\n    rm a b\n\nSave it as a script and run it with\
    \ './script.bash imu.txt imu.csv' to convert imu.txt to a csv file."
