On ROS2 Foxy, it seems rclcpp nodes create log files in ~/.ros/log. Is there any way to disable this file logging, but still log to stdout/stderr and /rosout?

The reason I want to do this is because I am running ROS2 on an embedded system and nodes should run for weeks or months, and I will need to rotate the log files occasionally because storage space is at a premium. Journald is a good way to do this, and is well documented. When ROS2 nodes are run under systemd, the stdout/stderr logging is enough to get everything working as I want it. I could delete the .ros/log directory every now and again on a cron job, but this feels like a hack. I would also like to minimize the amount of eMMC thrashing.

[Here](https://answers.ros.org/question/9627/how-can-i-completely-disable-writing-logs-to-filesystem/) is a similar question for ROS 1, but the answer was fairly unsatisfactory. I was hoping ROS2 would be more geared toward production systems and thus would support this out of the box.

The [concept page on logging](https://index.ros.org/doc/ros2/Concepts/About-Logging/) mentions very little and the [logging tutorial](https://index.ros.org/doc/ros2/Tutorials/Logging-and-logger-configuration/) mentions how to change the log dir, but not how to disable it. Also, this functionality only works on Galactic.

It seems this file logging feature is actually relatively new, [here](https://discourse.ros.org/t/what-is-the-log-mechanism-plan-in-ros2/4074) is a discussion on adding the file logging feature from 2019. In this discussion, wjwwood mentioned
> For production system [logging to systemd] makes sense though, and because of that it should be possible to disable file logging in favor of just printing to stdout/stderr.

[Here is a long discussion on logging](https://discourse.ros.org/t/ros2-logging/6469/34) and the linked comment discusses modifying the `rcl_logging_spdlog` package is the way to go. [This question](https://answers.ros.org/question/366350/is-it-possible-to-change-the-logger-without-building-ros-packages-ros2/) confirms that recompiled is required. This seems like the best option for me right now? Looking at the [default spdlog logger](https://github.com/ros2/rcl_logging/blob/foxy/rcl_logging_spdlog/src/rcl_logging_spdlog.cpp) it looks like it doesn't support an external config file yet, but I guess this could be the way to go in the future.
