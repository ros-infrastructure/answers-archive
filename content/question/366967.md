  body_markdown: "The `optenv` qualifier points to environmental variables as mentioned\
    \ in the [`roslaunch` documentation](http://wiki.ros.org/roslaunch/XML).  There's\
    \ no way to set an environmental variable from the `include` tag AFAIK, but someone\
    \ can correct me if I'm wrong.  In any case, I don't think that would get you\
    \ the behavior you want.  The syntax is `$(optenv VARIABLE_NAME default_value)`,\
    \ so if the variable is set, it will use that value everywhere.  As you're using\
    \ the lidar macro twice, the variables are used in multiple places and won't have\
    \ different values.\n\nOne option is to leave `sick_lms1xx_mount.urdf.xacro` alone\
    \ and put in some \"dummy\" joints/links to get the orientation you want, which\
    \ in your case might look similar to this:\n    \n    # robot, namespace stuff,\
    \ etc.\n    ...\n    # Note: you only have to include the lidar macro file (sick_lms1xx_mount.urdf.xacro)\
    \ once.\n    <xacro:include filename=\"$(find jackal_description)/urdf/accessories/sick_lms1xx_mount.urdf.xacro\"\
    \ />\n\n    <link name=\"base_link\" />\n\n    <joint name=\"base_front_joint\"\
    \ type=\"fixed\">\n      <origin xyz=\"0.1 0 0\" rpy=\"0 0 0\" />  # Puts it 10\
    \ cm forward.\n      <parent link=\"base_link\" />\n      <child link=\"front_link\"\
    \ />\n    </joint>\n\n    <link name=\"front_link\" />\n\n    <xacro:sick_lms1xx_mount\
    \ prefix=\"front\"\n                             parent_link=\"front_link\"\n\
    \                             topic=\"front_lidar_scan\"/>\n\n    <joint name=\"\
    base_rear_joint\" type=\"fixed\">\n      <origin xyz=\"-0.1 0 0\" rpy=\"0 0 ${-pi}\"\
    \ />  # Puts it 10 cm back and spins it 180 deg.\n      <parent link=\"base_link\"\
    \ />\n      <child link=\"rear_link\" />\n    </joint>\n\n    <link name=\"rear_link\"\
    \ />\n\n    <xacro:sick_lms1xx_mount prefix=\"rear\"\n                       \
    \      parent_link=\"rear_link\"\n                             topic=\"rear_lidar_scan\"\
    />\n    ...\n\nYou may note that there's repetition there, so you could create\
    \ your own macro for adding the lidar(s), which includes the pose parameters as\
    \ arguments:\n\n    <xacro:include filename=\"$(find jackal_description)/urdf/accessories/sick_lms1xx_mount.urdf.xacro\"\
    \ />\n    <xacro:macro name=\"sick_lm1xx\" params=\"prefix parent topic xyz rpy\"\
    \ />\n      <joint name=\"base_${prefix}_joint\" type=\"fixed\">\n        <origin\
    \ xyz=\"${xyz}\" rpy=\"${rpy}\" />  # Puts it 10 cm forward.\n        <parent\
    \ link=\"${parent}\" />\n        <child link=\"${prefix}_link\" />\n      </joint>\n\
    \n      <link name=\"${prefix}_link\" />\n\n      <xacro:sick_lms1xx_mount prefix=\"\
    ${prefix}\"\n                               parent_link=\"${prefix}_link\"\n \
    \                              topic=\"${topic}\"/>\n    </xacro:macro>\n    \n\
    \    <link name=\"base_link\" />\n\n    <xacro:sick_lm1xx prefix=\"front\"\n \
    \                     parent=\"base_link\"\n                      topic=\"front_lidar_scan\"\
    \n                      xyz=\"0.1 0 0\"\n                      rpy=\"0 0 0\" />\n\
    \n    <xacro:sick_lm1xx prefix=\"rear\"\n                      parent=\"base_link\"\
    \n                      topic=\"rear_lidar_scan\"\n                      xyz=\"\
    -0.1 0 0\"\n                      rpy=\"0 0 ${-pi}\" />\n\nAt this point you may\
    \ as well write your own version of the original macro with `xyz` and `rpy` parameters\
    \ and use that instead.  The [source](https://github.com/jackal/jackal/blob/melodic-devel/jackal_description/urdf/accessories/sick_lms1xx_mount.urdf.xacro)\
    \ is in the Jackal GitHub repo."

I am trying to include 2 LiDAR units in a `.xacro` file by including the file [here](https://github.com/jackal/jackal/blob/melodic-devel/jackal_description/urdf/accessories/sick_lms1xx_mount.urdf.xacro) twice. Here's the code I use:

    <?xml version="1.0"?>
    <robot xmlns:controller="http://playerstage.sourceforge.net/gazebo/xmlschema/#controller"
           xmlns:interface="http://playerstage.sourceforge.net/gazebo/xmlschema/#interface"
           xmlns:sensor="http://playerstage.sourceforge.net/gazebo/xmlschema/#sensor"
           xmlns:xacro="http://www.ros.org/wiki/xacro"
           name="sensors">
    
      <!-- Front LiDAR  -->
    
      <xacro:include filename="$(find jackal_description)/urdf/accessories/sick_lms1xx_mount.urdf.xacro" />
      <xacro:sick_lms1xx_mount prefix="$(optenv JACKAL_LASER_MOUNT front)"
                               parent_link="$(optenv JACKAL_LASER_MOUNT front)_mount"
                               topic="$(optenv JACKAL_LASER_TOPIC /front_lidar_scan)"/>
    
      <!-- Rear LiDAR  -->
    
      <xacro:include filename="$(find jackal_description)/urdf/accessories/sick_lms1xx_mount.urdf.xacro" />
      <xacro:sick_lms1xx_mount prefix="$(optenv JACKAL_LASER_MOUNT rear)"
                               parent_link="$(optenv JACKAL_LASER_MOUNT rear)_mount"
                               topic="$(optenv JACKAL_LASER_TOPIC /rear_lidar_scan)"/>                           
    </robot>

This works but I need one LiDAR unit to be oriented in the opposite direction. In the included file this segment below, it suggests I could set `JACKAL_LASER_RPY` but I can't work out how to do this from my file above. Could anyone show me how? I've been searching how I might be able to set `rpy` within the `include` tags but it seem that this isn't possible.

    <joint name="${prefix}_laser_mount_joint" type="fixed">
      <origin xyz="$(optenv JACKAL_LASER_OFFSET 0 0 0)"
              rpy="$(optenv JACKAL_LASER_RPY 0 0 0)" />
      <parent link="${parent_link}" />
      <child link="${prefix}_laser_mount" />
    </joint>
