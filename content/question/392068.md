  body_markdown: "A newbee like me might find this answer helpful. \n\nAfter some\
    \ debugging I have figured out the way to communicate different nodes over dds.\n\
    ```\nRMW_IMPLEMENTATION=rmw_fastrtps_cpp ROS_DOMAIN_ID=<id> ros2 run <package>\
    \ <application>\n```\nThis will run the ROS2 node on the fastrtps DDS. To establish\
    \ pub/sub communication between two nodes we have to use the same ROS_DOMAIN_ID.\
    \ As fastrtps is the default dds middleware for ROS2 so we do not have to install\
    \ it seperately. If anyone has to use other dds middleware he/she has to download\
    \ the desired dds middleware and replace it in the ``` RMW_IMPLEMENTATION=<desired_dds>```\n\
    \nIf the ROS2 nodes are in different DOMAIN, then **Integration-service** is there\
    \ to save us. Please check this links. [ROS2-FASTDDS](https://fast-dds.docs.eprosima.com/en/latest/fastdds/ros2/ros2.html),\
    \ [Integration-Service](https://integration-service.docs.eprosima.com/en/latest/installation_manual/installation.html),\
    \  [ROS2-Different-Domain-Communication](https://integration-service.docs.eprosima.com/en/latest/examples/same_protocol/ros2_change_domain.html)\n\
    \nThe transformation of ROS2 topic and DDS idl are handled by the integration-service.\
    \ [This example](https://github.com/eProsima/Integration-Service/blob/main/examples/basic/ros2_server__addtwoints.yaml#L17)\
    \ can be a good starting point.\n\nIf anyone has to compile their own ROS2 msg/service/interfaces\
    \ and generate mix files to use in the integration-service please check this,\
    \ [ROS2-System-handle.](https://github.com/eProsima/ros2-SH)"
