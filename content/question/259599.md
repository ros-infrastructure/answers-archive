  body_markdown: "Humplestilzzchen - no need to fork, Karl was spot on\n\nYou can\
    \ control the planar slice in the z-axis with the frame you output to via the\
    \ target_frame param. In my case I was looking for objects at 6ft high so I created\
    \ a static transform in my launch file:\n\n```\n<arg name=\"laser_height\" default=\"\
    1.829\" /> <!-- 1.829m == 6ft -->\n<node pkg=\"tf\" type=\"static_transform_publisher\"\
    ' name=\"laser_height_offset\" args=\"0 0 $(arg laser_height) 0 0 0 /base_link\
    \ /laser_height 100 />\n```\n\nThis creates the /laser_height frame in tf. Then\
    \ in the config for pointcloud_to_laserscan I have:\n\n```\n<node pkg=\"pointcloud_to_laserscan\"\
    \ type=\"pointcloud_to_laserscan_node\" name=\"scan\">\n  <remap from=\"cloud_in\"\
    \ to=\"your/Pointcloud2/topic/name\" />\n  <rosparam>\n    target_frame: laser_height\n\
    \    ...other params here...\n  </rosparam>\n</node>\n```\n\nNow you should have\
    \ a laserscan slice at the level specified by the laser_height param (6ft / 1.829m\
    \ in my case above).\n\nThe min_height and max_height params look like they define\
    \ a band of points from the pointcloud to operate on; anything outside is ignored.\n\
    \nThanks Karl!\n            \n"
