    \ [..]\n\nthis makes no sense to me. Why did you set `ROS_HOSTNAME` to the IP\
    \ of the android device?\n\n---\n\nEdit:\n\n> The ROS master is running on the\
    \ android phone thus I set HOSTNAME to `android_ip`. Is that wrong?  \n\nyes,\
    \ that is not correct. `ROS_IP ~= ROS_HOSTNAME`: both store information about\
    \ the local machine, not something remote. Only `ROS_MASTER_URI` ever points to\
    \ a remote IP / host.\n\nPlease note that only one of them is needed. If you set\
    \ `ROS_IP`, you don't need `ROS_HOSTNAME` and the other way around.\n\nOr to be\
    \ more precise: don't fill in the same information in the two. `ROS_HOSTNAME`\
    \ should be set to hostnames, and things will only work if you've got a working\
    \ DNS for all involved hosts (note: both forward and reverse lookups need to work).\n\
    \nIf you set `ROS_IP`, set it to an IP, not a hostname. If you do this, you don't\
    \ need DNS, but it's obviously less flexible in the face of (frequent) IP changes\
    \ of the involved hosts (such as with an 'overactive' DHCP server)."
