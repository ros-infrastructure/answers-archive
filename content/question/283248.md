  body_markdown: "You need a connection of all involved frames. This can be achieved\
    \ by properly adding the LIDAR to the URDF model. A very \n simple way of doing\
    \ so would be adding this to your URDF:\n\n    <joint name=\"laser_joint\" type=\"\
    fixed\">    \n      <origin xyz=\"0.1 0 0.2\" rpy=\"0 0 0\" />     \n      <parent\
    \ link=\"base_link\"/>\n      <child link=\"laser\"/>\n    </joint>\n\n    <link\
    \ name=\"laser\">\n    </link>\n\nThis adds a fixed joint to the `laser` link\
    \ containing no visual, collision geometry or inertial information and should\
    \ be all that is required to make things work for you. The `robot_state_publisher`\
    \ reads the URDF on startup and then publishes the fixed joint `tf` transform\
    \ automatically.\n\nAn alternative to editing the URDF is just running a [static\
    \ transform publisher](http://wiki.ros.org/tf#static_transform_publisher):\n\n\
    \    rosrun tf static_transform_publisher 0.1 0.0 0.2 0.0 0.0 0.0 base_link laser\
    \ 100\n\n\n\nNote these two options are the quick and simple way, doing it \"\
    right\" involved using xacro, proper geometry and inertial tags and support for\
    \ Gazebo integration. See for example these xacro macros for a Hokuyo LIDAR:\n\
    \n - Macro:\n   [hokuyo_utm30lx.urdf.xacro](https://github.com/tu-darmstadt-ros-pkg/hector_models/blob/kinetic-devel/hector_sensors_description/urdf/hokuyo_utm30lx.urdf.xacro)\n\
    \  \n - Usage Example:   \n   [quadrotor_hokuyo_utm30lx.urdf.xacro](https://github.com/tu-darmstadt-ros-pkg/hector_quadrotor/blob/kinetic-devel/hector_quadrotor_description/urdf/quadrotor_hokuyo_utm30lx.urdf.xacro#L15)"
