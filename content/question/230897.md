  body_markdown: "I will quote an [answer](http://stackoverflow.com/questions/19181332/libfreenect-vs-openni)\
    \ which I found on Stackoverflow belonging to that question i found as i stood\
    \ before that decision myself:\n\n> Libfreenect is mainly a driver which\n> exposes\
    \ the Kinect device's features:\n> - depth stream - IR stream - color(RGB) stream\
    \ - motor control -\n> LED control - accelerometer\n> \n> If does not provide\
    \ any advanced\n> processing features like scene\n> segmentation, skeleton tracking,\
    \ etc.\n> \n> On the other hand, OpenNI allows\n> generic access to Kinect's feature\n\
    > (mainly the image streams), but also\n> provides rich processing features such\n\
    > as: - scene segmentation - skeleton\n> tracking - hand detection and tracking\n\
    > - gesture recognition - user interface elements etc. but no low level\n> controls\
    \ to device features like\n> motor/LED/accelerometer.\n> \n> As opposed to libfreenect\
    \ which AFAIK\n> works only with the Kinect sensor,\n> OpenNI works with Kinect\
    \ but with\n> other sensors as well like Asus Xtion\n> Pro, Carmine, etc.\n\n\
    I am using freenect at the moment with success and haven't tried out out OpenNi\
    \ so long. You can find some info on my projects website [here](https://docs.google.com/document/d/1SfdtqLc7YeuoSwmdOspKt9vbfaUmWDyKpdCXwQvjaXY/edit#heading=h.yio46yi534cc)\
