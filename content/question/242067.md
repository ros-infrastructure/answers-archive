  body_markdown: "[eband_local_planner](http://wiki.ros.org/eband_local_planner) (classical\
    \ Elastic Band approach by Quinlan et al.) and [teb_local_planner](http://wiki.ros.org/teb_local_planner)\
    \ (Timed Elastic Band (TEB) approach) are two completely different planning algorithms.\
    \ However, the TEB principle is based on the classic elastic band idea.\n\n**eband_local_planner\
    \ (Elastic Band)**\n\n - Local path deformation (path: no timing law) based on\
    \ internal and external forces \n - Internal forces contract the path (-> leading\
    \ to the shortest path between start and goal)\n - External forces repel the path\
    \ from obstacles\n - Implementation based on bubbles that represent discrete path\
    \ points and free-space.\n - Adaption of the trajectory length w.r.t. bubbles/free-space\
    \ (insertion and deletion of discrete points) \n - Extension to non-holonomic\
    \ kinematics (supports differential-drive and omnidirectional robots)\n - Subject\
    \ to local minima (e.g. left or right path around an obstacle, depends on initial\
    \ path)\n\n**teb_local_planner (Timed Elastic Band)**\n\n - Local trajectory deformation/optimization\
    \ (trajectory: includes temporal information)\n - Instead of generating and applying\
    \ forces, an objective/cost function is minimized\n - Temporal information is\
    \ subject to optimization -> time-optimal trajectories (replacement for the internal\
    \ forces)\n - Temporal information allows incorporation of (kino-)dynamic constraints\
    \ during optimization (no need for a dedicated path-following controller, the\
    \ teb_local_planner mimics a predictive controller)\n - Adaptation of the trajectory\
    \ length based on the temporal discretization (insertion and deletion of discrete\
    \ trajectory points)\n - Supports differential-drive, car-like and omnidirectional\
    \ robots\n - Explores multiple distinctive topologies for parallel trajectory\
    \ optimization in order to partially overcome the local minima problem (only in\
    \ the scope of the local costmap due to limited CPU resources, a global planner\
    \ is still required).\n - Path-following mode (minimize distance to global plan\
    \ instead of minimizing transition time) \n - Bottleneck: very high computational\
    \ burden (-> limited local costmap size/resolution resp. robot size)."
