  body_markdown: "Hello turtlebot uses 1e-3 covairance for wheel odometry x,y  and\
    \ Ch robotic's UM6 driver for ros uses 1e-6 covairance for yaw. If you don't give\
    \ covairances for imu to robot_pose_ekf it will manually set covariance until\
    \ imu sends covariance  \n\n    // manually set covariance untile imu sends covariance\n\
    \    if (imu_covariance_(1,1) == 0.0){\n      SymmetricMatrix measNoiseImu_Cov(3);\
    \  measNoiseImu_Cov = 0;\n      measNoiseImu_Cov(1,1) = pow(0.00017,2);  // =\
    \ 0.01 degrees / sec\n      measNoiseImu_Cov(2,2) = pow(0.00017,2);  // = 0.01\
    \ degrees / sec\n      measNoiseImu_Cov(3,3) = pow(0.00017,2);  // = 0.01 degrees\
    \ / sec\n      imu_covariance_ = measNoiseImu_Cov;\n    }\n\nas you can see above.\
    \ I think it will be easier for you starting with turtlebot's odom covariances\
    \ increase them if you get poor odometry. Because picking covairances heavily\
    \ depends on system configuration(encoders,encoders resolution,motors,wheels,slippage,speed\
    \ controller,drive system type etc..) \n\nFor optimal values, I recommend you\
    \ to perform an odometry calibration alogirthm such as UMBMark. Calibrate it as\
    \ possible as it can be. Then set your covairances. Covairances show how much\
    \ you depend on your odometry data. If covairances are high, this shows that you\
    \ don't depend very much on your odometry data. \n\nHow to set covairances ? your\
    \ wheel odometry data is being published by you generally from base_link frame\
    \ to odom frame.    [Check here](http://www.ros.org/wiki/navigation/Tutorials/RobotSetup/Odom).\
    \ Odometry message type and IMU message type have parts where you can set covairances.\
    \ [Check out here for odometry](http://www.ros.org/doc/api/nav_msgs/html/msg/Odometry.html)\
    \ and [Check out here for imu](http://www.ros.org/doc/api/sensor_msgs/html/msg/Imu.html)"
