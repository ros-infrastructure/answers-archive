  body_markdown: "I'm running the same setup.\n\nThe problem is inside  imageCB()\
    \ method in stereo_view.cpp.\n\nimage_mutex_.unlock() was being called before\
    \ imshow() for the left, right and disparity images. \n\n\n    image_mutex_.unlock();\n\
    \    if (!last_left_image_.empty())\n      cv::imshow(\"left\", last_left_image_);\n\
    \    if (!last_right_image_.empty())\n      cv::imshow(\"right\", last_right_image_);\n\
    \    cv::imshow(\"disparity\", disparity_color_);\n\nthe location of <code> image_mutex_.unlock();\
    \ </code> is causing the window threads to lock up.\n\nchange the above to this:\n\
    \n    if (!last_left_image_.empty())){\n      cv::imshow(\"left\", last_left_image_);\n\
    \      cv::waitKey(1);\n    }\n    if (!last_right_image_.empty()){\n      cv::imshow(\"\
    right\", last_right_image_);\n      cv::waitKey(1);\n    }\n    cv::imshow(\"\
    disparity\", disparity_color_);\n    cv::waitKey(1);   \n\n    image_mutex_.unlock();\n\
    \nmoving the unlock() command below the Mat checks and adding <code> cv::waitKey(1)\
    \ </code> for each cv::imshow() solved it for me. \n\nYou'll have to download\
    \ the source code from <a> https://github.com/ros-perception/image_pipeline.git</a>\
    \ and compile it yourself. look in image_view/src/stereo_view.cpp for the image\
    \ call back.\n\nHope this helps"
