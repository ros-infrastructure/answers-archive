Hi,

I am currently working on a project where I'm sniffing all ROS2 data (topics, services and actions) send between ROS-Nodes. All data sent is deserialized which allows me to monitor all data sent between nodes in real-time. This allows me to see all data sent between nodes, equal to 

> ros2 topic echo

but unlike the command above, also for services and actions. As I am sniffing the data I do not need to instrument the ROS-Nodes sending the data.


I am stuck on the following problem:

The RTPS packets containing the messages contain a field: **appId** which is basically the substitute for the node name. Using the appID I can distinguish which node is sending which message. I would however prefer to have the actual node name instead of the appId. I however cannot seem to find a correct way to *"link"* the appId to a node name.

Can anyone point me in the right direction? Is this something that is dependent on the ROS 2 middleware being used? I am currently using Eprosima's fastdds.
